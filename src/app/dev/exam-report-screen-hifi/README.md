# 성적표 원장님 화면 Hi-fi

개발 경로: `/dev/exam-report-screen-hifi`. 원장 전용 개발 가드를 둔다. A의 목록·미리보기 구조 안에서 H1~H4의 세부를 비교한다. 실제 메뉴·API·DB·확정 쓰기는 연결하지 않는다.

| 안  | 바꾸는 축                                                               |
| --- | ----------------------------------------------------------------------- |
| H1  | 기준: 상태 배지·점수 목록, 미리보기 아래 문장, 위쪽 반 지면 설정·인쇄   |
| H2  | 목록만 변경: 점수·상태를 독립 열로 정렬                                 |
| H3  | 문장 위치만 변경: 미리보기 옆에서 편집, 좁은 폭에서는 아래로 쌓기       |
| H4  | 행동 위치만 변경: 학생 머리의 확정, 미리보기 옆 반 설정, 아래 인쇄 모음 |

모든 안에서 기존 `studentExamReportPages`·`classExamReportPages`와 `EXAM_REPORT_PAPER_CSS`를 그대로 사용한다. 지면 띠·확대는 `PaperStrip`, 긴 명단·설정·인쇄 검토는 `PickerDialog`다. 작업실 `Workroom.module.css`의 글꼴·단추와 `WorkspacePageHeader`를 사용한다. 공용 부품은 수정하지 않았다.

예시 상황은 문장 없음·문장 씀·확정·다시 확정·결시·길이 상한·저장 중·저장 실패·확정 실패·학생 48명·오답 20개다. 학생·문항은 전부 지어낸 자료다. 안·학생을 옮겨도 학생별 입력은 남으며 예시 상황 변경은 초기화한다. 저장은 로컬 650ms 지연으로 보이고, 실패 예시에서는 입력을 보존해 재시도한다. 문장 없이 확정할 수 있고 지면의 문장 칸은 빠진다. 확정 후 문장·반 지면 설정이 바뀌면 다시 확정으로 표시한다.

인쇄의 기본 범위는 확정된 학생만이다. 응시 학생 모두·선택한 학생에는 확정 전 학생도 포함할 수 있고 결시는 제외한다. 단추를 누르면 대상 명단과 첫 학생의 실제 H1 지면을 검토하는 로컬 창이 열린다. 반 성적표도 같은 창에서 검토한다. 실제 프린터·PDF 생성·에이와 전송은 실행하지 않는다. 48명 반의 C2 쪽 나눔은 기존 부품의 범위 밖이며 창에 한계를 알린다.

## 문장 상한과 실측 상태

**180자는 실측 전 비교값이다. H1 한 장에 드는 최종 상한으로 확정하지 않았다.** 페이지 상단에도 같은 사실을 표시한다. `maxLength`와 남은 글자 수는 이 비교값에 연결했다. 줄바꿈·오답 행·긴 제목까지 글자 수만으로 보장할 수 없으므로, 미리보기의 원본 H1 DOM에서 쪽 넘침·자식 내용 잘림·이웃 영역 겹침·바닥 여백 침범을 관찰한다. 글꼴이 준비되고 지면 확인을 마칠 때까지, 또는 넘침이 있으면 저장·확정·해당 학생 인쇄 검토를 막는다. 이 관찰도 실제 브라우저 검증 전이며 운영 검증기로 보장하지 않는다.

지시서의 **실제 지면 실측과 최종 상한 결정은 미완료**다. 이 환경에서 다음 제약을 확인했다.

- 로컬 Playwright Chromium은 `bootstrap_check_in … Permission denied (1100)`으로 시작하지 못했다.
- 로컬 HTTP 서버는 `listen EPERM: operation not permitted 127.0.0.1`로 열리지 않았다.
- 제공된 브라우저 도구의 IAB는 사용할 수 없었고, Safari 접근은 `Computer Use was not approved to use Safari`로 거절됐다. 권한을 바꾸거나 다른 사용자 앱으로 우회하지 않았다.

재현 가능한 실측 자는 아래 명령으로 만든다. 이 명령 자체는 브라우저·서버를 열지 않는다.

```sh
node scripts/qa/exam-report-screen-hifi.mjs
```

생성 파일은 `.qa-artifacts/exam-report-screen-hifi/index.html`이다. 공용 CSS·로컬 글꼴·시안을 한 파일에 넣으며 CSP로 연결 요청을 닫는다. 승인된 브라우저에서 파일을 열고 `H1 문장 상한 실측`을 누르면 다음 20조합을 **수정하지 않은 실제 H1 부품**으로 그려 수치를 표시한다.

- 오답 4·7·8·12·20개 × 한글 180자·넓은 영문 180자·한글 240자·줄바꿈을 포함한 180자.
- A4 원본 폭/높이, 내용 폭/높이, 문장 줄 수, 문장과 기록 현황 사이 거리, 잘림·겹침, 자체 글꼴 준비 여부.

같은 파일에서 가용 폭 1920·1280·1050·768·760·390·320px을 골라 화면 수치 확인과 수동 검토도 할 수 있다. **파일 생성 성공을 실측·화면 캡처·실물 검수 성공으로 세지 않는다.** 상한을 최종 결정할 때는 이 결과와 줄바꿈/많은 오답의 넘침 정책을 함께 확인해야 한다.
