# MP3 and PostgreSQL media evidence — 2026-10-03

Implemented in the media worker from main `a20cd6a88`; backend owns the additive Prisma schema/migration and HTTP authorization. No shared database, migration application, push or deployment was performed.

## Runtime and contract

`createListeningMediaService` keeps its public operations. `appendChunk`, `completeUpload` and `serve` accept a final optional `{signal}` argument. Every user operation authorizes and resolves current owner/branch; uploads recheck before commit, including exact retries. Canonical ready assets cannot be changed by the production adapter. Playback serves only the stored canonical identity and its byte count, with private/no-store headers and neutral filenames. Streaming cancellation closes the iterator and prevents subsequent reads; a pending database query may finish before its already bounded result is discarded.

Ready receipt `sha256` is the playback hash; `totalBytes` and `receivedBytes` remain original-upload byte counts. New optional ready fields are `originalSha256`, `playbackBytes`, `playbackRevision` (currently 1). Publish callers must bind the document to ready `assetId`/`sha256`/`durationMs`, never the upload's expected original hash. Internal original chunks and hash remain separate from the playback descriptor. Canonical PCM WAV can share the same immutable bytes since it has no ancillary metadata; decoded MP3 always has a separate derivative and hash.

MP3 is fully decoded by pinned `mpg123-decoder@1.0.3` (inline WASM, Node-compatible); there is no external binary, CDN or audio service at runtime. Strict Layer III framing rejects junk, incomplete frames, unsupported free-format, changing sample rate/channel count and mismatched Xing/VBRI counts. Leading ID3v2.2/3/4 and trailing ID3v1 are discarded; only PCM samples enter canonical RIFF/WAVE output. Every decoder error and nonfinite sample rejects publication. Unknown trailers such as APE are rejected. A complete-frame cut of a stream without an original-length header is indistinguishable from a shorter valid stream; teacher listening review remains required.

Hard pilot maxima: 16 MiB original; 600,000 ms actual decoded samples; 112 MiB playback; 1 MiB input/storage chunk; 64 KiB default read. Completion holds one bounded original buffer and small decoder/output batches, never the full derivative. At most two finalizations run per Node process; a third returns retryable `conflict`. Both parser duration preflight and actual output-sample duration are bounded. Xing's information frame and codec padding are allowed in preflight so exactly-at-limit audio succeeds; decoded PCM remains the final duration authority.

Official sources read: [decoder API and error behavior](https://github.com/eshaz/wasm-audio-decoders/tree/main/src/mpg123-decoder), [MP3 frame arithmetic in mpg123](https://github.com/libsdl-org/mpg123/blob/master/src/libmpg123/parse.c), [ID3 structure](https://id3.org/id3v2.4.0-structure), [Prisma parameterized raw queries](https://www.prisma.io/docs/orm/prisma-client/queries/raw-database-access/raw-queries), [PostgreSQL locking](https://www.postgresql.org/docs/current/explicit-locking.html), [PostgreSQL binary substring](https://www.postgresql.org/docs/current/functions-binarystring.html). Local Next 16.3 route/server-package guides were read before implementation.

## Durable store

`new PrismaListeningMediaStore(prisma, {maxOwnerBytes?, maxOwnerAssets?, orphanTtlMs?})` uses the backend-owned `english_listening_media_asset` and `english_listening_media_blob` tables. SQL is parameterized. Transactions lock owner first, then asset; revision CAS and committing blob references are atomic across processes. Reads use PostgreSQL `SUBSTRING(bytea)` so the driver receives only bounded slices. Each write creates an opaque, private immutable chunk; no URL or source filename exists.

Defaults are 512 MiB reserved per owner and 128 asset rows. Beginning an upload reserves original bytes, 1 MiB retry/staging headroom and, for MP3, maximum playback bytes; actual ready/blocked storage replaces the reservation at finalization. Staged bytes count against the reservation. Atomic owner locks stop concurrent oversubscription. A full-size duplicate finalizer may receive a retryable quota/conflict until the winning completion can replay.

`cleanupExpiredUploads(limit)` is a trusted maintenance entrypoint (not a user-authorized operation); backend must protect and invoke it. It tombstones expired incomplete records, deletes their chunks, and runs bounded orphan cleanup. Orphans must be uncommitted and older than the TTL (one hour default); sweeper/commit locking prevents deleting a newly committed reference. Empty expired rows are removed. Ready assets are never expiry-cleaned. Backend SQL adds immutable-byte and immutable-ready-record triggers, tested directly as well as through the adapter. RLS/revocation and deployment credentials remain backend integration responsibilities.

## Verified evidence

- 20 existing media tests and 14 real-MP3 tests pass. Real CBR mono, VBR stereo and MPEG-2 mono fixtures decode; an independent waveform measurement confirms 440 Hz and nonzero amplitude. Tests cover ID3v2/v1 removal, original/derivative hashes, completion replay, ranges, malformed/truncated frames, metadata-only impostors, limits, exact-duration padding, failed-output cleanup, stalled upload cancellation and decoder cancellation.
- Media integration and English fence checks pass (4 files, 51 tests after the final MP3 cases). Node decoder/storage code stays outside student UI imports.
- Existing offline PCM probe passes: 60 seconds, 5,760,044 bytes, six upload chunks, identical SHA256 `74f64a5cc8181b31f71b51f874a46bb2e27f0a03e58e07a9f1fdee6c0710a921`, max storage read 65,536 bytes.
- `media-postgres-probe.ts` passes against actual isolated PostgreSQL 18. Each run creates/removes its own schema using exact backend media migration statements, including immutability triggers. It verifies independent-client races, detached snapshots, reconnect persistence, full/range hashes, bounded SQL reads (4096 bytes), abort/revocation, aggregate quota races, orphan/expiry cleanup, and preservation of ready bytes. It refuses non-loopback or non-media test database names and never loads dotenv.
- The optional actual 600-second stereo probe passed with default service limits: original 9,600,812 bytes; canonical output 115,200,044 bytes; exact duration 600,000 ms; output SHA256 `28552f2da8652b4d356a95db825bc20c334f9c6c321dc8c7dc847e1c9ed07636`. Decode plus PostgreSQL persistence took 11,581 ms; including full streamed playback/hash took 13,609 ms. Maximum playback piece was 65,536 bytes; sampled whole-process peak RSS was 413 MiB. These are local measurements, not a Vercel latency/memory guarantee.
