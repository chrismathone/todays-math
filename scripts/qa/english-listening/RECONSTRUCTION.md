These tools prepare private draft data from actual audio-only assessment records. They do not register, upload, publish, approve rights, or create human review stamps.

Create an isolated Python environment and install `asr-requirements.txt`. For the verified Windows CUDA configuration, install NVIDIA's `nvidia-cublas-cu12==12.9.2.10`, `nvidia-cudnn-cu12==9.10.2.21` and `nvidia-cuda-nvrtc-cu12==12.9.86` wheels in that environment. The Python script scopes their DLL paths to its own process. Main project dependencies are unchanged.

Run `transcribe-local.py` with the original audio path, expected original SHA, an unused output path and a model cache directory. The verified first-pass configuration uses `--model medium --device cuda --compute-type int8 --language auto --multilingual`. CPU int8 remains available. The source hash and duration are checked. All inferred text, raw uncertainty measures, model/configuration, elapsed time and timestamp limitations are preserved. Never treat the model's uncertainty flag as proof that every original conversation was recovered.

Run `npx tsx scripts/qa/english-listening/reconstruct-audio.ts --prepared <audio-only-payload> --asr <asr-json> --output <separate-output-folder> --env-file <server-env-file> --generate --verify`. The explicit flags permit paid calls. Generation uses the existing DeepSeek-v4-pro model and TypeSafe/Jev performs semantic checks. API receipts are cached against the exact evidence and instructions; there are no automatic paid retries. Omitting flags permits reuse of completed receipts.

The new questions use actual ASR segment IDs and exact quotes. A missing original dialogue can reduce the count. The generator must not fill gaps, recover missing official answers, require unseen figures, or invent exact audio timings. Question `sourceNumber` values are new generated ordinals, explicitly marked in verification. Metadata's official `sourceNumber` remains null. The output explicitly labels `원본 문제지 없음 · 음원 기반 재구성` and preserves the original audio SHA in both metadata and reconstruction provenance.

Code deterministically shuffles choices and updates the answer before Jev independently chooses an answer from blind named transcript/prompt/choice records. It includes an unavailable-answer outcome. Separate Noul judgments check grounding and explanation support. Proposed answers and explanations are omitted from the shared answer-selection state. Answer disagreements and grounding below 0.5 are excluded from registration payloads, with candidates retained in audit. Weak explanations are cleared and remain `needs_review`. The initial 0.9 verification gate retains raw distributions for review; uncertain ASR or weak probabilities also result in `needs_review`. `ai_verified` describes semantic checks against model transcription, not human review or a guarantee of exact speech recognition. The output is still a draft with no audio alignment evidence or approval stamps.

`reconstruct-batch.ts` processes audio-only prepared inputs newest first, with one GPU ASR and at most two generation workers. Explicit `--execute` permits paid calls. Completed payloads are reused with their stable IDs. Payloads and the incremental manifest become visible through atomic `.partial` renames only after successful schema and answer checks.

When measured GPU memory permits two copies of the same model, `precompute-asr.py --prepared <audio-only-folder> --asr-output <asr-folder> --model-cache <cache> --limit 36` can prepare the oldest records alongside the main queue. It uses the same medium CUDA int8 configuration, with no paid calls. Both queues take an OS lock on each ASR output and reuse a completed matching SHA; process exit releases the lock. Run this script with the isolated environment's Python. Do not modify the live batch manifest from another process. Once both queues finish, rerun the main command to reconcile independently recovered payloads and retry incomplete records using their cached receipts.
