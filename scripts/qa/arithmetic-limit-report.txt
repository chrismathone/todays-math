Integration contract
New v1/v2 generation: max 10 rounds, 200 items in each round, 2,000 total.
arithmeticPerRoundBudget(1..10) returns 200, independent of round count.
Readers and regeneration targets retain ARITHMETIC_MAX_SAVED_ROUNDS=20.
No overlap rule is added to reopen/verification. Historical overlapping sheets,
source prompts, answers, SVG IDs, compressed canonical packs and versions remain
unchanged. The original 53-family fixture reopens and reproduces exactly.

Browser-safe preflight exported from src/lib/arithmetic/byteBudget.ts:
  arithmeticSheetByteIssue(payload: unknown)
  -> {code:"payload-size",message:string,bytes:number,max:number} | null
The helper measures UTF-8 serialized JSON, not JS string length. Root consumes it
before save. Builders and changed regeneration results enforce it server-side;
the saved-library route also enforces it before writing. Payload-size engine
errors use HTTP 413. Auth, menu access, writer flag, revisions and DB schema are
unchanged. All DB interactions in the persistence test are in-memory mocks.

Regeneration keeps the existing result shape with one optional addition:
  unchangedReason?: "fixed-overlap" | "overlap-capacity"
Use arithmeticRegenerationNotice(result), already consumed by both workbenches.
On zero feasible changes, changedOrders=[], sheet is the original object, and
unselected items/rounds are untouched. Root should preserve existing zero-change
dirty-state behavior. Fixed-overlap means unselected positions already exceed a
pair cap; overlap-capacity means selected domains cannot repair the target round.
Pairs between unrelated historical rounds are deliberately not revalidated.

Identity and selection
For every pair of new rounds, shared task identities <= floor(min(lengths)/5).
Within a round, no task repeats. v2 uses existing arithmeticV2PromptIdentity;
v1 uses the existing regeneration identity (notation, operator, ordered operands).
Operands themselves are not the overlap unit; commuted expressions stay distinct.
Type sections remain in request order; selected items are seed-shuffled within
each allocation section. Selection and regeneration are deterministic.

The ordinary path matches domains to globally distinct tasks, with no graph per
slot/candidate edge. Candidate iterators initially load each domain's total
demand only. If matching fails, only deficient connected domain components expand
to N distinct candidates per domain (N=total worksheet slots), or exhaust the
finite domain. Unrelated large domains stay lazy. No candidate SVG is rendered
while selecting; only selected figure IDs enter the trusted geometry pack.

Completeness: an out-of-pool assignment can be replaced by a pool identity unused
by the other N-1 slots, so N distinct candidates suffice and overlap cannot grow.
Nondeficient components already have globally distinct assignments in disjoint
current pools. The exact fallback uses domain-eligibility/round-membership symmetry,
memoized failed states, and necessary pigeonhole bounds over all round subsets.
No random retry count or timeout is reported as mathematical capacity failure.
The exact fallback can be exponential for adversarial heterogeneous overlapping
domains; measurements below are not a universal request-latency guarantee.

Regeneration first tries N seeded alternatives per selected slot. A feasible
all-changed result is globally optimal. Otherwise it expands to N alternatives
per fixed-round membership class and uses minimum-cost matching with complete
budget-exclusion branching. Each branch excludes one of b+1 identities exceeding
budget b; every valid assignment must exclude at least one. This maximizes changed
slots. v1 caches operand pairs per canonical skill/constraints and independently
verified prompt/answer templates per pair; item order/round/seed stay item-specific.

Feasibility examples
Rounds of length 1-4 allow zero shared tasks. Two length-5 rounds allow one;
the same domain therefore needs >=9 tasks. Three length-5 rounds over nine tasks
are impossible despite each pair being feasible in isolation; twelve tasks suffice.
For a shared universe D, two demands a,b force at least max(0,a+b-D) overlaps.
Heterogeneous requests use actual admissible task identities and exact matching,
including overlapping domains where greedy allocation would steal a singleton.

Transport limits (decimal bytes unless KiB is specified)
Generate request: 512 KiB, depth12, 100,000 tokens, string128.
Sheet: 3,250,000 bytes, leaving 250,000 bytes for envelope/metadata.
Regenerate/save wrapper: 3,500,000 bytes, depth16, 1,000,000 tokens,
string1,000,000. The shared library's pre-existing 3.5MB body ceiling is now enforced
while streaming, including chunked bodies without Content-Length.
Geometry subset pack: <=2,000 distinct trusted IDs, <=1,000,000 base64 characters;
cache bounded to two packs. Compression algorithm/order unchanged. Submitted packs
are compared to canonical trusted bytes before acceptance; untrusted SVG is never
inflated. Full sheet byte preflight additionally bounds prompt + pack combination.
