# AI 모델 비교 하네스

새 모델이 나오면 **제품과 같은 지시문 · 같은 응답 해석**으로 지금 모델과 나란히 재는 도구 (원장님 2026-10-19).
DB는 읽기만 합니다(표본 뽑기). 고정 표본을 `--sample`로 주면 DB 조회도 하지 않습니다.
`solution`은 호출별 최대 비용을 확보하는 엄격 예산 모드가 기본입니다. 다른 텍스트 측정은 `--budget`(달러)과 `--strict-budget`을 함께 씁니다.

```bash
npx tsx --conditions=react-server --env-file=.env scripts/qa/ai-model-bench/run.ts \
  --task solution --arms deepseek-v4-pro@16k,deepseek-flash@16k --n 20 --seed s1 \
  --budget 0.25 --strict-budget --concurrency 1 --out ../bench-out/solution
```

## 작업 (`--task`)

| 작업 | 제품의 어느 걸음 | 채점 |
|---|---|---|
| `solution` | 작업실 «해설» (`action: "solution"`) | DB 정답과 대조(같음 / 다름 / 빈 답) · KaTeX 렌더 실패 · `$` 짝 · 잘림 · 수식 내 빗금 분수 수 · 해설 평균/중앙 길이 · 시간 · 비용 |
| `page-ocr` | 문제 추출 1걸음: 한 쪽 → 문제 크롭 상자 (`page-ocr`, 제품은 찾기만 함) | 문항 찾음 · 지어낸 문항 · 크롭 IoU · **정답 영역 덮음**(잘린 문제를 잡는다) |
| `crop-ocr` | 문제 추출 2걸음: 크롭 사진 → 글 · 그림 상자 (`ocr`, 보강 호출 포함) | 글 일치(표기 차이를 걷은 편집 거리) · 수식 렌더 실패 · 그림 찾음 · 그림 IoU |
| `english-read` | 오늘의 영어 «사진에서 글 읽기» | **새로 짓지 않음** — `scripts/qa/english-read-bench/` 를 부르는 명령만 출력. 사진 자료는 저장소 밖(문서 25 §13.9) |

`page-ocr` · `crop-ocr` 표본은 공유 DB 문항을 2단 A4 지면으로 **그려서** 만듭니다(정답 글과 상자를 알기 위해).
그래서 깨끗한 인쇄면에서의 성능입니다. 스캔 잡음, 손글씨, 기울어짐은 들어 있지 않습니다.
같은 `--seed` 를 주면 두 작업이 같은 문항을 씁니다.

## 모델 팔 (`--arms`, 정의는 `arms.ts`)

`--list` 로 목록을 봅니다. 새 모델은 `arms.ts` 에 한 줄을 더합니다(공급자 · 모델 · 설정 · 단가와 출처).
설정의 기본은 제품과 같게 둡니다. 다르게 재는 팔은 id 에 그 차이를 적습니다(예: `deepseek-flash@16k`).

- `fallback` 이 있는 팔은 대체 경로입니다. 답이 비거나 잘리거나 형식이 깨진 문항만 다른 팔로 다시 부르고, 시간과 비용은 두 호출을 합해서 셉니다. 예: `flash→v4-pro`.
- `…@agy` 팔은 구독 CLI(Antigravity)로 Gemini를 부릅니다. API 키가 없을 때 쓰는 대리 측정이고, 비용은 0으로 셉니다. 사진을 싣는 방식이 제품 API와 다르고, 시간에는 에이전트 왕복이 섞입니다.
- 서버 키가 없는 팔은 부르지 않고 «건너뜀»으로 적습니다.

## 옵션

| 옵션 | 뜻 |
|---|---|
| `--n` · `--seed` · `--filter` | 표본 크기 · 시드 · 거르기(`solution`: `high` = 고등 과목, 응용과 심화를 반씩) |
| `--exclude <sample.json>` | 앞 측정의 문항을 빼고 뽑기 |
| `--sample <sample.json>` | 저장한 표본을 그대로 다시 쓰기(재현) |
| `--budget <달러>` | 상한(기본 0.5). `solution`은 엄격 제한, 다른 작업은 이 옵션 단독 사용 시 평균 추정·관측 최댓값으로 제한하므로 초과 가능성이 있습니다 |
| `--strict-budget` | 텍스트 전용(`solution`은 자동 적용). 매 호출의 입력 UTF-8 바이트+1024 토큰·캐시 미적중·출력 한도 전체를 미리 확보합니다. 동시·보강·대체 호출도 같은 예산을 씁니다. 사용량을 모르는 실패·이상 응답은 최대 비용으로 잡고 중단하며 완료된 호출의 기록·비용은 보존합니다 |
| `--dry-run` | 표본과 어림 비용만 내고 부르지 않기 |
| `--rescore` | 저장한 응답을 **다시 채점만** 하기(호출 없음). 채점기를 고친 뒤에 씁니다 |
| `--concurrency` | 팔마다 동시 호출 수(기본 3) |

결과는 `--out` 폴더에 `sample.json`, `results.json`(응답 원문 · 사용량 · 채점), `table.md`(팔별 한 줄)로 남습니다.
실호출은 `prompts.json`(실제 지시문·SHA-256)과 `records.jsonl`(완료 즉시 저장)도 남깁니다.
이번 제품 기본 출력 한도는 모든 공급자에서 16000입니다. 과거 결과는 저장 당시 설정을 기준으로 읽습니다.

«답 다름»은 자동으로 «틀림»이 아닙니다. 표기만 다른 경우가 많으니(`20π/27` 대 `\frac{20\pi}{27}` 등) 표를 내기 전에 사람이 확인합니다.

시험: `src/__tests__/unit/aiModelBench.test.ts`. 실호출 없이 채점, 비용, 예산 멈춤, 대체 경로, 건너뜀을 확인합니다.
