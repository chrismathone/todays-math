# REPORT-02 — 초등 familyKey, 값이 붙은 제안

작성: 2026-08-26
분모: **360** (초3~초6 230 + 중1~중3 130). 초등 230 = 360의 **64%**.
근거: `scratch/DECISION-01-scope.md` · 엔진 코드 · 지문 센서 `scripts/qa/census-elem-stem-frames.ts`
DB: 이번 워크트리에서 SELECT 못 함. 적재 건수는 문서 실측을 인용하고 출처를 붙인다.

「한 시험지에 같은 문항류 하나만」(2026-08-26 확정)은 **풀지 않는다.**

## 한 줄

키만 바꿔서는 초등 일일테스트 10문항이 안 나온다. 지금 밖으로 나온 유형 정체가 없고, 갈래당 발문 틀이 대개 하나라 키에 이름을 붙여도 **최저 4**다. 지문으로 센 평균 15.2는 소재 이름을 다른 틀로 센 과대라 쓰면 안 된다.

## 1. 생성기에 유형 정체가 이미 있는가

**없다.** `listCoverage()`가 들고 있는 것은 `grade · chapter · section · code · tiers`뿐이다 (`scripts/elem/gen-core.ts:48-58`). 유형 번호·mode·문형 id 필드가 없다.

| 층 | 키 | 적재에 쓰이나 |
|---|---|---|
| `G3`~`G6` 대단원 핸들러 | `학년\|대단원` | 아니오. 갈래 없이 낼 때만 |
| `G*_TIERS` | `학년\|소단원코드` 예 `"초6\|2-6-4"` | 예. 소단원당 함수 넷 |
| `ElemProblem` | content/answer/solution/figureSpec | mode 필드 없음 |
| 결합형 `familyIds` | 승인 문형 2개 | 적재기가 안 읽음 |

적재 키는 적재기가 만든다 (`scripts/import/load-engine-problems.ts:162`):

```
elem:${unit.grade}|${unit.section}|${tier}
```

주석 그대로 **소단원 + 난이도**. 핸들러 함수 이름도 내부 `if` 분기도 안 실는다.

같은 갈래를 씨앗만 바꾸면 숫자·물건 이름이 바뀐다. 원장님이 보신 초6 2-6-4는 갈래당 발문 틀 1개다 (`g6.ts` `ballKnowCalc/Word/Apply/Deep`). 일부만 `intBetween(rng,0,1)`로 틀이 둘인데 **이름이 없다**.

없으면 만들 것: 난이도와 **직교인 문형 id**. 함수 이름만 붙이면 넷이 이미 난이도라 갈래 수는 그대로 4.

## 2. 키를 바꾸면 무엇이 깨지는가

### 이미 적재된 초등 (문서 실측, 이번엔 DB 못 엶)

| 숫자 | 출처 |

### 중복 방지 (`load-engine-problems.ts:387-390`)

DB 조회를 **이번에 넣을 `familyKey` 목록**으로만 좁힌다. 본문+정답이 같아도 **키가 다르면 안 잡히고 INSERT**된다.

### 출제 쪽 — 키 문자열을 파싱하지 않는다. 동등 비교만

`src/lib/generator/familyKey.ts`의 `familyIdOf`는 `(unitId, familyKey 전체)`가 같아야 같은 류다. 키가 없으면 `solo:<problemId>` (D-105).

- `findEligibleProblems`: `familyKey`를 select만
- `balanceDifficulty`: `usedFamilies.has(familyIdOf(p))`
- `replaceTestProblem`: 다른 자리의 `familyIdOf`만 거름
- `generateDraftTest`: `countFamilies(usable)`를 `available`로
- 화면 `[초]`: `familyKey.startsWith("elem:")` — 접두사만, 단 수는 안 봄

깨지는 로직은 적다. 깨지는 것은 **적재 중복 범위**와 사람이 적어 둔 키 맵이다.

- `scripts/qa/reviewedArrangement.ts` 정확 문자열 **61개**. 키가 바뀌면 「이미 본 갈래」가 전부 미검토로 돌아온다.

### 옛 키와 새 키가 섞이면 — 이게 제일 중요하다

같은 소단원에

- `elem:초6|2-6-4 구 알아보기와 여러 가지 모양 만들기|심화`
- `elem:초6|2-6-4 구 알아보기와 여러 가지 모양 만들기|심화|구의부피`

가 공존하면 `familyIdOf`는 **다른 류**다. 한 시험지에 숫자만 다른 같은 발문이 두 번 들어간다. 원장님이 2026-08-26에 금한 바로 그 모양.

새 키로 다시 적재하면 `387-390`이 옛 키 행을 안 보므로 같은 본문이 **두 키로 INSERT**되고, 출제가 둘을 다른 류로 고른다.

**섞인 채로 두면 안 된다. 이관은 옛 키를 남기지 않는 일괄 UPDATE이거나, 넣지 말아야 한다.**

## 3. 되돌릴 수 있는가

적재기 `--revert`는 원장의 `problemId`를 **DELETE**한다 (`load-engine-problems.ts:532-562`). INSERT한 새 행용이다.

이미 있는 1,751행의 **키 UPDATE를 되돌리는 장치는 없다.** 키를 바꾸려면 before/after 원장(처음 before · 마지막 after, 줄어들면 멈춤)이 **새로** 필요하다. 코드(`problem_code`)를 유지하려면 DELETE+재적재가 아니라 UPDATE다. freeze 트리거는 코드 변경만 막는다.

## 4. 바꾸면 초등 230곳이 실제로 몇 갈래가 되는가

두 자로 쟀다. **평균만 적지 않는다.**

### 자 ㉠ — 코드에서 발문 틀 (표본 10곳)

핸들러를 열어 `if` 분기를 셌다. 슬롯(꼭짓점/모서리)은 같은 틀.

표본 최저 **4** · 중앙 **4** · 최고 **6** · **10 미만 10/10**.
초6 2-6-4 구는 4. 키에 함수 이름만 붙여도 넷이 난이도라 **230곳 평균 4 · 최저 4 · 10미만 230**.

### 자 ㉡ — 지문 센서 (전량 230 × 4갈래 × 씨앗 12 = 11,040, 실패 0)

`scripts/qa/census-elem-stem-frames.ts` · `scratch/census-elem-stem-frames.json`

수식·숫자만 지우고 남은 글자가 같으면 같은 틀.

| | |
|---|---:|
| 소단원 | 230 |
| 최저 | **4** |
| 평균 | 15.2 |
| 최고 | 47 |
| 10 미만 | **92** (40%) |
| 정확히 4 | 12 |

학년 최저: 초3 5 · 초4 4 · 초5 4 · 초6 4. 10미만: 초3 3곳 · 초4 37 · 초5 26 · 초6 26.

⚠️ **이 평균 15.2를 「이미 10갈래가 있다」로 읽지 마라.** 최고 47·40이 **막대그래프·그림그래프**다. 한글 소재·항목명은 지문이 못 지운다. 같은 문항류가 사과/배로 갈라진 것이다. 그 지문을 키에 붙이면 한 시험지에 「이름만 다른 같은 막대그래프」가 여러 개 들어간다 — 숫자만 다른 같은 문제의 다른 얼굴.

그래도 이 과대 센서에서조차 **최저 4 · 10미만 92곳**이다. 최저가 10 미만이면 「풀렸다」가 아니다.

## 5. 안 바꾸고 푸는 길 (규칙 약화 아님)

| 길 | 값 | 일일테스트 |
|---|---|---|
| 확인테스트가 여러 소단원을 묶음 | 초6 대단원 4소단원×4=16이면 정원 8은 가능 | **안 됨.** daily는 진도 한 소단원 |
| 일일을 대단원으로 | 12~24갈래 | 가능하려면 `resolveRange`와 화면 형태(D-07). 옆 소단원 미이수 문항이 섞임 |
| 형식 3종으로 가르기 | 갈래 +0 (이미 같은 류로 두기로 함) | 같은 문제가 객·서로 두 번 |
| 결합형 | 문형 2개, 미적재 | 돼도 4→6 |
| 같은 키에 행만 더 쌓기 | 가족 크기만 커짐. 갈래는 4 | 안 풀림 |

일일테스트 8문항을 **키 없이** 채우는 제품 경로는 없다.

## 고를 수 있는 안

### 안 1 — 키 유지 (지금)

- 키 예: `elem:초6|2-6-4 구 알아보기와 여러 가지 모양 만들기|심화`
- 초등 230곳: **평균 4 · 최저 4 · 10미만 230**
- 깨지는 것: 0
- 되돌리기: 해당 없음
- 한 줄: **키는 그대로. 일일테스트는 4문항이 상한. 확인테스트만 소단원을 묶으면 8이 된다.**

### 안 2 — 지문(센서 ㉡)을 키에 붙이기 — 추천하지 않음

- 키 예: `elem:초6|…|심화|<지문해시>`
- 초등 230곳(과대): 평균 15.2 · 최저 4 · 10미만 92
- 깨지는 것: 적재 1,751행을 이관하지 않으면 한 시험지에 같은 문제 두 번. 이관하면 REVIEWED_ARRANGEMENT 61개 무효.
- 되돌리기: UPDATE 원장 필요. `--revert`는 DELETE라 부족.
- 한 줄: **평균은 10을 넘지만 막대그래프 항목명을 다른 류로 센 거짓 평균이다. 쓰면 같은 그림 문항이 한 장에 여러 개 들어간다.**

### 안 3 — 핸들러에 문형 id를 붙이고, 10 미만인 소단원에는 **새 틀을 짠 뒤** 옛 키를 남기지 않고 이관

- 키 예: `elem:초6|2-6-4 구 알아보기와 여러 가지 모양 만들기|04` (중등 `mid:책|중단원|번호`와 같은 자리)
- 초등 230곳: 지금 코드만으로는 최저 4. **새 틀을 몇 개 짤지에 달림.** 최저를 10으로 못 박지 않으면 풀린 것이 아니다. 소단원당 +6이면 +1,380유형.
- 깨지는 것: 1,751행 이관 · 그림배치 맵 61개. 섞이면 같은 문제 두 번.
- 되돌리기: before/after UPDATE 원장. 새로 짠 유형의 INSERT만 `--revert`.
- 한 줄: **일일테스트 10문항을 초등에서 내려면 키와 함께 문항류 자체를 더 만들어야 한다. 키만 바꿔서는 안 된다.**

규칙을 「한 시험지에 같은 류 둘」로 푸는 안은 없다.
