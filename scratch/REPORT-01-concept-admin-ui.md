`전체 차시 735` → 학년 카드 › 단원 제목 › 차시 줄(코드 · 이름 · 강의 상태 알약)을 **전부 펼친** 보기(`ConceptUnitTree.tsx`). 묶음은 `gradesOf`·`chaptersOf`·`sectionsOf`(단원 피커와 같은 함수). 차시를 누르면 오른쪽 판이 그 차시로 선다(`GET /api/concept/lectures?unitId=`). 가장 긴 차시 이름(41자, `1-1-2 받아올림이 두 번, 세 번 있는 (세 자리 수)+(세 자리 수)`)은 줄을 바꿔 전부 보인다. `이번 주 진도` 로 돌아온다.

### 1.4 강의 등록·게시 — 관리자만 (D-124 ⑻⑼)

- 강의 목록은 **서비스 공용** — 모든 원장 계정이 같은 강의를 본다. 쓰기(등록 · 게시 · 게시 내리기 · 다시 게시 · 끝까지 봤다 · 주소 넣기)는 `isAdmin` 만. 관리자가 아니면 판의 단추 자리에 `관리자만 바꿀 수 있습니다.` 한 줄, 머리의 `meta.json 으로 등록` 도 없다. **라우트가 따로 또 막는다**(`authorizeAccount(request, true)` — 관리자 · 승인 · 같은 사이트).
- `meta.json 으로 등록` → 판 자리에 붙여넣기 칸 → `parseLectureMeta` → `planRegistration`(등록 CLI 와 **같은 계획기** — 한계 · 같은 잡 ID/같은 주소 멱등 · 차시를 지어내지 않기) → **초안**. 실패는 해석기·계획기가 낸 «왜»를 그대로 보인다. 차시는 meta 의 `unitCode` → 없으면 지금 고른 차시. 둘 다 없으면 화면 문구로 거절한다(계획기의 `--unit` 문구는 CLI 용이라 화면에 안 싣는다).
- 게시 조건은 서버가 `checkPublish` 로 낸 `gate` 를 그린다 — ✗ 는 막는 것(관문 문구 그대로), ! 는 알리는 것(`아직 끝까지 시청하지 않았습니다. 게시 전 시청을 권장합니다.`), ✓ 는 막히지 않은 조건. 게시 단추는 `gate.canPublish` 로만 잠긴다 — **권장(끝까지 보기)은 잠그지 않는다**, 그 아래 `끝까지 보지 않아도 게시할 수 있습니다 — 권장입니다.`(D-124 ⑻).
- 상태 전이는 리드 결정(브리프 §5)대로 순수 함수 한 곳 `src/lib/concept/lectureTransition.ts`:
  초안 → 게시(관문) · 게시 → 내림(«게시 내리기») · 내림 → 게시(«다시 게시», 관문 다시) · **게시 → 초안 없음** · `publishedAt` = 마지막으로 게시한 시각(내려도 안 지운다) · **영상 주소가 바뀌면 `reviewedAt` 을 비운다**(같은 영상의 youtu.be 주소는 바뀐 것이 아니다 — 정규형끼리 견준다). 라우트(PATCH)는 이 함수를, 화면 단추는 이 모듈의 전이표(`LECTURE_TRANSITIONS`)를 읽는다.
  쓰기는 읽은 행의 `status`·`videoUrl` 을 조건으로 건 `updateMany` — 사이에 다른 창이 바꿨으면 409.
- 영상 자리: 주소가 있으면 `youtube-nocookie` 임베드(원장님 쪽은 **앞으로 감기를 막지 않는다** — 평범한 iframe). 없으면 종이 판서 바탕에 제목만.
- «AI 보충 강의» 고지는 이 화면에만(D-124 ⑹) — 판 아래 한 줄 + ✓ 줄에 고지 원문.

### 1.5 끝까지 본 학생 · 안 본 학생 이름 (D-125 ⑹)

- 반 × **게시 강의**마다 `countWatchedToEnd` 의 n/m. 막대 단추를 누르면 표 아래 한 줄이 펼쳐져 `«강의 제목» 아직 끝까지 안 본 학생 k명` + 이름(반 목록 순서). 원장님 소유 반만, 퇴원 학생 제외.
- 🔴 n/m 과 이름 목록은 **같은 호출 한 번**에서 나온다. 그리고 **계약이 어긋남을 거절한다** — `conceptWatchSchema` 가 `watched + pending.length === total` 을 요구하고 서버가 응답을 그 계약으로 검사하므로(`jsonOk`) 어긋난 응답은 화면까지 오지 못한다.
- 시청 기록 읽기도 좁혔다 — **내 반 학생 × 최근 진도 차시의 게시 강의**만 묻는다.
- 학생 로그인 전이라 기록이 비어 있다 — 0/m 이 정상이고, 그때는 표 아래 `아직 학생 시청 기록이 없습니다. 학생 로그인이 열리면 끝까지 본 학생이 여기에 쌓입니다.`

관례는 기존 라우트를 따랐다 — 세션·승인·관리자·같은 사이트는 `authorizeAccount`(관리자 화면 라우트와 같은 도우미), 응답은 `jsonOk`/`jsonError`.

### 3.3 변이 — 브리프 §3 «①~③ 가드를 하나씩 끄면 빨개지는가»

하네스 `scripts/qa/mutate-concept-admin.ts` — 판정 순서는 concept-port 의 것과 같다(㉠ 음성 대조 → ⑴ 앵커 정확히 하나 → ⑵ 파일이 바뀌었나 → ⑶ 탐침 산출물이 바뀌었나 → ⑷ 실패한 시험 **이름**). 순수 함수 가드는 탐침으로 변이 전후를 견주고, 라우트·화면 가드는 모킹 없이 부를 수 없어 탐침이 없다 — 그때는 ⑷ 의 시험 이름으로만 빨강을 판정하고, 초록이면 «살아남음» 이 아니라 **판정 보류**로 둔다(뜻이 안 바뀐 변이인지 가드가 없는 것인지 못 가른다). 원복은 바이트로 `finally` 에서, 끝나고 md5 대조.

**경위(정직하게):**
1. 첫 실행(서식 확정 전 코드) — **메모리 부족으로 바깥 셸이 강제 종료**됐다(다른 프로젝트의 개발 서버가 2GB 가까이 쓰는 중이었다). node 하네스는 살아서 끝까지 돌았고 파일을 전부 되돌렸다(md5 ✓ · 앵커 grep ✓ · 떠돌이 탐침 없음). 결과 11/13 빨강 · 살아남음 0 · **판정 거부 2**(§5-초안 · §5-관문 — 변이 **전** 탐침부터 못 떴다: 그 시각 여유 메모리 232MB. 가드 탓이 아니라 측정 실패라 빨강으로 치지 않았다).
2. 커밋 훅의 prettier 가 앵커 하나(③-이름의 `pending:` 한 줄)를 네 줄로 쪼갰다 — 서식 뒤에 앵커가 0개가 됐다(⑴ 이 판정 거부로 잡았을 자리). 앵커를 확정 코드의 모양으로 고치고 **확정 코드에 13개 전부 다시** 돌렸다(아래 표). 이 재실행도 바깥 셸은 메모리 부족으로 종료됐고 node 는 계속 돌았다.

3. 두 번째 실행에서 탐침·러너가 또 메모리 부족으로 못 떠(그 시각 여유 397MB — 다른 세션의 `tsc` 둘이 3.3GB) ③·§5 일곱이 판정 거부됐다. 같은 탐침을 손으로 돌리면 3초에 멀쩡했다 → 하네스를 **측정 실패만 다시 재게** 고쳤다(출력 없음 · «빨간데 이름 없음»일 때 최대 3회 — 빨강은 여전히 이름 댄 실패뿐).
4. 세 번째(일곱을 한 번에)는 **기준 시험(음성 대조)의 러너가 세 번 다 종료 코드 `3221225794`(= `0xC0000142`, 프로세스 초기화 실패)로 못 떠** 변이를 걸기 **전에** 멈췄다 — 소스는 한 줄도 안 바뀌었다. 그 뒤 vitest 가 다시 뜨는 것을 확인하고(전이 19/19) 묶음을 나눠 다시 돌렸다 — §5 셋 → ③ 넷. 한 번에 뜨는 러너가 적어 둘 다 끝까지 판정했다.

## 4. 못 본 것 — 로컬 DB 가 없어 E2E 를 못 돌렸다

확인한 것: `docker` 명령이 PATH 에도 `C:\Program Files\Docker` 에도 없다 · `postgresql*` 서비스 없음 · 5432 청취 없음. 그래서 라우트는 **인메모리 가짜**(`prismaTestDouble` — 강의·시청 두 모델을 얹었다)로만 돌았다. 공유 DB 는 읽지도 않았다(`DATABASE_URL` 을 닿지 않는 `127.0.0.1:1` 로 두고 개발 서버·빌드를 돌렸다).

**그래서 못 본 것:**

1. **실제 Postgres 에서의 질의** — `class.findMany({ select })` · `student.findMany({ where: { classId: { in } }, select })` · `conceptLecture.findMany({ where: { OR: [...] } })` 의 모양은 `tsc`(Prisma 형)가 받쳤지만, 결과의 **뜻**(정렬·필터)은 가짜가 흉내 낸 것이다.
2. **동시성** — 같은 잡 ID 두 창 동시 등록(P2002 → 409 경로)과 `updateMany` 조건부 쓰기(409)는 가짜가 흉내만 낸다. DB CHECK 다섯(«게시면 주소 있음» 등)도 가짜가 흉내 낸 것이다(`assertConceptLectureChecks`).
3. **로그인한 원장님의 실제 화면** — 개발용 시안 페이지는 로그인 없이 픽스처로 그린다. 실제 세션으로 관문(`proxy.ts` → `/api/concept` → `concept` 메뉴)을 지나 응답을 받는 길은 **단위 시험**(`accountRouteAllowed`)으로만 봤다.
4. **원장님 실데이터** — 원장님 계정의 실제 반 수 · 반 이름 · 개별진도반. 특히 개별진도반은 반 진도 행이 없어 이 표에서 `진도 기록 없음` 으로 보인다(리드가 정할 것 2).
5. **실제 유튜브 영상 임베드** — 가짜 영상 ID 라 실물 재생을 못 봤다. `next.config.ts` 에 CSP 헤더가 없어 막히지는 않을 것으로 보이나 확인 안 함.

## 5. 리드가 정할 것

**원장님께 여쭐 것 (D-07 — 모양·표시)**

1. **강의가 둘 이상 게시된 차시의 «끝까지 본 학생»** — 지금은 강의마다 막대 한 줄(시안은 한 줄). 한 줄로 합치려면 «그 차시의 게시 강의를 **전부** 끝까지 본 학생 n/m»으로 셈을 새로 정해야 한다(펼치면 «하나라도 덜 본 학생»). 캡처 `expanded-1536.png` · `mockup12-1536.png` 의 중1 B반.
2. **개별진도반은 표에서 `진도 기록 없음`** — 학생마다 진도가 갈린 반은 반 진도 행이 없다(`deriveClassProgress` 가 일부러 안 만든다). 실데이터로는 연계 두 반 중 MS2A 가 그렇다(`noProgressReason.ts` 주석: 학생 10명이 단원 4개로 갈림). 기존 화면과 같은 판정이라 새로 판정하지 않았다(브리프 §1.1). 학생별 최신 차시를 모아 보일지는 새 결정이다.
3. **시안에 없던 모양 전부**(§2 #10) — 특히 **전체 차시 보기**(학년 카드 · 단원 제목 · 차시 줄 · 따라 내려오는 판)와 **meta.json 붙여넣기 칸 · 주소 넣기 칸**. 캡처 `tree-1536.png` · `blocked-1536.png`.
4. **시안의 요일 오류** — 시안 곳곳의 `9월 15일 (월)` 은 `(화)` 가 맞다. 구현은 달력을 따른다.
5. **처음 열 때 고르는 반**(§2 #9)과 **판이 표 아래로 내려가는 폭**(본문 1000px 이하 — 1280 노트북) — 1366·1280 캡처로 확인 요망.

**리드가 정할 것 (규칙·병합)**

6. **게시 중인 강의의 주소는 못 바꾼다**(`VIDEO_EDITABLE_STATUSES = [draft, archived]`) — 브리프 §5 밖에서 더했다. 학생이 보던 영상이 말없이 바뀌고 이미 쌓인 «끝까지 봤다»가 다른 영상의 것이 되기 때문이다. 바꾸려면 내리고 → 바꾸고 → 다시 게시. 유지할지.
7. **«끝까지 봤다»는 되돌리기가 없고, 이미 찍힌 강의는 다시 찍지 않는다**(409). 주소를 바꾸면 비워진다(§5 결정). 되돌리기가 필요하면 전이를 하나 더한다.
8. **새 메뉴가 모든 기존 계정에 켜진다** — `disabledMenus` 가 «끈 목록»이라, 관리자가 메뉴를 좁혀 둔 계정(예: `library` 만)에도 «오늘의 개념»이 새로 열린다. 그 계정이 보는 것은 공용 강의 목록과 **자기 반**뿐이지만, 기본 꺼짐을 원하면 데이터 한 번 손봐야 한다(스키마 변경 없이 `disabled_menus` 에 `concept` 추가).
9. **병합 충돌 예고** — `student-auth` 와 나란히 돌았다. 이 워크트리가 공용 파일 넷을 고쳤다: `src/lib/accountRouteAccess.ts`(+2줄 — 학생 경로를 여기 선언하면 겹친다) · `src/contracts/accountAccess.contract.ts`(메뉴 한 줄 · enum · max) · `src/mocks/prismaTestDouble.ts`(강의·시청 모델 — 학생 쪽이 시청 기록 쓰기를 얹으면 같은 자리) · `src/components/unified/UnifiedWorkspace.tsx`. 기준 뒤 main 의 새 커밋(`5ef39b9c`)은 문서 두 줄뿐이라 겹치지 않는다.
10. **시청 기록 «읽기 범위» 가드는 변이로 못 잡는다** — 서버가 시청 기록을 내 반 학생 id 로 좁혀 묻는데, 그 조건을 지워도 응답은 같다(계산이 반 목록으로 한 번 더 거른다). 응답에는 새지 않지만 «남의 반 기록을 읽지도 않는다»는 지금 코드 리뷰로만 지켜진다. 실DB 시험(E2E)이 생기면 질의 로그로 잠글 수 있다.
