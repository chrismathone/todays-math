## PNG 출력 정책

웹앱은 SVG 내려받기와 SVG 복사 버튼을 없애고 PNG 저장만 제공한다.

- `src/lib/figure/imageFilename.ts`: 로컬 시각 `yyyymmddhhss_난수6자리.png`. 요청한 형식 그대로 월·일·시·초를 쓰며 분은 포함하지 않는다. 파일 충돌은 브라우저가 `(1)`, `(2)` 등을 붙여 처리한다.
- `src/lib/figure/exportImage.ts`: 다운로드 함수는 확장자 `.png`와 PNG 데이터 URL을 모두 검사한다. SVG를 `.png`로 이름만 바꿔 저장할 수 없다.
- `src/App.tsx`, `src/PngPreview.tsx`: 결과 미리보기도 PNG로 변환해 우클릭 저장이 SVG로 빠지지 않게 했다.

각 호스트 앱의 결과 화면과 내려받기 경로에도 같은 정책을 반영해야 한다. 웹앱 전용 `FigureEditor.tsx` 전체를 복사하면 호스트 앱의 도형 적용·시험지 저장 흐름이 바뀔 수 있으므로 필요한 저장/클립보드 부분만 옮긴다.

`StudioFigureSaveResult`의 `svg`, `dataUrl`, `originalImage`는 계속 내부 저장용으로 필요하다. `svg`는 편집 원문이고 `dataUrl`은 조판·맞춤한 SVG이다. 외부 내보내기를 PNG로 제한한다는 이유로 이 필드를 삭제하거나 PNG로 바꾸면 재편집에 문제가 생긴다.

## 서버 저장 연동: 호스트 앱별로 연결

웹앱의 «이미지 저장»은 PNG 다운로드 후 `onSave`를 기다려 서버에 편집 원문과 최신 썸네일을 함께 저장한다. 성공 시 최근 작업 목록이 즉시 다시 읽히며, 같은 도형을 다시 저장하면 같은 항목을 갱신한다. 서버 저장 실패 시 PNG는 내려받고 오류와 재시도 안내를 표시한다.

공용 편집기는 특정 서버나 Supabase에 의존하지 않는다. 시험지 한글화와 todays-math는 각자 기존 저장소에 비동기 `onSave`를 연결하면 된다. 전달 데이터 예:

```tsx
onSave={async (result) => {
  await persistFigure({
    svg: result.svg,
    dataUrl: result.dataUrl,
    originalImage: result.originalImage,
    // 호스트 앱의 그림 ID, 최신 썸네일도 함께 저장
  });
}}
```

웹앱 전용 구현 파일은 `src/App.tsx`, `src/lib/aiClient.ts`, `src/lib/history.ts`, `src/RecentWork.tsx`, `server/jobs.ts`, `server/ai.ts`, `api/ai.js`와 `supabase/migrations/20261022140000_figure_save.sql`이다. 이 파일들을 다른 서비스에 그대로 넣을 필요는 없다.

- 새 `save` API는 AI 모델이나 토큰을 사용하지 않으며, AI 키가 없어도 저장할 수 있다.
- 도형의 비밀 저장 키는 이 브라우저의 로컬 기록에 보관한다. 서버는 공개 ID로만 목록을 내보낸다.
- 같은 저장 키로 저장하면 원문·썸네일·저장 시각을 갱신한다. AI 작업의 기존 토큰 수는 유지한다.
- 명시적으로 저장한 도형은 최근 목록 20개 밖으로 밀려도 서버에 남는다. 늦은 AI 완료 응답은 사용자가 저장한 최신본을 덮어쓰지 않는다.
- 다른 브라우저/다른 사람의 그림 또는 이 버전 이전에 만들어져 비밀 키가 없는 기록은 첫 저장 시 자신의 새 저장본을 만든다. 남의 원본을 덮어쓰지 않는다.
- `onAutosave`는 브라우저 임시저장을 유지한다. 서버에 최종본을 반영하는 시점은 «이미지 저장»이다.

다른 저장소에 반영한 뒤에는 공용 회귀 검사와 함께 «저장 → 닫기 → 최근 작업에서 재열기 → 수정 → 다시 저장 → 썸네일 및 재열기 내용 갱신»을 확인한다.

이 웹앱의 공용 최근 작업·브라우저 전용 이어서 편집·관리콘솔·사용 통계·IP 차단은 앱 전용이다. [최종 검수 기록](../../reviews/2026-10-22-webapp.md)을 참고한다.
