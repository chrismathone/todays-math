Strict identical-review rebinding implementation and GF14 demo

New utility: scripts/import/exam-twin/rebind-identical-review.mjs.
Export: rebindIdenticalReview({ oldRoot, selectionIndex, rawCommit, rawSolveDir, newRoot, workspace = process.cwd() }). CLI positional arguments have the same order, excluding workspace; invoke from the task checkout. The selection JSON is exactly {questions:[{n,id,candidate,sha256}]}, where candidate is the CURRENT original-author file path and sha256 is its raw SHA-256. Paths resolve against workspace. Select the complete old reviewed ID set, with unique IDs and numbers. This is not an authorization mechanism for choosing a different author lineage: the caller supplies the authoritative CURRENT selection.

The utility uses currentPackage, auditCollectedPack, direct freeze, blind and prepareSealedReview. It checks actual original-author IDs and raw SHA, full frozen private candidate byte identity, candidate/student/asset/solve digests, report bindings, actual ancestor Git raw blobs, working/blind raw byte identity and readable independent solutions. Report reuse begins only after all selected payloads pass. JSON serialization in author input and input-file location may differ; the normalized frozen private candidate must remain byte-identical. Any answer, solution, source, grade, classification, metadata or asset change throws NEW_REVIEW_REQUIRED. There is no bypass flag.

Original report bytes are copied without modifying their statuses/checks/evidence. Old trees and raw proof trees have complete before/after hash maps in each rebind receipt. New package gates remain conservative; all prior held reasons must survive the collected audit. No new mathematical, grade, candidate, rights, source or native approval is inferred. Source/rights/similarity/native holds remain separate. loadable=0 and DB writes=0.

Outputs must be NEW and inside the task worktree, outside dependencies and Git internals, outside old/raw/author trees, and without symlink/junction aliases. Existing paths are refused. A failed or interrupted NEW root is retained as incomplete evidence, with no success receipt; do not reuse it. The helper invokes existing tools synchronously and is intended for a quiescent review checkout, not concurrent writers. No existing implementation, README, current selection ledger or controller is changed.
