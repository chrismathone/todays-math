# Grid-measure support candidate — bounded proposal, not integration

The sole candidate implementation is `own-gridMeasure.ts`. No server or UI code is patched. It takes server-owned decoded grayscale data and returns either null or an explicitly advisory measurement. It has no `passed`, approval, snapping, persistence, model-routing or SVG-writing behavior. TypeScript execution and type checking are PENDING.

## Current server path and integration option (Root owns implementation)

`figure-comparison.ts::buildFigureComparisonImage` already validates the original data URL and reconstructed SVG, substitutes math labels, acquires the shared export browser, loads two images, waits for decoding and screenshots the comparison. `figure-engine.ts` uses that comparison for the final review and retains `passed && issues.length===0` and `source-and-rendered-images`. Preserve its cancellation, timeout, network interception, page release and final review attempts. Do not import the external browser-only `measureGrid(dataUrl)` into Node. Root package.json has no direct sharp dependency; this proposal adds none.

After the existing decode completes, use that SAME page and decoded image references to draw each image onto a detached white-backed analysis canvas sequentially. Composite transparency onto white before converting RGB using a documented 299/587/114 luma rule. Use max side <=1400, max total <=2M and safe positive dimensions before allocating or reading pixels. Prefer an analysis size near the existing 900px panel to avoid needless serialization. Read canvas pixels in page.evaluate and transfer a bounded row-major ordinary byte array to Node; call the pure function there. Do not start another browser or enable arbitrary page scripts/resources. Feasibility under current JavaScript-disabled CDP evaluation, image taint rules and serialization/memory budget still needs Root's runtime check. Existing decoder resource limits are not proven safe by the bounded grayscale function: compressed source size does not bound decoded pixels. Reuse existing decode rather than introduce another decode.

Treat each source/reconstruction image independently. A detected square lattice is not proof of graph paper: a regular table can have exactly the same pixels. Null covers invalid inputs, insufficient evidence, small spacing, nonuniform/missing lines, cropped borders, nonsquare spacing or absent orthogonal support. Conservative false negatives are acceptable. The candidate does not extrapolate cropped edges or invent a missing line.

For derived overlays only, reuse the same page to add peripheral ticks in a reserved margin around the two original-image panels. Never draw replacement figure lines or move points. Preserve the original input bytes and original unannotated image; screenshot a new comparison derivative. If either side cannot be measured safely, leave the original comparison unchanged or clearly mark measurement unknown; never silently invent shared coordinates. A count mismatch remains visible (e.g. source8x8 vs reconstruction9x8); do NOT copy the external instruction to ignore differing grid counts. The final visual/model review remains necessary and cannot be flipped to passed by this helper.

## Coordinate contract and annotation provenance

Array origin is TOP LEFT, x right, y down. The measured lattice's display origin may be its BOTTOM LEFT: ordinal tick j is at analysis y = y.last - j*y.cell. These are derived ordinal indices, NOT original printed coordinates or mathematical axis units. Keep separate analysis width/height, decoded natural dimensions, panel rectangle and contain transform.

For an image natural size nw,nh, analyzed wa,ha and a panel rectangle px,py,pw,ph: contain scale t=min(pw/nw,ph/nh), imageLeft=px+(pw-nw*t)/2, imageTop=py+(ph-nh*t)/2. An analysis coordinate ax,ay maps to imageLeft+ax*(nw/wa)*t, imageTop+ay*(nh/ha)*t. Keep x/y analysis resampling scales separate rather than assume they round equally. SVG viewBox origins/preserveAspectRatio letterboxing are another transform: avoid the external naive independent width/viewBox and height/viewBox conversion; measure the rendered pixels or obtain a validated actual transform before using metadata.

Margin text must explicitly say `DERIVED GRID INDEX — NOT SOURCE LABEL` (Korean equivalent in actual product). Colour alone is insufficient. Keep indices away from printed labels and never add them to FigureSpec, authored labels, source extraction, student payloads or storage. Do not tell a model to copy red indices as source numbers. Do not force integer endpoint coordinates from a heuristic lattice. Half-cell endpoints, nonzero source origins and clipped partial cells may be legitimate and require independent review.

## Candidate limits and differences from reference

The external implementation lacks strict width/height/gray shape validation and uses Math.max(...profile), which is unnecessary stack spread. The candidate checks bounds before allocation, accepts only byte arrays or ordinary arrays with exact length, copies validated bytes and scans max in a loop. Samples <=4000 values; projection arrays <=1400, centres <=61 per axis. Dense loops and line-support probes are bounded. No new image-decoding dependency exists.

The external algorithm infers skipped lines/reconciles spans; this small candidate deliberately declines missing/cropped evidence and checks sustained line support in both directions. It may reject low-contrast, dashed, obstructed, skewed, very small or non-square scan grids. It still cannot disambiguate a table or repeated text layout that genuinely mimics a lattice. It is not a security sandbox for malicious proxies/getters or shared-memory writers; pass only internal decoded bytes. All 32 fixtures are FUTURE runtime expectations, not executed TS results.
