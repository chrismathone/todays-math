# 영어 듣기 자료 초안 — 2026년 10월 3일

[samples.json](./samples.json)은 청취 테스트에 사용할 자체 창작 영어 대본 3개와 한국어 번역, 각 3개의 오지선다 문항을 담고 있습니다. 기존 기출문제나 저작물을 복사하지 않았습니다.

**Kokoro-82M v1.0으로 음원 생성을 완료하고 운영 사이트에 교사 청취용 초안 3개를 등록했습니다.** 대본·번역·문항·해설은 AI 초안이며, 사람의 내용·음성·구간 검수는 미완료입니다. 수준 표시는 목표 수준이며, 실제 학습자에게 난이도를 검증한 결과가 아닙니다.

사이트에서 `오늘의 영어 → 영어듣기`로 이동한 뒤 `[청취 샘플]` 제목을 찾으면 됩니다. 로컬 청취 페이지는 저장소 루트의 `.qa-artifacts/listening-samples/20261003/index.html`입니다. 학생 배정·공개는 하지 않았습니다.

| 자료 | 목표 수준 | 형식 | 영어 대본 단어 수 | 지정 음성 |
| --- | --- | --- | ---: | --- |
| sample-01 | 중1 · A2 | 학교생활, 2인 대화 | 86 | A: af_heart / B: am_michael |

단어 수는 각 자료의 `turns[].text`만 공백으로 나누어 계산했습니다. 축약형과 약어는 각각 한 단어로 세며, 화자 표시·제목·번역·문항은 포함하지 않습니다. 대본의 시간·가격·인원은 발음용 영단어로 표기했습니다. sample-03의 여러 턴은 같은 화자의 담화를 문단으로 나눈 것입니다.

## 텍스트 자체 검토

- 자료별 단어 수가 지정 범위에 드는지 확인했습니다.
- 자료마다 문항 3개, 문항마다 한국어 보기 5개와 단일 정답을 갖추었습니다. `answerIndex`와 `evidenceTurnIndices`는 모두 0부터 시작하며, 근거 인덱스는 해당 자료의 `turns`를 가리킵니다.
- 영어 원문과 번역의 의미를 대조하고, 정답과 해설이 지정된 근거 턴에 맞는지 검토했습니다. 다른 문항의 보기만으로 정답이 드러나지 않도록 각 문항이 서로 다른 정보를 묻게 했습니다.
- sample-02는 선택하지 않은 급행버스와 최종 선택한 일반 버스의 출발 시각·요금을 구분했습니다. 한 사람의 요금과 두 사람의 합계도 대본에 각각 명시했습니다. 부정 표현은 운전 선호와 급행버스의 정차 여부에 포함했습니다.
- sample-03은 방송의 목적, 직접 가져올 준비물이라는 세부 정보, 장소 선정의 이유를 각각 묻습니다.

텍스트 자체 검토 후, 위 표의 세 음성으로 로컬 CPU에서 실제 WAV·MP3를 생성했습니다. 클라우드 TTS나 유료 API는 호출하지 않았으며 Docker도 실행하지 않았습니다. 대본·문항 제작에는 연결된 Codex 구독 모델을 사용했습니다.

## Kokoro 조사 및 재현

[공식 모델 카드](https://huggingface.co/hexgrad/Kokoro-82M)는 82M 파라미터, Apache 2.0 가중치와 24kHz 출력 예제를 제공합니다. 상업적 환경에 배포할 수 있는 모델로 안내되어 있습니다. [공식 음성 목록](https://huggingface.co/hexgrad/Kokoro-82M/blob/main/VOICES.md)의 영어 음성은 미국식 20개, 영국식 8개입니다. 이번에는 미국식 여성 `af_heart`, 미국식 남성 `am_michael`, 영국식 여성 `bf_emma`를 썼습니다.

공식 음성 가이드는 아주 짧은 발화와 긴 발화에서 품질 편차가 날 수 있다고 안내합니다. 따라서 현재 대화 샘플의 짧은 대사, 숫자, 부정어와 문장 끝 억양은 직접 들어볼 확인 항목입니다. 음성별 표의 평점도 제작자의 추정이며 우리 서비스의 청취 평가 점수는 아닙니다.

실행기는 별도 프로젝트인 [kokoro-onnx](https://github.com/thewh1teagle/kokoro-onnx) 0.6.1입니다. `model-files-v1.1` 릴리스의 파일명 `kokoro-v1.0.onnx`를 사용했습니다. 릴리스 자산 묶음 버전과 원 모델 버전을 구분합니다. 다운로드 주소·파일 해시·패키지 버전·생성 결과는 [audition-results.json](./audition-results.json), [requirements-kokoro.txt](./requirements-kokoro.txt)에 남겼습니다.

현재 Windows 작업 환경에서 다시 생성하려면 다음 명령을 실행합니다. 모델·음원·가상환경은 Git에 포함하지 않습니다. 다시 생성한 음원을 운영 세트에 자동 덮어쓰지 않습니다.

```powershell
.qa-artifacts/listening-tts-venv/Scripts/python.exe scripts/content/generate-listening-samples.py --samples docs/listening-samples/20261003/samples.json --models .qa-artifacts/listening-tts-models --out .qa-artifacts/listening-samples/20261003-new
```

새 컴퓨터에서는 Python 가상환경을 만든 뒤 `pip install -r docs/listening-samples/20261003/requirements-kokoro.txt`로 실행 환경을 준비하고, 결과 JSON에 기록한 두 모델 자산을 내려받아 SHA256을 확인합니다. 사이트의 자동 TTS 생성 기능을 추가한 것은 아니며, 이번 결과는 로컬 생성 후 기존 업로드 서비스를 이용해 등록한 청취 자료입니다.
