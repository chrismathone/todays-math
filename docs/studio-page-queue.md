# 자료 제작: 페이지 대기열과 검수 공간

2026-09-14, `/dev/unified#studio`.

- **전체 페이지 자동 인식**은 현재 파일의 모든 페이지를 등록한다. 렌더링과 AI 호출을 합쳐 최대 2개 작업만 실행하며, 완료·실패한 자리는 다음 대기 작업이 사용한다. 같은 페이지의 중복 실행은 막고 완료된 페이지는 일괄 실행에서 건너뛴다.
- 페이지·원본 파일·작업 탭 이동은 페이지 인식을 중단하지 않는다. 답변이 도착한 순서와 관계없이 같은 파일의 문항은 페이지 순서로 정렬되며, 사용자가 보고 있는 페이지를 강제로 바꾸지 않는다.
- **쪽별 진행**에서 대기·지면 준비·인식 중·완료·빈 페이지·실패·취소를 구분하고 해당 페이지로 이동한다. 실패한 페이지만 재시도할 수 있고, **AI 연결 → 현재 쪽만 다시 인식**은 완료된 쪽도 명시적으로 재처리한다.
- 취소 버튼과 왼쪽 AI 상태판의 취소 모두 대기열과 실행 중 요청을 중단한다. 새로 시작은 확인 후 이 작업실을 초기화한다. 이미 내 시험지에 담은 문항은 부모 작업 공간에 남는다. 새로고침이나 브라우저 종료를 넘어 작업을 복원하는 큐는 아니다.
- 정상적인 `problems: []` 응답만 **빈 페이지**로 분류한다. API 오류나 잘못된 응답은 실패로 남긴다. 붉은 도장은 편집 화면의 오버레이이며 원본 이미지·크롭·내보내기에는 들어가지 않는다. 직접 문제를 추가하면 숨겨진다.
- 학년은 파일 이름 옆에서 해당 파일 전체에 지정한다. 기존 문항과 새로 인식할 문항에 적용하며, 그 파일을 인식하는 동안에는 변경을 잠근다. 원문은 보존하고 초등 미리보기에서만 가분수를 대분수로 표시한다.
- 오른쪽 제목·중복 안내·학년 블록을 제거했다. 영역 편집과 일괄 처리 버튼은 34px로 줄였으며, 주요 작업 버튼은 기존 44px를 유지한다.
- 공통 `WorkProgress`는 실제 완료 수, 움직이는 표시, 경과 시간과 취소를 제공한다. 알 수 없는 처리량을 퍼센트로 추정하지 않는다. 검색·파일 불러오기·PDF 표시·OCR·도형·해설·로그인·작업 복원/저장·인쇄 준비에 사용한다. 긴 응답 대기는 구분하고 동작 줄이기 설정을 따른다.

## 검증

- 핵심 컴포넌트·큐·구독 연결·진행 표시 72개 테스트와 관련 회귀 84개 테스트 통과.
- Playwright 6개 시나리오 통과. 생성한 6쪽 PDF로 동시 요청 최대 2개, 뒤바뀐 응답 순서, 페이지 이동, 중복 방지, 표지 도장, 파일 전체 학년 적용을 검증한다.
- 실제 Next dev에서 기존 스캔 기출 6쪽을 렌더링하고 AI 응답을 대체해 대기열·도장을 확인했다. 최대 동시 요청 2개, JS 오류 0개, 1680·1440·1366·1024·390px 가로 넘침 0개. 실제 공통 CSS 아래에서도 편집 도구 34px를 확인했다.
- 실제 dev에서 기존 박스·도형 검수와 내보내기·저장 후 복원도 확인했다. 이번 대기열 검증에는 모델 과금 요청을 보내지 않았다.
- `npm run build`, TypeScript, 변경 파일 ESLint와 affordance 검사 통과. 기존 `tier-bench/g4` 파일 추적 경고 2개와 Prisma 설정 폐기 예정 안내는 동일하다.
