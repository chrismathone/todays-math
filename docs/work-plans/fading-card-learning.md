# 독립 SRS 카드 학습 — 사용자 결정과 구현 기준

2026-10-07. Claude·Gemini 3.1 Pro와 코드·기능 목록을 대조한 합의에 사용자의 최신 정정을 반영했다. 기능 연결 상세는 [내부 기능 검토표](srs-internal-integration-plan.md)에 있다. 이 문서는 요구사항이며, 구현·검증·배포 상태는 아래에 별도로 기록한다.

## 이번 범위

SRS는 다른 기능의 연동 없이 작동한다. 개념 은행, 본인 학생 인증과 복습 기록, FadingSource로 학습·일정·통계를 제공한다. 교재·강의·진도·문제은행·영어·AI 연결은 후속 어댑터이며 기본 OFF다. 이후 ON/OFF 전환은 기존 복습 기록이나 일정을 초기화하지 않는다. 권한 확인은 항상 유지한다.

| 단계 | 한 장씩 보여주는 활동 | 기록 |
|---|---|---|
| 1 | 용어와 종류를 보고 생각 → Space/Enter로 문장·강조된 핵심어 확인 → 처음 봄/들어 봄/알고 있었음 | 첫 학습 진단. FSRS 비갱신 |
| 2 | 핵심 빈칸. 현재 칩 선택·끌기·칩 글 입력 유지 | 실제 배치·오배치 순서 |
| 3 | 더 많은 조건·수식 빈칸 | 실제 배치·오배치 순서 |
| 4 | 보기 없이 핵심 답 직접 입력 → 모든 카드가 끝난 뒤 기준 답 대조 | 실제 실패와 미판정 표현, 최종 평가 한 번 |

이미 4단계에 선 개념의 복습은 답을 먼저 보여주지 않고 4단계에서 시작한다. 카드마다 입력 전에 모름/긴가민가/확실을 묻되 확신만으로 오답 처리하거나 일정을 바꾸지 않는다. 재학습은 기존 서 있는 단계부터 진행한다. FSRS 일정은 기존 묶음 단위로 최종 평가에서 한 번 갱신한다.

## 직접 입력과 대조

- 동일한 `typedKey` 규칙을 화면과 서버가 사용한다. 수식도 평범한 입력란과 결정적 별칭으로 받는다.
- 정규화한 정답과 일치하면 받아들인다. 다른 답이나 검수된 함정과 일치한 실제 오답은 기록한다.
- 알아보지 못한 표현은 즉시 오답으로 확정하지 않는다. 답을 미리 보여주지 않고 보류한다.
- 전체 카드가 끝난 뒤 내 답과 기준 답을 대조한다. 보류한 표현은 학생이 같은 뜻/다름으로 확인한다.
- 실제 오답·포기·대조 불일치가 있으면 기존 다시 규칙을 적용한다. 확신 진단과 수행 결과를 평균하지 않는다.
- 대조에 들어가기 전에 서버에 단계 결과를 저장한다. 새로고침해도 미판정 답이 남는다. 평가 요청 ID로 중복 일정 갱신을 막는다.
- 온라인 AI 채점과 학생 답안의 외부 API 전송은 이번 범위에 없다.

## 화면과 키보드

PC와 모바일을 각각 지원하고 미리 보기의 기기를 바꿔도 같은 풀이를 유지한다. 개념 카드는 작은 파란 제목 배지와 연두 핵심어 강조를 사용한다. 지운 답이 제목이나 주제에서 드러나지 않도록 공통 검사를 거친다.

입력란의 Tab/Shift+Tab은 빈칸 위치를 옮기고 입력 초점은 유지한다. Enter는 입력 제출, Space는 글자 사이 공백이다. 입력란 밖에서는 Space/Enter로 뒤집기·진행을 지원한다. 숫자 진단 키는 입력란이 열리기 전에만 사용하며 한글 조합과 229 키 이벤트는 가로채지 않는다. Escape는 일반 Tab 이동으로 나오는 길이다. 모바일은 계속 스크롤할 수 있고 내용이 더 있을 때만 아래쪽 페이드를 보여준다.

## 계약과 배포

기존 `fading.version = 1`과 학생 기록을 유지한다. 새 관찰·미판정·모드는 선택 필드로 추가한다. 저장 계약뿐 아니라 strict API 응답 계약도 읽기 호환을 먼저 배포한다. 화면에 받는 풀이 ID는 내용·함정을 포함한 기존 토큰이며 저장 ID와 다르다. 기존 `session.digest`는 완료한 4단계의 8자리 내용 지문으로 유지하고 진행 중인 풀이의 다른 용도로 쓰지 않는다.

카드 방식 배포 스위치는 새로 여는 풀이에만 적용하며 풀이의 모드를 고정한다. 이미 열린 기존 풀이는 기존 방식으로 끝낸다. 답이나 표적이 바뀐 풀이를 새 내용으로 조용히 재채점하지 않는다. 카드 방식의 4단계에 구형 칩 요청을 보내면 모드 충돌을 처리한다. 이 스위치와 추후 기능 연동 ON/OFF는 별개다.

의미 있는 추가 빈칸은 SRS 전용 덧씌움으로 검수한다. 공유 은행의 인쇄용 원문을 변경하지 않는다. 추가 빈칸·별칭 변경은 열린 풀이의 지문 및 기존 기록과의 호환을 확인한 뒤 적용한다.

## 상태

- PC/모바일 미리 보기, 개념 표기, 단일 카드, Tab 빈칸 이동, 조건부 스크롤 페이드와 새 Anki·직접 입력 실행 규칙·화면은 main에 병합됐다.
- 저장·strict API 응답·기존 내용 토큰을 함께 지원하는 읽기 배포 `f983856fe`의 운영 성공을 확인했다. 새 카드 방식의 기록을 쓰는 코드의 호환 기준은 이 배포다.
- 카드 규칙·저장·API·화면의 최종 490개 테스트와 320/390/768/1280 너비에서 네 번의 전체 흐름 및 43개 화면 검증이 통과했다. 직접 입력, 미판정 답 대조, 한 번의 평가, 수식 복습, Tab 입력 초점, Space 공백을 확인했다. 작업실의 실제 미리 보기 자료 생성 경로에서도 새 카드 방식과 기기 전환 후 카드·뒤집기 상태 보존을 확인했다. 브라우저 확인에는 외부 요청과 학생 API 쓰기가 없다.
- 측정 도구는 `scripts/qa/fading-screens/cards.mjs`, 결과는 `.qa-artifacts/fading-cards/results.json`이다. 이전 화면의 897건 측정과 기기 미리 보기·교사 화면 56건도 보존했다.
- 기본 ON 변경 `382adff77`은 읽기 배포·전체 흐름 검증 뒤에 병합했다. `MATH_FADING_CARDS`가 없거나 `on`이면 새 풀이가 카드 방식이고, `off`나 알 수 없는 값이면 새 풀이가 기존 칩 방식이다. 이미 연 풀이의 방식은 유지한다. 기능 연동 어댑터는 후속 작업이다.

입력 별칭에 없는 표현은 자가 대조로 확인한다. 새로고침 후 보존하는 입력 원문은 판정을 기다리는 답이며, 이미 일치한 답의 입력 원문은 재현하지 않는다. 해당 단계와 복습 기록은 보존한다. 추가 빈칸 덧씌움은 이번 배포에 포함하지 않았다.

추가 변이 검증에서는 이전 코드로 남아 있던 중복 실행이 결과를 덮어썼고 새 실행은 메모리 부족으로 끝났다. 그 결과를 전체 통과로 세지 않는다. 누락된 계약 시험 하나를 보완해 규칙을 제거하면 실패하는 것을 확인했고, 활성화 문 세 규칙도 같은 방법으로 확인했다. 최종 변이 자리 점검은 326건에 불일치 0건이며 전체 변이 실행 통과를 뜻하지 않는다. 이 근거와 오래된 실행 로그는 `.qa-artifacts/srs-card-internals/`에 보존했다.
