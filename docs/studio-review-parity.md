박스의 표시 좌표와 저장 이미지는 같은 원본 캔버스를 기준으로 계산한다.
문제 영역을 바꾸면 내부 도형을 새 문제 범위와 교차시켜 다시 자른다.
문자·정답·해설은 자동으로 바꾸지 않으며, 검수 상태를 되돌려 사용자가 다시 확인한다.
초등 가분수의 표시 변환과 편집 원문의 분리는 유지한다.

## Mathgen과의 범위 차이

현재 통합 dev는 **전체 페이지 자동 인식**을 누르면 최대 2쪽씩 처리하고
나머지는 FIFO 대기열에 넣는다. 페이지·파일·작업 탭을 이동해도 페이지 인식은 계속된다.
문항별 문자·도형 인식과 해설도 같은 대기열을 사용하며 문제를 이동해도 중단하지 않는다.
**문제 자르기**는 영역 편집에 집중하고, **OCR · 디지털화**는 왼쪽 원본과 오른쪽의
수식·도형 결과 카드를 넓게 비교한다. 원문 편집은 `내용 수정`에서 연다.
드래그를 마칠 때마다 문제를 추가하며, 선택한 박스의 삭제 버튼과 우클릭·Esc 취소를 제공한다.

Mathgen의 실제 `FigureEditor`를 이식해 그림 편집에서 연결했다. 선·곡선·도형·함수·수식,
이동·확대·되돌리기, 원본 비교, SVG 저장을 지원한다. `원본으로 다시 그리기`는 기존 구독 CLI로
실행한다. 원본 이미지, 편집 가능한 SVG, 출력용 이미지를 분리해 저장하고 다시 열어 편집한다.
문자 인식도 내부 도형 영역을 함께 받을 수 있으며, 이미 편집한 도형은 문자 재인식으로 덮어쓰지 않는다.

크롭의 `다음: OCR · 디지털화`는 아직 내용이 없는 문항의 OCR과 미생성 도형의 SVG 재작도를 실행한다.
페이지·문항 인식으로 검출된 도형도 같은 대기열에서 자동 재작도한다. 성공한 인식 내용은
텍스트와 SVG를 출력하며, 사용자가 명시적으로 고른 원본 이미지 출력과 편집한 SVG는 유지한다.
후보정은 신규 AI 응답과 기존 저장 내용의 렌더링에 적용한다. Mathgen의 실제 Python 엔진과
카탈로그를 연결했으며, 재작도 실패 시 원본을 유지하고 해당 도형만 다시 시도할 수 있다.
업로드 자체는 AI를 실행하지 않는다. 도형 자동 대조는 원본 이미지와 스펙/SVG를 비교하며,
Mathgen의 두 래스터 이미지 대조와는 다르다. [디지털화 통합 검증](qa/studio-digital-pipeline.md)을 참고한다.
진행 표시, 파일별 학년, 빈 페이지 도장의 검증은 [페이지 대기열 기록](studio-page-queue.md)을 참고한다.

## 검증

아래는 초기 PDF·영역 검수 구현의 검증 기록이다. 이후 화면 분리·도형 편집기 이식과
문항 대기열 통합은 [최신 검증 기록](qa/studio-review-redesign.md)을 참고한다.

원본 기출 스캔 PDF 6쪽의 글자 마스크와 문항 크롭을 실제 dev에서 확인했다.
원인은 폰트가 아닌 CCITT/JBIG2 이미지 디코더 누락이었다.
사용자의 PDF와 이미지 산출물은 저장소에 포함하지 않았다.

회귀 검사는 실제 브라우저의 드래그·우클릭·키보드, 부모/자식 박스 범위,
문항 검수 이동, 편집 후 상태 변경, 텍스트 내보내기에 도형이 유지되는 경로를 다룬다.
Claude 구독 CLI의 실제 `figures` 요청도 합성한 직사각형 문항으로 확인했다.
실제 요청은 HTTP 200과 도형 1개를 반환했고, 외부 API 키 결제 경로는 사용하지 않았다.

최종 결과: 관련 테스트 134개, 브라우저 시나리오 5개, `npm run build` 통과.
실제 dev의 1440·1366·1024·390px 화면에서 가로 넘침 없이 검수 이동이 가능했고,
도형을 포함한 시험지를 저장한 뒤 페이지를 다시 열어도 도형이 유지됨을 확인했다.
