## 확인한 누락과 수정

| 항목                | 통합 화면의 기존 상태                   | 수정한 동작                                                                      |
| ------------------- | --------------------------------------- | -------------------------------------------------------------------------------- |
| 스캔 PDF            | 배경·필기는 보이지만 글자 마스크가 누락 | 설치된 PDF.js의 WASM, CMap, 기본 폰트를 같은 서버에서 제공                       |
| 자동 인식 중 포인터 | 영역을 지정할 수 있는 십자 커서         | 진행 커서, 수동 드래그·키보드 지정 잠금, 완료·취소·실패 시 복귀                  |
| 지정 취소           | 마우스로 취소하기 어려움                | 우클릭·Esc로 현재 지정만 취소; 저장한 문제는 유지                                |
| 문제 박스 검수      | 좌표를 표시하는 점선만 존재             | 원본 위 선택·이동·네 모서리 크기 조절·추가·삭제                                  |
| 내부 도형           | 별도 영역·재검출·출력 연결 없음         | 주황 도형 박스, 부모 문제 안으로 제한, 직접 추가·삭제·그림 다시 찾기             |
| 문항 이동           | 오른쪽 목록에서만 이동                  | 왼쪽 고정 이전·다음·검수 완료 후 다음 이동                                       |
| 확인 상태           | 담음 또는 검수 중만 존재                | 페이지의 영역 확인과 문항 내용 검수 완료를 별도로 관리; 수정 시 확인 상태 무효화 |
| 텍스트 출력         | 내부 도형이 누락될 수 있음              | 검수한 도형 이미지와 크기를 전달; 원본 이미지 출력은 전체 크롭을 사용            |

박스의 표시 좌표와 저장 이미지는 같은 원본 캔버스를 기준으로 계산한다.
문제 영역을 바꾸면 내부 도형을 새 문제 범위와 교차시켜 다시 자른다.
문자·정답·해설은 자동으로 바꾸지 않으며, 검수 상태를 되돌려 사용자가 다시 확인한다.
초등 가분수의 표시 변환과 편집 원문의 분리는 유지한다.

## Mathgen과의 범위 차이

현재 통합 dev는 명시적으로 누른 **현재 페이지 인식**과 **그림 다시 찾기**를
구독 CLI에 연결한다. Mathgen의 업로드 직후 전 페이지 자동 순차 검출,
영역 확인 후 자동 2차 OCR, SVG 벡터화까지 같은 파이프라인으로 옮긴 것은 아니다.
이 검수 화면에서는 인식 결과를 직접 수정하고 문자 인식·해설 생성을 실행할 수 있다.

## 검증

원본 기출 스캔 PDF 6쪽의 글자 마스크와 문항 크롭을 실제 dev에서 확인했다.
원인은 폰트가 아닌 CCITT/JBIG2 이미지 디코더 누락이었다.
사용자의 PDF와 이미지 산출물은 저장소에 포함하지 않았다.

회귀 검사는 실제 브라우저의 드래그·우클릭·키보드, 부모/자식 박스 범위,
문항 검수 이동, 편집 후 상태 변경, 텍스트 내보내기에 도형이 유지되는 경로를 다룬다.
Claude 구독 CLI의 실제 `figures` 요청도 합성한 직사각형 문항으로 확인했다.
실제 요청은 HTTP 200과 도형 1개를 반환했고, 외부 API 키 결제 경로는 사용하지 않았다.
