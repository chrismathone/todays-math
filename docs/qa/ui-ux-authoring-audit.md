## Validation

- Focused Vitest run: 7 suites, 102 tests passed (Bank, Concept, PrivateLibrary, Studio cart, PrintOptions, Figure editor and new modal regression). StudioCropOverlay and figure modal rerun: 2 suites, 35 tests passed after the delete-mode keyboard fix.
- `npm run type-check` passed after `npx prisma generate` restored the local generated client. Targeted ESLint on the changed TypeScript files and `npm run lint:affordance` passed.
- Chromium at 1440 × 900 and 390 × 900 visited the data free `/dev/concept-hifi#concept` and `/dev/choice-layout` fixtures on this worktree's port 3002. Both screens loaded without page errors; concept tree and worksheet settings/order tabs worked, and document scroll width equaled viewport width at both sizes. The fixtures do not write to the real dataset.

## Limits

- The browser check covered the concept and worksheet fixtures. Bank detail, private library, Studio crop/review/cart, and figure editor behavior was verified with component tests; their live account and file workflows were not exercised in a browser because those paths require seeded data or file import.
- The local dev server had no `AUTH_SECRET` and logged Auth.js configuration warnings. Both fixture routes still returned 200 and the checked UI produced no browser page errors; authenticated workflows were not evaluated.
- Native browser modal behavior is covered by the `showModal()` regression tests and code inspection; jsdom does not perform visual layout or native focus isolation. No print artifact was regenerated because print templates and typography did not change.
