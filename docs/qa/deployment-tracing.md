# 배포 파일 추적 범위 수정 — 2026-09-15

`/dev/tier-bench/g4`가 `process.cwd()`와 다른 모듈의 경로 상수를 조합해
검수 원장 JSON을 읽었다. Turbopack이 이 경로를 확정하지 못해 저장소 전체를
탐색했고, 정적 이미지와 문서·테스트·작업 파일까지 해당 서버의 배포 목록에 넣었다.

원장 파일을 정적 JSON import로 바꿨다. 같은 원장과 판정 함수를 사용하며,
프로덕션에서 `ENABLE_RENDER_QA=1`일 때만 화면을 여는 조건도 유지한다.
원장 수정은 개발 중에는 모듈 갱신으로, 프로덕션에서는 다음 빌드로 반영된다.

## 빌드 산출물 비교

동일 작업 폴더의 수정 전후 `page.js.nft.json`을 읽고, 각 경로의 실제 파일
크기를 합산했다. 압축 전 로컬 파일 합계이며 Vercel 업로드 용량은 아니다.

| `/dev/tier-bench/g4` | 수정 전 | 수정 후 |
| --- | ---: | ---: |
| 추적 파일 수 | 29,618 | 491 |
| 파일 크기 합계 | 1,084,013,406 bytes | 154,792,487 bytes |
| 저장소 전체 추적 경고 | 2 | 0 |
| 포함된 `public` 파일 | 18,869 | 0 |

`public` 파일 자체를 지우거나 정적 배포에서 제외한 것이 아니다. 이 내부
화면의 서버 배포 목록에 중복으로 들어가던 항목을 제거했다.

## 검증

- `npm run build` 통과. 이번 로컬 실행은 전체 76.45초, 컴파일 25.8초,
  TypeScript 15.2초였다. 이전 실행과 캐시·시스템 부하가 달라 시간 감소의
  근거로 사용하지 않는다.
- `npx vitest run src/__tests__/unit/tier4Ladder.test.ts`: 10개 통과.
- 프로덕션 빌드를 로컬에서 `ENABLE_RENDER_QA=1`로 실행하고 검수 화면의
  HTTP 200 및 원장 판정 집계 렌더링을 확인했다.
- PDF worker, 한국어 CMap, 기본 글꼴, 이미지 디코더 WASM, 도형 엔진,
  HWPX 변환기와 템플릿 등 13개 필수 파일이 각 API의 추적 목록에 존재하고
  실제 파일이 비어 있지 않은지 확인했다.
- `next.config.ts`의 API별 파일 포함 규칙과 Python 함수의 `vercel.json`
  포함·제외 규칙은 변경하지 않았다.

직전 Vercel 배포의 GitHub 상태 기록은 진행 00:27:48 UTC, 완료
00:33:38 UTC로 약 5분 50초였다. 이 구간에는 대기·빌드·패키징·배포가
포함된다. 이번 변경의 실제 배포 소요 시간은 새 배포 완료 후 별도로 비교한다.
