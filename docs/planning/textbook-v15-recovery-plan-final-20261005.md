# 2-1-1 기준 교재 제작 복구 실행 계획 — 최종 표결본 v02

작성일: 2026-10-05. 작성: Codex. 이 파일은 최종 표결의 고정 대상이다. **세 당사자의 승인 여부·실행 상태는 별도 합의 원장에 기록한다.** 승인 후 이 파일의 바이트를 고치지 않는다. 이번 산출물은 실행 계획이며 앱 구현·배포·내용 검수·실물 인쇄가 완료됐다는 뜻이 아니다.

## 1. 사용자가 원하는 결과

**학년·학기 → 문제 범위 시작/끝 → 난이도·문항 수 → 구성과 인물 선택 → 자동 생성 → 미리보기·PDF**로 제작한다. 기존 개념 대본을 자동으로 붙이고, 처음 사용하는 사람이 원고 구조를 알아야 하는 절차를 없앤다. 상세 편집은 선택 기능으로 둔다.

- 대상: 초3·초4·초5·초6·중1·중2·중3의 두 학기, 총 14조합. 초1·초2·고등은 제외한다.
- 디자인 정본: 사용자가 준 v15 ZIP과 259쪽 2-1-1 학생용 PDF. 서로 다른 내용의 쪽수 차이를 디자인 실패로 판정하지 않는다.
- 모든 독립 학습 활동은 on/off로 선택한다. 기본 화면은 추천 구성과 간단한 선택을 제공하고, 펼친 구성 패널에서는 전부 조절할 수 있게 한다.
- 선생님 10명, 학생 10명: 역할마다 남녀 각 5명. 학생 두 배역은 같은 학생 라이브러리에서 고른다. 얼굴·이름표·대사 호칭·조사를 연결한다.
- 쉬어가기에는 삽화·이야기·생각 나누기를 둔다. 기준 PDF에 대응 지면이 없으므로 별도 품질 검수 대상이다.
- 이번 복구는 기존 스택을 사용한다. ID 연결·수학 계산·번호·빈칸·조판·페이지 참조는 결정적 코드로 처리하며, 실행 중 AI 원고 생성이나 새로운 AI 판정 서비스를 추가하지 않는다.

## 4. P1 — 의미 계약·기존 데이터·토글 확정

대화는 수업/부분/발화/판서와 역할·표정·원문 위치를 보존한다. 개념은 conceptId·rowKey로 설명→이유/예→주의→확인을 같은 묶음 안에 놓는다. 학습/핵심어/통문장은 **동일한 공통 행 모델과 공통 페이지 분할**을 사용한다. 대표예제는 유형·전략·공개 풀이·미해결 확인 문제의 한 그룹이다.

### 데이터와 배포 호환

| 모집단 | 허용 변경 | 보존·불가 항목 |
| --- | --- | --- |
| 발행본 | 저장 산출물을 표시하는 방식 확인, 별도 신판 생성 | PDF/산출 바이트·snapshotHash·contentHash·manifestHash·pageMap·QR 예약 그대로. 현재 renderer로 재측정하는 화면이면 저장본 표시 또는 판본 차이 명시. |
| 기존 초안 | frozen.entries에서 무손실 개념 투영 | 저장 글/ID를 덮어쓰지 않음. 판서 여부·역할 호칭·오류 표지는 저장값으로 복원 불가하면 적용되지 않음을 표시. workLines=0의 의도를 추정해 바꾸지 않음. 새 생성 사본으로 복구 가능. |
| 새 초안 | 새 mappingVersion·선택 정책·원천 메타데이터 | 원문 수식/정답·영구 ID 보존, 표시 번호는 책 순서. 미확인 내용을 확정으로 표시하지 않음. |

- 저장 객체는 엄격 계약이다. 새 persisted 필드는 `.optional()`만 쓰고 **파싱 기본값을 넣지 않는다**. 계약·model·projection·편집기 client의 무손실 왕복 검사를 같은 변경에 넣는다.
- 새 **요청 토글**은 `.default(false)`로 옛 요청을 수용할 수 있지만, 이 기본값을 저장 블록/해시 계산에 전파하지 않는다. 과거 workedExamples=false와 새 UI의 추천 on을 구분한다.
- 읽을 수 있는 코드 먼저 배포/확인 → 새 필드 쓰기 플래그 켬. 새 필드가 쓰인 뒤에는 그 필드를 못 읽는 판으로 되돌리지 않는다. 렌더/템플릿 버전을 올리고 rollback 최소 지원 판을 명시한다.
- 기본 경로는 DB 스키마 변경 없음. DB CHECK의 learning_stage/start_policy/concept kind에 임의 새 값을 넣지 않는다. concept-check/type-practice/error-check 등 기존 값을 사용한다. DB 변경이 필요하면 별도 근거·호환·DB 먼저/코드 나중 절차를 확정한다.
- 실제 발행본 ≥1건의 해시와 실제 기존 초안 ≥1건의 저장 구획 원문을 변경 전후 비교한다. 운영 데이터 접근은 승인된 권한 내에서 읽는다. 미리보기에서 pageMap·QR 예약을 다시 쓰지 않고 명시적 발행 예약에서만 갱신한다.
- JSON 재생성은 저장소 밖 in-memory/임시 출력으로 드리프트를 확인한다. 이번 작업 정본은 커밋된 정적 원고와 검수 메타데이터이며 materializer를 무단 재실행해 덮어쓰지 않는다. 검수 변경이 보존되는 생성 절차를 확정한 뒤에만 재생성한다.

## 5. 객관적인 지면 통과 기준

원본 PDF의 텍스트·벡터·전체 이미지로 지면 유형별 머리말/제목/본문/열/꼬리말·색·선·서체 표를 만든다. 같은 원고의 기준점 허용오차는 **±0.5mm**다. `printCheck.ts`와 기존 `textbook-a4-qr-20261003`의 기준을 유지한다. 폰트가 실제로 포함/로딩됐는지 확인하고 측정한다.

1. 학습·핵심어·통문장의 (conceptId,rowKey) 집합·상대 쪽 순서·행 y가 같다(±0.5mm). 상세 concepts와 추가 termRecall은 이 3형식에 섞지 않는다. 한 형식만 켜도 공통 모델의 치수 유지.
2. 쓰기 칸마다 벡터 필기선 ≥1개, 두께 **0.2–0.35mm**, 피치 **7mm±0.5mm**. 쓰기 칸에 두께 0.5mm 초과 회색 채움 띠 금지. PDF drawing 명령으로 검사.
3. 서술형 선 길이는 문항 열 폭의 ≥95%. QR은 필기 상자 밖. 단답·선택·서술의 새 초안 기본 선은 0이 아니며 도형/답안 길이에 따라 높이 배정.
4. 동일 원고의 머리말·큰 제목·본문 시작·열 경계·꼬리말과 표지 코드/브랜드 기준선 오차 ≤0.5mm. 긴 제목 축소가 기준선을 밀지 않음.
5. 꺼진 구성의 모델 노드·제목·단계·안내 참조 0개. 출력에서는 해당 안내/구획 ID와 연결된 글을 검사하며 자연어 본문의 우연한 동일 단어를 오검출하지 않음.
6. 계속 쪽에 수업/개념 이름·계속 표시·실제 켜진 단계 진행 띠. UUID 숫자로 표시 번호를 만들지 않고 책 안의 차례로 번호 부여.
7. 학생용 일반 문항의 answer/solution 노드·텍스트가 없음. 공개 풀이 대표예제는 예외. 정답과 우연히 같은 일반 본문·선택지로 유출을 판정하지 않음.
8. 수식·그림·라벨·QR·말풍선·선의 잘림/겹침 0건, 원고 ID·참조·TeX 본문 바이트 보존. 분수는 원문을 바꾸지 않고 원본 KaTeX display 스타일로 조판.

기하 측정은 모든 표본의 모든 쪽에 적용한다. 일부러 행·선·꺼진 안내·유출·번호를 깨뜨린 fixture에서 검사 실패가 나는지 먼저 확인한다. 사람은 학습 관계·읽는 순서·작성 공간·여백의 쓸모를 전체 페이지 이미지로 본다. 단순히 공백이 넓거나 총쪽수가 다르다는 이유로 실패시키지 않는다.

대화는 단원 안에서 공통 글자 크기: **10.5pt 시작, 0.1pt씩 조정, 하한 9.2pt**. 하한에서도 넘치면 다음 페이지로 분할하고 남은 높이는 간격으로 배분한다. 판서는 연녹색 별도 박스이며 선생님 말풍선으로 바꾸지 않는다. 핵심어 빈칸 폭은 숨긴 글의 실제 advance를 기준으로 하고 22mm 고정 폭을 쓰지 않는다. **1–4회 확인은 conceptStudy에만** 둔다.

## 7. 조판과 발행의 페이지 정책

자동 단원 도입의 홀짝은 조판 측정 결과로 결정한다. 시작이 짝수면 원본 두 페이지 맞쪽. 홀수면 승인된 **단면 대체형**에 질문·설명·핵심 문구·삽화·목표·경로·점검·날짜를 모두 유지한다. 단면형을 원본 동일성 합격이라고 부르지 않는다. 단원별 선택과 이유를 미리보기/발행 사전검사에 표시하고 초안의 layout policy/렌더 판으로 재현한다. 수동 even-left는 기존 검증을 유지한다. 빈쪽·내용 삭제·쉬어가기 끼워넣기로 홀짝을 맞추지 않는다.

쪽수 슬롯은 충분한 고정 폭/높이로 예약한다. 발행은 기존 **걸음당 4구획·300블록**, renderer **8구획·600블록·32쪽** 등 한도를 유지한다. 예약 → 구획 걸음별 조판/좌표·앵커 수집 → 전체 학생 pageMap 집계 → 예약 슬롯 한 번 채움 → 같은 걸음 한도 안에서 최종 산출 검증 → 확정 순으로 설계한다. 채우기 전후 페이지 수·블록 좌표·pageMap 불변을 검사한다. 재렌더가 필요하면 예약 슬롯만 바뀌는 한 번의 제한된 최종 조판이며, 변경이 다시 배치를 바꾸면 실패한다. 전체 책을 한 호출에 몰거나 무한 반복하지 않는다. 실제 job 저장 단계·timeout/재시도·중간 산출 원자성은 P1에서 테스트 가능한 설계로 고정한다.

발행 걸음 경계에서도 쪽 번호·개념 번호·머리말·앵커가 이어지고 백지/초기화가 없다. 답지의 문항 참조는 최종 학생 pageMap을 가리키되 답지 높이와 쪽수는 독립이다. 등록된 실제 개념 영상 URL만 개념 QR을 만들고 문제 QR과 별도 슬롯으로 둔다. 주소가 없으면 빈 QR을 만들지 않는다. 쉬어가기는 단원 펼침면과 대화 사이에 넣지 않는다.

## 9. 간단 제작 UI와 구성 검사

기본 제작은 학년/학기·시작/끝 소단원·난이도/문항 수만으로 진행 가능하게 한다. 추천 구성은 원본 학습 흐름을 따르되, 구성 패널에서 28개 활동을 각각 조절한다. 인물 선택은 얼굴 카드, 쉬어가기/보충은 설명이 있는 선택으로 둔다. 추정 분량은 추정으로 표시하고 측정된 미리보기 쪽수와 구분한다.

검사 집합: **각 키만 on / 각 키만 off / 기존 요청 기본 / 새 UI 추천 / 전부 on / 전부 off 거절 / 표지만 거절 / 의존 짝**. 대표예제+유형, 암기 세 형식의 부분 조합, 오류만, 단원 도입+앞부분 모든 핵심 조합, 여러 단원 경계를 포함한다. 문항 예산 제약을 만족하는 입력으로 시험하며 2의 28승 전수 시각 검수라고 주장하지 않는다.

꺼진 활동은 구획·목차·학습 경로·진행 띠·안내·색인 참조에도 없어야 한다. 필요한 예제 확인 문제/준비 기록/설명 지침은 부모 안에 포함하고 화면에서 관계를 설명한다. 없는 문항/서술형/예제 연결/대본/자산은 구체적인 부족 수와 적용 결과를 보여 준다. 선택 옵션을 조용히 꺼서 성공으로 처리하지 않는다.

## 11. 형태 확정·3자 합의·통합 규칙

로컬 [CLAUDE.md](../../CLAUDE.md)의 “형태를 결정하는 모든 작업은 원장님 확정 없이 구현 착수 금지”, “인쇄 관련 변경은 실물 프린터 출력 검수까지가 완료 조건”을 준수한다. 사용자가 준 2-1-1 복구와 이번 3자 계획 확정은 이미 요청된 범위다. 이 계획을 정하기 위해 다시 허락을 묻지 않는다.

단면 대체형·새 구성 관계/문구·원천 없는 칸·초등 수식 없는 표지·새 쉬어가기의 구체 형태는 **원본 비교를 포함한 검토 가능한 Wire/HiFi 시안**을 먼저 만든다. 기존 확정/명시 위임으로 커버되는 항목은 그 근거를 결정 대장에 적고 진행한다. 커버되지 않는 새 형태는 시안 완성 후 최종 확정을 받으며, 추상 선택지 승인으로 구현을 시작하지 않는다. 대장 칸: 항목/선택지/선택/결정자/결정일/근거/시안/실행 상태. 핵심 집합 기본값 등 이번 계획 선택과 실제 형태 구현 승인을 구분한다.

이 계획의 합의는 같은 경로·v02·UTF-8 LF 바이트 SHA-256에 대한 Codex·실제 Claude·실제 Grok의 **APPROVE 3건**이다. v01의 REVISE를 승인으로 전환하지 않는다. 조건부 승인은 합의로 세지 않는다. 이견은 수정/근거/반영 위치와 함께 기록하고, 바이트를 바꾸면 새 해시로 다시 표결한다. 별도 합의 원장에 Run·Task·Dispatch·실제 완료 메시지·파일·해시를 남긴다.

실행 시 독립 worktree 변경을 main에 병합한다. 푸시 직전 대상 원격을 fetch/비교해 새로운 커밋을 보존·통합하고 충돌 후 관련 검사를 다시 수행한다. 강제 푸시 금지. main에 병합됐고 깨끗하며 실행 중 작업이 없는 Orca worktree만 제거하고 Git 브랜치는 보존한다.

최종 실행 산출물: 호환 계약/코드, 31종·28구성 대응표, 원천/검수/결정 원장, 14조합 출력 manifest, 세 쌍 전체 검수 PDF, 같은 영역 좌우 비교 화면, 기하 측정/깨진 fixture 증거, 실제 흐름/실물 상태. 이번 요청의 산출물은 그 실행을 위한 **해시가 일치하는 3자 합의 계획과 실제 표결 기록**이다.
