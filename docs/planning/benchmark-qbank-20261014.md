우리 `/problems` 화면에는 전체 117,828문제, `변형` 4,442문제, `교과서` 12,301문제가 표시됐다. 작업실 홈의 문제 수는 115,383문항이었다. 서로 다른 포함 기준인지 데이터 갱신 시점인지 확인이 필요하다. 외부 사이트의 `학교시험 133,251문항`과 단순 우열 비교하지 않는다.

후속 코드 검토에서는 `/problems`가 공용 풀의 보이는 문항, 작업실 홈이 출제 자격을 만족한 문항을 세는 차이를 확인했다. 따라서 두 화면의 수를 같은 총계로 비교할 수 없다. 이 코드 검토만으로 관찰 시점의 데이터 갱신 차이까지 배제하거나 운영 숫자를 재집계한 것으로 보지 않는다. 또한 현재 `SourceMaterial`에는 교과서 본문 쪽 필드가 없고 문항 번호는 자료 안 번호다. 경쟁사의 책/쪽 탐색은 참고 방향이며, [적용 계획](goal-bank-arithmetic-brand-20261014.md)은 먼저 책/자료/자료 안 번호를 사용하고 학평 구현은 제외한다.

## 페이지 구성에서 가져올 것

1. **선택 전 가용량:** 범위·유형·교과서·시험지 행에 실제 사용할 수 있는 수를 놓는다. 총원문/승인/권리상 사용 가능/변형 준비 수가 다르면 라벨을 나눈다.
2. **출처별 탐색 문법:** 단원은 계층 트리, 기출은 학교·연도·시험, 교과서는 출판사·책·쪽·번호, 모의고사는 학년·연도·월·번호가 자연스럽다. 한 종류의 735행 모달로 모든 출처를 표현하지 않는다.
3. **중심 작업에 폭 배정:** 우리 작업실의 고정 사이드바가 제작 2열과 지면 미리보기의 가로폭을 줄인다. 대상 사이트처럼 집중 작업에서 셸을 접거나, 작업 영역의 최소 폭과 반응형 전환을 실제 폭별로 검증한다. 공통 [DESIGN.md](../../DESIGN.md)의 셸·토큰은 유지한다.
4. **선택→검토→출력의 상태 지속:** 단계 제목·현재 수량·다음 행동은 화면 상단/하단의 일정한 위치에 둔다. 원본 30개 가운데 24개만 사용 가능하다면 다음 단계 전에 24개라고 알린다.
5. **후보 패널의 기준 설명:** `쌍둥이`(같은 원문 구조의 검증된 별문항), `유사`(같은 유형의 별개 문항), `AI 생성`(검수 상태)을 섞지 않는다. 교체와 추가의 차이, 정답 확인 상태, 출처/권리를 후보 옆에 표시한다.
6. **인쇄 중심 설계:** 문항 편집은 본문 가독성이 우선이고, 출력 단계는 실제 A4를 바로 보며 바꾸도록 한다. 우리 6개 템플릿·HWPX는 보존하면서 프리뷰 로딩 상태와 배치 폭을 다듬는다.

## 하위 기능 전수 탐색 기록

여기서 **실행**은 화면 조작과 결과를 확인했다는 뜻이고, **화면**은 하위 메뉴·설정·빈 상태까지 열어 봤다는 뜻이다. 학생에게 보내거나 개인 기록을 바꾸는 기능, 유료 주문은 실행하지 않았다. 화면만 확인한 항목을 검증 완료로 읽지 않는다.

우리 운영 화면과 저장소를 함께 확인한 범위에서는 `연산`이 문항 난이도/등급으로 쓰이고 공통 시험지 제작·인쇄·채점 경로는 있으나, 매쓰홀릭의 연산대장처럼 **연산 전용 유형 목록→회차별 생성→답안입력→분석**을 한 메뉴로 묶은 화면은 확인되지 않았다. 따라서 이를 이미 완성된 기능으로 비교하지 않는다. 반대로 문자·교육비·학부모 공지 등 학원 운영 기능은 문제은행 개선과 별도 제품 범위로 판단해야 한다.

## 후속 작업 우선순위 제안

1. **범위 진입 개선:** 선택된 반/과정이 있으면 해당 과정으로 시작, 출제 불가 범위는 기본 목록에서 뒤로 보내거나 접기, 검색/필터의 결과 수와 가용 문항 수 표시. 초1·초2 빈 범위의 비활성화는 현재처럼 유지한다.
2. **출처별 시작 화면:** 현재 공통 제작기를 지키면서 기출 시험지·교과서 책/쪽·모의고사 회차를 선택하는 입구를 추가한다. 권리와 승인/변형 상태는 원문 수량과 별도로 표시한다.
3. **교체 후보의 관계 표시:** 교과서 원문당 두 개의 검증된 변형, 일반 유형 유사, 새 생성 후보를 구분하고 `0/2·1/2·2/2` 준비 상태를 제작 단계에서도 보이게 한다. 오답 복습의 지정 쌍과 같은 데이터 계약을 재사용한다.
4. **숫자 계약:** 작업실 홈·문제은행·선택/검토/미리보기에서 각 수의 범위와 포함 기준을 명시하고, 실제 출력 가능 수가 단계마다 달라지지 않게 한다.
5. **폭별 실측:** 1700px·1280px·모바일에서 범위 모달, 문항 카드, A4 미리보기, 주 행동/스크롤을 검증한다. 작업 중 셸 접기/최대화가 편집 상태를 보존하는지 함께 본다.

문항 원문·수식·화면 디자인을 복제하지 않고, 탐색 구조·상태 표시·사용 흐름을 우리 데이터/권리 계약에 맞춰 적용한다.
