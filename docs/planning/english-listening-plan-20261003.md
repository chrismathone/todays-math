# 오늘의 영어 리스닝 추가 계획

2026-10-03 작성. 기준 코드 `763caff59`. 교사 수업, 학생 자기주도 학습, 중고등 듣기평가 대비를 모두 지원하는 계획이다. 승인한 교사 A·학생 B·H1 배치의 직접 제작·음원 업로드·저장·배정·풀이·짧은 평가를 통합했다. 최신 검증과 운영 반영 대기 사항은 [화면·저장 통합 기록](tracks/reports/listening-integration-20261003.md), 초기 구현 이력은 [L0 기록](tracks/reports/listening-l0-implementation.md)에 남긴다. 운영 DB 적용·배포와 AI/TTS·청취 품질 벤치는 완료되지 않았다.

Claude와 Grok의 독립 검토 및 수정본 재검토를 거쳤다. 2차의 문서 보완 조건까지 반영한 최신안이며, 판정 원문과 채택·조정 내역은 [검토 반영 기록](tracks/reports/english-listening-review-20261003.md)에 요약했다. 에이전트의 기획 검토를 구현·실측 통과로 해석하지 않는다.

핵심 방향은 **검수된 하나의 듣기 자료를 수업·학습·평가에 재사용하는 것**이다. 첫 통합 시범은 짧은 음원과 객관식으로 세 모드를 완주한다. AI 제작, 자동 전사, 받아쓰기, 중학 20문항·수능형 17문항은 이후 확장한다. 공급자는 실제 청취와 운영 비용을 비교한 뒤 선택한다.

사용자는 세 사용 장면 중 우선순위를 묻는 질문에 “셋 다”라고 답했다. 이에 따라 기존 D-35·D-123의 학생 기능 제한을 확장하는 리스닝 학습·응시까지 이번 기획 범위에 포함한다. 동일한 범위 확인을 다시 요구하지 않는다. 다만 이 답을 현재 운영의 학생 경로를 이미 열었다는 뜻으로 취급하지 않으며, 구현 시 결정 기록과 권한 계약을 함께 갱신한다.

## 1 사용 화면과 학습 흐름

오늘의 영어에 `영어듣기` 메뉴를 추가한다. 교사는 `듣기 자료`, `만들기`, `과제와 결과`를 오가며 같은 자료를 재사용한다. 학생은 기존 학생 로그인 후 배정된 듣기를 연다. 화면 배치와 명칭은 시안에서 확인할 제안이다.

| 모드 | 사용 장면 | 재생과 공개 정책 | 남기는 결과 |
| --- | --- | --- | --- |
| 수업 | 교실에서 교사가 스피커로 재생하고 함께 풀이 | 전체·문항별 재생, 교사 반복, 교사용 대본·해설 전환 | 기본은 수업 진행 기록. 종이 풀이를 자동으로 학생 성적으로 만들지 않음 |
| 학습 | 학생이 하루 5~10분 과제를 수행 | 답하기 전 대본 숨김, 응답 후 반복·근거 듣기·대본 확인 | 최초 답, 도움 후 답, 재생·대본 공개 이력 |
| 평가 | 학생별 또는 교실 감독하의 듣기 연습시험 | 고정 순서·속도·방송 횟수, 제출·마감 정책에 따른 공개 | 제출 답, 유효한 최초 응시, 중단·재응시 사유 |

학습 모드의 기본 흐름은 `상황 파악 → 전체 뜻 듣기 → 세부 문제 답하기 → 필요한 구간 다시 듣기 → 대본과 해석 확인 → 오답 복습`이다. 짧은 받아쓰기는 확장 단계에서 선택 활동으로 넣는다. 한 번의 듣기에 읽기·쓰기를 과도하게 요구하지 않고, 전체 뜻과 세부 정보를 나눠 확인한다. 이 구성은 [British Council의 듣기 수업 안내](https://www.teachingenglish.org.uk/professional-development/teachers/planning-lessons-and-courses/framework-planning-listening-skills)를 참고한 설계이며, 서비스의 학습 효과가 검증되었다는 뜻은 아니다.

첫 시범 자료는 자체 제작한 중1~2 수준의 짧은 대화와 고등 수준의 짧은 담화다. 학년은 편집 태그이며 자동 측정한 영어 능력 등급이 아니다. 초기는 목적·장소·주제, 시간·가격·수량, 이유·할 일·내용 일치, 적절한 응답을 다룬다. 그림·표, 하나의 담화에 여러 문항이 붙는 형식은 계약에는 고려하되 후속 단계에서 화면을 완성한다. 상황 예고에 정답인 장소·목적·가격을 먼저 쓰지 않는다. 평가는 해당 프리셋에 없는 힌트를 추가하지 않는다. 5~10분은 목표 시간이며 실제 시범에서 재기 전에는 보장하지 않는다.

중학 20문항·5지선다 구성은 [EBS 중학 안내](https://mid.ebs.co.kr/english/grade?clsfnSystId=22000012), 수능형 듣기 17문항은 [EBSi의 2027학년도 6월 모의평가 분석](https://www.ebsi.co.kr/ebs/ent/enta/retrieveEntAnlyStrdDataVw.ebs?cookieGradeVal=high3&datNo=127091)을 참고한다. 문항 수만 맞춰 공식 시험과 같다고 부르지 않는다. 안내 방송, 보기 읽는 시간, 반복 문항, 문항 간 간격은 해당 시험 자료에서 따로 확인하고 프리셋 버전을 기록한다.

## 3 자료와 응시를 보존하는 계약

아래는 논리 단위이며 최종 테이블명은 계약 검토에서 결정한다. 수학 `Problem`, `WorkspaceDocument/Asset`, 수학 복습 표에 영어 데이터를 넣지 않는다.

새 계약은 별도 `englishListening.contract.ts`로 제안한다. 교사용 원본, 공개 전 학생용, 공개 후 학생 복습용을 서로 다른 엄격한 스키마로 두고 허용된 필드만 직렬화한다. 새 영어 표와 Prisma 모델은 울타리 검사의 고정 이름 목록에도 추가한다. 마이그레이션은 기존 영어의 데이터베이스 접근 제한·소유권 검증 절차를 따른다.

| 단위 | 반드시 보존할 것 |
| --- | --- |
| 듣기 세트 | 소유자와 지점 범위, 제목·수준·유형, 선택적 내신 시험 연결, 편집 개정 번호 |
| 원본과 음원 | 출처·사용 권한, 음원 해시·길이·형식·저장 참조, 생성 공급자·모델·설정, 대본 개정과 관계 |
| 대본과 구간 | 원문·번역·화자, 검수 상태, 실제 음원 기준의 시작·끝 시각, 연결된 문항 ID |
| 문항 | 영구 ID, 문항 묶음 ID, 질문·보기·정답·해설, 근거 구간, 받아쓰기 인정답과 채점 규칙 |
| 발행본 | 고정된 음원·대본·문항·보기 순서·해설의 개정과 해시, 검수자·검수 시각, 생성 출처 |
| 배정 | 발행본 ID, 배정 생성 시 대상 학생 목록과 추가분 이력, 기간, 모드, 음원 재생 주체, 재생 정책, 정답 공개 정책, 취소 상태 |
| 응시 | 학생·배정·발행본 ID, 상태, 서버 시작·마감·제출 시각, 답안 개정, 제출 중복 방지 키, 재응시 관계 |
| 학습 기록 | 최초·복습 답, 재생 요청과 재생 성공 관측, 대본·해설 공개, 기술적 중단, 이전 노출 여부 |

`schemaVersion`은 읽을 수 있는 데이터 형식, `revision`은 동시 편집 충돌을 막는 개정 번호로 구분한다. 발행본과 기존 응시를 덮어쓰지 않는다. 대본을 수정하면 음원·시간 정렬·문항 근거의 검수가 다시 필요하고, 음원을 바꾸면 구간 시각도 다시 검수한다. 이미 배정된 자료를 바꾸려면 새 발행본으로 새 배정을 만든다.

문항 묶음 하나에 음원 하나와 여러 문제가 연결될 수 있어야 한다. 보기 순서를 바꾸면 표시 순서와 정답 매핑을 같은 발행본에 저장한다. 최초 구현은 문항과 보기 순서를 고정한다.

화면에 표시하는 대본과 TTS에 전달하는 발음용 대본을 구분한다. 예를 들어 금액과 시간을 말로 풀어 쓰더라도 원래 의미가 보존되는지 확인한다. 화자 연출 지시를 학생에게 들릴 대사에 섞지 않는다. 발음용 대본·정규화 설정의 변경도 음원 개정에 포함한다.

## 4 권한과 정답 공개

교사용 제작·편집·발행은 기존 영어와 동일한 교사 소유 및 지점 범위를 따른다. 세트·선택적 내신 시험·음원·배정 대상이 같은 허용 범위인지 각각 확인한다. 메뉴 표시나 ID의 존재만으로 작업을 허용하지 않는다.

새 메뉴는 기능 플래그와 명시적인 시범 계정 권한으로 연다. 현재 레거시 `english` 권한의 정규화와 차단 목록의 기본 허용 방식 때문에 메뉴를 한 줄 추가하면 과거에 영어를 막은 계정이 새 기능을 얻을 수 있다. 전환 규칙과 회귀 테스트로 기존 거절 의도를 보존한다. 영어듣기만 허용된 교사에게 반 배정 선택기가 필요하면 같은 소유 범위의 최소 반·학생 목록을 읽는 전용 경로를 제공한다. 전체 수업 관리 권한을 부여하지 않는다.

학생 화면은 `/learn/english/listening`, API는 `/api/english/learn/listening` 아래의 구체적인 메서드·경로로 제안한다. 영어 API에서 학생 인증을 가져오는 방향으로 구성해 기존 `/api/learn → english` 금지 규칙을 유지한다. 교사 관문과 학생 관문을 함께 갱신하되 학생 경로는 `requireStudent` 계열의 학생 인가만 사용하며 교사 제작 경로를 열지 않는다. 인증, 최초 비밀번호 변경, 학생 활성 상태, 학생 본인의 배정, 현재 반 소속, 배정 유효 상태를 모든 요청에서 확인한다.

반 전체 배정은 **배정 생성 당시** 대상 목록을 고정한다. 전입 추가는 원래 목록을 덮어쓰지 않고 새 배정 개정 또는 추가 대상 행으로 남기며, 기존 응시는 시작 당시 대상·발행본을 계속 가리킨다. 전출·퇴원·배정 취소 시 진행 중 응시를 포함한 이후 학습·미디어 요청을 막으며 과거 성적은 원래 배정 이력에 남긴다. 이미 서버에 저장한 답은 보존하고, 계속 수행이 필요하면 교사가 새 유효 배정으로 재응시를 연다.

학생 화면도 교사 응답을 우회해서 받을 수 없게 한다. `src/app/learn/**`와 `src/components/learn/**`에서 교사용 영어 라이브러리·컴포넌트·Prisma 모델로 가는 직접·간접 참조를 울타리 검사로 차단한다. 학생 UI는 순수 학생 계약과 위 학생 API가 만든 데이터만 사용한다. 학생 화면을 영어 DB 접근 허용 목록에 통째로 추가하지 않는다. 학생 페이지가 교사 직렬화기를 가져오는 잘못된 변경을 넣었을 때 검사가 실패해야 한다.

공개 전 학생 응답에는 문제·보기·허용된 재생 정보만 포함한다. 정답·해설·전체 대본·번역·정답 근거의 시각·내부 검수 기록은 서버에 남긴다. HTML 초기 데이터, API, 캐시, 다운로드, 오디오 메타데이터와 파일명에서도 누출을 검사한다. 정답을 가리킨 그림 대체 텍스트도 금지한다. 교사 응답이 학생 캐시에 섞이지 않게 한다.

학습의 공개 단위는 문항 또는 같은 음원·대본을 공유하는 **문항 묶음**이다. 해당 단위의 최초 답을 서버에 모두 확정한 뒤 그 단위의 복습만 연다. 하나의 대화에 두 문항이 있으면 첫 문항 해설로 두 번째 정답을 미리 알려 주지 않는다. 평가는 기본적으로 **배정 마감 이후** 공개한다. 조기 공개를 교사가 선택하면 이후 응시의 노출 가능성을 표시한다. QR은 학생 로그인과 배정 검사로 들어가는 링크이며 공개 음원·정답 주소가 아니다. 이미 받은 오디오 바이트를 회수하거나 외부 녹음을 막을 수 있다는 약속은 하지 않는다.

공개 판정은 서버 함수 하나와 전이 표로 관리한다. 입력은 모드·공개 단위·단위 내 답 확정 여부·전체 제출 여부·마감 시각·수동 공개 기록·현재 시각이며, 출력은 단위별 공개 여부다. 학습의 `after_unit_answer`와 평가의 `after_submit`, `at_time`, `manual`, `never`를 구분한다. 평가 기본값은 마감 시각의 `at_time`이다. 공개를 뒤로 미뤄도 이미 전달한 내용을 회수할 수 없으므로 공개 이력을 보존한다. QR은 기존 D-123에서 보류한 시험지 QR과 구별되는 리스닝 확장 제안이며 필수 출시 조건이 아니다. 인쇄 시안에서 채택하면 L3에 넣는다.

학생 응답은 문항별 공개 상태가 구분되는 엄격한 데이터 배열이다. 공개 전 항목과 복습 항목을 상태 값으로 구분하고 각각의 허용 필드로 검증한다. 또는 복습 요청을 별도 응답으로 분리할 수 있으나, 미공개 항목에 복습 필드가 섞이는 동작은 허용하지 않는다. 누출 검사는 정답 식별자·보기 인덱스·정답 매핑·대본·해설·근거 시각·교사 메모·내부 기록과 숨은 메타데이터를 대상으로 한다. 정답 보기의 문장이 다른 보기와 함께 있는 것은 정상이다. 검수 fixture에서 금지 필드를 추가하거나 문항 간 정답 근거를 노출시키는 변경을 잡아야 한다.

## 5 재생과 중단 복구

첫 화면에 소리 확인과 명시적인 시작 버튼을 둔다. 브라우저는 사용자의 조작 없이 시작하는 유성 미디어 재생을 차단할 수 있으므로 `play()` 실패를 처리하고 다시 시작할 수 있게 한다. [MDN 자동 재생 안내](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Autoplay)

학습은 재개 위치와 답을 복구한다. 평가는 서버가 시작·마감·제출을 관리한다. 배정의 `audioSource`를 `student_device`와 `teacher_device`로 구분한다. 학생 개별 재생은 브라우저가 재생 진행을 보고하며 소리 확인과 음원 준비가 끝나기 전에 타이머를 시작하지 않는다. 네트워크 장애나 브라우저 중단 때는 응시를 `interrupted`로 표시하고 첫 단계에서는 교사가 재응시를 열어 준다. 중단된 응시를 정상 최초 성적과 합치지 않는다. 새로고침만으로 시간을 다시 받지 못하게 한다.

교사 방송 방식에서는 학생 응답에 음원 주소를 넣지 않고 학생 미디어 요청도 허용하지 않는다. 교사 방송 세션 하나에 참여 학생·시작·마감·음원 버전을 기록하고, 서버는 교사의 시작·종료 조작으로 반의 응시 시간을 관리한다. 교사 음원이 중단되면 방송 세션과 영향받은 응시에 그 사유를 남긴다. 학생의 답안 통신 실패와 교사 방송 실패를 구분하며, 학생 기기에 음원이 없다는 이유로 재생 실패를 기록하지 않는다.

답은 문항 단위로 서버 저장하고 저장 성공 여부를 표시한다. 저장·제출 재시도에는 중복 방지 키와 답안 개정 검사를 적용한다. 오래된 탭이 최신 답을 덮거나 중복 제출로 점수가 두 번 생기지 않아야 한다. 서버 마감 후 제출, 교사 재개·취소, 재응시의 성적 선택 규칙은 같은 상태 전이 표로 검증한다.

평가의 속도·탐색·재생 횟수 제한은 앱의 정상 사용 흐름을 관리하는 기능이다. 다운로드 가능한 브라우저 음원에서 부정행위를 완전히 방지하는 보안 경계로 취급하지 않는다. 공식 성적용 고신뢰 시험은 별도 범위이며 초기 제품은 학습과 감독 가능한 연습평가다.

L3의 실전 프리셋은 반복 방송과 문항 사이 간격을 담은 검수된 연속 음원으로 재생한다. 백그라운드에서 지연될 수 있는 브라우저 타이머로 시험 방송 간격을 만들지 않는다. 교실 감독 연습은 교사 기기 일제 재생을 기본으로 하고 학생 기기는 답안을 제출한다. 학생별 실전 연습은 같은 음원과 정책을 쓰되 기기 중단 여부를 함께 보여 준다.

미디어는 비공개 원본과 배정 인가 후의 만료되는 전달 경로를 사용한다. 부분 요청과 탐색에 필요한 `Range`·`206` 응답, 길이, 중간 연결 끊김, URL 만료 시 재인가를 실제 저장 방식에서 확인한다. 서명 링크만 쓸 경우 취소 후에도 만료까지 접근 가능한 시간을 명시하고, 즉시 차단이 필요한 경로는 요청마다 확인하는 중계를 쓴다. [MDN 부분 요청 안내](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Range_requests)

L2 학생 미디어는 요청마다 배정과 계정 상태를 검사하는 중계를 기본으로 하며 취소 이후 새 Range 요청도 거절한다. 이미 내려받거나 진행 중인 응답의 바이트는 회수할 수 없다. 이후 직접 서명 링크로 전환하려면 최대 만료 시간과 취소 효력 지연을 먼저 계약·시험에 반영해야 한다. 인가를 건너뛰는 공용 캐시 응답을 허용하지 않는다.

키보드 조작, 버튼 이름, 현재 문항과 재생 상태, 오류 안내를 제공한다. 청각 지원이 필요한 학습은 대본 또는 대체 과제를 열 수 있게 하되, 해당 수행은 듣기 단독 점수와 구분한다. iOS Safari, Android Chrome, PC Chrome·Edge에서 소리 시작, 이어폰 전환, 화면 잠금·탭 전환·복귀, 저속 네트워크를 확인한다.

교사 제작·수업은 PC와 스피커를 우선한다. 학생 학습·짧은 평가는 폰 화면에서 답 선택과 재생을 완주할 수 있게 설계한다. 기존 PC 우선 계획에서 학생 리스닝에 필요한 대응만 확장하며 제품 전체의 모바일 개편은 포함하지 않는다.

## 6 제작과 검수

첫 단계는 **MP3와 교사가 확인한 대본·객관식 문항을 직접 등록**하는 방식이다. 문장 자동 정렬 없이 전체 음원 또는 교사가 지정한 문항 단위 구간으로 시작한다. 텍스트만 등록해 재생할 음원이 없는 자료는 발행할 수 없다.

확장 단계에서 입력 경로를 세 가지로 연다.

1. 대본 작성 또는 붙여넣기 → 문항 초안 → 음성 생성 → 교사 검수.
2. 학년·상황·표현·문항 유형 → 대본과 문항 초안 → 음성 생성 → 교사 검수.
3. MP3와 대본 업로드 → 정렬 → 문항 연결. 대본이 없으면 전사 초안 → 사람의 대본 확인 → 정렬.

기존 독해 지문을 그대로 낭독하는 자료와 대화·담화로 재구성한 자료는 구별한다. 화자의 의도나 숫자 정보를 듣는 문항에는 실제 대화 맥락이 필요하므로 독해 문제를 단순히 음성으로 바꿔 자동 발행하지 않는다.

검수는 네 층으로 분리하고 각각 확인한 사람·시각·대상 개정을 남긴다.

| 검수 | 담당과 기준 | 실패 시 처리 |
| --- | --- | --- |
| 형식과 참조 | 코드로 보기·정답·ID·구간 범위·해시·발행 상태 검사 | 저장 또는 발행 거절, 문제 위치 표시 |
| 내용 | 교사가 정답·오답 보기·근거를 확인. TypeSafe는 대본의 근거 지지·모호성을 보조 판정 | 검토 필요로 남기고 교사 해결 전 발행 금지 |
| 실제 음성 | 사람이 음원을 들어 대본 일치, 숫자·부정어·화자, 잘림·무음·속도, 반복 구간을 확인 | 관련 음원·정렬을 수정하고 다시 확인 |
| 구간 정렬 | 사람이 실제 재생으로 문장·문항 시작과 끝을 확인 | 검수되지 않은 구간 반복은 닫고 검수된 전체·문항 재생만 제공 |

기존 텍스트 생성의 `resolveEnglishVendor` 경로를 유지한다. TypeSafe/Jev는 작은 의미 판단 단위에 사용하며 객관식 채점, 인정답 비교, 재생 횟수, 복습 날짜는 코드로 계산한다. 확신도는 정답 인증이나 음질 평가가 아니다. 서비스 자료로 오판·불확실을 측정하고 검토 기준을 보정한다. [프로젝트 TypeSafe 스킬](../../.agents/skills/typesafe-ai/SKILL.md), [근거 확인 예제](https://docs.typesafe.ai/cookbooks/citation_check), [확신도 안내](https://docs.typesafe.ai/confidence)

AI 검수는 L3 보조 기능으로 두며 L1·L2는 교사 검수만으로 완주할 수 있다. 현재 작업실용 Jev 빠른 경로를 검수 배치에 그대로 붙이지 않고, 검수용 시간 제한과 실패·미검사 상태를 별도로 둔다. 결과는 대본·문항 개정, 모델과 요청문 버전에 묶는다. 실제 음성을 재전사해 비교하는 검사는 오류 후보를 찾는 보조 수단이며 전사 모델의 오류도 있어 사람 청취를 대체하지 않는다.

전사와 강제 정렬은 정답·대본 검수의 대체물이 아니다. 대본과 음원이 다르면 그 차이를 먼저 해결한다. 정렬 정보가 없거나 검수가 끝나지 않으면 문장 단위 반복 대신 검수된 전체·문항 단위 재생으로 내려간다.

자동 생성은 문항 또는 하나의 대화 묶음을 작업 단위로 둔다. 턴별 합성이 부분 수정에 유리한지, 대화 전체 합성이 화자 사이 흐름에 유리한지는 벤치에서 비교한다. 글자 시간 정보가 없는 공급자도 있다는 전제로 수동 경계·후처리 정렬을 지원한다. 요청 상한과 출력 형식은 선택한 모델 문서에서 확인하고, PCM/WAV를 재생용 압축 음원으로 바꾸는 경우 변환 비용·지연·품질을 포함한다. 모든 공급자가 반드시 턴 단위 합성을 요구한다고 단정하지 않는다.

실전용 연속 음원에는 별도 합성 작업을 둔다. 입력은 문항 음원 해시 목록, 안내 음원, 반복·간격을 정한 프리셋 버전이다. 이를 순서대로 결합하고 필요한 무음을 삽입해 파생 음원 해시·문항별 시작과 끝·합성 설정을 저장한다. 서버 인코더 또는 오프라인 도구의 선택은 L3 착수 전에 검증한다. 인코딩 후 실제 길이를 기준으로 시간표와 구간 일치를 검사하고 사람이 전체 음원을 한 번 들어 잘림·이음새·반복을 확인한다.

## 7 음성 공급자와 비용

공급자는 확정하지 않는다. 동일한 자체 대본 20개로 Gemini TTS와 ElevenLabs를 비교하고, 간격·발음 제어가 부족하면 Azure SSML을 함께 평가한다. 생성 결과를 검수해 저장하고 여러 학생이 재사용한다. 학생이 재생할 때마다 새 음성을 생성하지 않는다.

벤치 기록은 공급자·모델·날짜·대본 개정·음원 해시·요청 설정·비용을 보존한다. 표본 20개는 중등 10개·고등 10개로 제안하며 숫자·부정어·2인 대화·짧은 응답을 포함한다. 숫자·날짜·금액·부정어 오류와 정답이 달라지는 누락·추가는 발행 차단이다. 자동 비교로 후보를 찾고 사람이 모든 시범 음원을 듣는다. 화자 안정성, 자연스러움, 사람이 표시한 구간과 자동 구간의 차이, 한 문장 수정 시 재생성 범위도 기록한다. 실패 편수와 재생성 횟수를 평균 점수와 별도로 남긴다. 블라인드 청취의 우선순위와 합격 문턱은 L0에서 먼저 정하고 모델 이름을 공개하기 전에 평가한다. 벤치 도구의 기본 실행과 CI는 실호출을 하지 않는다.

2026-10-03 조회한 [Google 공식 가격표](https://ai.google.dev/gemini-api/docs/pricing)의 Standard 요금으로 Gemini 3.8 Flash TTS의 신규 음원 1,000분은 출력만 약 **13.50달러**다. `1,000분 × 60초 × 25토큰 ÷ 1,000,000 × 9달러`로 계산했다. 공지상 2027-01-01부터는 27달러다. 이는 입력·실패 및 재생성·전사·정렬·저장·전송·운영 비용을 제외한 예시이며 서비스 월 비용 견적이 아니다.

운영 비용은 `신규 및 재생성 음원 + 대본·문항 생성 + 전사·정렬 + 저장 기간 + 학생 전송량 + 작업 실행`으로 계산한다. 계정별 분량·동시 작업·월 예산을 두고, 시작 전에 예상 사용량을 예약하며 종료·실패 후 실제 사용량을 정산한다. 중복 요청 방지는 소유 범위·대본 개정·음성 설정·공급자·모델을 포함한 키로 한다. 다른 학원의 자료를 권한 확인 없이 공유 캐시에 넣지 않는다.

## 8 저장과 비동기 작업

오디오 자산은 기존 영어 자료 개선 M1과 같은 소유권·해시·수명 규칙을 사용한다. 저장 백엔드는 L0에서 비공개 객체 저장 또는 영어 자산 저장 구현을 비교하고 실제 배포 경로의 업로드·부분 전송·최대 길이·용량을 검증한 뒤 결정한다. 기존 DB에 MP3를 무제한 적재하거나 이미 저장 서비스가 완성되었다고 가정하지 않는다. 최대 바이트뿐 아니라 재생 길이·MIME·파일 서명·실제 디코딩을 확인한다.

큰 음원은 서버 함수의 본문 한도에 걸리지 않게 서명된 직접 업로드 또는 검증된 청크 업로드를 사용한다. 미완료 업로드에는 만료 시각과 정리 주체를 두고 확정 전에는 재생·배정하지 못하게 한다. 저장 원본과 재생용 파생 파일을 구분하고 각 해시·개정을 기록한다.

L3의 긴 실전 파생 음원도 함수 요청 본문으로 왕복시키지 않는다. 작업 실행자가 저장소에 직접 저장하거나 검증된 청크 경로로 확정한다. L1의 짧은 음원 성공만으로 전체 실전 길이의 저장·부분 전송이 검증되었다고 처리하지 않는다.

L1은 작은 검수 음원의 등록과 재생만으로 범위를 제한한다. L3의 TTS·전사·정렬은 영속 작업 큐와 실제 작업 실행자가 있어야 활성화한다. 작업 표만 만들어 놓고 HTTP 요청 종료 뒤 계속 실행된다고 기대하지 않는다.

작업 상태는 `queued → running → needs_review 또는 succeeded`, 실패·취소 상태를 별도로 둔다. 실행 임대, 만료 작업 회수, 재시도 횟수·간격, 중복 방지, 계정별 동시성, 부분 산출물 정리와 오류 로그를 포함한다. 취소·권한 철회·원본 개정 변경을 최종 저장 직전에 재확인한다. 공급자 오류로 재시도하더라도 자동 발행은 하지 않는다.

배포는 추가형 데이터 구조 → 기존 읽기와 호환되는 배포 → 시범 쓰기 활성화 순서다. 새 데이터가 생긴 뒤 구형 읽기 전용 코드로 무조건 되돌리지 않는다. 데이터 보존과 쓰기 중지 절차를 정하고, 기존 영어 v1의 생성·저장·인쇄 회귀를 확인한다.

원본, 파생 음원, 응시 이력의 보존 기간과 삭제 범위는 별도 정책으로 정한다. 발행본이 참조하는 자산은 임의 정리하지 않는다. 권한 철회 시 향후 이용을 차단하고 감사 이력·법적 보존 필요를 확인해 삭제를 진행한다.

교사·학생 계정 삭제 시 기존 cascade와 충돌하지 않는 보존·익명화 정책을 L0에서 정한다. 과거 성적 유지가 필요한 경우 개인 식별 정보·답안·음원을 같은 기간 보존한다고 가정하지 않는다. 학생 운영 데이터가 생기는 L2 전에는 미결정 상태를 해소한다.

## 9 채점과 복습

객관식은 고정된 문항 ID와 정답으로 채점한다. 받아쓰기는 후속 단계에서 대소문자·공백·허용된 구두점을 정규화하고, 교사가 지정한 인정답과 비교한다. 부정어, 숫자, 단위가 달라지는 정규화는 하지 않는다. 철자 정확도와 듣기 이해 정답률은 별도 결과로 보여 준다.

듣기 평가에 쓰는 받아쓰기는 대본 공개 전에 한다. 대본을 본 뒤 표현을 적는 활동은 복습이며 최초 듣기 점수에 합치지 않는다.

같은 자료의 최초 응시, 반복 연습, 힌트 또는 대본 확인 후 응시를 구별한다. 학생이 앱 안에서 이미 본 동일·파생 자료는 노출 이력으로 표시한다. 앱 밖에서 본 적이 없는지까지 보장하지 않으므로 `앱 내 미노출`이라고 표현한다. 소수 문항으로 종합 듣기 능력이나 CEFR을 확정하지 않는다.

평가 배정 시 재노출 자료를 교사에게 알리고 미노출 자료를 우선한다. 결과 화면은 배정·제출 건수, 최초·복습 정오, 도움 사용, 중단·재응시를 보여 준다. 짧은 시범 점수를 하나의 종합 능력 지수나 예상 등급으로 바꾸지 않는다.

복습은 틀린 문항의 근거 구간과 표현을 다시 확인하고, 다음에는 같은 내용을 외워 맞히는 점수와 다른 대화의 유사 유형 점수를 분리한다. 간격 반복은 시범 운영 규칙으로 시작하고 효과를 관찰해 조정한다. 수학 복습 엔진과 결과 표를 공유하지 않는다. 최초 버전은 복잡한 적응형 추천보다 교사의 배정과 오답 목록을 우선한다.

## 10 콘텐츠 권한과 개인정보

시범 자료는 자체 제작 또는 허락 범위가 확인된 자료만 사용한다. EBS 등 외부 자료는 유형 연구와 원문 링크로 참고한다. 공개 다운로드와 앱 내 저장·재배포·외부 AI 전송은 별개의 사용 범위로 취급한다. [EBS 콘텐츠 사업 안내](https://about.ebs.co.kr/kor/business/contents)

원본 저장, 교사 검토, 생성 입력, 검색 적재, 외부 모델 전송, 학생 배포 권한을 각각 기록한다. 확인한 사람·시각·근거·유효 범위가 필요하다. 외부 모델 전송 전과 발행 직전에 권한을 재검사한다. 기존 v2 계약에 관련 필드가 있다는 사실을 운영 경로가 이미 집행한다는 뜻으로 읽지 않는다.

알 수 없는 권한을 기본 허용하지 않는다. 업로드 출처가 `user_supplied`이거나 요청 본문에 `approved`가 있다는 이유로 허용하지 않고, 권한 있는 교사의 확인 행위를 서버에서 기록한다. 허용된 용도만 열며 원본 보관 자체가 허용되지 않으면 파일을 저장하지 않는다. 외부 서비스는 요금제별 학습 활용·로그 보존·삭제 조건을 확인하고 운영 데이터에 맞는 설정을 선택한다. Google 가격표상 무료·유료 티어의 제품 개선 활용 여부가 다르므로 무료 키를 운영 기본값으로 삼지 않는다.

첫 범위에는 학생 음성 녹음과 발음 점수를 넣지 않는다. 학생 개인정보가 포함된 업로드는 외부 처리 전에 제거하거나 해당 처리 근거를 확인한다. 비밀 키·원문·정답·학생 식별 정보를 로그에 불필요하게 남기지 않는다.

| 소리 시작 실패·재생 중단·새로고침·통신 복구 | 데이터 보존, 중단 표시, 서버 시계 유지, 교사 재응시 이력 |
| 교사 방송 방식의 학생 요청 | 학생에게 음원 주소를 주지 않음. 교사 방송 실패와 학생 답안 통신 실패를 구분 |

L0의 권한·발행 계약이 고정된 뒤 자료·미디어와 학생 응시 흐름을 독립 작업으로 나눌 수 있다. 공용 계약 변경은 먼저 합의하고 같은 파일을 여러 세션에서 동시에 수정하지 않는다. 전체 자료 개선의 PDF/OCR 작업과 리스닝 작업은 자산 계약을 공유하며 출시를 서로 불필요하게 묶지 않는다.

화면 구현 전에는 저장소의 [CLAUDE.md 디자인 규칙](../../CLAUDE.md)에 따라 Wire 4~5안과 Hi-fi 4~5안을 구체적인 픽스처로 제시하고 선택을 받는다. 계획 검토와 운영 공유 데이터베이스 변경 승인은 별개다. 2026-10-03 구현 시작 승인 후 사용자가 **Wire 교사 A·학생 B, Hi-fi H1**을 선택했다. 두 선택은 확정이며 같은 화면 선택을 다시 묻지 않는다.

새 인쇄물은 `src/app/dev/print-check/items.ts`에 학생·교사 지면 검수 항목을 등록한다. DOM·PDF에서 대본·정답 누출, 문항 잘림, 그림·표·QR을 확인하고 실물 출력 확인 전에는 지면 검수를 완료로 처리하지 않는다.

기간과 총예산은 아직 산정하지 않는다. L0의 저장 실험, 지원 기기, 실제 음성 검수 시간을 재고 단계별로 견적을 낸다. “셋 다”의 첫 통합 완료는 L2이며, 공식 형식에 가까운 실전 연습의 완료는 L3이다.

유료 음성 벤치를 실행하는 별도 작업에서는 샘플 수·공급자·예상 비용·상한을 먼저 정한다. 이번 기획 검토에서는 유료 호출을 실행하지 않았다.

## 12 시범 운영과 다음 결정

첫 시범에서 교사의 자료 1개 준비 시간, 검수 수정 빈도, 학생 시작·완료율, 재생 실패·중단율, 지원이 필요한 문항, 최초 이해와 도움 후 개선, 자료당 총비용을 기록한다. 통과 수치가 없는 상태에서 성공했다고 선언하지 않도록 L0에서 표본·목표·중단 조건을 정한다.

학생 개별 재생 실패율은 해당 방식의 응시만 분모로 사용한다. 교사 방송은 방송 세션의 실패와 영향받은 학생 수를 별도로 보고한다. 최초 성과는 문항 정오 등 관측값이며 종합적인 이해 능력 판정이 아니다.

즉시 구체화할 산출물은 세 모드 화면 시안, 자체 대본·문항 fixture, 발행과 응시 상태 전이 표, 권한 테스트 표, 비공개 음원 저장 실험이다. 공급자 최종 선택, 운영 업로드 한도, 장기 보존 기간, 실제 시험 프리셋의 시간표는 실물 검증 후 확정할 사항이다.
