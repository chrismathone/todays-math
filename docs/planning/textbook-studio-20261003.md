## 확정할 기본 선택

아래는 합의를 요청하는 리드 제안이다. 세 모델의 실제 수정·표결을 반영한 버전에만 구현 승인을 기록한다.

1. **메뉴:** `textbook`, 수학 메뉴의 내 시험지와 수업·학생 관리 사이. 메뉴 배열·런타임 enum·DB CHECK·해시·API·인쇄 경로를 함께 갱신한다. 기존 새 메뉴 관례대로 승인된 계정의 기본 메뉴에 추가하며 관리자에서 회수할 수 있다. 특정 사용자만 여는 별도 데이터 변경을 몰래 하지 않는다. 영어 레거시 `english`와 세 분리 메뉴의 CHECK 불일치는 같은 확장 마이그레이션과 명시적인 회귀 시험으로 해결한다.
2. **저장:** 전용 교재·판본·구획·스냅샷·배치·자산 관계·영상·QR·배정·발행 작업 모델을 사용한다. `WorkspaceDocument`의 다른 kind에 우회 저장하지 않는다. 변경·계정 삭제에 종속되는 `workspace_asset` 대신 내용 해시 기반 불변 `textbook_blob`을 둔다. 발행본·스냅샷·QR 대상·바이트의 불변성은 DB 트리거와 RESTRICT 외래키로도 지킨다. 구획별 CAS와 판본 전체 revision을 함께 관리한다.
3. **소유:** 원고는 개인 작업물로 시작한다. 지점 공유는 소유자의 명시적 선택이며, 동료는 읽기·독립 사본만 가능하다. 사본에는 새 book/edition/item ID와 새 QR을 발급한다. 개인 문서 권한에 운영 데이터의 관리자 소유자 우회를 적용하지 않는다. 학생 배정은 교재 접근권과 실제 반·학생 소유 범위를 모두 검사한다. 지점 이동·공유 취소·계정 정지는 다음 요청에 반영한다. 교사의 메뉴 회수는 편집·새 배정을 막되 유효하게 배정한 기존 학생 열람을 자동 취소하지 않는다. 소유자가 지점을 떠나면 동료 반 배정은 닫히며 학생에게 접근 불가 사유를 안내한다.
4. **사용 흐름:** 교재 목록 → 만들기/가져오기 → 단원·구획 구성 → 원고 편집과 펼침면 → 문항/영상 연결 → 검수 → 저장·내보내기·발행. 새 책을 실제로 만들고 서버에서 다시 열 수 있어야 한다. 원시 JSON만 고치는 화면은 인정하지 않는다.
5. **디자인:** 기존 `--learn-*`와 Pretendard 화면 체계를 유지한다. 교재 지면의 색·서체·캐릭터는 화면 도구와 별도 토큰이다. Wire 4안의 실제 1280/390px 시안을 동일 조건으로 비교한 뒤, 선택 구조의 Hi-fi 4안을 만든다. 사용자의 3자 합의 지시에 따라 세 실제 모델의 표결로 선택하고 기록한다. 그 전 제품 UI 구현을 시작하지 않는다.
6. **학습 데이터:** 학교급·학년·학기·권차·과정·설정·원고·조판 코어를 분리한다. 중2 1학기 3권 코드는 `2-1-1/2-1-2/2-1-3`. 학교급도 내부 키에 포함한다. 216±20쪽은 soft target이며 기존 259쪽을 억지로 줄이지 않는다. 미작성 학년은 미작성이라고 표시한다.
7. **AI:** 새 유료 AI 통합을 기본 경로에 넣지 않는다. 기존 문항을 두 번 생성해 같게 만들지 않고, 같은 데이터로 렌더한다. 확장 원고 생성이나 의미 기반 매칭을 추가할 때만 프로젝트 TypeSafe 스킬과 live 문서를 읽고 별도 판단 계약을 검토한다. 동일성·해시·계산·조판·접근권은 결정적인 코드다.

## 공통 계약과 동일성

`injaewon.textbook.exchange.v1`의 의미를 유지하는 하나의 Zod 계약과 TypeScript 타입을 서버·편집기·변환기·내보내기가 공유한다. 실제 스키마는 후속 검토에서 파일과 함수 단위로 고정한다.

- `bookId`는 교재, `editionId`는 판본, `revision`은 편집 충돌, `problemId/problemCode`는 저장된 원문 연결, `snapshotId`는 특정 내용, `itemId`는 반복을 포함한 배치, `displayNumber`는 표시 번호다. 어느 쌍도 혼용하지 않는다.
- linked 문항은 서버가 기존 출제 가능 정책·pool·실제 ID/코드·내용을 문항마다 검증한 것만 가능하다. 스냅샷 표에도 기존 격리 문항 외벽 트리거를 건다. `Problem`은 공유 문항이며 `Problem.userId`로 교재 소유를 판단하지 않는다. 소유 범위는 교재·원본 시험지·배정에 각각 적용한다. `familyKey` 또는 유사도만으로 확정하지 않는다. 원문 변경 뒤 예전 코드를 붙인 새 문항을 linked로 표시하지 않는다.
- 원본 `Problem`과 `Test`를 가져오는 동작은 원래 시험지나 문제를 변경하지 않는다. 새 문항 등록·변형은 기존 등록/검수 정책을 따르는 명시적 동작이며 요청 ID로 중복을 방지한다.
- `contentHash`는 payload 전체를 원문 그대로 재귀 키 정렬·배열 순서 유지·UTF-8 JSON·SHA-256으로 계산한다. 공백·LaTeX·부호·보기 순서를 임의 정규화하지 않는다. 정답·해설 변경도 새 snapshot이다. 해시가 같아도 다른 problemId를 합치지 않는다.
- P1에서 `canonicalizationVersion: injaewon.textbook.c14n.v1`과 content/manifest의 정확한 투영 필드, 포함·제외·변이 검증 벡터를 고정한다. `contentHash` 입력은 payload 전체이며 ID/시간/page/QR/다운로드 URL은 제외하되 payload 안의 assetId는 보존한다. 발행본 재포장 시 assetId를 재발급하지 않는다. manifest는 최종 config·edition identity/label·units·snapshots와 contentHash·items·assets와 byte hash·qrTargets·pageMap·renderer/template/canonicalization 버전으로 계산하고 자신의 hash·내보내기 시각·mutable video status/URL은 제외한다.
- 손실이 있는 기존 `serializeProblem`/`toPrintProblem`의 반환값이나 목적이 다른 `problemFingerprint`를 무손실 snapshot/hash 입력으로 재사용하지 않는다. 전용 어댑터가 원본 행을 읽고 raw 보존값과 렌더용 표현을 분리한다. source figureDims와 실제 자산에서 측정한 픽셀 치수는 다른 필드로 보존한다.
- `figureSvg`, `figureUrls`, `figureDims`, `figureSourceMm`, `choiceFigureIndex`의 순서·물리 폭·대응·미상 값을 모두 보존한다. 실제 자산 바이트를 승인된 저장에 고정하고 해시를 검증한다. `choiceIndex` 0/양수/null의 의미를 유지한다.
- 발행본은 설정·원고·스냅샷·자산·배치·쪽 지도·QR target·renderer/template 버전을 고정한다. 편집 요청은 새 판본 초안을 만든다. 변경 가능한 영상 상태/URL은 manifestHash에 포함하지 않고 별도 이력을 남긴다.
- 교재의 같은 문제로 재출제할 때도 발행 snapshot을 사용한다. 별도 additive migration으로 `test_problem.snapshot_id` nullable FK를 추가하고 `src/lib/tests/testProblemContent.ts`의 `contentOf`를 화면·인쇄·채점표·자동 채점·내보내기의 공통 내용 통로로 둔다. 현재 `loadTestProblemItems`는 live Problem을 읽으므로 그대로 재사용하지 않는다. 원본 문제 ID는 단원·통계·격리 정책에 유지하며 내용을 새로 읽는 파일이 통로를 우회하는지 전수 가드한다. 문제 교체 시 snapshot 연결을 명시적으로 비운다. 원본 삭제/출제 자격 박탈 시 시험지 재출제를 거부하고 이유를 알린다. 발행본 자체는 그대로 보존한다.
- 엄격한 버전/필드/ID/참조/배열/개수/바이트 검증. 모르는 필드를 조용히 버리지 않는다. ZIP은 경로 이탈·압축 폭탄·실행 콘텐츠·누락/위조 해시를 거부한다. 모든 숫자는 실제 범위를 제한한다.
- 교육과정 목록은 기존 단원/선수 데이터와 별도로 복제해 정본을 만들지 않는다. 연결 출처·확인일·검증 범위를 기록한다. 기존 선수 관계는 교육적 추론이며 성취기준 전수 대조 미완료·소단원 직접 선수 간선 미포함 상태를 유지한다. 배열 순서나 단원 관계를 소단원 선수 조건으로 확대하지 않고, 학생 숙달 기록도 교재 원고와 분리한다.

## 개념백지·학생 학습과의 통합

2026-10-03 추가 사용자 지시 «실제로 책에 들어가는 개념들도 개념백지와 연관되게», «모든 웹앱시스템이 철저히 한팀이 되게 유기적으로»를 제품 인수 조건에 포함한다. 교재 탭은 기존 학습 기능들과 같은 데이터·권한·학생을 쓰며, 메뉴 간 단순 링크만으로 통합 완료라고 하지 않는다.

- 현재 정본: 개념백지는 `CONCEPT_BLANK_BANK`의 `concepts/ox/apply/figures`, 탐험은 보정된 `definitionCards`, 문제은행은 DB `Problem/Unit`, 코스는 `COURSE_SECTIONS`, 선수 그래프는 기존 편집 데이터다. 같은 이름이나 `familyKey`를 공통 conceptId로 쓰지 않는다. 각 namespace와 실제 ID를 유지하는 검수된 연결 계약을 둔다.
- 교재의 각 개념 블록에 `blockId`, 개념백지 `sectionKey`와 정확한 `entryKind/entryId` 목록·순서, 선택적인 DB `unitId`/코스 `sectionId`/탐험 `cardId`/그래프 `unitId`, 연결 상태·검수 출처·매핑 버전을 둔다. 예를 들어 개념백지 `e5-1-4-3-c1`과 탐험 `g5-common-denominator`는 서로 다른 참조다. 기존 `curriculumBridge.ts`는 후보 근거로 재사용하되 소단원 일치만으로 모든 항목이 같은 개념이라고 확정하지 않는다.
- 편집기에서 실제 개념백지 항목을 검색·선택하고 핵심 정의·조건·키워드·예/반례를 같은 검수 대상으로 확인한다. 긴 설명·대화는 교재 원고로 남되 원래 핵심 정의와의 차이를 표시한다. 필요한 항목이 없으면 «연결할 개념 없음»으로 남기고 검수된 은행 보강 대상으로 삼는다. 조용한 다른 개념 대체는 없다.
- 현재 개념백지 저장은 `{selection}`뿐이며 특정 항목 선택도 없다. 기존 문서 호환을 유지하면서 **정확한 항목 ID/순서 선택**을 계약과 `composeSheets` 경로에 추가한다. 교재에서 «이 개념으로 백지 만들기»를 누르면 같은 항목만 들어간다. 알 수 없는 키를 조용히 제거하는 기존 동작은 이 경로에서 오류로 보고한다.
- 발행 시 실제 개념 원고와 개념백지 선택 항목의 본문·정답·그림·`givenCase`·순서·매핑 버전·SHA-256을 **개념 snapshot**으로 고정한다. 코드 은행의 최신 선택만 저장하거나 20비트 지면 코드를 불변 원문 대신 쓰지 않는다. 같은 렌더·파서·은행을 재사용하며 고정된 과거 snapshot은 새 정본 은행으로 취급하지 않는다. 새 판본에서만 최신 내용 차이를 보고 갱신한다. 발행 개념 블록의 누락/불명 연결은 검수 오류다.
- 교사용 원클릭 동선: 교재 개념 → 그 개념의 백지 편집/인쇄 → 연결된 출제 가능 문항 → 같은 학생·반에 배정. 동선에 `editionId/conceptSnapshotId/itemId`의 검증된 출처를 전달하고 기존 교사 메뉴·소유권을 매번 확인한다. 교재 돌아가기 문맥을 유지한다.
- 학생 동선: 배정된 교재 개념 설명 → 해당 판본의 백지 활동 → 제출 또는 교사의 종이 활동 확인 → 연결 개념의 기존 탐험/복습. 개념백지에는 현재 학생 제출 API가 없으므로 별도의 작은 `textbookConceptAttempt` 계약/저장 경로를 추가한다. 텍스트 응답과 교사 관찰을 구별하고, 응답·판본·개념 snapshot·채점 방식·확인자·시각·요청 ID를 기록한다. 열린 답은 교사가 확인하며 새 유료 AI 채점을 넣지 않는다. 원본 Problem이 없는 백지 항목을 `ProblemAnswer`에 가짜 ID로 넣지 않는다.
- `/learn`에는 현재 교재·카드 진입 문맥이 없으므로 서버가 배정/연결을 확인한 학습 문맥을 추가한다. 탐험을 시작할 때는 기존 `handleExplorerRequest`와 `changeSrsState`의 CAS·미완료 탐험·재전송 규칙을 따른다. 다른 미션이 열려 있으면 이어하기와 이후 복습을 안내하고 현재 미션/goal/보상/복습 기한을 덮어쓰지 않는다.
- 교사 학생 상세에서 교재·백지 제출/확인, 같은 개념의 기존 탐험 결과, 연결 문제 풀이를 함께 보여 준다. 기존 `explorerTeacherSummary/Detail`와 교사 범위 검증을 재사용한다. 관찰 출처·날짜·판본·채점 방식을 보존하고 서로 다른 결과를 하나의 근거 없는 숙달 점수로 합치지 않는다. 책 열람·영상 시청·종이 제출은 탐험 정답 이벤트가 아니다.
- 선수 추천은 기존 승인된 초5 분수 확인 경로와 OFF 기본값을 그대로 둔다. 교재/백지 결과에서 자동 새 선수 간선을 만들거나 범위를 넓히지 않는다. 추가 연결은 교사 확인용 후보로 제시하고 학생 숙달은 기존 교육과정 정본 밖에 저장한다.
- 통합 시험: 정확한 개념 ID 선택 → 동일 항목 백지 → 발행 snapshot → 권한 있는 학생 응답 → 교사 확인 → 연결된 기존 복습 기록 표시까지 한 시나리오로 검증한다. 은행 개정/개념 삭제·동명이개념·동시 탭·메뉴/배정 회수·진행 중 탐험·응답 재시도·학생 답 누출도 부정 시험한다.

## 원고 편집과 조판 상세

- 텍스트, 대화(여자 선생님/민서/지호·표정·방향), 개념(목표·선수·정의·조건·예/반례·오개념), 대표예제, 개념학습/핵심어/통문장, 연습문항, 그림, 영상 참조를 명시적 타입으로 편집한다. 역할·학습 단계·난도는 다른 축이다.
- 대표예제의 공개 풀이와 연습문항의 교사용 정답을 구별한다. 학생 인쇄용 PDF/HTML 및 그 생성 DTO에는 연습 답·해설·교사 메모가 서버에서 제거돼야 한다. 인증된 QR 해설 열람은 배정과 명시적 글 해설 공개 정책을 통과한 문항의 답/해설만 별도 학생 DTO로 제공할 수 있다. 교사용 전체 교환 JSON은 학생에게 보내지 않는다.
- 원문은 Markdown+LaTeX. 기존 `[[...]]`/`{{...}}`는 전용 어댑터로 의미를 보존하며 원본 백업·변환 원장을 둔다. 임의 HTML/스크립트는 실행하지 않는다. KaTeX 오류·지원하지 않는 명령·넘침은 원고 위치와 연결한다.
- 대화는 연속 수업 흐름을 유지한다. 얼굴 방향만 반전하고 말풍선·수식은 반전하지 않는다. 여자 선생님을 유지하며 필요한 원본 이미지 미확보 시 임의 인물로 v15를 재현했다고 하지 않는다.
- 단원 도입은 짝수 왼쪽 + 홀수 오른쪽 2쪽. **모든 주요 구획은 even-left**, 그 안의 하위 단계는 continue다. 실제 제본 순서·표지 포함/분리·본문 시작 면·표시 쪽번호를 구분한다.
- 불가능한 시작 면은 해당 구획과 이전 구획을 가리키는 편집 오류다. 빈 페이지·무관한 삽화·읽을거리·임의 생성/삭제로 성공 처리하지 않는다. 기존 원고 재배치/풀이 공간/실제 학습상 필요한 편집은 교사의 명시적 변경이다.
- 풀이선 기본 7mm, 같은 펼침면의 대응 행 시작/끝/하단을 맞춘다. 짧은 문제에는 해당 영역 안에서 추가 풀이 공간을 주고 다음 행/QR/자기점검을 침범하지 않는다. 개념학습에는 1–4회 점검 원을 둘 수 있고 keywords/sentences에는 회차 원을 넣지 않는다.
- 같은 DOM/치수/폰트/KaTeX를 미리보기와 인쇄에 사용한다. 구획만 다시 측정하고 뒤쪽 쪽번호는 누적 계산한다. 편집기는 현재 펼침면과 인접 펼침만 렌더하며 전권 PDF는 bounded 작업으로 별도 처리한다.
- 실제 페이지 지도에서 목차·색인·번호·해설 참조·CSV를 동시에 생성한다. 이전 `q.page`를 신뢰하지 않는다.

## 영상·QR·학생 접근

- 서버가 발급한 영구 HTTPS `/q/{opaqueSlug}` 계열 주소를 사용한다. 배포 origin은 설정된 정식 서비스 origin만 허용한다. localhost·임시 프리뷰·서명 URL·학생 식별자를 QR에 넣지 않는다.
- QR target은 `edition+item`, 영상 binding은 snapshot과 검수 contentHash에 연결한다. slug/target은 재사용·재할당하지 않는다. 영상 교체는 같은 snapshot 검수 후 가능하고 기존 QR은 유지한다.
- 개념 예습과 문제 해설을 별도 상태/연결로 둔다. 기존 개념영상을 단원이 같다는 이유로 문제영상으로 표시하지 않는다. 초안/검수대기/게시/게시중지를 구분하고 구간 시작/끝을 검사한다.
- `videoPolicy: required`는 검수·게시 누락을 막는다. optional은 준비 중인 영상을 허용하지만 문제 동일성·권한·QR 정확성을 완화하지 않는다. 영상 없는 영구 문제 페이지는 정확히 준비 중을 표시한다. 미연결 legacy에는 가짜 QR을 넣지 않는다.
- 기존 학생 인증을 사용한다. 로그인 후 허용된 서비스 내부 원래 QR로 돌아온다. 현재 `/learn/login`의 통합 `/login` 이동, `AuthForm`의 학생 성공 분기, 최초 비밀번호 변경 후 복귀까지 같은 허용 경로 검증기를 사용해 QR 목적지를 이어 간다. 학생 세션·현재 지점·교재/범위 배정·회수·만료·반 이동을 매 요청 서버에서 확인한다. 배정 예습은 진도 기록 전에도 열리며 기존 개념영상의 진도 규칙은 따로 유지한다.
- 학생에게는 허용된 판본/문제/게시 영상과 정책상 공개한 글 해설만 보낸다. 미발행 QR은 교사 미리보기 외 비공개. 다른 학생/지점·교사 초안은 공개하지 않는다.

## 저장·발행·내보내기

1. 구획 CAS 저장과 판본 revision을 연결한다. 409에서는 사용자의 수정본을 보존하고 최신본 비교·복사/새 초안 저장을 제공하며 자동 덮어쓰지 않는다. 서버 저장과 브라우저 임시본의 상태를 구분한다. 계정별 키·계정 전환/권한 회수·실패 복구를 시험한다.
2. 발행 요청은 저장된 특정 revision을 대상으로 한다. 원고·문항 연결·교열·영상 정책·자산·참조를 서버에서 검사하고 QR을 예약한다. 예약 상태는 학생에게 열리지 않는다.
3. 실제 예약 URL로 PDF를 렌더한다. 저장된 고정 revision을 서버가 구획 묶음 단위로 조판하고 작업 상태·임대를 저장해 재개한다. 기존 `launchExportBrowser`를 사용하되 신뢰한 공통 조판 번들·로컬 글꼴·정본 자산만 요청 가로채기로 공급하며 외부 요청은 차단한다. 서버가 layout/pageMap·수식/자산·생성 PDF의 모든 QR decode·artifact byte hash를 확인한다. 클라이언트 성공 플래그나 임의 업로드 PDF로 발행하지 않는다. 전권을 기존 HTML 8,000,000자 상한/60초 generic PDF 경로(`src/lib/export/pdfServer.ts`의 `PdfPayloadSchema`)에 넣지 않는다. 조판 트랙 첫 작업에서 200쪽 이상 시험 원고로 실행 시간·메모리를 측정하고 묶음 크기를 정한다.
4. 발행 직전 revision을 다시 비교하고 불변 원고·pageMap·QR·manifestHash·PDF hash를 원자적으로 확정한다. DB와 파일 저장을 하나의 원자 작업처럼 가정하지 않는다. 실패는 비공개 예약/임시 업로드 상태로 남기고 같은 요청 재시도는 같은 결과를 반환한다.
5. 학생용·정답해설 PDF, 펼침면, 안전한 단일 오프라인 HTML, JSON/ZIP, `mapping.csv`, `validation.json`을 제공한다. 패키지는 로컬 글꼴·KaTeX·이미지·도형을 포함하고 자격증명은 포함하지 않는다. 온라인 영상의 오프라인 재생을 약속하지 않는다. 합친 PDF가 저장 한도를 넘으면 검증한 분권 PDF와 전체 쪽 지도·ZIP을 제공하며 이를 한 파일이라고 표시하지 않는다.
6. 발행본 삭제로 인쇄 QR을 끊지 않고 retired/withdrawn 안내를 유지한다. 운영 자료의 자동 삭제/정리 job을 추가하지 않는다.
7. 발행 교환 패키지를 보관본으로 열 때는 원래 ID·manifest·쪽 지도·QR·영상 메타데이터를 그대로 보존하고 읽기 전용으로 표시한다. 온라인 새 원고로 복사하는 동작은 별도이며 새 ID·QR을 발급하고 원본 패키지와 ID 이동표를 보관한다. 다른 서버가 발급한 QR/영상 검수 권한을 가져오기 성공만으로 부여하지 않는다. 필드를 조용히 버리는 왕복 변환은 허용하지 않는다.
8. 한 책에 활성 초안 하나, 학생 글 해설 정책 기본값 `never`, QR 방문으로 별도 숙달 기록을 만들지 않는 것으로 시작한다. 개념영상 배정 접근만으로 기존 시청 진도를 만들어 내지 않는다. 예약한 QR은 삭제·재사용하지 않는다. 예약 후 문항 빼기는 QR을 void로 남기며 발행 직전 원자 확정만 active로 바꾼다.

## 인수 기준과 완료 상태

입력 03의 I-01~I-20을 누락 없이 검증 원장에 옮긴다. 각 항목은 시험 파일/실행 결과/실측 artifact/미실행 이유를 갖는다. 최소 독립 부정 시험은 아래와 같다.

- 숫자가 다른 같은 family 두 문제, 같은 문제의 반복 배치, 원문/정답/도형 변경, 새 판본 수정 후 옛 QR/PDF 불변.
- 잘못된 코드/후보 매칭/미연결/외부 자산/해시·참조·버전 위조, 파일 이탈·압축 폭탄·SVG 실행·수식 오류·CSV 수식 값.
- 다른 계정/지점/반/학생, 메뉴 회수·공유 회수·만료·반 이동·미발행 QR·로그인 복귀 주소 위조.
- 저장 성공 응답 유실·동시 편집·가져오기/발행 재시도·조판 중 revision 변경·영상 검수 hash 변경·필수 영상 누락.
- 학생 payload/DOM/HTML/PDF에서 연습 답·교사 정보가 없고, 공개 대표예제 풀이만 유지됨.
- 긴 대화/다층 분수/도형 보기/문항 수 변경/표지 분리/3쪽 대화의 even-left 충돌/마지막 쪽에 누락·잘림·임의 filler 없음.
- 초등 실제 짧은 원고와 다른 중등 단원, 동일 템플릿에서 고정 중2 문구 없음. 시험 fixture는 실제 전권과 명확히 구분.
- 200쪽 이상 전체 규모의 저장·재열기·구획 이동·내보내기 벽시계/메모리/바이트 측정. 모든 페이지의 영역 검사와 대표/경고 쪽 이미지 검수. 좌우 기준선 목표 오차 0.5mm.
- 출력 PDF의 **모든** QR 디코드와 manifest URL 일치, 실제 권한/문제 대응. 실제 영상·모바일·물리 인쇄 확인은 모의 시험과 별도.

최종 보고는 기능/원고/문항 연결/영상/인쇄를 각각 집계한다. 원본 미확보는 v15 이관 미완료, 실제 영상 없으면 준비 중, 실물 인쇄 미실시는 `/dev/print-check` 대기로 남긴다. 필요한 것까지 만들고 검증하며 부분 구현을 전체 완료로 부르지 않는다.
