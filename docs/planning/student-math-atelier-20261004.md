## P0 피드백과 전환

1. AnswerFeedbackEffect의 중앙 방사 overlay/큰 메달/불꽃을 아이콘+상태 문장이 있는 inline 결과로 바꾼다. 탐험 보기에 체크 글자를 다시 넣지 않는다. 오답 선택은 기존 코발트다. data-answer-feedback/data-page-turn/data-explorer-dock/data-expedition-* 표지를 유지한다.
2. 각 dock/재풀이 격자의 기존 지시 줄 또는 답한 뒤 비는 controls 줄을 결과 줄로 사용한다. dock 밖에 56px를 추가하지 않으며 총높이를 유지하는 배치를 우선한다. 줄바꿈/200%/짧은 화면에서는 자연스럽게 결과 줄이 늘어도 기존 문제 스크롤로 본문에 접근하고 결과가 보기/수식을 덮지 않아야 한다. 고정 56px 강제 대신 실제 줄바꿈과 실측으로 검증한다.
3. 장식 opacity 모션은 420ms 이하. 결과 문장은 correct 상태가 유지되는 동안 남고 CSS 끝 프레임으로 숨기지 않는다. 기존 1200ms hold/자동 넘김 및 이미 있는 수동 다음 버튼/포커스 규칙을 보존한다. 한 결과의 live region은 하나다.
4. 문구는 클라이언트에서 정중한 평서형으로 매핑한다. 느낌표/서버의 반말을 그대로 복사하지 않는다. 서버 문자열/스키마를 바꾸지 않는다.
   - 첫 풀이 오답은 기본 '다시 생각해 볼 문제예요'. 실제 큐가 새로 생긴 상태에서만 '모았어요'를 사용할 수 있다. 첫 풀이 초등 giveUp도 나중에 큐에 들어가므로 큐 없음으로 단정하지 않는다.
   - '모르겠어요'는 제출 action으로 구분한다. 빈 submittedAnswer로 자기 평가와 혼동하지 않는다. 큰 X/콤보 상실 표현을 하지 않는다. 예: '모르는 부분을 확인했어요'.
   - 큐 안 재풀이 오답은 '아직 해결하지 못했어요'; 초등 재풀이 giveUp은 큐에서 빠지는 현행 동작을 유지하고 '아직 모르겠어요로 기록했어요' 등 실제 기록 안내만 한다.
   - 미션 재풀이 정답은 '이번에는 해결했어요'. 완료 칸 재풀이 정답은 '정확하게 풀었어요', 오답은 '다시 생각해 보세요'(오늘 큐가 늘었다는 말 없음).
   - 자기 평가는 '혼자 풀었다고 기록했어요' / '다시 볼 내용으로 기록했어요' 등 자기 평가 기록임을 밝힌다.
   - 공방 split/match/rule 오답은 해당 조작 재시도 안내. check 오답은 다음으로 진행하므로 '확인 결과를 기록했어요'. reviewOnly/보충 카드의 오답은 큐·수집 주장을 피하는 기본 문구.
5. 답 피드백은 현재 네 화면의 확인된 로컬 제출 전이에만 뜬다. 탐험 requestId, 초등 feedbackId 및 문제/재풀이키, 중등 feedbackId/retryTurn, replay feedbackEvent를 유지한다. 같은 requestId가 확인된 뒤 다시 재생되지 않게 필요할 때 client guard를 보강한다. 응답을 받기 전 실패 후 같은 요청이 처음 확인되면 한 번 보여준다. 로드/해설/409/5xx/늦은 응답/학생 전환은 새 답 효과를 만들지 않는다. 서버 필드를 만들지 않는다.
6. 본문 520ms rotateY와 빛 띠를 걷고 120~180ms opacity 전환만 쓴다(이동 0px 허용). 스크롤 컨테이너를 이동/확대하지 않는다. 첫 마운트는 즉시 표시, 확인된 문제 전환만 짧게 표시한다. 현재 문제 머리/다음 버튼 포커스와 키보드 예외를 유지한다. 빛 띠 고정시험은 원래 목적인 넘침 방지로 개정한다.

## P1 홈/공방/기기 설정

7. 모바일의 기존 미션→지도→도구→pendingReview DOM 순서 유지. PC는 지도 칸 폭 480px 이상이 확보되는 넓은 화면에서만 미션/지도 나란히(max~1120). 768은 한 열. 기존 next/active/activeReview/pendingRetry/complete/unavailable/prerequisiteContext/canStart/busy/saving/loading/오류 상태와 실제 goal을 유지한다. 기록 카드/새 미션을 만들지 않는다. 도감/기지/시트는 표면/여백만 정리한다.
8. 분수 공방은 전체 길이·칠한 양과 즉시 값 갱신을 유지하고 색 외 선택 패턴을 보강한다. ✓ 글자를 칸에 넣지 않는다. match는 (3,2)뿐 아니라 (6,4) 등 같은 분모도 허용하는 현행 채점, check는 선택 개수만 보는 현행 채점 그대로다. 별도 lab 드래그/자동 제출/합성음은 제외한다.
9. 움직임 줄이기는 학생 id가 없는 namespace 로컬 기기 preference다. OS reduce OR 앱 reduce가 적용되며 저장소 실패에도 이번 화면에서 동작한다. 학년/단원 설정 잠금/저장 중에도 토글이 작동하고 풀이 중 접근 가능하다. 공통 훅으로 지도 WAAPI를 취소/생략한다. 학생 수학 module의 기존 OS reduced 선언과 동일한 최종 상태 선언을 앱 줄이기에서도 쓴다. 무차별 animation:none!important 규칙을 복사하지 않는다. CSS 체크 선/상자/칸 효과의 최종 상태는 보인다. 지도 이동 경로 650ms 유지, 장식 hop<=8px, 착지 확대/회전 장식 제거, 줄이기에서 가만히 몸짓도 없음. 언마운트/설정 전환 시 WAAPI 정리.
