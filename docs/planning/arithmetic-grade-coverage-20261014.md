## 이후 확정·구현된 직접 연산

사용자가 같은 날 나머지 학년 구현을 지시했고, 실제 연산이 가능한 영역만 포함하도록 범위를 좁혔다. [확정 실행 범위](arithmetic-expansion-20261014.md)에 따라 v2에 아래 **53개 직접 연산 유형**을 추가했다. 기존 v1의 7개 자연수 스킬·97개 세부 프리셋도 유지한다. 아래 수는 학년 전체나 성취기준 완성도가 아니다.

## 최초 감사 당시의 결론과 v1 범위

**현재 초3부터 중3까지를 다룬다고 말할 수 없다.** 97개 프리셋은 아래 7개 자연수 연산군의 조건 변형이며, 97개 교육과정 주제가 아니다. 초3 계산의 일부와 선수 연습에 쓸 수 있지만 **어느 학년의 연산 전체도, 어느 학년의 수학 전체도 완성하지 않았다.** 정답 계산 성공은 원리 이해나 성취기준 달성의 증거와도 다르다.

| 구현된 스킬                                        | 실제 입력·결과 제한                                             |
| -------------------------------------------------- | --------------------------------------------------------------- |
| `one-digit-add`, `one-digit-sub`                   | 피연산자 0~9, 뺄셈 결과 0 이상                                  |
| `two-digit-vertical-add`, `two-digit-vertical-sub` | 피연산자 10–99, 받아올림 0–2회·받아내림 0~1회, 뺄셈 결과 0 이상 |
| `times-table`                                      | 단과 곱하는 수 각각 1~9                                         |
| `two-digit-times-one`                              | 10–99 × 1–9, 받아올림 조건                                      |
| `two-digit-div-one`                                | 10–99 ÷ 1–9, **나머지 0만**                                     |

근거: [계약](../../src/contracts/arithmetic.contract.ts), [카탈로그](../../src/lib/arithmetic/catalog.ts), [프리셋](../../src/lib/arithmeticPresets.ts). 정답 계약은 0~999 정수 문자열이고 분수·소수·음수·근호·문자식·방정식 계약은 없다. 엔진/카탈로그 v1, 학습지 payload v1은 저장된 발문·정답 스냅샷을 검증해 다시 열며 재생성하지 않는다. 기존 [검증 보고](../reports/arithmetic-presets-20261014/report.txt)의 313개 통과 테스트, 97개 예시, 19,456개 생성 문항 검사는 **현재 7종**의 증거다. 이번 문서 작업에서 재실행하지 않았고, 학년 적합성 시험으로 해석하지 않는다.

## 교육과정 근거의 범위

교육부 시행 일정상 2026학년도 초3–초6·중1–중2는 2022 개정, **중3은 2015 개정이며 2027-03-01부터 2022 개정** 적용이다.[S1] 아래 `4수`, `6수`, `9수` 코드는 각각 초3–4, 초5–6, 중1~3 **학년군** 기준이다. 국가 고시가 개별 학년·학기·교과서 단원 순서를 모두 지정한 것으로 읽지 않는다.[S2]

초등 학년 배치는 교육청 성취기준-단원 연결표[S4][S5]와 저장소 [단원 자료](../../src/lib/lab/units.json), [검토 문서](../lab/elementary-math-feasibility.md)를 대조했다. 중학교 세부 학년 배치는 [단원 시드](../../prisma/seed-data/units.ts)의 중1 `소인수분해/정수와 유리수`, 중2 `수와 식`, 중3 `실수와 그 계산`을 따른 **제품 제안**이다. 시드와 개념은행은 국가 고시 원문도 연산 엔진 구현도 아니다. 학교별 교과서·차시와 중학교 개별 학년 배치의 공식 대조는 미완료다.

## 수치·정답 계약을 먼저 확장한다

다음은 **새 버전의 설계 제안**이다. 현 v1 정답 문자열에 수식을 임의로 끼워 넣지 않는다. JSON에는 BigInt 값을 직접 저장하지 않고 정규화한 정수 문자열을 저장하며, 계산·동치 판정은 BigInt 기반으로 한다. 입력 자릿수·지수·분모·항 수 제한을 두어 자원 사용도 제한한다.

| 종류             | 저장·판정 제안                                                                                                                                                                                                                |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 정수·몫과 나머지 | 부호 있는 정수 문자열, `−0` 정규화. 몫·나머지는 `{quotient, remainder}` 두 정수; 자연수 제수에 대해 `a=bq+r`, `0≤r<b` 검증                                                                                                    |
| 분수·유리수      | `{numerator, denominator}` 정수 문자열, 분모>0, gcd=1, 0은 `0/1`. 계산값과 표시 형식을 분리하여 가분수/대분수·약분 여부·지정 통분 분모까지 검사. 값이 같은 `2/4`, `1/2`를 모든 과제에서 무조건 같은 응답으로 취급하지 않음    |
| 유한소수         | `{coefficient, scale}`로 `coefficient × 10^(−scale)` 표현; 표시 자릿수는 별도 보존. 부동소수 오차 허용치로 정답을 판정하지 않음. 기약분수 분모의 소인수가 2·5뿐일 때만 유한소수; 정확값 모드와 반올림 모드의 자리·방법을 분리 |
| 순환소수         | 부호·정수부·비순환부·순환마디로 표시, 값은 위 유리수로 정규화. 정수식으로 분수 변환, 최소 주기 확인, 끝없는 0/9 표현 제외. 현재 출시 계약에 없음                                                                              |
| 근호             | 유리수 계수 × 제곱인수 없는 양의 정수의 제곱근 항들의 정규형; 0과 유리수 항 별도 처리, 같은 근호 결합. 부동소수 근삿값 비교로 동치 판정하지 않음; 초기에는 단일 근호 제수로 닫힌 범위만 지원                                  |

**순수 수치 연산과 방정식 풀이는 분리한다.** 중1 일차식 ±, 중2 단항식·다항식 계산, 중3 전개·인수분해는 선택 가능한 **문자식 계산** 확장이다(2022 `9수02-02·08~10·19`, 2015 중3 `9수02-12`).[S2][S3] 도입하려면 유리수 계수·변수·차수의 다항식 정규형과 동치 검사, 인수분해 결과의 전개 역검사가 필요하다. 임의 몇 점 대입만으로 항등성을 확정하지 않는다. 일차방정식·연립방정식·부등식·이차방정식은 해 집합/해 없음/무수히 많음과 정의역·대입 검증이 필요한 별도 계약이며 이번 연산 확장 목록의 완료 조건에 포함하지 않는다.

## 구현 순서와 출시 관문

1. **자연수 보완:** 초3~4 자릿수·나머지 계약 → 조건별 정확한 생성 가능량 → 검산 → 스냅샷 재열기 → 프리셋. 현재 전수 탐색 한도 10,000을 단순히 올리는 방식은 피한다. 예를 들어 세 자리 두 수의 조합은 810,000개이므로, 제한 범위 열거 또는 정확한 조합 계수·순위 선택을 설계한다.
2. **분수·소수 공통층:** 정규 유리수/정수 스케일 계산과 답 표시 정책부터 검증 → 초4 ± → 초5 ×·이분모 ±·혼합 계산 → 초6 ÷. 식은 연산 트리로 제한하고 `eval`로 해석하지 않는다. 통분·반올림·나머지는 각각 별도 정답 정책이다.
3. **중등 수치층:** 부호/유리수 → 순환소수·자연수 지수 → 근호 순서. 각 단계는 앞 단계의 독립 검산을 유지한다. 문자식 계산·방정식은 범위와 계약을 따로 승인받는다.

모든 신규 스킬·프리셋의 완료 조건:

- **생성과 수량:** 명세·제약 정규화, 안정적 ID와 버전, 유한한 0 초과 도메인, 정확한 `domainSize`, 기본 수량 `min(20, domainSize)`. 표기만 다른 동치 분수를 중복으로 셀지 학습상 구별할지 명세에 고정한다. 현재 순서 있는 피연산자 정체성을 묵시적으로 바꾸지 않는다. 혼합 선택의 겹침·이미 사용한 문항을 반영하고 수량 부족을 중복 채우기로 숨기지 않는다.
- **독립 검산:** 생성기 답 계산을 재호출하지 않는 별도 구현과 손검산 경계 사례를 둔다. 작은 도메인은 전수 비교, 큰 도메인은 정확한 계수 증명/소범위 전수 비교와 결정적 다중 시드 검사를 병행한다. 분수는 교차곱·기약성, 나눗셈은 역연산·나머지, 소수는 정수 스케일, 근호는 독립 제곱인수 분해와 정규형 동치를 검사한다.
- **회귀:** 조건 충족·정답·중복 없는 회차·동일 시드 재현·가능한 경우 새 시드 변화·정확한 부족 거절·변조 거절·저장 발문/정답 그대로 재열기를 검증한다. 시드 변경마다 새로운 숫자를 보장하지 않는다. 기본 수량이 도메인 전체이면 순서만 바뀌며 단일 문항 도메인은 변화가 없다.
- **호환성:** 엔진/카탈로그/payload 버전과 이전 문서 판독 경로를 설계하고, 확장 문서를 읽는 서버·클라이언트·출력 경로 배포 확인 뒤 writer gate를 연다. 기존 저장 문서를 새 시드로 재작성하지 않는다. 생성 미리보기·읽기는 DB 기록/사용량/순위를 만들지 않으며 대량 문항 fixture를 클라이언트 번들이나 운영 DB에 적재하지 않는다.
- **표시:** 테스트 통과한 스킬/조건만 공개한다. 학년 표시는 위 근거를 대조한 추천 위치로 제한하며, 전체 성취기준 대응·학습 효과·학년 완성도는 별도 검증 전까지 미확인으로 남긴다.
