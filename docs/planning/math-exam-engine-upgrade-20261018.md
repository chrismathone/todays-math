# 기출 대비 엔진 업그레이드 실행안

2026-10-18 · 시작 기준 `2c18d65a5` · 소유자: problem_make Codex

사용자는 전체 기출에 대한 기출 엔진 업그레이드 착수를 지시했다. 결과는 특정 학교명에 묶인 복제기가 아니라, 학교·학년·범위의 추상 수학 요구에 맞는 새 문제를 실제 웹앱에서 만들고 풀어 볼 수 있는 공통 경로다. 원문 DB를 복원하거나 원문 문장·수치·그림을 생성 입력으로 쓰지 않는다. 앞선 사용자의 Claude 계획 승인 요청을 지켜, 아래 실행안은 Claude 검토 뒤 구현한다.

## 제공할 실제 흐름

1. 기존 `/exam`에서 ‘기출 대비 연습’으로 진입한다. 별도 기존 시험 예측 이력은 보존한다. 원문 적재가 선행 조건이라는 오래된 안내를 정정한다. 기존 시험지 만들기 Hi-fi 작업 영역과 학생 SRS는 건드리지 않는다.
2. 학교/학년·과목/검토 범위 또는 일반 범위 연습을 선택한다. 검토된 학교 프로필은 적용 근거와 미확인 범위를 보여 준다. 이름만 입력한 미검토 학교는 일반 범위 연습으로 명시한다. 학교명 문자열만으로 특성을 꾸며 내지 않는다.
3. 실제 지원하는 유형·난도·객관식/단답/과정 서술 형식과 문항 수로 생성한다. 필수 요구가 모자라면 부분 제공/미지원과 빠진 요구를 표시하며 조용히 다른 학년/형식/난도로 채우지 않는다.
4. 새 문제, 필요한 자체 그림·그래프, 정답·풀이·서술형 기준을 확인하고 같은 요구의 다른 조건으로 재생성한다. 기본은 답/풀이 숨김이다. 기존 공통 시험지 양식·인쇄를 재사용한다. 새 생성은 원문 DB·유료 모델·AI 호출에 의존하지 않는다.
5. 문항의 정체는 형식과 분리한다. 같은 질문의 객관식/단답을 두 문제로 세지 않고 한 세트에 같은 논리 과제를 중복 배치하지 않는다. 과정 서술은 본래 설명 요구와 모범답·채점 기준이 있는 경우만 지원한다.

## 공통 계약과 엔진

- `src/contracts/examStudy.contract.ts`에서 요청/응답 검증 및 순수 TypeScript 생성기 계약을 정의한다. 학년·과목, unit ID/과제 요구, 응답 형식, 난도/근거, 그림, rubric, family/version/seed/variant, 논리 문항/과제 지문을 분리한다. 실제 학교 원문 필드는 두지 않는다.
- `src/lib/examStudy/`에 정적 검토 프로필, 생성기 manifest, 기존 엔진 adapter, 요구별 대응, 엄격한 세트 조립을 둔다. 학교에 따라 동작하는 if 문이 아니라 프로필 데이터와 공통 계획기가 선택한다.
- 기존 elementary/middle/high/native 생성기는 검토된 과제만 실제 지원으로 연결한다. 나머지는 일반 엔진 카탈로그/선수 요소와 구분한다. 등록 수가 전체 학습 대응률이 되지 않는다.
- 학교 프로필은 앞선 비교의 추상 요구만 옮긴다. 대륜중 중1/중2, 경명여중 중1/중3, 경신고 공통2의 검토 범위와 미확인을 보존한다. 일반 범위에서는 학교 프로필 없이 같은 자작 가족을 이용할 수 있다. 초등/고등 등 범위 전체의 미지원과 미검증을 숨기지 않는다.
- 결과는 `complete / partial / unavailable` 및 각 요구의 완결/요소/미검증/미지원 상태를 갖는다. 프로필 개정·등록부 개정·seed·형식·지문을 고정한다. `complete`는 요청한 검토 범위 충족이며 학교 시험 전체나 실측 난도 보장이 아니다.
- 새 순수 생성기 모듈은 `middleFamilies.ts`, `advancedFamilies.ts`로 소유권을 나눈다. 둘 다 같은 manifest/출력 계약을 사용하며 공통 등록은 core가 소유한다. 새 엔진 수를 부풀리기 위해 기존 합/개수/순위 갈래를 복제하지 않는다.

## 새 수학 과제 보강 범위

아래는 학교별 원문 변형이 아닌 일반적인 수학 의존 구조다. 기존 완결 대응이 있으면 재사용하고, 새 과제는 원문과 독립된 자체 수치·문장·그림으로 저작한다.

| 분담 | 우선 완결 과제 |
| --- | --- |
| 중1·중2 | 꺾은선의 여러 구간/반복 통과/거리·방향 공동 판단; 비례 그래프와 정사각형 공유 변; 반비례 두 점과 넓이비/동일 길이/부호/사다리꼴; 넓이비의 두 분할점과 기울기; 해가 이동하는 두 연립식; 축절편 사다리꼴의 가능한 평행변 경우; 공식 의존·잔여량·단위·최소 시간; 연료/정지 구간/작업률의 과정 서술 |
| 고등·중3·교과서 기하 | 진리집합 포함과 매개변수; 중간 진리집합의 수; 제한 정의역/치역의 일대일대응; 절댓값 유리함수의 가지·제외점·교점 수; 유한 대응의 합성/역함수·반복 제약; 근호곡선과 넓이/기하; 포물선→직선→추가 교점 의존; 두 하위 삼각형의 서로 다른 중심과 연장선 조건 |

각 가족은 모든 허용 매개변수에서 해의 유일성/완전성·정의역·퇴화/부호/경계·원조건 대입을 검산하고 조건이 실제 풀이에 필요한지 확인한다. 계산 출력과 서술 요구를 표면만 바꿔 같은 루브릭을 붙이지 않는다. 구현이 어려운 요구를 사실상 단순한 과제로 줄여 완결 대응으로 올리지 않는다.

## API·제품 연결

- `/api/exam/practice` GET은 검토된 카탈로그/프로필, POST는 엄격 요청을 받아 결정적으로 새 문제를 생성한다. 기존 계정/메뉴/출력 권한을 서버와 proxy에서 함께 적용한다. 익명·학생·권한 없는 교사 우회를 허용하지 않는다. 기존 `/api/exam/rounds`와 predictor 저장 동작은 보존한다.
- 새 페이지 `/exam/practice`와 전용 컴포넌트에서 범위→문항 검토→공통 출력으로 연결한다. 디자인은 `DESIGN.md`, 메뉴 적용표와 기존 Math 작업실을 따른다. 화면에는 사용자가 결정하는 범위·형식·부족한 학습 요구를 표시하고 내부 seed/manifest 등의 구현 용어는 넣지 않는다.
- 현행 `WorksheetEditor`가 제공하는 저장 없는 연습/고정 구성 경로를 재사용할 수 있다. 인쇄/PDF/HWPX는 기존 출력 권한을 따른다. 저장을 연결할 때는 서버의 검증된 recipe/지문 재생성과 소유 권한으로 현재 계약을 지키며 임의 클라이언트 발문을 신뢰하지 않는다. 구현되지 않은 저장 버튼은 노출하지 않는다.
- 운영 DB 쓰기·스키마 변경은 이 경로의 선행 조건으로 만들지 않는다. 은행 영구 적재가 필요해지면 기존 승인/자격/논리 문항 계약을 거친 별도 적용으로 다룬다. 첫 결과가 CLI/보고서에만 남지 않게 실제 웹 진입과 생성·검토·출력을 이번 구현의 필수 범위로 둔다.

## 분담과 검증

Claude 계획 검토 → 계약 확정 → Codex 독립 worktree 3개(core/중등/고등·기하)를 동시에 실행한다. root는 API·UI·통합과 검증을 소유한다. 완료 후 독립 검토에서 찾은 결함을 수정하고 local main에 병합하며 종료된 clean/merged worktree를 정리한다. 원격 push가 필요하면 직전 fetch·비교·통합 후 관련 검사를 한다. 기존 동시 UI 작업 파일은 별도 세션의 변경을 보존한다.

필수 검사:

- 같은 범위의 프로필에서 수학 요구만 달라지면 계획/실제 문제가 달라지고, 같은 프로필의 학교 표시 이름만 바뀌면 수학 계획이 임의로 달라지지 않음.
- 새 가족과 기존 adapter의 독립 발문 검산, 모든 중요한 조건 갈래/경계, 작은 유한 영역 전수, 실제 그래프/도형 눈검수.
- 논리 문항·형식·family 중복, 부족/불가능한 형식·난도·그림·서술 요구, 혼합 학년과 미상 학교, 개정/지문 변경에 대한 확인.
- 실제 화면→인증 API→생성/엄격 조립→정답/풀이/그림→공통 출력의 통합 검사. 익명/학생/메뉴 제한 및 잘못된 입력 거절.
- 영향을 받는 기존 엔진·은행·권한·형식·출력 회귀 검사, 타입/린트, 넓은/좁은 화면 검증. 새 시드만 많이 돌리고 대응력이 좋아졌다고 보고하지 않음.

미측정 범위는 그대로 명시한다: 학교 시험 적중률, 실제 학습 효과, 학생 반응으로 보정한 난도, 공식 교육과정 전수 정합성. 이것들은 구현 합격과 별도이며 미확인을 숨기거나 전체 기출 완성을 선언하지 않는다.
