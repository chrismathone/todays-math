# 2-1-1 기준 교재 제작 복구 계획 v01

작성일: 2026-10-05. 상태: Codex 초안, Claude·Grok 독립 검토 전. 이번 요청의 산출물은 **3자 합의된 실행 계획**이다. 이 문서를 작성했다는 이유로 앱 수정·배포·전체 교재 검수가 끝났다고 보고하지 않는다.

## 1. 목표와 범위

사용자는 학년·학기, 시작/끝 소단원, 난이도를 고르면 기존 개념 대본과 문제를 자동으로 넣고, 각 교재 구성을 토글로 선택해 교재를 만들 수 있어야 한다. 기본 제작 화면에 조판 내부 구조나 필수 원고 편집을 요구하지 않는다.

- 범위는 초3·초4·초5·초6·중1·중2·중3, 두 학기를 포함한다. 초1·초2와 고등은 추가하지 않는다.
- 디자인 기준은 사용자가 제공한 v15 ZIP과 259쪽 2-1-1 학생용 PDF다. 실제 파일의 해시로 판본을 식별하며 과거의 다른 260쪽 파일·이전 검수본과 섞지 않는다.
- 원본의 대화·판서, 개념 이해, 학습/빈칸/통문장 공통 행, 기본 확인, 대표예제/확인 문제, 복습·평가·설명 활동을 기능과 지면 구조 모두 복구한다.
- 선택 가능한 선생님/학생 얼굴은 역할마다 10종, 남녀 각 5종이라는 기존 요구를 유지한다. 역할·표정·선택 이름을 대사 속 호칭까지 연결한다.
- 쉬어가기는 삽화·이야기·생각 나누기를 갖춘다. 지정 기준 PDF에 대응 페이지가 없으므로 원본 동일성 대신 별도 품질 기준으로 검수한다.
- 모든 독립 구성은 on/off로 제어한다. 끈 구성은 안내·목차·경로·출력에도 남지 않아야 한다. 필수 관계는 화면에서 쉽게 설명하며 자동으로 숨은 구성을 켜지 않는다.

## 2. 검수 결과와 보존 조건

근거는 [대응 영역 검수](textbook-v15-matching-region-audit-20261005.md)와 상세 보고서 3개다. 현재 시각 수용 상태는 미통과다. 기능 테스트와 자산 보존은 지면 동등성을 증명하지 못한다.

반드시 보존할 조건:

1. 이미 발행한 교재·개념·문제·그림·정답·해설의 스냅샷과 파일은 바꾸지 않는다. 기존 초안도 저장 원문을 조용히 덮어쓰지 않는다.
2. 원문 ID·개념 ID·참조·내용 해시를 보존한다. 화면 표시 번호와 영구 ID를 구분한다.
3. 일반 학생용 문항의 정답·해설은 숨기고 대표예제의 공개 풀이와 답은 유지한다. 선택지·개념 설명을 정답 유출로 오판하지 않는다.
4. 기존 학생 pageMap과 QR·답지 참조 계약을 보존한다. 답지는 답·해설 높이에 따라 독립 조판한다.
5. 기존 시간·파일·블록·페이지 제한을 우회하거나 느슨하게 하지 않는다. 여러 구획으로 나누어 발행하는 현재 경로를 유지한다.
6. 내용 삭제·임의 빈 페이지·작은 글자로 강제 축소해 쪽수만 맞추지 않는다. 문항 수·원고 분량이 다른 교재의 전체 쪽수가 달라지는 것은 허용한다.
7. 현 프로젝트 스택을 유지한다. 개념 연결·빈칸 변환·번호·기하·수학 계산은 결정적 코드로 처리한다. 이번 복구에 실행 중 AI 원고 생성이나 새로운 AI 판정 서비스를 추가하지 않는다.

## 3. 기준 표본과 통과 방법을 먼저 고정

### P0 — 실제 기준과 재현 표본

- 원본 ZIP/PDF, 실제 저장 초3 학생용·답지, 새 초3/중2 검증본의 해시·옵션·물리 페이지를 manifest로 고정한다. 합성 QA 입력과 실제 문제은행 입력을 구분한다.
- 먼저 원본 중2 U01 등 **같은 원고**를 원본 경로와 새 경로에 넣는다. 서로 다른 대본의 4쪽/9쪽 차이로 결함을 판단하지 않는다.
- 표지/안내/단원/대화·판서/개념/암기 3형식/기본/예제/연습/오류/복습/서술/평가/독립 설명에 대한 기준 페이지와 필수 요소 목록을 만든다.
- 치수 표는 원본의 머리말, 제목, 본문 시작, 열 폭, 행 높이, 글자, 선 두께, 색, 탭, 꼬리말을 지면 유형별로 기록한다. A4 전체 페이지를 같은 축척으로 비교한다.
- 통과는 필수 요소·학습 관계·행 대응·작성 공간이 모두 충족된 상태다. 넓은 공백이나 원본과 다른 문항 수만으로 실패시키지 않는다.

완료 증거: 공개 가능한 fixture, manifest, 대응 페이지 표, 기준 전체 페이지 이미지. 비공개 DB 원고와 답안 fixture는 저장소에 커밋하지 않는다.

## 4. 공통 표현 구조를 먼저 복구

### P1 — 원고·조판 계약

현재 대화 원고에서 판서를 선생님 말로 바꾸고, 여러 개념의 정의와 예를 종류별로 모은다. CSS 수정 전에 원고의 의미를 유지하는 표현 단위를 확정한다.

- 대화는 수업·부분·발화·판서를 구분하고 역할·표정·출처 위치를 유지한다. 판서는 발화로 변환하지 않는다.
- 개념은 conceptId와 행 키로 정의·분류·조건·이유·예·주의·오개념 교정·설명·확인 문제를 연결한다. 실제 원천에 없는 내용을 있다고 표시하지 않는다.
- 학습/빈칸/통문장은 공통 행과 치수를 공유하고 가려지는 텍스트·답안 상태만 바꾼다.
- 대표예제는 유형·전략·공개 풀이 예제·관련 확인 문제를 한 그룹으로 표현한다. 기본 확인, 자유 백지, 독립 설명은 일반 문제 목록이나 통문장으로 대신하지 않는다.
- 우선 렌더 투영과 선택적 필드로 호환을 유지한다. 저장 계약 변경이 필요하면 버전·기존 데이터 adapter·실패 처리·왕복 교환 검증을 먼저 명시한다. 과거 계약을 암묵적으로 변경하지 않는다.
- 기존 정적 개념 원고의 직접 편집을 materializer 재생성으로 덮어쓰지 않도록 변경 원천과 생성 절차를 정한다.

완료 증거: 구조 계약 표, 기존/신규 fixture의 무손실 투영·왕복 검사, ID/수학 원문/정답 분리의 회귀 확인. 이 계약이 확정돼야 병렬 구현을 시작한다.

P4의 필기선·오류 안내와 P2의 호칭은 사용성 결함으로 먼저 고친다. P2/P3/P5의 독립 내부 구현은 P1 확정 후 병행할 수 있으나 같은 `html.ts`, `editorialCss.ts`, `paginate.ts` 파일을 여러 작업자가 동시에 편집하지 않는다. 공통 파일은 조율 담당이 통합한다.

맞쪽 처리의 구현 선택은 P1에서 명시한다. 우선 기존 비어 있지 않은 앞부분 지면의 순서/분할로 의도한 양면 쌍을 만든다. 특정 토글 조합에서 불가능하면 임의 백지를 넣지 말고 제작 전에 적용 가능한 단면 배치와 이유를 명확히 보여 준다. 페이지를 만든 뒤 실제 쪽수 링크를 최종 투영하는 절차는 제한된 횟수 내에서 안정화해야 한다.

## 6. 초3~중3 개념 대본과 라이브러리

### P8 — 연결 완료와 내용 완성도를 별도로 검수

현재 README에는 7개 학년 파일, 360개 소단원, 1,657개 개념, 7,792개 대사가 기록돼 있다. 이는 현 파일을 다시 계수해 확인할 출발점이며 교육과정·수학·수업 흐름 전체 통과의 증거가 아니다.

- 학년·학기·단원·소단원·개념 ID별 연결 표를 만든다. 은행 연결 기준과 실제 앱의 학년/학기 선택 기준이 일치하는지 전수 검사한다.
- 360개 원고의 ID 유효성, 원천 개념/예/오류 교정 보존, 수식 렌더, 참조, 역할, 판서 보존, 잘못된 정답 유입을 결정적으로 확인한다.
- 수학 내용은 계산 가능한 식을 검산하고 정의·조건·단위·학년 어휘·추론은 실제 편집 검수한다. 자동 보존 검사와 수학적 검수 상태를 각각 기록한다. 확인하지 않은 원고를 내용 검수 통과로 표시하지 않는다.
- 14개 학년·학기 조합에서 실제 문제은행을 사용한 학생/답지 대표 출력을 만든다. 적어도 수식·도형·분수·장문 서술·오개념 교정이 있는 사례를 포함한다. 누락 원고가 있으면 운영 제작 전에 범위별로 표시하고 보완한다.
- 인물 라이브러리의 역할별 10종/성별 5종과 표정·이름·반응 조사를 확인한다. 부족한 자산만 추가한다.
- 쉬어가기마다 삽화·이야기·생각 나누기, 학년 어휘와 주제, 선택 범위 연관, 적절한 분량, 이미지 출처를 검수한다. 없는 원본 지면과 같다고 보고하지 않는다.

## 7. 간단 제작과 구성 토글

### P9 — 실제 사용자 흐름

제작의 기본 흐름은 학년·학기 → 범위 시작/끝 → 난이도·문항 수 → 구성/인물 선택 → 생성·미리보기 → 학생용/답지 내려받기다. 세부 편집은 선택 기능이다.

- 기존 18개 토글과 원본 활동의 대응 표를 작성한다. 자유 백지·기본 확인·독립 설명 등 현재 미확인 활동이 기존 옵션의 무엇에 해당하는지 확인하고, 독립 기능이면 별도 토글을 추가한다. ‘토글 18개’라는 숫자를 보존하기 위해 다른 활동에 숨겨 합치지 않는다.
- 각 토글의 on/off와 관련된 필수 관계를 검증한다. 한 개만 켠 경우, 전부 끈 경우, 기본 조합, 전부 켠 경우, 짝이 있는 구성의 조합을 검사한다. 모든 2의 N승 조합을 직접 시각 검수했다고 주장하지 않는다.
- 실제 문제 부족, 서술형 부족, 원고 미검수/누락, 범위 오류에는 이유와 적용된 결과를 보여 준다. 요청 문항 수와 실제 입력된 수를 구분한다.
- 실제 로그인한 운영 사용자 흐름에서 생성 성공, 미리보기의 첫/중간/끝 페이지 이동, 답지 전환, 390/820/1600px, 그림·수식·영상/QR, 다운로드를 확인한다. 공유 DB에 테스트 교재를 무단 추가하지 않고 격리 검증과 실제 사용자 검증을 구분한다.

## 8. 병렬 작업과 책임

P0/P1은 먼저 조율 담당이 정본과 경계를 고정한다. 이후 독립 Orca 작업은 다음 소유 범위로 나눈다.

| 대화·인물 | 전용 대화/판서 모듈, 역할·호칭 연결, 해당 검증 자료 | P1 |
| 암기·문제 | 전용 회상/문제/기록 모듈, 해당 검증 자료 | P1, 개념 행 계약 |
| 조율·통합 | 공통 renderer·CSS·pagination, 자동 구성·토글·UI·pageMap·기존 계약 호환 | 위 계약과 모듈 |
| 독립 검수 | 원본 대응 PNG/PDF 비교, 내용 원장 확인, 실제 흐름 검사 | 각 지면 표본 및 통합 출력 |

같은 파일의 공동 편집이 필요하면 소유자를 정해 변경을 전달한다. 무관한 병행 작업과 공유 환경·node_modules·운영 DB는 변경하지 않는다. 실제 배정은 구현 착수 시 가용 작업자를 확인해 결정한다.

## 9. 최종 완료 관문

| 관문 | 제출할 증거 | 미통과 처리 |
| --- | --- | --- |
| G0 동일 원고 중2 | 원본/새 출력 대응 페이지, 필수 요소·치수·학습 관계 판정 | 다른 학년 대량 생성으로 넘어가며 원본 완료라고 보고하지 않음 |
| G1 구조·내용 보존 | ID·참조·내용 해시·수식·빈칸 행·일반 정답 분리 | 원고/계약부터 수정 |
| G2 출력 | 학생/답지 PDF 전체 페이지의 잘림·겹침·빈쪽·그림/수식/필기선 검사와 대응 영역 시각 검수 | 기능 테스트만 통과한 상태로 배포하지 않음 |
| G3 학년·구성 | 14개 학년/학기 연결, 원고 내용 검수 상태, 단독/기본/전체/관계 조합 토글, 라이브러리 | 검증되지 않은 범위를 전체 완성으로 보고하지 않음 |
| G4 실제 흐름 | 로그인 생성→미리보기→학생/답지 다운로드, QR/영상의 실제 유효성·권한 | 합성 QA 발행 성공으로 대신하지 않음 |
| G5 통합·운영 | 관련 회귀, 형 검사, lint, 배포 빌드, 새 커밋의 실제 자산/출력 확인 | 실패 원인 수정 후 관련 검사 재실행 |

새로 만든 최종 PDF는 모든 페이지를 읽어 내용 누락·잘림·겹침·필기 공간을 확인한다. 이미지/자동 탐지는 위치 후보를 돕고 실제 전체 페이지 시각 검토를 대신하지 않는다. 원본 디자인 동일성은 같은 영역끼리 보고, 원고가 다른 경우에는 구조만 비교했다고 표시한다.

최종 산출물은 코드·기존 호환 계약, 학년별 원고 검수 원장, 구성 대응 표, 학생/답지 PDF, 원본/새 출력 좌우 비교 화면, 오류 0건/미확인 항목 목록과 실제 검수 범위다. 인쇄 실물 검증은 PDF 확인과 별도 상태로 기록한다.

main 통합 후 푸시 직전 대상 원격을 fetch해 비교하고 새 커밋을 보존·통합한다. 충돌 해결 후 관련 검사를 반복하며 강제 푸시하지 않는다. main에 병합됐고 깨끗하며 작업이 끝난 Orca worktree만 정리하고 브랜치는 보존한다.

## 10. 3자 합의 절차

1. Codex v01과 같은 검수 자료를 Claude·Grok이 각각 독립 검토한다. 표결은 APPROVE 또는 REVISE이며 막는 문제와 정확한 수정 문구를 남긴다.
2. Codex가 지적을 근거와 함께 수용/조정하고 이견을 표로 기록한다. 미해결 필수 사항이 있으면 합의로 표시하지 않는다.
3. 수정된 최종 후보의 파일 경로·버전·바이트 SHA-256을 고정하고 세 당사자가 **동일 해시**를 확인해 다시 표결한다. 조건부 승인과 실제 완료를 구분한다.
4. 세 당사자 모두 같은 최종 후보에 APPROVE했을 때만 합의 원장에 Run·Task·Dispatch·실제 메시지 ID와 해시를 기록하고 최종본으로 제출한다. 최종 승인 후 표결 대상 바이트는 변경하지 않는다.
