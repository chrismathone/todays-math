# 오늘의 영어 전면 고도화 — 계획과 Hi-fi 5안

작성일: 2026-10-07. 상태: 선택을 위한 제안. 이 문서는 운영 기능이나 디자인 확정 기록이 아니다.

## 목표와 범위

교사가 원문과 자료를 확보하고, AI·엔진으로 다양한 문제를 제작하고, 검토한 문제를 문제은행에 축적한 뒤 시험지와 수업 자료로 다시 구성하는 도구로 재설계한다. 사용자의 후속 지시인 “AI나 엔진을 사용해 각종 문제들도 제작 … 문제 은행은 당연”을 핵심 요구로 반영한다.

학교별 내신, 독해·어휘·어법·서술형 제작, 원문 복원, 듣기 자료를 일관된 작업 흐름 안에 둔다. 제작 방식의 기술 이름보다 제작 목적과 결과물을 먼저 보여 준다.

## 현재 화면에서 확인한 문제

- `EnglishMakerView.tsx`: 제작 방식이 `ChatGPT 로 제작 / 원문 복원 / API 직접 생성`으로 분리된다. JSON 복사와 붙여넣기가 일반 제작 화면에 나타난다.
- `EnglishStudio.tsx`, `EnglishPrepView.tsx`: “학교의 출제 흐름에 맞춰”라는 안내가 있다. 현재 확인한 계약에는 학교 출제 경향을 분석·입증하는 데이터가 없다. 학교·학년·시험 범위를 기준으로 준비한다고 표현한다.
- `EnglishLibraryView.tsx`: 문제 보관함은 선택한 시험의 세트 목록이다. 시험과 독립된 문항은행이라고 간주할 수 없다.
- `EnglishResourceBank.tsx`: 자료은행은 지문과 듣기 자료를 관리한다. 원문 자료은행과 제작된 문항의 문제은행은 역할을 나눈다.
- 현재 저장 상태는 `초안 / 검토 중 / 검토 완료`다. 형식 검사 통과를 정답 검증, 사람 검토 완료 또는 학생 발행 완료로 표시하지 않는다.

## 새 정보 구조 제안

| 작업 | 사용자가 하는 일 | 화면에서 보이는 핵심 |
|---|---|---|
| AI 문제 제작 | 원문 유지·변형, 새 지문, 규칙 기반 연습 선택 | 입력 자료, 유형, 학년, 문항 수, 제작 후 검토 |
| 문제은행 | 만든 문항과 세트 찾기·편집·재사용 | 유형·학년·검토 상태, 원문 연결, 담기 |
| 자료은행 | 원문·사진·듣기 자료 확보 | 원문과 출처, 텍스트 확보 여부, 이용 범위 |
| 시험·수업 구성 | 문제를 고르고 순서·묶음 설정 | 현재 구성, 학생용·교사용 미리보기 |
| 듣기 | 음원·대본·문항 검토, 기존 수업 연결 | 실제 음원 연결과 검토·공개 상태 |

문제 제작의 주요 선택은 `원문으로 만들기 / 새 지문으로 만들기 / 원문 복원 연습`이다. AI 제작과 결정적 엔진의 차이는 필요한 설정에서 설명한다. 기술 공급자 이름과 JSON은 일반 작업 흐름의 첫 화면에 두지 않는다. 외부 도구를 통한 가져오기 기능을 유지할 경우 보조 메뉴로 정리한다.

현재 계약에 있는 14개 유형을 출발점으로 삼는다: 주제, 내용 일치, 어법, 빈칸 추론, 문장 삽입, 서술형, 어휘, 언급 없음, 해석, 영영풀이, 공통 빈칸, 문장 전환, 단어 배열, 원문 복원. 신규 지원 유형은 별도 계약과 품질 기준이 갖춰진 뒤 추가한다.

## 서로 다른 Hi-fi 방향

| 안 | 이름 | 첫 화면 구조 | 주된 사용 흐름 | 시각 문법 |
|---|---|---|---|---|
| A | 시험 작업대 | 시험 목록 + 선택 시험의 준비 작업대 | 시험 선택 → AI 제작 → 검토 → 인쇄 | 밝은 회청색, 넓은 작업영역, 명확한 우선 행동 |
| B | 원문 편집실 | 원문과 문항·제작 설정이 나란히 있는 편집기 | 원문 선택 → 유형 제작 → 근거와 답 검토 → 은행 저장 | 잉크색 헤더, 문서 중심, 정밀한 분할 패널 |
| C | 제작 흐름 보드 | 초안·검토 중·검토 완료 세 열 | 미완료 작업 발견 → 검토 → 완료 → 재사용 | 여백 있는 보드, 상태 색, 행동 중심 카드 |
| D | 문제 탐색과 조합 | 검색·필터 + 문항 상세 + 구성 트레이 | 은행 검색 → 문제 확인 → 담기 → 시험지 구성 | 밀도 높은 검색 도구, 정돈된 목록, 고정 구성 영역 |
| E | 수업 자료집 | 수업 맥락 + 학습지 표지·구성 미리보기 | 수업 선택 → 은행에서 구성/AI로 보충 → 지면 확인 | 종이와 활자 중심, 세로 자료집, 절제된 와인색 |

다섯 안은 동일한 역할을 색만 바꿔 반복하지 않는다. 시작점, 탐색 구조, 화면 분할, 제작·검토의 접근 방식이 각각 다르다. 모든 안에 AI 제작과 문제은행 진입이 보인다. 예시 자료와 수치는 시안 전용이며 DB 조회·저장·실제 AI 호출·학생 배정은 하지 않는다.

## 실제 구현 순서 제안

1. 선택된 안의 정보 구조·문구·공통 컴포넌트를 확정하고, 기존 메뉴와 권한에 대응시킨다.
2. 공통 셸과 제작 화면을 바꾼다. 제작 조건 → 생성 요청 → 초안 → 검토의 기존 API 흐름을 연결한다. API 실패·지문 상한·취소·저장 충돌·미저장 이탈 상태를 함께 완성한다.
3. 문제은행을 별도 설계한다. 현재 시험별 세트와 독립 원문은행을 보존한다. 문항 단위 저장, 출처·원문 버전, 사용 참조, 소유·지점 범위, 세트/문항 관계를 먼저 정한다. 은행 이관은 복사와 참조를 중심으로 하고 기존 기록을 대량 재작성하지 않는다.
4. AI 제작 경로와 규칙 엔진을 작업 목적에 맞춰 정리한다. 수·유형·길이·권한 검사는 코드로 수행하고, 생성된 문항은 초안으로 시작한다. AI 판단이 필요한 품질·라우팅 설계는 프로젝트 TypeSafe 스킬과 당시의 live docs에 따라 별도 검토한다.
5. 은행에서 시험지·수업 자료로 구성하고 학생용·교사용 인쇄를 연결한다. 여러 원문의 일괄 제작/조합과 수업 자료집 저장은 새로운 기능이므로 계약·저장 설계를 추가한다.
6. 듣기의 음원·대본·검토·공개 단위와 기존 배정 관문을 연결하고, PC·모바일·키보드·회귀·인쇄 품질을 확인한다.

## AI·엔진과 품질 점검의 역할 제안

이 부분은 향후 구현을 위한 설계 제안이며, 이번 HTML 시안은 AI를 호출하거나 자동 판정을 실행하지 않는다. 프로젝트 TypeSafe 스킬과 2026-10-07에 읽은 live docs를 기준으로 정리했다.

| 역할 | 실행 주체 | 결과와 화면 표현 |
|---|---|---|
| 원문 복원, 수·길이·유형·보기 개수·필수값 검사 | 결정적 코드/기존 규칙 엔진 | 빈칸 연습 또는 형식 오류. 정답의 의미를 검증했다고 표시하지 않음 |
| 새 지문·변형 문항·보기·해설 초안 제작 | 기존 생성 모델 연결 | 제작된 초안. 실제 호출 성공, 실패, 취소를 구분 |
| 답과 원문의 관계, 해설 근거, 의심 항목의 분류 | TypeSafe/Jev를 활용하는 좁은 의미 판단 후보 | 확인할 근거와 항목을 교사에게 제시. 사람의 확인 완료와 분리 |
| 확정·출력·학생 공개 | 교사 행동과 서버 정책 | 행동 기록에 따른 검토 상태와 공개 상태 |

해설의 인용문은 우선 코드로 원문에 존재하는지 검사한다. 존재할 때만 원문의 주변 문맥이 답·해설을 지지하는지 좁은 판단으로 확인하는 흐름을 제안한다. 이는 TypeSafe의 [인용문 점검 cookbook](https://docs.typesafe.ai/cookbooks/citation_check)의 패턴을 영어 문항에 적용하는 설계적 추론이며, 그 예제의 성능 수치를 영어 문제 검증 성능으로 옮기지 않는다.

판단의 불확실성은 검토 순서와 추가 확인에 사용한다. 모델 confidence를 정답 정확도·학생 점수·품질 보증 수치로 표시하지 않는다. 자동 처리 임계값은 자체 영어 문항과 교사 판정 데이터로 검증한 뒤 정하며, cookbook의 예제 임계값을 그대로 가져오지 않는다. [TypeSafe confidence 문서](https://docs.typesafe.ai/confidence)

원문이 바뀌면 예전 근거와 품질 판정을 다시 확인한다. 문제은행에는 생성 출처, 원문 ID·버전, 형식 검사, 의미 점검, 교사의 검토 행동을 별도 정보로 남기는 방향을 제안한다. 첫 구현에 모든 자동 점검을 묶을 필요는 없으며, 제작·수동 검토·은행 재사용부터 완성한다.

## 유지해야 할 경계

- 기존 영어·듣기 기록, 수학 기록, 소유·지점 권한과 학생별 추가 메뉴 정책을 보존한다.
- 파일 업로드를 원문 추출 완료로 표시하지 않는다. PDF·DOCX의 자동 추출과 대용량 수입은 기존 M0 계약과 후속 게이트를 따른다.
- 출제 경향 예측, 점수 향상률, 정답 검증률, 완벽한 출제 같은 근거 없는 문구·수치를 넣지 않는다.
- 듣기 공식 링크와 자체 소유 자료, 사람 검토와 형식 검사, 검토 완료와 학생 공개를 구분한다.
- 이번 작업의 납품은 계획과 클릭 가능한 디자인 시안 5개다. 운영 화면 교체는 디자인 선택 뒤 진행한다.
