# 오늘의 영어 전면 고도화 — D안 확정과 구현 계획

작성일: 2026-10-07. 상태: **사용자가 D안을 선택. 오늘의 수학 구성을 참고하여 구체화 중.** 운영 기능은 아직 교체하지 않았다.

## 확정된 방향

사용자 결정: “D가 좋네. D로 가자”, “오늘의 수학과 구성은 맞춰야하니까 D + 오늘의 수학 구성을 참고”. 초기 다섯 안은 비교 기록으로 보존하고, 이후 화면 설계와 구현의 기준은 D 하나로 통일한다. 종전 A·B·D 혼합 추천은 이 결정으로 대체한다.

**오늘의 수학의 공통 작업실 + D의 문제 탐색·상세·시험지 조합**이 최종 방향이다. 제품 전환, 왼쪽 작업 메뉴, 페이지 제목과 주요 행동, 검색·필터, 담은 문제와 내보내기의 사용 방식을 맞춘다. 영어 문항은 원문과 답의 근거를 함께 보아야 하므로 D의 목록·상세 분할은 유지한다. 수학 문항 카드 격자를 영어에 그대로 복제하지 않는다.

추가 요구 “원문까지도 AI에서 만들 수 있게”, “필요한건 AI 가 처리할 수 있게”를 기본 흐름에 반영한다. 교사는 수업 목적·수준·범위를 정하고, AI와 엔진은 원문 확보부터 제작·점검·분류·구성 보조까지 담당한다. 필요한 판단만 교사에게 모아서 보여 준다.

## 오늘의 수학과 맞출 구성

| 수학 작업실의 기준 | 영어 D 적용 |
|---|---|
| 제품 전환과 공통 왼쪽 메뉴 | 오늘의 수학/영어 전환, 메뉴 접기, 계정·지점 위치를 공통 셸에 맞춤 |
| 오늘의 작업 | 진행 중인 시험지, 제작 작업, 확인할 항목으로 돌아오는 진입점 |
| 시험지 만들기 | D의 문제은행 검색·필터·문항 상세·담은 문제를 이 작업 안에 배치 |
| 문제 추출 | 영어는 `AI 문제 제작`으로 대응. 기존 원문과 AI 새 원문을 한 제작 흐름에서 선택 |
| 내 시험지 | 저장한 시험지의 열기·수정·출력을 제공할 대상으로 계획. 독립 문항은행과 구분 |
| 담은 문제 → 시험지 · 내보내기 | 담기·빼기·순서 변경 후 학생용·교사용 지면. 별도 최상위 내보내기 메뉴를 중복하지 않음 |
| 공통 페이지 제목·행동 버튼 | 같은 제목 계층, 버튼 크기·위치, 선택 수와 다음 행동의 표현 |
| 수학의 학년·단원·난이도 필터 | 영어의 학년·유형·원문·검토 상태로 대응. 원문은행·듣기는 영어 전용 메뉴 |

근거: `UnifiedWorkspace.tsx`의 `mathNav` 및 숨겨진 내보내기 메뉴, `WorkspacePageHeader.tsx`, `BankView.tsx`, `BankBasket.tsx`. 자세한 대응 근거는 [구성 조사](../design/reviews/todayenglish-d-math-alignment-20261007.md)에 기록한다. 메뉴명 변경은 권한 계약 변경과 별개다. 운영 연결 시 기존 메뉴 ID·소유 범위·딥링크 호환을 먼저 매핑한다.

## 목표와 범위

주제나 수업 요청만으로 AI가 원문과 다양한 문제를 제작하고, 점검·분류한 문항을 문제은행에 축적한 뒤 시험지와 수업 자료로 다시 구성하는 도구로 재설계한다. 이미 가진 원문이나 자료로 시작하는 경로도 함께 제공한다.

학교별 내신, 독해·어휘·어법·서술형 제작, 원문 복원, 듣기 자료를 일관된 작업 흐름 안에 둔다. 제작 방식의 기술 이름보다 제작 목적과 결과물을 먼저 보여 준다.

## 현재 화면에서 확인한 문제

- `EnglishMakerView.tsx`: 제작 방식이 `ChatGPT 로 제작 / 원문 복원 / API 직접 생성`으로 분리된다. JSON 복사와 붙여넣기가 일반 제작 화면에 나타난다.
- `EnglishStudio.tsx`, `EnglishPrepView.tsx`: “학교의 출제 흐름에 맞춰”라는 안내가 있다. 현재 확인한 계약에는 학교 출제 경향을 분석·입증하는 데이터가 없다. 학교·학년·시험 범위를 기준으로 준비한다고 표현한다.
- `EnglishLibraryView.tsx`: 문제 보관함은 선택한 시험의 세트 목록이다. 시험과 독립된 문항은행이라고 간주할 수 없다.
- `EnglishResourceBank.tsx`: 자료은행은 지문과 듣기 자료를 관리한다. 원문 자료은행과 제작된 문항의 문제은행은 역할을 나눈다.
- 현재 저장 상태는 `초안 / 검토 중 / 검토 완료`다. 형식 검사 통과를 정답 검증, 사람 검토 완료 또는 학생 발행 완료로 표시하지 않는다.

## 새 정보 구조 제안

| 작업 | 사용자가 하는 일 | 화면에서 보이는 핵심 |
|---|---|---|
| AI 문제 제작 | 원문 유지·변형, 새 지문, 규칙 기반 연습 선택 | 입력 자료, 유형, 학년, 문항 수, 제작 후 검토 |
| 문제은행 | 만든 문항과 세트 찾기·편집·재사용 | 유형·학년·검토 상태, 원문 연결, 담기 |
| 자료은행 | 원문·사진·듣기 자료 확보 | 원문과 출처, 텍스트 확보 여부, 이용 범위 |
| 시험·수업 구성 | 문제를 고르고 순서·묶음 설정 | 현재 구성, 학생용·교사용 미리보기 |
| 듣기 | 음원·대본·문항 검토, 기존 수업 연결 | 실제 음원 연결과 검토·공개 상태 |

문제 제작의 주요 선택은 `원문으로 만들기 / 새 지문으로 만들기 / 원문 복원 연습`이다. AI 제작과 결정적 엔진의 차이는 필요한 설정에서 설명한다. 기술 공급자 이름과 JSON은 일반 작업 흐름의 첫 화면에 두지 않는다. 외부 도구를 통한 가져오기 기능을 유지할 경우 보조 메뉴로 정리한다.

현재 계약에 있는 14개 유형을 출발점으로 삼는다: 주제, 내용 일치, 어법, 빈칸 추론, 문장 삽입, 서술형, 어휘, 언급 없음, 해석, 영영풀이, 공통 빈칸, 문장 전환, 단어 배열, 원문 복원. 신규 지원 유형은 별도 계약과 품질 기준이 갖춰진 뒤 추가한다.

## 서로 다른 Hi-fi 방향

| 안 | 이름 | 첫 화면 구조 | 주된 사용 흐름 | 시각 문법 |
|---|---|---|---|---|
| A | 시험 작업대 | 시험 목록 + 선택 시험의 준비 작업대 | 시험 선택 → AI 제작 → 검토 → 인쇄 | 밝은 회청색, 넓은 작업영역, 명확한 우선 행동 |
| B | 원문 편집실 | 원문과 문항·제작 설정이 나란히 있는 편집기 | 원문 선택 → 유형 제작 → 근거와 답 검토 → 은행 저장 | 잉크색 헤더, 문서 중심, 정밀한 분할 패널 |
| C | 제작 흐름 보드 | 초안·검토 중·검토 완료 세 열 | 미완료 작업 발견 → 검토 → 완료 → 재사용 | 여백 있는 보드, 상태 색, 행동 중심 카드 |
| D | 문제 탐색과 조합 | 검색·필터 + 문항 상세 + 구성 트레이 | 은행 검색 → 문제 확인 → 담기 → 시험지 구성 | 밀도 높은 검색 도구, 정돈된 목록, 고정 구성 영역 |
| E | 수업 자료집 | 수업 맥락 + 학습지 표지·구성 미리보기 | 수업 선택 → 은행에서 구성/AI로 보충 → 지면 확인 | 종이와 활자 중심, 세로 자료집, 절제된 와인색 |

다섯 안은 동일한 역할을 색만 바꿔 반복하지 않는다. 시작점, 탐색 구조, 화면 분할, 제작·검토의 접근 방식이 각각 다르다. 모든 안에 AI 제작과 문제은행 진입이 보인다. 예시 자료와 수치는 시안 전용이며 DB 조회·저장·실제 AI 호출·학생 배정은 하지 않는다.

## 실제 구현 순서 제안

1. D를 기준으로 수학의 공통 셸·제목·담은 문제·내보내기 패턴을 맞추고, 기존 영어 메뉴·권한·딥링크에 대응시킨다.
2. 공통 셸과 제작 화면을 바꾼다. 기존 원문 또는 목적·주제 → 원문 초안 → 문항 제작 → 점검의 흐름을 연결한다. API 실패·지문 상한·취소·저장 충돌·미저장 이탈 상태를 함께 완성한다.
3. 문제은행을 별도 설계한다. 현재 시험별 세트와 독립 원문은행을 보존한다. 문항 단위 저장, 출처·원문 버전, 사용 참조, 소유·지점 범위, 세트/문항 관계를 먼저 정한다. 은행 이관은 복사와 참조를 중심으로 하고 기존 기록을 대량 재작성하지 않는다.
4. AI 제작 경로와 규칙 엔진을 작업 목적에 맞춰 정리한다. 수·유형·길이·권한 검사는 코드로 수행하고, 생성된 문항은 초안으로 시작한다. 점검 가능한 항목은 자동 처리하고 의심 항목을 집중 검토에 모은다. AI 판단은 아래 TypeSafe 설계와 자체 평가에 따라 연결한다.
5. 은행에서 시험지·수업 자료로 구성하고 학생용·교사용 인쇄를 연결한다. 여러 원문의 일괄 제작/조합과 수업 자료집 저장은 새로운 기능이므로 계약·저장 설계를 추가한다.
6. 듣기의 음원·대본·검토·공개 단위와 기존 배정 관문을 연결하고, PC·모바일·키보드·회귀·인쇄 품질을 확인한다.

## AI·엔진과 품질 점검의 역할 제안

### 교사가 요청하고 AI가 처리하는 범위

제작의 시작은 `기존 원문 사용` 또는 `AI로 원문부터 제작`이다. 후자는 “중2, 공동체 주제, 100단어 안팎, 내용 일치와 어휘 6문항”처럼 목적을 전달하면 된다. 세부 유형·분량은 직접 조정하거나 추천값을 적용한다.

| 단계 | AI·엔진이 처리할 일 | 교사가 확인할 때 |
|---|---|---|
| 제작 조건 | 요청에서 학년·주제·유형·분량 후보를 채우고 부족한 조건만 확인 | 모호한 조건 또는 요청 변경 |
| 원문 | 새 원문·제목·문장 구분·어휘 후보 제작, 필요 시 수준과 길이 조정 | 원문의 의도 변경 또는 사실 확인 필요 |
| 문항 | 유형별 발문·보기·정답·해설·원문 근거 제작 | 자동 점검에서 의심된 항목 |
| 점검·보완 | 형식 검사, 근거 대조, 복수 정답·불충분한 근거 후보 식별, 해당 항목 재제작 | 재시도 후에도 해결되지 않거나 교사의 판단이 필요한 경우 |
| 문제은행 | 원문 연결·학년·유형·태그 후보·제작 이력과 점검 상태를 함께 보관 | 일괄 저장 결과 확인 또는 분류 수정 |
| 시험지 | 선택 조건에 맞는 문항 추천, 부족한 유형 추가 제작, 순서·지면 구성 보조 | 최종 사용 대상과 출력·배정 확정 |

모든 단계를 매번 수동 승인하게 만들지 않는다. 요청한 범위의 생성·검사·분류는 이어서 진행하고, 확인할 문제가 있으면 이유·근거·수정안을 한곳에 모은다. 생성 문항의 자동 보관과 교사의 검토 완료는 별개 상태로 기록한다. 학생 배정·공개는 기존 정책과 교사 행동에 따른다.

원문부터 제작하는 경우도 실제 문서의 출처를 꾸며 붙이지 않고 `AI 제작 원문`으로 보관한다. 원문 버전, 파생 문항, 답·해설의 근거 연결을 유지한다. 원문을 바꾸면 영향받는 문항의 점검 결과를 갱신한다. 한 문항 재제작 시 다른 문항과 교사의 수정 내용은 유지한다.

작업 화면에는 현재 단계, 완료한 항목, 확인할 항목, 취소·실패·재시도와 결과 수를 표시한다. 실패한 항목만 다시 처리하고 이미 저장한 문항을 중복 생성하지 않도록 작업 ID와 단계별 결과를 유지하는 계약이 필요하다. 수업에 맞는 수준·정답·해설 품질은 실제 생성 평가를 거쳐야 한다.

이 부분은 향후 구현을 위한 설계 제안이며, 이번 HTML 시안은 AI를 호출하거나 자동 판정을 실행하지 않는다. 프로젝트 TypeSafe 스킬과 2026-10-07에 읽은 live docs를 기준으로 정리했다.

| 역할 | 실행 주체 | 결과와 화면 표현 |
|---|---|---|
| 원문 복원, 수·길이·유형·보기 개수·필수값 검사 | 결정적 코드/기존 규칙 엔진 | 빈칸 연습 또는 형식 오류. 정답의 의미를 검증했다고 표시하지 않음 |
| 새 지문·변형 문항·보기·해설 초안 제작 | 기존 생성 모델 연결 | 제작된 초안. 실제 호출 성공, 실패, 취소를 구분 |
| 답과 원문의 관계, 해설 근거, 의심 항목의 분류 | TypeSafe/Jev를 활용하는 좁은 의미 판단 후보 | 확인할 근거와 항목을 교사에게 제시. 사람의 확인 완료와 분리 |
| 확정·출력·학생 공개 | 교사 행동과 서버 정책 | 행동 기록에 따른 검토 상태와 공개 상태 |

해설의 인용문은 우선 코드로 원문에 존재하는지 검사한다. 존재할 때만 원문의 주변 문맥이 답·해설을 지지하는지 좁은 판단으로 확인하는 흐름을 제안한다. 이는 TypeSafe의 [인용문 점검 cookbook](https://docs.typesafe.ai/cookbooks/citation_check)의 패턴을 영어 문항에 적용하는 설계적 추론이며, 그 예제의 성능 수치를 영어 문제 검증 성능으로 옮기지 않는다.

판단의 불확실성은 검토 순서와 추가 확인에 사용한다. 모델 confidence를 정답 정확도·학생 점수·품질 보증 수치로 표시하지 않는다. 자동 처리 임계값은 자체 영어 문항과 교사 판정 데이터로 검증한 뒤 정하며, cookbook의 예제 임계값을 그대로 가져오지 않는다. [TypeSafe confidence 문서](https://docs.typesafe.ai/confidence)

원문이 바뀌면 예전 근거와 품질 판정을 다시 확인한다. 문제은행에는 생성 출처, 원문 ID·버전, 형식 검사, 의미 점검, 교사의 검토 행동을 별도 정보로 남기는 방향을 제안한다. 첫 구현에서도 원문 제작→문항 제작→자동 형식 검사→은행 초안의 연결을 완성한다. 의미 점검은 평가가 끝난 범위부터 붙이고 미연결 항목은 점검하지 않았다고 표시한다.

## 유지해야 할 경계

- 기존 영어·듣기 기록, 수학 기록, 소유·지점 권한과 학생별 추가 메뉴 정책을 보존한다.
- 파일 업로드를 원문 추출 완료로 표시하지 않는다. PDF·DOCX의 자동 추출과 대용량 수입은 기존 M0 계약과 후속 게이트를 따른다.
- 출제 경향 예측, 점수 향상률, 정답 검증률, 완벽한 출제 같은 근거 없는 문구·수치를 넣지 않는다.
- 듣기 공식 링크와 자체 소유 자료, 사람 검토와 형식 검사, 검토 완료와 학생 공개를 구분한다.
- 초기 납품은 계획과 클릭 가능한 디자인 시안 5개다. 사용자 선택 이후 D를 수학 구성과 AI 원문 제작 흐름에 맞춰 보완한다. 이번 변경은 선택안의 구체화이며 운영 UI·API·DB 연결은 다음 구현 단계다.
