## 2. 원장님께 물을 것 (구현 전에 닫아야 함)

- **D1 — A형에도 AI 첨삭을 다는가.** 시안은 A형이었지만 지금은 A형을 모델이 채점하지 않는다(F1). 셋 중 하나다.
  - (가) B·C·D·E 에만 단다. A형은 지금처럼 교사 확인이다.
  - (나) A형도 모델이 «첨삭 초안»을 만든다. 판정(○△×)은 교사가 하고, 초안은 교사가 확인한 뒤에만 공개한다.
  - (다) A형도 자동 판정·자동 공개한다. 11-25 결정을 뒤집는 것이다.
  - 리드 추천은 (나)다.
- **D2 — 공개 시점.** 지금은 판정이 다 되면 즉시 공개한다. 종이 위 빨간 글은 목록의 한 줄보다 무겁게 읽힌다.
  - 추천: ○ 와 ✓ 는 즉시 공개한다. **× · △ 의 첨삭 글은 교사가 «첨삭 공개»를 누른 뒤** 학생에게 보인다. 판정 자체의 공개 규칙은 그대로 둔다.
- **D3 — 바른 답을 학생에게 보이는가.** 시안은 예 칸에 바른 계산(20−5=15 …)을 적었다. 같은 지면을 다시 풀게 할 계획이 있으면 답이 새 나간다.
- **D4 — Hi-fi 단계(D-07).** 실제 제품 글꼴·빨강·밑줄 두께·폰 폭에서의 모양은 Hi-fi 4~5안으로 다시 고른다. 시안은 Wire 수준이다.
- **D5 — 오른쪽 «왜 틀렸나» 카드를 남기는가.** 남기면 사진 위 글은 짧게, 카드는 길게 쓸 수 있다.

## 3. 설계

### 3.1 무엇을 모델에 묻고, 무엇을 코드가 정하는가

- **모델은 «말»만 낸다.** 표적마다 `notes` 를 최대 3개 낸다.
  - `kind`: `wrong`(틀린 말) · `missing`(빠진 근거) · `example`(예의 계산 실수)
  - `quote`: 학생이 쓴 글에서 **그대로 따온 부분**
  - `say`: 종이에 쓸 짧은 말. 한 줄 18자 안팎으로 두 줄까지.
  - `fix`: 바른 계산이나 바른 문장. 선택 칸이며 D3 에 따른다.
- **코드는 «자리»를 정한다.** 모델이 주는 좌표는 쓰지 않는다. 손글씨 위 좌표는 잰 적이 없다.
- **결정적 검사를 한다.**
  - `quote` 가 읽은 글의 부분 문자열이 아니면 그 첨삭은 버린다. 칸 단위 번호만 남긴다.
  - `kind=wrong` 인데 판정이 `correct` 이면 버린다.
  - 개수와 길이가 상한을 넘으면 버린다.
- **지시문 판을 올린다.** 채점 판 `…-v3-markup`. 기존 `reason` 한 줄은 그대로 둔다. 화면의 다른 곳과 교사 수정 이력이 그것을 쓴다.

### 3.2 자리 찾기 (사진 → 종이 좌표, 결정적)

1. `matched` 인 사진만 쓴다. `uncertain` 이면 사진 위에는 그리지 않고, 지금처럼 목록에 까닭만 보인다.
2. `warpScanPage` 로 칸 영역을 종이 좌표로 편다. 저장된 빈 지면 렌더와 견줘 **인쇄된 줄·글자를 빼고 학생 잉크만** 남긴다. 그다음 잉크의 가로 띠(글줄)를 찾는다.
3. **줄 맞추기.** 읽기 지시문을 고쳐 칸의 글을 **줄바꿈 그대로** 옮기게 한다(판 `…-v4-lines`). `quote` 가 있는 줄 번호 k 와 잉크 글줄 k 를 맞춘다. 글줄 수와 읽은 줄 수가 다르면 줄 맞추기를 포기하고 칸 단위로 표시한다.
4. **밑줄의 가로 범위.** 1단계에서는 그 글줄의 잉크 범위 안에서 **글자 수 비례**로 근사한다. 2단계(§4 M4)에서 정확도를 잰 뒤 더 나은 방법(글줄 잘라 한 번 더 묻기 등)을 고른다. 기준을 못 넘으면 **줄 끝 번호만** 단다.
5. **빈 줄 찾기.** 학생 잉크가 없는 인쇄 줄 가운데 마지막 글줄 아래를 쓴다. 자리가 모자라면 예 칸의 빈 아래쪽을 쓰고, 그래도 모자라면 번호만 달고 글은 카드로 보낸다.
6. 결과는 **종이 mm 좌표의 배치표**로 저장한다. 그릴 때만 사진의 변환 행렬로 옮긴다. 배치는 같은 입력이면 같은 출력이다.

### 3.3 저장 (DB 먼저 · 코드 나중)

- 새 표 `concept_blank_scan_markup`. append 전용이다.
  - 칸: `submission_id` · `grade_id`(어느 판정 행의 첨삭인가) · `sequence` · `origin`(ai · teacher) · `notes` JSON · `layout` JSON(mm 배치) · `prompt_version` · `requested_model` · `published_at`(D2) · `teacher_id`
  - 교사의 고침·삭제·공개는 새 행으로 쌓는다. 원래 AI 초안은 덮지 않는다.
- `evidence` 칸에 넣지 않는 이유가 둘이다. 판정 행은 교사 수정 때 새로 생기므로 첨삭의 공개 상태와 수명이 다르다. 학생 공개 경계도 따로 지켜야 한다.
- 마이그레이션은 추가만 한다. 표가 없으면 첨삭 API 는 503 을 내고, 기존 결과 화면은 그대로 돈다.

### 3.4 그리기

- 기존 `ScanPhoto` 오버레이(SVG)를 넓힌다. 사진 위 칸 테두리와 같은 변환을 쓴다.
- 글꼴은 **자체 호스팅**한다(Google Fonts 금지 — 20번 교훈 2026-10-18 «로그인 관문이 글꼴을 HTML 로 바꿨다»). 글꼴 적재 실패를 시험으로 잡는다.
- 빨강 고정색과 흰 테두리를 쓴다. 테마 토큰을 쓰지 않는 예외로 05 에 적는다.
- 교사 화면(R4)에서는 첨삭마다 [고치기]·[지우기]가 있고, 공개 전후 상태가 보인다. 학생 화면(R2)은 공개된 것만 보인다.
- 폰 폭에서 글이 너무 작으면 사진 확대에 맞춰 글도 커진다(SVG 이므로 자연스럽다). 최소 크기는 Hi-fi 에서 정한다.
- 공용 부품 규칙(D-159)을 따른다. 여러 쪽은 `PaperStrip` 의 쪽 크게 보기 안에서 그린다.

### 3.5 비용

- 채점 호출의 출력이 표적당 몇십 토큰 늘어난다. 선예약 상계(최대 출력 16,000)는 그대로 두고, 실제 정산으로 증가분을 잰다.
- 읽기 v4(줄바꿈)는 출력이 조금 는다. 사진 입력은 같다.
- A형 초안(D1 나)은 지금 0원인 A형에 새 호출이 생긴다. 월 상한 $100 안에서 하루 장수로 다시 잰다.

## 5. 위험

- **틀린 빨간 펜.** 모델이 맞은 말을 «틀렸다»고 적으면 학생에게 해롭다. → D2 공개 문, 결정적 검사, 교사 고침률을 지켜본다.
- **자리 어긋남.** 글줄 찾기가 틀리면 남의 줄에 밑줄이 간다. → 맞추기 실패면 칸 단위로 물러난다. 억지로 그리지 않는다.
- **답 노출.** D3 에 따른다.
- **사진 맞춤 실패.** F5 처럼 `uncertain` 이면 첨삭은 목록으로만 보인다. 실제 폰 사진의 `matched` 비율을 M2 표본에서 함께 잰다.
- **글꼴.** Google Fonts 를 쓰지 않는다. 손글씨체의 라이선스(OFL 등)를 확인한다.

## 6. Codex 협의 결과 (v2 — §1~§5 보다 앞선다)

### 6.1 사실 정정

- **F4:** `matched` 사진은 저장할 때 이미 A4 로 펴진 JPEG 이다. 행렬과 칸 네 점은 **펴진 저장 사진** 기준이다. 그래서 다시 원근 보정할 필요가 없고, 그리기는 펴진 사진 위 mm → px 비례로 충분하다(`flatten.server.ts` · `submission.ts`).
- **F6:** 빈 지면은 **픽셀로 저장되지 않는다.** 저장되는 것은 쪽별 HTML·CSS·글꼴 지문과 배치·해시다. 잉크를 가르려면 같은 발행본으로 기준 영상을 새로 렌더해야 한다.
- **F5 · F7:** 운영 수치는 리드의 측정 기록이다. Codex 는 운영 DB 를 다시 보지 않았다. 0.46mm 는 QR 오차이며, 칸이나 글줄의 오차로 쓰지 않는다.

### 6.2 합의한 것

1. **첫 출시는 칸 단위 표식과 검증된 빈 자리만.** 글자 수 비례 밑줄은 내부 시제품까지만 쓴다. 줄 끝 번호는 인용이 한 줄에 유일하고, 국소 정합과 글줄 순서가 믿을 만할 때만 단다. 낱말 물결 밑줄은 M4 에서 사람 참값으로 잰 뒤 따로 켠다(오지목 0건 권고). 자리가 없으면 다른 칸으로 밀지 않고 번호와 목록으로 보낸다.
2. **× · △ 첨삭은 교사가 공개한 뒤에만 학생에게 보인다.** 글뿐 아니라 번호·∧·밑줄·배치도 함께 숨긴다. ○△× 판정과 한 줄 까닭은 지금처럼 즉시 공개한다. ✓는 그 줄·칸의 정답 근거가 따로 확인될 때만 단다. 여러 칸을 묶은 ○ 에서 줄마다 ✓ 를 추측하지 않는다.
3. **학생 응답은 서버가 허용 필드로 공개본만 직렬화한다.** 초안·미공개 인용·배치·기준 답·교사 이력은 학생 경로에 넘기지 않는다. 판정이 바뀌면 그 전 판정의 첨삭은 바로 숨기고, 교사가 다시 공개한다. 공개본을 고치는 동안에는 마지막 공개본을 보여 준다. 삭제는 따로 기록한다.
4. **판정과 첨삭은 따로 검증한다.** 엄격한 `scanGradeSchema` 에 `notes` 를 붙이면 판정까지 실패할 수 있다. 첨삭이 잘못되면 버리고 판정은 저장·공개한다. `correct` · `review` 에는 교정 문구를 만들지 않는다. 인용은 한 칸의 **원 판독**에서만 찾고, 직접 입력은 종이 글의 근거로 쓰지 않는다.
5. **비용과 복구.** 지시문과 스키마가 길어지면 선예약 입력 상계가 는다. 이것을 다시 잰다. `model.ts` 의 결과 열쇠가 판에 묶여 있으므로, 판을 바꾸기 전에 대기 작업을 다 비우거나 구판 복구를 지원한다. 첫 출시는 **추가 모델 호출 없이** 채점 응답 하나에 담는다.
6. **저장은 별도 append 표.** 판정별 첨삭 스냅숏과 edit · publish · remove 사건을 둔다. 같은 제출의 grade · photo 만 참조하게 DB 제약을 걸고, 순번 유일·재시도 키를 둔다. «첨삭 없음 · 실패»도 기록해 같은 유료 응답을 다시 쓰지 않는다. 표가 없을 때의 503 은 첨삭 경로에만 둔다.
7. **D3:** 바른 답·바른 계산은 학생에게 자동으로 보이지 않는다. 교사용 승인 화면에만 둔다. 학생 문구는 공개 승인 때 답이 새는지 함께 본다.
8. **D5:** 오른쪽 상시 카드는 두지 않는다. 기존 결과 목록을 번호로 짚는 대체 경로로 쓴다. 사진이 작거나 만료됐을 때도 읽을 수 있다.
9. **M2 측정은 사람 참값으로.** 물리적 줄·낱말 범위·빈 자리를 사람이 따로 표시한다. 칸 오인 · 줄 오인 · 앵커 오차(mm) · 학생 글 가림 · 후퇴율을 분모와 함께 기록한다. 실제 인쇄·폰 사진(기울기·그림자·옅은 연필·지움·칸 밖 답)으로 잰다.
10. **M3 시험 보완.** 두 교사의 동시 공개, 판정 교체 경쟁, 권한(본인·다른 학생·교사), 사진 만료·삭제·교체, DB 미적용, 저장 뒤 작업 중단·재개를 시험한다.

### 6.3 의견이 갈려 원장님께 묻는 것

- **D1 — A형(자유 서술).**
  - 리드는 (나)를 추천했다. AI 가 첨삭 초안만 만들고, 판정과 공개는 교사가 한다.
  - Codex 는 (가)를 추천했다. 첫 출시는 B·C·D·E 만 한다. A형 초안도 «어느 말이 틀렸나»라는 의미 판단이어서, 참값 없이 교사 검수만으로는 위험하다는 이유다.
  - **리드도 첫 출시는 (가)에 동의한다.** A형 초안은 교사 전용으로 따로 재 보고(내용 오류율 · 교사 채택·수정 시간) 둘째 단계에서 정한다.
  - 원장님이 고른 시안이 A형이었으므로 이것은 원장님이 정하신다.
- **낱말 밑줄이 첫 출시에 없다.** 시안의 물결 밑줄은 M4 의 측정을 지나야 켜진다. 그 전에는 칸 번호와, 조건이 맞을 때만 줄 끝 번호를 단다. 모양이 시안과 달라지므로 원장님께 알린다.

### 6.4 원장님 결정 (2026-11-26)

- **D1 → 나눠서.** 첫 출시는 AI 가 채점하는 B·C·현재 D·E 지면에만 첨삭을 단다. A형은 교사 전용으로 AI 초안의 정확도를 따로 잰 뒤 둘째 단계에서 정한다.
- **낱말 밑줄 → 재 보고 켜기.** 첫 출시는 칸 번호(조건이 맞으면 줄 끝 번호)와 그 아래 빨간 글이다. 물결 밑줄은 M4 에서 실제 폰 사진의 사람 참값으로 오지목 0건을 확인한 뒤 켠다.
- D2 · D3 · D5 는 §6.2 의 합의안대로 간다. D4(Hi-fi 4~5안)가 다음 차례다.
