# 탐험에 통합하는 개념 복습 — 2026-10-07

## 확정한 사용자 요구

기본 화면은 기존 수학 탐험이다. 진도판·문제풀이·도감·복습을 유지하면서,
새 개념 학습을 탐험 안에서 연다. 별도의 v2 홈으로 학생을 보내지 않는다.
기존 기록과 새 `fading` 기록은 보존한다. 외부 앱 연동 없이도 작동해야 한다.

학습은 개념을 떠올리고 읽기 → 빈칸에 직접 입력하기 → 더 많은 빈칸 →
핵심 답 직접 쓰기와 기준안 대조 순으로 이어진다. 답 칩은 숨긴다.
읽었을 때의 익숙함과 도움 없이 떠올린 결과를 서로 다른 증거로 다룬다.

학생별 하루 기본 분량을 정하면 엔진이 복습·선수개념 확인·진도를 섞어 구성한다.
20은 예시이며 모든 학생에게 강제하는 상수가 아니다. 학습 중 꼭 필요한
재학습은 1분이나 5분 뒤에 다시 넣는다. **기본 20 + 재학습 n**은 허용한다.
따라서 추가 재학습까지 포함한 총량을 20으로 잘라 버리지 않는다.

## 일정의 두 층

장기 일정은 기존 FSRS-5를 사용한다. 안정도·난도·지난 평가 이후의 경과 일수로
다음 복습일과 현재 회상 가능성을 계산한다. 모든 학생에게 1·3·7일을 일괄 적용하지 않는다.
기본 목표 회상률 90%는 모델의 목표이며, 개별 학생에게 실제 측정한 정확도가 아니다.
계산의 기준 벡터와 날짜 경계를 유지한다. 자료가 적을 때 개인별 가중치를 학습했다고 주장하지 않는다.

단기 재학습은 분 단위의 별도 대기열이다. 틀림·포기·답 확인이 필요한 상태를
기록하고 다른 문제를 푸는 사이에 재검증한다. 초기 운영 정책은 다음과 같다.

| 결과                              | 단기 재학습               | 장기 일정                                       |
| --------------------------------- | ------------------------- | ----------------------------------------------- |
| 답을 떠올리지 못함·오답·도움 사용 | 1분 뒤 확인               | 실패를 성공으로 덮지 않음                       |
| 단기 재학습에서 도움 없이 맞힘    | 5분 뒤 다시 확인          | 같은 날 반복을 별도 장기 성공으로 누적하지 않음 |
| 뒤의 확인에서도 도움 없이 맞힘    | 단기 대기열 종료          | 장기 복습일 유지                                |
| 뒤의 확인에서 다시 실패           | 1분 뒤 재학습과 보충 안내 | 기존 실패 증거 보존                             |

1분·5분은 사용자가 제시한 초기 재학습 정책이다. 모든 학생에게 최적이라는
실험 결과로 표현하지 않는다. 같은 개념을 즉시 반복해서 맞히는 것과 간격을 두고
기억해 내는 것을 구분한다. 대기열은 새로고침과 이탈 후 복귀에도 보존해야 한다.
타이핑 중 갑자기 화면을 바꾸지 않고 현재 문항을 마치는 경계에서 준비된 재학습을 안내한다.

## 하루 구성과 선수개념

열린 학습을 먼저 이어가고, 장기 복습은 망각 위험과 실제 만기 기록으로 정렬한다.
부족이 확인된 선수개념은 보충하고, 평가되지 않은 선수개념은 확인부터 한다.
진도는 남은 기본 분량과 기존 설정을 따르며, 단기 재학습은 추가 분량으로 별도 표시한다.
분량이 넘쳤다는 이유로 원래 복습일을 뒤로 쓰지 않는다.

선수도 간선은 저자가 작성한 교육적 연결이다. 정답 하나로 전체 단원의 이해를
확정하지 않으며, 오답 하나로 선수개념 부족을 확정하지 않는다. 제목 유사도로
ID를 연결하지 않는다. 확인되지 않은 매핑과 문제 공급은 미확인으로 남긴다.

은행 문제·개념 문장·묶음·기존 탐험 활동의 개수는 각각 표시한다. 개념 문장 다섯 개가
담긴 묶음을 은행 문제 한 개로 표시하지 않는다. 같은 문장을 여러 단계에서 연습한
것도 새로운 다섯 문제로 부풀리지 않는다. 공급이 모자라면 모자란 분량을 설명한다.

## 구현과 검증 경계

Codex는 화면·키보드·반응형·미리 보기를, Claude는 일정·세션·일일 구성·계약·저장·검증을 맡는다.
화면은 라이브러리와 source 결과를 표시하며 비율·간격·진도를 자체 계산하지 않는다.
기존 탐험과 새 개념 학습의 ID·평가·일정 저장 경로를 합쳐서 중복 갱신하지 않는다.
새 JSON 필드는 독자가 먼저 배포된 뒤 기록한다. 이전 콘텐츠를 들고 온 요청의
409·세션 토큰·지문·요청 영수증을 유지한다.

로컬 미리 보기는 서버에 읽기·쓰기 요청을 보내지 않는다. 사용자 인증과 지점 범위는
실제 API에서 그대로 적용한다. 완료 검증은 기본 분량 혼합, 1분/5분 경계,
대기열 복귀, 오답·도움과 장기 일정 분리, 선수도 미확인, 중복 요청과 화면 전체 흐름을 포함한다.
