## 공통 납품

- 담당자가 지정한 HTML 파일만 작성한다. 자체 CSS/JS를 전부 inline으로 넣고 상대 리소스를 참조하지 않는다. 외부 라이브러리 없이 브라우저에서 열린다. SVG 직접 제작 가능, 외부 사진 불필요. 폰트는 CDN Pretendard 또는 Noto Sans KR을 써도 되지만 로컬 한국어 fallback 필수.
- 진짜 제품처럼 보이는 풀 화면 시안. PC 1440×1000 기준 촬영 가능하고 390px에서도 깨지지 않는다. 색만 다른 같은 카드 대시보드 금지. 담당 안의 정보 구조와 작업 방식이 보여야 한다.
- 상단에 작은 시안 표시 `A/B/C/D/E … · 예시 데이터`를 두되 제품 화면 내부에 설계 설명을 남발하지 않는다.
- 모든 안에 `AI 문제 제작`, `문제은행`, `자료은행`, `듣기`가 접근 가능하다. AI/엔진이 핵심 제작 도구이고 공급자 브랜드/JSON/API를 주된 메뉴로 내세우지 않는다.
- 최소 2개의 실제 화면 상태를 HTML 내부 JS로 제공한다. 제작 조건 선택, 원문 선택/본문 입력, 유형 선택(3~8문항), 초안 미리보기·검토, 문제은행 선택/담기 중 유용한 최소 3개 인터랙션을 만든다. 단순 토스트만 반복하는 가짜 버튼 금지. 작동하지 않는 행동은 무조건 작동한다고 보이지 않게 처리한다. 네트워크 API와 데이터베이스를 호출하지 않는다.
- 인쇄 미리보기는 자체 시안 지면 표시 가능. 실제 인쇄를 한다면 브라우저 인쇄만. 실제 음원이 없으면 재생 버튼으로 시간을 흘리는 가짜 재생 금지. 연결 필요 상태나 음원 선택 화면을 제공한다.
- 샘플 학교 `한빛고`, 고1 `2학기 중간고사`, 샘플 자료 `도시의 작은 정원 / Small gardens, big changes`. 영어 예문은 직접 창작. 문항 정답과 근거가 일치하도록 설계.
- 현재 문항 유형: 주제, 내용 일치, 어법, 빈칸 추론, 문장 삽입, 서술형, 어휘, 언급 없음, 해석, 영영풀이, 공통 빈칸, 문장 전환, 단어 배열, 원문 복원.
- 저장 상태는 `초안 / 검토 중 / 검토 완료`. 형식 검사를 사람 검토/정답 검증으로 바꾸지 않는다. 신규 은행/일괄 구성은 미래 설계 시안이고 실제 운영 완료가 아니다.
- 자동 출제 경향 파악/성적 예측/AI 정확도/평균 제작시간/인쇄 완료 집계 같은 가상 기능과 과장 문구 금지. 샘플 수치는 작업물 수로 명확하고 일관되게 제시한다.
- Focus-visible, 실제 button/link/label, 적절한 대비, dialog Escape/닫기, reduced-motion, 반응형을 갖춘다.
- 적용한 frontend-design 스킬을 읽고 계획→구현→시각 확인. Next 코드·서버·DB·의존성·기존 제품 파일은 변경하지 않는다. node_modules의 Next docs를 읽어야 한다면 부모 작업트리의 로컬 문서를 활용한다.
- 완료 후 담당 파일만 커밋한다. push/main merge/공개 링크 발행/다른 worktree 제거는 하지 않는다. 부모가 파일을 합치고 QA한다. 최종 답변에 파일 경로, commit hash, 구조 차이, 인터랙션, 한계와 검증을 알려준다.
