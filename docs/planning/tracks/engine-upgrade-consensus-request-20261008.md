## 물음 — 각 물음에 «결론 · 근거(파일:줄) · 반대하는 점 · 위험»을

**Q1 (①) 등록 단위.** 계산 판정 · 비교 객관식을 엔진의 어디에 둘까?
(가) 새 RPM 유형처럼 차시별 등록부(`typesForSection`)에 «판정형 유형»으로 (나) 결합형처럼 별도 등록부 (다) `expandEngine` 단계의 새 «형식»(단답 · 객관 다음 셋째) — 문항류(`familyKey`) · `externalId` 모양 · 난이도 칸 · 적재기 · `checkUnloadedTypes` 와의 관계까지.

**Q2 (①) 보기 다섯을 짓는 법.** 같은 유형을 씨앗 다섯으로 부르나, 같은 차시의 여러 유형을 섞나? «옳지 않은 것» 하나를 어떻게 만드나(정답을 `numericMistakes` 로 흔든 «틀린 등식»?) — 그리고 **모호함을 막는 조건**(두 보기의 값이 같다 · 틀리게 만든 값이 우연히 맞다 · 한 보기만 유난히 길다 · «나머지 넷과 다른 하나»에서 둘이 다르다 · «가장 큰 것»에서 같은 값이 둘)을 무엇으로 시험하나.

**Q3 (②) 설명 판정의 진술 원천.** ⑴ 매개변수로 참거짓을 **계산하는** 진술 틀(정비례 · 반비례 · 일차함수 그래프의 성질 · «정비례/반비례하는 것» 상황 문장 …)을 어느 차시부터 ⑵ 개념 백지 ○× 문장을 재료로 쓰면 무엇을 지켜야 하나(되풀이 · 은행 개정 때 씨앗 결과 변동 · 내용 지문 · 출처 표지) ⑶ 꼴은 «옳은/옳지 않은 것 하나» · «모두 고르면?(정답 2개)» · «ㄱㄴㄷ 조합 보기» 중 어디까지 — ○× 괄호 지면은 시안 대상이라 이번에 뺄지.

**Q4 (③) 공통수학2 물결 2.** `high-engine-plan.md` 의 물결 1 방식(중단원별 모듈 · 세션별 소유 · `HOLDS` · 시험 · 판정기)을 그대로 쓸 때, 범위와 차례(그림 없는 중단원 먼저? 교과서 빈도순?), 세션을 어떻게 나누나, 적재와 `supportedGrades` 에 공통수학2 를 여는 시점.

**Q5 공통 — 진행 순서와 문.** ①②③을 어떤 차례 · 어떤 단위로 main 에 올리나(끊어서 푸시), 각 단계의 시험 · 판정기 · 적재 · 관문(`checkUnloadedTypes` · `refresh-engine-content` 드라이런 0) · 원장님께 보일 시안(있다면 무엇).
