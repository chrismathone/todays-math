# 기출 생성 엔진과 기존 문항 재구축의 작업 분담

2026-10-20 사용자가 이 대화에서 확정한 최신 범위다. 이전의 지속 추출·집필 지시보다 이 작업 분담을 우선한다.

- 이 세션은 **생성 엔진 개선**을 담당한다. 학년·교육과정 관문, 유형·조건·정답 계산·학생용 해설, 새 그림/이미지 자산 지원, 메타데이터와 재현성 검증을 코드로 보완한다.
- 다른 컴퓨터의 세션은 **기존 118,166개 문항의 전수 검수·재구축**을 담당한다. 그 세션은 `src/lib/examStudy/**`와 아래 엔진·렌더 파일을 수정하지 않으며, 여기서 발견한 결함은 목록으로 남겨 엔진 담당이 반영한다.
- 사용자가 구체화한 다른 세션의 첫 범위는 **문제 지면 수정**이다. 최신 main에서 기준 자료를 다시 추출하고, 다음 지면 결함을 수정한 뒤 AI 모델들로 교차 검수하고, 마지막 DB dry-run 묶음을 만든다. 중고등 엔진 결함은 직접 고치지 않고 `handoff-engine.md`에 남긴다. 이 세션은 그 목록의 실제 파일·기준 커밋·재현 조건을 읽어 엔진 수정으로 연결한다.
- 다른 세션의 둘째 범위는 **서술형 첫 묶음**의 실제 지면 출력·측정과 정답을 가린 독립 풀이의 병행이다. 이 세션은 해당 묶음을 중복 제작·검수하지 않는다. 엔진 결함 목록을 넘겨받는 일과 해당 문항의 DB·지면·blind 승인은 구분한다.
- 경계 파일: `src/lib/middle/m3.ts`, 중3 그림/제곱근 모듈(`m3figures.ts`, `m3root.ts`), `src/lib/figure/renderFigureSpec.ts`, `src/lib/engine/expandEngine.ts`, `src/lib/engine/deriveFormats.ts`. 사용자가 말한 `expandEnginge.ts`는 현재 저장소의 `expandEngine.ts`를 가리킨다. 실제 경로와 최신 커밋을 확인한 다음 수정한다.
- `src/lib/examStudy/curriculumEligibility.ts`와 `src/lib/examStudy/families/middle/inverseCoefficient.ts`는 문항 검수 세션이 수정하지 않는 것으로 별도 확인됐다. 현재 중3 방법의 학년 관문과 해설 보완은 이 세션의 변경이다.
- 이 세션은 **이미 출제된 문항, 기존 은행 행, 학생 기록을 수정하지 않는다.** 다른 컴퓨터에서 공유 DB를 수정할 때도 이 세션의 기출 쌍둥이 문항은 범위에서 제외한다. 원본 기출·보호된 82행·보정 원장 세 개·경산여19 영구 제외도 유지한다. 이 분담은 운영 삭제·재적재·잠금 해제·쌍둥이 적재 권한을 추가하지 않는다.

보존할 쌍둥이의 현재 식별자 목록은 [DB 수정 제외 목록](reports/exam-engine-ownership-20261020/excluded-twins.json)에 별도로 고정한다. 목록은 현재 선택 174개와 미선택 초안 4개의 새 ID를 구분한다. `exam-twin-` 접두사는 참고 경계이며 이 목록만으로 기존 DB의 모든 대응 행이 식별됐다고 단정하지 않는다. DB 작업자는 실제 ID·출처/생성 계보와 별도의 구체적인 수정 대상 목록을 대조해야 한다. 기존 미선택/폐기 버전이나 이미 저장된 계보를 이 목록 밖이라는 이유로 수정 대상에 자동 포함하지 않는다.

현재 실제 작성은 178개, 마지막 완성된 정본 v50의 선택은 174개, 전체 수학·학년 검수는 173개다. 정본 밖 네 초안을 이 수에 합산하지 않는다. 최종 승인·적재 가능·운영 적재·이 세션의 DB 쓰기는 모두 0이다. 새 raw 풀이와 기존 증거는 보존하되 엔진 중심으로 범위를 전환하며 문항 집필 배치를 추가하지 않는다. 이 숫자는 현재 DB 재조회가 아니다. 마지막 실제 DB 읽기는 2026-10-20 08:00:50.819024+00이며, 이후 다른 세션의 DB 변경을 반영한 최신값이라고 하지 않는다.

다른 컴퓨터가 이 분담을 받도록 현재 기능 브랜치 `chrismathone/exam-extraction-resume-20261008`에 체크포인트를 커밋·푸시한다. 매번 푸시 직전에 원격 기능 브랜치와 main을 fetch/비교하고 새 커밋을 보존·통합한 뒤 관련 검사를 통과시킨다. force-push, 기능 브랜치의 main 병합, 배포는 하지 않는다. 다른 세션의 결함 목록은 파일 경로·커밋·재현 조건을 확인하고, 기존 문항 수정과 엔진 수정의 책임을 구분해 반영한다.

현재 보완의 근거는 [중3 방법 관문 보고서](reports/exam-engine-grade-method-hardening-20261020.md)다. 현재 원격 main과 로컬의 다른 세션 커밋도 확인하며, 아직 main에 없는 다른 컴퓨터의 변경을 임의로 cherry-pick하거나 그 DB 갱신 작업을 재실행하지 않는다.

2026-10-21에는 [검산·렌더 데이터 소유권의 최신 main 검증](reports/exam-engine-draft-ownership-checkpoint-20261021.md)을 추가했다. 다른 세션의 [중고등 엔진 결함 M1~M38](brief-engine-handoff-display-20261021.md)을 이어받아 생성 코드에서 수정·검증한다. 기존 문항 지면과 DB 갱신은 계속 다른 세션의 범위다.
