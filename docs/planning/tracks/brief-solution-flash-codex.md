## 할 일
1. 해설 출력 한도 16000(딥시크 두 모델 모두 — 다른 공급자 해설 경로도 같은 값인지 확인, 다르면 맞춘다).
2. 해설 지시문(`buildDevAiPrompt` solution 갈래) 정제 — 짧게 덧붙인다:
   - 분수는 항상 `\frac{}{}`(빗금 분수 금지), 곱셈 앞 계수 분수는 괄호로 모호함 없게.
   - 그 문제의 **핵심 변형**(인수분해의 묶는 법 · 완전제곱 · 치환 · 경우 나누기)은 한 줄이라도 식으로 보인다.
   - **과하지 않게**: 단계는 핵심만(대략 2~5 step), 같은 말 반복 · 검산 나열 · 일반론 설명 금지. 고등도 같은 원칙.
   기존 출력 형식(JSON · step 표기 · 경고 칸)은 바꾸지 않는다.
3. 하네스로 재측정(유료, 상한 0.25달러): 표본 = 기존 30문항 + 고등 20문항(같은 ID 파일). 팔: flash@16k 새 지시문 · v4-pro@16k 새 지시문(비교 기준). 잴 것: 정답 일치(기존 판정 + 사람 확인 필요 목록) · 렌더 실패 · 잘림 · **빗금 분수 수**(`\d/\d` 같은 패턴을 수식 안에서 세는 검사를 채점기에 추가) · 평균 길이(과하지 않음 — 기존 v4-pro 평균보다 길어지면 안 됨) · 시간 · 비용. 핵심 변형 생략은 앞서 지적된 두 문항(인수분해 b531252f… · 이차함수 fb0fb51f…)을 나란히 출력해 리드가 읽게.
4. **전환 기준**: flash 가 정답 일치 ≥ v4-pro, 잘림 0, 렌더 실패 0, 빗금 분수 0 이면 해설 기본 모델을 `deepseek-flash` 로 바꾼다(`src/lib/studio-ai/routing.ts` API_MODELS · 화면 표시 «DeepSeek · 해설 전용» 라벨은 그대로 둬도 되면 그대로). 기준 미달이면 바꾸지 말고 무엇이 모자란지 보고.
5. 하네스 파일(`scripts/qa/ai-model-bench/`, `src/__tests__/unit/aiModelBench.test.ts`)은 이번 변경과 함께 커밋 대상이다 — 그대로 두고 필요한 만큼만 고친다.
6. 관련 시험(studio-ai 라우팅 · 프롬프트 스냅샷 등) · `npm run type-check` · 변경 파일 eslint. 공유 DB 쓰기 금지 · 커밋 금지. 키 출력 금지. 보고서 `docs/planning/tracks/reports/solution-flash-codex-20261019.md`(표 + 두 문항 나란히).
