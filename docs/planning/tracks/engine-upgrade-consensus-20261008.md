## 3. 셋째 눈이 찾은 것 — 계획에 넣는다

1. **`isChooseAll` 이 ㄱㄴㄷ 조합형을 «모두 고르기»로 읽는다.** «옳은 것을 **모두 고른** 것은?» 은 «모두» 가 «고르» 앞에 있어 정답 2개 규칙에 걸린다(`src/lib/problem/chooseAllRule.ts` — 직접 읽음). ㄱㄴㄷ 꼴을 넣기 전에 이 반례를 시험으로 박고 규칙을 가른다. (codex)
2. **«4+1» 비교형은 «값이 같은 보기 금지»와 부딪힌다.** «나머지 넷과 다른 하나»는 같은 값 넷이 정답 구조다 — 식의 중복 · 값의 중복 · 정답의 유일성을 문형별로 따로 시험한다. 묶음 크기가 정확히 4+1 인지, 3+2 로 변조하면 시험이 실패하는지(변이)까지. (codex)
3. **고등 기반은 등록부 밖에서 끊겨 있다.** 적재기에 `HighTarget` 이 없고, `checkUnloadedTypes` · 제자리 갱신에 고등 경로가 없고, 출처 판정의 엔진 접두사가 `elem:` · `mid:` 둘뿐이다(`src/lib/problem/provenance.ts` — 직접 읽음). 공통수학1 168유형도 아직 문제은행에 **안 실려 있다**는 뜻이다 — ③ 의 «0단계»가 이 배선이다. (codex)
4. **48차시는 «교과서가 있는 차시»다.** 시드는 공통수학2 소단원 50(«증명» · «(교육과정 외) 두 원의 위치 관계» 포함) — 완료 분모로 48 을 쓰지 않는다. (codex)
5. **고등 전수 시험에 등록 수 168 고정값**이 있다 — 과목별 보존 검사로 바꾸며 넓힌다. 집합 · 함수식 답은 지금 수 정답 읽개로 검산이 안 된다. (codex)
6. **드라이런 0 은 «같은 문제»의 보증이 아니다** — `identityRisk` 문지기를 우회하지 않는다(20번 문서 2026-10-03 «298행»). (codex)
7. 그림만 바뀐 행은 글 비교에서 «같음»으로 빠진다 — 제자리 갱신 드라이런에 그림 문항류를 명시한다. (Gemini)

## 4. 원장님 결정 (2026-10-08 — 물은 것)

- **개념 백지 ○× 문장을 ②의 재료로 — «출처를 달고 같이 씀».** 매개변수 진술과 함께 쓴다. 대신 codex 의 여섯 조건을 **계약**으로 붙인다(시험이 지킨다):
  1. 되풀이 — 한 시험지 안에서 같은 원천 ID · 같은 문장을 다시 쓰지 않는다. 순서만 바꾼 세트를 새 내용으로 세지 않는다.
  2. 씨앗 재현 — 은행 배열을 매번 읽지 않고, **판이 고정된 후보 목록(스냅숏)**에서 뽑는다.
  3. 내용 지문 — ID 뿐 아니라 차시 · 문장 · 참거짓 · 까닭을 묶은 지문을 남긴다(같은 ID 의 내용 수정도 잡힌다).
  4. 출처 — 원천 ID · 은행 판 · 내용 지문을 생성 기록에 남긴다. 교과서 이관본 · RPM 유형으로 표시하지 않는다.
  5. 개정 — 새 은행 판은 **새 생성판**으로 적재한다. 이미 실린 문항을 최신 은행 문장으로 자동 교체하지 않는다.
  6. 난이도 — 은행의 하 · 중 · 상을 엔진 6칸에 기계적으로 대지 않고 조합 문형의 판단 요구로 따로 정한다.
  - 🔴 은행 문장의 참거짓 표지를 그대로 베끼면 검산이 동어반복이다 — 재료로 쓰는 문장은 «개념을 묻는다» 하브루타(26 §11)를 지난 것만, 거짓 문장은 «어디가 틀렸는가»가 까닭에 있는 것만.
- (알림 — 물을 것 없음) ○× 괄호 지면 · 소문항 묶음은 이번에 안 한다 — 하게 되면 Wire 시안부터.
