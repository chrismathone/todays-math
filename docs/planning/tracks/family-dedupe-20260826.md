# 한 시험지에 같은 문항류 1개 — 분모·확충 우선순위 (2026-08-26)

> **한 줄 결론:** 반 3개의 정원은 모두 8문항인데, 현재 엔진이 닿는 152소단원 중
> **135곳은 문항류가 8갈래보다 적고 8갈래까지 총 522갈래가 모자란다.** 원장님이
> 보신 초6 「2-6-4 구 알아보기」도 출제 가능 문항은 15행이지만 문항류는 **4갈래**뿐이라,
> 같은 `family_key`를 한 장에 한 번만 쓰면 4문항이 상한이다. D-20을 적용해도 이 수는 4다.

이 표는 규칙을 약하게 할 근거가 아니다. 같은 `family_key`는 한 시험지에 **무조건 1개**만
쓰고, 부족분은 새 문항류를 만들 순서로 쓴다.

## 3. NULL·`solo:*`·출처 검산

### 출제 가능 분모

| source | 행 | distinct 가족 | 저장된 `solo:*` | NULL | 빈 값 |
|---|---:|---:|---:|---:|---:|
| `manual` | 2,410 | 780 | 0 | 0 | 0 |
| `past_exam` | 0 | 0 | 0 | 0 | 0 |
| `transformed` | 0 | 0 | 0 | 0 | 0 |
| `ai_generated` | 0 | 0 | 0 | 0 | 0 |

즉 현재 우선순위 분모에는 검수·격리를 통과한 엔진 문항만 있다. 기출·자작·AI 변형을
규칙이 과하게 묶는 현상은 이 분모에서 일어나지 않는다.

### 문제은행 전체 — 분모 밖 대조

| source | 전체 행 | 방어 환산 뒤 가족 | NULL/독립 가족 | 저장된 `solo:*` | 둘 이상 묶인 가족 | 최대 가족 크기 |
|---|---:|---:|---:|---:|---:|---:|
| `manual`(자작+엔진) | 3,177 | 1,544 | 764 | 0 | 775 | 4 |
| `past_exam`(기출) | 41,084 | 41,084 | 41,084 | 0 | 0 | 1 |
| `transformed`(변형) | 3,526 | 3,526 | 3,526 | 0 | 0 | 1 |
| `ai_generated` | 0 | 0 | 0 | 0 | 0 | 0 |

기존 기출 41,084행과 변형 3,526행은 실제 저장값이 `solo:*`가 아니라 **NULL**인
레거시 행이다. 따라서 구현은 NULL을 하나의 가족으로 묶으면 안 된다. 문항 ID별 독립 가족으로
환산하면 기출·변형은 모두 가족 크기 1이고, 자작 `manual`의 NULL 764행도 각각 독립이다.
이것이 D-105의 「키가 없으면 혼자 한 무리」를 현재 데이터에 적용한 결과다.

## 4. D-20 적용 결과

기준일 창 안에는 시험지 3장, 서로 다른 최근 `problem_id` 8개가 있었다. 그러나
**갈래 수가 감소한 소단원은 0곳**이다. 최근에 쓴 아류를 빼도 같은 가족의 다른 아류가
남아 있기 때문이다.

따라서 이번 규칙의 분모는 다음처럼 읽어야 한다.

- D-20 전: 시험지 한 장에서 쓸 수 있는 최대 수 = distinct 가족 수
- D-20 뒤: 최근 문항 ID를 뺀 뒤 남은 distinct 가족 수
- 2026-08-26 실측에서는 735곳 전부 두 값이 같다.

이 결과는 D-20을 가족 단위로 넓히라는 뜻이 아니다. 이번 지시는 **한 시험지 안** 중복
금지이고, 최근 14일은 기존처럼 정확한 `problem_id`만 제외한다.

## 6. 이 조사가 못 보는 것

1. **키가 수학적으로 맞게 붙었는지**는 못 본다. 서로 다른 류가 같은 키를 받았거나 같은 류가
   다른 키를 받은 오분류는 distinct 집계만으로 드러나지 않는다.
2. **난이도 배분을 만족하는 매칭 가능성**은 못 본다. 가족 하나가 여러 난이도에 걸치면 앞 난이도의
   선택이 뒤 난이도의 유일 가족을 막을 수 있다. 8갈래가 있어도 요청 배분으로는 8개를 못 고를 수 있다.
3. **지면·`problemType`·문항 형식의 질**은 못 본다. 이 표는 출제 자격과 가족 수만 센다.
4. **0갈래 583곳의 원인**은 한 숫자로 못 가른다. 엔진 미구축, 미적재, 검수 대기, 격리 중 무엇인지
   소단원별 생성기·잠금 원장을 따로 대조해야 한다.
5. **미래의 D-20 감소**는 못 보장한다. 이번 창에서는 감소 0이지만 시험 이력이 쌓이면 어떤 가족의
   마지막 아류까지 최근 제외될 수 있다.
6. **예측 문제지의 청사진 충족**은 별개다. 예측 출제는 단원·난이도·문항 형식 슬롯을 맞추므로
   같은 가족 금지 뒤 결손이 나는지는 별도 시뮬레이션이 필요하다.

## 7. 원장님께 여쭐 것

1. 확충 목록을 **현재 엔진이 닿는 152곳**부터 처리할지, 0갈래인 **583곳의 신규 엔진 구축**도
   같은 우선순위에 넣을지. 같은 표에 넣으면 0갈래 583곳이 언제나 맨 앞을 차지한다.
2. 기존 엔진 확충은 수치대로 **중2 부족 6·5인 네 소단원부터** 시작할지, 아니면 원장님이
   실제로 보신 초6을 포함해 **초5·초6 112곳에 각 4갈래씩** 먼저 늘릴지.
3. 초등 새 가족 키는 현재의 `elem:<학년>|<소단원>|<난이도>` 뒤에 별도 유형 정체를 붙이는
   방식으로 확장할지. 난이도만 키로 유지한 채 산출물 수만 늘리면 갈래 수는 영원히 4다.
