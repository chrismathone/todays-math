## 2. 만들 것

### 2.1 학생 앱 «오늘의 기억» — 이번 일의 본체

주소는 **`/learn/fading`** 과 그 아래(`/learn/fading/**`) — 관문 허용 목록에는 리드가 이미 적었다(아래 주소는 codex 가 정한다 · 한 장에서 탭으로 돌려도 되고 주소를 나눠도 된다).
서버 문 `MATH_FADING` 이 꺼져 있으면(기본) **화면도 404** 여야 한다 — 페이지의 서버 컴포넌트에서 `fadingEnabled()`(`@/lib/fading/enabled`)를 보고 `notFound()`. 학생 세션 확인은 `src/app/learn/math-explorers/page.tsx` 와 같은 방식.

탭 넷(정본 §2 · §13 D3) — **오늘의 복습 · 개념 소거 · 개념 목록 · 학습 통계**(폰 아래 탭의 표시 이름은 «복습 · 소거 · 목록 · 통계»). 풀이 중에는 탐색을 접는다.
강의 · 영어듣기로 가는 길은 홈의 이동 카드와 위쪽 «학습 전환»이다(D3). 지금 `/learn` 전체에 뜨는 `StudentMobileNav` 와 이 앱의 아래 탭이 겹치지 않게 한다.

화면 — 시안에 있는 것과, 시안에 없어 우리가 맞추는 것(정본 §8 «받지 않아도 되는 것»):

| 화면                                                                                           | 읽는 것                                                                                                 |
| ---------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| 홈(오늘의 복습) — 첫날 · 평소 · 오늘 다 끝냄 · 오래 쉬고 돌아옴 · 밀림(«나눠서» / «오늘 전부») | `state()` 의 `summary`(`plan` · `queue` · `streak` · `stepCounts` · `todayCount` · `mode`) · `concepts` |
| 풀이 1단계 정독                                                                                | `opened.concept` · `session`                                                                            |
| 풀이 2 ~ 4단계(빈칸 + 칩)                                                                      | `erasedTargets` · `chipTray` · `session.ts`                                                             |
| 틀렸을 때 · «아직 모르겠어요» · 단계 뒤의 대조(기준안)                                         | `FadingStepResult` · 개념의 문장                                                                        |
| 자가 평가(4단계 뒤 한 번) · 다음 복습일 한 줄                                                  | `session.ratings`(평가와 «N일 뒤») · 응답의 `receipt`                                                   |
| 풀이 끝 요약 · 나가기 확인                                                                     | 세는 값만(정본 §3)                                                                                      |
| 개념 목록(학년 → 단원 → 개념) · 단원 상세 · 개념 하나 읽기 · 복습일 전의 연습                  | `catalog(grade)` · `concept(id)`                                                                        |
| 학습 통계 — 기록 없음 포함                                                                     | `summary` · `days`(여덟 주)                                                                             |
| 불러오는 중 · 저장 실패 · 연결 끊김 · 409 뒤의 맞추기                                          | `FadingSourceError`                                                                                     |

싣지 않는 것은 정본 §5 표 전부다(순위 · EXP · 공유 · AI 처방 · 진단 테스트 · 배점 · 마스코트 · 북마크 · 음성 · 평가 직후 전면 화면 …). **«기억 보존율» 한 값도 싣지 않는다**(§3 · D7) — 시안의 큰 고리 자리에는 오늘의 복습(한 것 / 할 것)을 둔다.
오개념 클리닉 · 눈풀이 챌린지는 **이번 범위가 아니다**(재료의 검증이 안 끝났다 — 함정 칩은 재 봤고 기준을 못 넘었다 · 정본 §16.3). 자리를 비워 두지도 말고 «준비 중»도 적지 않는다.

### 2.2 서버 없이 도는 측정용 화면 — `/dev/fading`(또는 codex 가 정한 `/dev/…`)

**정본 §11-8 이 처음 볼 것으로 못 박은 것** — 은행의 실제 문장으로 320 · 390 폭에서 «무엇을 가리고, 첫 시도를 어떻게 가리는지». 풀이 2 ~ 4단계부터 세우고 거기서 잰다.

## 3. 속을 쓰는 법 — 규칙을 다시 짓지 않는다

- 화면은 **`FadingSource`**(`src/lib/fading/source.ts`) 넷만 안다 — `state()` · `act(action)` · `catalog(grade?)` · `concept(id)`.
  학생 API 를 부르는 구현은 codex 가 화면 쪽에 짓는다(`src/components/learn/learnApi.ts` 의 관례 — 계약 스키마로 응답을 확인 · 서버 문구 그대로 · 연결 끊김 문구 하나). 실패는 **`FadingSourceError`** 로 던진다(로컬 구현과 같은 꼴이라 화면이 한 벌로 받는다).
- 풀이 중의 채점은 그 자리에서 `session.ts` 로 한다 — `startFadingSession` · `finishReading` · `placeChip` · `giveUpStep` · `allowedRatings` · `closeWithRating`. 칩은 `chipTray(개념, 단계, { seed, traps })`, 빈칸은 `erasedTargets(개념, 단계)`.
- 서버에 보내는 것은 넷이다(정본 §13.2 «흐름») — `open` → (1단계) `read` → 단계를 다 채우면 `step`(넣은 차례 **전부** · 틀린 것까지 · «아직 모르겠어요»는 `gaveUp`) → 4단계에서 틀리면 **그 자리에서** `miss` → `rate`(요청 번호는 `newFadingId()`).
  다시 들어오면 `state()` 한 번으로 이어 간다(풀이가 열려 있으면 `opened` 가 같이 온다 · 칩 자리는 씨앗이 같아 그대로다).
- 🔴 칩에는 «어느 빈칸의 것인지 · 함정인지»가 **없다**(id 는 놓인 자리 `c1` … 일 뿐). 화면이 그것을 알아내 표시하지 않는다 — 고르기 전에는 모든 칩이 똑같이 보인다(§6). DOM 의 속성 · 클래스 · 차례에도 흘리지 않는다.
- 🔴 **빈칸을 채우는 화면(2 ~ 4단계)에는 열린 개념의 명제 용어(`term`)를 어디에도 그리지 않는다** — 명제 옆 · 머리 · 진행 표시 · `aria-label` · `title` 다 포함(2026-10-06 codex 가 짚었다).
  재 보니 명제 9,119 가운데 1,034(11.3% · 정의 갈래는 39%)가 제 용어에 제 빈칸의 답을 품고 있다(«접선» → «…그 원의 {접선}이라 한다»). 그런 명제가 하나라도 있는 개념이 2,040 가운데 669다.
  풀이 머리의 개념 이름은 **소단원 이름 + 난이도 + 몇째/모두 몇**(`section` 의 셋째 토막 · `level` · `ordinal`/`siblings`)이다. 용어를 그려도 되는 곳은 1단계 정독 · 단계를 마친 뒤의 대조 · 풀이 밖의 목록(홈 대기열 · 개념 목록 · 통계)이다.
- 홈의 «오래 쉬고 돌아옴»은 `summary.longBreak` 로 가른다(`summary.idleDays` 는 문구에만 · `summary.lastOn` 은 마지막으로 평가를 닫은 날). 화면이 날 수로 문턱을 다시 짓지 않는다 — 교사 현황의 «오래 쉼»과 같은 값이다.
- 🔴 틀리게 넣은 빈칸은 다시 맞혀도 «틀림»으로 남는다(§4-6). 기준안은 **단계를 마친 뒤에만** 열린다(D5). 4단계에서 하나라도 틀리면 평가는 «다시»뿐이다(`session.ratings` 가 그렇게 온다 — 화면이 따로 판단하지 않는다).
- 숫자는 받은 값을 그대로 싣는다. 퍼센트는 `toPercent` 하나로만 반올림한다. 망각 위험에는 **추정**임을 밝힌다. `passed` 는 정답률이 아니다(«다시»가 아닌 평가의 수). «배운 개념»은 첫 평가를 마친 수다 — «다 외웠다 · 마스터»로 읽히는 말을 쓰지 않는다.
- 날짜는 서버가 준 `today` 로만 센다(화면의 시계로 «오늘»을 짓지 않는다). 시각(«07:00 · 14시간 뒤»)은 싣지 않는다 — 날 단위다.
- 수식은 우리 KaTeX 길로 그린다(`src/components/math-explorers/ExplorerMath.tsx` 가 학생 화면의 전례 — 표적의 `tier` 가 `math` 인 것과 문장 속 `$…$`).
- 개념 · 단원의 이름은 받은 값에서 온다(`section` 은 «학년::대단원::소단원» · `terms` 는 명제의 용어).

**속에 없는 값이 필요하거나 꼴이 불편하면** `src/lib/fading/**` · `src/contracts/**` 를 고치지 말고 리드에게 묻는다(오르카 `ask` — 리드가 같은 워크트리에서 바로 고친다). 화면에서 규칙을 흉내 내어 메우지 않는다.

## 4. 겉모습 — codex 가 정하되 지킬 것

- v2 의 느낌은 **이 앱 범위에만** 건다(CSS 모듈 · 이 앱의 뿌리 요소 아래 변수). 전역 토큰 · `globals.css` · 다른 화면을 바꾸지 않는다(10월 4일 «아틀리에»를 탐험 범위에만 건 방식 — `src/components/math-explorers/explorer-home-atelier.module.css`).
  v2 를 제품 전체로 넓힐지는 **미확정**이라 `05-design-system.md` 는 이번에 고치지 않는다 — 정한 값과 까닭은 보고서에 적는다.
- 외부 요청 0 — 글꼴 · 아이콘 · 그림을 CDN 에서 받지 않는다. 아이콘 글꼴을 들이지 않는다(필요한 그림은 SVG 로). 새 의존물을 설치하지 않는다.
- 문구는 한글 · 간결(`D-08`) — 느낌표 · 이모지 없음. 영어 라벨은 «STEP 01» 꼴의 단계 표지만(§2).
- 누르는 것은 44px 이상 · 글자는 12px 이상 · 320 폭에서 가로 넘침 0 · 768 ~ 1279 폭의 모양도 정한다(시안에 없다 — §6).
- 마우스 어포던스(`D-30`) — 손가락 커서 · hover 배경은 실제로 누르는 컨트롤에만. `<div onClick>` 금지. `npm run lint:affordance` 가 본다.
- 키보드와 화면 낭독기로 칩을 넣을 수 있어야 한다(칩 → 빈칸을 끌기만으로 만들지 않는다 — 누르기로 된다).

- `prisma/**` · `.env*` · `package.json` · `package-lock.json` · `docs/planning/05-design-system.md` · `CLAUDE.md` · `AGENTS.md`.

**하지 않는 것** 🔴

- git 으로 쓰는 일 전부 — `commit` · `stash` · `checkout` · `reset` · `restore` · `clean` · `merge` · `push`. 이 워크트리의 변경은 **전부 미커밋**이다(리드의 속 전체가 그렇다). 되돌릴 자리가 없으니 파일을 지우거나 덮기 전에 본다.
- **DB 에 붙지 않는다.** main 의 `.env` 를 가져오지 않는다. `MATH_FADING=on` 으로 실제 학생 라우트를 돌리지 않는다 — 공유 DB 의 학생 기록에 새 칸이 생기면 운영의 지금 배포판이 그 학생의 기록을 못 읽는다(정본 §13.2 «배포와 되돌림»). 화면은 2.2 의 로컬 길로만 띄운다.
- 개발 서버는 **리드가 포트 3443 에 띄운 것 하나**를 같이 쓴다(2026-10-06 고침 — 한 워크트리에 `next dev` 는 하나만 뜬다 · `.next/dev/lock`). 따로 띄우거나 끄지 않는다 — 원장님이 그 주소로 화면을 보신다.
  꺼져 있으면 리드에게 알린다. 다른 세션의 node 를 죽이지 않는다.
- 전체 시험(`npm test`)을 돌리지 않는다(다중 세션에서 워커가 굶는다 · 리드가 병합 뒤 한 번 돈다). 자기 시험 파일만 `npx vitest run <파일>` 로. 변이 실험기(`scripts/qa/fading-mutants/run.ts`)를 돌리지 않는다.
- 창을 띄우는 자동화를 돌리지 않는다 — 브라우저는 **헤드리스**로만(원장님 화면의 포커스를 뺏지 않는다 · `CLAUDE.md` 절대 규칙 9).

## 6. 다 됐다는 기준

1. `npx tsc --noEmit`(힙 8GB — `NODE_OPTIONS=--max-old-space-size=8192`) 0건 · 자기 파일에 `npx eslint` 0건 · `npm run lint:affordance` 통과.
2. 시험(TDD — 규칙마다 빨강을 먼저 본다) — 로컬 길(`createLocalFadingSource`)로 화면을 돌려:
   - 틀린 칩을 넣으면 그 자리에서 알리고, 다시 맞혀도 그 빈칸은 틀림으로 남는다 · 4단계에서 틀리면 `miss` 가 **그 자리에서** 나가고 평가는 «다시»뿐이다
   - «아직 모르겠어요» · 기준안은 단계를 마친 뒤에만 보인다(마치기 전에는 DOM 에도 답이 없다 — 빈칸의 답 · 칩의 정오 표지)
   - 중간에 나갔다 들어오면 같은 단계 · 같은 칩 자리로 이어진다 · 409 를 받으면 상태를 다시 읽어 맞춘다 · 평가 요청이 두 번 나가도 한 번만 반영된다
   - 복습일 전의 풀이는 연습이다(아무것도 보내지 않는다) · 첫날 / 다 끝냄 / 밀림의 홈
   - 서버 문이 꺼져 있으면 페이지가 404
3. 측정(헤드리스 · `/dev/fading` · 2.2 의 계산으로 뽑은 표본 **전부**) — 320 · 390 · 768 · 1280 폭에서 가로 넘침 0 · 44px 미만 컨트롤 0 · 12px 미만 글자 0 · 수식 잘림 0(잉크로 잰다) · 풀이 단추가 화면 밖에 가려지지 않는다(`elementFromPoint`). 글꼴을 먼저 싣고 잰다.
   숫자와 캡처는 `.qa-artifacts/fading-screens/`(추적하지 않는다)에, 요약은 보고서에.
4. 보고서 **`docs/planning/tracks/reports/fading-screens-codex.md`** — 만든 화면과 주소 · 정한 겉모습(값과 까닭 · 시안과 달리 한 곳) · 잰 숫자 · 못 한 것 · 원장님이 정하실 것 · 리드에게 바라는 것(속의 빈틈) · Wire 의 추천안.
   🔴 «했다 · 통과»는 돌려 본 것만 적는다. 못 잰 것은 «못 잼»으로 적는다.

## 7. 차례와 물음

차례는 2.2 의 뼈대(로컬 길로 풀이 2 ~ 4단계) → 2.1 의 나머지 화면 → 학생 API 구현과 페이지 → 2.3 → 2.4 다. 중간에 끊기더라도 앞의 것이 온전히 서 있게 한다.

막히면 멈춰 있지 말고 리드에게 묻는다. 원장님만 정하실 수 있는 것(겉모습의 범위 · 이름 · 원칙을 뒤집는 것)은 추천을 적고 «확인 대기»로 둔 채 나머지를 간다.
