# 시험지 만들기 H2 — 실사용 다듬기 (원장님 2026-10-20, 운영 스크린샷 다섯 장)

## 1. 공간 활용 · 좌우 따로 스크롤 (1단계 · 2단계 모두)
원장님: «공간 활용하지도 못하고 잘린다» · «좌우 스크롤 차이가 너무 심함» · «2단계도 공간활용 최대화, 좌측 우측 별도 스크롤».
- 넓은 화면(컨테이너 ≥ 900px 정도)에서 1단계 `.sequenceLayout` 과 2단계 `.reviewLayout` 의 **두 열이 각각 자기 스크롤**을 갖는다: 각 열 `position: sticky; top: <위 띠 아래>`, `max-height: calc(100dvh - <띠 높이와 여백>)`, `overflow: auto`, `overscroll-behavior: contain`. 띠 높이는 `--workspace-sticky-inset` 과 단계 띠 실측으로 — 열의 위 끝이 단계 띠 밑에 가려지지 않게(지금 제목 칸 · «저장한 조건» 단추가 띠 밑으로 잘려 보인다 — 같이 고친다).
- 좁은 화면 · 폰은 지금처럼 한 줄로 쌓고 페이지 스크롤 하나.
- 2단계 비율도 넓게: 오른쪽 문항 열이 남는 폭을 쓴다.
- 1단계 오른쪽 «출제 범위» 목록의 범위 한 개가 4줄(학년·단원 / 차시 / 출제 가능 / 문항 수 칸 + 고정 + 빼기)이라 오른쪽만 길어진다 → 넓은 화면에서 **한 범위 = 두 줄**로 압축: 1줄 «차시 이름 · 출제 가능 N갈래», 2줄 «학년·단원(작게) … [문항 수] [고정] [빼기]». 문구는 그대로.

## 2. 마지막 단계(차시) 불러오기가 매우 느림
리드 실측: 서버 `view=scope-counts`(초3 평면도형 5차시) 0.27~0.38초, `recent=1` 0.38~0.53초 — 서버는 범인이 아니다.
의심(코드로 확인하고 고칠 것): `ExamBuilder.tsx` 의 `loaded` 가 `demandIds`(지금 보이는 · 고른 차시 id) 에 묶여 있어, 차시 단계에 들어가거나 **체크할 때마다** `loaded` 가 비고 `scopeLoading` → `ScopeSequencePicker` 의 `pending` 이 참이 되어 **차시 목록 전체가 «불러오는 중»으로 바뀌고 수가 올 때까지 안 보인다**. 고칠 방향:
- 차시 이름 목록(`navigation.lessons`)이 오면 **바로 그린다**. «출제 가능 N갈래»만 수가 올 때 채운다(그 칸만 기존 불러오는 중 표시 — 새 문구 만들지 않음).
- 이전에 받은 수는 새 요청 중에도 유지(깜빡임 없음). 이미 받은 차시만 다시 묻지 않게 — 필요한 id 만 요청.
- 체크 · 해제가 목록 전체를 다시 불러오게 하지 않는다.
- 브라우저 시험으로 «차시 단계 진입 → 목록이 수 응답 전에 보인다» · «체크해도 목록이 pending 으로 안 바뀐다»를 잠근다. 요청 수도 센다(진입 1회, 체크마다 0회 또는 새 id 만).

## 3. 단추 자리 정리 (원장님 «너무 제각각 위치»)
2단계 오른쪽 머리: «정답·해설 보기» · «되돌리기»는 글자 링크처럼, «+ 문항 추가»는 테두리 단추로 각각 다른 줄 · 다른 정렬. 규칙 하나로:
- 패널 머리의 동작은 **오른쪽 한 줄**, 모두 같은 보조 단추 모양(테두리 · 같은 높이 44px), 순서 [정답·해설 보기] [되돌리기] [+ 문항 추가]. 제목 · 개수 · 요약은 왼쪽.
- 범위 머리의 «+ 이 범위에 추가», 문항 줄의 [형식 변경] [교체] [삭제] [↑] [↓]도 같은 오른쪽 정렬 · 같은 높이. 형식 변경 옆 «객관식 · 단답형» 같은 설명 글은 단추 줄 밖(위 메타 줄)로.
- 1단계 오른쪽 · 2단계 왼쪽의 [이전] [다음] 은 지금처럼 맨 아래 같은 폭.
- 색 · 문구는 바꾸지 않는다(D-08). D-30 어포던스.

## 4. (추가) 문항과 문항 사이 여백
원장님: «문항과 문항 사이에 약간의 여백 둘 것. 문항 구분하기 위함.» 2단계 문항 목록에서 한 문항(머리 · 본문 · 보기 · 정답·해설 · 단추 줄)이 끝나고 다음 문항이 시작하기 전에 여백(약 16~24px)과 구분이 보이게. 범위 머리 줄(«1-2-3 … 1문항 · + 이 범위에 추가»)과 문항 사이도 같은 규칙. 새 색 · 장식 없이 기존 선 · 토큰으로.

## 5. (추가) 단추를 누르면 테두리가 넘쳐 보임
원장님 스크린샷: «정답·해설 보기»를 마우스로 누르자 두껍고 둥근 파란 초점 테두리가 단추 밖으로 크게 번져 옆 · 아래 단추와 겹친다. 고칠 것:
- 마우스 클릭에는 초점 테두리를 보이지 않게(`:focus:not(:focus-visible)` 에서 outline 없음), 키보드 초점(`:focus-visible`)에만 보인다(접근성 유지).
- 키보드 초점 테두리도 단추 모양을 따라 2px · `outline-offset: 2px` 이내, 이웃과 겹치지 않게. 이 화면(ExamBuilder · 대화창)의 단추 · 링크 단추 전부 같은 규칙. 전역 스타일이 원인이면 이 화면 범위에서만 덮는다.
- 시험: 클릭 후 outline 없음 / 키보드 Tab 후 outline 있음(계산된 스타일로).

## 6. (추가) 단계 이동 단추 맞추기
