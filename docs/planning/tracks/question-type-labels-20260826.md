## 2. 할 일 ⑴ — `[서]` 를 `[단]` 과 `[서]` 로 가르기 (구현 완료)

### 2.1 원장님이 찾으신 결함 확인 및 검증
원장님이 지목하신 4개 문항:
- `J30101-A02-002` (`questionType = "단답형"`, `choices = 0`)
- `J30101-A05-002` (`questionType = "단답형"`, `choices = 0`)
- `J30101-A06-002` (`questionType = "단답형"`, `choices = 0`)
- `J30101-A07-002` (`questionType = "단답형"`, `choices = 0`)

이전 코드에서는 보기가 없는 모든 주관식을 일괄 `written` (`[서]`)으로 처리하여 `[서]`로 표시되던 결함이 있었으며, 변경 후 **4문항 모두 정확하게 `[단]` (단답형)으로 분류**됨을 단위 테스트(`src/__tests__/unit/problemProvenance.test.ts`) 및 실데이터 검증으로 확인했습니다.

### 2.2 판정 로직 (`src/lib/problem/provenance.ts:classifyFormat`)
```ts
export function classifyFormat(problem: ProvenanceInput): ProblemFormat {
  const choices = parseProblemContent(problem.content).choices.length;
  const answerHasChoiceNumber = ANSWER_CHOICE_NUMBER.test(problem.answer);

  // 1. 객관식: 지면 파서 기준 보기가 2개 이상이고 정답이 보기 번호인 경우
  if (choices >= 2 && answerHasChoiceNumber) return "multiple_choice";

  // 2. 주관식: 보기가 없고 정답이 번호가 아닌 경우
  if (choices === 0 && !answerHasChoiceNumber) {
    if (problem.questionType === "단답형") return "short_answer";
    if (problem.questionType === "서술형") return "descriptive";
    // 엔진 생성 문항(elem:, mid:)은 단답형 생성기임
    const family = problem.familyKey ?? "";
    if (family.startsWith("elem:") || family.startsWith("mid:")) {
      return "short_answer";
    }
    // questionType 미기록 상태에서 problemType이 서술형인 경우
    if (!problem.questionType && problem.problemType === "서술형") {
      return "descriptive";
    }
    // RPM 등 questionType 미기록 주관식은 뭉개지 않고 미분류로 표출
    return "unknown";
  }

  return "unknown";
}
```

## 3. 할 일 ⑵ — `[중]` 이 무엇인가 (조사 및 시안)

### 3.1 원인 분석
- **그리는 자리**: `src/lib/problem/provenance.ts` 내 `ORIGIN_BADGE.middle_engine`
  ```ts
  middle_engine: { text: "[중]", name: "중등 엔진 생성", className: "text-src-middle" }
  ```
- **값의 원천**: 문항의 `familyKey`에 `mid:` 접두사가 붙은 **중등 생성 엔진 산출물** (662건).
- **왜 난이도로 읽혔는가?**:
  1. 화면 배치: `Q J30101-A05-002 [중] [단]  응용 활용 승인` 에서 코드 바로 오른쪽에 대괄호 라벨이 위치하고, 바로 옆 오른편에 난이도 칩(`기본`·`응용`)이 붙어 있음.
  2. 일반적인 학원 환경의 `[상] [중] [하]` 난이도 표기 관행과 맞물려 `[중]`을 난이도 '중'으로 직관적 오인.
  3. 실제 오늘의수학 난이도 사다리는 **`연산 < 기본 < 응용 < 심화`** 4단계(D-106)뿐이므로 난이도 체계에 '중'은 존재하지 않음.

## 4. 할 일 ⑶ — 축이 겹치는지 실측 조사 (`problemType` vs `questionType`)

### 4.1 문제 정의
`src/contracts/problem.contract.ts`에서 `problemType`의 허용 값은 `['계산', '개념', '활용', '서술형']`입니다.  
동시에 출제 형식 축인 `questionType`과 형식 라벨(`[서]`)도 '서술형'을 표현하고 있어 **두 축이 같은 '서술형'이라는 단어를 중복 사용**하고 있습니다.

### 4.2 전수 실측 교차표 (47,787건)

| `problem_type` | `question_type: 객관식` | `question_type: 단답형` | `question_type: 서술형` | `question_type: null` | `problem_type` 합계 |
|---|---|---|---|---|---|
| **`개념`** | 31,537 | 441 | 32 | 4,423 | **36,433** |
| **`서술형`** | 0 | **278** | **7,728** | 29 | **8,035** |
| **`활용`** | 0 | 1,397 | 0 | 296 | **1,693** |
| **`계산`** | 0 | 1,030 | 30 | 566 | **1,626** |

### 4.3 분석 결과
1. **일치율**: `problem_type='서술형'`(8,035건) 중 96.2%(7,728건)가 `question_type='서술형'`과 일치합니다.
2. **어긋난 자리 (338건)**:
   - `problem_type='서술형'`인데 `question_type='단답형'`인 **278건**:
     - 예: `HAL0210-QTTJ` ("과정을 서술하고 답을 쓰시오" 발문이나 question_type이 단답형으로 오기된 경우 등)
   - `problem_type='개념'`/`'계산'`인데 `question_type='서술형'`인 **62건**:
     - 예: `J30503-U7C4` (삼각비 계산 문제이나 "풀이 과정을 상세히 쓸 것"으로 출제된 서술형 문항)
3. **축의 본질적 의미 충돌**:
   - `problemType`: 문제의 해결 방식/사고 유형 (`계산`, `개념`, `활용` 등 내용적 유형)
   - `questionType`: 시험지 지면 및 답안 제출 형식 (`객관식`, `단답형`, `서술형` 등 외형적 형식)
   - `problemType`에 '서술형'이 포함되어 있어 유형 축과 형식 축이 교차 오염되고 있습니다.

## 5. 이 조사가 못 보는 것 (한계와 사각지대)

1. **`question_type` 컬럼이 NULL인 5,314건의 실물 분류**:
   - RPM 교재 이관본 3,526건(주관식 1,992건)과 옛 수동 764건은 DB 적재 당시 `question_type`이 기록되지 않았습니다.
   - 현재 판정기는 이를 안전하게 `unknown`(`[?형식]`)으로 분류하지만, 실물 문항은 대부분 단답형 계산 문제에 해당하므로 추후 메타데이터 보강(백필)이 필요합니다.
2. **수식 파서의 그림 선택지 인식 한계**:
   - 선택지가 텍스트 원문자가 아니라 그림 파일로만 구성된 문항(111건)은 본문 파서가 보기를 세지 못해 `[?형식]`으로 분류됩니다.
3. **`BIGSHOL/problem-type-criteria` 워크트리와의 연계**:
   - `problemType`의 기준 개정 작업이 별도 워크트리에서 진행 중이므로, `problemType`의 값 체계 변경은 해당 트랙과 협의 후 일괄 적용되어야 합니다.
