# 서술형 엔진 1단계 — «주 저자 + 보조 엔진» 구조 · 계약 · 문지기 · 첫 묶음 (원장님 2026-10-20)

정본 계획: `docs/planning/descriptive-engine-middle-20261020.md`(맨 아래 «3자 검토와 합의안»). 원장님 결정 · 지시(2026-10-20, 이 순서로):
1. **학교 시험 연습용 엔진이다 — 그래서 기출을 보라고 한 것.** 문항은 학교 서술형처럼 보여야 한다(물음 꼴 · 난도 · 소문항 구조 · 배점 4~12점 · 부분점수). 기출 원문 · 수치 · 그림은 쓰지 않고, 기출 묶음(칸)에서 «무엇을 · 어떤 꼴로 묻는가»를 뽑아 새로 짓는다.
2. **서술형 엔진이 메인, 도형 엔진 등 나머지 엔진은 보조 팀원 — 같이 문제 하나를 만든다.** 서술형 엔진(주 저자)이 평가 목표 · 상황 · 요구 · 발문 · 소문항 · 채점표를 쓰고, 보조 엔진에게 일을 맡긴다: 중등 계산 엔진(`src/lib/middle/` — 수치 생성 · facts · 정답), 도형 엔진(그림 — `docs/planning/09-figure-engine-guide.md` · 기존 FigureSpec/SVG 경로), 그래프 · 표 등 기존 생성기. 보조 엔진의 출력은 주 저자의 요구에 맞춰 조립되고, 독립 검산은 조립된 최종 문항(인쇄될 발문 · 그림)을 읽는다.
3. **겨울 선행부터** — 2027 년 1학기 단원(중1-1 · 중2-1 · 중3-1). 2027 중3 은 2022 개정 첫 적용 → 칸마다 교육과정 · 성취기준.
4. **일일 · 확인 시험지에도 싣고, 배점은 서술형에만**(D-28 의 예외 — 07 Decision Log 에 마지막 D 번호 다음 번호로 기록하고 보고).

## 할 일 (TDD)
1. **구조**: 주 저자 인터페이스(평가 목표 · 요구 ID · 상황 · 발문 조립 · 소문항 · 채점표)와 보조 엔진 어댑터(계산 · 도형 · 그래프)의 계약. 한 문항 = 주 저자 1 + 보조 0~n. 보조가 실패하면 그 문항은 만들지 않는다(조용히 다른 것으로 채우지 않음).
2. **문지기 G1~G6**: 앞서 이 작업트리에 만든 `src/lib/engine/nativeDescriptiveGates.ts` · `descriptiveVerification/` · 시험을 **살려서** 새 구조에 맞춘다(계획 문서 합의 3번 정의). G3 독립 검산은 조립된 최종 발문 · 그림만 읽는다.
3. **기출 칸 → 요구**: 첫 묶음 대상 칸(중1-1 · 중2-1 · 중3-1)의 기출 서술형에서 물음 꼴 · 소문항 구조 · 배점 분포를 뽑아 «학교 서술형 요구» 표로(원문 금지 — 꼴 · 수만). 기존 examStudy 요구 ID 와 대응, 없으면 새 요구 후보.
4. **세로 한 줄 시연**: 정의 1개를 끝까지 — 주 저자 + 계산 엔진 + (가능하면) 도형 엔진이 함께 만든 문항 하나, 문지기 전부 통과, 학생용 · 교사용 렌더 시험. 등록 · 적재는 하지 않는다.
5. **첫 묶음 후보 10개 표**: 칸 · 평가 목표 · 학생이 쓸 증거 · 단답 쌍둥이와 다른 요구 · 보조 엔진(어떤 유형 id · 그림) · 예상 총점.
