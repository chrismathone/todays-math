| 검수 | 새 정답/해설의 풀이·독립 검산·교육과정 검토, 도형 검수, 권리/유사성 검토 상태, 보류 사유 |

기출 참고 정보를 가진 **변형 문항**으로 관리한다. 쌍둥이에 원래 기출과 같은 `externalId`/`problemCode`를 부여하거나 실제 학교의 원문 기출이라고 표시하지 않는다. 기존 `Problem.source=transformed` 등 출처·origin 계약을 확인해 맞추고, 원문이 DB에 없으면 없는 `originProblemId`를 지어내지 않는다. 기존 계약에 없는 추적/검수 값은 별도 검수 원장에 보존하고 필요 확장을 명시한다.

현재 지원되는 단원/학년 범위·난이도·유형/형식·출처·검수상태·그림/답/해설 유무·키워드 필터와 실제 저장값을 대조한다. 새 검색 축이 필요하면 UI→계약→조회→저장까지 연결 계획을 세운다. 이번 준비 단계만으로 모든 새 검색 축이 이미 구현됐다고 보고하지 않는다.

## 현재 코드와 새 요구의 차이

`--regenerate-all`은 모든 답·해설의 독립 검산을 지원하지만, **쌍둥이 본문 변형·모든 도형 재생성·메타데이터 전수 검수의 전체 파이프라인은 아니다.** 현재 `load-exam-paper.ts`는 `source: "past_exam"`, `figureSvg: null`, 원본 그림의 `figureSource: "source"`를 설정한다. 그대로 실행하면 최종 요구와 다르다.

재개 작업자는 `src/lib/ai/transformer.ts`, `src/lib/ai/prompts/transform.ts`, `src/lib/dev-ai/figure-engine.ts`, `src/lib/figure/renderFigureSpec.ts`와 기존 검수·출처 계약을 먼저 확인하고 재사용할 부분을 분리한다. 기존 원문 적재 경로를 조용히 바꾸거나 다른 트랙을 깨지 않는다. 새 쌍둥이 저장/드라이런 경로와 변형물·원문 증거의 데이터 관계를 명시해야 한다.

AI 분류·검수·라우팅의 통합을 설계하거나 변경할 때는 `.agents/skills/typesafe-ai/SKILL.md`와 관련 live TypeSafe 문서를 읽고 프로젝트 클라이언트를 유지한다. 계산·해시·배열 길이·ID 관계는 코드가 검증하고, 의미 판정은 별도 근거와 불명 상태를 남긴다. AI typed 출력이나 높은 confidence 자체를 수학적 정답·권리 허가로 간주하지 않는다. 유료 호출이나 새 연동은 이번 세팅 완료 증거에 포함하지 않는다.

## 추출 후의 문제 생성 엔진 업그레이드

사용자 추가 지시: «기출문제 추출이 끝나면 추출한 기출문제들을 바탕으로 우리 문제 생성 엔진을 업그레이드 할 수 있는 부분은 업그레이드 시킬 것».

추출 때부터 각 문항에 교육과정·개념·핵심 풀이 절차·문제 구성·난이도 근거·도형 요구를 기록해 엔진과 대조할 근거를 준비한다. 대상 원본의 추출·문항 경계·수식·그림·출처 검수가 마무리되면 엔진 개선 단계에 들어간다. 보류/불가 자료는 사유를 남겨 빠진 범위가 보이게 하며, 추출하지 않은 자료까지 전량 분석 완료로 세지 않는다.

| 개선 후보 | 실행할 일 |
|---|---|
| 유형/개념 커버리지 | 현행 Unit/live family와 대조해 미지원·빈약한 유형을 찾고, 필요한 생성 규칙을 추가/확장 |
| 조건/숫자 구성 | 쌍둥이에서 확인한 제약을 규칙화해 조건 모순·답 없음·답 여러 개·보기 중복을 막음 |
| 풀이 품질 | 교육과정에 맞는 설명·경우 구분·단위·수식 표기와 정답 계산을 개선 |
| 도형 | 반복되는 작도를 재사용 가능한 kind/spec/엔진 기능으로 확장하고 조건과 그림의 관계를 검증 |
| 메타데이터 | 생성 시 실제 단원·유형·난이도·그림/형식 정보를 일관되게 부여하고 필터/검색의 누락을 수정 |
| 이미지 포함 문제 | imagegen으로 제작·검수한 이미지 자산과 수학 조건/정답/풀이/메타데이터를 연결해 새 이미지 문항의 생성 지원을 추가 |
| 생성/검수 안정성 | 실제 분석으로 드러난 보기 품질·표기·재현성·보류/실패 분류·중복 생성·검수 누락을 개선 |

**이미지 생성 스킬을 활용한 문제 생성 엔진 업데이트가 주요 과제**다. 기존 도형 스펙→SVG 경로를 버리지 않고, 그 경로로 재현하기 어려운 이미지 문항의 지원을 보완한다. 이번 코드 검색에서 수학 생성 엔진 안의 내장 imagegen 호출 경로는 확인하지 못했다. 기존 가이드에는 이미지 도구로 원본 보정하는 설명이 있고 탐험 화면에는 과거 생성 이미지 자산이 있으므로 «프로젝트 어디에도 이미지 생성 활용이 없다»고 확대하지 않는다.

스킬은 Codex 제작 과정에서 내장 이미지 도구를 사용한다. 운영 앱에서 스킬을 직접 호출할 수 있다고 가정하지 않는다. 개발·제작 단계에서 만든 자산/템플릿을 엔진의 입력·조건·수치·라벨·문항류와 결합하는 길부터 준비하고, 운영 시 실시간 이미지 생성이 필요하면 별도 API/비용/인증/검수 계약과 범위를 명시한다. 원문 이미지를 그대로 복제하는 방식과 달리, 바뀐 쌍둥이 조건에 맞는 새 이미지와 검수된 재사용 규칙을 만든다. 이미지의 픽셀을 수학 계산의 유일한 근거로 삼지 않고 명시적인 수학 데이터/정답 검증을 함께 둔다.

유형은 발문 표현이나 학교 이름으로 분류하지 않는다. 원문에서 개념/조건/풀이 원리를 분석해 생성 가능한 규칙으로 옮기며, 원문 문장·답/해설·그림의 복제 자체를 엔진 개선으로 삼지 않는다. 가능한 개선은 코드로 구현하고, 변경한 규칙의 수학 불변식·여러 씨앗·경계값·실제 렌더/검색 경로를 검증한다. 현재 저장된 문제나 다른 트랙을 바꿀 때는 별도 영향 범위와 갱신 원장을 둔다.
