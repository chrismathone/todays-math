## 1. 「전에 얘기한 적이 있다」 — **찾았다**

원장님 기억이 맞았다. 규칙은 **엔진 안에** 있었다 —
`vendor/figure-engine/core/figure_svg.py` 의 `lint_svg` docstring 이 지시를 인용한다:

> 「이걸 왜 완성되었다고 하나」 · 「아주 철저히 쪼으란 말야」 (2026-08-12)
> **「선위에 겹쳐서 배경처리해버리면 도형 읽는데 애로사항 있음」** (2026-08-13)

그 함수가 세는 다섯 규칙이 원장님 지적 넷과 **하나씩 대응**한다:

| lint_svg | 규칙 | 원장님 지적 |
|---|---|---|
| 1 | 잘림 — viewBox 밖 잉크 | ④ |
| 2·5 | 라벨-선 겹침 / **점 라벨은 선 밖에 둔다** | ②③ |
| 4 | 떠 있는 맨 길이 라벨은 `measured()` 규격 위반 | ① |
| 7 | halo 가 **실선**을 지우면 위반 | ② |

**그런데 그 lint 는 이 저장소에서 한 번도 돈 적이 없다.** `render_spec.py` 는
`sanitize_svg`(보안 경계)만 통과시키고, `lint_svg` 는 `core.figure_generator`
(resvg 래스터화)를 부르는데 vendor 에는 네 모듈만 들어와 있다(09 §0).
**규칙은 있고 배선이 없었다.**

찾은 명령(근거로 남긴다):

```
grep -rn "라벨" docs/planning/09-figure-engine-guide.md
grep -n "라벨\|꼭짓점" docs/planning/07-coding-convention.md
git log --all --oneline --grep="라벨" / --grep="꼭짓점" / --grep="치수"
git log --all -S"sideAnchor"          → d3373130 (변 라벨을 변에 수직으로)
grep -n "def lint_svg" -A 25 vendor/figure-engine/core/figure_svg.py   ← 여기 있었다
```

관련 결정도 확인했다 — **D-61**(같은 그림이 두 번이면 kind), **09 §4-16**(cm 붙은 글자는
전부 `measured()`), **§4-20**(받은 치수를 다 적는다), **§4-20-b**(발문이 이미 말했는가),
**§4-7**(FigureSpec `labels` 는 점 옆에 앉는다).

## 4. 🔴 원장님께 여쭐 것 — **원 그림에는 길이가 안 적혀 있다**

「발문이 말한 길이가 그림에 적혀 있나」를 **값으로** 세니(`overline{XY}=…cm` ↔ 스펙 안의
모든 글자), 지금 DB 에 실린 유형 중 **16종**이 안 적고 있다. 전부 **원 계열**이다:

```
3-2|원과 직선 01·02·03·05·07·08·09·10·11·12·13·14·15·16
3-2|원주각 06 · 3-2|원주각의 활용 14
```

(전 중등 엔진으로 넓히면 71유형. 삼각비 갈래는 이번에 **0건**으로 만들었다.)

**이것이 결함인지 아닌지는 원장님 결정입니다.** 두 결정이 서로 다른 방향을 가리킵니다:

- **2026-08-22 확정(§4-20-b)** — 「문제에 굳이 있는데 라벨로 **이중표기**해서
  너저분해질 필요가 없을듯」 → 마름모·원기둥의 라벨을 **뺐다**.
- **2026-08-25 지적** — 삼각형에서 길이 표시가 없거나 하나만 있는 것을 **결함**으로 보심.

제가 읽은 차이는 이렇습니다: **삼각형은 변이 셋이라 「어느 변의 길이인가」를 그림이
말해 주지 않으면 발문과 그림을 맞댈 수 없다.** 마름모·원기둥은 그 값이 붙을 자리가
하나뿐이라 이중표기가 됩니다. 원 그림(현·접선·할선)은 그 중간입니다 —
`OM`·`AP` 처럼 **이름 붙은 선분**이라 어느 것인지는 알 수 있지만, 값은 발문에만 있습니다.

→ **「원 그림에도 치수선을 달까요?」** 를 여쭙니다. 「달자」면 16유형에 붙이고
같은 방식으로 전량 다시 재겠습니다(작업량은 오늘 것과 비슷합니다).

## 6. 곁가지 — 다른 세션이 걸릴 함정 둘

### ㉠ 워크트리 이름에 한글이 있으면 **Prisma 가 안 올라온다** (Node 22, Windows)

```
Error: Cannot find module '#main-entry-point'
  at node_modules/.prisma/client/default.js
```

`npx tsx scripts/…` 로 DB 를 만지는 **모든 스크립트**가 이 워크트리에서 죽었다.
최소 재현(저장소와 무관):

```bash
mkdir -p /c/tmp/임프트-한글/node_modules/pkg      # package.json 에 "imports": {"#e": …}
cd /c/tmp/임프트-한글 && node t.js               # 🔴 Cannot find module '#e'
cd /c/tmp/impt-ascii  && node t.js               # 🟢 42
```

**Node 가 비ASCII 경로에서 `#imports`(subpath imports)를 못 푼다.** 2026-08-19 의
「`fs.rmSync` 가 한글 경로에서 프로세스를 죽인다」와 **같은 부류**다.
이 저장소는 워크트리 이름을 한글로 짓는 관례라 **다음 세션도 똑같이 걸린다.**

임시 회피(이번에 쓴 것): 생성물 `node_modules/.prisma/client/default.js` 의
`require('#main-entry-point')` 를 `require('./index.js')` 로 바꾼다.
`npx prisma generate` 로 원상복구된다. **근본 대책은 워크트리 이름을 ASCII 로 짓는 것.**

### ㉡ `build-figure-marks-compat.py --check` 가 **「못 구웠다」를 「달라졌다」로** 말했다

`C:/tmp/probe-round2.py`(임시 파일)가 없는 컴퓨터에서는 round2 7종이 코퍼스에서 통째로
빠지는데, `--check` 는 그것을 `CHANGED` 로 찍었다. 그 상태로 다시 구우면 **기준선에서
7종이 조용히 사라진다.** 그 파일 docstring 은 「기준선을 이미 구운 뒤에는 임시 파일이
사라져도 기준선 JSON 이 정본이다」라고 적어 두었는데 **코드에 그 문장이 없었다.**
없으면 기준선에서 스펙을 물려받게 고쳤다 — 고친 뒤 HEAD 엔진으로 `--check` 가
「28개 전부 바이트 불변」.
