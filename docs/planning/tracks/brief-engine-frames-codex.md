## 1. 먼저 재고 고른다 — 코드 쓰기 전에 보고 한 번

엔진 출력이 바뀌면 문제은행의 **적재본**과 어긋난다(20번 교훈 «엔진을 고친 것과 적재본을 고친 것은 다른 일»).

- 확인 도구: `scripts/qa/refresh-engine-content.ts` 드라이런.
- 푸시 관문: `.husky/pre-push` — `checkUnloadedTypes.ts`(엔진에만 사는 유형) · `check:raw-latex` 등.

**두 길을 재서 고른다.**
- **(가) 덧붙이는 길 — 우선한다.**
  - 기존 씨앗의 기본 출력(`generateElementaryProblem(unit, seed, tier)`)은 **한 글자도 바꾸지 않는다.**
  - 새 틀은 명시적 선택(예: 옵션 인자 · 별도 함수)으로만 닿게 하고, SRS 생성기의 다시 뽑기가 그 선택을 쓴다.
  - 이 경우 다음을 확인한다:
    - 적재본 드라이런이 0인지
    - `checkUnloadedTypes` 가 새 틀을 «엔진에만 사는 유형»으로 세는지
    - SRS 문제의 **그림 재현 경로**(문제에 씨앗을 저장하는 까닭 — 원격에서 그림을 다시 그리는 곳이 있는지, 저장된 `figureSpec` 만 쓰는지)가 새 틀도 똑같이 다시 만드는지
  - 저장된 회차를 다시 읽을 때 엔진을 다시 돌려 견주는 곳이 있으면 그 경로도 새 틀을 알아야 한다(옛 판으로 되돌려도 저장본을 읽을 수 있어야 한다 — «읽는 쪽 먼저» 규칙. 필요하면 읽는 쪽을 따로 커밋).
- **(나) 기존 갈래에 섞는 길.** 기존 씨앗의 출력이 바뀌므로, 적재본 드라이런의 «바뀌는 행 수»를 재서 보고만 한다. 공유 DB 쓰기 · 적재는 하지 않는다(리드 · 원장님 승인 사항).

보고(짧게) → 리드 확인 뒤 2 로 간다. (가)가 막힘 없이 되면 보고만 남기고 바로 2 로 가도 된다.

## 2. 틀을 더한다

- **차례:** 2학기 소단원부터(시범 대상: 초5 2학기 앞쪽) → 1학기.
- **목표:** 칸마다 서로 다른 틀 3개 이상.
- **틀의 뜻:**
  - 묻는 것이 실제로 다른 문제다. 낱말만 바꾼 «버스 / 지하철»은 같은 틀로 친다.
  - 소단원의 성취기준 안에서, 그 난이도(D-71 · D-72 — `연산 · 기본 · 응용`)의 뜻에 맞게 쓴다.
- **문장은 우리 말:** 교재 · 교과서 원문을 옮기지 않는다.
- **그림이 드는 소단원**(합동 · 대칭 · 직육면체 등): `docs/planning/09-figure-engine-guide.md` §2.1 · §2.2 를 먼저 읽고 그 불변식을 지킨다. 그림을 새로 그려야 하면 기존 kind 를 쓰고, 새 kind 가 필요하면 멈추고 보고한다.
- **답 · 입력:**
  - 정답은 코드가 계산한다.
  - 시험은 정답을 **다른 방법으로 다시 계산**해 견준다(같은 식을 두 번 쓰지 않는다).
  - 학생 입력 모드가 `self-check` 로 떨어지지 않게 하고, 가능하면 `number` · `text`(목록) 꼴로 쓴다(`getCourseProblemInput`).
  - 보기(`makeCourseAnswerChoices`)가 정답 하나 · 오답 셋으로 서는지 확인한다.
