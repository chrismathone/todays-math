# «오늘의 기억» — Hi-fi 안정화 뒤 검토할 항목

2026-10-06 · 원장님 지시: «그건 일단 지금 구현된 hifi 페이지들이 안정화되면 리스트로 남겨두자».

현재 구현된 학생·교사 Hi-fi의 안정화를 먼저 마친다. 아래는 후속 검토 목록이며, 자유 입력·칩 공개·문장 소거의 새 규칙을 이번 안정화에 추가하지 않는다. 기존 시안 구현 및 제외 항목은 [정본 §17](../srs-overhaul-20261006.md), [학생 화면 보고서](reports/fading-screens-codex.md), [목록·통계 보고서](reports/fading-catalog-stats-codex.md), [교사 Hi-fi 보고서](reports/fading-teacher-hifi.md)를 따른다.

## 후속 목록

| 항목                          | 원장님이 검토하신 방향                                                                        | 다음에 정할 것                                                                                                                                   |
| ----------------------------- | --------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| 자유 입력 채점과 칩 선택 병행 | 글을 직접 입력해 답을 제출하고, 칩도 고를 수 있게 한다. 정답은 채우고 오답은 틀렸다고 알린다. | 한글·수식의 허용 표기, 숫자키 칩 선택의 해제 범위, 입력 초점과 다음 빈칸 이동. 공통 채점 함수와 저장 계약을 속 담당이 정한 뒤 화면에 연결한다.   |
| 칩 공개 시점                  | 처음에는 칩을 숨기고 오답 뒤 공개하는 방안도 검토한다.                                        | 처음부터 공개 / 첫 오답 뒤 공개 / 학생이 «칩 보기»를 눌러 공개 가운데 결정한다. «칩 보기»는 Codex의 추천이며 아직 원장님이 선택한 정책은 아니다. |
| 4단계 문장 소거 확대          | 백지 단계에 글이 많이 남으므로 조사 등을 제외한 문장을 더 비우는 방안을 검토한다.             | 남길 조사·어미의 범위, 지울 문장의 단위, 칩과 입력 답의 구성. 개념 데이터와 소거 규칙을 함께 검토한다.                                           |

어떤 방식을 택해도 정답이나 맞는 칩을 미리 암시하지 않는다. 중복 칩의 수량은 공개하지 않고, 틀림 기록은 다시 채우거나 선택을 취소해도 남는다. 모든 빈칸의 크기를 같게 하는 `FADING_BLANK_WIDTH_MODE = uniform`과 입력 전후 줄바꿈 유지 결정은 계속 따른다.

현재 추가된 입력란은 **칩 글을 입력해 기존 칩을 선택하는 기능**이다. 임의 답의 자유 입력 채점이 완료된 것으로 보지 않는다.

## 속 쪽에서 미리 재 둔 것 (리드 · 2026-10-06)

자유 입력의 속 초안은 이 가지에 **없다** — 가지 `BIGSHOL/srs-typed-answer`(`5aa668224`)에 따로 두었다. 숫자와 까닭은 [정본 §17.11](../srs-overhaul-20261006.md)에 있다. 정할 때 볼 것만 옮긴다.

- 은행의 답 12,480개 가운데 글 9,985 · 수식 2,495. 글 답의 99.5%는 한글 · 숫자 · 띄어쓰기뿐이라 자판으로 칠 수 있다. 수식 답 가운데 801개는 수식 명령 · 첨자가 들어 있어 자판 글로 읽는 규칙이 따로 있어야 한다.
- 띄어쓰기 · 대소문자 · `$` 를 보지 않고 견줘도 한 개념 안에서 서로 다른 두 답이 같아지는 곳은 0 이다.
- 🔴 글자로 견주는 채점은 뜻이 같은 다른 말 · 오타를 못 알아본다. 글 답 다섯에 하나(1,963)가 세 낱말 이상이다. 그래서 초안은 결과를 셋으로 가른다 — 맞음 · 틀림(그 단계의 다른 칩의 글) · 모름(어느 칩의 글도 아니다 · 적지 않는다). **«모름»을 틀림으로 적을지가 원장님이 정하실 첫째 것이다.**
- 초안의 요청 계약: 넣은 것 하나는 `{ targetId, chipId }` 이거나 `{ targetId, text }` 다. 화면은 결과(`correct` · `wrong` · `unknown`)만 보고 그린다 — 견주는 규칙을 화면에 다시 짓지 않는다. 지금의 칩 글 입력(`fadingChipInputText`)은 그때 속의 규칙으로 바꾼다.
- «조사만 남기고 비우기»는 아직 재지 않았다. 지금의 빈칸은 은행이 `{ }` 로 표시한 핵심어다.

## 먼저 마칠 안정화 확인

- 학생 홈의 각 상태, 풀이 1~4단계, 오답·대조·평가·요약·나가기, 목록·단원 상세·통계·빈 상태와 교사 Hi-fi를 최신 구현으로 시각 검수한다.
- 학생 풀이의 선택 취소, 중복 칩 유지·소진, 틀림 기록 표시와 카드 아래 설명을 확인한다.
- 320·390·1280폭에서 넘침·12px 미만 글자·잘린 글과 빈칸 입력 전후의 크기·줄바꿈 변화가 없는지 확인한다.
- 관련 화면 시험, 수정 파일 ESLint 및 어포던스 검사를 통과하고 남은 차이를 기록한다. 개발 화면은 로컬 자료를 쓰며 실제 학생 API나 DB에 기록하지 않는다.

안정화 검수가 끝난 뒤 이 목록의 정책을 결정하고 후속 작업 범위를 정한다.

## 다른 제품의 같은 표기 — 손대지 않았다 (2026-10-06)

원장님이 짚으신 «단원 번호가 제목 첫머리의 숫자와 붙어 읽힌다»는 «오늘의 기억» 안에서만 고쳤다(`src/components/fading/labels.ts` 의 `curriculumName` — 정본 §17.14).
같은 이름이 보이는 다른 자리 — 개념 백지 · 교재 연결 · 문서 미리 보기 — 는 그대로다. 교육과정 전체로 세면 소단원 490개 가운데 번호가 붙은 것이 360개이고,
번호 바로 뒤가 숫자로 시작하는 제목은 35개다(«오늘의 기억»의 범위에는 7개 — 초3 «1cm보다 작은 단위» · «1m보다 큰 단위» · «1분보다 작은 단위» · 초4 «1000이 10개인 수 알아보기» …).
다른 제품에도 같은 표기를 쓸지는 원장님이 정하실 일이다 — 쓴다면 표시 함수를 한 자리로 올려 같이 부르게 한다.
