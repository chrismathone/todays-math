## 1. 모든 트랙이 지킬 것

### 1.1 먼저 읽는다

`CLAUDE.md`(절대 규칙 · 교훈 색인) → `docs/planning/18-qa-playbook.md` 의 «판정 코드 쓰기 전 점검표» →
(초등 트랙) `docs/planning/09-figure-engine-guide.md` → 이 지시서의 내 절.
교훈 색인에서 특히: «엔진을 고친 것과 적재본을 고친 것은 다른 일이다»(2026-08-27 · 08-30) ·
«가드가 0을 내면 못 센다일 수 있다» · «변이가 동작을 안 바꾸면 가드가 아니다» · «사례에서 우연히 맞던 규칙을
조건 없이 일반화했다 — 보편 진술은 반례 후보를 넣어 본다»(2026-10-03).

### 1.2 TDD — 지적마다 «고치기 전에 빨간» 시험

- 시험은 **글자 맞추기가 아니라 수학**으로 쓴다. 「발문에 «예각»이 있다」가 아니라
  「발문이 허용하는 경우를 전부 세면 정답이 하나다」 · 「보기 다섯의 값이 서로 다르다」 · 「그림의 글자에 정답이 없다」.
  글자 검사만 가능한 자리(문구 수리)는 글자 검사 + 재현 씨앗의 반례가 사라졌음을 같이 문다.
- 재현 씨앗 하나로 끝내지 않는다 — 씨앗 0 ~ 299(무거우면 0 ~ 99)를 돌려 **그 틀 전체**에 대어 본다.
  분모(몇 판을 봤나)를 시험이 같이 문다 — 모집단이 비면 빨개져야 한다.
- 가드를 세웠으면 **한 번 일부러 깨뜨려** 빨개지는지 본다(고친 줄을 되돌려 보기). 보고서에 «되돌리니 빨강»을 적는다.

### 1.3 🔴 난수 소비를 바꾸지 않는다

적재본은 `externalId` 에 씨앗을 담고 있고, 리드가 **같은 씨앗으로 다시 만들어 제자리에서 덮는다.**
그래서 고친 뒤에도 **같은 씨앗이 같은 수치를 내야** 한다.

- 문구만 고치는 수리는 `rng` 를 부르는 횟수 · 차례를 한 번도 바꾸지 않는다.
- 후보 풀을 좁혀야 하는 수리(조건을 만족하는 매개변수만 남기기)는 **지금 잘 나오던 씨앗의 산출이 그대로**이게 한다 —
  예: 거절 표집이 실패하던 씨앗만 구제하고, 성공하던 씨앗은 한 글자도 안 바뀐다.
- 어쩔 수 없이 바뀌면 **보고서에 틀 이름과 까닭**을 적는다(리드가 그 틀의 적재본을 전부 다시 만든다).
- 내가 고친 틀 **밖**의 산출은 한 글자도 바뀌면 안 된다. 고치기 전에 내 파일이 내는 산출의 지문(씨앗 0 ~ 49 의
  `content|answer|solution` 해시)을 떠 두고, 끝에 «내가 고친 틀만 달라졌다»를 대조해 보고서에 적는다.

### 1.4 같은 뿌리를 훑되, 넓히지는 않는다

고친 틀과 **같은 함수 · 같은 풀 · 같은 전제**를 쓰는 형제 틀을 읽는다. 같은 누락이 있으면 같이 고치고 보고서에 적는다.
그 밖(다른 단원 · 다른 종류의 결함)은 **고치지 않고 목록으로** 남긴다 — 리드가 원장님께 묻는다.

### 1.5 글 쓰는 법

- 발문 문구는 **그 생성기의 이웃 문항과 같은 말투**(초등 «~입니다 / ~입니까? / 구하시오», 중등 · 고등 «~이다 / ~구하시오»).
  설명 투 · 느낌표 · 이모지 없음. «단, …» 조건은 그대로 써 두면 `wrapDanClause` 가 괄호로 싼다.
- 🔴 TeX 가 든 글은 **파일 편집 도구(apply_patch 등)로만** 쓴다. 셸(echo · heredoc · sed)로 쓰면 역슬래시가 반으로 준다.
  고친 뒤 내 파일에 제어 문자(0x08 · 0x09 가 아닌 탭 자리 · 0x0c)가 없는지 본다 — `\b` · `\f` · `\t` 가 먹힌 자국이다.
- prettier 는 **이름을 적은 파일에만**. 폴더로 돌리지 않는다. `prisma format` 금지.

### 1.6 건드리지 않는 것

- 다른 트랙의 파일 · 공유 문서(`CLAUDE.md` · `10-handoff.md` · `20-lessons-learned.md` · `18-qa-playbook.md` · `07-coding-convention.md`) — 리드가 쓴다.
- 개념 백지(`src/lib/concept-blank/**` · `e2e/concept-blank-paper/**`) · `docs/design/reviews/**` · 저장소 뿌리의 `elem-*.html`.
- 계약(`src/contracts/**`) · Prisma 스키마 · 마이그레이션. 필요해 보이면 **멈추고 ask**.
- `npm install` · `prisma generate` · `prisma migrate` · `db push` 금지(node_modules 는 정션이다).
- 유형 키 · 문형 id · `familyKey` · `externalId` 의 모양 — 적재본을 되짚는 열쇠다.
- push 금지. 내 가지에만 커밋한다(`git config --local user.email chrismathone@gmail.com` · `user.name SUN`).

### 1.7 관문 — `worker_done` 전에

1. 내 시험 + 그 엔진의 기존 시험 묶음: `npx vitest run <파일들> --maxWorkers=1` (전체 `npm run test` 금지 — 이 기계에서 메모리로 죽는다).
2. `npm run type-check` (`.next/dev/types/validator.ts` 에서만 죽으면 그 파일만 지우고 다시).
3. `npx eslint <내가 고친 파일들>`.
4. 그림을 건드렸으면 `scripts/figure` 쪽 기존 검사(09 지침에 적힌 것)와 `src/__tests__/unit/elementaryFigure.test.ts`.
5. 보고서 `docs/planning/tracks/reports/bank-fix-<트랙>.md`:
   지적마다 **무엇을 어떻게 고쳤나 · 시험 이름 · 되돌리니 빨강 · 난수 소비가 바뀌었나(바뀐 틀 목록) ·
   같은 뿌리로 더 찾아 고친 것 · 안 고치고 남긴 것(까닭)**. 끝에 «원장님께 물을 것».
6. 커밋 뒤 `worker_done --report-path <보고서>`.

막히거나 방침을 바꿔야 하면 스스로 정하지 말고 `ask` 한다.

## 4. 파생 · 채점 (`bank-fix-derive`)

### 4.1 Q-P01 — 소수 오답 (`src/lib/engine/deriveFormats.ts` `formatRat` 584 ~ · `decimalWidth`)

`formatRat(r, "dec")` 이 **나머지를 그대로 소수 자리에 적는다.** 829/1001 → `0.829`, 829/100 → `8.0029`.
결과 둘:

1. **같은 값의 보기 둘** — 정답 `0.8290` 옆에 `0.829`(재현: `asMultipleChoice({...generateMiddleProblem("3-2|삼각비|18", 15), familyKey: "x", problemType: "활용"}, createRng(0x9e37))`).
   중복 판정이 **글자**만 본다.
2. **깨진 소수 보기** — 적재본 실측: 소수 정답 객관식 2,381행 중 최소 313행(101 문항류)에 `1.0002547` · `0.00159` 같은 보기.
   학생이 계산 없이 지워 낸다(이 파일 주석이 스스로 막으려던 것).

고칠 것:
- 소수는 **값대로** 적는다. 유한소수가 아닌 후보는 소수 모양으로 내지 않는다.
- 보기의 **소수 자릿수는 정답과 같게**(끝자리 0 포함 — 정답이 `0.8290` 이면 보기도 넷째 자리까지). 그 자릿수로 정확히 못 적는 후보는 버린다.
- 정답 · 보기의 같음은 **유리수 값**으로 판정한다(글자가 달라도 값이 같으면 같은 보기).
- 🔴 후보가 줄어 5지선다를 통째로 잃는 문항류가 생기면 안 된다(이 파일의 `WEAK` 주석 참조 — «버리지 말고 뒤로 민다»).
  소수 정답에 맞는 실수(끝자리 ±1 · 한 자리 위 ±1 · 소수점 자리 밀기는 뒤로)로 후보를 채운다.
  고치기 전후로 **객관식을 만들 수 있는 문항류 수**를 엔진 전수(초등 문형 · 중등 유형, 씨앗 몇 개)로 세어 보고서에 적는다 — 줄면 안 된다.
- 🔴 **소수 정답이 아닌 문항의 파생 결과는 한 글자도 바뀌지 않는다**(§1.3). 고치기 전 산출을 떠 두고 대조한다.

### 4.2 Q-P02 — 동그라미 정답 (`src/lib/testResults/gradeAnswers.ts` 108 ~ 113)

`String(selectedChoice) === problem.answer.trim()` — 그런데 은행의 객관식 정답은 **전부 동그라미**다
(적재본 47,933행: 하나짜리 47,798 · 「①, ④」 같은 여럿 135 · 숫자 0). 이 경로(`POST /api/tests/{id}/submit`)는
지금 화면이 없고 기록도 0행이지만, 켜는 순간 객관식이 전부 오답이 된다.

고칠 것:
- 하나짜리 정답은 번호로 정규화해 견준다(동그라미 ↔ 숫자). 이미 있는 선택지 번호 읽기(`src/lib/problem/` 의
  `answerIsChoiceNumber` · `canonicalCircled` 근처)를 **쓴다** — 규칙을 새로 적지 않는다.
- 정답이 여럿인 문항은 번호 하나로 **맞았다고 하지 않는다**(강제로 하나로 줄이지 않는다). 지금 계약(`selectedChoice: number`)으로는
  채점할 수 없다는 것을 시험과 주석에 남기고, 계약을 넓힐지는 보고서의 «원장님께 물을 것»에 적는다.
- 시험: 엔진이 낸 객관식 → `gradeAnswers` 로 이어지는 왕복(맞는 번호 = 정답 · 다른 번호 = 오답), 숫자로 저장된 옛 꼴도 그대로 정답.
- `gradeMarks`(틀린 번호만 넣는 길)는 건드리지 않는다.

자리: `scripts/import/exam-paper/` — `exams/<시험>/{hwp_fixed,answers,sol_fixed,body}.json` → `build-exam-drafts.ts` → `drafts.json`

🔴 원칙: **원본 없이 지어내지 않는다.** 저장소 자료(`hwp_fixed` · `answers` · `sol_fixed` · `body` · `pieces_*` · 그림)로
**확정되는 것만** 고친다. 원본(N 드라이브 HWP · PDF)을 봐야 하는 것은 고치지 않고 「원본 필요」 목록으로 남긴다.
