# 브리프 — 매일 자동 출제 뒷단 (22번 ②③⑤)

SSOT: `docs/planning/22-daily-auto-test.md` · 결정 **D-129**(07). **먼저 둘 다 읽어라.**
이 브리프는 **뒷단만**이다. 화면은 D-07 시안이 아직이라 **만들지 않는다**(§6).

## 1. 목표 한 줄

원장님이 반의 **수업 요일과 시작 차시**를 정해 두면, **아침 8시에 그날 학생별 시험지 «초안»이 서 있다.**
확정·인쇄는 원장님 손이다. 진도가 기록되면 **그 기록이 계획을 이긴다.**

## 2. 하는 것

### ② 계획 표 + 날짜 펴기 규칙

- **규칙을 저장한다. 날짜별 행을 쌓지 않는다.** 반 계획 한 줄: 수업 요일(여럿) · 한 수업당 차시 수(기본 1) ·
  시작 차시(`unitId`) · 시작일 · 켜짐. 개별 진도 학생(`Student.useIndividualProgress`)은 **학생 계획이 반 계획을 덮는다**
  (같은 모양 한 줄). 다르게 하려면 보고서에 까닭을 적고 리드에게 물어라.
- **순수 함수**로 «그 날짜에 나갈 차시»를 센다 — 시작 차시부터 교육과정 차례(`Unit.orderIndex`, 735차시)로
  수업일마다 `한 수업당 차시 수`만큼 나아간다. 휴일은 **다루지 않는다**(요일만 — D-129 ⑷).
- 🔴 **실제가 이긴다** — 진도 기록(`Progress` 최신 행, `getCurrentProgress`)이 있으면 **그 차시가 정본**이고,
  남은 계획은 **그 지점부터 다시 편다**. 계획을 고쳐 쓰지 마라(규칙은 그대로 두고 «어디서부터»만 옮긴다).
  계획보다 앞서 있으면 앞선 대로, 뒤처져 있으면 뒤처진 대로 이어 간다. **밀림/앞섬(일 수)** 을 함께 내라 —
  나중에 화면이 쓴다.
- 계약은 `src/contracts/` 에(Zod, 계약 SSOT). 마이그레이션은 **파일만 만들고 공유 DB 에 적용하지 마라** —
  적용은 원장님 확인 뒤 리드가 한다(`scripts/qa/apply-*-migration.ts` 관례, `c3443e6e` 참고).

### ③ 아침 8시 자동 초안

- cron 하나를 더한다(`vercel.json`) — **KST 08:00**. `CRON_SECRET` 문지기는 기존 것과 같은 결
  (`src/app/api/eywa-sync/cron/route.ts:18-28`).
- 🔴 **서버 혼자 부를 길이 없다** — `POST /api/tests/generate` 는 `getSessionUser()` 를 요구한다
  (`src/app/api/tests/generate/route.ts:17-18`). 세션 없이 **같은 출제 함수**(`generateDraftTest`)를 부르는
  경로를 내라. 출제 규칙·문항 수·난이도 배분은 **지금 것을 그대로** 쓴다(새로 짜지 마라).
- 소유자(원장 계정)를 어떻게 정하나 — 기존 `EYWA_SYNC_OWNER_EMAIL` 패턴을 참고해 **한 곳에서** 정하고,
  못 찾으면 **조용히 0건이 아니라 오류**로 끝내라(관례: `syncScope.ts:76-82`).
- **초안까지만.** 확정(`confirm`)·인쇄(`print`)는 절대 자동으로 부르지 마라(D-129 ⑶).
- **중복 금지** — 같은 날 같은 학생에게 시험(초안 포함)이 있으면 만들지 않는다(지금 규칙과 같다).
- 범위·문항 수는 지금 갈래 그대로: `resolveDefaultReviewRange`(D-63) · `poolTotal >= neededCount`.
  **문항이 모자라면 만들지 말고 기록만 남겨라**(화면이 「직접 출제」로 안내한다 — D-64 와 같은 결).
- 한 회차가 무엇을 했는지 **남겨라**(만든 수 · 건너뛴 수와 까닭). 표를 새로 만들지, 기존 것을 쓸지는
  네가 정하고 보고서에 근거를 적어라.

### ⑤ 자동 대상 넓히기

- 지금 `daily-review` 는 **eywa 연계 학생만** 읽는다(`src/app/api/tests/daily-review/route.ts:61`).
  🔴 **계획이 있는 학생이면 전부** 대상이 되게 넓혀라 — 손으로 등록한 학생 · 고등 포함(D-129 ⑷).
- 🔴 **eywa 진도 동기화는 이번에 쓰지 않는다**(D-129 ⑸ — 보류). eywa 쪽 코드·cron·env 를 **건드리지 마라.**
  「오늘 수업한 학생」을 `eywaLastReportDate` 로 재는 지금 셈에 기대지 말고, **계획(요일)** 으로 정해라.

## 3. 시험 (TDD — RED→GREEN, 테스트 없이 구현 금지)

- 날짜 펴기·«실제가 이긴다»·밀림 셈은 **순수 함수 단위 시험**으로. 경계: 시작일 당일 · 요일이 하나뿐인 반 ·
  한 수업 두 차시 · 교육과정 끝에 닿았을 때 · 진도가 계획보다 앞/뒤 · 진도 기록이 하나도 없을 때.
- 자동 회차는 **API 시험**으로(문지기 없는 호출 거부 · 중복 금지 · 문항 부족이면 안 만듦 · 확정·인쇄 안 부름).
- 🔴 **변이 하네스**를 만들어라 — `scripts/qa/mutate-daily-plan.ts`(관례는 `mutate-learn-screens.ts`).
  가드마다 하나씩 꺼 보고 **빨개지는지**. ⚠️ `rmSync` 금지(`noRmSync.test.ts` — 임시 파일 + `unlinkSync`).
- 관문: `npx tsc --noEmit` 0 · 관련 시험 초록 · `npm run lint` · `npm run build`.
  전체 관문은 리드가 돌린다(이 기계에서 28분 걸린다).
