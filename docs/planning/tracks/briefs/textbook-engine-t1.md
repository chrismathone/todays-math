## 범위

0단계 보고서의 **T1 중1 수 · 유리수 계산** — ⓑ 후보 544행 · 64묶음(소수와 거듭제곱 · 소인수분해 · 공약수/공배수 · 정수와 유리수 · 수의 대소 · 유리수의 덧셈/뺄셈 · 곱셈 · 나눗셈 등 보고서가 T1 에 넣은 단원).
묶음과 행은 `docs/planning/tracks/reports/textbook-engine-census/` 의 데이터에서 읽는다. 교과서 원문은 저장소 밖 `/Volumes/새 볼륨/today-backups/textbook-mid-rows.jsonl`.

## 할 일

1. 묶음마다 **기존 유형의 확장인가, 새 유형 키인가**를 정한다(같은 계산 골격이면 확장 — 유형 키를 함부로 늘리지 않는다). 결정과 까닭을 표로.
2. 중등 엔진(`src/lib/middle/`)에 짓는다 — **TDD**(RED → GREEN):
   - 씨앗이 같으면 결과가 같다 · 씨앗마다 숫자 · 부호 · 분모 · 소문항이 바뀐다.
   - 정답은 생성기와 **다른 길**로 다시 계산하는 시험(유리수 정확 계산 — 부동소수 금지).
   - 0 나누기 · 약분 · 대분수/가분수 · 음수 표기 · 소문항 순서를 지킨다. 답이 지나치게 크거나 흉한 수가 나오지 않게 범위를 둔다.
   - 지면 글은 기존 엔진 문항의 꼴과 D-164 를 따른다. **교과서 문장을 옮기지 않는다**(유형만 본다).
   - 난이도(easy/mid/hard)는 유형 속성 — 보고서의 난이도를 기본으로, 실제 생성물을 보고 고친다.
3. 기존 유형 등록 · 커버리지 도구(`scripts/middle/gen-cli.ts` · `type-census.ts`)에 새 유형이 보이게 한다.
4. **대체 원장**(데이터, 저장소 안): 교과서 문항 id → 대체 유형 키(확장이면 기존 키). 그 유형의 생성물이 그 교과서 문항의 «유사 유형»인지 묶음마다 견본으로 확인한 근거. 확인 못 한 행은 원장에 넣지 않는다.
5. 견본 지면: 새 · 확장 유형마다 씨앗 셋으로 HTML 미리보기(저장소 밖 `/Volumes/새 볼륨/today-backups/textbook-engine-t1-preview/`) — KaTeX 오류 0 · 가로 넘침 0 을 재서 보고서에.
6. 보고서 `docs/planning/tracks/reports/textbook-engine-t1.md`: 묶음별 결정 · 새/확장 유형 목록 · 시험 · 견본 수치 · 원장 행 수 · 못 한 것.

## 지킬 것

- 🔴 **DB · 운영 쓰기 없음 · 적재 · 잠금 없음**(2단계는 리드가 드라이런 뒤 원장님 확인으로 한다).
