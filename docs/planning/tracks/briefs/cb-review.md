## 2. 원장과 도구

원장 한 줄 = 다시 봐야 하는 문항 하나. 처분은 **은행의 글에서 읽는다** — 글이 바뀌면 «고침», 그대로 두기로 했으면 «둠», 뺐으면 «뺌», 아니면 «남음».

```
npx tsx scripts/qa/concept-blank/review/progress.ts --part <e3…m3> --sections          # 줄마다 남은 수 · 소단원마다 남은 줄
npx tsx scripts/qa/concept-blank/review/worklist.ts --part <p> --section "<소단원 열쇠>"   # 그 소단원의 남은 줄 — 형식별로 «학생에게 보이는 것»
npx tsx scripts/qa/concept-blank/review/worklist.ts --part <p> --section "<열쇠>" --all    # 고친 뒤 다시 읽을 때(고친 줄 포함)
npx tsx scripts/qa/concept-blank/review/worklist.ts --part <p> --id <문항 id>
npx tsx scripts/qa/concept-blank/review/keep.ts --part <p> --id <id> [--id <id> …] --note "<까닭 한 줄>"   # 고치지 않고 둔다
npx tsx scripts/qa/concept-blank/review/keep.ts --part <p> --section "<열쇠>" --screen   # 훑는 줄(num · copy · example)뿐인 남은 줄을 «봤다»로 닫는다
```

줄에 선 까닭(`queues` — 한 문항이 여러 줄에 설 수 있다):

| 줄 | 뜻 | 닫는 법 |
|---|---|---|
| `packet:<분류>` | 외부 검토가 의견을 단 문항 | 고치거나, `keep --id … --note` 로 **문항마다 까닭** |
| `num` | 핵심어에 숫자가 든 개념 | §3.1 로 판정 — 고치거나 소단원 단위 `--screen` |
| `copy` | 핵심어가 전부 용어 안에 든 개념 | §3.2 — 고치거나 `--screen` |
| `example` | 예가 달린 개념 | §3.3 — 고치거나 `--screen` |
| `rewrite` | 초3 처음 은행의 예 56개 | §3.4 — **반드시 새로 쓴다**(«둠»으로 못 닫는다) |

`packet:level`(초4 의 «난도 재분류» 60건)은 합의 안건 6 으로 이미 «둠»이다 — 난이도는 건드리지 않는다.

## 3. 형식마다 학생에게 보이는 것이 다르다 — 이 트랙의 핵심

개념 한 장이 형식 넷에 같이 쓰인다. **고친 뒤 형식 넷을 각각 읽는다**(작업표가 형식별로 찍어 준다).

| 형식 | 학생지에 찍히는 것 | 채점표 |
|---|---|---|
| A 완전 백지 | 소단원 이름뿐 | 용어 + 뜻 문장(핵심어 굵게) |
| B 용어 → 뜻 | **용어만** | 용어 + 뜻 문장 — «굵은 부분의 뜻이 모두 있어야 ○» |
| C 문장 빈칸 | **뜻 문장만**(핵심어 자리는 빈칸 · 용어는 안 찍힌다) | 굵은 글이 빈칸의 답 |
| D 개념 지도 | **용어 + 예 물음** | 뜻 문장 + 예의 답 |

### 3.1 `num` — 용어만 보고 굵은 핵심어를 하나로 정할 수 있나 (합의 안건 1 · 2)

판정: **그 학년 학생이 용어만 보고, 교과 지식으로 굵은 핵심어를 하나로 정할 수 있으면 둔다. 다른 값도 핵심어가 될 수 있으면 고친다.**
하나로 본다 — ⑴ 정의 · 단위 환산 · 자리값 · 교과서가 그 학년에 하나로 정한 수(직각 $90^\circ$ · $1\,\mathrm{km}=1000\,\mathrm{m}$ · 원주율 $3.14$ · 십진법의 $10$),
⑵ 용어 칸에 이미 적힌 수에서 나오는 계산값.

고치는 법: **용어 칸에 조건을 싣는다.** 뜻 문장은 그대로 둔다(C 지면이 안 바뀐다).
- «단위가 있는 곱» → «$4\,\mathrm{m}$의 $0.3$배 구하기» · «몫 찾기» → «$35\div5$의 몫을 곱셈식으로 찾기» · «필요한 최소 점수» → «두 과목이 $88$점, $86$점일 때 세 과목 평균 $90$점이 되는 점수».
- 🔴 용어에 **답을 싣지 않는다**(굵은 핵심어가 용어에 보이면 `copy` 꼴이 된다). 조건(주어진 수 · 식 · 상황)만.
- 용어는 보이는 글자 **40자** 안 · 한 소단원 안에서 같은 용어 금지(은행 시험).
- 40자에 못 담으면 **그 문항만** 뜻 문장을 일반 진술로 다시 쓴다(«길이에 수를 곱하면 곱에도 {같은 단위}를 붙인다») — 작업자 재량으로 넓히지 않는다.
  그 소단원에 같은 진술이 이미 있으면 §4 의 «빼고 새로 쓰기».

### 3.1′ 사례 표지 — A(완전 백지) 채점표에서 빼는 카드 (합의 안건 11)

A 는 소단원 이름만 보여 준다. «$4\,\mathrm{m}$의 $0.3$배 구하기 → $1.2\,\mathrm{m}$» 같은 카드는 학생이 떠올릴 수도, 교사가 줄과 맞춰 볼 수도 없다.
**굵은 답이 용어에 주어진 값으로 정해지는 카드에 사례 표지를 단다** — 답이 낱말이어도 단다(«한 층의 높이가 $3\,\mathrm{m}$일 때 … {곱셈}으로 대응»).
단위 환산 · 자리값 · 직각 $90^\circ$ · 원주율처럼 **수 자체가 개념인 카드는 달지 않는다**. 기본은 «싣는다»다 — 헷갈리면 작업표의 «A 채점표» 줄을 읽고
«소단원 이름만 보고 이 뜻 문장을 떠올릴 수 있나»로 정한다.

- 보강 파일: 개념 줄 **끝**에 `CASE` — `["하", 용어, 갈래, 뜻문장, CASE]` 또는 `[…, 뜻문장, [예 물음, 예 답], CASE]`. 파일 머리의 import 에 `CASE` 를 더한다(`import { CASE, joinBanks, plusSection } from "./plus";`).
- 원래 파일: 파일 끝의 `markGivenCases(bank, [ … ])` 에 그 개념의 id 를 적는다(없는 id 는 던진다).
- §3.1 로 용어에 조건을 실은 문항은 거의 다 사례다. 용어에 이미 수가 있던 문항(`num` 줄의 «둠» 후보)도 본다.
- 표지를 달면 원장은 «고침»으로 읽는다. A 에서 줄이 줄어도 **채우지 않는다**(보편 진술을 새로 쓰는 일은 이번 범위 밖 — 보고서에 소단원마다 A 에 남는 수를 적는다).

### 3.2 `copy` — 굵은 글이 용어뿐이다 (합의 안건 12)

핵심어가 전부 용어 안에 든 개념이다. 읽어서 둘로 가른다 — **핵심어 표기는 늘리지 않는다**(`{ }` 하나를 계약 · 조판 · 채점표 · 지면 코드가 같이 쓴다).

- **이름 대기 문장** — 굵은 글이 용어 이름 그 자체(`수를 자리에 맞추어 위아래로 적고 계산하는 방법을 {세로셈}이라 한다`). **그대로 둔다.**
  C 는 이름 한 칸 그대로고, B 는 채점 안내가 가른다(«굵은 글이 용어와 같으면 그 이름은 답이 아니다 — 이름을 뺀 나머지 뜻이 문장과 같으면 ○»). 소단원 단위 `--screen` 으로 닫는다.
  다만 이름을 뺀 나머지가 뜻이 못 되는 문장(«{세로셈}으로 계산한다»처럼 뜻이 없는 것)은 뜻이 드러나게 다시 쓴다.
- **답이 새는 문장** — 굵은 글이 이름이 아니라 **뜻의 말**인데 용어 안에 그대로 보인다(«서로의 수선» → `…직선 나도 직선 가의 {수선}이다` ·
  «합동인 도형의 넓이» → `합동인 두 도형은 {넓이}도 같다`). 빈칸을 **뜻의 다른 곳으로 옮긴다**(`합동인 두 도형은 {완전히 포개어지므로} 넓이도 같다`). 핵심어를 더하지 않는다.

### 3.3 `example` — 예 물음만 보고 풀 수 있나 (합의 안건 5)

D 는 용어와 예 물음만 찍는다. 뜻 문장의 수 · 식 · 상황에 기대는 예(«조각이 $24$개이면 케이크는 몇 개인가?» — 한 개를 몇 조각으로 나눴는지가 뜻 문장에만 있다)는
- 예 물음에 **조건을 다시 써 넣는다**(보이는 글자 80자 안). 답은 새 조건으로 다시 계산한다.
- 80자를 넘기고 뜻 문장이 보편 진술이면 예를 뺀다(빈 예 칸 — 학생이 예를 든다). 뜻 문장이 사례 하나뿐이면 §3.1 처럼 뜻을 일반화한 뒤에만 뺀다.
- 은행 시험이 «이때 · 이 … · 그 … · 구한 … · 이/같은 방법으로»로 시작하는 예를 막는다 — 그 자는 좁다. **가리킴말이 없어도 조건이 빠진 예**를 읽어서 잡는 것이 이 줄의 일이다.
- 예가 그 용어의 예인지도 본다(«선분» 가지에 반직선을 묻는 예는 고친다).

### 3.4 `rewrite` — 초3 처음 은행의 예 56개 (합의 안건 10 · e3 트랙만)

`e3.ts` 의 예 56개는 그 소단원 적용 문항을 글자 그대로 옮긴 것이다. **전부** 그 용어의 뜻만으로 풀리는 새 예로 쓴다 — 적용 문항과 다른 수 · 다른 물음, 물음 80자 · 답 60자 안.

### 3.5 `packet:*` — 외부 검토의 의견

작업표가 의견 · 제안 · 재검증을 찍는다. 읽는 법:
- **재검증(independent_qa)이 앞 제안보다 우선한다.** «묶음 방향»은 여러 문항의 공통 방향일 뿐 이 문항의 글이 아니다 — 그대로 복사하지 않는다.
- 제안문은 «새 문제» 꼴이라 우리 칸(용어 · 뜻 문장 `{핵심어}` · ○× 문장 · 까닭 · 적용 물음 · 답)에 그대로 못 넣는다. **문항의 뜻을 지키며 최소로** 고친다 — 다른 문제로 바꾸지 않는다.
- 제안의 1,191건은 «원문 뜻 문장을 빈칸으로 찍어라»(= 이미 있는 C 형식)다. 그런 문항의 실제 결함은 §3.1(용어에 조건이 없다)이다.
- `explanation_only` 는 정답을 지키고 까닭 · 해설만 고친다. ○× 의 답을 기계로 뒤집지 않는다 — 문장을 고쳐 참 · 거짓이 깨끗해지게 한다
  (리드의 본보기: `m2-02-03-xo18` — «약한 조건이라 참»인 문장을 `$a\le-1$이면 … 자연수가 없다`(×)로).
- **조건을 붙이는 선**(합의 안건 7): 그 문항의 수 · 그림 안에서 반례가 생기거나, ○× 의 참 · 거짓이 조건에 따라 갈리면 붙인다.
  학년 정의가 이미 막고 그 반례가 문항에 없으면 안 붙인다(초등 각기둥은 직각기둥 · 공정한 주사위 · $0$이 아닌 수로 나눈다) — 이때는 `keep --note "교과서 관행 — …"`.
- 후보(`review_candidate`) · 권고(`review_recommendation`) · 선택 개선(`optional_improvement`)도 **전부 원문과 대조해** 고침 / 둠(까닭)을 남긴다.
  차례는 필수(조건 · 발문 · 형식)가 먼저다.
- 초등 도형 · 측정에서 «그림 없이» 문제(전개도의 가로 · 세로, 겨냥도에서 보이는 면, 위 · 앞 · 옆에서 본 모양, $\overline{DE}\parallel\overline{BC}$ 의 점 배치 …)는
  **문항 글 안에 배치 조건을 써 넣는다**(«밑면이 바닥에 닿게 세운 원기둥을 …», «$\triangle ABC$의 변 $AB$, $AC$ 위에 각각 점 $D$, $E$가 있고 …»). 그림을 더하지 않는다.

### 3.6 줄에 없어도 고치는 것

작업표를 읽다가 보이면 같이 고친다(보고서에 «줄 밖에서 고친 것»으로 적는다):
- **일상어 빈칸** — 빈칸이 «빠짐없이 · 한눈에 · 차례로» 같은 말이면 수학 대상어로 옮긴다(`…{가려진 쌓기나무}까지 알 수 있다`).
- **C 에서 답 방향을 못 정하는 문장** — 같은 소단원에서 빈칸을 비운 글이 같고 답이 다르면 은행 시험이 빨갛다. 목적을 **빈칸 밖**에 넣는다(«가장 큰 조사값을 찾으려면 … {가장 높은 점}»).
- **불가능한 조건** — 문항의 수가 동시에 참인 대상이 없는 것(그림이 대략이어도 수는 성립해야 한다). 리드가 넓이 · 내접원 꼴은 기계로 훑어 고쳤다. 나머지는 읽으며 본다(합의 안건 14 의 목록):
  1. 삼각형 부등식 위반 · 세 각의 합이 $180^\circ$가 아님 · 한 각이 $0^\circ$ 이하이거나 $180^\circ$ 이상.
  2. 두 변이 $a$, $b$인 삼각형의 넓이가 $\frac{ab}{2}$를 넘음 · 둘레 $p$인 삼각형의 넓이가 $\frac{\sqrt{3}p^2}{36}$을 넘음(내접원 반지름이 $\frac{p}{6\sqrt{3}}$를 넘음).
  3. 현 > 지름 · 호 > 원둘레 · 중심각 > $360^\circ$ · 부채꼴 > 원 · 외접원 반지름이 내접원 반지름의 $2$배보다 작음 · 원에 내접하는 사각형의 대각의 합이 $180^\circ$가 아님.
  4. 직각삼각형에서 빗변이 다른 변 이하 · 세 변이 다 있는데 $a^2+b^2\ne c^2$ · 원뿔에서 모선 < 높이 · 구의 단면 반지름 > 구의 반지름 · 정다각형 · 직사각형 · 평행사변형의 변 · 각 · 대각선이 정의와 모순.
  5. 확률이 $0$과 $1$ 사이 밖 · 상대도수 · 백분율의 합이 $1$($100\%$)이 아님 · 평균이 최솟값과 최댓값 밖 · 음수 도수.
  6. 분모 $0$ · 근호 안이 음수 · 나머지 ≥ 나누는 수 · 자연수 단원인데 답이 음수 · 농도 · 비율이 $100\%$를 넘음 · $60$분 이상의 «분», $2$월 $30$일 같은 단위의 자리값을 넘는 수.
- 같은 소단원의 ○× · 적용이 고친 개념과 같은 틀린 주장을 하면 같이 고친다.

## 4. 안 바꾸는 것 · 글자 상한을 넘을 때

- **문항 id · 소단원 · 난이도 · 갈래 · 차례 · 문항 수**(소단원마다 개념 · ○× · 적용 하 · 중 · 상 10개씩)는 그대로다. 은행 시험이 잠근다.
- 글자 상한(보이는 글자): 용어 40 · 뜻 160 · ○× 문장 · 까닭 120 · 적용 물음 120 · 답 80 · 예 물음 80 · 예 답 60. 핵심어 `{ }` 는 1~4곳.
- **상한을 넘을 때의 퇴로**(합의 안건 13 — 이 차례대로):
  1. 먼저 §3.1 · §3.3 의 규칙 — 예가 80자를 넘고 뜻이 보편 진술이면 **예만** 비운다(문항은 남는다). 용어가 40자를 넘으면 그 문항의 뜻 문장을 일반 진술로.
  2. 그래도 넘으면 **조건을 지킨 채 더 짧은 참인 문장으로 다시 쓴다.** 🔴 자르지 않는다 · 경우를 특수화하지 않는다(조건을 떼어 내 거짓이 되게 하지 않는다) · ○× 는 참 · 거짓을 지킨다.
  3. 그래도 안 되면 그 문항을 뺀다 — 보강 파일은 그 자리에 `RETIRED`, 같은 목록 **끝에** 새 문항(같은 소단원 · 같은 칸 · 같은 난이도). 더 쉬운 옆 개념으로 바꾸거나 같은 개념을 두 번 쓰지 않는다.
     원래 파일(`e3.ts` …)의 문항은 빼지 않는다 — 고쳐 쓴다. 정 안 되면 리드에게 `ask`.
  4. 뺀 문항과 새 문항을 보고서에 **짝으로** 적는다. 그 개념이 소단원에 하나뿐이었으면 «성취기준 공백»이라고 적는다.
- ○× 는 난이도마다 참 4~6(원래 + 보강 10개 가운데)을 지킨다 — 답을 바꾸면 다시 센다.
- 한 소단원 안에서 같은 용어 · 뜻 · ○× 문장 · 적용 물음 금지, ○× 문장이 그 소단원 뜻 문장과 같은 글이면 안 된다(은행 시험).

## 5. 표기 — cb-ten §4 그대로, 그리고

- 모든 수 · 식 · 단위 · 분수 · 각은 `$...$`. 한 글자 인수도 중괄호(`\frac{1}{2}` · `\dot{3}`). 수식 뒤 조사는 읽는 소리에 맞춘다.
- 🔴 **수식이 든 글은 `` r`...` `` 로 쓴다.** 보통 따옴표에 `\,\mathrm{m}` 을 쓰면 `,mathrm{m}` 이 되어 지면에 «3, mathrmm» 이 찍힌다(이번 검토가 찾은 실제 결함 — 은행 시험이 이제 막는다).
  보통 따옴표였던 글에 수식을 더하면 그 글을 `r` 글로 바꾼다. 원래 파일 가운데 `r` 이 없는 파일은 머리에 `const r = String.raw;` 를 둔다.
- 🔴 **Bash · PowerShell 로 TeX 가 든 글을 쓰거나 치환하지 않는다**(역슬래시가 줄어든다). 파일은 편집 도구로만. 정규식 한 번으로 여러 문항을 바꾸지 않는다 — 문항마다 읽고 고친다.
- 🔴 교재 문장을 옮기지 않는다 — `check-leak.ts` 0건. 수식으로 바꾸면 한글이 이어 붙어 누출 창이 새로 생길 수 있으니 고친 뒤 다시 돌린다.

## 6. 검산 — 고친 글이 새 오류를 만들지 않게

- 수 · 식 · 답이 바뀌는 수정은 **전부 다시 계산**한다(스크래치 스크립트는 저장소 밖). 도형 조건은 실제로 있을 수 있는지 본다.
- ○× 는 고친 문장으로 참 · 거짓을 다시 판정하고 까닭이 그 판정과 맞는지 읽는다. «항상 · 모든 · 만»에 반례가 없는지.
- 용어를 고친 개념은 작업표 `--all` 로 **B · C · D 를 각각** 읽는다: B 는 용어만 보고 굵은 답이 하나로 정해지는가 · C 는 문장만 보고 빈칸이 하나로 정해지는가 ·
  D 는 용어 + 예 물음만 보고 예가 풀리는가.
- 대단원 하나를 끝낼 때마다 그 대단원에서 고친 문항을 난이도마다 몇 개씩 골라 다시 읽는다(보고서에 수).

## 7. 일하는 차례 · 커밋

교육과정 차례대로 **소단원 하나씩**: 작업표 → 고침 → 작업표 `--all` 로 다시 읽기 → 남은 외부 검토 문항은 `keep --id … --note` → 훑는 줄은 `keep --section … --screen`.
대단원 하나가 끝나면:

```
npx tsx scripts/qa/concept-blank/review/progress.ts --part <p>
npx vitest run src/__tests__/unit/conceptBlankBank.test.ts src/__tests__/unit/conceptBlankSentence.test.ts src/__tests__/unit/conceptBlankReviewLedger.test.ts --pool=threads --maxWorkers=1
npx tsx scripts/qa/concept-blank/check-notation.ts --part <p> ; npx tsx scripts/qa/concept-blank/check-notation.ts --part <p>plus      # 0
npx tsx scripts/qa/concept-blank/check-leak.ts --part <p> ; npx tsx scripts/qa/concept-blank/check-leak.ts --part <p>plus              # 0
npx tsx scripts/qa/concept-blank/check-cross.ts --part <p>plus                                                                         # 0
npx prettier --write <내 파일 둘>          # 이름을 적어서만 — 폴더로 돌리지 않는다
git commit --only <내 파일 둘> <내 원장> <내 보고서> -m "…"        # 가지에만. main 에 밀지 않는다
```

- 시험은 이 묶음만, 한 번에 하나씩(`--maxWorkers=1`). 🔴 전체 `npm run test` 를 돌리지 않는다 — 일곱 트랙이 같이 돌면 기계 메모리가 바닥난다.
- 대화가 길어져 요약되면 진행표와 보고서부터 다시 읽고 이어 간다 — 파일 전체를 다시 읽지 않는다(은행 파일은 2만 줄이다. 고칠 자리는 문항의 글로 찾는다).
- 막히면 리드에게 `ask`(주입된 머리말의 명령). 방침을 스스로 바꾸지 않는다.
