## 2. 무엇이 «개념을 묻는 문항»인가

**가르는 물음: «정답으로 인정받으려면 어떤 개념 근거를 드러내야 하는가?»**
계산값 · ○× 표시 · 외운 절차만으로 정답이 다 채워지면 **계산형**이다 — 고친다. 수가 나온다고 계산형이 아니다:
«$62\times4$ 의 곱을 구하는 일»은 계산이고 «$6\times4=24$ 가 십의 묶음 $24$개라고 말하는 일»은 개념이다.

개념 백지는 하브루타 수업의 재료다 — 학생이 짝이나 선생님에게 **소리 내어 설명**하고, 듣는 쪽이 되묻는다. 좋은 문항은
- 답의 알맹이가 **말**이다(뜻 · 까닭 · 조건 · 구별 · 방법의 원리). 수는 장면일 뿐이다.
- 학생이 틀리게 말할 때 **어디를 잘못 생각했는지**가 드러난다(계산 실수가 아니라 생각의 잘못).
- **그 소단원이 새로 가르치는 개념** 하나를 겨눈다. 앞 학년 개념(곱셈의 뜻 · 곱하는 순서 바꾸기 …)은 이 소단원의 개념과 **이을 때만** 쓰고, 그것만 다시 묻는 문항으로 칸을 채우지 않는다.

개념을 묻는 «면» 아홉 — 새 글을 쓸 때 이 가운데서 고른다(면을 하나씩 기계로 찍어 내는 것도 정원 채우기다 — 그 개념에 맞는 면만):

| 면 | 물음 꼴 | 본보기 · 조심할 것 |
|---|---|---|
| ① 뜻 | 무엇인지 제 말로 | 뜻에는 **성립 조건**이 들어간다. 낱말만 바꾼 동의어 돌리기는 설명이 아니다 |
| ② 까닭 | 왜 그렇게 하는가 · 왜 그런가 | «$4\times3=12$ 의 $12$ 가 낱개 $120$개를 뜻하는 까닭» |
| ③ 조건 | 언제 성립하는가 · 조건이 바뀌면 | «십의 자리에서만 올림이 있는 조건» · 한쪽만 참인 것을 필요충분처럼 쓰지 않는다 |
| ④ 구별 | 헷갈리는 둘을 가르기 | «곱하는 순서 바꾸기와 숫자 맞바꾸기» · «기울기와 $y$절편» |
| ⑤ 잘못 찾기 | 틀린 풀이의 잘못 | **틀린 과정을 적어 준다** — 틀린 답만 주면 잘못이 하나로 안 정해진다 |
| ⑥ 관계 | 앞 개념 · 다른 방법과 어떻게 이어지나 | «나누어 곱해도 되는 까닭» · «방정식의 해와 그래프의 $x$절편» |
| ⑦ 판단 | 계산을 끝내지 않고 가리기 + 까닭 | 판단만 묻지 않는다 — 까닭이 답의 알맹이다 |
| ⑧ 표현 바꾸기 | 모형 · 그림 · 식 · 말 사이를 옮기기 | 바꾼 결과가 **최종 계산값**이면 다시 계산이다 |
| ⑨ 예 · 반례 들기 | 맞는 예 · 틀리게 만드는 예를 들고 까닭 | «언제나 세 자리 수인가 — 아닌 예를 들고 까닭을 쓰시오» |

### 3.1 `case` — 사례 카드를 보편 진술로

사례 카드는 «$73\times3$을 자리를 나누어 곱하기 → $70\times3=210$과 $3\times3=9$를 더해 {$219$}» 처럼 **원리를 수 하나에 입혀 쓴** 장이다. 차례대로 한다:

1. **이 사례가 보여 주는 원리**를 한 문장으로 적는다(«몇십몇을 몇십과 몇으로 나누어 각각 곱한 뒤 더한다»).
2. 작업표 머리의 «이 소단원에 이미 있는 개념»을 읽는다. 그 원리가 **없으면** 그것을 보편 진술로 쓴다.
3. **있으면** 같은 개념의 다른 면(§2)으로 쓴다 — 까닭(«나누어 곱해도 되는 까닭») · 조건 · 흔한 잘못 · 관계.
4. 같은 말의 되풀이밖에 안 나오면 뺀다(§4). **참인 보편 문장을 쓸 수 없으면 사례로 되돌리지 않고 뺀다.**

쓰는 법:
- 🔴 **성립 조건을 본문에 쓴다.** 사례에서 우연히 맞던 규칙을 조건 없이 일반화하는 것이 이 일의 가장 큰 함정이다(합의문 §2 —
  «십의 자리 곱의 앞 숫자가 백의 자리 숫자»는 일의 자리에서 올림이 있으면 틀린다: $39\times9=351$). 문장을 쓴 뒤 **반례 후보를 넣어 본다**:
  $0$ · $1$ · 올림(받아올림 · 받아내림)이 두 자리에서 같이 있는 경우 · 식은 다른데 값이 같은 경우 · 경계값 · 음수(중학). 한쪽만 참인 것을 «…이면 …이다 · …일 때만»으로 넓히지 않는다.
- **용어는 개념의 이름**이다 — 수가 든 식이 아니라 «자리를 나누어 곱하기» · «나누어 곱해도 되는 까닭». B(용어 → 뜻)에서 학생은 용어만 보고 설명한다.
  굵은 답이 용어에 그대로 보이면 안 된다.
- **굵은 글 `{ }` 은 계산값이 아니라 뜻의 알맹이**(낱말 · 구)다. 수 자체가 개념인 것(직각 $90^\circ$ · 단위 환산 · 자리값의 $10$)은 수가 굵어도 된다.
- A(완전 백지)에 실린다 — **소단원 이름만 보고 떠올릴 수 있는 진술**이어야 한다.
- **예를 단다** — 방법 · 흔한 잘못 · 경계를 말하는 카드는 예가 있어야 초등학생이 붙잡을 것이 있다(물음 80자 · 답 60자). 원래 사례의 수를 여기로 옮긴다.
  🔴 **예도 가르는 물음의 대상이다**(D 지면은 용어와 예 물음만 찍는다) — «$62\times5$는 $62\times4$보다 얼마 큰가? → $62$» 는 두 곱을 구해 빼면 맞는다.
  «…보다 $62$만큼 큰 까닭은? → $62$씩 한 묶음이 더 늘어서» 로 쓴다. 예 물음은 그것만 보고 풀려야 한다.
  🔴 **예의 답은 빈칸 하나에 드는 짧은 구다**(2026-10-03 덧붙임 — 리드가 시범에서 놓쳤다). D 지면은 예 물음 뒤에 빈칸 하나만 주고,
  그 빈칸은 «답의 보이는 폭 × 14px + 24px» 이 240px 에서 잘린다 — 답이 **15.4em**(한글 열다섯 자쯤)을 넘으면 손으로 쓸 자리가 없다.
  «…이기 때문이다» 문장이 아니라 근거의 알맹이만(«…라서»). 줄일 수 없으면 예의 장면을 더 단순한 것으로 바꾼다(긴 설명은 적용 칸의 몫).
  자: 은행 시험 `every map example answer fits the blank the sheet gives it` · 트랙에서는
  `npx tsx D:/tmp/concept-blank-havruta/tools/example-blank.ts . <학년>` 이 «넘는 예 0개».
- 줄 끝의 `CASE` 를 뗀다(원래 파일은 파일 끝 `markGivenCases(…)` 목록에서 그 id 를 뺀다). 표지가 남아 있으면 원장은 «남음»이다.

### 3.2 `calc` — 적용을 «개념을 써서 판단 · 설명하는 물음»으로

C 지면의 «나 · 방금 쓴 뜻으로 답하고, 까닭을 쓰시오» 칸이다(문항마다 120px 이상의 풀 자리와 «답» 줄). 물음 120자 · 답 80자.
채점 안내는 «결론과 까닭이 다 있어야 ○ — 말이 달라도 뜻이 같으면 된다»이다.

- **답은 결론 + 근거인 한 문장**이다. 교사가 «이 근거가 있으면 ○»로 가를 수 있게, 답 문장에 **꼭 있어야 하는 근거**를 묶음 · 자리 · 조건의 말로 적는다(초등은 40자 안팎).
  - `$62\times4$를 계산하시오. → $248$` ⇒ `$62\times4$의 곱이 세 자리 수가 되는 까닭을 쓰시오. → 십의 묶음 $24$개 가운데 $20$개가 백의 묶음 $2$개로 바뀌기 때문이다.`
  - `지호는 $73\times3$을 $19$라고 했다. 바른 답을 쓰시오. → $219$` ⇒ `지호는 $73\times3$에서 $7\times3=21$의 $1$만 십의 자리에 쓰고 … $19$라고 했다. 빠뜨린 것을 설명하시오. → 십의 묶음 $21$개에 든 백의 묶음 $2$개를 빠뜨렸다.`
  - `$81\times6$과 $61\times8$ 중 곱이 더 큰 것을 쓰시오.` ⇒ `$72\times3$과 $32\times7$ 가운데 어느 곱이 더 큰지 끝까지 계산하지 않고 설명하시오. → $70\times3$과 $30\times7$은 같고 더하는 $2\times3$보다 $2\times7$이 크므로 $32\times7$이 더 크다.`
  - (중2) `기울기가 $4$이고 $y$절편이 $-3$인 일차함수의 식을 구하시오. → $y=4x-3$` ⇒ `$y=4x-3$에서 $4$와 $-3$이 그래프에서 각각 무엇을 나타내는지 쓰시오. → $4$는 $x$가 $1$ 늘 때 $y$가 느는 양, $-3$은 $y$축과 만나는 점의 $y$좌표이다.`
- 🔴 **답이 값뿐이면 안 된다**(«$124$개» · «$3$, $4$» — 원장이 `isBareValue` 로 «남음»으로 읽는다). 값이 개념으로 정해지는 물음이어도 **근거를 붙여 말로** 쓴다
  («$12\,\mathrm{cm}$보다 길고 $16\,\mathrm{cm}$보다 짧다 — 원주는 지름의 $3$배보다 길고 $4$배보다 짧다»). `keep --note` 로 값 답을 두는 것은 **수 자체가 개념**일 때뿐이다(«직각은 몇 도인가»).
- 답 문장이 **물음을 되풀이**하면 안 된다(«$63\times2$를 $63+63$으로 확인할 수 있는 까닭 → $63\times2$는 $63$을 두 번 더한 것과 같다» ✗).
- 까닭이 **결론을 받쳐야** 한다 — 참인 말이어도 그 결론이 따라 나오지 않으면 틀린 답이다(«서로 다른 곱셈식이라 곱이 다르다» ✗ — 다른 식이어도 곱은 같을 수 있다).
- 개념 카드의 뜻을 **그대로 되묻지 않는다**(«올림이 무엇인지 설명하시오» — A · B 지면이 이미 하는 일이다).

### 3.3 `num` — ○× 는 «생각의 잘못»을 가른다

B 지면에서 학생은 «맞으면 ○, 틀리면 × 에 표시하고 **까닭을 쓴다**». 채점은 «표시와 까닭이 둘 다 맞아야 한 개».

- **문장이 계산 한 번으로 갈리면 다시 쓴다** — `$63\times2=136$이다. [×]` · `$91\times5$의 곱은 세 자리 수이다. [○]` · `$51\times4$는 $200$보다 크다. [○]` 는 곱을 구하면 끝난다.
  까닭만 개념으로 바꾸는 것으로는 안 된다(학생은 «$455$니까»라고 쓴다).
- 가장 좋은 ○× 는 **흔한 오개념을 그대로 적은 문장**이다: `일의 자리에서 올림이 없으면 십의 자리에서도 올림이 없다. [×] — $32\times4$는 일의 자리 곱이 $8$이라 올림이 없지만 십의 자리 곱은 $12$라 올림이 있다.`
  참인 문장도 조건과 까닭을 살피게 하면 좋다 — 거짓만 쓰지 않는다.
- 수는 **자리의 뜻 · 오개념의 장면**일 때 남긴다: `$41\times5$의 십의 자리 계산에서 얻은 $20$은 낱개 $20$개를 뜻한다. [×]` — 곱을 알아도 참 · 거짓이 저절로 안 갈린다.
- **까닭(`why`)은 완성된 계산값에 기대지 않는다.** 거짓 문장의 까닭은 실제 반례이거나 근거 개념이고, 그 문장의 참 · 거짓을 받쳐야 한다.
- 수가 들었어도 판단의 근거가 개념이면 둔다. 다 읽은 뒤 `--screen`.
- ○× 는 난이도마다 참이 4~6할쯤 되게 한다 — 답을 바꾸거나 빼면 다시 센다.

### 3.4 되풀이 · 줄에 없어도 고치는 것

- **되풀이 = 같은 판단 + 같은 근거를 수만 바꿔 요구하는 것.** 한 칸에서 하나만 남기고 나머지는 다른 개념 · 다른 면으로 쓰거나 뺀다(«$81\times6$에서 일의 자리 올림» · «$21\times6$에서 …» · «$32\times4$ …»).
  수가 달라 **올림의 유무 · 경계 조건이 달라지면** 다른 문항이다.
- **칸을 건너서** 같은 개념을 다루는 것은 된다(개념 카드가 말하고 · ○× 가 그 오개념을 가르고 · 적용이 장면에서 설명하게 한다).
  그러나 **같은 장면 · 같은 주장 · 같은 근거를 그대로 옮기지 않는다** — 수나 장면을 달리하거나 묻는 면을 달리한다.
  🔴 **«예»도 한 칸이다.** 사례의 수를 개념 카드의 예로 옮기면 그 장면은 그 예의 것이다 — 같은 식 · 같은 물음이 ○× 나 적용에 남아 있으면
  그쪽을 다른 장면으로 바꾸거나 뺀다(리드의 시범 둘째 판에서 이것이 열일곱 건 나왔다 — 합의문 §5). **한 소단원에서 한 장면(같은 식 · 같은 상황)은 한 곳에서만 쓴다.**
  세 칸과 예를 한 표로 놓고 «이 식이 어디어디에 나오나»를 세어 본다.
- 작업표를 읽다가 보이면 줄 밖이어도 고친다(보고서에 «줄 밖에서 고친 것»):
  **처음부터 있던 개념 카드의 조건 누락**(시범에서도 나왔다) · 답에 수가 없어도 계산만 하면 끝나는 적용 · 판단만 묻고 까닭이 없는 적용(«올림이 있는 자리를 쓰시오 → 십의 자리») · 사례 표지는 없지만 수 하나에 묶인 개념 카드.

## 4. 뺀다 — «정말 추가할 만한 게 없으면»

원장님은 10개 정원을 지키는 쪽이다. **먼저 채워 보고, 없을 때만 뺀다.** 그러나 **같은 말을 다시 써서 장수를 지키지 않는다** — 그것이 이번에 고치는 병이다.

- 뺄 때: 그 소단원의 개념마다 §2 의 면을 떠올려 봤는데 **이미 있는 문항과 같은 판단 · 같은 근거**밖에 안 남을 때 · 그 딱지(난이도)로 쓸 참인 글이 없을 때 · 앞 학년 개념만 다시 묻게 될 때. «쓰기 어렵다»는 까닭이 아니다.
- 보강 파일(`*-plus.ts`): 그 자리에 `RETIRED`(뒤 번호가 밀리지 않게). 파일 머리 import 에 `RETIRED` 를 더한다. 새 문항을 끝에 더하지 않는다.
- 원래 파일(`e3.ts` …)의 문항은 **빼지 않는다** — 고쳐 쓴다. 정 안 되면 리드에게 `ask`.
- 뺀 뒤 `keep --gone --id … --note "<왜 더 쓸 개념이 없는가 — 어느 문항이 이미 말하는가>"`.
- **보고하는 선**(멈추지는 않는다 — 보고서 «리드에게»에 소단원 · 칸 · 수를 적는다): 난이도 한 칸이 3장 아래로 내려갈 때 · 한 칸(30장)의 절반 넘게 뺄 때.
  시험이 막는 것은 «난이도 한 칸이 0장»뿐이다 — 0장이 정직한 답이면 리드에게 `ask`.
- 🔴 **칸마다 3장이 목표다**(2026-10-03 덧붙임 — 초6 계산 소단원 열한 곳에서 71%가 빠지고 3장 아래 칸이 13개 나왔다). 한 칸이 3장 아래로 내려가면 닫기 전에 그 소단원의 개념마다
  §2 의 아홉 면을 대어 본다 — **한 개념에서 면이 다르면 다른 문항이다**(결론과 근거가 달라진다). codex 의 «삭제»는 «그 글이 되풀이»라는 뜻이지 «그 칸에 쓸 것이 없다»는 뜻이 아니다.
  3장은 하한이 아니다 — 대어 봤는데도 같은 근거로 돌아오면 빼고, 보고서의 «3장 아래 칸»에 **대어 본 면**을 한 줄로 적는다.

## 5. 안 바꾸는 것

- **문항 id · 소단원 · 난이도 딱지 · 차례**는 그대로다. 갈래(`kind`)는 새 글에 맞게 고친다.
- **난이도는 물음의 종류가 아니다**(«까닭»이라고 상이 아니다). 딱지를 그대로 두고 **그 딱지에 맞게** 쓴다:
  **하** — 뜻 · 단서를 준 한 걸음 까닭 / **중** — 구별 · 관계 · 조건 하나 / **상** — 조건이 겹침 · 오개념 · 경계 · 단서 없는 까닭.
- 글자 상한(보이는 글자): 용어 40 · 뜻 160 · ○× 문장 · 까닭 120 · 적용 물음 120 · 답 80 · 예 물음 80 · 예 답 60. 핵심어 `{ }` 는 1~4곳.
- 한 소단원 안에서 같은 용어 · 뜻 · ○× 문장 · 적용 물음 금지, ○× 문장이 그 소단원 뜻 문장과 같은 글이면 안 된다(은행 시험 · `check-cross`).
- **그 학년 · 그 소단원까지 배운 말만** 쓴다(초3 1학기 곱셈에서 «어림 · 반올림 · 나눗셈 검산»을 끌어오지 않는다). 헷갈리면 그 소단원의 원래 은행 말투를 따르고, 보고서에 적는다.
- 🔴 교재 문장을 옮기지 않는다 — `check-leak.ts` 0건.

## 6. 표기 — cb-ten §4 · cb-review §5 그대로

- 모든 수 · 식 · 단위 · 분수 · 각은 `$...$`. 한 글자 인수도 중괄호. 수식 뒤 조사는 읽는 소리에 맞춘다.
- 🔴 **수식이 든 글은 `` r`...` `` 로 쓴다.** 🔴 **Bash · PowerShell 로 TeX 가 든 글을 쓰거나 치환하지 않는다**(역슬래시가 줄어든다) — 파일은 편집 도구로만.
- 정규식 한 번으로 여러 문항을 바꾸지 않는다 — 문항마다 읽고 쓴다.

## 7. 검산

### 7.1 스스로

- **보편 진술마다 반례 후보를 넣어 본다**(§3.1). «언제나 · 모든 · 만 · 반드시»가 든 문장, 조건을 뗀 문장은 특히.
- 예 · 까닭에 든 수는 **전부 다시 계산**한다(스크래치 스크립트는 저장소 밖).
- 고친 개념은 형식 넷으로 읽는다: A — 소단원 이름만 보고 떠올릴 수 있는가 · B — 용어만 보고 무엇을 설명할지 아는가 · C — 문장만 보고 빈칸이 하나로 정해지는가 · D — 용어 + 예 물음으로 예가 풀리고, 그 예가 계산형이 아닌가.

### 7.2 codex 에게 — 소단원마다 (원장님 «코덱스와 적절히 협업해»)

소단원 하나를 다 고치고 `keep` 까지 닫은 뒤:

```
npx tsx scripts/qa/concept-blank/havruta/review.ts --part <p> --section "<소단원 열쇠>"
```

요청서(그 소단원의 범위 · 줄에 안 선 개념 · 고친 문항의 전 → 후 · 합의문 §3 의 기준)를 만들어 codex 에 보내고 답을 저장소 **밖** `D:\tmp\concept-blank-havruta\review\<p>\` 에 적는다(5~8분).
기다리지 말고 **다음 소단원을 한다**(배경으로 돌린다). 답이 오면:

- 지적을 **은행에 대어 가린다** — 수학 오류(반례) · 여전히 계산형 · 되풀이 · 범위 밖 · 모호. 맞는 지적은 고치고, 안 받는 지적은 까닭을 한 줄로(보고서에 갈래별 수).
  codex 가 틀릴 때도 있다 — 반례를 **직접 계산해** 본다. 그러나 리드의 첫 시범에서는 지적의 대부분이 맞았다(합의문 §2).
- 고친 뒤 그 소단원을 다시 보내지는 않는다(리드가 표본으로 다시 본다). 리드의 시범도 둘째 판에서 스물여덟 건을 받았다 — 대부분 «같은 장면을 돌려씀»이었다.
  같은 갈래의 지적이 소단원마다 되풀이되면 **그 갈래를 다음 소단원에서는 쓰기 전에** 막는다(보고서에 «되풀이해 받은 지적»으로 적는다).
- 요청서가 25KB 를 크게 넘으면(문항이 90개인 소단원) 답이 10분을 넘긴다 — 그래도 한 번에 보낸다(되풀이는 소단원 전체를 봐야 보인다).
- 동시에 둘까지만 띄운다(일곱 트랙이 같이 부른다).
- 🔴 **줄 밖 개념 카드의 «예»가 계산형이라는 지적은 받지 않는다**(2026-10-03 덧붙임 — 중1 첫 소단원에서 지적 34건 중 20건이 이것이었다). 이번 일의 범위는 원장의 세 줄이고,
  지도(D)의 «예»는 뜻을 쓴 뒤 드는 작은 사례다(«$13$의 약수를 모두 쓰면?»). 줄 밖 카드의 뜻을 «절차 → 까닭»으로 다시 쓰는 것도 하지 않는다.
  줄 밖에서 고치는 것은 §3.4 끝 줄 그대로다(조건 누락 · 계산만 하면 끝나는 적용 · 판단만 묻고 까닭이 없는 적용 · 수 하나에 묶인 카드) — 여기에 수학 오류 · 고친 문항과 같은 장면 겹침 · 예의 답이 빈칸을 넘는 것.
  **네가 다시 쓰는 카드의 예는 §3 그대로**다. 보고서에 «줄 밖 예 가운데 codex 가 계산형이라 한 수»를 소단원마다 적는다(리드가 모아 원장님께 범위를 여쭌다).

## 8. 일하는 차례 · 커밋

교육과정 차례대로 **소단원 하나씩**: 작업표 → (개념 → ○× → 적용 차례로) 고침 → 작업표 `--all` 로 다시 읽기 → `keep`(뺌 · 둠) → `--screen` → `review.ts`(배경) → 다음 소단원.
소단원 하나의 세 칸을 **같이** 본다 — 개념을 먼저 정리해야 ○× · 적용이 무엇을 겨눌지 정해진다.

대단원 하나가 끝나면(그 대단원의 검산 답을 다 반영한 뒤):

```
npx tsx scripts/qa/concept-blank/havruta/progress.ts --part <p>
npx vitest run src/__tests__/unit/conceptBlankBank.test.ts src/__tests__/unit/conceptBlankSentence.test.ts src/__tests__/unit/conceptBlankHavrutaLedger.test.ts src/__tests__/unit/conceptBlankReviewLedger.test.ts --pool=threads --maxWorkers=1
npx tsx scripts/qa/concept-blank/check-notation.ts --part <p> ; npx tsx scripts/qa/concept-blank/check-notation.ts --part <p>plus      # 0
npx tsx scripts/qa/concept-blank/check-leak.ts --part <p> ; npx tsx scripts/qa/concept-blank/check-leak.ts --part <p>plus              # 0
npx tsx scripts/qa/concept-blank/check-cross.ts --part <p>plus                                                                         # 0
npx prettier --write <내 은행 파일 둘>          # 이름을 적어서만 — 폴더로 돌리지 않는다. 원장 JSON 은 prettier 를 돌리지 않는다
git commit --only <내 은행 파일 둘> <내 원장> <내 보고서> -m "…"        # 가지에만. main 에 밀지 않는다
```

- 시험은 이 묶음만, 한 번에 하나씩(`--maxWorkers=1`). 🔴 전체 `npm run test` 를 돌리지 않는다 — 일곱 트랙이 같이 돌면 기계 메모리가 바닥난다.
- 🔴 **대단원마다 커밋한다** — 리드가 끝난 대단원부터 가져가 지면 검사 · 병합 · 푸시한다(끊어서 민다). 커밋한 대단원은 시험이 초록인 상태여야 한다.
- 보고서는 대단원을 끝낼 때마다 이어 쓴다(끝에 한꺼번에 쓰지 않는다 — 대화가 요약되면 수를 잃는다).
- 대화가 길어져 요약되면 진행표와 보고서부터 다시 읽고 이어 간다 — 파일 전체를 다시 읽지 않는다(은행 파일은 2~3만 줄이다. 고칠 자리는 문항의 글로 찾는다).
- 막히면 리드에게 `ask`(주입된 머리말의 명령). 방침을 스스로 바꾸지 않는다.
