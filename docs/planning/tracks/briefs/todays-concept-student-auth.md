## 2. 리드가 정한 설계

### 2.1 🔴 학생 세션은 기존 코드에게 «로그인 안 한 사람»으로 보여야 한다

지금 코드는 세션이 있으면 원장이라고 믿는 자리가 많다 — `proxy.ts` 는 **`role` 이 없는 세션을 원장으로 본다**(주석에
이유가 있다), API 는 대개 `session?.user?.id` 만 보고 들어간다. 학생 세션이 `user.id` 를 가지면 **기존 API 전부가
학생에게 열린다.** 그래서:

- 학생 토큰에는 **`user.id` 를 두지 않는다.** 학생 정보는 별도 칸(예: `session.student = { accountId, studentId, name }`)에만.
- `jwt` 콜백은 지금 매번 `db.user` 를 다시 읽는다 — 학생 토큰은 **그 길을 타지 않고** 학생 계정을 다시 읽는다
  (꺼진 계정·지워진 학생이면 세션을 끊는다). 원장 토큰의 동작은 **한 줄도 바뀌면 안 된다.**
- `proxy.ts` 에 학생 갈래를 넣는다 — 학생 세션은 **허용 목록**(학생 화면 경로 · 학생 API · 로그아웃 · 비밀번호 바꾸기)
  밖으로 못 나간다. 허용 목록은 `routeAccess.ts` 처럼 **순수 함수 한 곳**에 둔다.
- Auth.js `session` 콜백의 기본값은 `session.user` 를 **빈 객체로라도** 만든다 — `if (!session?.user)` 만 보는 자리가 있으면
  학생이 통과한다. **전수로 찾는다**: `auth()` · `getServerSession` 류를 부르는 모든 API 라우트와 서버 액션을 목록으로 뽑고,
  학생 세션을 흉내 내 **전부 401/403** 인지 표로 시험한다(모집단은 파일 목록에서 **스스로** 뽑는다 — 손 목록 금지,
  2026-08-18 교훈 「세는 쪽과 고치는 쪽이 같이 눈이 먼다」).

### 2.3 발급·로그인·비밀번호 (서버 쪽, 화면 없이)

- 발급은 **원장만**, **학생 한 명씩**(D-124 ⑷). 그 학생의 반이 발급하는 원장 소유여야 한다(`Class.userId`) — 남의 반 학생에게
  발급하면 거부. 이미 계정이 있으면 거부(«다시 발급»은 비밀번호만 새로). 끄기는 `disabledAt` 만 찍고 지우지 않는다(수맥 규칙).
  모두 `AccountAuditLog` 에 남긴다(기존 `recordAudit`).
- 초기 비밀번호는 `concept-port` 가 옮긴 `initialPassword.ts` 를 쓴다. **응답에 한 번만** 싣는다.
- 로그인: 아이디 정규화(대소문자·앞뒤 공백) → 계정 → 꺼짐이면 실패 → bcrypt 비교. 실패·성공 감사 기록.
  **실패 문구는 «아이디 또는 비밀번호가 맞지 않습니다» 하나** — 아이디 존재 여부를 흘리지 않는다.
- 첫 로그인(`mustChangePassword`)이면 비밀번호 바꾸기 외에는 못 간다 — proxy 허용 목록의 한 갈래.
- 아이디 형식·비밀번호 규칙(길이 등)은 **Hi-fi 단계에서 원장님께 여쭌다** — 지금은 상수 한 곳에 두고 보고에 적는다.

### 2.4 시청 기록 API

- 학생 세션만: «본 지점 · %» 를 받아 `concept-port` 의 시청 규칙(뒤로 안 감 · 한 번 완료면 완료)으로 올려 쓴다.
