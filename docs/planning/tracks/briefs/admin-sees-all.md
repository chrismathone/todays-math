# 브리프 — 관리자는 학원 운영 데이터를 전부 본다 (D-130)

결정: **D-130**(07 Decision Log). **먼저 읽어라.** 관련: D-129 · `docs/planning/22-daily-auto-test.md`.

## 1. 목표 한 줄

원장님 계정(`st2000423@gmail.com`, `isAdmin`)은 반이 0개인데 실제 데이터는 역할 계정
(`test_o` 원장 · `test_t` 선생님 · `test_s` 학생)에 흩어져 있다. **반을 옮기지 않고**,
관리자가 **학원 운영 데이터의 소유 울타리를 넘게** 한다.

## 2. 넘는 것 · 안 넘는 것

**넘는다(읽기 + 쓰기)** — 반 · 학생 · 진도 · **진도 계획**(`progress_plan`) · 시험지 ·
「오늘의 확인테스트」 · 기본 범위(`/api/tests/default-range`) · 작업실 개요 숫자.

**안 넘는다(지금 그대로)** — 장바구니(`basket`) · 작업실 문서·자료(비공개 자료) ·
예측 회차 · 문항 소유(`Problem.userId` — 공용 풀 규칙 D-31 그대로) · eywa 갈래(`isEywaOwner`).

## 3. 어떻게

- 🔴 **판정은 한 곳.** 라우트마다 `userId: session.id` 를 적지 말고 **소유 범위 헬퍼 하나**를 만들어
  거기서만 «관리자면 넓힌다»를 판단해라(이름·모양은 네가 정하고 보고서에 근거를 적어라).
  지금 그렇게 거르는 자리는 최소 이만큼이다 — `api/classes/route.ts` · `api/classes/[id]` ·
  `api/tests/route.ts` · `api/tests/daily-review/route.ts`(계획 갈래) · `api/tests/default-range` ·
  `api/studio/overview` · `api/dev/unified/overview` · 진도 쓰기 자리(`api/progress`·`advance`).
  **전수로 찾아라** — 위 목록을 믿지 말고 `userId: session.id` 를 전부 훑어 표로 보고해라.
- **쓰기도 넘는다** — 관리자는 남의 반에 진도·계획을 넣을 수 있어야 한다(그게 이 결정의 목적이다).
  단 **개인 작업물 라우트는 건드리지 마라**(§2).
- **자동 출제**(`src/lib/tests/autoDraftOwner.ts` · `runAutoDraft.ts`) — 소유자가 관리자면 **전 반**을 돈다.
  지금은 소유자의 반만 돈다. 같은 헬퍼를 쓴다.
- **관리자가 아닌 계정은 지금 그대로다.** 이게 이 작업의 반증 축이다 — 넓히다가 남의 반이 새면
  2026-09-07 사고(새 계정이 원장님 학원 데이터를 봄)의 재판이다.

## 4. 시험 (TDD — RED→GREEN)

- **핵심 반증 시험 둘**: ⑴ 관리자 아닌 계정은 남의 반·시험지·계획이 **안 보인다**(넓히기 전과 같다).
  ⑵ 관리자는 **전부 보인다**. 두 시험을 같은 픽스처로 나란히 두어라.
- 쓰기도 같은 짝으로 — 관리자는 남의 반에 진도를 넣을 수 있고, 아닌 계정은 403/404 그대로.
- 개인 작업물(장바구니·작업실 문서)은 **관리자여도 안 넘는다**는 시험을 꼭 넣어라.
- 🔴 **변이 하네스** `scripts/qa/mutate-admin-scope.ts` — 헬퍼의 «관리자면 넓힌다»를 끄면 빨개지고,
  **거꾸로 «항상 넓힌다»로 바꿔도 빨개져야 한다**(한쪽만 지키면 새는 쪽을 못 본다).
  ⚠️ `rmSync` 금지(`noRmSync.test.ts`) — 임시 파일 + `unlinkSync`.
- 관문: `npx tsc --noEmit` 0 · 관련 시험 초록 · `npm run lint` · `npm run build`.
