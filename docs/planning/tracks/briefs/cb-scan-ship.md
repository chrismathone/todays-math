## 합의 (확정 — 이대로 짓는다)

1. **지면 P1** — 20mm QR 을 머리 오른쪽 독립 열에. 학생지 · 채점표 모든 쪽. 채점표 사진의 제출은 서버가 거절한다. 글자 코드는 그대로 둔다.
   **모서리 표식 넷**을 더한다(작고 조용하게 — 지면의 인상을 바꾸지 않는다. 쪽 나눔이 달라지지 않게 본문 영역 밖 여백에).
2. **식별자** — 인쇄(발행) 때 서버에 스냅숏을 저장하고 **불투명 발행 ID** 를 낸다. QR 은 `…/concept-blank/scan?p=<발행 ID>&page=<n>&part=student|key` 꼴
   (정답 · 이름 · 비밀 없음). `pick` 고르기와 코드가 정원을 넘는 지면도 같은 길. 같은 발행물의 재인쇄는 같은 ID.
   발행 때 **쪽별 답 칸의 지면 좌표와 표식 위치**를 같이 얼린다(서버가 믿을 수 있는 길로 — 브라우저가 보낸 임의 좌표를 검증 없이 기준으로 삼지 않는다. 길을 정하고 까닭을 보고서에).
   저장 전 옛 지면은 자동 채점하지 않는다(재발행 안내).
3. **촬영 C1** — 현재 쪽 촬영이 먼저, 찍은 쪽은 아래 `PaperStrip`. 교사는 첫 촬영 전에 학생을 고른다(`PickerDialog` — C4 의 차례만).
   빠진 쪽이 있으면 제출을 막고 어느 쪽인지 알린다. 사진 속 QR 로 다른 발행물 · 다른 쪽 · 채점표를 가른다. «채점 전에 찍는다» 안내 · 외부 AI(Claude) 전송 고지.
   폰 사진은 본문 상한(4.5MB) 아래로 브라우저에서 줄인다(`studio-ai` 의 축소 사다리를 쓴다).
4. **읽은 답 확인 V3 꼴** — 답 칸 테두리 · 번호는 필기 바깥(좁으면 확대로) · 전체 학생지에서 이어지는 번호 · 누르면 그 칸 확대 · 사진 아래 같은 번호 입력 칸
   («확인 번호 · 쪽 · 문항»). **학생 수정은 공개 전까지만.** «종이에도 비워 뒀어요»(빈 답 → ×)와 «지금 확인하기 어려워요»(확인 필요)를 가른다.
   못 읽은 칸만 기본으로 보이되 전체 판독문을 펼쳐 고칠 수 있다(정답 · 판정은 안 보인다). 고친 칸에 «직접 입력». 분수 · 도 · 좌표 입력 보조.
   **사진 맞춤이 불확실하면 번호 · 테두리를 숨기고** 쪽 · 문항 목록으로 물러선다(틀린 칸에 그럴듯한 번호를 붙이지 않는다).
5. **결과** — 학생: **R2**(지면 순서의 문항별 ○ △ × 확인 필요 + 한 줄 까닭) + 확인 필요만 보기 · 첫 항목으로 가기. 종합 점수 없음 —
   상태별 개수만(단위를 붙여서). △ 옆에 빠진 뜻. 교사(넓은 화면): **R4** — 사진의 그 칸 · 처음 읽은 글 · 직접 입력 · 자동 판정 · 교사 수정을 나란히, 까닭과 함께 고친다.
   채점이 끝나면 바로 공개. 공개 뒤 학생은 고치지 못한다(교사만).
6. **형식** — 자동 판정은 B · C · 현재 D · E. **A 와 옛 D 는 «교사 확인»**으로 남긴다(숨기지 않는다).
7. **모델 · 값** — 읽기 Opus 5.5 high · 통째 한 번(뒷단 그대로). 월 상한은 **호출 전 선예약**으로 바꾼다(입력 상한 + 최대 출력으로 상계 → 정산 때 차액을 푼다).
   월 100달러 · UTC 달 · 서비스 전체 합. 사용량 저장소의 **DB 구현**을 짓는다. 상한 · 꺼짐 · 바쁨은 학생에게 까닭과 함께 알리고, 받아 둔 사진 · 읽기는 버리지 않는다(다시 값을 치르지 않게).
8. **권한** — 새 «배정» 표를 만들지 않는다. 학생은 **발행한 교사가 `ownerScope` 로 볼 수 있는 학생**일 때만 그 발행물에 제출한다(서버 검사 — 본문의 학생 ID · 코드를 믿지 않는다).
   교사의 대리 촬영도 같은 검사. NULL 지점을 전체로 읽지 않는다. 학생 관문의 허용 목록(2026-10-20 교훈)에 새 주소를 넣고 전수 시험을 같이 고친다.
   메뉴는 기존 «개념 백지» 메뉴의 켜짐을 따른다(새 메뉴 값을 만들지 않는다).
9. **사진 보존** — 앱 Supabase **비공개** 버킷. 채점에 쓴 사진 30일 · 미제출 · 실패 · 교체된 사진 7일. 열람은 권한 확인 뒤 짧은 서명 주소. 지우는 길(기한 · 교사의 조기 삭제)과 실패 재시도.
   지우는 일을 돌릴 예약 작업이 필요하면 기존 방식(`vercel.json` 의 것)을 따른다. 손글씨 이름으로 학생을 찾지 않는다.

## 차례

1. **Hi-fi (D-07)** — `/dev/concept-blank-scan-hifi` 에 위 합의 구조 위의 Hi-fi **4 ~ 5안**(지면 머리+QR+표식 · 촬영 · 읽은 답 확인 · 학생 결과 · 교사 결과).
   제품 토큰 · 글꼴 · 부품 그대로, 제품 지면 치수 그대로, 실제 은행의 고르기로. 안마다 다른 점 · 약점 한 줄. 그 가운데 하나를 고르고
   (기준: 05 §0 의 정체성 · 금지 목록 · 기존 개념 백지 화면과의 일관 · 폰 390 폭에서의 읽힘 · D-30) 고른 까닭과 버린 까닭을 보고서에 적은 뒤 **멈추지 말고** 그 안으로 구현한다.
   Hi-fi 화면은 남겨 둔다(원장님이 나중에 보신다). `/dev` 가드 전수 시험에 넣는다.
2. **DB** — `prisma/schema.prisma` 에 모델을 더하고 마이그레이션 SQL 을 쓴다(초안 `prisma/drafts/concept-blank-scan/` 를 다듬어). **추가만**(기존 표 · 칸 · CHECK 를 바꾸지 않는다).
   🔴 **공유 DB 에 적용하지 않는다** — 워크트리에는 `.env` 가 없고, 적용은 리드가 검수 뒤에 한다. 적용 차례 · 되돌림 · 표가 없을 때 코드가 어떻게 되는지(503 과 까닭)를 보고서에. `prisma generate` 는 된다.
3. **발행** — 개념 백지 인쇄 길에 «스냅숏 저장 → 발행 ID → QR · 표식이 실린 지면». 저장이 실패하면 QR 없는 지금의 지면으로 그대로 인쇄된다(인쇄를 막지 않는다 · 알린다).
4. **촬영 → 읽기 → 확인 → 채점 → 결과 → 교사 고침** 의 라우트와 화면. 라우트는 `withErrorLog` · 전수 가드에 맞춘다. 읽던 요청은 화면이 떠나도 받아 둔다.
5. **지우기 · 상한 · 꺼짐** 의 흐름.
