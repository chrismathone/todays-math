## 1. 무엇을 알아내야 하나 — 물음 다섯

### 물음 ① **우리 중등 사다리의 꼭대기가 외부 눈금의 어디에 닿나**

초등에서 나온 답은 「우리 **심화** = 저쪽 6단 중 **넷째**(실력(중))」였고, 근거는
표본 비교가 아니라 **같은 문형의 직접 대응**이었다(저쪽이 실력(중)에 두는 문형이
우리에게는 심화더라). 중등에서도 **문형을 직접 대라.**

⚠️ **초등의 답을 물려받지 마라.** 중등은 문자·방정식이 있어 도구가 다르다.
저쪽이 중등에도 6단을 여는지부터 확인하고, 아니면 그 사실을 적어라.

### 물음 ② 🔴 **모집단이 둘인가** — 초등에서 이것이 제일 컸다

초등은 `generateElementaryProblem`(갈래)와 `generateElementaryForm`(문형) 둘이었고
**적재기가 부르는 것은 문형**인데 판정기들은 갈래를 재고 있었다.

중등에서 같은 물음을 던져라:

```
src/lib/middle/generate.ts    registeredTypes() · typesForSection() ·
                              generateMiddleProblem() · generateMiddleSet()
적재기                        scripts/import/load-engine-problems.ts 가 **무엇을 부르나**
```

**「지면에 나가는 난이도 분포를 정하는 것이 무엇인가」**를 코드로 짚고, 판정기들이
재는 것과 **같은지** 확인하라. 다르면 그것이 이 조사의 첫째 발견이다.

### 물음 ③ **갈래가 어디서 오나** — 중등은 초등과 구조가 다르다

`registeredTypes()` 의 한 항목에는 `difficulty` 가 **없다**
(키: `key, grade, unitSection, rpmBook, rpmMinor, rpmType, rpmTitle, handler`).
갈래는 `src/lib/middle/combo.ts` 의 `resolveMiddleTier(declared, content, hasFigure)` 가
정하는데, 그 함수는 **`기본` 을 `연산` 으로 내리기만 한다**:

```ts
if (declared !== "기본" || hasFigure) return declared;
const only = loneInstruction(content);
if (!only || !OPERATION_INSTRUCTION.test(only)) return declared;
return "연산";
```

그러면 `declared` 는 어디서 오나? **핸들러가 스스로 붙이나, 유형 표에 있나, 적재기가
정하나** — 코드로 짚어라. 그리고 **중1/2/3 의 갈래 분포를 실제로 세라**(몇 %가 심화인가).

D-113 ⑼ 는 「중등은 아직 핵심 넷만 낸다 — 등록값에 확대 갈래가 없다」고 적어 두었다.
그 문장이 **지금도 참인지** 확인하는 것도 네 일이다.

### 물음 ④ 🔴 **D-115 의 되짚기 잣대가 중등에도 서나** — 그대로 물려받지 마라

D-115 확정 잣대(`docs/planning/07-coding-convention.md` D-115 를 **전문으로 읽어라**):

```
심화하   되짚기 사슬의 마디마다 값이 하나로 굳는다
심화중   굳지 않는 마디가 하나 있고 **그 소단원의 성질**이 그것을 굳힌다
심화상   성질로 못 굳혀 **만들어 견주어야** 하고, 후보를 발문이 주지 않는다
⑾       굳히는 성질이 후보를 «끝까지 계산하지 않고» 걸러 내면 중,
         다 계산해 견주어야 하면 상. **참은 «해설이 밟는 길»이다.**
```

**중등에서는 이 축이 무너질 수 있다** — 되짚기가 중등의 «기본 도구»(방정식)라
초등에서처럼 위쪽에만 몰려 있지 않을 수 있다. 그러니 **의견이 아니라 측정으로 답하라**:

```
㉠ 갈래마다 「되짚기 사슬의 마디 수」를 세어 분포를 낸다  → 축이 갈리나?
㉡ 반증 ④ (뒤집힘 필터)를 전 소단원에 댄다             → 몇 곳이 «안 갈린다»로 나오나?
㉢ 갈린다면 그 축을 쓰고, 안 갈리면 **중등만의 축을 찾아 같은 방법으로 검증하라.**
```

⚠️ **초등에서 «열거 축»이 기각된 까닭을 먼저 읽어라**(D-115 ⑵). 그럴듯한 축을 고르고
   나중에 재면 늦다 — **후보 축 둘 이상을 같은 모집단에 나란히 대서** 고른다.

### 물음 ⑤ **어디가 가장 얇나** — 대단원마다 한 줄

초등 벤치가 낸 꼴: 「초5 2-4 소수의 곱셈 여섯 소단원 — 심화가 전부 `a×□=b` 한 걸음
역산이다」. 중등에서도 **대단원마다** 「이 대단원의 심화는 무엇을 시키나」를 한 줄로 적고,
같은 문형이 되풀이되는 자리를 **세어서** 짚어라.

## 3. 이 저장소가 이미 데인 자리 — 되풀이하지 마라

`CLAUDE.md` 의 Lessons Learned 를 읽어라. 이 조사에 특히 걸리는 것:

```
· 지표가 **실패를 셀 수 있는 형태인가** — 「0건」은 «깨끗»과 «못 셈»을 안 가른다.
  판정기를 만들면 **일부러 걸리는 입력**을 넣어 빨개지는 것을 먼저 보아라.
· 판정자를 눈금 맞출 때 **양성 대조군과 음성 대조군이 둘 다** 있어야 한다.
  양성만 대면 재현율만 재고 «지어냄»은 구조적으로 0이 된다.
· 「N passed」는 N이 전부인지 말해 주지 않는다 — **분모**를 먼저 지켜라.
· **표에 판정을 적을 때 «돌려서 나온 것»인지 «읽고 적은 것»인지 구분하라.**
  후자는 근거처럼 보이지만 측정이 아니다(2026-08-25).
· **파생물을 정본과 견줄 때 «누가 무엇을 덧붙였나»를 먼저 빼라** — 적재기가
  객관식 본문에 보기를 덧붙인다. 안 빼면 「다르다」의 절반이 파이프라인이다.
· 판정이 **놀라운 값**을 내면 판정 대상보다 **«재는 쪽»을 먼저 의심하라.**
· 역슬래시가 든 코드는 **Edit 도구로** 써라 — heredoc 이 한 겹 벗긴다.
```
