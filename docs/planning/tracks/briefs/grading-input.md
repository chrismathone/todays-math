# 브리프 — 채점 입력 화면 (D-134 트랙 1)

확정: **19 §5′**(D-07 **A안** — 표: 학생 × 문항, 원장님이 결정을 위임하셔서 codex·grok 협의로 확정됐다) ·
**23 §1·§4**(왜 이것이 먼저인가 · 거짓말하는 자리 넷) · 시안 `/dev/retry-wire`(**A 탭**, 실데이터 7×8=56칸).
**먼저 읽어라.** `src/lib/generator/planRetry.ts` 머리말도 읽어라 — 이 트랙이 여는 문의 반대쪽이다.

## 0. 왜 이것이 첫 트랙인가

공유 DB 실측(23 §1.1): `test` **13행**인데 `test_result` **0행** · `problem_answer` **0행** · `analysis_report` **0행**.
**뒷단은 다 있는데 부르는 화면이 없어서** 채점이 한 번도 안 들어왔다. 이 화면 하나가
「학생별 성취도」·「학부모 리포트」·「오답 재출제」를 **전부** 연다.

## 1. 만들 것

### 1.1 🔴 세 상태를 담을 자리 — 계약과 스키마

지금 `ProblemAnswer` 는 `isCorrect` **참/거짓 둘뿐**이고 `selectedChoice`·`essayScore` 가 둘 다 NULL 이면
**오답 0점**으로 채점된다. 그래서 다음 둘을 못 가른다:
「**오답 표시로 채점했다**(A안 — 틀린 번호만)」 vs 「**응답을 전사했다**(기존 `/submit`)」.
그리고 「**아직 안 봄**」과 「**결시**」도 자리가 없다.

- **`TestResult.gradingMode`** — `marks`(틀린 번호만) | `answers`(전량 전사). 기본값은 `answers`
  (기존 `/submit` 의 뜻을 안 바꾼다).
- **`TestResult.absent`** — 결시. `Boolean @default(false)`.
- 🔴 **`TestResult.score` · `predictedScore` 를 nullable 로 바꾼다.** 결시를 `score = 0` 으로 적으면
  그 0이 평균·추이·리포트에 **진짜 0점처럼** 실린다(23 §4 ③). 지금 **행이 0개**라 바꿔도 잃을 데이터가 없다 —
  **지금이 유일하게 싼 시점이다.** 계약(`testresult.contract.ts`)도 같이 `.nullable()`.
  `AnalysisReport` 는 결시면 **만들지 않는다.**
- **「아직 안 봄」은 행이 없는 것**이다 — `TestResult` 행이 없으면 미채점. 이 뜻을 스키마 주석에 박아라.
- `gradingMode = "marks"` 일 때도 **`ProblemAnswer` 행은 전 문항** 만든다(`selectedChoice`·`essayScore` 는 NULL,
  `isCorrect` 는 화면이 표시한 것만 false). 행이 없는 것을 «맞음»으로 읽게 두면 두 방식이 서로를 오염시킨다.
- **마이그레이션**: `prisma/migrations/2026091700xxxx_test_result_grading_mode/`.
  적용기 `scripts/qa/apply-grading-mode-migration.ts` — `apply-test-auto-draft-migration.ts` 와 같은 결
  (기본 dry-run · `ALLOW_SHARED_IMPORT=1 --apply` · 적용 뒤 칸 확인).
  🔴 **공유 DB 에 적용하지 마라.** 리드가 원장님 확인을 받고 적용한다. 이 워크트리엔 `.env` 도 없다.

### 1.2 채점 입력 API

- 기존 `POST /api/tests/{id}/submit`(전량 전사)은 **뜻을 바꾸지 마라.** 예측 문제지 쪽이 쓴다.
- 새 경로 또는 같은 경로의 다른 본문 — **네가 정하고 보고서 ②에 근거를 적어라.** 받아야 하는 것은
  학생 한 명당 «틀린 문항 번호 배열» + «결시» 둘이고, **한 시험지의 여러 학생을 한 번에** 받아야 한다
  (A안은 표 하나에서 7명을 찍고 한 번 저장한다).
- 🔴 **미채점 행이 남은 채로 저장되면 안 된다** — 요청이 이번에 채점한 학생을 전부 실어 오고,
  서버는 **시험지 대상 학생 중 빠진 이름**이 있으면 거절한다. 거절 문구는 **몇 명이 아니라 이름을 나열**한다(19 §5′).
- 소유 범위는 `src/lib/ownerScope.ts` 하나만 묻는다(D-130). 라우트에서 `isAdmin` 을 새로 읽지 마라.
- 재채점(정정)은 지금처럼 막지 않는다 — 같은 `(testId, studentId)` 에 새 행, 최신은 `takenAt` 내림차순.

### 1.3 화면 — **A안** (`/tests/{id}/grade`)

`/dev/retry-wire` **A 탭이 SSOT 다.** 시안에 없는 모양을 지어내지 마라.

- 표 한 장: **행 = 학생 · 열 = 문항 번호**. 칸 세 상태 — `점선 = 아직 안 봄` / `○ = 맞음` / `✕ = 틀림`.
- 학생 줄 끝의 단추가 **누르기 전부터** `0개 끝` / `2개 끝` 이라 적어 **무엇을 주장하는지** 보인다(19 §5′).
- 🔴 **일괄 단추(«전원 응시» · «전부 맞음»)를 두지 마라** — 결석생을 한 번에 만점으로 굳힌다.
- **결시**는 학생 줄에서 따로 표시한다(칸을 전부 ✕ 로 찍는 것과 **다른 뜻**이다).
- 미채점 학생이 남으면 저장이 잠기고 **이름을 나열**한다.
- 진입점: **시험지 화면 `/tests/{id}` 에 «채점» 단추 하나.** 확정(`confirmed`)·인쇄(`printed`) 상태에서만 보인다.
  초안(`draft`)에는 안 보인다 — 아직 나가지 않은 시험지다. 메인 «오늘의 확인테스트» 줄은 **건드리지 마라**(§2).
- 문구는 D-08(간결·사무적, 느낌표·이모지 없음) · 어포던스는 D-30(`npm run lint:affordance`).

### 1.4 채점 뒤 보이는 것 — **최소한만**

저장 직후 그 시험지의 **학생별 점수 목록**(이름 · 맞은 개수 / 전체 · 결시)을 같은 화면에 띄운다.
🔴 **단원별 정답률·난이도 분포를 여기서 그리지 마라** — 8문항 한 회차는 단원당 1~2문항이라 통계가 아니다(23 §4 ①).
그 축은 트랙 2가 **기간 누적**에서 연다.

## 2. 안 하는 것

- 🔴 **리포트 화면·학부모 지면·숙제·태도·출결** — 전부 다른 트랙이거나 원장님 확정 대기다(23 §7).
- 🔴 **`planRetry` 배선(오답 → 복습지)** — 트랙 5다. 이 워크트리에서 `selectProblems` 를 건드리지 마라.
- 🔴 **메인 «오늘의 확인테스트» 줄**(`src/components/main/DailyReviewSection.tsx` · `api/tests/daily-review`) —
  지난주에 크게 고친 자리다(D-133). 채점 진입점을 거기 붙이지 마라. 붙일 자리 제안만 보고서 ⑤에.
- **공유 DB 쓰기**(마이그레이션 **적용** 포함) · eywa · 인쇄 지면.
- 시험지 목록 화면(트랙 6).
