**판정: APPROVE**

**남은 필수 차단 사항: 없음**

이 개정안은 구현 명세로 충분하다. 승인은 테스트나 구현이 통과했다는 뜻이 아니다.

**Wire A / H1: 동의한다.** 지점 목록에서 지점 상세의 계정·사용 메뉴로 들어가는 구조는 URL에 지점 맥락을 남기고 기존 계정 화면을 재사용한다. 시각은 현재 흰 패널, 절제된 파란 강조, 기존 밀도와 컴포넌트를 유지한다. 사용자가 위임한 기존 디자인 범위 안의 선택이다.

**원장이 지점 체크리스트를 따름: 동의한다.** 실제 메뉴는 지점 허용, 개인 허용, 기존 시범 운영 제한의 교집합이다. 원장·지점 관리자 직책은 메뉴 전체 허용권이 아니다. 최고관리자는 `isSuperAdmin`으로 구분하고, 업무 메뉴는 소속 지점·개인 설정을 따른다. `/admin`과 운영 복구는 별도 권한이다. 미소속 계정은 개인 정책만 따른다. 활성 원장 2명과 미소속 최고관리자 1명의 개인 차단값이 모두 비어 있고, 빈 배열은 전체 허용이므로 원장 자동 허용을 제거해도 기존 원장 메뉴는 유지된다.

**개인 설정 보존: 동의한다.** 저장값은 차단 목록이다. 강사 기존 차단값은 유지하고 원장 개인 설정을 일괄 초기화하지 않는다. 지점 제한은 개인 차단 목록을 덮어쓰지 않는다. 체크 상태는 지점 상한을 반영한 실제 허용 메뉴를 보여주고, `configuredMenus` 원본은 보존한다. 저장은 그 원본을 기존 `menus` 키로 보내며 계산 결과를 다시 쓰지 않는다. 메뉴가 바뀌지 않은 이름·이메일 저장은 `menus`를 보내지 않는다. 지점에서 다시 켜면 보존된 개인 설정이 돌아온다. 적용 전 익명 집계로 차단값 유무를 다시 확인한다.

**기존 관리 권한 범위: 동의한다.** 지점 체크리스트와 관리 콘솔 계정 관리는 최고관리자 전용이다. 원장의 기존 `/branch` 기능은 현재 동작 그대로 두고, 지점 메뉴 상한 변경이나 `/admin` API 확장은 하지 않는다. `isAdmin`은 소유권 판정에 남기고 메뉴 우회만 제거한다. 학생 `/learn`, 동기화·배치, `ownerScope` 확대는 범위 밖이다. eywa 잠금, 마지막 원장 보호, 승인·정지·삭제, 세션 폐기는 유지한다.

**조건부 갱신·감사: 동의한다.** 메뉴 PATCH에 `expectedMenuRevision`이 없으면 400이다. 일치 행이 정확히 1개일 때만 성공하고, 같은 트랜잭션에서 revision을 올리며 기존 `AccountAuditLog`에 이전·이후 메뉴, actor, branchId, revision을 남긴다. 감사 실패 시 갱신도 롤백한다. 이름만 변경하는 PATCH는 revision을 요구하거나 증가시키지 않는다. 계정 변경은 `expectedUpdatedAt`과 `expectedBranchId`로 409를 반환한다. 비밀번호 재발급에도 수정 시각·소속 비교와 트랜잭션을 넣는다. 현재 메뉴 ID만 허용한다. JWT는 매 요청 계정을 다시 읽고 `branch.disabledMenus`를 함께 보며, 토큰의 오래된 menus를 권한 원천으로 쓰지 않는다.

**테이블 두 개의 RLS 폐쇄: 동의한다.** `branch`와 `user`에만 RLS를 켜고 `anon`·`authenticated`의 DML을 회수하며 새 정책은 열지 않는다. 다른 테이블로 범위를 넓히지 않는다. 적용 전 서버 역할의 소유·우회를 확인하고, 이후 로그인·메뉴 읽기·계정 변경과 공개 클라이언트 거부를 검증한다.

**DB 우선 대상 배포: 동의한다.** `disabledMenus` 기본 `[]`와 `menuRevision` 기본 1을 추가하는 migration 하나만, 전제 스키마 확인 후 트랜잭션으로 적용한다. 무관한 미적용 migration은 이름·체크섬 기록만 하고 함께 실행하거나 기록을 고치지 않는다. 스키마 검증 후 코드를 배포하고, 구현 중 운영 메뉴를 임의로 끄지 않는다.

1차 조정에도 동의한다. 원장 설정 삭제, 지점 관리자에게 콘솔 전 권한 부여, 응답 계약을 차단 목록으로 교체, 무관한 migration 일괄 중단은 이번 명세에 넣지 않는 판단이 맞다.
