# 개념 백지 사진 위 첨삭 M2-A — 잉크 글줄 (2026-11-27)

`findInkLines(photo, slot, reference)`는 같은 A4 쪽의 펴진 RGBA 사진, 지면 mm 칸 좌표, 빈 인쇄 RGBA 래스터를 받는다. 참조와 사진의 픽셀 밀도는 다를 수 있다. 함수는 결정적으로 지면 mm 잉크 상자와 상자 안 잉크 면적 비율을 반환한다. 빈 줄 후보는 참조에서 검출한 두 인쇄 괘선 사이에서 약한 잔상까지 검사해 비어 있는 띠만 돌려준다. 칸 주변 3mm까지 읽으며 잉크 대부분이 칸 안에 있는 띠를 채택한다. 결과 계약은 `scanInkLinesSchema`다.

사진의 국소 종이 밝기는 열별 상위 분위수로 추정한다. 참조의 인쇄 위치는 국소 조각에서 최대 약 1.75mm 이동을 탐색한 뒤 사진 해상도에서 2px 팽창한 마스크로 뺀다. 그 위에서 가로 투영을 만들고 획 사이의 짧은 세로 공백을 잇는다. 줄이 많이 겹치거나 번진 영역, 규칙선 잔여물이 의심되는 길고 희박한 범위는 `unreliable`로 반환한다. 이때 줄과 빈 자리 모두 비운다. 인쇄선과 잉크가 가까우면 일부 잉크도 마스크에 걸릴 수 있다.

## 합성 비교

합성 사진 32장에 제품 `prepareScanPhoto`를 적용했다. 이 함수가 `registerScanPhoto`로 맞춤을 검산하고 맞춘 쪽만 편 뒤 저장 품질 JPEG를 만든다. 잉크 검출은 그 JPEG를 다시 읽었다. 맞춤에는 정답표의 행렬이나 참값을 사용하지 않았다. 현재 작업 가지의 등록은 18장을 맞췄다. 요청한 24장 측정은 인쇄 글자 후보 제거가 들어간 `phase/cb-scan-markup`의 등록을 지정해 반복했다(등록 변경 `f9be3786f`). 아래 표는 그 24장 기준이다. 큰 휨 8장은 제품에서 `uncertain`이었다.

| 항목                               |                                 결과 |
| ---------------------------------- | -----------------------------------: |
| 등록                               | 24/32 matched, 8 uncertain, 0 failed |
| 칸별 찾은 줄 수 = 참 줄 수         |                   **97/105 (92.4%)** |
| 여러 줄 칸의 줄 수 일치            |                      **7/8 (87.5%)** |
| 빈 칸에 지어낸 줄                  |                       **0줄 / 27칸** |
| 지운 잔상을 독립 글줄로 센 수      |                          **0 / 9개** |
| 후퇴한 칸                          |                                3/105 |
| 참 글줄과 일대일로 대응한 상자     |                                78/87 |
| 세로 중심 절대 오차, 중앙값 / 최고 |                **0.167mm / 0.548mm** |
| 잉크 가로 범위 IoU, 중앙값 / 최저  |                    **0.987 / 0.260** |

줄 수 일치율의 분모는 맞춤을 통과한 쪽의 모든 칸이다. `unreliable`도 해당 분모에 넣어 불일치로 셌다. 비교 상자는 두 줄 취소 획까지 포함한 정답표의 `fullInk.mm`다. 상자들이 가로·세로 모두 만날 때만 중심 오차가 작은 순으로 일대일 대응을 만들었다. 중심 오차와 IoU는 그 78쌍에서 측정했다. 잔상 수는 참 글줄에 대응하지 않은 검출 상자와 `ghost` 상자의 교집합으로 셌다. 옅은 실제 글씨와 지운 흔적이 명암에서 겹치는 조건은 이 합성 세트에서 검증할 수 없다.

정면 33/35, 그늘 33/35, 완만한 휨 31/35칸의 줄 수가 일치했다. 누락 5칸은 인쇄 ○·×와 겹친 작은 체크 표식이었다. 두 칸은 남은 밑줄이 짧은 답의 가로 범위를 크게 늘려 후퇴했고, 한 칸은 기울고 가까운 두 줄이 하나의 띠가 돼 후퇴했다. C형 빈칸에서는 인쇄 잔여물이 남은 경우에 줄 수가 맞아도 폭이 틀어졌다. IoU 0.260 사례는 상태가 `ok`였다. 이 결과만으로 H1 물결 밑줄을 켜면 오지목을 막을 수 없다. 사람 참값을 단 실제 학생 필기에서 글줄 순서와 범위를 검증하고, 합의 조건을 못 채우는 경우 문항 번호를 쓴다.

## 원장님 실제 빈 사진

Wire의 원본으로 사용된 11월 25일 A형 1쪽 빈 사진(로컬에 있던 사본)을 저장 품질 JPEG로 펴고, 로컬 발행 자료의 선택을 제품 인쇄 렌더러에서 재현해 새 참조를 만들었다. 저장 HTML 원본은 확보하지 못했고, 재현한 슬롯 위쪽 좌표는 발행 당시와 최대 0.129mm 차이가 났다. 기존 좌표의 세 문항 영역에서 모두 `ok`, 지어낸 글줄 **0 / 3칸**이었다. 빈 사진 한 장으로 필기 검출률이나 빈 줄 배치율을 평가할 수 없다. 사진과 재현 파일은 저장소 밖에 있다.

## 운영 참조 래스터 선택지

발행 스냅숏은 HTML·CSS·글꼴 정보를 보존한다. 잉크 검출 함수에 필요한 쪽별 픽셀을 지금 저장하지 않는다.

| 선택지                          | 비용과 조건                                                                                                                                                                             |
| ------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 요청 때 발행 스냅숏을 다시 렌더 | 추가 영속 저장이 적다. 매번 브라우저 시작 또는 풀이 필요하고, 글꼴·렌더러 버전 고정과 결과 해시 검증이 필요하다. 옛 발행본의 렌더 환경을 못 맞추면 줄 앵커를 쓰기 어렵다.               |
| 처음 사용 시 렌더하고 쪽별 캐시 | 같은 발행본과 해상도에서 계산을 재사용한다. 첫 요청 지연과 동시 캐시 채우기, TTL·삭제와 키 관리가 필요하다. 키에는 발행 아티팩트 해시·쪽·해상도·렌더러 버전을 넣을 수 있다.             |
| 발행 과정에서 PNG도 만들어 저장 | 최초 판독에 재렌더 지연이 없고 발행 당시 결과를 고정한다. 발행 시간과 객체 수·보존 비용이 늘고 옛 발행본에는 별도 경로가 필요하다. 이 합성용 300dpi 흑백 PNG 10면은 장당 92–200KiB였다. |

제품 경로나 저장에는 연결하지 않았다. 레이아웃 검증에서는 잉크 상자의 범위와 별도로 실제로 배치한 글이 학생 잉크를 가리는지도 확인해야 한다.
