# M3 주어진 전체 각만 수치로 표시

새로 생성하는 `2-2|삼각형의 성질|09`의 각도 갈래에서 그림이 계산한 반각을 미리 표시하던 문제를 수정했다. 예를 들어 발문은 AOB=42°를 주지만 기존 그림은 두 반각에 21°를 각각 표시했다. 이제 두 반각에는 같은 호 표시만 남기고, 별도 바깥 호에 주어진 전체 각 42°를 한 번만 표시한다. 실제 두 반직선·이등분선·수선·꼭짓점과 묻는 각의 x 표시는 유지한다. 이 갈래만 기존 `clear_angle_labels` 배치를 사용해 라벨·호·지시선을 피한다. 전역 렌더러나 엔진 기본값은 바꾸지 않았다.

변경 전 실제 생성기에서 길이 갈래 147조합, 각도 갈래 21조합, 공개 API 32개를 채집했다. 새 시험은 변경 전 23실패·1통과, 변경 후 24개 통과였다. 길이 갈래의 모든 조합은 바이트 기준으로 같으며 세 번의 난수 호출도 유지한다. 각도 갈래의 40°·42°·…·80° 전체에서 두 번의 난수 호출, 발문·정답·해설·facts·좌표·선분은 그대로다. 변한 것은 선언한 각 표시와 해당 갈래의 라벨 배치 설정뿐이다. 공개 API 100개 seed도 검사했다. 이 수를 새 저작·학생 독립 풀이·학년 승인 문항 수에 더하지 않는다.

학생에게 필요한 풀이는 C·D가 수선의 발이므로 사각형 OCPD의 두 각이 직각이고, 내각 합에서 CPD=360°−90°−90°−AOB를 얻는 것이다. 수치 반각이나 삼각함수는 학생 풀이에 필요하지 않다. 내부 좌표 검산의 삼각함수와 학생 풀이를 구분한다. 해당 학년의 모든 선수학습·공식 성취기준·Unit/live family 승인까지 이 그림 검사로 대체하지 않는다.

코드 적용 전 배치 3종을 각각 21개 각도에서 실제 조판해 63개 후보 SVG를 비교했다. 이 실험은 QA 사본이며 생산 실행과 구분한다. 같은 각의 작은 호 반지름 14, 전체 각 호 38과 갈래별 라벨 회피 설정을 선택했다. 적용 후 실제 현재 생성기로 다시 만든 21개 명세는 공개 렌더 함수의 엄격 모드·MathJax 조판을 모두 통과했고, 선택한 후보의 SVG와 21/21 바이트까지 같았다. 이때 사용한 실제 `label_metrics`도 별도로 보존했다. 현재 40°·42°·80° PNG를 직접 확인했다. 렌더 성공이나 그림 픽셀만으로 수학·인쇄·출제 승인을 하지 않는다.

현재 관련 Vitest 8파일 **434개**, 프로젝트 옵션을 사용한 변경 TypeScript 3루트 오류 0, ESLint 3파일 오류·경고 0이다. 전체 프로젝트 타입 검사나 Next 운영 빌드를 뜻하지 않는다. 이전 M14 교점 회귀와 main에서 가져온 교과서 쌍둥이 순수 helper 검사도 포함했다. M14 둘째 갈래의 기존 EF 치수 배치 보류는 유지한다.

독립 검수의 변경 전 21개 계산·Python 렌더는 소스 이식 계산이며 실제 TypeScript 호출로 세지 않는다. 후속 검수는 실제 제공된 handler 21개·API 출력 100개·최종 SVG 21개를 분석하고, 실제 MathJax 치수 명세 21개를 현재 Python 엔진으로 별도 재렌더했다. 라벨·halo 잘림, 라벨끼리 겹침, 전체 각·x 라벨의 본선 침범은 검사 범위에서 모두 0이었다. 지시선 시작점은 독립 계산한 해당 각호 중점과 오차 1e−10 미만으로 일치했다. 최종 그림에는 전체 각과 x가 각각 하나이고 반각·정답 숫자는 없었다. 이 검수는 새 TS/API 실행이나 모든 글리프·선 굵기·지시선·호 조합의 픽셀/인쇄 검증을 뜻하지 않는다.
