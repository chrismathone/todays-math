# 간편 교재 제작과 준비된 수업 원고

처음 교재를 만드는 교사는 학년·학기, 시작과 끝 소단원, 난이도를 고르면 된다. 제목·권 코드·목표 쪽수·지면 틀을 먼저 작성하지 않아도 문제와 개념 원고가 담긴 초안이 만들어진다. 완성 미리보기를 기본으로 열고, 세부 편집은 별도 버튼으로 연다. PDF 만들기는 기존 서버의 확인·예약·조판·확정을 이어서 진행하며 학생용/해설 PDF를 내려받을 수 있다.

지원 범위는 기존 교육과정 은행의 초3~초6·중1~중3, 두 학기다. 범위의 양 끝을 포함하고 학기 밖의 소단원은 거절한다. 360개 소단원, 1657개 원본 개념, 7792개 교사·학생 대사를 일곱 JSON 원고에 저장했다. 제공받은 v15의 실제 대화 24편·298블록을 해당 중2 소단원에 보존했다. 실행 중 AI로 원고를 새로 만들지 않는다. 원고 출처와 재생성 방법은 `src/lib/textbook/scripts/README.md`에 기록했다.

표지·학습 안내·학습 계획·질문 기록·준비 학습·단원 도입·개념 대화·개념 정리·용어 암기·빈칸 개념 암기·통문장 개념 암기·유형/실전 문제·서술형·오류 점검·복습 문제·단원 확인·쉬어가기, 총 17가지 구성을 각각 켜고 끈다. 기본 화면에서는 구성과 인물 선택을 접어 두어 선택 부담을 줄였다. 간편 교재의 도입은 자동 배치 가능한 일반 소개 페이지로 구성하고, 기존 수동 원고의 짝수 왼쪽 도입 펼침면 규칙은 유지한다.

선생님과 학생은 각각 여성 5명·남성 5명으로 총 20명이다. 각 인물의 PNG는 평온·질문·생각·알아챔 4표정의 2×2 원본 시트다. 허용된 인물 ID에만 시트 자르기를 적용한다. 오른쪽 초상만 뒤집으며 이름은 뒤집지 않는다. 인물과 삽화 바이트는 교재 제작 트랜잭션에서 해시와 함께 고정된다.

쉬어가기에는 나눔·반복 규칙·텃밭 넓이/둘레·지도 거리·저울의 균형·날씨 자료, 총 6종의 삽화와 소재에 맞는 한국어 이야기·생각 나누기 질문을 마련했다. 선택 범위의 대단원 사이에서 주제에 맞는 이야기를 고른다. 쉬어가기와 다음 내용은 서로 페이지를 공유하지 않는다. 이미지가 정확한 수량을 나타낸다고 가정하지 않고 이야기에서 수학 조건을 명시한다.

문제는 기존 승인/직접 사용 가능 문항과 선택한 난이도 안에서만 고른다. 각 소단원의 문제 수는 켠 문제 구성들 사이에 나누며, 부족한 경우 소단원과 필요한 수를 알려 주고 제작 전체를 되돌린다. 같은 제작 요청을 재시도하면 기존 결과를 돌려주므로 중복 교재가 생기지 않는다. 원본 문제 은행은 수정하지 않는다.

이미지는 내장 imagegen 도구로 만들었으며 원본은 `public/textbook/portraits/`, `public/textbook/illustrations/`에 저장했다. 사용한 프롬프트는 `docs/planning/textbook-asset-prompts-20261004.json`에 남겼다.

검증:

- 화면과 편집 상태 67개 검사 통과: 기본 제작, 토글, 인물 선택, 범위 변경 중 오래된 응답 무시, 같은 요청 재시도, 자동 PDF 단계 진행, 세부 편집에서 선택 인물 표시.
- 개념 원고/자동 구성/클라이언트/PDF 진행/완전한 PDF 다운로드 58개 검사 통과. 360개 소단원과 14개 학기 범위, 원본 개념·예제·v15 대사, 전체 TeX, 새 수업 예의 숫자 등식, 토글·표지 조합의 실제 페이지 계획을 검사했다.
- API와 자산 저장 26개, 기존 교사 저장 흐름 31개 검사 통과. 원고·그림 고정, 변경하지 않는 원본, 타 사용자 접근, 재시도, 늦은 실패의 전체 롤백을 실제 Postgres 엔진 PGlite로 확인했다.
- 원본 이미지 26개를 실제 Chromium으로 출력했고, 별도로 해설 PDF/표정 시트/페이지 배치 8개 검사를 통과했다. 조판 문서·수식·삽화에 넘침이 없고 기존 단일 초상과 짝수/홀수 바깥 쪽 번호도 유지된다.
- 브라우저에서 3개 소단원의 끝 범위, 쉬어가기 on, 10번째 선생님을 선택하고 제작 입력을 확인했다. 데스크톱과 390px 모바일에서 가로 넘침이 없으며 새로고침 이후 콘솔 오류·오류 화면이 없다. 이 화면 검토는 테스트 API를 연결한 실제 구성요소를 사용했다. API 저장과 PDF 출력은 위의 별도 통합 검사로 검증했다.
- TypeScript와 변경 파일 ESLint 통과. 공유 node_modules 정션이 있는 자식 워크트리에서 Turbopack이 외부 정션을 거절하므로, 최종 Next 빌드는 정션을 쓰지 않는 main 작업 폴더에서 확인한다.
