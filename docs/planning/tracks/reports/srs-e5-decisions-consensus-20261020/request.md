# 초5 SRS 남은 결정 넷 — 합의 요청 (2026-10-20)

원장님이 위임하셨다: «길잡이 캐릭터는 스스로 처음에 선택하도록 하지뭐. 다 괜찮네. 나머지는 코덱스 gemini 등과 합의 도출».

리드(Claude) · Codex · Gemini 가 **따로** 답한 뒤 맞춘다. 각자 질문마다 하나를 고르고 까닭을 두세 줄로 쓴다. 보기에 없는 안이 낫다면 그 안을 적어도 된다.

## 배경

학원 원장이 만드는 수학 학습 서비스다. 초등 5학년 학생이 집 컴퓨터나 폰에서 **혼자** 개념 카드와 문제를 풀고, 복습 일정(SRS)을 따라간다.

- 목표: 2026-11-18 까지 초5 실사용(원장님 2026-10-19).
- 지금 운영에서 이 기능을 쓰는 실학생은 **0명**이다(2026-10-19 운영 DB 읽기 전용 확인).
- 화면은 원장님이 고르신 Hi-fi «C 바다의 넘김책»이다. 펼친 책 두 면 꼴이고, 첫 화면 · 예습 카드 · 문제 화면이 같은 넘김책 틀을 쓴다.

## 지금 코드의 사실

**예습 카드**
- 소단원의 학습 회차 첫 문제 앞에 두 쪽 넘김책으로 뜬다. 뜻 → 그림 → 풀어 보인 예 둘 → 따라 풀기 하나이고, 따라 풀기는 저장하지 않는다.
- 조건: `session.mode === "learn"` · 시도 0 · 미완료 · 이 회차에서 아직 안 닫음(`src/components/math-srs/StudentCoursePractice.tsx` 114행).
- 닫은 기록은 화면 상태에만 있다. 새로고침하면 시도가 0 인 동안 다시 뜬다.
- 학습 회차는 정답률 80% 미만이면 다음 날 같은 소단원으로 다시 온다(`courseAutomation.ts` 853행 · 336행 «A failed new lesson rests until tomorrow»). 그래서 **같은 소단원을 다시 배우는 날에도 같은 카드가 또 뜬다.**
- «그 소단원의 첫 학습 회차인가»는 서버 기록(`state.history`)에서 알 수 있다. 화면 응답에는 그 정보가 없다.
- 옛 화면은 응답을 엄격하게 읽는다. 그래서 응답에 새 칸을 더하려면 머리글로 요청한 화면에만 보내는 방식을 써야 한다(이미 쓰는 길 — `x-course-follow-up`).
- 카드는 지금 초5 56 소단원 가운데 **시범 단원 5-2-1 의 6 소단원**에만 있다.

**맞힌 뒤 1.2초 자동 넘김**
- 보기 고르기 · 터치 입력 문제에서 **맞혔을 때만** 1.2초 뒤 다음 문제로 넘어간다(`StudentCoursePractice.tsx` 402~406행 — `hasFeedback && instantAnswer && !followUp`).
- 틀리면 «다시 해 볼까요 → 정답 · 풀이 → 알겠어요»를 거치고, 학생이 눌러야 넘어간다(2026-10-20 운영).
- 자판으로 답을 쓰는 문제는 맞혀도 «다음» 단추를 누른다.
- 넘어가기 전까지는 «다음» 단추에 초점이 있어 Enter 로 바로 넘길 수 있다.

**길잡이**
- 후보 5안을 codex 이미지 생성으로 만들었다(첨부 `guide-1.png` ~ `guide-5.png` 는 각 안의 «안내» 그림).
  1. 또래 기록가(사람 아이)
  2. 담비 동행(작은 동물)
  3. 종이 제비(접은 종이 새)
  4. 책갈피 정령(책 속 요정)
  5. 나무 조각 친구(나무 · 도형)
- 안마다 다섯 장이 있다: 안내 · 맞았어요 · 다시 해 볼까요 · 하루 마침 · 보상 소품. 512×512 흰 바탕 PNG 이고, 아직 투명 처리 · 제품 반영은 하지 않았다.
- 화면 자리는 지금 둘이다(`src/components/math-explorers/ExplorerStudyBook.tsx`). 첨부 `hifi-C-pc.png` 가 확정 화면이다.
  - 첫 화면 넘김책 왼쪽 면의 작은 자리(100×76 정도). 지금은 «길잡이» 글자만 든 빈자리다.
  - 하루 마침의 보상 자리(126×126). 지금은 «오늘의 한 장을 채웠어요» 글만 있다.
- 진도판 테마는 학원이 다섯 가지 가운데 하나로 정한다. 길잡이는 어느 테마에도 어울리게 만들었다.
- 학생별 설정의 저장:
  - 소리 켜고 끄기는 브라우저에만 있다(`localStorage`).
  - 학습 기록은 서버의 학생 기록 JSON 이다. 여기에 새 선택 칸을 더하면 «읽는 코드 먼저 배포 → 쓰는 코드»(되돌림 하한)를 지켜야 한다. 이 길은 이번 주에도 세 번 썼다.
- **원장님이 이미 정하신 것: 학생이 처음에 스스로 고른다 · 5안 모두 쓴다.**

## 질문

**Q1. 예습 카드는 언제 띄우나?**
- A. 지금대로 그 소단원의 학습 회차마다(다시 배우는 날도) 첫 문제 앞에 자동으로
- B. 그 소단원의 **첫 학습 회차에만** 자동으로. 다시 배우는 날에는 첫 문제 앞에 «개념 다시 보기» 단추를 두어, 누르면 열고 아니면 바로 문제로
- C. 첫 학습 회차에만. 다시 배우는 날에는 띄우지 않는다

**Q2. 맞힌 뒤 1.2초 자동 넘김은?**
- A. 그대로 둔다
- B. 없애고 맞혀도 «다음» 단추로 넘긴다(자판 답 문제와 같게)
- C. 넘기되 시간을 늘리고(예: 2초), 운영체제의 «움직임 줄이기»를 켠 학생에게는 단추로

**Q3. 11/18 의 «끝»은?**
- A. 시범 소단원에서 혼자 공부가 되는 흐름 + 실학생 1주 사용 검증. 전 범위 예습 카드 · 테마 · 3D 는 그 뒤 이어서
- B. 초5 전 범위 완성(예습 카드 56 소단원 · 그림 전부 · 테마 · 3D) + 시범
- C. 2학기 전 범위 예습 카드 + 길잡이 · 보상 + 시범 1주. 1학기 카드 · 3D · 공부 화면 테마는 이어서

**Q4. 길잡이 고르기의 세부**(학생이 처음에 고른다는 전제 위에서)
- **4a 언제:**
  - A. 첫 화면을 처음 열 때 고르기 쪽이 먼저 나온다. 고르기 전에는 공부를 시작하지 않는다
  - B. 처음 열 때 고르기 쪽이 나오되 «나중에»로 넘길 수 있다(그때는 기본 길잡이)
  - C. 처음에는 기본 길잡이. 길잡이를 누르면 고를 수 있다는 안내만
- **4b 바꾸기:**
  - A. 언제든 첫 화면에서(길잡이를 누르면 고르기 쪽)
  - B. 바꾸지 않는다(선생님만)
  - C. 바꿀 수 있으나 하루 한 번
- **4c 저장:**
  - A. 서버 학생 기록의 새 선택 칸(읽는 쪽 먼저)
  - B. 브라우저에만(기기마다 다를 수 있음)
  - C. 서버의 새 표(DB 먼저)
- **4d 고르기 쪽의 꼴:**
  - A. 넘김책 한 쪽에 다섯 길잡이를 나란히(그림 + 이름, 폰은 두세 줄). 누르면 고르고, 아래 «이 친구와 시작» 단추
  - B. 한 명씩 넘겨 보며 고르기(넘김책 쪽 넘김)
  - C. 공용 «고르기 창»(이 저장소의 `PickerDialog` — 긴 목록용 규칙 D-159)
- **4e 길잡이가 나오는 자리:**
  - A. 지금 있는 두 자리만(첫 화면 안내 · 하루 마침 축하와 보상)
  - B. 두 자리 + 문제 화면의 «맞았어요» · «다시 해 볼까요» 표정
  - C. 두 자리 먼저, 문제 화면 표정은 시범 학생을 본 뒤
