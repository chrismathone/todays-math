## 2. 선행 배선 (`e1107f892`)

- **`displayRows?: RecallDisplayRow[]`** — 회상 블록에 이 칸이 있으면 `memoryHtml` 은 그 행을 **주어진 대로** 그리고 노드의 `rows` · `rawText` 를 읽지 않는다. `answersVisible === false` 가 같이 오면 `displayRows` 에 남은 핵심어 · 문장도 한 번 더 지운다. 칸이 없으면 종전대로 노드의 행을 투영한다. `e8dd1baaf` 의 모델이 이 칸과 `answersVisible` 을 채우고 학생용 숨김 단계의 `rawText` 를 비운다.
- **`renderSourceFragments(node.fragments, resources)`** — 개념 블록의 조각 노드를 그릴 때 자원을 넘긴다.

## 3. 🔴 찾아서 고친 개인정보 결함 (`df41631bb`)

**학생용 핵심어 빈칸 지면에 숨긴 핵심어가 찍히고 있었다**(`16dfd927d` 시점). 새 검사가 실제 파이프라인(PGlite → 교환 형식 → 모델 → HTML)에서 찾았다.

- 증거: 초3 `1-1-1` 의 `clozeRecall` 블록, 행 `e3-1-1-1-c2.definition`. 학생 HTML 에 «세로로 더할 때에는 **같은 자리**에 있는 숫자끼리 나란히 놓는다.»가 통째로 찍혔다(핵심어 «같은 자리»).
- 원인: 그때의 모델은 행 노드가 있는 회상 블록을 문단으로 쪼개고 조각마다 행 전체를 실었다. 용어 문단에는 어느 판에서도 빈칸이 없는데, 내 렌더러의 대체 추정이 «빈칸이 없다 = 정답 판»으로 읽었다.
- 고침(내 쪽): 명시된 `answersVisible` 이 없으면 **쪼개지지 않은 온전한 블록**에 빈칸이 없을 때만 정답 판으로 읽는다. 쪼갠 조각은 숨긴다.
- 고침(조율 담당 쪽, `e8dd1baaf`): 블록을 쪼개지 않고 `answersVisible` · `displayRows` 를 주고 `rawText` 를 비운다. 내 방어 추정은 그대로 남긴다.
- 지금의 검사: 학생용 숨김 단계의 **DTO** 에 정본 글 · 평문 문장 · 핵심어가 없고 HTML 에도 없다. 열쇠는 저장된 원고에서 가져온다(학생 노드에서는 지워졌으므로). 정답 판에는 찍힌다.

## 4. 반복 표시 줄의 자리 (`f09357c9f`)

조율 담당의 요청: 자동 작성기의 행 노드(`node.kind === "rows"`, 개념 이름 없음)는 개념학습에만 1~4회 줄이 생겨 첫 행의 높이가 단계마다 달랐다.

- 바꾼 것은 `recall.ts` 하나다. 행 노드에는 **세 단계 모두** `<header class="tb-memory-title tb-memory-title-bare" data-anchor="memory-title">` 를 낸다. 개념학습만 그 안에 표시를 찍고, 빈칸 · 통문장은 비워 둔다(글자 · 표지 없음).
- `contentCss.ts` 는 고치지 않았다 — `.tb-memory-title` 의 최소 높이 7mm · 아래 여백이 이미 줄의 높이를 정한다.
- 실제 Chromium(제품 글꼴): 줄 27.372~34.371mm, 첫 행 36.670~45.868mm, 여섯 행 전부 — **세 단계에서 차이 0.000mm**. 개념 노드(`kind: "concept"`)는 원래 같았고 그대로다.
- 이 변경으로 `textbookRecoveryContentRender.test.ts` 의 단정 하나(«행 노드에는 제목 줄이 없다»)를 «빈 줄이 있다»로 고쳤고, 통합 검사에 행 노드 기하 검사를 더했다. 같은 통합 파일의 `afterAll`(브라우저 닫기)에는 60초 한도를 줬다 — 다른 22파일과 한꺼번에 돌릴 때 기본 10초를 넘겨 한 번 실패했던 자리다.

## 9. 한계

- 조율 담당이 모델과 조판을 계속 고치는 중이다. 여기 검사가 쓰는 조판(블록 높이 75mm 고정)은 구조만 본다 — **지면 기하의 증명이 아니다.**
- 은행은 합성이다. 실제 은행의 엔진 유형 분포 · 풀이 유무 · 반복 문항 비율은 보지 않았다.
- 28개를 «하나만 켬 / 하나만 끔»으로 본 것이지 2의 28승 조합을 본 것이 아니다. 의존 짝은 대표예제 · 추론 · `includeConcepts` 만 따로 봤다.
- 잠금은 «그 문장이 그 차례에 나갔다»까지다. PGlite 는 연결이 하나라 두 요청이 실제로 다투는 경합은 재지 않았다.
