# Listening persistent backend — 2026-10-03

Implemented independently owned listening sets with incomplete drafts, strict teacher HTTP inputs, fresh Auth.js identities plus current database account/membership authorization, server provenance and reviews, verified immutable publication, class/target scope, assignment revision snapshots, practice and editable exam answers, transactional attempts/receipts, manual release and exposure history, cancellation, authorized retries and teacher broadcast start/end/interruption.

Teacher routes use `/api/english/listening`; learner routes use `/api/english/learn/listening`. Learners receive only the strict student projection and an allowlisted attempt snapshot. Commands require both an exact current `attemptId` and revision/idempotency key; delayed requests cannot attach to a newly authorized retry. Same-origin writes and project `{data}` / `{error}` envelopes apply, including asynchronous media errors. All responses are private and non-cacheable. Each resource transaction acquires a PostgreSQL advisory lock and verifies revision CAS, stores answers and receipts together, and normalizes timestamp writes to UTC. There is no process-memory persistence fallback.

The additive migration creates 12 listening-only tables, with RLS and no PUBLIC/anon/authenticated grants, restrictive foreign keys, initial-attempt/receipt uniqueness, byte-length constraints, and immutable publication/media/blob guards. Existing students and owners cannot be hard-deleted while retained listening history references them; retention/anonymization remains an explicit operator policy, not a cascading deletion. The migration/apply script requires an explicit `LISTENING_DATABASE_URL`; default is a read-only check, `--dry-run` rolls back, `--apply` applies only this migration. Shared writes require an additional approved `ALLOW_SHARED_IMPORT=1` gate.

Protected playback reloads current account, membership, target, cancellation, current content rights, content-owner pilot access, publication binding and exact published asset. Teacher-device assignments omit learner media. The media worker's durable adapter is composed with runtime authorization; original uploads require confirmed storage rights. Pilot limits are 1 MiB upload chunks, 16 MiB originals and 10 minutes. The teacher Node route allows 300 seconds for bounded decoding/storage. A versioned operator maintenance command, `scripts/qa/english-listening/cleanup-media.ts`, defaults to read-only inspection and permits explicitly requested bounded cleanup of 25 expired uploads; it never deletes ready assets.
