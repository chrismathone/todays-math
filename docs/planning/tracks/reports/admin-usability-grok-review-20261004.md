## 재검토 전에 고칠 것

### 1. B01 복구는 ‘연결 활성화’가 아니다

`shadow`와 `retire`는 같은 트랜잭션에서 확정 연동 계정의 `suspendedAt`과 `sessionVersion`을 바꾸고, 연결의 `enabled`를 끈다. `retire`만 `retiredAt`을 남긴다 (`src/lib/eywa/managedAdministration.ts` 221–264행). 화면의 ‘연결 활성화’는 `mode`만 `active`로 바꾼다 (377–380행). 정지 해제와 `enabled: true`는 없다. 버튼 문구는 여전히 ‘새 연결·쓰기 중지’다 (`src/components/account/EywaManagement.tsx` 173–184행).

보안 효과를 유지하고 실행 전에 대상·세션 폐기·복구를 확인시키는 정책은 맞다. ‘쓰기만 중지’로 느슨하게 바꾸지 않는다. 다만 확인 문구가 지금 버튼을 복구 절차로 안내하면 거짓이 된다. 계획에 실제 복구를 적는다. 계정 화면의 개별 ‘정지 해제’와, 연결을 다시 켜는 별도 동작이 무엇인지, 그 동작이 이번 범위인지 이번 범위 밖인지를 적는다. API의 `rebaseline`도 같은 정지를 한다 (371–376행). 화면 버튼은 없지만 이번 문구 변경으로 그 경로를 열거나 약화하지 않는다고 적는다.

### 2. A08과 B05는 한 수용 기준으로 닫히지 않는다

`loadMainDashboard`는 `/api/classes`, `/api/tests`, `/api/units`, `/api/metrics` 중 하나라도 실패하면 전체를 던진다 (`src/lib/main/loadMainDashboard.ts` 54–82행). 그다음 반마다 `/api/progress`를 기다리고, 204·404가 아닌 실패도 전체를 던진다 (84–99행). 제안 조회만 실패를 삼킨다.

B05의 권한 경계는 맞다. `tests`·`exports`는 `export`, `metrics`는 `home`, 반·학생·진도는 `teaching`이다 (`src/lib/accountRouteAccess.ts` 154–190행). `teaching`만 있는 계정은 부가 조회를 호출하지 않아야 하고, 호출 실패를 빈 데이터로 바꿔 보여 주면 안 된다.

A08의 대기 원인은 그 부가 조회가 아니다. 반 수만큼의 진도 요청이 한 `Promise.all`에 묶여 있다. 부가 조회를 빼도 진도 한 건의 실패와 지연은 수업 진행 전체를 막는다. 수용 기준을 둘로 나눈다. 권한 없는 API는 호출하지 않는다. 진도는 반 단위로 실패와 재시도를 격리한다. 목표 응답 시간은 이번에도 정하지 않는다.

### 3. A05 식별자는 학생 ID 하나다

`loadOperationalRoster`는 연동 학생만 등록 행을 반마다 펼치고, 지역 학생은 `classId` 한 줄이다 (`src/lib/classAccess.ts` 270–325행). 화면은 그 행 수를 ‘명’으로 세고 (`CourseDashboard.tsx` 258행, 333행), 목록 병합·선택·React key·저장 반영이 모두 `student.id`다 (123–132행, 164–172행, 394행, 686–691행). 상세 응답은 학생의 반 이름을 통째로 덮어쓴다 (`courseServer.ts` 92–95행, 116–120행).

‘학생 1명 · 등록 2건’과 공유 학습 상태가 다른 반의 이름·소유권을 바꾸지 않는다는 계약은 맞다. 계획에 다음을 더한다. 등록 행의 선택 키는 `classId`와 `studentId`다. 학습 계획 저장은 학생 단위로 남되, 응답의 `classId`·`className`으로 다른 등록 행을 고치지 않는다. 회귀 fixture는 연동 등록이 두 개인 학생이다. 지역 학생 둘을 놓는 시험은 이 결함을 지나간다. `CourseDashboard.test.tsx` 235–258행은 서로 다른 학생을 행 수로 세므로, 그 초록을 이 항목의 검증으로 세지 않는다.

### 4. C01은 저장된 학년을 확인된 학교급으로 쓰면 안 된다

과정 화면은 접근 가능한 반을 `id`·`name`만 읽고 학년을 받지 않는다 (`courseServer.ts` 173–178행). 시작 진도 선택은 초등 3–6만 있다 (`CoursePlanForm.tsx` 77–103행). 반 학년 칸은 `Class.grade`다 (`schema.prisma` 317행). 연동 반영은 원본 학년, 학생 학년 집계, 기존 값 순으로 보고 없으면 `"중1"`을 넣는다 (`managedRelations.ts` 260–270행).

초3–초6만 기본 과정으로 두고 그 밖은 보충을 명시적으로 켜며, 이미 저장된 보충 계획을 지우거나 다시 계산하지 않는 정책은 맞다. 기본 ‘설정 필요’에서 빼기 전에 학년의 출처를 보여 준다. 정확한 `초3`·`초4`·`초5`·`초6`만 기본 대상이다. 빈 값과 가져오기 기본값 `중1`은 확인된 중학 반이 아니다. 그 반을 대상 밖으로 조용히 빼면 학년 없는 초등 반이 ‘설정 필요’에서 사라진다. 보충 선택은 시작 진도 드롭다운과 다른 명시 동작이다. 학생 개인 학년으로 반 학년을 덮어쓰지 않는다.

### 5. T01 정답은 원고 JSON에 넣지 않는다

교사용 정답은 화면 상태만 바꾼다 (`parts.tsx` 893–901행). 저장 직렬화에는 없고 (`client.ts` 712–722행) 다시 읽을 때 빈 문자열이다 (`client.ts` 633행). `textbook_section.content`는 블록 JSON이다 (`schema.prisma` 1801–1802행). 판본 복사는 그 JSON을 펼쳐 넣는다 (`books.ts` 316–324행). 발행 판본의 원고 수정은 `requireOwnedDraft`가 막는다 (`sections.ts` 343행, `items.ts` 445–446행). 학생 계약은 교사 페이로드와 숨은 정답을 받지 않는다고 적혀 있다 (`textbookStudent.contract.ts` 11행). 화면의 `visibleAnswer`는 교사·학생 모드를 나누지만 (`model.ts` 321–338행) 저장 계약이 아니다.

정답을 영속화하고 학생 응답에 넣지 않으며 발행 불변성과 CAS를 유지하는 방향은 맞다. 저장 위치를 정하기 전에는 구현하지 않는다. `content`나 학생 응답 스키마에 칸을 추가하지 않는다. 교사 전용 칸은 학생 조회·교환 파일의 학생용·배정 응답에서 select하지 않는다. 새 초안 복사 INSERT에 그 칸이 없으면 발행 뒤 초안에서 다시 사라진다. 발행 행은 고치지 않고, 고치려면 새 초안이다. 이 칸의 migration이 필요하면 계획의 운영 반영 절차를 타고, 칸이 생기기 전에 코드를 배포하지 않는다.

### 6. D07은 미리보기 후 생성이 아니다

학생 계정 API는 GET이 미리보기, POST가 생성이다 (`student-accounts/route.ts` 64–71행). 버튼은 미리보기 없이 POST를 바로 보낸다 (`BulkStudentAccountButton.tsx` 33–42행). 로드와 동기화는 계정을 만들지 않고, 다시 실행해도 기존 계정을 유지하는 현재 동작은 보존한다. 비밀번호와 전화번호는 응답·로그·증빙에 남기지 않는다.

‘GET을 확인한 뒤에만 POST’는 현재 동작이 아니라 새 화면 조건이다. 기존 GET 요약(생성 가능, 기존, 제외 사유)을 보여 준 뒤에만 버튼을 활성화한다. 미리보기 토큰이나 새 프로토콜은 만들지 않는다. 시험이 쓰는 직접 POST는 그대로 두고 서버의 기존 계정 보존을 유지한다. 원래 D07의 승인·권한·반복 설정 일괄 처리는 이번 행의 범위가 아님을 적는다. 그 일반 제안을 이번 발급 버튼의 완료로 처리하지 않는다.

### 7. B02를 데이터 손실이 없다는 이유로 P2로 내리지 않는다

이름·이메일 입력은 값이 원본과 같아도 잠금을 켠다 (`AccountReview.tsx` 437–439행, 451–453행). 메뉴·소속은 이미 `isDraftDirty`로 잠근다 (481–483행). 원본과 같아지면 `dirty`는 거짓이라 저장은 비활성화되고 ‘변경 취소’는 렌더되지 않는다 (723–764행). 부모 잠금은 그대로라 검토를 닫거나 링크를 따라갈 수 없다.

데이터는 저장되지 않는다. 그러나 저장·취소·이동이 모두 없는 함정이다. 우선순위 표에 증빙의 P1을 남긴다. 이름·이메일·Ctrl+Z·순차 원복은 `dirty || busy`만 잠근다. 다른 칸의 기존 dirty 계산은 유지한다.

### 8. A04에 현재 관리자 헤더를 그대로 붙이지 않는다

연결 페이지는 `isAdmin`이면 열고 공통 헤더가 없다 (`eywa-sync/page.tsx` 5–18행). `AdminHeader`는 이미 `eywa` 활성 값을 받지만 지점 관리와 SRS를 항상 보여 준다 (`AdminHeader.tsx` 25–52행). 그 두 페이지는 `isSuperAdmin`이 아니면 `/`로 보낸다 (`admin/branches/page.tsx` 12행, `admin/math-srs/page.tsx` 18행).

헤더를 그대로 붙이면 지점 관리자에게 최고관리자 메뉴가 보이고, 누르면 권한 설명 없이 작업실로 떨어진다. 권한에 있는 메뉴만 보여 준다. 지점 관리자의 복귀는 자기 지점이다. 연결 페이지의 진입 조건과 플랫폼 전용 동작은 헤더를 달면서 넓히지 않는다.

### 9. 늦은 응답 규칙은 같은 요청 키 안에서만 수동 입력을 지킨다

공통 계약 3은 맞다. 다만 ‘기본값 응답이 수동 입력을 덮지 않는다’를 반이 바뀐 뒤의 기본 범위까지 막는 뜻으로 읽으면 안 된다. 확인테스트는 반·학생이 바뀌면 이전 범위를 버리는 것이 현재의 안전한 동작이다 (`useGenerateSetup.ts` 194–232행). 같은 `classId`·`studentId`에서 사용자가 고친 값만 늦은 기본 응답이 덮지 못한다. 이전 반의 응답은 지금 키에 적용하지 않는다. 내보내기 링크도 판본이 바뀌면 지우고, 같은 판본의 완료 결과만 유지한다.

## 시험과 정책

회귀는 계획이 적은 실패 경로를 유지한다. POST 성공 뒤 GET 실패, 연동 학생 1명의 등록 2건, 이름·이메일 원복, 같은 키의 늦은 응답, dirty 이동, `teaching`만 있는 계정, 반 101개와 마지막 반 직접 진입, 교재·학습계획 CAS 충돌과 재시도, 교사 응답과 학생 응답의 정답 분리다. `CourseDashboard.test.tsx`의 `/classes/class-2` 기대는 고친 경로로 바꾼다. 그 파일의 행 수 단언은 A05의 통과 증거가 아니다. 테스트가 초록인 것만으로 실제 이동·저장이 확인됐다고 적지 않는다.

정책은 다음을 유지한다. 메뉴 권한과 연동 세션 검증을 우회하지 않는다. 학생 정책과 SRS 엔진과 권한 체계를 이번 작업으로 넓히거나 바꾸지 않는다. 계정 발급은 지점 관리자 이상이 명시적으로 실행할 때만 한다. 학생 이름 ID, 등록 전화번호 끝 4자리, 기존 계정 보존, 중복 이름·번호 누락 제외를 유지한다. 복귀 URL은 허용한 내부 경로와 필요한 쿼리만 받는다. 외부 URL, 다른 지점, 비밀번호, 근거 원문은 받지 않는다. 운영 migration은 대상·전제·체크섬과 DB 다음 코드 순서를 따로 적기 전에는 적용하지 않는다.

공유 파일은 묶음 밖으로 동시에 고치지 않는다. `CourseDashboard.tsx`는 SRS·복귀, `AccountReview.tsx`와 `EywaManagement.tsx`는 연동·계정, `TextbookStudioView.tsx`는 교재, `useGenerateSetup.ts`와 `loadMainDashboard.ts`는 작업실이다. 작업실 파일은 루트 소유다.

## 하지 않은 것

운영 화면을 다시 열지 않았다. 배포 커밋이 `049f08f65` 또는 `487236f7c`와 같은지는 확인하지 않았다. Vitest, 브라우저, 합성 데이터 재현은 실행하지 않았다. 이 판정은 그 검증을 대신하지 않는다.
