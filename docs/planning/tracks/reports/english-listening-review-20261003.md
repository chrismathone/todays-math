# 영어 리스닝 계획 검토와 반영 기록

2026-10-03. 대상은 [오늘의 영어 리스닝 계획](../../english-listening-plan-20261003.md)이며 기준 코드는 `763caff59`다. 사용자는 교사 수업·학생 자습·시험 대비를 모두 기획하고 Claude와 Grok에게 재검토하도록 요청했다. Orca의 실제 Claude와 Grok 에이전트가 별도 읽기 전용 작업 트리에서 같은 초안을 독립 검토했다. 모델명은 실행 설정을 따랐으며 특정 모델 버전으로 단정하지 않는다.

1차 의견은 Claude 12건, Grok 10건이다. 중복된 주제를 포함하므로 서로 다른 결함 22개라는 뜻은 아니다. 코디네이터가 현재 코드와 공식 문서를 대조하고 반영한 뒤 수정 계획을 두 에이전트에게 다시 전달했다. 제품 구현·데이터베이스 적용·배포·유료 음성 생성은 이 검토의 범위가 아니다.

## 3 의견이 달랐던 부분의 결정

**학생 범위.** Claude는 옛 문서의 학생 문제 풀이 제한을 근거로 별도 범위 승인을 제안했다. 이번 사용자 요청이 학생 자기주도 학습과 평가를 이미 포함하므로 기획을 멈추거나 같은 질문을 반복하지 않았다. 화면 형태 선택과 운영 데이터베이스 적용은 별도 단계로 남긴다.

**학생 API 위치.** Grok은 learn 아래에서 영어 모듈을 가져오지 않는 분리를, Claude는 영어 API 안의 학생 경로를 제안했다. 실제 울타리를 읽고 후자를 채택했다. 학생 관문의 허용 목록과 배정 인가는 어느 경로에서도 필요하다.

**첫 음원 입력.** 두 검토자는 첫 수업에 TTS를 넣는 안을 제안했지만, 수정안은 허용된 짧은 MP3·확인 대본·객관식을 수동 등록하는 방식이다. 자동 전사·정렬과 생성 작업자 없이 자료 발행·권한·재생을 먼저 검증할 수 있다. 오디오 저장 실험은 L1 전 필수다.

**저장 방식.** Claude의 1MiB 이하 bytea 임시 저장과 Grok의 객체 저장 선결정을 모두 확정 사양으로 채택하지 않았다. 실제 배포의 업로드 제한, Range, 파일 크기, 비용을 L0에서 비교한다. 임시 저장을 먼저 만들고 운영 때 반드시 다시 갈아엎는 계획을 피한다.

**실전 방송.** Claude의 클라이언트 순차 재생 제안은 수업·학습에는 사용할 수 있다. 시간 간격이 중요한 실전에는 Grok의 검수된 연속 음원 방식을 채택했다. 재생 버튼을 숨기는 것으로 외부 녹음·탐색이 차단된다고 표현하지 않는다.

**반 이동 후 응시.** Grok은 시작한 응시는 제출까지 허용하는 안을 제안했다. 수정안은 전출·취소 이후 접근을 중지하고 저장한 답을 남긴다. 계속 응시해야 한다면 교사가 새 유효 배정을 열도록 일관된 규칙을 선택했다.

**음성 검수.** 음원 전사와 대본의 낱말 차이는 유용한 보조 검사지만 전사도 틀릴 수 있다. 따라서 결정적인 음성 진실 판정으로 쓰지 않는다. 또한 공급자의 권장 글자 수를 강제 상한으로 바꾸거나 모든 음성을 턴별로 합성해야 한다고 단정하지 않았다.

**정답 누출 시험.** 정답 보기의 글자는 정상 보기 목록에도 들어 있다. “정답 문자열이 응답에 전혀 없어야 한다”는 단순 검사는 채택하지 않는다. 정답 식별자·매핑·해설·대본·근거와 문항 간 의미 누출을 검사한다.

## 4 재검토와 남은 검증

두 에이전트에게 같은 수정 계획과 위 결정 취지를 전달해 2차 검토를 완료했다. **Claude는 CONDITIONAL로 문서 조건 4건·선택 권고 1건, Grok은 CONDITIONAL로 문서 조건 3건**을 보고했다. Claude는 설계를 다시 뒤집을 차단 사항이 없다고 명시했고, Grok은 아래 세 문단 보완 전 계약 기준선으로 고정하지 말라고 했다. 두 검토의 요구 문장을 코디네이터가 최종 문서에 반영했다. 반영 뒤 세 번째 에이전트 검토를 수행한 것은 아니므로 이를 두 에이전트의 무조건 PASS로 표기하지 않는다.

| 2차 지적 | 최종 반영 |
| --- | --- |
| Claude F1, Grok R2-1: 문항별 공개와 배정 전체 공개가 섞임 | §4에 학습 `after_unit_answer`와 평가 정책을 분리. 문항별 공개 상태에 따른 엄격한 응답 검증. 동일 대화의 여러 문항은 답을 모두 확정한 뒤 복습 공개 |
| Claude F2, Grok R2-3: 대상 고정 시점·전입 추가의 의미가 모호 | 자료 발행 시점이 아닌 배정 생성 시점으로 수정. 추가분 행 또는 새 배정 개정으로 전입을 기록하고 기존 응시의 스냅샷 보존 |
| Claude F2: 취소·전출·비활성·마감 거절의 인수 기준 누락 | §11에 L2 검증 표 추가. 진행 중 응시의 새 요청·Range 거절, 저장 답 보존, 마감 후 저장·제출 거절, 학생 간 접근 차단 |
| Claude F3: 교사 방송 방식의 계약과 지표가 없음 | §5에 `audioSource` 두 방식, 교사 방송 세션·반 시계·참여 학생, 학생 음원 미전송, 방송 실패와 학생 통신 실패의 분리. §12 지표 분모 분리 |
| Claude F4: 연속 음원을 만드는 절차와 큰 파일 경로 누락 | §6에 입력 해시·프리셋 시간표·안내·무음 합성과 출력 구간·해시·전체 청취. §8에 작업자 직접 저장 또는 청크 경로, §11에 실전 길이 검증 |
| Claude F5, Grok R2-1: 누출 검사 범위가 모호 | §4에 비밀 필드·정답 매핑·근거·메타데이터 검사 정의. 정상 보기 문장의 노출을 금지하는 잘못된 기준 제외 |
| Grok R2-2: 학생 화면에서 교사 데이터를 직접 가져올 수 있음 | §4에 학생 페이지·컴포넌트의 교사 영어 코드·Prisma 접근을 직접·간접 참조 검사로 차단. 학생 API 데이터와 순수 학생 계약만 사용 |

코디네이터는 수정 후 문서 간 링크, 기존 코드 근거, 계획과 미구현의 구분, 단계별 인수 조건, diff 공백 오류를 확인했다. 문서만 변경했으므로 제품 테스트·빌드·음성 호출을 검증 결과로 제시하지 않는다.

계획 검토 통과와 제품 인수 통과는 다르다. 실제 음성 청취, 업로드·기기 실험, 화면 선택, 학생 데이터 보존 규칙, 예산, 시험별 방송 간격은 해당 개발 단계의 진입 조건으로 남는다.
