## Q-P01 — 소수 오답

지시서의 `3-2|삼각비|18`, 씨앗 15와 파생 RNG `0x9e37` 호출로 먼저 재현했다.
수리 전 보기는 `8.0029, 0.8290, 0.829, 0.0083, 1.171`이었다.
발문의 삼각비 표와 여각 관계로 계산하면 정답 0.829에 해당하는 보기가 둘이었다.
수리 후 같은 호출의 보기는 `0.8291, 0.8290, 0.8288, 0.8289, 0.8280`이며 정답은 계속 ②이다.

- 약분하기 전 소수 자릿수를 보존하고, 기약분모가 그 자릿수의 10의 거듭제곱을 나눌 때만 정확한 정수 연산으로 표시한다. 끝자리 0도 유지한다.
- 소수 후보는 유리수 값으로 중복을 판정한다. 순환소수·정답보다 많은 자릿수가 필요한 후보는 버린다.
- 끝자리 ±1·±2, 한 자리 위 ±1로 후보를 보충하고 소수점 자리 이동은 뒤로 미룬다. 0.0에서도 다섯 보기를 만든다.
- 같은 함수의 형제 경로도 고쳤다: 단위·꼬리표가 붙은 소수, 정수 값인 소수(1.0), 정수 부분이 0인 음수(-0.3), 생성기가 직접 제공한 소수 오답의 중복과 정밀도.

시험: `src/__tests__/unit/deriveFormatsDecimal.test.ts`.
첫 실행은 20개 중 19개 실패했다. 독립 BigInt 유리수 연산으로 실수 태그의 실제 값과 표시된 값을 비교한다.
삼각비 재현은 정답 필드 대신 발문의 표에서 값을 구해 정답 보기 개수가 1인지 묻는다.
일반·수식·단위 표기 42가지 × 씨앗 0~299 = 12,600판, 삼각비 유형 300판,
전체 초등·중등 등록부의 세 씨앗에서 발견한 소수 문항류를 씨앗 0~99까지 추가 검증한다(15,000판 이상).
확장된 소수 시험 23개가 통과했다. 기존 파생 시험 세 파일을 함께 돌린 첫 묶음도 75개 통과했다.

**되돌리니 빨강:** `deriveFormats.ts`를 기준 커밋 내용으로 되돌리고 재현·유리수·부호·직접 제공 오답 시험을 실행하니 18개가 실패했다.
재현 문항에서 정답 보기 개수가 다시 2가 됐다. 파일 편집 도구로 수리본을 복원했다.

## 전수 지문과 객관식 가능 범위

`src/__tests__/helpers/deriveFormatsCensus.ts`는 실제 등록부와 제품 생성기를 사용한다.
각 문항의 `content, answer, solution`을 SHA-256으로 저장하고 단답·서술·객관 파생 결과 및 난수 호출 수를 함께 대조한다.
생성 씨앗은 0~49, 파생 RNG는 `0x9e37 + seed * 17`이다.

| 모집단 | 문항류 | 생성 판수 | 파생 객관식 가능 문항류 전→후 | 파생 객관식 판수 전→후 |
| --- | ---: | ---: | ---: | ---: |
| 초등 문형 | 2,468 | 123,400 | 2,209 → 2,209 | 109,545 → 109,628 |
| 중등 유형 | 1,505 | 75,250 | 1,459 → 1,459 | 72,334 → 72,373 |
| 합계 | 3,973 | 198,650 | 3,668 → 3,668 | 181,879 → 182,001 |

- 생성 실패 전후 0. 객관식 가능 문항류·판 손실 모두 0.
- 표는 `asMultipleChoice`의 성공을 센다. 생성기가 처음부터 보기 목록을 낸 문항도 원본 지문 비교에 포함되며, 그 원본은 모두 그대로다.
- 비소수 188,354판은 파생 결과·예외·난수 횟수가 전부 그대로다.
- 소수 225문항류의 10,296판만 달라졌다. 원본 발문·정답·해설, 단답·서술 파생은 그대로다.
- 비소수 지문의 집계 SHA-256 전후 동일: `413b6f89cacdf0d5fb2d56d9e28a2b79a8e00890621dfc4a71eb432b6914b9f4`.

## Q-P02 — 동그라미 정답

수리 전 직접 호출에서 정답 ②·선택 2·배점 10은 `isCorrect=false, score=0`이었다.
`src/__tests__/unit/gradeAnswers.test.ts`의 첫 실행은 16개 중 13개 실패했다.
기존 `circledValueRaw`를 사용하여 한 글자 동그라미 정답만 번호로 읽고 선택 번호와 비교한다.
원문자 계열 규칙은 새로 만들지 않았다. 숫자로 저장된 옛 정답과 미답·부분점수·배점 경로는 그대로다.
단일 정답 가드가 있어 `①, ④`에서 첫 번호만 읽지 않으며, 설명 속 번호도 정답 번호로 잘라내지 않는다.

시험 16개가 통과했다. 초등 소수 덧셈 문형과 중등 삼각비 유형의 씨앗 0~299, 합계 600문항을
실제 객관식으로 만든 뒤 선택 번호 1~5를 모두 채점했다(3,000회). 문항마다 정답 응답이 정확히 하나이고,
정답 번호 다섯 자리를 모두 거쳤다. 숫자 저장형과 여러 원문자 계열, 복수 정답·설명·미답도 함께 검증한다.
계약이 배열 응답을 받지 않는다는 시험과 복수 정답을 단일 선택으로 맞았다고 하지 않는 시험을 남겼다.
기존 제출·배점 시험까지 합친 5파일 70개도 통과했다(실제 DB 대신 기존 테스트 대역 사용).

**되돌리니 빨강:** 비교 한 줄을 기존 `String(selectedChoice) === problem.answer.trim()`으로 되돌리자
같은 13개 시험이 실패했고, 재현 응답 점수도 다시 0이 됐다. 수리한 비교식을 복원했다.
이 수리에는 난수가 없다. `gradeMarks`는 변경하지 않았다.

## 안 고친 것과 원장님께 물을 것

- 복수 정답(예: ①, ④)은 `selectedChoice: number` 하나로 채점할 수 없다. 계약을 배열로 넓히고 전부 선택하는 방식으로 지원할지 원장님 결정이 필요하다. 이 트랙에서는 계약을 넓히지 않는다.
- 비소수 정답의 오답 품질 문제는 별도 범위다. 기존 `expandEngineDistractors.test.ts`가 기록한 생성기 오답 없는 다항식의 지수 변형, `deriveFormats.test.ts`가 기록한 구간의 후보 부족은 그대로 두었다. 이번에는 비소수 파생의 한 글자도 바꾸지 않는 조건을 지킨다.
