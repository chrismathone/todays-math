## 한 것

- 첫 학습 회차의 예습 카드는 자동으로 열고, `session.relearn` 회차는 첫 문제부터 연다. 카드가 있는 소단원에만 보조 단추 «개념 다시 보기»를 두었다. 같은 예습 카드를 열고 «문제 풀기»로 첫 문제에 돌아온다.
- 보기·터치 문제의 자동 넘김은 저장된 정답일 때만 2,000ms 후 실행한다. 첫 오답과 회차 끝 재도전 오답은 자동으로 넘기지 않는다. 기존 후속 풀이의 명시적 확인 흐름은 유지했다.
- 피드백 화면에 빠져 있던 보기 문제의 다음 단추도 표시했다. 다음 단추와 Enter로 즉시 넘길 수 있다. 운영체제의 움직임 줄이기가 켜져 있으면 자동 넘김을 예약하지 않으며, 대기 중 켜져도 타이머를 취소한다.
- 넘김책 왼쪽 면에 다섯 길잡이 선택 단추와 «이 친구와 시작»을 넣었다. 리드 검토를 반영해 PC는 세 열의 **3+2 두 줄**, 390px 폰은 두 열로 놓는다. 고르기 그림의 속성과 표시 비율은 모두 **200:152**다. 선택 표시와 실제 단추의 커서·hover만 적용했다.
- `getGuide()`의 `null`에서 처음 고르기를 열고, 저장된 선택은 바로 표시한다. `saveGuide(id)` 응답을 기다리는 동안에도 공부를 시작할 수 있다. 실패한 선택도 현재 앱 방문 동안 유지하고, 저장되지 않은 학생의 다음 방문은 다시 고르기부터 시작한다.
- 첫 화면의 길잡이 그림을 누르면 다시 고른다. 첫 화면에는 `guide`, 하루 마침에는 `done` 100×76과 `reward` 126×126을 세로로 놓았다. 문제 화면에는 길잡이를 넣지 않았다.
- 교사 미리보기는 선택을 메모리 안에서만 유지하며 길잡이 API를 호출하지 않는다.

### 리드 검토 후 고르기 그림 확대

PC에서 그림이 작다는 지적에 따라 3+2 배치와 최대 그림 폭 160px을 적용했다. `img`의 `width`·`height`는 200·152, CSS 비율도 200/152로 맞췄다. 원본 WebP와 총 용량은 그대로다.

계산된 크기 시험은 실제 Chromium의 이미지 박스와 투명도를 함께 읽는다. 알파 32 초과인 세로 범위에 `object-fit: contain`의 배율을 적용해 **투명 여백을 제외한 그림 높이**를 계산했다. 다섯 그림의 높이 90~115px, 속성·표시 비율 200:152, PC의 3+2 배치, 시작 단추 높이와 그림 사이 간격을 검사한다. 변경 전 [18개 실패](srs-e5-guide-screens-20261020/picker-size-red.json)를 확인한 뒤 변경 후 **18개 모두 통과**했다.

| 폭   | 변경 전 그림 높이 | 변경 후 그림 높이 | 변경 후 이미지 박스 | «이 친구와 시작»                         |
| ---- | ----------------- | ----------------- | ------------------- | ---------------------------------------- |
| 1280 | 51~59px           | **95~110px**      | 약 159×121px        | 위 612px·아래 668px, 기존과 같음         |
| 1440 | 57~65px           | **96~110px**      | 약 160×122px        | 위 632px·아래 688px, 기존과 같음         |

시작 단추 높이는 세 폭 모두 56px이다. 여섯 테마 × 세 폭의 `picker` 18장을 다시 찍고 기본 판 1280·바다 1440·숲 390 화면을 직접 확인했다. 가로 넘침·깨진 이미지·브라우저 실행 오류는 모두 0건이다. 재현 명령은 `node scripts/qa/srs-e5-guide/verify.mjs --picker-only`이며, `--measure-only`를 더하면 스크린샷을 덮어쓰지 않고 실패 기준을 측정할 수 있다. ESLint 오류 0건(기존 `img` 권고 경고 4건), 어포던스 검사와 `git diff --check`도 통과했다. 리드 요청대로 전체 타입 검사는 다시 실행하지 않았다.

- 길잡이: 구현 전 모듈 부재 실패, 느린 저장 중 공부 시작 단추가 없는 실패, 자산 25개가 없는 다섯 실패 → 구현 후 화면·자산·예습 묶음 26개 통과.
- 최종 묶음: **6개 파일, 83개 시험 모두 통과**. 모든 Vitest 실행에 `--maxWorkers=1`을 사용했다. 마지막 리터럴 타입 보완 뒤 예습 9개도 다시 통과했다(종료 0).
- ESLint: 오류 0건. 미리 최적화한 작은 WebP에 일반 `img`를 사용한 권고 경고 4건이 남는다.
- 마우스 어포던스 검사·`git diff --check`: 통과.
- 전체 타입 검사: 전체 1회는 4GB 힙 한도에서 메모리 부족으로 중단(종료 134). 전체 통과를 주장하지 않는다. 변경 파일 한정 검사에서는 시험 데이터의 `relearn` 리터럴 타입을 보완했다. Next·시험 확장 선언을 포함한 마지막 한정 검사의 남은 진단은 변경하지 않은 `src/lib/db.ts`·`bankReadFingerprint.ts`·`math-srs/courseBank.ts`의 Prisma 타입 관련 18건이며, 수정 파일 진단은 0건이다. `next-env.d.ts`는 작업트리에 없고 Prisma 생성 타입이 불완전하므로 설치·생성으로 우회하지 않았다.
