# 협의 요청 — «오늘의 영어»: 수정 요청문 단추 · 검사 표시 · 삽입 문항의 보기 (Wire — 구조 고르기) (한국어 · 파일 수정 금지 · 마크다운 90줄 이내)

너는 한국 중·고 영어 내신 수업과 교육용 소프트웨어 화면 설계를 아는 검토자다. 같은 질문을 세 검토자가 서로 보지 않고 따로 답한다.
아래 **세 안건을 하나씩 고르고** 근거 · 위험을 적어라. 듣기 좋은 말 말고 반대 의견을 우선하라. 그림은 못 보니 글로 적은 시안과 잰 값만으로 판단하고, 판단에 모자란 정보가 있으면 무엇이 모자란지 적어라. 이미 정해진 것은 다시 열지 마라.
이번은 **구조**(무엇이 어디에 서는가 · 무엇을 보이고 안 보이는가)만 정한다. 색 · 굵기 같은 시각 세부는 다음 단계다.

## 배경 — 제품
- 학원 원장(교사)이 영어 지문 하나로 내신 대비 문항 세트(보통 여섯: 주제 · 내용 일치 · 어법 · 빈칸 추론 · 문장 삽입 · 서술형)를 만든다. 만드는 길 셋: ① ChatGPT 로 제작(앱이 요청문을 복사해 주고, 원장이 자기 ChatGPT 대화에 붙여 받은 JSON 을 앱에 붙여 넣는다 — 키 없는 주 경로) ② 원문 복원 ③ API 직접 생성.
- 붙여 넣은 결과는 **검증기**를 지나야 저장된다(보기 5개 · 정답 번호 범위 · 근거가 지문의 연속 인용인가 · 요청한 문항 수와 유형). 저장되면 곧바로 **검토 · 편집 화면**(문항마다 카드: 발문 · 보기 다섯 칸 · 정답 번호 · 해설 · 지문 속 근거)으로 간다. 저장 전 미리보기는 없다 — 편집 화면이 곧 검토다.
- 제약: 문구는 사무적으로(느낌표 · 이모지 없음) · 손가락 커서와 hover 는 실제로 누르는 단추에만 · 새 색 · 새 글꼴 · 새 장식 금지(지금 화면의 토큰만) · **DB 표를 바꾸는 일은 이번 범위 밖**(원장 승인이 따로 필요) · 저장되는 JSON 에 새 칸을 더하면 배포를 두 번 해야 한다(옛 코드가 새 칸을 못 읽는다).

## 이미 정해진 것(앞선 3자 합의 — 다시 열지 않는다)
- ChatGPT 길: 검증기가 **거절했을 때만** «고쳐 달라 요청문»을 복사하게 한다. 요청문에는 저장을 막은 사유와 관측 사실(문항 번호 · 근거가 어디까지 지문과 같고 어디서 달라지는지)만 싣는다. 막지 않는 품질 검사의 지적은 싣지 않는다. **복사 전에 내용을 볼 수 있다.**
- 품질 검사 표시: 문항에 보이는 것은 **관측 사실과 위치**로(빨강이 아니다) — ⓐ 해설이 말하는 정답 번호 ≠ 정답 칸 ⓑ «모두 옳다 / 정답 없음» 꼴 보기 ⓒ 글자 그대로의 `\n` 찌꺼기. 세트 머리에 **한 줄만** — ⓓ 정답 보기만 유독 김 ⓔ 절대어(always · only · every …)가 오답에만 ⓕ 정답 번호가 한 번호에 몰림. 어법 · 삽입 · 빈칸의 «정답 오류» 검사는 정밀도가 낮아(0~41%) 보이지 않는다. **기각은 그 지적의 관련 입력과 검사 버전에 묶어 유지**한다. 수정률 · 기각률과 사람 판정으로 정확성을 확인한 뒤 표시 여부를 조정한다.

## 잰 사실
- 수정 요청문(실제 세트를 두 군데 어긋나게 해 만든 표본): **10,801자 · 115줄**. 구성 — [고칠 곳](사유 3줄) · [고치는 범위] 3줄 · [조건] · [원문] 전체 · [앞서 낸 결과](붙여 넣었던 JSON 전체) · [답 형식]. 사람이 읽을 만한 것은 앞의 열 줄 남짓이고 나머지는 ChatGPT 가 읽는 것이다.
- 거절 사유의 예(화면에 지금 나오는 빨간 알림): «가져오지 못했습니다. 아래 사유를 고쳐 다시 붙여 넣어 주세요. · **2번 문항** 지문 속 근거를 지문에서 찾지 못했습니다 (그대로 이어진 인용이어야 합니다). · **4번 문항** 보기는 5개여야 합니다 (지금 4개).»
- 거절에는 두 갈래가 있다: (갈래 1) JSON 은 읽혔는데 검증 규칙에 걸림 (갈래 2) 붙여 넣은 글에서 **JSON 을 못 찾음**(«붙여 넣은 글에서 JSON 을 찾지 못했습니다. ChatGPT 답의 코드펜스 안 내용 전부를 붙여 넣어 주세요.») — 원장이 일부만 복사했을 수도, ChatGPT 가 말로만 답했거나 답이 잘렸을 수도 있다. 앱은 어느 쪽인지 모른다. 갈래 2 에서도 요청문은 지어진다(사유 한 줄 + 붙여 넣었던 글 그대로).
- 검사 표시가 실제로 서는 빈도(벤치에 쌓인, 저장 검증을 지난 세트): **문항 줄 ⓐⓑⓒ 는 462세트에서 0건**(ⓒ 는 9-30 부터 받을 때 자동으로 줄바꿈으로 고친다 — 남는 길은 손으로 친 경우와 옛 세트). **머리 줄 ⓓⓔⓕ 는 제품 경로(luna) 30세트 중 8세트(27%) · luna 전체 289세트 중 136세트(47%)** — ⓔ 97 · ⓕ 42 · ⓓ 29세트. 정밀도는 재지 않았다(ⓔ 표본 4건을 눈으로 보니 넷 다 오답 보기에만 only · every 가 있었다 — 표본일 뿐이다).
- 편집 화면은 길다(제품 CSS 의 치수로 그린 시안에서 잰 값 — 제품 화면 자체를 잰 것은 아니다): 세트 카드(제목 · 메타 줄 · 지문) 다음에 문항 카드가 이어지고, 1280px 화면에서 문항 카드 하나가 약 750px 이다(편집 화면 위 끝에서 2번 카드의 정답 번호 줄이 1,673px, 4번 카드 끝이 3,377px).

## 안건 1 — 수정 요청문 단추(«문제 만들기 · ChatGPT 로 제작», 폭 880px 한 칸)
지금 화면의 위에서 아래: 조건 칸 → [요청문 복사] → «ChatGPT 결과 붙여넣기» 칸(10줄) → (거절되면) 빨간 알림(사유 목록) → [가져오기].
- **F1 알림 안**: 빨간 알림 안, 사유 목록 아래에 단추 둘 — [수정 요청문 복사] [요청문 보기]. «요청문 보기»를 누르면 알림 안에 읽기 전용 글 상자(10줄 높이, 굴림)가 펼쳐진다. 알림 첫 문장은 «가져오지 못했습니다. 아래 사유를 ChatGPT 에 알려 고친 결과를 다시 붙여 넣어 주세요.»로 바뀐다. 거절 직후 늘어나는 높이 **+54px** · 단추는 알림 안 · 복사까지 1번 누름.
- **F2 다음 할 일 카드**: 알림은 지금 그대로(사유만). 그 아래 새 카드 «다시 받기» — «1. 아래 요청문을 같은 ChatGPT 대화에 붙여 넣습니다. [수정 요청문 복사]» + 요청문이 **늘 보이는** 읽기 전용 상자(6줄, 굴림) + «2. 고친 답을 위 칸에 바꿔 넣고 가져오기를 누릅니다.» 늘어나는 높이 **+325px** · 단추는 알림 끝에서 아래 67px · 1번 누름.
- **F3 창**: 알림 안에 단추 하나 [수정 요청문 보기] → 창(제목 «수정 요청문» · 읽기 전용 상자 14줄 · [닫기] [복사]). 복사하려면 창을 열어야 한다(늘 본다). 늘어나는 높이 +54px · 2번 누름 · 창이 붙여넣기 칸을 가린다.
- **F4 위쪽 단추 옆**: 맨 위 [요청문 복사] 옆에 [수정 요청문 복사] [요청문 보기]. 거절 전에는 흐리게(못 누름) 서 있다. 알림에는 «위의 «수정 요청문 복사»로 …» 한 문장만. 늘어나는 높이 0px · 단추는 알림 위 끝에서 **위로 301px**(붙여넣기 칸 너머) · 1번 누름.
- 네 안 공통: 복사하면 화면의 알림 자리(상태 줄)에 «수정 요청문을 복사했습니다. 같은 ChatGPT 대화에 붙여 넣어 주세요.» 클립보드를 못 쓰는 브라우저에서는 요청문 상자를 펼쳐 직접 복사하게 한다(지금 «요청문 복사»와 같은 방식).

같이 정할 것:
- 1-가. **단추 이름** — «수정 요청문 복사» / «고쳐 달라 요청문 복사» / «고쳐 쓰기 요청문 복사» / 다른 이름. (맨 위 단추는 «요청문 복사»다.)
- 1-나. **갈래 2(JSON 을 못 찾음)에서 단추를 보일지** — 보인다 / 안 보인다 / 보이되 문구를 달리한다.
- 1-다. **복사한 뒤 붙여넣기 칸** — 그대로 둔다(원장이 새 답으로 덮어쓴다) / 비운다 / 다른 방법.
- 1-라. 거절된 뒤 원장이 조건이나 붙여넣기 칸을 고치면 요청문은 **거절된 그때의 글 · 조건**으로 짓는다(지금 화면의 사유 목록과 맞게). 이의가 있으면.

## 안건 2 — 검사 표시(검토 · 편집 화면, 1280px 화면에서 본문 폭 1000px)
표본 세트에 실제로 서는 것은 하나 — ⓔ «4번(빈칸 추론)의 오답 보기 ③ · ⑤ 에만 only 가 있다». ⓐ 는 실제로는 0건이라 «2번의 해설이 정답을 ④ 라 적고 정답 칸은 ③»인 상태를 일부러 만들어 그렸다.
- **Q1 제자리 줄**: 세트 카드의 메타 줄(«AI 생성 · 6문항 · 학교») 아래 한 줄 — «확인해 볼 곳 · 4번 빈칸 추론 — 오답 보기 ③ · ⑤ 에만 only 가 있습니다.» 문항 줄은 어긋난 칸 바로 아래(2번 카드의 정답 번호 줄 아래 — «정답 칸은 ③, 해설은 ④ 를 정답으로 적었습니다.»). 지적이 서는 높이: 4번 줄 163px(세트 머리) · 2번 줄 1,673px. 늘어나는 높이 +65px.
- **Q2 문항 머리 딱지 + 카드 끝**: 지적을 전부 그 문항에 둔다(ⓓⓔ 도) — 문항 머리(«QUESTION 04 · 빈칸 추론») 오른쪽에 «확인 1», 카드 끝에 줄. 세트 카드에는 ⓕ 만. 2번 줄 1,869px · 4번 줄 3,377px — 위에서는 아무것도 안 보인다. +66px. (앞선 합의의 «ⓓⓔ 는 세트 머리에 한 줄»과 다르다.)
- **Q3 위쪽 요약 상자**: 도구 줄(목록 · 검토 상태 · 인쇄 · 세트 삭제 · 저장) 아래 상자 하나 «확인해 볼 곳 2»에 전부 — 줄마다 [N번으로] 단추. 문항 카드는 지금 그대로. 2번 줄 101px · 4번 줄 127px. +122px.
- **Q4 눌러서 보기**: 도구 줄에 [확인해 볼 곳 2] 단추 → 창에 목록. 화면에는 아무 줄도 없다. +0px.

같이 정할 것:
- 2-가. **머리 줄(ⓓⓔⓕ)을 지금 보일지** — 27~47% 세트에서 서고 정밀도는 재지 않았다. 보인다 / 정밀도를 재기 전에는 안 보인다 / 일부만(어느 것).
- 2-나. **기각(«확인함»)** — (가) 두지 않는다: 고치면 사라지고 안 고치면 남는다 (나) «확인함» 단추를 두고 **그 브라우저에만** 기억한다(관련 글이 바뀌면 다시 선다 · 다른 기기 · 다른 강사에게는 다시 보인다) (다) 서버에 저장한다(이번 범위 밖 — 나중). 앞선 합의는 «기각을 유지»다.
- 2-다. **문구** — 위 두 예문과 이름표 «확인해 볼 곳». ⓑ «보기 ⑤ 가 «모두 옳다» 꼴입니다.» ⓒ «발문에 글자 \n 이 남아 있습니다. 인쇄하면 그대로 찍힙니다.» ⓓ «2번 — 정답 보기 ④ 만 다른 보기보다 깁니다.» ⓕ «정답 번호 — 객관식 5문항 가운데 3문항이 ①입니다.» 고칠 것.
- 2-라. ⓒ 에 **[줄바꿈으로 바꾸기] 단추**를 둘지(벤치에서 ⓒ 12건은 12건 모두 진짜였다).
- 2-마. 지적은 **편집하는 동안 바로 다시 계산**한다(고치면 그 자리에서 사라진다) / 불러올 때 · 저장할 때만.
- 2-바. 편집 화면에만 둔다 / 보관함 목록 · 인쇄 화면에도.

## 안건 3 — 삽입 문항의 보기(학생용 · 교사용 지면)
삽입 문항은 발문 안에 ( ① )~( ⑤ ) 자리가 있고 보기 값이 번호 글자(«①»…) 그대로다. 지면이 보기 번호를 한 번 더 붙여 «① ①» · «② ②»…로 다섯 줄을 찍는다(결함).
- **가**: 번호만 다섯 줄(겹친 것만 없앤다 — 높이는 지금과 같다).
- **나**: 한 줄에 «① ② ③ ④ ⑤»(문항이 네 줄 짧아진다).
- **다**: 보기 줄을 찍지 않는다(수능 꼴 — 글 속 번호에 직접 표시한다. 다섯 줄 짧아진다).
- 어법 보기처럼 보기 글이 자기 번호로 시작하는 경우(«① grow»)에도 겹친 번호를 걷을지.
