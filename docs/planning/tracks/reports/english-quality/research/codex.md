**2. 한국 내신·수능 영어의 출제 원리와 좋은 문항 기준**

**2-1. 공식 자료에서 확인되는 기준**

평가원의 공개 수능 안내서는 영어 독해에서 세부 정보, 중심 내용, 논리적 관계와 흐름 등을 평가하고, 문법·어휘도 의사소통과 정확한 이해에 연결해 다룬다. 따라서 문항의 품질은 **정답이 존재하는지와 함께, 의도한 독해 능력을 실제로 요구하는지**로 평가해야 한다. [평가원, 『2026학년도 대학수학능력시험 이렇게 준비하세요』 영어 영역, 학교 게시본](https://sw-h.goebc.kr/upload/sw-h/na/bbs_5638/2025/04/24C7E49F-18C3-E41D-9BA6-FCB5E9301D80.pdf)

학업성취도 평가의 공개 설명은 평가틀을 **영역·역량·맥락**으로 나눈다. 영어는 듣기·말하기·읽기·쓰기, 영어 의사소통·지식정보처리 등의 역량, 개인적·사회적 맥락을 고려한다. 이는 생성 요청에 유형 이름만 넣는 것보다 **평가하려는 능력과 근거를 함께 지정**해야 한다는 설계 근거가 된다. [교육부·평가원, 맞춤형 학업성취도 자율평가 안내](https://clik.nanet.go.kr/clikr-collection/policyinfo/202/1010/2022/CLIKC5611694429246770_attach_1.pdf)

내신에서는 학교의 성취기준과 수업 범위가 더 직접적인 기준이다. 경기도교육청의 2026 안내서는 평가 요소 선정, 문항 개발, 구체적인 채점 기준과 예시 답안, 협의를 통한 검토·수정을 제시한다. **서술형은 모범답안 한 개만 생성해서 완성되는 유형이 아니다.** [경기도교육청, 2026 고등학교 학생평가 운영 안내](https://www.goe.go.kr/resource/goe/na/bbs_2675/2026/05/f27cfa70-9c9d-49ac-8eb9-32d63635b87d.pdf)

**평가원의 최신 내부 영어 출제 매뉴얼 전문과 현행 내부 검수 체크리스트는 확인 못 함.** 아래 유형별 기준은 공개 평가 방향과 문항작성 연구를 제품에 맞게 구체화한 **설계 제안**이며, 평가원 내부 규칙을 그대로 옮긴 것은 아니다.

**2-2. 유형별 출제·오답 설계 기준**

공통 원칙은 다음과 같다.

- 정답은 **발문이 요구하는 기준에서 유일하게 가장 적절**해야 한다.
- 오답은 실제로 발생할 법한 오독을 반영하되, 지문 근거로 배제할 수 있어야 한다.
- 보기의 길이·문법·표현 수준만으로 답을 찾게 하는 단서를 줄인다.
- 어려움은 평가하려는 능력에서 발생해야 한다. 불명확한 발문이나 불필요한 희귀어로 난도를 올리지 않는다.

일반적인 문항작성 원칙의 근거는 [NBME Item-Writing Guide](https://www.nbme.org/sites/default/files/2021-02/NBME_Item%20Writing%20Guide_R_6.pdf)다. 다만 의학 평가용 지침이므로, 부정형 발문이나 빈칸형을 피하라는 원칙을 한국 영어의 내용 불일치·어법·빈칸 유형에 일괄 적용해서는 안 된다.

내용 일치에는 `supported / contradicted / not_stated`의 구분을 권한다. 불일치형이라면 원칙적으로 **4개는 지문에서 지지되고, 1개는 명확히 어긋나게** 설계한다. ‘언급되지 않은 것’을 묻는 문항은 별도 발문·하위 유형으로 관리하는 편이 안전하다.

예를 들어 지문이 “피드백은 구체적이고 시의적절할 때 학습에 도움이 된다”고 주장한다면, 좋은 오답 후보는 ‘피드백은 항상 효과적이다’, ‘피드백의 속도만 중요하다’, ‘학습자의 능력이 피드백의 구체성을 결정한다’ 등이다. 각각 **조건 삭제·범위 축소·관계 역전**이라는 다른 오독을 겨냥한다. 전혀 무관한 소재의 보기는 쉽게 배제되어 변별력을 낮춘다.

또한 **모든 지문에서 모든 유형을 만들 수 있다고 가정하면 안 된다.** 삽입 위치를 강하게 제한하는 연결 관계가 없거나, 적절한 어법 표적이 부족하다면 출제 부적합 사유를 반환해야 한다.

따라서 권장 순서는 **정답이 될 수 없는지 검사 → 오답으로서 그럴듯한지 평가**다. 오답 매력도 점수로 정답 유일성 결함을 상쇄해서는 안 된다.

**3-1. LLM-as-judge에 적용할 제품용 루브릭**

다음은 IWF 연구를 참고해 한국 영어용으로 재구성한 제안이다. 총점 하나보다 **결함 코드와 근거**를 남기는 방식이 적합하다.

| 평가 항목 | 판정자가 반환할 내용 | 처리 |
|---|---|---|
| 해결 가능성 | 학생에게 보이는 정보만으로 풀 수 있는가? 부족한 정보는 무엇인가? | 불가능하면 차단 |
| 정답 유일성 | 발문의 조건을 충족할 수 있는 모든 보기와 각각의 근거 | 복수·무정답이면 차단 |
| 정답표 일치 | 독립 풀이 결과와 작성 정답이 같은가? | 불일치 시 검토·수정 |
| 유형 타당성 | 해당 독해·문법 능력을 실제로 요구하는가? | 부적합하면 수정 |
| 오답 타당성·매력도 | 각 오답의 배제 근거와 예상 오독 | 타당성 결함은 차단, 매력도 부족은 개선 |
| 문항작성 결함 | 길이 단서, 문법 단서, 보기 중복·포함 관계, 불명확한 발문 | 심각도별 처리 |
| 학년·난도 적합성 | 어휘, 구문, 추론 범위, 선택지 간 구별 부담 | 추정치로 표시 |
| 서술형 채점 가능성 | 예시 답안의 조건 충족, 허용 답안·부분점수 기준 | 기준 부재 시 수정 |

판정자에게 처음부터 작성 정답과 해설을 보여 주면 그 답을 정당화할 수 있다. **독립 풀이 단계에서는 이를 숨기고**, 이후 판정 단계에서 작성 의도와 풀이 결과를 비교한다. 판정 출력에는 장문의 사고과정 대신 **보기별 짧은 근거·반증과 결함 위치**를 요구한다. 근거: [독해 문항 평가 연구](https://arxiv.org/html/2404.07720v1), [IWF 평가 연구](https://websites.umich.edu/~kevynct/pubs/L_S_2024_WorkInProgress_Question_Generation_CRFinal2.pdf).

**3-2. 난이도: CEFR·어휘·가독성·IRT를 분리해야 한다**

난이도는 적어도 네 축으로 관리하는 편이 좋다.

| 축 | 초기 측정·제어 방법 | 해석상 주의 |
|---|---|---|
| 언어 부담 | 어휘 목록 포함률, 문장 길이, 구문 특성, 보기의 언어 수준 | 긴 문장·희귀어가 많다고 좋은 고난도 문항이 되는 것은 아니다. |
| 독해 부담 | 필요한 근거 문장 수, 근거 간 거리, 생략된 추론 관계 | 생성기의 자체 설명만으로 확정하지 않는다. |
| 선택지 부담 | 바꿔쓰기 정도, 오답과 정답의 구별 기준, 예상 오독 | 의미 유사도를 높이면 복수 정답 위험도 커진다. |
| 학생 실측 | 정답률, 응답 시간, 보기별 선택률, 변별도 | 학년·수업·원문 사전학습 여부에 따라 달라진다. |

- **CEFR**은 언어 활동과 수행 수준을 설명하는 준거다. 한국 학년과 CEFR 수준의 공식적인 일대일 대응은 **확인 못 함**. 제품에서는 목표 수준 또는 추정 수준으로 표시해야 한다. [Council of Europe, CEFR Companion Volume](https://www.coe.int/en/web/common-european-framework-reference-languages/cefr-companion-volume-and-its-language-versions)
- **교육부 기본어휘**는 2022 개정 기준 3,000개 표제어이며, 초등 권장 800개·중학교 및 고등학교 공통과목 권장 1,200개·그 밖의 1,000개로 구분된다. 학년별 완전한 난이도 사전은 아니다. 교육과정 버전과 굴절·파생어 처리 규칙을 함께 관리해야 한다. [교육청 게시 기본어휘 자료](https://www.goe.go.kr/resource/old/BBSMSTR_000000030136/BBS_202307111028067791.pdf), [기본어휘 개발·적용 연구, 2023](https://www.kci.go.kr/kciportal/mobile/ci/sereArticleSearch/ciSereArtiView.kci?sereArticleSearchBean.artiId=ART002927558)
- **Lexile**은 문장 길이와 어휘 빈도 등을 이용한 자체 측정 체계다. 직접 계산한 Flesch 계열 지수를 ‘Lexile 점수’라고 부르면 안 된다. 지문 복잡도와 문항 난도 역시 구분해야 한다. [Lexile Analyzer 공식 설명](https://lexile.com/educators/tools-to-support-%20reading-at-school/tools-to-determine-a-books-complexity/the-lexile-analyzer/)

초기에는 학생 정답률과 수정 문항–총점 상관, 보기별 선택률부터 수집하는 것이 현실적이다. IRT는 이후 실제 응답 자료가 축적되면 적용한다. 같은 지문에서 파생한 문항들은 서로 영향을 받을 수 있어, 독립 문항처럼 취급하면 측정 정밀도를 과대평가할 수 있다. 공통 지문을 묶음으로 다루는 *testlet* 접근을 검토해야 한다. [NBME 문항 분석 안내](https://www.nbme.org/sites/default/files/2021-02/NBME_Item%20Writing%20Guide_R_6.pdf), [ETS, TOEFL testlet 모형 연구](https://www.ets.org/research/policy_research_reports/publications/report/2001/hygp.html)

현재 기획에서 학생 응답 수집은 후속 범위다. 따라서 당장 표시할 수 있는 것은 **언어 특성·판정자 추정 난도**이며, 실측 난도와 명확히 구분해야 한다.

**4. 유형별 결정적·비AI 검증**

핵심 전제는 **문제용 지문을 LLM이 통째로 다시 쓰게 하지 않는 것**이다.

원문을 고정하고, 모델은 “어느 문장을 삭제할지”, “어느 구절을 무엇으로 치환할지”, “어떤 경계를 후보 위치로 삼을지”를 구조화해 반환한다. 프로그램이 이를 적용해 학생용 지문을 만든다. 다음 표는 현재 저장소 구조를 바탕으로 한 구현 설계다.

| 대상 | 결정적으로 검사할 수 있는 것 | 이 검사로 보장하지 못하는 것 |
|---|---|---|
| **원문 유지** | 고정 원문과 저장 원문의 동일성, 허용한 변환 외 변경 없음, 출처·버전 해시 일치 | 원문 자체의 사실·문법 정확성 |
| **어법** | 밑줄 5개가 실제 구간을 가리킴, 번호·구간 중복 없음, 정답 구간만 치환됨, 원래 표현으로 복원하면 원문과 일치 | 치환 결과가 진짜 비문인지, 다른 밑줄이 모두 문법적으로 옳은지 |
| **어휘** | 대상 5개 존재, 지정한 1개만 치환, 나머지 내용 유지 | 치환어의 문맥 부적절성·유일성 |
| **원문 복원 빈칸** | 지정 구절 삭제, 정답이 삭제한 구절과 일치, 정답 삽입 후 원문 복원, 빈칸 수 일치 | 원문 암기 없이도 답이 유일한지 |
| **추론형 빈칸** | 빈칸 위치·개수, 원문 구절과 근거 연결, 보기 수·형식 | 바꿔 쓴 정답의 적절성, 다른 보기의 성립 가능성 |
| **문장 삽입** | 대상 문장의 특정 출현 위치가 삭제됨, 삽입 후보 5개가 실제 경계와 연결됨, 정답 위치로 복원하면 원문 일치 | 다른 위치도 자연스러운지 |
| **순서** | 원문을 빠짐·중복 없이 분할, 각 보기의 배열 유효성, 정답 배열의 원문 복원 | 다른 배열의 논리적 가능성 |
| **내용 일치** | 인용 위치 유효성, 보기·정답 번호 일치, 숫자·고유명사 변경 이력 | 자연어 문장의 함의·모순 관계 전체 |
| **요약** | A/B 빈칸과 보기 구조, 조합 중복, 정답 매핑 | 요약이 핵심 내용을 정확히 보존하는지 |
| **서술형** | 모범답안의 단어 수, 필수어 포함, 허용된 형태 변화, 형식 조건 충족 | 다른 정당한 답안의 범위, 의미상 부분 충족 |
| **학생용 출력** | 원문·정답·해설·검증 메타데이터 노출 여부, 표시 번호와 정답 매핑 | 다른 문항이 의미상 힌트를 주는 모든 경우 |
| **어휘·가독성** | 정해진 토큰화 규칙의 단어 수, 목록 포함률, 문장 길이, 가독성 공식 결과 | 실제 학생에게 느껴지는 난도 |

중요한 예외가 있다.

- **‘치환이 한 군데’와 ‘문법 오류가 정확히 하나’는 다르다.** 원문에 이미 오류가 있거나 치환이 문법적으로 허용될 수도 있다.
- **‘원문 위치로 복원됨’과 ‘삽입 정답이 유일함’은 다르다.** 전자는 문자열 사실이고 후자는 담화 판단이다.
- **추론형 빈칸의 정답은 원문과 다른 바꿔쓰기일 수 있다.** 원문 일치 검사를 모든 빈칸 유형에 강제하면 좋은 문항도 탈락한다.
- 같은 문장이 원문에 두 번 등장하면 단순 문자열 존재 여부로 삭제를 판정하면 안 된다. **특정 출현 위치**를 추적해야 한다.
- 품사 분석기·문장 분석기가 통계 모델을 사용한다면 그 결과는 비AI 확정 검사와 별도로 분류해야 한다.

권장 문항 구조에는 다음 정보가 필요하다.

| 정보 | 용도 |
|---|---|
| `schemaVersion`, `questionId`, 고정된 `optionId` | 계약 변경 대응, 보기 재배열 후 정답 추적 |
| `subtype`, `polarity` | 주제/제목/요지, 일치/불일치 구분 |
| `sourceRefs`, `edits`, `boundaries` | 삭제·치환·배열·삽입을 재현 |
| `evidenceSpans[]` | 떨어진 여러 근거를 각각 정확하게 인용 |
| `optionRationales` | 정답 근거와 오답별 배제 사유 |
| `rubric`, `answerConstraints` | 서술형 허용 답안과 채점 조건 |
| `qualityReport`와 콘텐츠 해시 | 검사 결과가 어떤 문항 버전에 해당하는지 확인 |

모델이 계산한 문자 오프셋은 그대로 신뢰하지 않는다. `문장 ID + 인용문 + 해당 문장의 몇 번째 출현` 등을 프로그램이 해석해 위치를 확정하는 방법이 안전하다. 현재의 `evidence` 연속 인용 검사는 유지하되, **여러 개의 유효한 구간**으로 확장하면 추론·삽입 문항을 더 잘 설명할 수 있다.

**5. 비용과 지연을 고려한 파이프라인**

**5-1. 권장 기본 경로**

**생성 → 결정적 검사 → 정답을 가린 다른 모델의 독립 풀이 → 코드로 정답 비교 → 필요한 문항만 판정·수정**

처음부터 모든 문항에 생성·풀이·판정·재판정을 반복하는 방식은 지연이 크다. 우선 **생성 1회 + 독립 검증 1회**를 기본으로 도입하는 것을 권한다.

| 단계 | 입력·역할 | 실패 처리 |
|---|---|---|
| **출제 가능성 판단** | 원문 특성과 요청 유형·조건을 확인한다. 초기에는 생성 응답에 적합성 판단을 포함해 추가 호출을 줄인다. | 근거 부족 유형은 사유와 함께 보류 |
| **생성 G** | 원문, 출제 사양, 유형별 제약 → 구조화 문항 | JSON 실패는 기존 재시도 활용 |
| **결정적 검사 D** | 변환·복원·번호·인용·출력 조건 검사 | 의미 검증 호출 전에 수정 대상 확정 |
| **독립 풀이 S** | 다른 모델에 학생용 문항만 제공. 각 보기의 성립 가능성과 선택 답을 반환 | 무정답·복수 후보·정답 불일치 검출 |
| **조건부 판정 J** | 작성 근거, S의 응답, 원문, 유형별 루브릭 비교 | 구체적인 수정 지시 생성 |
| **수정 R, 최대 1회** | 실패한 문항만 수정. 고정 원문과 유지할 필드 명시 | 수정 후 D와 필요한 S/J를 다시 수행 |
| **저장·표시** | 자동검사 결과와 교사 검토 상태를 별도로 저장 | 미완료·불확실을 통과로 표시하지 않음 |

독립 풀이자에게 제공할 입력이 중요하다.

- 제공: 발문, **학생용 문제 지문**, 보기.
- 숨김: 작성 정답, 해설, 오답 사유, 삭제 전 구절, 정답 위치가 들어 있는 변환 정보.
- 빈칸·어법·삽입 문항에는 **변형 전 원문도 숨긴다.**
- 각 보기를 `발문 충족 / 불충족 / 판단 불가`로 평가하게 한다. 불일치형에서는 ‘지문에서 참인 보기’와 ‘정답 보기’를 혼동하지 않도록 한다.
- 문항 단독 검증과 별도로 세트의 원문·다른 문항을 통한 답 노출을 검사한다.

다른 모델을 사용하면 생성기의 해석에 끌려갈 위험을 줄일 수 있지만, **두 모델의 일치가 유일정답의 증명은 아니다.** 보기 순서를 바꾸거나 지문을 제거한 검사는 오프라인 평가·의심 문항에 선택적으로 적용하는 것이 비용상 적절하다. 근거: [독해 문항의 지문 유무 평가](https://arxiv.org/html/2404.07720v1), [자체 수정의 한계](https://proceedings.iclr.cc/paper_files/paper/2024/hash/8b4add8b0aa8749d80a34ca5d941c355-Abstract-Conference.html).

2026-09-30에 확인한 DeepSeek 공식 가격표는 `deepseek-v4-pro`에 대해 다음 단가를 제시한다. 달러/100만 토큰 기준이며 가격은 변동될 수 있다. [DeepSeek 공식 가격표](https://api-docs.deepseek.com/quick_start/pricing/)

| 항목 | 비혼잡 시간 | 혼잡 시간 |
|---|---:|---:|
| 입력, 캐시 미적중 | $0.66 | $1.32 |

예를 들어 **캐시 미적중 입력 6,000토큰 + 과금 출력 10,000토큰**을 가정하면 생성 1회의 비용은 약 **$0.024 / $0.048**이다. 이는 계산 예시이며 현재 저장소의 실측 사용량은 아니다. 독립 모델 비용은 해당 모델 단가로 별도 계산해야 한다.

운영 예산은 다음처럼 잡을 수 있다.

`평균 비용 = 생성비 + 독립 풀이비 + 판정 대상 비율 × 판정비 + 수정 비율 × (수정비 + 재검증비)`

지연은 사용자 제공치인 **생성 40~120초**를 기준으로 한다.

- 기본 경로: `40~120초 + 독립 풀이 시간`.
- 동일한 지연의 모델을 생성·풀이·판정에 직렬로 세 번 사용한다면 **2~6분**이다. 이는 산술 예시다.
- 수정한 문항을 다시 검사하면 추가 시간이 필요하다.
- 다른 모델을 쓴 검증 경로의 실제 p50·p95 지연과 전체 비용은 **확인 못 함**.

현재 `callAi()`는 텍스트만 반환해 사용량과 모델 정보가 호출부에 남지 않는다. 품질 고도화 전에 **단계별 모델·버전·토큰·소요 시간·실패 코드**를 기록해야 비용과 효과를 비교할 수 있다. JSON 재시도와 의미 수정에는 공통 총예산을 두어 재시도가 중첩되지 않게 한다. [현재 AI 클라이언트](C:/Users/user/orca/workspaces/todays-math/english-making/src/lib/ai/client.ts:68)

**5-4. ChatGPT 복사·붙여넣기 경로**

API 없이도 같은 검증 구조를 적용할 수 있다.

1. **생성 요청 복사**  
   현재 요청문을 구조화 계약으로 확장한다. 모델에게 검수를 지시하더라도 결과는 ‘생성기 자체 확인’으로 기록한다.

2. **결과 붙여넣기 → 로컬 결정적 검사**  
   변환·복원·인용·보기·단어 수 검사를 브라우저에서도 수행한다.

3. **‘검증 요청 복사’ 제공**  
   프로그램이 정답·해설·복원 원문을 제거한 독립 풀이 요청을 만든다. 새 대화, 가능하면 다른 모델에서 풀게 한다. `questionId`, 보기 ID와 콘텐츠 해시를 포함한다.

4. **검증 결과 붙여넣기 → 정답 비교**  
   작성 정답과 독립 풀이의 선택 답·복수 후보를 비교한다. 해시가 다른 오래된 결과는 적용하지 않는다.

5. **필요한 경우 ‘수정 요청 복사’**  
   실패 문항과 결함만 전달한다. 수정 결과에도 동일한 검사를 반복한다.

추가 복붙이 부담인 사용자는 결정적 검사까지만 사용할 수 있어야 한다. 이 경우 화면에는 **‘형식·원문 검사 완료 / 독립 풀이 미실시’**처럼 실제 수행 범위를 표시한다. API 검증을 받지 않았다는 이유만으로 저장을 막을 필요는 없다.

**7. 개선 효과를 판정할 최소 평가 계획**

다음 수치는 연구 결과가 아닌 **제품 평가를 시작하기 위한 제안 규모**다.

- 현재 AI 생성 6개 유형을 균형 있게 포함한 **120~180문항**으로 시작한다.
- 교사 2명이 생성 방식과 모델을 모르는 상태에서 검토하고, 불일치는 합의 판정한다.
- 같은 원문에서 만든 변형들은 하나의 묶음으로 분리해 평가 자료 누출을 막는다.
- 비교군은 `현재 v1`, `v2 프롬프트`, `v2+결정적 검사`, `+독립 풀이`, `+조건부 수정`으로 둔다.
- 실제 학생 자료가 없을 때의 오답 매력도는 ‘교사 추정’으로 표시한다.

| 핵심 지표 | 측정 목적 |
|---|---|
| **자동 통과 문항 중 치명 결함률** | 통과를 신뢰할 수 있는가 |
| **복수 정답·무정답·정답표 오류율** | 가장 중요한 의미 결함이 줄었는가 |
| **유형별 결함 탐지율·오탐률** | 검증기가 특정 유형을 놓치거나 과도하게 탈락시키는가 |
| **교사가 수정 없이 채택한 비율** | 현장 사용성이 좋아졌는가 |
| **사용 가능한 세트당 교사 수정 시간** | 원장의 실제 작업 시간이 줄었는가 |
| **검증 통과 문항당 비용·p50/p95 지연** | 추가 호출이 경제적인가 |
| **학생 보기별 선택률·변별도** | 오답이 실제로 기능하는가 |

난도와 오답 매력도를 본격적으로 보정할 때는 **원문 사전학습 여부**도 수집해야 한다. 같은 문항이라도 원문을 암기한 내신 대비 학생과 처음 읽는 학생의 반응은 다르다. 실제 응답 자료를 얻기 전에는 **한국 중·고 학생에 대한 난도 적합성과 오답 매력도 개선 폭은 확인 못 함**으로 남겨 두는 것이 정확하다.
