## 리드의 추가 지시 반영

| 확정 지시                         | 반영                                                                                                                                                         |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 휴대폰에서 못 읽은 답을 글로 수정 | 촬영과 결과 사이 `읽은 답 확인`. 입력한 칸에 `직접 입력`, 교사 화면에 같은 지면·문항 ID로 원본 대용 지면과 입력문을 좌우 대조. 분수·도·좌표 입력 보조도 시연 |
| ○ · △ · × 및 확인 필요            | 네 상태를 구별. △는 일부 충족, 확인 필요는 판독 불확실로 보여 주며 오답과 구별하는 안. 교사가 이유와 함께 네 상태로 수정 가능                                |
| 채점 전에 찍는 안내               | 촬영 화면 상단에 `채점 전에 찍어 주세요. 채점 표시가 없는 답안을, 모서리와 QR까지 한 쪽 전체가 나오게 찍습니다.`                                             |
| 문항·정답은 인쇄 때 저장          | 모든 화면의 전제로 명시. 은행 변경 상태는 `저장 전 옛 지면 · 코드 확인 필요`에만 한정. 현재 은행 정답으로 소급 채점하는 단추 없음                            |

추가 지시 2의 고정 구조도 반영했다. **사진 위 문항의 답 칸 표시 + ①②③ 번호 → 사진 아래 같은 번호 입력란**이다. 초기 지시의 전체/불확실 목록 비교보다 최신 고정 구조를 우선했다. 실제 AI 좌표가 아니라 **제품 쪽 나눔이 그린 답 칸의 DOM 좌표**를 쓴다. 사진 맞춤·원근 보정이 구현됐다는 뜻은 아니다. 모서리 표식 필요 여부는 아래 물음으로 남겼다.

## 실제 은행의 고르기

모두 초5 `2-3 합동과 대칭 / 2-3-3 선대칭도형과 그 성질 알아보기`. `loadGradeBank("초5")`로 원래+보강 은행을 읽고 `composeSheets`와 `encodeSheetCode`를 사용한다. 문항·참고 답·그림을 시안용 문장으로 바꾸지 않았다. 제목과 날짜는 입력 표본이며 학생 기록은 아니다.

| 표본   | 실제 고르기                         | 학생지 / 채점표 | 코드                  |
| ------ | ----------------------------------- | --------------- | --------------------- |
| single | B 하 3, ○× 0                        | 1 / 1쪽         | `1RYH.3S4J.0FFG.Y5`   |
| multi  | B 하·중·상 각 6, ○× 각 1            | 3 / 2쪽, 21문항 | `1RYH.199A.V80G.0Y9`  |
| all    | A~E 본 수 하2·중1·상1, B/C 추가 하1 | 6 / 5쪽         | `1RYK.ZBES.6S6D.MQS0` |

`all`은 A 1쪽 · B 1쪽 · C 1쪽 · D 2쪽 · E 1쪽이다. E는 실제 재고가 그림 하나라 세 칸(이름표 하나·설명 두 줄)이다. 요청 수를 맞추려고 가짜 그림을 추가하지 않았다.

multi의 제목은 계약 상한 **40자**인 `선대칭도형과 점대칭도형의 성질 비교와 대응하는 점과 변과 각 설명해 보기`다. 사용자가 입력할 수 있는 긴 머리의 부담 표본이며 고르기 범위를 넓혔다는 뜻은 아니다. 짧은 머리·긴 여러 쪽·다섯 형식을 같은 면에서 함께 비교한다.

교사 학생 선택의 `학생 가/나/다`는 선택 구조를 보기 위한 명시적 가상 계정이다. 실제 학생 명단이나 답안을 읽지 않았다. 결과의 ○△×는 상태 배치 시연이며 채점 정확도 자료가 아니다.

세 쪽 각각 실제 앞 두 서술 답 칸을 `못 읽음` 상태로 시연한다. 번호는 문항 번호와 다르므로 입력란에 `① · 2쪽 문 8`처럼 쪽과 문항을 함께 적는다. 입력 방법은 글/수식 직접 입력, 분자·분모, 각도+°, x·y 좌표다. 입력 보조는 글을 답란에 넣을 뿐 판독·채점·정답 추정은 하지 않는다. 모든 직접 입력은 새로고침 전 화면 메모리만 유지한다.

못 읽은 칸 **0개**는 별도 상태 선택으로 볼 수 있다. 표시·빈 입력란을 만들지 않고 `못 읽은 답 칸이 없습니다`와 결과로 가는 행동을 제시한다. ○△× 공개 전/후 수정 문구는 선택한 안에 따른다.

채점 중은 임의 퍼센트나 예상 시간을 쓰지 않는다. 채점 완료 결과는 교사 확정 대기 없이 공개하고 나중에 교사가 판정과 이유를 수정한다. 처리 실패/재시도 상태도 제공한다.

A는 개념별 대조, B는 질문 답과 ○× 까닭, C는 문장 빈칸과 적용, D는 가지별 질문, E는 이름표·설명 칸을 구별한다. 현재 은행의 B 명칭은 `개념 질문`이다. 옛 명칭만 가정해 새 문항을 만들지 않았다. 직접 입력 대조는 원래 3쪽 표본의 코드·문항에 묶고, A~E 결과 표본과 별도임을 화면에 명시한다.

## 치수와 QR 근거

- 제품 A4 실측 **793.6875 × 1122.515625px** (CSS 210 × 297mm, 96 CSS px/in). 첫 쪽 패딩 36/50/20px, 다음 쪽 24/50/20px. 본문 폭 약 694px.
- QR 오른쪽 끝은 네 안 모두 종이 끝에서 **50px = 13.229mm**. 기존 코드 줄 끝과 종이 아래 사이 **20px** 유지.
- 실제 코드와 쪽을 포함한 주소 제안은 학생지에서 **86/87/88 ASCII 문자**다. 예: `https://today.aywa.co.kr/concept-blank/scan?code=1RYK.ZBES.6S6D.MQS0&page=1&part=student`. origin의 근거는 기존 교재 발행 코드 `publish/deps.server.ts`의 서비스 주소 예시다. **이 새 경로는 제안이며 라우트 미구현, 주소 요청 0건**이다. 최종 식별자/주소가 달라지면 QR 밀도를 다시 재야 한다.
- 기존 `browserQrDataUrl`과 동일하게 오류 정정 **M**, 사방 여백 **4모듈**, 원본 PNG 모듈당 6px로 생성한다. 실제 표본은 QR 버전 5(37×37) 또는 6(41×41).

| 안  | QR 전체 한 변(여백 포함) | 한 모듈: 37/41 격자 | 300dpi에서 최소 dots/module | 300dpi 복호화 | 96dpi 관측 |
| --- | -----------------------: | ------------------: | --------------------------: | ------------: | ---------: |
| P1  |       20mm (실측 19.997) |     0.444 / 0.408mm |                        4.82 |         18/18 |      18/18 |
| P2  |       24mm (실측 23.999) |     0.533 / 0.490mm |                        5.79 |         18/18 |      13/18 |
| P3  |       28mm (실측 27.996) |     0.622 / 0.571mm |                        6.75 |         18/18 |      18/18 |
| P4  |       22mm (실측 21.998) |     0.489 / 0.449mm |                        5.30 |         10/10 |      10/10 |

계산은 `전체 한 변 ÷ (격자 한 변 + 8)`, dots는 `mm × 300 ÷ 25.4`다. QR 개발사 DENSO WAVE는 사방 4모듈 여백을 요구하고, 인쇄 해상도와 모듈의 점 수로 면적을 계산하는 예를 제시한다([공식 설명](https://www.qrcode.com/en/howto/code.html)). 이 근거와 위 실측은 설계 크기를 비교하기 위한 것이며 **폰 카메라 인식 보장이나 최소 규격 인증이 아니다**.

12조합/72쪽(학생지+채점표) 중 **P3 multi 채점표 1쪽에서 본문 영역 넘침 25.984px**, 나머지 71쪽에서는 측정된 넘침 0. P3의 약점을 화면에도 공개했다. 제품 쪽 나눔을 몰래 바꾸거나 본문을 줄여 숨기지 않았다.

64개 QR 모두 300dpi 대응 래스터에서 `jsqr`가 원래 주소와 일치하게 복호화했다. 96dpi의 P2 다섯 실패는 기록에 남겼다. 화면 재샘플링에 따라 더 큰 QR도 불리할 수 있으므로 크기 순서만으로 인식률을 단정하지 않는다. 실물 프린터, 휴대폰 사진, 흔들림·원근·그림자·필기 겹침·복사 품질은 이번에 검증하지 않았다.

## 원장님께 물을 세부와 남긴 물음

1. 지면 P1~~P4, 촬영 C1~~C4, 읽기 V1~~V4, 결과 R1~~R4 중 선택. P3는 채점표 넘침이 있는 그대로의 비교안이다.
2. **사진 맞춤용 네 모서리 표식이 필요한가, QR 하나로 충분한가?** 실제 전체 쪽 사진에서 원근·굴곡·잘림을 검증하기 전에는 정하지 않았다. 이번에는 답 칸 위치를 알고 있다는 전제만 시연했다.
3. 최종 QR 주소·인쇄 저장본 ID·쪽/몫 표기. 현재 `pick` 직접 고르기는 기존 코드가 지원하지 않고, 과도하게 긴 기존 코드에는 `코드 없음`도 있으므로 저장본 식별과 수동 코드 경로를 별도로 설계해야 한다.
4. 공개 전 수정/공개 뒤 수정, 수정 가능 횟수와 마감, 사진에 쓴 답과 새로 고친 답의 구분, 재채점 이력. 확정하지 않은 운영 정책은 넣지 않았다.
5. △의 실제 기준·부분점수와 A~E 합산 단위, 확인 필요를 종합 점수에서 어떻게 다룰지. 종합 점수의 산식은 임의로 만들지 않았다.
6. 번호는 쪽마다 재시작할지 이어갈지, 번호 딱지 위치·밑줄/형광/테두리, 답 칸 확대와 수식 입력 보조의 기본 노출 여부.
7. 인쇄 당시 문항·정답·레이아웃과 답 칸 위치의 동결 방식, 저장 전 옛 지면 확인 경로. 은행 변경 뒤 새 정답을 적용하지 않는다는 경계만 반영했다.
8. 사진의 이름 줄 등 개인정보 처리·보관 기간·삭제, 외부 전송 고지의 최종 문구/자리. 서버 키·Claude 모델·비용·지연·정확도는 호출하거나 추정하지 않았다.

시안 선택과 위 세부 결정, 실제 답안의 사진 맞춤/읽기 검증을 거친 뒤 Hi-fi 및 제품 구현으로 이어갈 수 있다. 이 보고서는 제품 채점 기능이나 실물 인쇄 검수의 완료 보고가 아니다.
