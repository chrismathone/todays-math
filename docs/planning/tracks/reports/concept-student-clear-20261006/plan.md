# 학생이 이해하고 답할 수 있는 개념백지로 재설계

사용자 지적(2026-10-06): 제목만 제시하는 B형의 「조각의 개수만 견주기」「분모와 몫」은 무엇을 쓰라는 것인지 알 수 없다. C형 「구한 몫에 나누는 분수를 곱하면 □가 되어야 한다」도 상황 없이 읽으면 답을 떠올리기 어렵다. 「나누어지는 분수가 나누는 분수보다 □ 몫은 1보다 작다/크다」처럼 작은·큰을 답하는 문장은 의도가 바로 보이므로 좋은 기준이다. 필요하면 모든 내용을 바꾸더라도 실제 학년에 도움이 되는 명확한 문항을 원한다.

## 판단 기준

학생은 해당 학년과 이전 과정에서 배운 것만 알고 있다고 가정한다. 개념명·소단원·정답·앞 문제·교사의 보충 설명이 실제 지면에 없으면 사용하지 않는다. 질문만 보고 무엇에 대해 어떤 종류의 답을 써야 하는지 알 수 있어야 한다. 어른이 익숙한 문장을 복원할 수 있다는 사실로 학생의 이해를 대신하지 않는다.

B형은 제목을 개념 이름인 것처럼 제시하지 않고, 필요한 조건과 물음을 갖춘 질문을 쓴다. C형은 짧은 낱말·익숙한 관계·구체적인 수나 식으로 답할 수 있어야 한다. 배 관계·조각 같은 표현은 학생이 이미 아는 정확한 말로 풀거나 상황과 그림·식을 함께 준다. 수학적 내용의 범위를 보존하고 조건과 결론을 동시에 가리지 않는다. 모호한 답을 학생의 부족한 개념으로 판단하지 않는다.

각 문항의 학습 목표와 확인할 답을 맞춘다. 질문을 늘리는 데 그치지 않는다. 유용한 정상 문항은 유지하고, 설명 범위가 없는 조각 제목·의미가 반복되는 형식·아무 개념을 확인하지 못하는 문항은 교정 또는 해당 형식에서 제외하는 것을 검토한다. 제거가 필요한 경우 ID를 밀거나 학생 이력을 삭제하지 않고 배제 근거를 기록한다.

## 진행과 분담

최신 main을 기준으로 초3~4, 초5~6, 중1~3을 Orca Codex 작업으로 나눠 실제 B형 제목과 C형 학생 문장을 전수 읽고, 문항별 유지·교정·제외 이유와 수정안을 기록한다. 이 단계는 검토 초안이며 생산 코드에 먼저 적용하지 않는다. 리드는 화면/인쇄/교재 스냅샷/복습 데이터의 공용 계약을 검토하고, 계획과 구체적인 좋은·나쁜 사례를 독립 Claude 검토로 확인한 뒤 최종 구현 작업을 배정한다. 사용자가 승인한 Codex·Claude 검토 방식을 유지한다.

질문과 개념 설명은 별도의 필드로 관리하는 방안을 우선 검토한다. C형 문장을 B형에 그대로 노출하거나 빈칸 정답을 질문 속에 쓰지 않는다. 설명 질문은 실제로 확인하려는 개념 전체와 채점 기준이 맞아야 한다. 단순히 모든 제목 뒤에 「설명하시오」를 붙이지 않는다.

독립 검토는 학생에게 실제 보이는 물음으로 먼저 답과 풀이 근거를 쓰고, 그 뒤 작성자의 예시 답과 대조한다. 의미가 다른 여러 정답, 상황 누락, 낯선 표현과 단순 문법 맞추기는 따로 판정한다. 같은 뜻의 표현이나 동치인 식은 허용한다. 사용자가 좋은 기준으로 지정한 두 비교 문장의 실제 원문 답은 「작으면」「크면」이며 문법을 변경하지 않고 유지한다.

B의 고정 질문은 `bQuestion: { prompt, answer, requiredIdeas }`처럼 물음·예시 답·꼭 포함할 내용으로 관리한다. 모든 개념 ID에는 B 질문 또는 형식별 제외 사유를 기록하며, 질문을 만들지 못한 B 문항을 제목이나 임의 fallback으로 출제하지 않는다. 실제 적용 물음으로 바꾼 경우 예시 답도 그 사례와 맞춘다. 새 고정 질문은 서버·학년별 적재·새 교재 스냅샷이 동일하게 사용한다. 기존 스냅샷에 없는 필드를 현재 은행에서 몰래 보충하지 않는다.

C에도 별도의 `clozeQuestion`을 둬 일반 개념 설명 `definition`과 평가 문장을 분리한다. 구체 식이 필요한 문항을 C용 사례로 고치더라도 A형 복습·교재·SRS의 일반 설명을 임의의 수에 종속시키지 않는다. 일반 설명 자체에 수학 오류나 이해하기 어려운 표현이 있으면 별도의 `coreAfter`로 교정하고 연동 원천을 함께 검증한다. 질문용 조건·사례와 개념 원천을 구별해 기록한다.

필수 내용은 물음에서 요구한 내용만 둔다. 이미 물음에 적힌 요소, 사전 용어로 다시 써야만 맞다고 하는 조건, 요구하지 않은 긴 설명은 채점의 필수가 아니다. 타당한 다른 풀이·동치 답·같은 개념을 설명하는 표현은 예시 답과 다른 문장이어도 인정한다. 여러 다른 개념을 구별할 수 없을 때는 문항을 고치거나 해당 형식에서 제외한다. 한 낱말만 쓰는 B를 유지하면 그 학습 목표와 C와의 역할 차이를 기록한다.

채점 요소는 `requiredIdeas`의 각 원소를 `{ anyOf: string[] }`로 둔다. 원소들은 모두 필요한 독립 내용이고 한 원소 안의 표현들은 같은 내용을 보이는 대안이다. 이는 교사가 읽는 의미 기준이며 문자열 일치 규칙이 아니다. 이미 물음에 제시한 말의 재진술을 요구하지 않는다. 식으로 정확히 답하거나 구체 수로 설명한 경우도 인정하고 예시 답은 허용 답의 전부가 아니다. 새로운 자동 채점 정책을 만들지 않는다.

서로 다른 형식은 별도 학생지로 구성된다. 혼합 구성에서 같은 문항의 완성 답을 다른 문제 본문으로 제공하지 않는지 확인한다. 사용자가 승인한 작으면·크면 짝은 대비해 배우는 유효한 문항으로 유지하며, 단순히 반대 관계의 짝이라는 이유로 제거하지 않는다. 학생에게 적합하지 않은 형식의 제외와 개념 자체의 폐기를 구별한다.

한 인쇄 페이지에는 한 형식만 들어가며 같은 ID의 B·C를 한 페이지에 함께 싣지 않는다. 각 질문 자체의 답을 다른 본문에서 복사하게 하는 누출은 질문 코호트 검토에서 제거한다. 여러 형식의 연습지가 같은 개념을 확인하는 것은 허용하되, 한 낱말 B는 학습 목표와 형식별 역할을 기록한다. 그림이 꼭 있어야 답하는 B는 실제 그림을 제공하지 못하면 B에서 제외한다. 기존 E형 그림 문항과 별도 그림 자료를 임의로 다른 문제의 그림처럼 붙이지 않는다.

질문의 원문·답·채점 요소가 바뀌면 그 내용의 지문과 버전을 기록한다. 기존 정오·숙달 기록을 새 문항을 풀었다는 기록으로 다시 해석하지 않는다. 문항과 키의 대응, 전 ID 검토 누락, 현재 출제되는 질문의 검토 지문, 학생용 지면의 정답 노출, 조판과 수식은 각각 검증한다. 학년별 구체적인 B 질문과 예시 답, C의 좋은·나쁜 사례를 계획의 독립 검토에 함께 제시한다.

## 적용과 완료 조건

현재 지원되는 초3~중3 전체의 검토 ID를 보존하고 수정·유지·제외를 집계한다. 새 질문과 바뀐 C 문장은 독립 검토와 학생용 지면 확인을 거친다. 좋은 작은·큰 문항은 불필요하게 바꾸지 않는다. 모든 과목 성취기준 전수 검증이나 실제 학생 실험을 했다고 주장하지 않는다.

공용 개념백지 및 교재 제작의 B형 질문·C형 빈칸·채점표가 같은 데이터를 읽는지 확인한다. 정적 교재 설명과 복습 명제가 바뀌면 출처·질문·정답·오답 칩까지 함께 재검증한다. 개념 ID·관계·학생 기록을 보존하고 발행본의 고정 자료를 덮어쓰지 않는다. 바뀐 지면의 길이를 조판 비용에 반영하여 실제 인쇄에서 답 칸, 줄바꿈, 넘침과 수식을 확인한다.

최신 원격을 병합하고 검사 후 정상 푸시한다. 운영 배포를 확인하고 완료한 깨끗한 작업 폴더는 가지를 보존하여 정리한다. 수정 수나 형식 검사만으로 학습 효과까지 입증했다고 말하지 않는다.

## 독립 설계 검토에서 채택한 구체 조건

Claude의 설계 검토는 방향에 동의하면서 일곱 가지 보강을 요구했다(`design-evidence/plan-contract-raw.md`). 아래 조건을 채택하여 프레임워크를 구현한다. 예시 문항의 내용 승인은 별도 블라인드·답 범위 검토로 진행한다.

- `anyOf`의 대안은 별도 배열 원소로 저장한다. 각 필수 의미에는 삭제 검사(빠져도 옳은 답이면 독립 필수가 아니다)와 베껴 쓰기 검사(물음의 말만 옮겨 적어도 충족되는지)를 적용한다.
- C는 `{ sentence, acceptedAnswers: string[][] }`이다. 배열 한 칸이 빈칸 하나와 대응하며 지문에 쓴 정답을 반드시 포함한다. 같은 값·같은 뜻의 표현도 인정한다. 유지 결정도 원문 자체를 명시 저장하고 `coreAfter`에 따라 바뀌지 않는다.
- 결정 대장은 ID×형식으로 유지·교정·제외를 기록한다. 학습 역할은 정의 회상·절차·까닭·적용·명명 등 문항별 목표로 남기고, 목표 이동과 코호트 내 반복을 확인한다.
- 독립 1차에는 학년과 실제 보이는 물음만 제공한다. 2차에 원문·참고 답·의미 기준을 공개한다. 여러 다른 개념의 답·상황 누락은 교정 또는 제외하고, 같은 뜻의 대안은 인정 답으로 남긴다. 낯선 표현은 해당 단어와 검토자의 학년 판단이 추정임을 명시한다.
- 직접 답 베끼기 검토의 단위는 같은 형식의 학생지 한 벌(여러 페이지 포함)이다. B·C처럼 별도 형식이 같은 개념을 연습하는 것은 허용한다. 흔한 낱말이 다른 개념 설명에도 나타나는 사실만으로 일괄 제외하지 않는다.
- 질문 필드가 없는 구 동결 자료의 B는 당시 제목과 당시 채점 기준을 유지한다. 새 질문으로 바꾸려면 새 판본에서 현재 항목을 다시 확인·발행한다. 과거 기록은 저장된 판본·내용 해시를 통해 해석하며 새 질문을 풀었다고 재해석하지 않는다. 판본이나 문항 지문이 없는 기록으로 새 문항의 숙달을 주장하지 않는다.
- 제외 뒤의 재고는 B·C별로 집계한다. 자동 고르기는 출제 가능한 문항 수로 숫자 칸을 제한한다. 정확한 선택이나 발행에서 제외 항목을 특정 형식으로 요구하면 오류와 선택 변경 안내를 반환하며 임의 대체하지 않는다. 일반 개념과 학생 이력은 보존한다.

현재 필드 이름은 `questionRevision`, `bQuestion`, `clozeQuestion`, `questionExclusions`이다. 새 문항의 두 형식 결정과 판 번호가 모두 필요하며, `null`이면 해당 형식의 제외 사유가 필요하다. 현재 은행은 전 ID 검토 기록을 함께 적재하고, 구 동결 자료를 현재 은행의 질문으로 보충하는 경로는 만들지 않는다.
