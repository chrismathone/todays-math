계획만 작성한다. 각 ID의 원본 definition과 coreAfter를 실제로 읽고 일반 학습 설명의 뜻을 보존한다. coreAfter는 학생 학습/SRS definition에 적용할 문장으로 C 평가문장과 다르다. 구체 산수 예 하나로 일반 개념을 대체하지 말고 새 수학 범위를 만들지 않는다. 실제 오류·불명확한 말에 필요한 교정 이유를 유지한다. 표준 이름/개념은 중학생이 이해할 쉬운 말로 쓴다. 각 coreAfter에는 꼭 1~4개 {핵심어} 표지가 있어야 하며, 기존 핵심어가 유효하면 유지한다. 단순 형식 통과를 위해 낱말 아무 데나 감추지 말고 개념의 핵심을 판단한다. 기호 LaTeX 내부 중괄호는 표지가 아니다. 화면에서 보이는 길이는 최대160자이다(수식은 글자 수가 아닌 렌더링 의미로 간략하게). 길면 중복만 줄이고 조건/대상/일반 관계를 빠뜨리지 않는다. 숫자·기호는 $...$ KaTeX로 작성한다. 질문에 붙는 답을 C로 사용하지 않는다.
출력은 ID순서 동일한 [{id,coreAfter,coreReason,coreRepairReason}] JSON배열이다. coreRepairReason은 원본 핵심어/의미를 어떻게 지켰는지 실제 내용을 짚는다. 형식상 이미 좋으면 그대로 보존하고 이유를 짧게 기록한다.
