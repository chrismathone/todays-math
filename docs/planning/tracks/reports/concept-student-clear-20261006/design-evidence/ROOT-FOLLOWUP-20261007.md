# 실제 문항 재독과 후속 통합

이 폴더의 Root 읽기 기록은 생산 적용이나 독립 승인과 구별한다. 수정 후 정규화된 실제 B 질문·답·필수 의미, C 문장·허용 답, 바뀐 일반 설명을 읽고 현재 장부와 연결했다. 독립 검토의 원문 응답과 입력은 별도로 보존한다.

초3~4의 `root-e3e4-dispute-assist-application-20261007.json`은 최초 적용 시도 기록이다. 행 배열을 문서에 다시 넣지 않아 저장 결과가 바뀌지 않은 오류를 실제 저장 해시 대조에서 발견했다. 이 파일을 현재 적용 증거로 사용하지 않는다. 수정 후 읽어서 저장한 `root-e3e4-dispute-assist-application-v2-20261007.json`이 이를 대체한다. 이후 fresh, partition, last-two, final-reasons 기록은 각 시점의 수정과 재독이며 과거 입력을 덮어쓰지 않았다.

초3 `e3-1-6-1-xc2`의 일반 설명은 원래의 모양과 크기·포개기 설명을 유지한다. C에서 크기를 비교하는 예제를 일반 정의 변경으로 확대하지 않는다. 마지막 B는 세 조각을 실제로 포갠 결과를 판단하도록 바꿨다.

초5~6의 최종 전달 이후 Root의 fresh-22, fresh-8, fresh-3 기록에 해당하는 후속 교정을 적용했다. 이전 전달 manifest는 당시 파일 바이트 증거로 보존하며 이후의 현재 질문을 대표한다고 주장하지 않는다. 분수 곱셈의 작은/큰 비교 두 문항은 유지했다.

중학교의 완료 전달은 885개 파일 바이트, Git 객체, 보존된 원문과 3,719개 현재 읽기 계약을 별도로 대조했다. 원문 예제에만 남은 분수 조사 오류 한 곳은 일반 문항 제안과 분리한 최소 교정 입력으로 처리한다. 원문의 수학 내용·답·ID·순서는 바꾸지 않는다. 이 한 곳을 위해 추가한 저장 계획 코드는 먼저 기존 코드의 바이트를 대조한 뒤 적용했고 관련 회귀 검사를 통과했다.

모든 이력은 읽기·내용 판단·독립 검토·실제 저장·배포를 구별한다. 실제 학생 실험이나 성취기준 전수 대조 완료를 주장하지 않는다.

전달 파일 안에는 당시 실행한 일회성 TypeScript 도구도 바이트 그대로 보존한다. 이 기록용 코드는 제품 모듈이 아니므로 프로젝트 TypeScript 입력에서 이 보고서 폴더만 제외했다. 실제 제품 코드, 통합 도구와 회귀 검사는 계속 공식 타입 검사의 대상이다. 최초 통합 검사에서 나온 오류는 모두 이 보존된 도구 파일에 한정되었다.
