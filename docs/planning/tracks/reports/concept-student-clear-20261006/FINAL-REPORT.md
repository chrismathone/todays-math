# 학생이 질문만 읽고 답할 수 있는 개념백지

현재 지원하는 초3·초4·초5·초6·중1·중2·중3의 기본·보강 개념 9,119개 ID를 전수 검토하고, 실제 질문·참고 답·확인할 의미·빈칸별 인정 답을 별도 평가 데이터에 반영했다. 개념명만 보고 설명을 추측하거나 교사가 숨은 상황을 보충해야 하는 물음은 교정하거나 해당 형식에서 제외했다. 단순 계산만 필요한 문항에 계산 이외의 설명을 억지로 요구하지 않는다. 번호·순서·학년·난이도는 보존했다.

일반 개념 설명 607개는 숫자가 주어진 평가 물음과 분리했다. 새 교재의 기초 원천 개념 99개에 대응하는 대본 137곳을 동기화하고, 69개 도입부의 원천 지문을 갱신했다. 기존 대화의 다른 내용과 최초 교정의 원문은 유지했다. 일반 설명을 읽는 복습과 교재, 새 평가 물음을 읽는 학생지·교사용 기준안이 동일한 원천 ID를 사용한다. 기존 동결 자료와 학생 기록은 당시 자료로 해석하며, 새 물음을 풀었다고 바꾸어 해석하지 않는다.

초6 분수 나눗셈의 `e6-2-1-1-xc11`, `xc12`의 작은·큰 비교는 유지했다. 질문 없이 「나누어지는 분수」를 떠올리게 하던 확인 물음은 상황과 수치를 명시했다. 초3의 똑같이 나누기는 넓이를 기준으로 설명하여 모양이 달라도 넓이가 같으면 같은 크기라는 점을 반영했다.

검토는 Codex의 실제 문항 읽기와 Claude의 답을 가린 검토·답과 원문을 공개한 검토를 구별하여 기록했다. 현재 내용에 대응하는 독립 코호트 138개는 입력·원응답·실제 모델 출처에 모두 결합되어 있다. Grok의 사용량 오류 이후 사용자가 승인한 Codex·Claude 검토 경로를 따랐다. 이 기록은 실제 학생의 학습 효과나 공식 성취기준 전수 검증을 입증하지 않는다.

전체 기본 Turbopack 프로덕션 빌드가 타입 검사·페이지 생성을 포함해 통과했다. [최종 실행 검사](design-evidence/final-release-checks-20261008.json)에 실제 결과와 로그 지문을 남겼다.

## 적용 데이터와 검증

- [최종 내용 적용 계획](application-plan-final-v2.json): 9,119개 질문표와 각 ID의 실제 검토 묶음.
- [일반 설명 변경](applied-definition-changes.json): 607개 변경의 이전·이후·이유.
- [실행 데이터 대조](design-evidence/final-runtime-proof-20261008.json): 최종 질문표 일치, 번호·순서·난이도 유지, 표기 결함 0. 별도의 OX 조사 4곳은 수식·답·판정을 보존한 3개 문장 교정으로 명시했다.
- [교재 동기화 기록](design-evidence/final-source-sync-20261008/output-manifest.json): 준비된 대본·교정 원장의 정확한 바이트를 적용 후 확인했다. 전체 7학년 materialize와 source-ledger 검사는 일치한다.
- [실제 인쇄 지면](design-evidence/final-print-20261008/report.json): 학년별 실제 B/C 학생지·교사용 기준안 28개 지면의 넘침·수식 오류·답안 노출 오류 0. Chromium 인쇄 검사 2개 통과.
- 통합 검사 52개 파일·777개 테스트 통과. 로더 변경 후 관련 5개 파일·105개 테스트와 브라우저 인쇄 2개를 다시 확인했다.
- [복습 답 비교](design-evidence/final-typed-worker-report-20261008.md): 관련 11개 파일·258개 테스트 통과. 수학적으로 같은 두 표기 쌍은 맞게 읽고, 다른 답·함정에 대한 72,278개 비교는 틀림으로 유지했다.
- [함정 적용 검증](design-evidence/final-trap-activation-20261008.json): 받은 함정 43개 모두 현재 내용 지문과 일치. 바뀐 7개 묶음의 30개 빈칸 검토도 실제 Claude 원응답과 대응한다.
- [학생 기록 읽기 전용 확인](design-evidence/final-memory-and-review-binding-20261008.json): 바뀐 일반 설명과 관계된 492개 묶음의 열린 평가·구형 평가 단계 충돌 0. 학생 기록을 쓰거나 초기화하지 않았다.

JSON 문항 자료는 화면 코드와 분리했다. 각 자료의 ESM 로더와 타입 선언은 타입 추론 부담을 줄이며, 실행 시 모든 실제 항목의 계약 검증과 전체 내용 지문 대조는 유지한다. 전체 빌드는 기존 공식 타입 검사와 같은 8GB 한도가 Next의 타입 검사 작업에도 전달되도록 구성했다. 타입 오류를 무시하는 설정은 사용하지 않는다.

선수 관계는 교육적 추론으로 표시한다. 단원 간 연결을 모든 소단원 간 연결로 늘리거나 학습 요소의 배열 순서를 선수 간선으로 바꾸지 않는다. 소단원 간 직접 선수 간선과 공식 성취기준 전수 대조가 포함되지 않은 데이터 상태를 유지한다.

최신 원격 main을 통합한 뒤 관련 검사와 푸시 관문을 실행한다. 실제 배포 상태는 해당 main 커밋의 GitHub Vercel 상태와 Vercel 배포 정보로 확인한다.
