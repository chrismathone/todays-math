계획 초안만 작성한다. 제공 순서의 모든 ID에 대해 JSON 배열로만 출력한다(코드펜스와 생략 금지).
각 행은 {id,bDecision,bPrompt,bAnswer,bRequiredIdeas,learningRole,bGoal,bReason,studentLabel?,cDecision,cAfter?,cReason,cSlotEquivalents?,coreAfter?,coreReason?,exclusionReason?,exampleNeeded?,answerNotes?}.
learningRole은 definition/procedure/reason/application/naming 중 해당 항목의 실제 주된 학습 역할을 판단해서 쓰라.
bRequiredIdeas는 [{anyOf:["독립적으로 필요한 의미의 표현1","같은 의미의 다른 유효한 표현2"]}] 꼴이다. 질문이 실제 요구한 핵심만 적는다. 예제의 결과를 묻지 않았으면 그 결과를 필수로 요구하지 말라. 올바른 답에서 어떤 기준을 빼도 여전히 질문에 답했다면 그 기준은 제거한다. 의미가 같은 쉬운 말과 올바른 다른 풀이를 허용하고 특정 문장 암기를 요구하지 말라. bAnswer는 요구 범위에 맞는 간결한 모범답으로 쓰며, 불필요한 전체 계산과 설명을 늘리지 말라.
C 슬롯의 유효한 다른 답이 있으면 cSlotEquivalents에 슬롯 순서의 대안 배열을 기록한다. 예 [[],["일만"]]. 원문의 C keep은 정확한 source studentC와 canonical answers를 고정하며 coreAfter의 문장으로 대체하지 않는다. 대안을 적을 때 동의어와 다른 수학 역할을 혼동하지 말라.
질문·답·requiredIdeas·C 문장·C 대안에 든 모든 숫자와 수학 기호는 원문과 같은 $...$ KaTeX 표기로 쓰라. 6×7=42는 $6\times7=42$로 쓰고 숫자만 있어도 $6$처럼 표시한다.
반복 장황한 서술을 줄여 compact JSON으로 출력한다. bGoal은 25자 내외, bReason/cReason은 각 항목의 구체 이유를 40자 내외로 쓰며 이유를 일반 pass 문구로 대신하지 않는다.
새 계약에서 일반 definition은 학습 설명(A/SRS)으로 남고, B bQuestion(prompt,answer,requiredIdeas)와 C clozeQuestion은 별도다. cAfter는 clozeQuestion을 위한 완성 문장(정답은 {답})이며 일반 설명을 자동으로 대체하지 않는다. coreAfter는 실제 수학 오류나 학년 언어가 불분명한 일반 설명을 고칠 때만 쓰고 coreReason으로 원문의 문제를 특정하라. 단순 계산 C를 만들었다고 일반 설명을 계산 하나로 바꾸지 말라.
bDecision은 rewrite 또는 exclude. cDecision은 keep, rewrite, exclude. bPrompt는 조건·대상·답할 범위가 명확한 완성 질문이다. 단순 제목+설명하시오 금지. 본문에 예상 답을 넣어 베끼게 하지 말라. 선분, 직각, 자연수 같은 보통 이름은 어떤 성질을 답할지 좁힌 정의 질문 가능. 설명 질문은 의미·이유·방법을 확인하도록 하되 억지 이유 질문은 금지. 구체 예제는 원문에 이미 있거나 새로 만든 간단한 수/상황으로 자립시켜야 하고 bAnswer는 그 예제의 실제 결과와 설명이어야 한다. 일반 개념을 단일 산수 답으로 대체하지 말라.
단순 기호·단위 읽기, 일반 설명 목표가 없는 반복 계산, 이미 다른 ID와 같은 목표인 목록은 B에서 제외 가능: 그때 bPrompt/bAnswer는 null, exclusionReason에 B만의 구체 이유를 적어라. C가 좋은 짧은 계산이면 B제외와 무관하게 유지한다. 자료는 물리적으로 지우지 않는다.
C는 실제 studentC만 보고 짧은 비교(큰/작은/같다), 선명한 계산, 익숙한 낱말 빈칸을 유지한다. 좋은 문장을 괜히 바꾸지 말라. 가려진 대상, 긴 키워드 구절, 어려운 말, 불명확한 답 범위만 고친다. rewrite일 때 cAfter는 완전한 새 C평가 문장 문자열로 정답 부분을 {답}으로 표시한다. 빈칸은 1~4개다. 수식 LaTex의 { }와 빈칸표시 { }를 혼동하지 말라. 학생 C에는 답 표시가 □가 된다. 원문의 목표·사실을 보존한다. 낯선 세모/문자 기호를 새로 만들지 말라. 두 문장 중 첫 문장에 정답을 그대로 제시하지 말라. 문장 복원을 요구하는 빈칸 대신 짧고 친숙한 답을 써라. 조건과 결론을 동시에 가리지 말라. 그림·구체 예제가 필요한 새로운 사례는 exampleNeeded에 어떤 그림/상황인지 적어라.
원문 예시는 숨겨져 있으므로 자동으로 보인다고 가정하지 말라. 답의 동의어와 다른 정답을 분리해서 필요한 경우 answerNotes에 실제 동의어와 오답 경계 설명을 넣어라. source 오류는 bReason/cReason에 명확하게 표시하고 수학적 사실을 보존하라. bGoal/bReason/cReason는 그 항목의 구체 내용으로 짧게 적어라. 모든 원문을 개별 읽고 일반적인 pass 문구로 채우지 말라.
사용자는 성인에게 통하는 '구한 몫에 나누는 분수를 곱하면 □가 되어야 한다'(답 나누어지는 분수)를 거절했다. 따라서 초3에서도 '구한 몫에 나누는 수를 곱해 □와 같은지 확인한다'는 숨은 수 이름 복원 대신 실제 계산식을 주거나 친숙한 대상부터 고쳐야 한다. 반면 '나누어지는 분수가 나누는 분수보다 {작으면} 몫은 1보다 작다'같은 단순 관계는 유지할 가치가 있다.
