# 초3·초4 학생용 개념백지 계획 초안

범위는 main `13bf05dce`에서 추출한 2,779개 ID다. e3 194개, e3plus 984개, e4 145개, e4plus 1,456개이며 소단원은 118개다. 원문의 ID와 순서를 보존하고 운영 코드·개념 데이터·학생 이력을 바꾸지 않는다.

`source-evidence.json`은 B의 실제 제목·정의, C의 실제 학생 문장, 원문 답, 원문 예제를 모두 보존한다. `audit.json`은 그 출처 지문값과 연결되는 항목별 B 질문·모범답·목표·이유, C 유지/수정/제외 제안을 기록한다. B의 `exclude`는 설명형에서 제외하자는 제안이며 C나 개념 자체의 삭제가 아니다. C의 `rewrite`에서 `cAfter`는 빈칸 정답을 `{답}`으로 표시한 완전한 새 **C 평가 문장**이며 A/SRS 일반 설명을 자동으로 바꾸지 않는다. `coreAfter`는 원래 학습 설명의 수학 오류 또는 학년 언어 문제를 고치는 별도 제안이며 `coreReason`을 함께 기록한다. LaTeX의 중괄호를 빈칸으로 간주해서는 안 된다.

## 설계 판단

학생에게 실제 보이는 질문만으로 대상·조건·답의 범위를 알 수 있어야 한다. B는 편집용 제목을 그대로 보여 주는 대신 질문과 모범답을 함께 관리한다. 모범답은 그 질문의 수·상황·범위에 맞춘다. 예를 들어 ‘곱셈으로 확인’ 질문이 구체식 `24÷6=4`를 제시했다면 모범답도 `6×4=24`라는 식과 확인 이유를 담아야 한다. 원래 일반 정의를 그대로 답으로 재사용하지 않는다.

조건과 답을 한 문장에 함께 제시하고 ‘설명하시오’를 붙이는 것은 피한다. 반면 선분·반지름·진분수 등 익숙한 이름은 끝점·이어지는 모양·분자와 분모처럼 확인할 성질을 좁힌 정의 질문으로 쓸 수 있다. 기호 읽기·단위 읽기·동일 계산의 반복은 C의 짧은 회상/계산 목표가 될 수 있지만 B에서 억지 일반 설명을 요구하지 않는다.

C의 분명한 비교(크다/작다/같다), 짧은 수·계산·낱말 빈칸은 유지한다. 제목이 숨겨진 상태에서 수 이름을 복원해야 하는 문장, 구체 수나 전체가 없는 조각·묶음 문장, 답이 긴 문구가 되는 문장은 필요한 경우에만 바꾼다. 문장을 읽으면 정답을 그대로 베낄 수 있는 중복 문장, ‘말’, ‘문장’ 등 출력 형식 자체를 외우는 문항은 해당 형식에서 제외할 수 있다.

## 검토의 한계와 구현 인계

원문은 전수 읽었으며 초안 작성에는 코디네이터가 허용한 격리 Claude CLI를 사용했다. 작성 보조의 출력과 개별 출처를 남기고 Codex가 학년별·소단원별 의미와 위험 사례를 검토한다. 이 작업을 리드의 최종 독립 Claude 검토나 실제 학생 실험으로 부르지 않는다. 형식 검사도 학습 효과 검증이 아니다.

그림이 필요한 항목은 `exampleNeeded`로 명시한다. 원문 예제는 원문 증거이며 학생 화면에 자동으로 보인다고 가정하지 않는다. 구현 전에 실제 지면에 그 조건·그림이 나타나는지, B 답 칸이 충분한지, C의 짧은 정답과 실제 동의어가 구분되는지 확인해야 한다. 특히 복합도형 붙이기·접기·그래프·분류 표는 그림 없이 모호한 질문을 출하하지 않는다.

현재 단계는 계획 초안이다. root/Claude의 계획 합의 후 공용 문항 계약, 생산 데이터 반영, 독립 검토, 인쇄 지면 및 운영 검증은 코디네이터가 맡는다.
