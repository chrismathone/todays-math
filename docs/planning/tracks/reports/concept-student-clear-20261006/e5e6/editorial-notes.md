# 초5·초6 학생용 개념백지 편집 기록

기준: main `13bf05dce`, 입력 `D:/tmp/concept-student-clear-20261006/e5e6.json`. 생산 코드·개념 데이터에는 적용하지 않는 계획 초안이다. 초5 기본 197개·확장 1,233개, 초6 기본 196개·확장 995개, 총 2,621개 ID를 입력 순서대로 보존한다.

## 직접 읽은 범위와 판단 방법

Codex는 입력 순서 0–2620의 모든 B 제목(`term`), 원문 정의(`definition`), 실제 C 학생 문장(`studentC`)을 직접 읽었다. 출력이 잘린 171–239, 636–639, 2090–2092, 2195–2203은 별도 다시 읽었다. 이 기록은 원문을 읽었다는 범위이며 최종 생산 문항이나 학생 실험을 검증했다는 뜻이 아니다. 각 원문은 `evidence/source.json`에 보존하고 전체 파일 SHA-256과 행별 SHA-256으로 제안과 연결한다.

112개 소단원별로 전체 원문을 전달한 도구 없는 Claude 호출은 전수 초안 작성을 보조한다. 처음에는 Opus를 사용했으며, 반복된 서버 과부하 529 뒤 코디네이터가 Sonnet의 계획 초안 보조를 허용하여 단일 가용성 확인 후 전환했다. 실제 모델·effort, 원문 입력·원시 응답·실행 시간·사용량·ID 목록은 각 `evidence/section-NNN-*`에 남긴다. 완료 응답은 보존하며 동시에 세 호출을 넘지 않는다. 편집 초안의 출처와 Codex의 직접 읽기·수정은 구분한다. 루트가 맡은 독립 검토나 최종 합의로 간주하지 않는다.

초기 보조 스크립트는 공급자 실패 뒤 다음 항목을 계속 시작하는 오류가 있었다. 해당 실패 입력과 기록은 `evidence/failed-author-attempt-before-reset/`에 보존했고, 개별 오류가 직접 429를 증명한 것과 코디네이터가 별도 확인한 429를 구분했다. 이후 공급자 오류가 한 번 발생하면 새 작업을 시작하지 않고 기존 호출만 정리한 뒤 중단하도록 고쳤다. 21:40 KST 이후 529 과부하와 한 번의 제한된 재시도도 같은 방식으로 중단했다. 이는 문항 검증 실패나 학생 실험 결과가 아니다.

`codex-proposal-reading.json`은 실제 제안 B 질문과 C 학생 문장을 직접 읽은 범위만 기록한다. 전수 원문 읽기, 제안 지면 읽기, 선택한 답·기준 검토, 코디네이터의 독립 최종 검토를 하나의 통과 표시로 합치지 않는다. `candidate-flags.json`은 다시 볼 위치를 찾는 보조 대장이며 그 항목 수가 검토 범위나 합격 수를 뜻하지 않는다.

## 제안의 기준

- B에는 질문과 모범답안을 별도로 둔다. 필요한 조건, 물어보는 대상, 답의 범위를 질문 안에 쓴다. 익숙한 정식 이름은 정의의 특정 부분을 물어도 되지만, 편집 제목은 학생이 알아야 할 개념명처럼 취급하지 않는다.
- 예시를 붙인 B는 일반 방법·관계를 묻고 그 예에서도 적용하게 한다. 모범답안은 일반 설명과 질문에서 실제로 쓴 예의 답을 함께 제공한다. 숫자 계산 하나만으로 원래의 일반 개념을 대체하지 않는다.
- C의 짧은 비교, 구체적인 식, 낱말 빈칸은 유지한다. 길고 임의적인 답 구절, 숨은 대상, 다음 문장에서 정답을 복사할 수 있는 문장은 다시 쓴다.
- 제외는 B 또는 C에 한정한 제안이다. ID를 삭제하거나 학생 이력을 지우지 않는다. 같은 목표를 반복하는 항목과 공부 방법에 불과한 항목은 이유를 적어 해당 형식에서 제외할 수 있다.
- 수학적 조건은 학생에게 보이는 문장 안에 있어야 한다. 양수·0으로 나눌 수 없음·같은 전체·단위·겹침 없음·직육면체라는 대상·어림값과 정확한 값의 차이를 숨은 제목으로 보충하지 않는다.

## 남아 있는 합의와 확인

확정된 생산 후보는 일반 학습 설명(`definition`)과 B(`bQuestion`), C(`clozeQuestion`)를 분리한다. `coreAfter`만 일반 설명의 실제 사실·학년 언어 교정이며, 새 계산 C를 일반 설명으로 이식하지 않는다. C keep에는 원래 표시 문장·실제 학생 문장·정답을 명시적으로 고정한다. B 필수 의미는 `{anyOf: string[]}[]`로 각각 독립적으로 기록하고, 대안을 하나의 ‘또는’ 문장으로 묶지 않는다. C의 슬롯 수와 정답 그룹 수를 맞추고 canonical key를 각 그룹에 포함한다.

B/C는 글·수식 전용 계약이다. 실제 도형이 꼭 있어야 길이·넓이·맞붙는 변을 판단할 수 있는 제안은 해당 형식에서 제외한다. 연구용 SVG나 그림 사양은 보존하지만 그림 없는 질문으로 적용하지 않는다. 일반 도형의 정의처럼 실제 개별 그림 없이도 뜻이 분명한 항목까지 일괄 제외하지 않는다.

제안 수·식·단위의 KaTeX 변환은 `markup-evidence.json`에 원문과 변환을 남기고 수학 내용의 되돌린 문자열이 같은지 확인한다. 별도의 `notation-corrections.json`은 실제 baseline 표기 자로 찾은 수식 뒤 조사 교정 기록이다. 보존 C 원문은 교정하지 않는다. 이 기계적 검사로는 개념의 사실성이나 학생 이해를 증명하지 않는다.

최종 audit의 모든 결정은 적용 후보이다. 루트/Claude 합의 후 공용 계약·도형 자료·B 모범답안의 채점 범위·C 정답과 오답 칩을 함께 검토해야 한다. 긴 새 B 질문은 인쇄 줄 수와 답 칸 크기가 달라지므로 실제 지면 확인이 필요하다. 이 작업에서는 생산 파일 변경, 설치, prisma 실행, 푸시 또는 배포를 하지 않는다.
