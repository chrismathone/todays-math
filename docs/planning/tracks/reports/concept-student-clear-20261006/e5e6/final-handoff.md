## 적용할 내용과 읽을 파일

[audit.json](audit.json)이 현재 제안의 기준이다. 원문 제목·일반 정의·실제 C·원래 답을 `source`에 보존하고, 문항의 학습 목표와 개별 수정/유지/제외 이유를 함께 기록했다. 조립된 `bQuestion`과 `clozeQuestion`을 사용하며, null이면 해당 형식 제외다. `partial-audit.json`은 같은 현재 행을 가진 호환 사본이다.

[final-representative-problems.md](final-representative-problems.md)는 초5와 초6에서 원문과 현재 B·C를 나란히 확인하는 자료다. 초5 반올림 범위와 약수·배수, 초6 몫 확인·같은 분모의 나눗셈·소수의 비·입체도형의 높이를 포함한다. 초기 `representative-problems.md`는 변경 이력으로만 보존했다.

일반 학습 설명은 `coreAfter`가 있을 때만 별도 교체를 제안한다. 구체적인 수를 넣은 평가용 C가 일반 설명을 덮어쓰면 안 된다. 유지 결정 C는 원문 문장과 기본 답을 고정했다. 소유자가 유지하도록 지정한 `e6-2-1-1-xc11`·`xc12`도 원문 그대로이며, 현재 원문의 답은 각각 ‘작으면’·‘크면’이다.

B는 학생에게 보이는 조건과 답변 범위를 적었다. 예컨대 ‘조각의 개수만 견주기’는 실제 두 분수와 공통 단위분수를 제시하고, 그 개수로 몫을 구할 수 있는 까닭을 묻는다. 몫 확인 C는 ‘나누어지는 분수’라는 긴 이름 복원을 실제 식에서 잘못된 몫을 곱셈으로 확인하는 빈칸으로 바꿨다. 짧고 쓸모 있는 비교와 용어·계산 빈칸은 개별적으로 유지했다.

마지막 독해에서는 질문에 없는 조건이나 다른 답을 같은 답으로 취급하는 사례도 고쳤다. `e6-2-4-2-xc12`는 곱할 수를 10·100·1000 중 고르도록 범위를 밝혀, 4도 가능한 질문에 100만 강제하던 문제를 없앴다. 비례배분의 10÷4가 소수로 나누어떨어지는 경우, 원주율과 3.14의 구분, 쌓기나무의 가려짐과 전체 개수, 원기둥을 세우는 방향 등도 실제 학생 문장·답·기준을 함께 맞췄다.

## 그림과 예시

[example-followups.json](example-followups.json)에 28개 표시를 모았다. 이미 질문에 넣은 수치 예, 일반 학습 설명에 권하는 그림, 그림 없이는 출제에서 제외하는 문항을 모두 포함하므로 ‘28개 그림 미제작’이라는 뜻은 아니다. 각 행의 B/C 결정과 이유를 함께 읽어야 한다.

현재 합의된 글·수식 형식에서 그림이 꼭 필요한 문항은 제외 상태를 유지한다. 최종 독해로 `e6-2-5-1-xc15`의 원 안팎 도형, `e6-2-5-3-xc18`의 바깥 정사각형·정육각형 넓이 비교, `e6-2-5-4-xc18`의 원 조각 배열도 같은 기준을 적용했다. 제안했던 구체 문장과 일반 학습 내용은 근거 파일에 남겼다. 두 SVG는 계획 근거이며, 그림 첨부 출제 기능을 구현했다는 뜻이 아니다.

## 독해 근거와 검증

[codex-final-editorial.json](codex-final-editorial.json)은 ID마다 실제 읽은 제안 fingerprint, 입력 파일, 개별 이유와 시각을 가진다. 현재 기록은 worker 명시 2,207개, Root Codex 263개, 초기 Codex 기록 151개다. 초기 151개는 `reader` 필드가 없는 옛 형식을 그대로 남겼으며, 이유·시각·실제 입력과 현재 fingerprint 일치를 확인했다. 수정 전 판단은 이력으로 보존하고 현재 문항에 소급 승인하지 않았다.

[final-review-summary.json](final-review-summary.json)과 [최종 근거 연결 검사](evidence/final-provenance-check-ctx-7fc6b4391c84.json)는 원문 행·순서·모든 원문 및 제안 fingerprint, 실제 독해 입력 파일과 그 안의 현재 payload 일치를 2,621개 모두 확인한다. 이 검사는 독해 판단을 새로 부여하거나 독립 승인을 생성하지 않는다.

원래 `e5e6.json`의 SHA-256은 `d1b80f375e0a48caa7a295ca09bb27712be69e8d0f0170bbd5320fc7425bd172`다. 저장된 `evidence/source.json`은 원본 끝에 LF 하나를 붙인 바이트이며, JSON 내용은 완전히 같다. 보관본 SHA-256은 `97ba2708ca0efe97056e25ace61f16de297a50778a5ba6ed15eaa63c8b9e1123`다. 두 파일의 해시 차이를 내용 차이로 숨기지 않고 명시했다.
