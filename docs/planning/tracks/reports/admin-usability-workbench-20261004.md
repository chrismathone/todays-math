# 작업실 사용성 구현과 검증

상태: 작업실 소유 11개 항목을 구현하고 로컬 검증했다. 교재·계정·SRS 통합 및 운영 반영 여부는 별도 통합 보고서에서 다룬다.

## 구현 추적

| 항목 | 구현과 근거 |
| --- | --- |
| A08 / B05 | `loadMainDashboard`가 반·차시를 먼저 전달하고 반별 진도를 최대 6개씩 읽는다. 각 조회의 실패를 분리하고 GET만 재시도한다. `MainScreen`이 메뉴 권한을 전달하며 teaching 단독 사용자는 tests/metrics/DailyReview 조회나 출제 버튼을 이용하지 않는다. 통계 미조회는 0으로 표시하지 않는다. |
| A09 | 상단 날짜, 출제 기본 시행일, 바구니·인쇄 날짜에 공통 `kstDateOf`를 사용한다. 연동 관계 날짜의 중복 오프셋 계산도 공통 함수로 교체했다. |
| W01 | 승인 PATCH 뒤 단건 GET으로 서버 계산 `eligible`와 사유를 읽는다. 성공 후 조회 실패는 승인 실패와 분리하고 GET 재시도만 제공한다. 목록의 필터·순서·선택한 행을 보존한다. 새 단건 API도 studio 권한과 공유 문제 조회 범위를 검사한다. |
| W02 / W03 | 반 변경 즉시 학생 선택과 목록을 지운다. 조회 로딩·빈 결과·오류·재시도를 구분하며, 학생 조회 준비 전 개별 출제를 막는다. 대상별 요청 세대와 수동 범위 키를 관리해 늦은 초기 학생·기본 범위 응답이 수동 선택을 덮지 않는다. |
| W07 | 공통 `fetchClasses`·`fetchStudents`가 모든 페이지를 읽고 응답을 검증한다. 출제 설정·메인·반 관리·바구니·온보딩이 공통 함수를 사용한다. 요청한 반이 누락되면 다른 첫 반으로 자동 교체하지 않는다. |
| W08 | 개념 쓰기의 성공 안내와 후속 조회 오류를 함께 유지한다. 응답을 확인하지 못한 쓰기는 확인 필요 상태로 알리고 GET만 재시도한다. 쓰기 중 중복 제출과 대상 전환을 차단한다. |
| W09 | 저장 문서 직접 링크를 복원하는 동안 저장을 막는다. 403·404·통신 실패를 구분하고 해당 자료 GET 재시도와 자료 목록 복귀를 제공한다. 실패한 자료 링크를 새 문서로 조용히 대체하지 않는다. |
| D01 | 전체 반 데이터에서 이름·학년·담당 검색과 학년·담당 필터, 전체 차시에서 코드·단원·차시 검색과 학년·영상 상태 필터를 제공한다. 필터 밖에 있는 현재 선택을 보존하고 안내한다. 반 API는 종료 연동 반을 이미 제외하므로 운영 범위는 ‘종료된 연동 반 제외’로 명시한다. 제공되지 않는 active 값을 만들어 상태 필터로 가장하지 않는다. |
| D03 | 테마 선택·키보드 탐색은 미리 보기이며 ‘전체 학생에게 적용’만 PUT한다. 실제 범위가 서비스 전체라는 안내를 표시한다. 실패·조회 재시도에도 선택을 보존하고 중복 적용을 막는다. |

## 검증 결과

- 구현 커밋: `d219ad715`, `4d95f078f`, `6cae54e8c`. 각 커밋의 ESLint·Prettier·affordance 검사를 통과했다.
- 13개 관련 회귀 파일의 고유 사례 163개가 통과했다. 최초 실행에서 162개가 통과하고 KST 전체 소스 스캔만 20초 제한을 초과했다. 해당 파일 4개 사례는 `--testTimeout 90000` 단독 재실행에서 모두 통과했다. 스캔은 약 25초였으며 제품 동작 실패로 분류하지 않는다.
- 회귀 범위: `BankView.filters`, `ConceptBlankView`, `ConceptView`, `JourneyThemePicker`, `unifiedBankRow`, `mainRowGrid`, `kstDate`, `classListPagination`, `mainDashboardPartial`, `GenerateSetup.races`, `GenerateSetup`, `TeachingMainScreen`, `Onboarding`.
- 전체 `tsc --noEmit --pretty false`를 Node 8GB 한도로 실행해 통과했다. 이 결과는 후속 교재·계정 통합 전 단계이며 통합 상태의 결과를 대신하지 않는다.
- 실제 제품 컴포넌트와 스타일을 사용하는 Vite 격리 화면을 agent-browser 0.38.2로 열고 화면·오류·가로 넘침을 확인했다. Playwright `workbench.spec.ts` 320·390·1440px 3개 흐름이 통과했다: 필터 후 선택 유지, 735개 차시에서 검색, 미리 보기와 키보드 탐색의 PUT 0회, 명시적 적용 1회, 페이지 오류 없음과 가로 넘침 없음.
- 브라우저 API는 합성 fixture로 처리했다. 실제 로그인·운영 DB·배포 반영까지 검증했다고 주장하지 않는다. 이미지와 결과는 ignored `.tmp-admin-ui` 및 `test-results/admin-accounts`에 있다.
- 추가 브라우저 통합 확인: `workbench.spec.ts` 총 5개 흐름이 통과했다. 위 3개에 더해 teaching 단독 권한의 메인을 320·1440px에서 검사했다. 진도 응답을 대기시켜 반 목록이 먼저 보이는지, 한 반만 실패시켜 다른 반이 남는지, 실패한 반만 GET 재시도하는지, tests/metrics 등 금지 API가 0회인지와 가로 넘침 없음을 확인했다.
- 교재 전체 검사에서 드러난 기존 실패 2건을 보완했다. 공통 뒤로가기 CSS의 pointer를 실제 `a`·`button` 선택자로 한정했고, SQL 문장 분할 검사는 고정된 교재 migration 개수 대신 사이에 있는 지점 제약 migration도 실제 순서로 적용해 DB 동등성을 비교한다. 두 파일 26개 사례가 통과했다.

## 통합 시 확인

다른 세 작업의 최신 코드와 main의 다른 팀 변경을 보존해 병합한 뒤 전체 타입·빌드 및 변경 간 경계 검증을 완료한다. 기존 운영 반영 대기 migration과 원본 시스템 전화번호 끝자리 전달은 이전 구현 보고서의 DB→코드 순서를 유지한다.
