# 도형 엔진 통합 패치 06 검증

최신 사용자 지시에 따라 `D:/math-figure-editor/docs/export/todays-math/patches/06-engine-all.patch`의 52파일 묶음을 현재 feature branch에 3방향 병합했다. 이미 반영된 모눈·escape는 중복 적용하지 않고 집·등대 등 실물 에셋 39종의 통일된 흑백 선화, v2/graph-1 assets 연결, 명시적 원근 직각 표시, 한 글자 단위 정자와 `render_json` 경로를 가져왔다. 전달 저장소는 읽기만 했다. 시험지 한글화 저장소도 이 작업에서 수정하지 않았다.

지정한 원본 확인 스크립트를 `--save` 없이 실제 호출한 결과는 다음과 같다. 호출 전후 스크립트·기대 파일의 해시가 같고, 별도 실행에서도 원시 stdout 바이트·SHA256 6쌍이 모두 같았다.

```text
같음 grid
같음 assets
같음 perspective
같음 units
같음 right-refused
같음 solid-object-refused
결과: 모두 같음
```

변경 전에는 grid만 같고 나머지 5종이 달랐다. 적용 후 및 null 입력 보강 후 모두 6종이 같았다. 이 결과는 지정 6개 입력의 출력 일치이며 모든 가능한 명세·지면의 동일성을 증명한 결과는 아니다. 확인 스크립트/기대 파일/패치/README 9파일 사본과 해시는 `.qa-artifacts/exam-resume-20261008/engine-upgrade-20261019/engine-all-sync-20261021-r1/`에 있다.

정제기 한 파일의 충돌은 `data-asset` slug 허용과 기존 data-grid의 양수·유한성·정사각형·1~60 정수 칸·배치 검사를 함께 보존해 해결했다. 앞선 `clear_angle_labels`, 유한성·퇴화·직각 기호 크기 검사, solid 검산과 M28/피타고라스 코드는 덮어쓰지 않았다. 원근 표시가 있어도 영 길이·공선·그려지지 않은 변은 계속 거절한다. `perspective:true`는 투영된 그림에 표시를 그리는 기능이며 수학적 직각·학생 학년 허용의 증거가 아니다.

독립 실행에서 `assets:null`이 누락된 assets처럼 처리되어 기본 그림을 성공 반환하는 반례가 나왔다. 원래 입력·출력과 실패 기대값을 보존했다. 명시적 null을 거절하도록 보강하고, 추가 unittest 9개가 모두 통과했다. 유효한 지정 6종 출력은 이 보강 후에도 바이트 동일하다. 카탈로그는 실제 생성기로 재생성해 새로 받는 `angles.perspective` 한 필드만 더했다. 이름만 목록에 수동 추가한 것이 아니다.

에셋 변경은 생성 엔진의 새 렌더 자산이며, 기존 초등 assetScene을 향후 다시 렌더하면 새 흑백 선화가 나온다. 이미 저장된 출제 문항·그림·학생 기록을 재작성하거나 DB를 일괄 갱신하지 않았다. 각 에셋의 파일 해시와 전달 프로젝트 소스는 내부 QA 원장에 연결했고 권리 상태는 UNKNOWN/별도 검토로 남겼다. 수학 도형으로 그릴 수 있는 캔·주사위·컵·그릇 등은 v2/graph-1의 그림 조각으로 계속 거절한다. 학년 강제 제외, 권리·유사성, 수학 독립 검산, 최종 내용 승인 관문은 자동 통과시키지 않는다.

독립 증거는 `figure-engine-all-audit-20261021-r1/`(정적), `figure-engine-all-runtime-audit-20261021-r1/`(원래 반례), `figure-engine-all-runtime-audit-20261021-r2/`(현재 재실행)다. 작업자 커밋 `9d05de714`·`40aca96b7`·`7391f2f8f`를 보존 통합하며, 139개를 문항 독립 풀이·학년·권리 검수로 세지 않는다.

자동 gridSnap, 불확실 지적 삭제 후 자동 통과, 마지막 대조 생략, 실패한 마지막 명세를 이전 통과처럼 저장하는 처리는 적용하지 않았다. src/의 에셋 편집·AI 명세 안내 연결과 모눈 실측 보조는 별도 후속 단계다. 06은 엔진 묶음이며 이 파일에서 UI 이관까지 끝났다고 보고하지 않는다. TypeScript/Vitest 추가 회귀는 RAM 사전 기준을 충족하지 않은 실행을 통과로 세지 않는다. 기존 v50 문항 집계, 최종/적재 가능 0·운영 DB 쓰기 0·배포 0은 유지한다. 전체 기출 쌍둥이/엔진 개선 목표는 미완료다.
