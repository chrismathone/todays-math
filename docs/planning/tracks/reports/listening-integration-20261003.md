# 영어듣기 실제 화면·저장 통합 기록

2026-10-03. 교사 A·학생 B·H1 선택에 맞춘 **직접 제작과 MP3/PCM16 WAV 업로드 기반 시범 기능**을 main에 통합했다. 교사 수업, 학생 학습, 3~5문항 연습평가가 인증된 API와 실제 PostgreSQL 저장소를 사용한다. 사용자의 운영 반영 승인으로 공유 DB 적용·검증을 완료했다.

## 실제 사용 경로

- 교사: 오늘의 영어 → 영어듣기 (`/#english-listening`). 자료 목록/만들기/과제와 결과에서 미완성 초안, 출처·사용 권리 확인, 음원 업로드, 대본·보기·정답·근거 구간 입력, 내용·음성·구간 검수, 발행, 반/학생 배정, 방송, 결과·수동 공개·중단·재응시를 처리한다.
- 학생: 학습 홈/하단 영어듣기 → `/learn/english-listening`. 소리 확인, 한 문제씩 풀이, 실제 음원 재생, 저장과 제출, 공개 후 복습을 제공한다. 교사 방송에서는 학생에게 음원 요소와 미디어 주소를 보내지 않는다.
- 발행본: 학생용/교사용 인쇄 링크. 학생용은 서버에서 대본·정답·해설을 제외하고, 교사용은 포함한다. 과거 배정과 발행 내용은 새 초안 수정으로 바뀌지 않는다.
- 서비스 최고관리자는 기본 시범 대상이다. 추가 교사는 `ENGLISH_LISTENING_TEACHER_IDS`로 지정한다. `ENGLISH_LISTENING_ENABLED=false` 또는 기존 메뉴 제한은 현재 세션에도 반영된다.

## 검증 증거

격리된 loopback PostgreSQL 18과 실제 Next 16.3.0, Auth.js 교사·학생 로그인을 사용했다. 테스트 데이터와 비밀 연결 문자열은 Git에서 제외한 `.qa-artifacts/listening-postgres/`에만 저장했다.

- **통합 회귀 24개 파일/260건 통과**, 이후 PostgreSQL RESTRICT 오류 대응 추가 후 명단 삭제 회귀 **6건 통과**. 여기에는 DB의 동시 응시 생성·개정 충돌·같은 요청 재전송, 발행/음원 불변성, 전출/비활성/권리 회수, 공개 이력, 평가 초안과 제출 스냅샷 검증이 포함된다.
- **`npm run build` 통과**: Prisma 생성, Next 프로덕션 번들, 전체 TypeScript, 155개 정적 페이지 생성 완료. 변경 파일 ESLint와 affordance 검사도 적용한다.
- 실제 UI: 교사 제작 → PCM16 WAV 업로드 → 검수/발행 → 반 배정 → 학생 로그인/재생 → 새로고침 후 답 복원 → 같은 음원의 모든 문항 답 확정 뒤 공개 → 제출. 데스크톱 1440px·학생 모바일 390px에서 가로 넘침과 브라우저 실행 오류 없이 통과했다.
- 실제 평가: 첫 답을 바꿔 저장하고 새로고침으로 복원, 제출 때 고정 답안 생성, 수동 공개 전 대본 부재, 공개 후 표시. 연결 중단 시 재생 중지와 서버 중단 기록, 교사 재응시 허용 뒤 새 응시를 확인했다.
- 교사 방송 시작·학생 참여·공통 방송 시각·교사 중단을 확인했다. 학생 화면에는 음원 요소가 없다.
- 실제 Next API에서 MP3를 디코딩해 별도 PCM 해시로 저장하고 `206 Range`를 재생 가능한 WAV로 반환했다. 미발행 음원 추측 요청과 배정 취소 후 다음 Range는 거절됐다.
- PDF: 학생/교사 각각 A4 1쪽을 내보내 텍스트 추출과 PNG 렌더를 확인했다. 학생용 대본 부재, 교사용 대본·정답 포함, 기본 3문항의 잘림/겹침 없음. 실물 출력은 `english-listening-student-teacher` 검수 항목에 **대기**로 남겼다.
- 최대 10분 MP3의 실제 디코딩/DB 저장·범위 전송/정리 검증은 [미디어 구현 기록](../../../../scripts/qa/english-listening/media-implementation.md), 영속 계층의 상세 결과는 [DB/API 기록](listening-runtime-20261003.md)에 있다.

브라우저 재현 스크립트는 [persistent E2E](../../../../e2e/english-listening/persistent/README.md)에 보관한다. 가짜 인증이나 메모리 저장소를 쓰지 않는다.

## 통합 중 수정한 문제

MP3 패키지의 Node worker 동적 import를 Next가 잘못 번들링하는 문제를 `serverExternalPackages`로 해결했다. Zod의 기존 배열 최소 길이가 남아 빈 근거 구간 초안을 거절하던 문제를 수정했다. 자료 선택이 초기 반 목록 요청을 취소하던 경합은 목록 로드 전 입력을 잠가 막았다. 새 API는 기존 오류 로그 처리기를 거친다. 학습 기록에 연결된 학생/반 삭제는 데이터를 지우지 않고 409 안내를 반환한다(PostgreSQL RESTRICT SQLSTATE 23001 포함).

## 운영 반영 승인과 DB 적용

적용 전 프로젝트의 현재 DB를 **읽기 전용 트랜잭션**으로 확인했다. 듣기 테이블은 0개였으며, 스크린샷의 계정은 승인된 최고관리자이고 메뉴 제한이 없다. 따라서 새 코드의 메뉴 대상에 해당하며 별도 계정 권한 변경은 필요 없다.

적용 대상은 `prisma/migrations/20261003120000_english_listening/migration.sql` 하나다. 듣기 전용 테이블 12개·제약·비공개 권한·불변성 트리거를 추가하며 기존 업무 데이터는 수정하지 않는다. 격리 DB의 rollback dry-run/실제 적용/사후 검사에서 12개 테이블, 제약 131개, 공개 역할 grant 0개를 확인했다.

사용자가 DB 적용·배포 질문에 **“어 진행해”**로 승인한 뒤, 프로젝트 `jyaguxwuaxgdnovtulna`의 명시적 세션 연결(port 5432)에 `LISTENING_DATABASE_URL`과 승인용 `ALLOW_SHARED_IMPORT=1`을 설정했다. `scripts/qa/english-listening/apply-migration.ts --dry-run` → `--apply` → 기본 사후 검사를 순서대로 통과했다. 운영 DB 결과는 **테이블 12개·제약 66개·발행 불변성 트리거·공개 역할 grant 0개**이며 계정·반·학생 수가 적용 전후 일치한다. 로컬 PostgreSQL 18의 제약 131개와 운영의 66개 차이는 PostgreSQL 버전별 NOT NULL 카탈로그 표현 차이다. 일반 `prisma migrate deploy`로 다른 미적용 migration을 실행하지 않았다.

배포 경로는 `main` push에 연결된 기존 Vercel Git 통합이며 운영 주소는 **`https://today.aywa.co.kr`**다. 최신 원격 `65720e207`을 병합해 다른 작업도 보존했다. 로컬 `.vercel/project.json`과 CLI 계정은 이전 팀을 가리키므로 이를 이용해 새 프로젝트를 만들거나 재연결하지 않는다. GitHub 커밋의 `Vercel` 상태와 운영 HTTP/화면을 확인한다. Supabase MCP advisor는 연결 계정 권한 부족으로 실행되지 않았으며, 실제 적용 검사에서 RLS·접근 권한·필수 제약·트리거를 직접 검증했다.

미완료 업로드 정리는 `scripts/qa/english-listening/cleanup-media.ts`의 기본 읽기 전용 검사 후 명시적 `--apply`로 제한된 건수만 처리한다. 정상 음원과 발행/답안 이력은 정리 대상이 아니다.
