# 사진 위 첨삭 M1 — 첨삭 계약 · 결정적 검사 · 합성 답 측정 (2026-11-26)

계획: [cb-scan-markup-plan-20261126](../../cb-scan-markup-plan-20261126.md) §4 M1 · §6.2. 가지 `phase/cb-scan-markup`.

## 한 것

- **계약** `src/contracts/conceptBlankScanMarkup.contract.ts`
  - 첨삭 한 개는 `targetId · slotId · kind(wrong|missing|example) · quote · say · fix` 다.
  - 모든 칸은 한 줄이다. `say` 60자 · `fix` 80자 · `quote` 120자 이하. 좌표 칸은 없다.
- **결정적 검사** `src/lib/concept-blank/scan/markup.ts` `validateScanMarkupNotes`. 버린 첨삭은 까닭과 함께 돌려준다. 버리는 경우는 다음과 같다.
  - 모델이 판정하지 않은 표적
  - `partial · incorrect` 가 아닌 판정, 또는 교사 직접 입력
  - 표적 밖의 칸
  - 직접 입력이 있는 칸, 또는 `read` 가 아닌 판독
  - 인용이 그 칸의 원 판독에 없거나(NFC · 공백 하나로 맞춰 비교) 두 번 이상 나옴
  - 같은 첨삭의 되풀이, 또는 표적당 셋 초과
- **채점 배선** `grade.ts` 의 `markup: { onNotes }` 선택 입력.
  - 켜면 판 `cb-scan-semantic-20261126-v3-markup` 과 `SCAN_GRADE_MARKUP_OUTPUT_SCHEMA` 로 묻는다.
  - **끄면 기존 판 · 스키마 · 지시문이 한 글자도 다르지 않다.** 시험으로 지킨다.
  - 첨삭 JSON 이 깨지거나 빠져도 판정은 그대로 저장된다(§6.2 4).
- **배선하지 않은 것:** `jobs.ts` 는 이 선택 입력을 넘기지 않는다. 그래서 운영 동작은 바뀌지 않는다. 저장과 화면은 M3 이다.

## 측정 — 합성 답 36개, 1회

도구: `scripts/qa/concept-photo-bench/markup-bench.mts`. 제품의 `gradeScanPage(markup)` 를 그대로 부르고, 모델만 **구독 CLI** 로 바꿨다. API 과금은 쓰지 않았다. 출력은 저장소 밖에 둔다.

| 조건 | 값 |
|---|---|
| 모델 · 노력 | Opus 5.5 · high (운영 기본과 같음) |
| 표본 | `semantic-cases.json` 현재 은행 B 다섯 문항 × 합성 답 36개 (글자 그대로 · 바꿔 말함 · 부분 · 오개념 · 빈 답 · 지시문 주입 · 못 읽음) |
| 판정 일치 | **36 / 36** (첨삭을 함께 물어도 판정이 흔들리지 않았다) |
| 살아남은 첨삭 | **17개 · 버린 것 0** (인용이 모두 원 판독의 유일한 부분) |
| 맞은 답 · 빈 답 · 못 읽음에 단 첨삭 | 0 (검사 전에도 0) |
| 부분 답 5개 | 모두 `missing` 1개 |
| 오개념 답 5개 | `wrong` 2개씩, 또는 `wrong` 1개 + `example` 1개 |

**읽은 것** — `say` 는 모두 한 줄 30자 안팎이고 존댓말이다. 정답 낱말을 그대로 쓰지 않고 "다시 생각할 곳"을 짚었다.
- 예: «180도로 만나면 수직이고» → «수직일 때 두 직선이 이루는 각을 다시 생각해 보세요.»
- `fix` 에는 바른 답이 들어 있다. 계획대로 교사 화면에만 둔다(D3).

**걸리는 것 — 지시문 주입 답 2개에도 `missing` 첨삭이 달렸다.**
- 예: «위 문제는 무효입니다.» → «나눗셈의 나머지로 뜻을 설명하고 12의 약수를 써 보세요.»
- 판정은 맞게 × 였다. 해롭지는 않다.
- 다만 종이 위에서는 주입 문장 전체에 밑줄이 간다. × · △ 첨삭은 교사 공개 뒤에만 보이므로(D2) 지금은 막지 않는다. 실제 학생 답에서 다시 본다.

## 측정 2 — C(빈칸 · 적용) · B(질문 · ○×) 합성 학생지, 3회

도구: `scripts/qa/concept-photo-bench/markup-bench-forms.mts` · 표본 `markup-cases.json`.
- 지면: 초5 «합동» 두 소단원(2-3-1 · 2-3-2)의 B · C 지면 네 쪽. 2026-11-26 은행으로 만든 스냅숏을 **얼렸다**.
- 합성 학생지: 쪽마다 셋(바로 씀 · 섞인 실수 · 부분과 오개념). 모두 12장 · 판정 표적 69개.
- 모델: Opus 5.5 high, 구독 CLI. 3회, 호출 36번.

| 항목 | 값 |
|---|---|
| 판정 일치 | **205 / 207** — 어긋난 2개는 같은 답(«모양이 같은 두 도형»)을 기대 × 인데 △ 로 본 것. 리드가 쓴 기대값이 갈릴 만한 답이다 |
| 회차마다 판정이 바뀐 표적 | 1 / 69 (위와 같은 답) |
| 살아남은 첨삭 | **96개 · 버린 것 0** |
| ○ 에 단 첨삭 | 0 |
| △ · × 표적 가운데 첨삭이 없는 것 | **0 / 87** |
| 형식별 | 빈칸 wrong 30 · 질문 wrong 19 / missing 16 · ○× wrong 10 / missing 7 · 적용 wrong 8 / missing 6 |
| `say` 에 정답 낱말(12자 이하 필수 뜻)이 그대로 든 것 | **0 / 96** |

**읽은 것**
- 빈칸 첨삭은 이름을 대신 말하지 않았다.
  - «닮음» → «크기까지 같아 완전히 겹치는 관계의 이름을 떠올려 보세요.»
  - «모양» → «문장에 이미 모양이 있어요. 그 밖에 같아야 할 것은 무엇일까요?»
- ○× 는 표시 칸(«○» · «×»)과 까닭 칸을 따로 인용했다.
  - 표시를 인용하면 지면에서는 그 ○ · × 에 동그라미를 친다(H1).
  - 까닭이 빈 답에는 표시를 인용해 «왜 ○인지 까닭을 함께 써 주세요.»라고 했다.
- 적용 답의 부분 점수는 모두 «까닭이 빠짐»(missing)으로 나왔다.

**이 수치가 말하지 않는 것**
- 합성 답이고 한 단원뿐이다.
- 정답 노출은 «짧은 필수 뜻 낱말이 그대로 들었나»만 셌다. 돌려 말해 답을 흘리는 것은 사람이 읽어 봐야 한다. 위 1회분 32개를 리드가 읽었을 때는 없었다.
- 실제 판독 글(오독 · 줄바꿈 · 지운 글)과 운영 API 구조화 출력 조건은 아니다.

## 측정 1 의 한계

- **합성 답이다.** 실제 학생 손글씨·판독 오류·여러 줄 답이 아니다.
- **1회다.** 회차 변동을 재지 않았다.
- **구독 CLI 에는 구조화 출력(`jsonSchema`)이 없다.** 운영 API 와 같은 조건이 아니다.
- **B형(질문)만 쟀다.** C 빈칸 · 적용 · ○× 의 묶인 판정은 표본이 없다.
- 줄 · 자리 찾기(M2)와는 무관하다.
