## ① 만든 것

### 1.1 🔴 세 상태를 담을 자리 — 스키마 · 마이그레이션

**스키마** (`prisma/schema.prisma`)

| 무엇 | 값 | 왜 |
|---|---|---|
| `enum GradingMode` | `marks` \| `answers` (`@@map("grading_mode")`) | `marks` 는 `selectedChoice`·`essayScore` 가 **전부 NULL** 인데, 기존 채점 규칙은 그 둘이 NULL 이면 «미답 → 오답 0점»으로 읽는다. 안 가르면 「오답 표시로 채점함」과 「전사했는데 다 비었다」가 같은 행이 된다 |
| `TestResult.gradingMode` | `GradingMode @default(answers)` | 기본값이 `answers` 라 **기존 `/submit` 의 뜻이 한 글자도 안 바뀐다**. 기존 행도 전부 `answers` 로 채워진다 |
| `TestResult.absent` | `Boolean @default(false)` | 결시 — **칸을 전부 ✕ 로 찍는 것과 다른 뜻**이다 |
| `TestResult.score` | `Float` → **`Float?`** | 결시를 `0` 으로 적으면 그 0이 평균·추이·리포트에 **진짜 0점처럼** 실린다(23 §4 ③) |
| `TestResult.predictedScore` | `Float` → **`Float?`** | 같은 까닭 — 결시에는 예상 점수가 없다 |

**「아직 안 봄」은 행이 없는 것**이라는 뜻을 모델 머리말에 박았다 —
> 시험지 대상 학생인데 `TestResult` 행이 없으면 **미채점**이다. 0점도, 만점도, 결시도 아니다.
> 그래서 집계는 «대상 학생 수»가 아니라 «행 수»를 분모로 삼아야 한다.

### 1.2 채점 입력 API — `GET`·`POST /api/tests/{id}/grade`

몸통은 `src/lib/testResults/gradeSheet.ts`, 순수 함수는 `gradeMarks.ts`·`scoreRollup.ts`.
**기존 `POST /api/tests/{id}/submit` 은 한 글자도 안 건드렸다.** 경로를 나눈 근거는 ②.

**GET** — 채점표. 대상 학생(`test.studentId` 가 있으면 그 한 명, 없으면 반 학생 전부 · `createdAt` 오름차순 =
`GET /api/students` 와 같은 차례) · 문항(번호는 `orderIndex` 차례를 1부터) · 학생마다 **최신 한 건**(`takenAt` 내림차순).
🔴 채점한 적 없는 학생은 **`latest: null`** — 계약이 「아직 안 봄」을 그렇게만 표현한다.

**POST** — 한 시험지의 **여러 학생을 한 번에**. 본문:

```jsonc
{ "entries": [
  { "studentId": "…", "absent": false, "wrongProblemIds": ["…", "…"] },
  { "studentId": "…", "absent": true,  "wrongProblemIds": [] }
] }
```

거절하는 자리(순서대로):

| 언제 | 코드 | 문구 |
|---|---|---|
| 대상이 아닌 학생이 섞임 | 422 | `이 시험지의 대상 학생이 아닙니다: <이름 · 이름>` |
| 🔴 **대상 학생이 빠짐** | 422 | `아직 채점하지 않은 학생이 있습니다: <이름 · 이름>` — **몇 명이 아니라 이름**(19 §5′) |
| 시험지에 없는 문항 번호 | 400 | `이 시험지에 출제되지 않은 문항이 포함되어 있습니다.` |
| 초안 시험지 | 422 | `초안 시험지는 채점할 수 없습니다. 먼저 확정하십시오.` |
| 남의 시험지 | 403/404 | `ownership.ts` → `ownerScope.ts` 한 곳 |

저장되는 것:

- `gradingMode = "marks"` · `score` = 맞은 문항의 **배점 합**(`maxPointsOf` 를 `gradeAnswers` 와 **나눠 쓴다** — 두 곳에 적으면 같은 시험지가 채점 방식에 따라 다른 점수를 낸다) · `predictedScore` 는 기존 v0 판독기 그대로.
- 🔴 `ProblemAnswer` 는 **전 문항** — `selectedChoice`·`essayScore` 는 NULL, `isCorrect` 는 표시한 것만 false.
- `AnalysisReport` 는 채점된 학생에게만.
- 🔴 **결시**: `score`·`predictedScore` 가 **NULL** · `AnalysisReport` **없음** · **`ProblemAnswer` 도 안 만든다**
  (전 문항 오답으로 남기면 난이도 분포가 «다 틀린 학생»으로 거짓말한다 — ⑥-2 에 적었다).
- 전부 **한 트랜잭션** — 한 학생에서 실패하면 아무것도 안 남는다(반쪽 채점이 남으면 「누가 남았나」가 거짓이 된다).
- 재채점(정정)은 **안 막는다** — 같은 `(testId, studentId)` 에 새 행, 최신은 `takenAt` 내림차순.

응답: `scores[]`(이름 · 결시 · 맞은 개수 / 전체 · 점수) + `gradedCount` · `absentCount`.

**`scoreRollup.ts`** — 🔴 **합산은 여기 한 곳에서만 한다.**
`rows.reduce((s,r) => s + (r.score ?? 0), 0) / rows.length` 는 한 줄이라 어디서든 다시 써지고,
그때마다 결시가 0점짜리 응시자가 된다. `rollupScores` 는 `absent` 뿐 아니라 **`score === null` 인 행도** 평균에서 뺀다.
잴 것이 없으면 평균은 `0` 이 아니라 **`null`**.

### 1.3 화면 — A안 `/tests/{id}/grade`

`src/components/test/GradeSheet.tsx` + `src/app/(main)/tests/[id]/grade/page.tsx`(제품 크롬 `AppChrome` 안).
`/dev/retry-wire` **A 탭**을 그대로 옮기고, 시안에 없던 **결시**만 줄 끝에 더했다(브리프 §1.3 이 요구).

- 표 한 장 · 행 = 학생 · 열 = 문항 번호. 칸 세 상태:
  **점선 빈 칸 = 아직 안 봄** / **○ = 맞음** / **✕ = 틀림**. 접근성 이름도 `{이름} {N}번 {상태}` 로 갈린다.
  🔴 **○ 는 「끝」을 누른 뒤에만** 뜬다 — 맞았다는 주장은 원장님이 하는 것이지 빈칸이 하는 게 아니다.
- 줄 끝 단추가 **누르기 전부터** `0개 끝` / `2개 끝` · 누른 뒤 `2개 ✓`.
- **결시** 단추(줄마다). 누르면 그 줄의 칸이 **잠기고** 오답 표시가 지워진다 — 칸을 전부 ✕ 로 찍는 것과 다른 뜻.
- 🔴 **일괄 단추 없음**(「전원 응시」·「전부 맞음」).
- 미채점이 남으면 저장이 잠기고 `아직 안 본 학생: 이름 · 이름` — **이름**을 댄다.
- 서버 거절 문구는 **그대로** 띄운다(빠진 학생 이름이 거기 있다).
- 저장 직후 **학생별 점수 목록**만(`채점 N명 · 결시 N명` + 이름 / `맞은 개수 / 전체` 또는 `결시`).
  🔴 단원별 정답률·난이도 분포는 **안 그린다** — 8문항 한 회차는 단원당 1~2문항이라 통계가 아니다(23 §4 ①).
- 진입점: 시험지 화면 `/tests/{id}` 하단에 **«채점» 링크 하나**. 🔴 **초안에는 안 보인다.**
  감추는 것으로 끝내지 않고 **서버도 같은 규칙**(초안이면 422) — 화면만 막으면 경로가 열린 채 남는다.
- 메인 «오늘의 확인테스트» 줄은 **한 글자도 안 건드렸다**(브리프 §2 · D-133).

## ② API 모양을 그렇게 정한 근거 — 왜 `/submit` 이 아니라 새 경로인가

브리프가 나에게 맡긴 결정이다. **새 경로 `POST /api/tests/{id}/grade`** 로 정했다.

| 축 | `POST …/submit`(그대로 둠) | `POST …/grade`(새로) |
|---|---|---|
| 받는 단위 | **학생 하나** | **시험지 하나 · 대상 학생 전원** |
| 받는 것 | 문항마다 `selectedChoice`/`essayScore`(**전량 전사**) | 학생마다 «틀린 문항 번호» + «결시» |
| 정오를 누가 정하나 | **서버가 계산**(정답 대조) | **원장님의 주장**(계산할 것이 없다) |
| 거절하는 까닭 | 「시험지의 **모든 문항**에 응답이 필요하다」 | 「시험지의 **모든 학생**이 실려야 한다」 — 빠진 **이름**을 돌려준다 |
| 응답 | `testResult` + `analysisReport` 하나 | 학생별 점수 목록 + 채점/결시 수 |
| 쓰는 쪽 | 예측 문제지(`/exam`) | 채점 화면 A안 |

**같은 경로의 다른 본문으로 안 한 까닭 셋**

1. **`min(1)` 의 뜻이 정반대다.** `/submit` 은 「응답이 최소 1건」이고 새 경로는 「학생이 최소 1명」이다.
   한 스키마에 담으면 그 한 줄이 두 뜻을 갖고, 어느 쪽 규칙을 고치든 다른 쪽이 조용히 흔들린다.
2. **거절 문구가 응답 계약이다.** 새 경로는 거절할 때 **이름 목록**을 실어 보내고 화면이 그걸 그대로 띄운다.
   판별 합집합(discriminated union)으로 묶으면 zod 오류가 두 갈래 모두를 늘어놓아, 화면이 어느 쪽 문구를
   띄울지 다시 골라야 한다 — 「이름을 댄다」가 그 자리에서 흐려진다.
3. **`/submit` 은 이미 예측 문제지가 쓰고 있다**(브리프 §1.2 «뜻을 바꾸지 마라»).
   `strictObject` 를 합집합으로 바꾸는 것만으로도 그 경로의 400 문구가 달라진다.

**본문을 문항 **번호**가 아니라 `problemId` 로 받는 까닭** — 화면이 보여 주는 「3번」은 `TestProblem.orderIndex`
차례일 뿐이라, 시험지를 검수하며 문항을 교체하면 같은 번호가 다른 문항을 가리킨다.
`problemId` 로 받으면 서버가 **이 시험지의 문항인지** 대조할 수 있고(위 400), `/submit` 과도 같은 열쇠다.
`ProblemAnswer.sequence` 는 서버가 `orderIndex` 에서 **스스로** 적는다 — 밖에서 채우면 지면 차례와 어긋날 수 있다.

**초안(`draft`)을 서버에서도 막은 것**은 브리프에 없던 판단이다. 브리프는 진입점을 확정·인쇄로 한정했는데,
화면만 감추면 경로는 열려 있어 「확정 전에 이미 본 시험」이 남는다. 되돌리기 쉬운 쪽(조건 한 줄)이라 넣었다 — ⑤-C.
