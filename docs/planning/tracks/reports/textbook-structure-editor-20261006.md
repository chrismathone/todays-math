# 교재 제작 — 구조 전용 편집 칸 1판 (2026-10-06)

어제의 단기 조치(구조에서 나오는 본문은 읽기 전용 — `textbook-edit-guards-20261005.md` §4)에 이어,
그 블록의 글을 실제로 고칠 수 있는 편집 칸을 열었다. 설계는 codex 와 두 차례 협의했고 구현은 codex 가 검토했다. 형태는 원장님이 정했다.
같이 찾은 결함 하나(새 초안 복사 · 가져오기의 구조 안 번호)도 고쳤다.

## 1. 무엇을 여는가

| 구조 | 1판 | 고치는 것 |
|---|---|---|
| 쓰기 활동 `writing`(질문 기록 등) | 연다 | 질문 문구, 질문마다 작성선(1~30) |
| 자동 단원 도입 `unitIntro`(`auto-unit-intro` 틀) | 연다 | 도입 제목 · 질문 · 설명 · 핵심 문구 · 학습 목표 · 학습 순서 · 출발점 질문 · 날짜 문구 |
| 판서 `board` | 연다 | 판서 제목 · 수식 · 주석 |
| 차례 · 찾아보기 `references` | 읽기 전용 | 쪽 번호는 조판이 채우고, 항목은 다른 구획을 가리킨다 |
| 유형 머리 `exampleGroup` | 읽기 전용 | 문항 번호와 묶여 있고, 자동 구성의 전략 글은 지면에 찍히지 않는다 |
| 원본 조각 `fragments` | 읽기 전용 | 글 · 그림 · 표가 함께 원본 지면을 이룬다 |
| 은행 설명 활동 `rows`(`explainActivity`) | 읽기 전용(이번에 잠금) | 본문을 읽지 않는다. 자유 백지 · 개념 지도는 본문을 읽으므로 그대로 고친다 |

**항목의 개수와 순서는 그대로다**(원장님 — 1판은 문구만). 추가 · 삭제는 지면 검수와 함께 다음 판에서 연다.

## 2. 지키는 것 (codex 합의)

- **본문(markdown)은 건드리지 않는다.** 구조만 바꾼다. 조판이 본문의 꼴(제목 한 줄)을 쪽 나눔에 쓰기 때문에,
  구조에서 본문을 다시 지으면 글을 고친 일이 붙여 넘김을 켜거나 끌 수 있다. 본문에 옛 글이 남아도 지면은 구조에서 나온다.
- **고친 칸 말고는 아무것도 바뀌지 않는다.** 편집은 «저장본의 구조에 지금 값들을 다시 얹는» 식이다(`editStructure`).
  열어 보기만 하거나 고쳤다가 되돌린 구조는 저장본과 같은 객체다. 지웠다 다시 적은 칸도 원래 자리로 돌아온다.
  저장본과 지금 구조의 **꼴이 다르면**(종류 · 항목 수 · 칸 밖의 내용) 저장본에서 다시 얹지 않고 지금 구조에 그 칸만 고친다 —
  다시 얹으면 지금 구조에만 있는 내용이 사라진다(codex 3차).
- **선택 칸**(핵심 문구 · 날짜 문구 · 주석 · 도입 제목): 비우면 칸을 지운다(빈 글을 저장하지 않는다). 없던 칸은 비워 두면 생기지 않는다.
  날짜 문구와 도입 제목은 비우면 기본 문구(«공부를 시작한 날» · «단원 도입»)가 찍힌다 — 칸에 그 기본을 흐리게 보인다.
- **출처 기록(`provenance`)은 지우지 않는다.** 원본의 출처 · 검수 이력이며 **지금 문구의 검수 증명이 아니다.**
  «교사가 고쳤다» 는 기록은 1판에 두지 않았다(교환 형식의 판 호환을 같이 정해야 한다).
- **지면 적합은 기존 측정이 본다.** 단원 도입의 왼쪽 · 오른쪽 · 한 면 적합과 넘침, 쓰기 활동의 넘침은 조판이 재고
  (`recoveryMeasurement.ts` · `paginate.ts`), 미리보기 칸이 그 경고 · 오류를 보인다. 발행은 서버가 다시 잰다. 글자 수 상한은 두지 않았다.
  핵심 문구를 비우면 왼쪽 면의 그 영역이 없어 두 면 배치가 한 면으로 바뀔 수 있다 — 실물 검수 항목에 올렸다.
- **서버에 편집기 전용 검증을 넣지 않았다.** 같은 저장 길을 가져오기 · 문항 담기 · 개념 연결이 쓴다. 편집 함수의 불변식은 시험으로 지킨다.
  판서 수식의 `$` · 줄바꿈은 화면의 단추, 구획 저장(`saveDraft` — 저장 후 이동도 이 길을 지난다), 개념을 구획에 잇는 저장(`attachConcept`)
  세 자리에서 같은 함수로 막는다(조판이 그 수식을 거절한다). 공용 계약(Zod)은 옛 데이터 조사 전이라 그대로 뒀다.

## 3. 형태 (원장님 2026-10-06)

- Wire: **«내용 수정» 을 눌러 그 자리에서 연다.** 평소에는 읽기 모양, 누르면 같은 자리가 입력 칸이 된다. 저장은 «이 구획 저장» 하나.
- 닫힌 모양: 주요 글 + 개수 한 줄. 단원 도입은 질문 · 설명 · 핵심 문구와 «학습 목표 N · 학습 순서 N · 출발점 N»,
  질문 기록은 «질문 N · 질문마다 작성선 M줄» 과 첫 질문.
- 연 모양: **칸 이름은 지면의 제목 그대로**, 두 묶음 — «여는 글»(도입 제목 · 질문 · 설명 · 핵심 문구) ·
  «배움의 길잡이»(이 단원의 학습 목표 N · 선택한 범위의 학습 순서 N · 나의 출발점 N · 날짜 문구).
- 고친 블록의 머리에 **« · 저장 전»**. 구획을 저장하면 사라진다. 저장본에 없는 블록도 저장 전으로 본다.
- 연 상태는 그 판본 · 구획의 것이다. 다른 구획에 다녀오면 다시 닫혀 있다.

원장님이 보신 시안은 단원 도입과 질문 기록이다. 같은 원칙으로 정한 것: 판서의 머리 «판서 · 제목», 요약 «수식»(주석이 있으면 «주석»),
칸 이름 «판서 제목 · 수식 · 주석»; 질문 기록의 칸 이름 «질문 N · 질문마다 작성선»; 제목 없는 쓰기 활동의 머리 «쓰기 활동»;
저장을 막는 사유 «판서 수식에는 $ 기호와 줄바꿈을 쓸 수 없습니다.» — 원장님 확인 대상이다.

## 4. 같이 고친 결함 — 새 초안 복사 · 가져오기의 구조 안 번호

복사와 가져오기는 문항 배치 번호를 새로 짓는데, 문제 블록의 번호만 바꾸고 구조 안의 번호는 옛것으로 뒀다 —
유형 묶음의 `exampleItemId` · `confirmItemIds`, 색인의 `targetItemId`, 원본 조각 · 꼬리말 · 머리말의 그림 자산 번호.
복사한 초안에서는 대표예제 · 확인문제의 역할 판정(`render/blocks/problem.ts`)이 빠지고 색인이 대상을 찾지 못한다.
어제 넣은 안내 «수정하려면 새 초안을 만드세요» 가 바로 이 길로 보낸다.

- 순수 함수 `remapSemanticRefs`(`src/lib/textbook/semanticRefs.ts`)를 복사(`server/books.ts`)와 가져오기(`server/imports.ts`)가 같이 쓴다.
  바꿀 것이 없으면 같은 객체를 돌려준다. `groupId` 는 묶음끼리 같은지만 보므로 바꾸지 않는다.
- `semanticFragmentAssetIds` 가 꼬리말 · 머리말의 그림도 센다.
- 시험은 PGlite 로 실제 서버 코드를 돌린다. 고치기 전에는 복사본의 번호가 옛것 그대로라 실패했다.
- **운영 DB 전수(읽기 전용, 2026-10-06)**: 원고가 있는 판본 2개 가운데 옛 번호를 품은 판본 **0개**
  (`scripts/qa/textbook/census-stale-structure-refs.ts`). 복구할 판본은 없다.
- 자산 수집을 넓힌 탓에 저장 · 내보내기의 참조 검사가 꼬리말 · 머리말의 그림까지 본다. 같은 전수로 센 결과
  운영 원고에 그런 그림은 **0개**다 — 이번 변경으로 새로 막히는 기존 판본은 없다.

## 5. 시험

- `src/__tests__/unit/textbookStructureFields.test.ts` — 편집 규칙. 자료는 실제 생성기(`writingActivity` · `appendUnitIntro`)가 낸 것을 계약으로 읽는다.
- `src/__tests__/components/TextbookStructureEditor.test.tsx` — 화면에서 고친 구조가 **실제 client 의 PUT 본문**에 실리는지,
  미리보기가 쓰는 실제 경로(`buildSectionPreview` → 렌더 모형 → 블록 HTML)에 나오는지. 무편집 저장은 손대지 않은 구획의 저장 요청과 글자를 맞춘다.
- `src/__tests__/unit/textbookStructureText.test.ts` — «본문을 읽는가» 판정. 은행 활동 셋의 갈림을 더했고, 자료를 계약으로 읽게 고쳤다.
- `src/__tests__/unit/textbookSemanticRefs.test.ts` · `lib/textbookDraft.test.ts` · `lib/textbookFrozenSources.test.ts` — 번호 치환.
  가져오기 시험은 자산 번호가 내용 해시가 **아닌** 패키지로 본다(같은 번호면 치환을 빼도 통과한다 — codex 3차가 짚었고, 빼 보니 실제로 통과했다).
- 뒤에 더한 가드(꼴 검사 · 저장 차단 두 자리 · 연 상태 비우기 · 자산 대응표)는 빼고 돌려 시험이 실패하는 것을 확인했다.
  연 상태 시험은 처음에 «완성 보기» 를 거쳐 옮겼는데, 그 길은 편집기가 화면에서 내려가 가드 없이도 통과했다 — 세부 화면의 목차로 옮기게 고쳤다.
- 화면에서 고친 값이 미리보기 칸의 측정 · 쪽 나눔까지 가는 것은 jsdom 에서 재지 못한다(실물 검수 항목).

## 6. 남긴 것

- **실물 출력 검수 셋** — `/dev/print-check` 의 `textbook-structure-edit-intro` · `textbook-structure-edit-writing-board` ·
  `textbook-draft-copy-structure-refs`(대기). 구조를 고친 판본은 지면이 바뀐다.
- 항목 추가 · 삭제 · 순서 바꾸기, 차례 · 색인 문구, 유형 묶음, 원본 조각, 구조 행의 편집.
- 유형 묶음은 구조 입력을 잠가도 블록의 위로/아래로 이동으로 구성이 깨질 수 있다(codex 1차) — 묶음 단위 이동은 따로 정한다.
- 이미 저장된 본문과 구조의 불일치 복구, 구조와 본문의 동기화(쪽 나눔 신호를 명시 정보로 옮기는 설계와 함께).
- 판서 수식의 계약 강화(옛 데이터 조사 뒤).
- 발행 전 확인이 구조 안의 옛 문항 번호를 알리는 검사(지금 운영 데이터에는 해당 판본이 없다).
