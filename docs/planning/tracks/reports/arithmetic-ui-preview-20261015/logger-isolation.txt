Development workspace preview: client logger isolation
2026-10-15

Cause and scope
The root ClientErrorLog installs once and retains the original fetch in
clientReporter State.send. The development preview replaces window.fetch later,
so timed log flushes bypass previewFetch. The leave handler also uses sendBeacon
directly. A fixture AI 503 caused POST /api/logs/client, whose handler records
events in the database. Browser audits aborted every real /api/** request before
delivery; no API write was performed during verification.

Change
Use the page's exact development-only gate: NODE_ENV === development and
location.pathname === /dev/workspace-alignment. Check at enqueue, timed flush
and leave flush. Fixture errors never enter the queue. Real-page events queued
before entering preview stay queued without polling or consuming the page quota.
Returning to a normal page permits the next report/leave to flush them normally.
The reporter remains installed; production and other development routes retain
existing behavior. No route, API, geometry or database files changed.
