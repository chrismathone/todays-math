# 작업실 진입 속도 개선 완료 보고

2026-10-19 · 작업 지시: [brief-workspace-entry-speed-codex.md](../brief-workspace-entry-speed-codex.md)

모델 용량 오류로 중단된 `phase/12-workspace-speed` 작업트리의 변경과 미추적 파일을 먼저 읽고 이어서 검증했다. 작업실의 첫 서버 렌더에서 문제은행 전체 투영 조회를 제거하고, 필요한 화면이 기존 인증 API로 메타데이터를 받는 변경을 마무리했다.

## 1. 최종 동작

- `WorkspacePage`는 계정 권한을 확인한 뒤 빈 초기 은행 데이터와 `deferBankMetadata`를 셸에 전달한다. `loadUnifiedBankBootstrap`을 호출하거나 기다리지 않는다. 사용자별 `key`와 초안 저장 범위는 유지한다.
- 홈의 시험지 만들기 카드가 실제로 표시되고 초기 탐색 복원이 끝났을 때 기존 `GET /api/studio/problems?identity=question&view=bootstrap`을 호출한다. 문제은행 권한이 없거나 다른 메뉴로 직접 들어오면 홈 카드용 조회를 시작하지 않는다. 화면을 벗어나면 요청을 취소한다.
- 시험지 만들기는 출제 범위가 필요할 때 같은 메타데이터 전용 API를 사용한다. 기존 출제 가능 수 조회와 단원 조회는 병렬로 실행한다. 미리 제공된 단원이 있는 개발·시안 화면은 계속 그 값을 사용한다.
- 기존 목록 API에 `view=bootstrap` 분기를 추가했다. `identity=question&view=bootstrap` 두 조건만 허용하며 검색·최근 출제 제외 등 다른 조건을 섞으면 400으로 거절한다. 문항 본문과 후보 페이지는 읽지 않고 기존 bootstrap과 같은 총수·학년·대단원·단원·단원별 수·문항 식별 메타데이터를 반환한다.
- 클라이언트는 새 `unifiedBankBootstrapSchema`로 응답을 검증한다. 잘못된 응답이나 API 실패는 기존 문제은행 연결 오류 상태로 처리한다.
- 단원 ID가 없는 예전 저장 문항은 메타데이터로 학년·단원 이름을 매핑한 뒤 구성 수를 한 번 복원하며 이후 교사의 구성 수 수정은 보존한다. 출력·저장 검증 함수도 필요한 단원을 직접 조회한 뒤 현재 단원·출처를 비교한다. 별도의 새 source로 검증하는 저장 경로도 지원한다. 로컬 추출 문항은 기존처럼 은행 검증 없이 출력할 수 있다.
- 관리자 권한을 겸한 검수자는 기존 프록시와 같은 관리자 예외로 API를 사용할 수 있다. 일반 검수자 차단과 POST의 같은 출처 검사는 유지한다.

주요 파일: `src/components/unified/WorkspacePage.tsx`, `UnifiedWorkspace.tsx`, `WorkroomHome.tsx`, `src/components/exam-builder/ExamBuilder.tsx`, `mathSource.ts`, `src/lib/unifiedPreview.ts`, `src/lib/studio-ai/guard.ts`, `src/contracts/unifiedBankBootstrap.contract.ts`.

## 2. 캐시와 계정·지점 경계

`problemVisibleWhere()`는 공용 풀만 고르고, `problemEligibleWhere()`는 승인·출제 허용·정답 보유 조건만 더한다. 이번 bootstrap의 조회 조건에는 사용자·지점·최근 출제 이력이 들어가지 않는다. 따라서 **이 공용 메타데이터는 계정·지점 간 공유가 가능하다.**

기존 `loadQuestionBankSummary()`의 `cachedBankRead()`를 그대로 재사용한다. 캐시 키에는 조회 조건·학년·학기·검수 조회 여부와 `BANK_COUNTS_EPOCH`가 들어가며, TTL은 조회 완료 후 15초다. 진행 중인 동일 조회도 합친다. 기존 import 무효화·실패 제거 동작은 유지한다.

인증·권한 결과와 최근 출제 제외 결과를 이번 공유 메타데이터에 넣지 않는다. API는 매번 기존 인증·권한 검사를 거치고 `Cache-Control: no-store`를 반환한다. 개발 API는 기존 development 전용 관문을 유지한다. `recent` 등 계정에 따라 달라지는 조건은 bootstrap 분기에서 거절된다.

## 3. 로딩 상태와 디자인 범위

`DESIGN.md`, 메뉴 구현표, 설치된 Next.js 문서와 React 검토 기준을 읽었다. 기존 `WorkProgress`와 이미 사용 중인 문구를 재사용했다.

- 홈 카드: `시험지 만들기를 여는 중입니다…`.
- 시험지 범위: 기존 `출제 범위를 불러오는 중입니다…`.
- 실패: 기존 `문제은행 연결을 확인해 주세요. 문제 추출은 바로 사용할 수 있습니다.`.

조회 전 총수를 0으로 표시하지 않고, 응답 뒤 실제 수와 학년 버튼을 표시한다. 검색·다른 메뉴 행동은 계속 사용할 수 있다. 새 CSS·문구·상태 컴포넌트는 추가하지 않았다. 새 표시가 필요한 미해결 사항은 없다.

이번 확인 범위는 컴포넌트의 로딩·성공·실패·권한·이탈 상태와 서버/API 동작이다. 실제 브라우저의 전체 폭별 시각 재검증과 인쇄 실물 검수는 수행하지 않았다. 지면·스타일 변경은 없다.

핵심 시험은 `WorkspaceEntry`, `WorkspaceBankMetadata`, `UnifiedWorkspace.loading`, `mathExamBuilderSource`, `unifiedBankFilters`, `studioWorkspace`, `bankReadCache`다. 다음을 잠근다.

- 은행 bootstrap이 끝나지 않거나 실패해도 첫 셸 렌더가 이를 호출·대기하지 않는다.
- 사용자별 초안 범위와 익명·검수자·메뉴 권한 동작을 유지한다.
- 초기 메뉴 복원 중 홈용 메타데이터를 미리 요청하지 않는다.

- 출력·저장 검증이 필요한 단원 메타데이터를 기다린 뒤 저장 문항의 단원 변경을 검사한다. 화면에서 앞서 범위를 읽었는지에 의존하지 않는다.
- 은행 조회가 실패해도 로컬 추출 문항만 있는 저장본은 원래 내용으로 출력한다.
- 실패·잘못된 응답·이탈 취소를 기존 상태 안에서 처리한다.
- 동시·반복 조회의 공용 캐시 적중, 불필요한 후보 페이지 생략, 인증 재확인과 비공용 조건 거절을 확인한다.
- 관리자 겸 검수자의 조회는 허용하며 일반 검수자와 다른 출처의 POST는 계속 거절한다.

관련 기존 시험은 작업실 접근·행동·담기·순서·계정·초안, 문제은행 구성·필터·출처·진행, 성적표·SRS 진입, 은행 재고·출처·행·문항 투영·readiness API를 포함한다. 공통 구성기와 인증 가드의 수정에 맞춰 실제 문항 형식 UI, 서버 AI 경로 대역, 양식·출제 조건·사용 기록 API 시험도 포함했다. Vitest 게이트에서 예상 파일 수와 실행 결과 수가 모두 31파일로 일치했으며 385개 전부 통과했다.

Orca의 독립 Codex 검토에서 공용 캐시·계약·읽기 전용 측정 보호를 확인하고 저장본 구성표·출력 검사·관리자 겸 검수자 회귀 3건을 찾았다. 신규 시험에서 수정 전 4개 실패를 재현했다. 재검토에서 별도 저장 검증과 로컬 추출 출력 경로도 확인해, 단원 조회를 검증 함수 안에서 지원하고 로컬 문항에 은행 조회를 요구하지 않도록 보완했다. 해당 세 파일의 시험은 최종 57개 전부 통과했다. 마지막 독립 검토에서도 두 후속 지적의 해결을 확인했으며, 지정된 수정 범위에서 새 구체적 결함을 찾지 못했다.

시험 중 기존 오류 기록 대역의 `create` 누락 로그와 변경하지 않은 문제 변형 패널의 `<p>` 안 `<div>` 경고가 출력됐다. 해당 시험은 모두 통과했으며 이번 속도 변경의 수정 범위에는 포함하지 않았다.
