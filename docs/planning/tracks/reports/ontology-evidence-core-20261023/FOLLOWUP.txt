Root cause and change
The old prompt correctly allowed context explanations for withheld candidates,
but also instructed any next-check request with an unavailable candidate to select
insufficient. That blanket condition conflicted with the explanation policy and
matched the three actual generic-only failures below. The new prompt checks scope
first, then separates proposal eligibility from current-state explanation availability.
For an in-scope next-check request, existing relevant availability/source/plan facts
can explain withholding through context with candidateIds=[] and every required
citation. It explicitly forbids guessing or substituting another withholding cause.
Unsupported dates/sections and diagnosis/mastery/automatic assignment demands still
select insufficient with the existing scope limitation; actual proposals still require
eligible candidates. No product edits follow the immutable prompt commit.
