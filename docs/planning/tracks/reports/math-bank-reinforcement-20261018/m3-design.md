## 검증의 계약과 재현

[m3-independent.ts](m3-independent.ts)의 입력은 key와 표시된 content뿐이다.
MidProblem, 생성기의 facts·정답·산술 도우미를 입력으로 받지 않는다.
독립 풀이로 기대 정답을 만든 뒤 테스트에서 생성기 정답과 대조한다.
네 수치 단답 유형 F01/F03/Q03/S02만 정확한 수치 오답 넷을 제공하며,
나머지 여덟 유형은 본래 판단형 5지선다다. 임의의 텍스트 오답 파생이나 서술형 파생은 없다.

100씨앗은 0~99이며 세 variant를 모두 검사한다. 별도로 RNG 하한 0, 상한
`1-Number.EPSILON`, 두 방향의 하한/상한 교대 스트림을 쓴다.
F01의 대입값 0, F03의 일차항 소거와 1 계수, Q03의 나머지 0·4,
S02의 양의 최소 표준편차를 포함한다. 실제 source RNG는 바꾸지 않았다.

최종 36개는 실제 `parseProblemContent(content).question`에서 보기를 완전히 제거하고
공백을 정리한 뒤에도 모두 다르다. figureSpec은 모두 null이다.
보기 순서나 seed 표식만 바꾸어 개수를 채우지 않았다.
숫자·식 보기의 동치/중복을 독립 평가·계수로 확인했고 파생 객관식도 실제 파서로
다섯 보기 및 정답 위치의 수치 일치를 확인했다.

기본 8유형·응용 4유형이다. 개념·오류 판단을 연산으로 내리지 않았고 기존 resolveMiddleTier도 그대로다.
기존 loader가 기본을 problemType=계산으로 추정하는 역사적 필드는 후보 JSON에 현행 계약대로
보관했지만 이것을 난이도가 연산이라는 뜻으로 사용하지 않는다.

C의 오류 정정·모델 풀이와 부적합 해 제외·자료변화 근거 서술형을 복사하지 않았다.
F01은 틀린 인수분해를 고치는 대신 한 점 검산의 사각지점을 찾고, Q01~Q03은 모델 선택·불가능성·
정수 나머지 복원이다. S01/S03도 자료를 별도로 저작한 객관 판단이며 C의 끝맺음 변경본이 아니다.

m3-vitest.config.mts는 envDir:false, node 환경, 빈 setup을 사용한다.
기본 vitest.config의 loadEnv와 vitest.setup을 불러오지 않는다. 테스트 중 fetch는 실패하도록 막았다.
DB·인증·AI 클라이언트·적재기를 import하지 않는다. 의존성은 허용된 node_modules 심볼릭 링크만 사용했다.
코드 작성 전에 로컬 Next의 `node_modules/next/dist/docs/01-app/02-guides/testing/vitest.md`를 읽었다.

```sh
node_modules/.bin/vitest run --config docs/planning/tracks/reports/math-bank-reinforcement-20261018/m3-vitest.config.mts
node_modules/.bin/tsc --noEmit --project docs/planning/tracks/reports/math-bank-reinforcement-20261018/m3-tsconfig.json
```

테스트는 [후보 본문·독립 풀이·렌더 digest](m3-candidates.json),
[계획용 selector](m3-selectors.json), [B 제안 목록](m3-proposed-manifest.json),
[기계 검증 결과](m3-verification.json)를 결정적으로 다시 쓴다.
제안 목록의 SHA는 B 슬라이스를 식별할 뿐 최종 통합 배치 승인 SHA가 아니다.
