## 2. 우선 관리할 회귀 위험

### 높음 — S2의 초기화가 누적 선택까지 번지는 경우

S2 시안은 `grade/chapter/stage/query/page`와 `selection`을 별도로 둔다(`StepOneVariants.tsx:62`, `:137`, `:152`). 학년을 고르면 단원·검색·페이지를, 단원을 고르면 검색·페이지를 초기화하지만, 이미 담은 다른 학년의 차시와 입력 수는 유지한다. ‘변경’은 앞 목록을 다시 여는 행동이며 그 자체로 담은 범위를 지우지 않는다.

제품의 `chooseScopes`는 넘어온 ID에 없는 행을 제거한다(`ExamBuilder.tsx:608`). S2에서 현재 단원의 선택만 보내면 이전 학년의 배분·고정값이 사라진다. 학년/단원/출처를 `ExamBuilder` 전체의 React key로 사용해 재마운트하는 방식도 조건·이력·출력 상태를 함께 잃을 위험이 있다. 탐색 상태만 초기화해야 한다.

`ExamScope.detail`은 선택값이다. 모든 출처에 단원 단계가 있다고 가정하면 상세 묶음이 없는 기존 출처가 차시 선택까지 진행하지 못할 수 있다. `initialGroup` 지정 진입과 저장 조건 적용 후 탐색 경로도 빈 첫 진입과 구분해 검증해야 한다.

### 높음 — 미확인 재고를 0 또는 선택 가능으로 오인하는 경우

`canSelectScope`는 수학에서 `undefined`를 선택 불가로, 양의 안전한 정수만 선택 가능으로 판정한다. `0`은 확인된 빈 재고이고 `undefined`는 미확인이다. 현재 학년 목록도 두 상태의 안내를 구분한다(`ScopePicker.tsx:50`). 이 규칙은 S2 학년·단원·차시의 개별 선택 및 전체 선택에 일관돼야 한다.

`mathSource.ts:268`은 문항류 중복 허용 여부에 따라 문항 수와 갈래 수를 구분하고, 갈래 집계가 없으면 행 수로 대체하지 않는다. S2 시안의 `available: 40~48`, 기본 행 수 1, `scope-${orderIndex}` ID는 모두 제품 데이터가 아니다. 실제 ID·원본 순서·개별 재고·제품의 새 행 기본 배분 계산을 유지해야 한다. 시안의 초기 총수 40도 제품의 `total: null` 기본값을 바꿀 근거가 아니다.

### 높음 — 늦게 오는 단원과 저장 조건 복원을 S2가 덮어쓰는 경우

`ExamBuilder.tsx:125`의 복원은 `source.info(item).scopeId`에 의존한다. 구 저장본은 `mathSource.ts:79`, `:100`의 단원 메타데이터 매핑이 준비된 뒤 ID를 알 수 있으며, `ExamBuilder.tsx:140`은 이를 한 번 다시 복원하는 경로다. 초기 목록이 없거나 늦게 채워진 상태에서 S2가 빈 선택을 부모에 통보하면 저장본의 범위를 잃을 수 있다.

저장 조건은 출처/최근 출제 조건이 맞는 재고가 온 뒤 적용하고, 없는 차시는 제외·부족한 차시는 해당 재고까지 줄여 이유를 알린다(`ExamBuilder.tsx:360`, `:387`). S2 경로도 그 **실제로 적용된 행**과 맞아야 한다. 이후 재고 갱신 때마다 이미 손으로 수정한 배분을 저장본 값으로 덮어쓰면 안 된다. 저장 조건 v1은 형식·객관식 우선 순서를 저장하지 않으므로 적용 시 현재 값을 유지한다(`:456`).

### 높음 — 다섯 막힘 안내가 실제 출력 조건과 달라지는 경우

현재 버튼/실행 경로는 `disabled || busy`, 0문항, `canOutput`, `intentWarning`을 조합한다(`ExamBuilder.tsx:318`, `:725`, `:885`, `:983`). H2 안내는 이 상태를 읽어 **왼쪽 순서표 바로 아래**에서 이유와 다음 행동을 보여야 한다. 총수와 형식 불일치를 단순히 `!canOutput`으로 합치면 권한 안내가 잘못 나온다. 작업 중과 목록 재조회도 구분해야 한다. 목록 불러오기 자체를 새로운 출력 권한으로 삼지 않는다.

시안 `SimpleHifi.tsx:827`, `:1036`은 안내·이전/다음 행동을 같은 영역에 두고, 막힌 다음 버튼을 `aria-describedby`로 이유와 연결한다. 제품의 상단 3단계 이동에도 같은 차단이 적용돼야 한다. 0문항·권한 없음·불일치가 겹치는 경우도 거짓 안내가 나오지 않도록 별도 사례가 필요하다. 서버 원본 변경·검증 실패 안내와 기존 문항 보존은 다섯 안내를 추가해도 유지한다.

권한은 `accountAccess.contract.ts:77`의 `canOutputFrom` 그대로다. 수학 제작기에는 `UnifiedWorkspace.tsx:1899`가 `canOutputFrom(allowedMenus, "bank")`를 전달한다. **`bank` 권한이 있으면 별도 `export`를 요구하지 않으며, `export`만 있다고 출력이 허용되지도 않는다.** 안내를 붙이면서 과거 export 관문을 되살리지 않아야 한다.

### 높음 — H2 순서표/페이지와 실제 문항 순서의 불일치

H2 시안은 왼쪽 순서표와 오른쪽 목록이 같은 6문항 페이지를 사용한다(`SimpleHifi.tsx:753`, `:953`, `:1066`). 제품은 현재 전체 배열을 연속 범위별로 묶어 표시하며, `useQuestionReorder`는 `reviewRef` 아래 `[data-exam-question]`의 위치를 배열 인덱스로 다룬다. 왼쪽 표에도 같은 속성을 붙이거나 2페이지의 화면 인덱스 0을 전체 배열 인덱스 0으로 보내면 잘못된 문항이 이동·삭제·교체될 수 있다.

한 문항 배열에서 번호·통계·표·본문을 파생해야 한다. 추가/삭제/교체/형식 변경/되돌리기마다 모두 갱신하고, 마지막 페이지가 비면 유효 페이지로 보정한다. 범위 수는 담은 문항의 서로 다른 범위 수이며, 배분 행 수나 A→B→A의 연속 그룹 수가 아니다. `source.info`의 형식·난이도를 사용하고 `summarize`의 표시 문자열을 파싱하지 않는다. 수학의 ‘미분류’ 형식을 단답형으로 간주해서도 안 된다.

시안은 HTML drag/Alt+방향키, 제품은 포인터 및 Space/Enter·방향키·Home/End·Escape를 지원한다. 모양을 옮기면서 기존 키보드 이동·취소·되돌리기 경로를 없애지 않아야 한다. 안내 문구도 실제 지원하는 조작과 일치시킨다.

### 중간 — 간단한 출처 줄이 필터·조회 최적화를 잃는 경우

‘전체 / 교과서만’은 표현 변경이다. 기존 선택의 `sourceGroup/books/materialKinds/materials`와 문항류 규칙은 가용 수·후보·구성에 같은 조건을 전달한다(`MathExamBuilder.tsx:178`, `mathSource.ts:210`, `:294`, `:339`). 책/자료 조건 해제나 저장 조건 적용 뒤 화면과 실제 요청이 다르면 잘못된 시험지가 생긴다. 저장된 세부 출처가 두 선택지로 충분히 표현되지 않는 경우에도 조건을 조용히 바꾸지 않아야 한다.

현재 전체 출처 수는 출처 창이 열릴 때, 자료는 창이 열리고 책이 있을 때 조회한다. `source`는 학년·단원·검색이 아니라 실제 출처 조건과 문항류 규칙에 따라 메모화돼 있다. S2에서 매 단계 이동마다 `source`를 새로 만들면 범위 재조회·기존 작업 abort가 늘어난다. 보유량 표시를 없애는 일과 필요한 재고 조회를 없애는 일도 구분해야 한다.

`mathSource.ts:219`의 가용 재고 캐시는 컴포넌트 내부, 조건별, 응답 후 15초이며 문항류 규칙 변경 간 진행 중 조회를 공유한다. 기존 소비자의 abort가 새 소비자의 공유 조회를 중단시키지 않는 경계, 실패 후 재시도를 보존한다. 교체 창도 기존 `ReplaceDialog`와 빠른 후보 조회를 재사용하고 시안의 후보 생성으로 대체하지 않는다.

### 중간 — 공통 CSS·출력·다른 과목으로 영향이 번지는 경우

직접 제품 사용자는 수학 `MathExamBuilder`와 영어 `EnglishExamBuilder`다. 관찰한 연산대장은 `ArithmeticWorkbench`의 별도 흐름이며 공통 `ExamBuilder` 직접 사용은 찾지 못했다. 따라서 연산 제작기를 이번 S2에 맞춰 변경할 근거는 없다. 공통 `WorksheetEditor`와 인쇄 예외는 보존 대상이다.

영어는 `conditions`, `compareReplace`, `questionFormats`, `renderAnswer`가 없는 기존 어댑터를 쓴다. 수학의 여섯 난이도·형식 배분·최근 14일·문항류 재고·단원 단계를 필수로 강제하지 않는다. `ExamBuilder.module.css`는 `MaterialPicker`, `BuilderDialog`, 저장 조건·정답 패널 등에서도 쓰므로 일반 `.panel/.toolbar/.dialog` 변경은 새 H2/S2 범위 밖에 영향을 줄 수 있다.

## 4. 기존 시험을 보존·보강할 위치

- `ExamBuilder.test.tsx`는 배분 보존, 재고 선택 제한, 단계 복귀, 원본 검증, 추가/교체·문항류, 정답 토글, 키보드 이동, W4 조건을 이미 다룬다. S2 전환으로 기존 select/초기 체크박스 개수 조회가 바뀌므로 학년·단원 선택 절차만 갱신하고, 배분·호출 인수·순서·보존 assertion은 유지한다.
- **이 파일의 기본 `source()`/`conditioned()`에는 `questionFormats`가 없다.** 따라서 총수/형식 출력 차단 분기(`ExamBuilder.tsx:293`)는 W4 시험만 통과해도 검증됐다고 할 수 없다. 실제 수학 어댑터를 사용하는 `src/__tests__/components/QuestionFormatsUI.test.tsx:262`에 부분 구성 차단 시험이 이미 있다. 여기에 H2 안내 위치와 형식만 다른 사례·0 지정 사례를 연결하는 편이 유효하다.
- `SavedConditions.test.tsx:374`는 복원 후 제외·부족 보고와 재구성 미실행을 다룬다. S2 경로/초점 및 비동기 응답 경계를 더한다. 늦은 단원으로 구 저장본 범위를 복원하는 **공통 UI 시험**은 읽은 `ExamBuilder.test.tsx`에서 찾지 못했으므로 별도 보강 우선순위가 높다.
- `src/__tests__/unit/mathExamBuilderSource.test.ts`의 조건 동일성·캐시/abort·미확인 집계·원본 보존·최근 제외·교체 조회 시험, `exportPerMenu.test.ts`의 메뉴별 출력 계약을 유지한다. 시안 시험 통과는 제품의 실제 출처 계약 통과와 구분한다.

## 5. 정적 검토로 확정할 수 없는 완료 조건

실제 화면 검수에서는 1040·1440·390·320px 및 짧은 높이에서 S2 초기/선택/변경, 긴 실제 차시명, 20개 초과 목록, H2 다섯 막힘, 정답 펼침, 교체/조건 창을 함께 확인할 필요가 있다. 문서·내용 영역의 가로 넘침 0, 잘라 숨긴 내용 없음, 44px 조작, 이름 있는 스크롤 영역과 마지막 항목 접근, sticky 가림·초점 복귀를 본다. 시안은 본문 최대 1040px·컨테이너 900px 분기이고 기존 제품 규격은 860px 분기이므로, viewport 숫자만 같다고 동일 배치를 확인한 것으로 볼 수 없다. 실제 작업실 셸·사이드바를 포함한 가용 폭을 확인해야 한다.

독립 시안 측정 스크립트는 시안만 번들한다. 그 통과 기록을 새 제품 H2/S2의 통과로 재사용하면 안 된다. 기존 제품 범위 로딩은 초기 단원이 없을 때 bootstrap과 가용 재고 조회를 병행하고, 이후 학년·단원 이동은 메모리 필터다. 오프라인 mock으로 호출 증가를 잠글 수 있지만 **실제 API 호출 수·시간이 이전보다 늘지 않았다는 결론은 이 정적 검토에서 내릴 수 없다.**

브리프의 기존 시험 전체·새 시험·type-check·변경 파일 ESLint·affordance·브라우저 폭·실측 성능은 모두 이 세션에서 미실행이다. 공유 DB를 읽어도 된다는 주 구현 브리프의 범위는 이 독립 세션의 접근 금지 지시로 확대하지 않았다.
