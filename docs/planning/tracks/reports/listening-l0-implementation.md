# 영어듣기 L0 기반 구현 기록

2026-10-03. 사용자의 “최신 계획 승인 구현 시작” 지시에 따라 [승인 계획](../../english-listening-plan-20261003.md)의 첫 기반과 확정한 화면 컴포넌트를 구현했다. **L0 전체나 실제 사용 가능한 영어듣기 출시가 완료된 상태는 아니다.** 계약·권한 판정·응시 전이·비공개 전송 라이브러리와 교사·학생 React 화면은 실행 가능한 코드이며, 운영 저장소·인증 라우트·화면 연결·MP3 처리는 다음 작업이다.

## 화면 결정

- Wire 선택 완료: 사용자가 **교사 A 목록과 작업대 + 학생 B 한 문제 집중**을 선택했다.
- [Wire 4안](../../../design/mockups/english-listening-wire.html)은 구조 비교 기록으로 보존한다.
- [Hi-fi 4안](../../../design/mockups/english-listening-hifi.html)은 확정 배치에 H1 기존 화면 연결, H2 큰 글자, H3 재생 강조, H4 문서 중심을 적용했다. **사용자가 H1을 선택해 상세 모양도 확정했다.** 공통 색은 현재 `globals.css`의 Workroom 값을 따른다.
- 각 시안은 교사 제작·수업·학생 자습·평가를 전환한다. 실제 저장·제출·음성 재생이 없는 독립 HTML임을 표시했다. 교사 방송 평가에는 학생 재생 버튼이 없다.
- Chromium의 1440px·390px에서 각 32개 화면 조합, 문항 이동·부분 응답 차단·두 문항 후 복습 공개를 확인했다. 실제 기기의 미디어 호환성 검증을 대신하지 않는다.
- 실제 React 화면도 별도 [브라우저 검증 환경](../../../../e2e/english-listening/README.md)에서 확인했다. 교사 선택·대본 보기, 학생 소리 확인·답 확정·같은 요청 재시도·서버 공개 응답·제출, 교사 방송의 학생 음원 부재를 1440px·390px에서 검증한다. 이 환경은 실제 도메인 함수와 임시 메모리 상태를 사용하며 저장·인증은 운영 연결이 없는 대역임을 화면에 표시한다.

| 학생 화면 | `ListeningStudentView`: B 한 문제 집중, H1 공통 토큰, 소리 확인·시작·답 확정·저장 실패 재시도·제출. 요청 식별자와 본문을 재시도 동안 고정. 서버가 준 복습 DTO만 표시하며 교사 방송에는 음원 요소가 없음 |
| 코드 경계 | 학생 화면/컴포넌트 → 교사용 영어 코드·계약·Prisma/DB의 직접·간접 참조를 검사. 기존 학생 서버 페이지의 인증·테마 조회 일곱 간선만 정확히 예외로 두고, 그 경로도 영어 코드 참조 검사는 유지 |

라이브러리에 넘기는 계정·권한·검수·공개 이력은 **서버에서 읽은 사실**이어야 한다. 클라이언트가 `approved`, `ready`를 보냈다는 이유로 발행하지 않는다. 현재 이 정책을 운영 요청에 연결한 라우트는 없으므로 기능이 이미 열려 있다고 해석하지 않는다.

## 응시와 공개 전이

| 요청 또는 상태 | 판정 |
| --- | --- |
| 소리 확인과 음원 준비 전 개별 시작 | 거절. 타이머 시작 없음 |
| 교사 방송 시작 | 같은 방송의 참여자·발행본·시작·마감 시각을 사용. 학생 지연 접속으로 시간을 새로 만들지 않음 |
| 최초 답 확정 | 같은 문항의 최초 답을 덮어쓰지 않음. 초기 구현의 이 명령은 편집 가능한 자동 저장 초안이 아님 |
| 묶음 일부 문항만 답함 | 대본·해설·정답·근거 구간 비공개 |
| 학습 묶음의 최초 답 전체 확정 | 그 묶음 복습만 공개 |
| 평가 제출 | 확정된 상태로 전환. 해설은 배정 공개 정책에 따라 판정 |
| 같은 키·같은 요청 재전송 | 기존 접수 상태 반환. 마감 뒤 재전송도 새 제출을 만들지 않음 |
| 같은 키·다른 요청 또는 오래된 개정 | 충돌 거절 |
| 새 답 또는 새 제출이 마감 뒤 도착 | 거절. 이미 저장한 답 유지 |
| 제출 후 공개된 문항에 복습 답 | 최초 답과 제출 시각을 유지하고 복습 답만 별도 저장 |
| 배정 취소·전출·계정 비활성 | 기존 응시가 있어도 다음 읽기·미디어 요청 거절. 이미 받은 바이트는 회수할 수 없음 |
| 교사 방송의 학생 미디어 요청 | 거절. 학생 답안 통신 장애와 교사 방송 장애는 다른 사유 |

이 전이는 순수 함수다. 실제 동시 요청을 제어하려면 응시 개정 조건, 중복 키의 유일 제약, 답과 접수 기록 저장을 **같은 DB 트랜잭션**으로 구현해야 한다. 최초 응시 중복 생성 제약도 영속 저장 계층의 필수 조건이다. 평가의 편집 가능한 초안과 제출 답안 스냅샷은 L2 라우트 전에 추가해야 한다.

## 독립 코드 리뷰 반영

Claude의 [10개 지적과 재현](listening-l0-code-review.md)을 코드와 회귀 시험으로 재점검했다. 기획 때의 Claude·Grok 검토와 구분되는 구현 리뷰다.

- 학생 미디어 요청은 발행본의 **정확한 세트·음원 ID**에 묶인다. 같은 세트의 미발행 음원도 거절한다.
- 음원 소유자·지점·검증 시각은 서버 조회 및 완료 레코드에서 가져온다. 문서의 값을 복사해 검증을 통과시키지 않는다. 매 요청에서 현재 범위와 업로드 당시 범위를 비교한다.
- 기존 영어 세 메뉴를 모두 차단한 교사는 기본 거절한다. 시범 허용 명단과 별개의 명시적 전환 예외만 허용하며, 실제 관리자 저장 계약과 메뉴 연결은 후속이다.
- `appendListeningAssignmentTargets`는 옛 배정 스냅샷, 새 개정, 추가 감사 기록을 반환한다. 영속 어댑터는 응시가 가리키는 `assignmentRevision`을 읽고, 현재 취소·계정·소속 권한은 별도로 다시 확인해야 한다.
- 응시 생성 전 공개 이력은 인증된 `context.studentId`에 묶는다. 배정 취소 후에도 인가된 관리자의 취소 전이만 기록할 수 있고 일반 읽기·답안 쓰기는 거절한다.
- 최초 답의 `savedAfterRelease`는 **그 배정에서 저장 직전 공개 여부**다. 옛 데이터에 값이 없으면 미상으로 세고, `false`를 다른 자료나 과거 응시까지 포함한 무노출 증거로 해석하지 않는다. 점수와 공개 후 답의 수를 별도 반환한다.
- 내용 해시는 권리·출처까지 포함하는 보수적 정책을 유지한다. 제작 절차는 **권리·출처 확인 → 내용·음성·정렬 검수 → 발행**이다. 앞선 확인을 바꾸면 검수를 다시 해야 한다.
- 전입 학생을 포함한 방송도 기존 학생은 보존된 배정 개정으로 같은 시각에 시작할 수 있다. 방송을 만들 때 현재 명단 전체를 인가하고, 응시 전이에서는 해당 학생의 참여 여부·발행본·시각을 확인한다.
- HTTP 부분 전송은 모르는 단위와 지원하지 않는 유효한 다중 범위를 무시하고 전체를 보내며, 잘못된 바이트 범위는 416으로 거절한다. HEAD에는 Range를 적용하지 않는다. 이 경우에도 같은 인가 검사를 수행한다. [RFC 9110 §14.2](https://www.rfc-editor.org/rfc/rfc9110.html#section-14.2)

실제 API는 취소 명령의 관리자 권한, 배정 개정 CAS, 공개 이력과 최초 노출 감사 기록을 영속 저장해야 한다. UI 재생 제한만으로 평가의 청취 횟수나 이미 내려받은 음원의 재생을 강제할 수는 없다.

## 다음 구현의 조건

1. **확정 화면의 운영 연결.** 교사 A·학생 B와 H1의 실제 컴포넌트는 구현했다. 자료 조회·답 저장·재생 권한은 검증된 서버 응답과 연결해야 한다. 화면 테스트의 콜백 대역은 운영 저장·인증 검증을 대신하지 않는다.
2. **운영 저장소 실측과 영속 모델.** 현 구현은 프로세스 안의 메타데이터와 임시 디스크만 사용한다. 로컬 Docker 데몬이 실행 중이지 않아 PostgreSQL 실험은 수행하지 않았다. 공유 DB를 대체 실험장으로 사용하지 않았다. 비공개 객체 저장소와 영어 전용 청크 저장을 실제 배포 조건에서 비교하고 확정해야 한다.
3. **MP3 처리.** 현 MP3는 서명만 감지하고 발행·재생을 막는다. 실제 디코딩과 메타데이터 제거 도구, 재생용 파생 파일, 손상 파일·길이·원본 보존 규칙을 확인한 뒤 L1 업로드를 연다. PCM 시험 통과를 MP3 통과로 부르지 않는다.
4. **실제 경로와 메뉴 연결.** 교사 시범 권한, `requireStudent({active:true})`, 최신 계정/소속 조회, 소유 범위의 반 선택, 서버 저장/조회/미디어 인가를 라우트마다 연결한다. 학생의 일반 교사 API 접근은 계속 거절한다.
5. **운영 기록과 보존.** 배정 생성 시 대상 스냅샷, 전입 추가 이력, 취소, 노출·재생 관측, 감사 기록의 영속 모델을 만든다. 계정 삭제·익명화·보존 기간과 실제 청취 벤치/시범 합격 기준을 L0의 남은 결정으로 유지한다.
6. **L1·L2 실제 완주.** 자료 등록→검수→발행→교사 재생, 이어서 학생 배정→자습→3~5문항 평가→제출·복습을 저장소 왕복과 실기기로 검증한다. 새 인쇄물은 별도 실물 확인이 필요하다.

공유 DB 마이그레이션, 배포, 유료 음성 호출은 수행하지 않았다. 실제 영어듣기 메뉴·API·학습 화면을 열지 않았으며, 기존 영어 생성·저장·인쇄 경로의 계약은 그대로다.
