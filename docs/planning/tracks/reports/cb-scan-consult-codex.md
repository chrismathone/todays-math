# 개념 백지 사진 채점 — Codex 독립 협의 의견

2026-11-25 · 검토 기준 `0619edd6a` · 가지 `phase/cb-scan-core`

**추천 조합은 P1 + C1 + V3의 표시·확대와 V1/V2의 공개 전 수정 + R2, 교사에게만 R4 대조다.** 새로 발행한 지면을 대상으로 시작하고, A 자유 서술의 자동 판정은 제외한다. 사진 위 번호는 발행 당시 칸 좌표와 모서리 표식으로 맞추되, 정합을 확인하지 못하면 번호를 억지로 붙이지 않는다.

지정된 세 보고서와 Wire 코드를 판단 근거로 삼은 독립 추천이며, 리드와의 합의 결과를 전제하지 않는다. 아래의 **관찰**은 보고서·코드에서 확인한 내용, **추천**은 이번 독립 판단, **추측**은 아직 사용자 관찰이나 실물 시험으로 확인하지 않은 이유다. 이번 협의에서 코드를 바꾸거나 새로운 측정을 하지는 않았다. 문서의 선택은 협의안이며 이미 제품에 반영됐다는 뜻이 아니다. 작업 트리에 이미 있는 미커밋 구현물은 이번 추천의 완료·성능 근거로 쓰지 않았다.

선택 이유 중 «찾기 쉽다», «비교하기 쉽다», «왕복을 줄인다»는 사용성 판단은 **시안 구조에서 한 추측**이다. 실제 학생·교사의 과제 완료 시간이나 오류율을 비교 측정한 결론은 아니다. 측정으로 확인한 지면 넘침·QR 복호화와 구별한다.

## 1. 네 묶음의 선택과 버린 이유

### 지면 QR: P1

| 안 | 판단과 이유 |
| --- | --- |
| **P1 머리 옆 독립 열** | **채택.** 제목 옆에서 QR을 찾기 쉽고, 현재 측정에서 본문 넘침 없이 학생지와 채점표를 모두 식별한다. 20mm는 실물 검증 전 잠정 크기다. |
| P2 날짜 위 QR | 버림. 머리 높이를 늘리면서도 현재 축소 실험의 복호화가 더 낫지 않아, 지면 공간을 더 쓸 근거가 부족하다. |
| P3 머리 위 전용 띠 | 버림. 긴 표본의 채점표에서 실제 넘침이 관찰됐으므로 현 쪽 나눔 위에 그대로 얹을 수 없다. |
| P4 이름 아래·학생지만 | 버림. 채점표에도 기계적으로 구별할 표지가 있어야 잘못 올린 답지의 자동 판독·정답 노출을 막기 쉽다. |

학생지·채점표 모두 QR을 두고 `part`를 식별해 **채점표 제출은 서버에서 거절**한다. 글자 복구 코드는 남긴다. 최종 발행 ID/주소가 바뀌면 QR 밀도를 다시 재며, 모서리 표식을 추가한 최종 지면에서 긴 제목과 모든 형식을 다시 확인한다. «20mm 확정»이나 «기존 페이지 수 보장»으로 넘기지 않는다.

이 구별은 진입 주소의 `part`나 화면에서 고른 쪽을 믿는 방식이어서는 안 된다. **업로드한 사진 자체에서 읽은 QR**을 저장된 발행물·쪽·학생지/채점표와 대조해야 한다. 다른 쪽이면 올바른 자리를 안내하고, 다른 발행물이나 채점표면 현재 제출에 넣지 않는 것이 추천 동작이다. QR을 읽지 못한 사진은 식별 성공으로 취급하지 않고 §3의 복구 흐름으로 보낸다.

### 촬영: C1, 교사의 학생 선택 우선순위만 C4에서

| 안 | 판단과 이유 |
| --- | --- |
| **C1 한 쪽씩 촬영** | **바탕으로 채택.** 폰의 주 행동인 현재 쪽 촬영을 앞에 두고, 이미 찍은 쪽은 아래에서 확인한다. |
| C2 쪽 목록 먼저 | 전체 구조는 버림. 미촬영 쪽 요약과 해당 쪽으로 이동하는 기능만 가져와 접힌 상태로 둔다. 목록이 촬영 틀을 밀어낼 필요는 없다. |
| C3 촬영과 제출 분리 | 별도 단계는 버림. 제출 직전 모든 쪽 확인은 같은 흐름 안에 두어, 한 쪽 재촬영 때문에 화면 단계를 왕복하지 않게 한다. |
| C4 답안 주인 먼저 | **교사의 첫 촬영 전 학생 확정에만 채택.** 촬영한 지면 띠까지 카메라 위에 올리는 구성은 학생에게 쓰지 않는다. |

관찰: C1에도 답안 주인 영역이 있다. C4에서 가져오는 것은 새로운 인증 기능이 아니라 **교사가 여러 학생을 대신 찍을 때의 정보 우선순위**다. 학생은 인증된 본인으로 고정하고, 교사는 학생을 먼저 고른다. 촬영을 시작한 뒤 주인을 바꾸려면 기존 답안에 덮어쓰지 않고 새 제출로 분리한다. 이는 잘못된 학생에게 저장할 위험을 줄인다는 추측이며, 교사 촬영 관찰로 확인해야 한다.

빠진 쪽·중복 쪽·다른 발행물·채점표의 구별, 재촬영, 로그인 뒤 맥락 복귀, 외부 AI 전송 고지는 네 안에 이미 있는 요구를 유지한다. 시안의 학생/교사 선택 스위치는 제품 권한 검사가 아니다.

발행 스냅숏의 학생지 전체가 모이기 전에는 읽기 제출을 받지 않는다. 빠진 쪽을 빈 답으로 채우지 않고 촬영 상태로 남긴다. 중복 쪽은 새 쪽 수로 세지 않으며, 같은 쪽을 바꾸는 재촬영인지 확인한다. 사진의 이름으로 주인을 추측하지 않는다.

### 읽은 답 확인: V3의 외형·확대 + V1/V2의 공개 전 수정

| 안 | 판단과 이유 |
| --- | --- |
| V1 밑줄·왼쪽 번호 | **공개 전 수정 원칙만 채택.** 밑줄은 인쇄 쓰기 줄과 구별하기 어렵고 쪽마다 번호를 다시 매기면 같은 번호가 반복된다. |
| V2 형광 띠·위쪽 번호 | 공개 전 수정과 이어지는 번호는 동의하지만 외형은 버림. 필기 위 색 면을 얹어 원본의 옅은 획을 비교하기 어렵게 만들 이유가 없다. |
| **V3 테두리·오른쪽 번호** | **표시·이어지는 번호·누르면 확대를 채택.** 답 영역을 가리지 않고 위치를 연결하기에 적합하나 공개 뒤 학생 재입력은 버린다. |
| V4 모서리 선·안쪽 번호 | 버림. 안쪽 번호는 필기를 가릴 수 있고, 확대 없는 초점 이동만으로는 작은 글씨를 확인하기 어렵다. |

V3의 현 CSS도 배지가 테두리에 걸친다. 제품에서는 **가능한 한 필기 바깥에 번호를 놓고 연결선을 쓰며**, 좁으면 확대 보기로 넘기는 보완이 필요하다. «현재 코드가 필기를 전혀 안 가린다»는 판단은 아니다. 사진 아래 같은 번호 입력란, 번호를 눌렀을 때 확대, 확대에서 그 입력란으로 이동하는 연결은 유지한다.

### 결과: R2, 교사 대조만 R4

| 안 | 판단과 이유 |
| --- | --- |
| R1 종합 점수 우선 | 버림. 형식별 판정 단위와 보류 처리가 다른데 가중치·부분점수를 만들어 합산할 근거가 없다. 빈 «—점» 자리도 남기지 않는다. |
| **R2 문항별만** | **채택.** 지면 순서와 연결해 무엇이 맞고 어떤 뜻을 보완해야 하는지 직접 보여 준다. |
| R3 확인 필요 먼저 | 기본 재정렬은 버림. 확인 필요 개수·필터·첫 항목 이동만 가져오고, 원래 쪽·문항 위치는 유지한다. |

교사는 사진의 해당 칸, 최초 읽은 글, 학생 직접 입력, 자동 판정, 교사 수정 이유를 같은 대상으로 대조한다. 학생도 직접 입력 여부와 교사 수정 사실을 볼 수 있어야 한다. 처리가 끝난 결과는 바로 공개하며 교사 확정을 기다리게 하지 않는다. 일부가 확인 필요여도 판정된 나머지는 공개한다.

## 2. 세부 결정

**학생 수정은 공개 전에 끝낸다.** 목적은 종이에 쓴 답의 판독 정정이다. 기본 화면은 못 읽은 칸을 안내하되, 잘못 읽었는데 확신한 답도 고칠 수 있도록 전체 판독문을 펼쳐 볼 수 있게 한다. 이때 정답·판정·채점 근거는 보이지 않는다. 제출 확정에서 입력 판을 고정하고, 그 판으로 채점·공개한다. 뒤늦게 도착한 수정이나 다른 탭의 오래된 요청이 공개된 판정을 덮지 않게 해야 한다.

공개 뒤 학생은 «종이에 쓴 답과 달라요»라고 교사에게 알리고 교사가 원본과 대조해 수정한다. 첫 출시에는 기존 연락 경로를 쓰고 별도의 정정 요청함까지 만들 필요는 없다. 학생에게 정답을 보여 준 뒤 스스로 평가 기록을 다시 쓰게 하지는 않는다. 이후 다시 풀기는 별도의 학습 기록이다. 최초 읽기·직접 입력·자동 판정·교사 판정을 각각 보존하고, 교사 수정에는 이유를 붙인다. 수정 횟수나 제한 시간을 임의 숫자로 정하지 않는다.

**빈 답과 못 읽음을 구분한다.** 시안 `ReadAnswers.tsx`는 입력이 비어 있으면 다음 행동을 막고, 비어 있지 않은 문자열만 직접 입력으로 센다. 제품에서는 «종이에도 비워 두었어요»와 «지금 확인하기 어려워요»를 명시적으로 구별해야 한다. 전자는 빈 답으로, 후자는 확인 필요로 남긴다. 모든 칸을 억지로 채워야 결과를 볼 수 있는 흐름은 채택하지 않는다. 학생이 답을 못 확인해도 나머지 판정은 볼 수 있다.

**번호는 전체 학생지에서 이어지고, 제출 동안 고정한다.** 발행 스냅숏의 쪽 순서·칸 순서로 확인 번호를 정한다. 화면에 불확실한 칸만 보이면 번호가 건너뛸 수 있지만, 수정할 때마다 다시 매기지는 않는다. `slotId`가 실제 연결 키이고 번호는 표시용이다. «확인 번호 · 쪽 · 문항 · 빈칸»을 함께 적어 문항 번호와 구별한다. 원문 쪽 번호도 학생지 전체 기준 하나로 안내한다. 현재 `circled()`의 유니코드 문자 덧셈을 일반 번호 체계로 복사하지 말고, 숫자를 원형 배지 안에 그린다.

**종합 점수는 만들지 않고 △는 유지한다.** ○는 요구한 뜻을 모두 충족하며 모순 없음, △는 일부를 충족했으나 명시적인 오류는 없음, ×는 오개념·핵심 뜻 없음·확인된 빈 답, 확인 필요는 판독이나 판정 근거 부족이다. △ 옆에는 부족한 뜻을 구체적으로 적는다. △를 절반 점수로 환산하거나 확인 필요를 ×로 바꾸지 않는다. ○도 장기 숙달을 뜻하지 않는다. 상태 개수를 보여 주면 «문항», «빈칸», «이름표» 등 단위를 붙이고 서로 다른 단위를 합친 성공률을 만들지 않는다.

결과의 단위는 뒷단 `targets`를 따른다. B의 ○× 표시와 까닭은 함께 한 판정, C의 문장 빈칸은 칸별·적용은 문항별, 현재 D는 질문별, E는 이름표·설명 칸별이다. 시안 `ResultView.tsx`의 C 개념 행을 곧바로 실제 빈칸 판정 하나로 삼으면 안 된다.

**A 자유 서술은 1차 자동 판정 범위에서 뺀다.** 자유로운 개념 배치·동치 설명·보조 그림·기준 밖의 맞는 개념을 연결하는 검증이 없다. 기존 A 인쇄는 유지하며, 혼합 발행물에 A가 있으면 촬영·원본 열람·교사 확인에는 포함하되 자동 ○△×를 내지 않는다. 지원하는 부분만 자동으로 처리했다는 범위를 명시한다. 새 자동 채점의 목표 범위는 B·C·현재 D·E로 두되, 형식별 폰 검증을 통과한 것부터 연다. **옛 D의 열린 뜻·예도 첫 출시에서는 교사 확인으로 둔다.** 뒷단에 판정 계약이 있다는 사실과 실물 성능 검증을 구별한다.

## 3. 사진 위 번호의 위치 — 가장 덜 위험한 길과 후퇴

**추천은 P1의 QR + 페이지에 넓게 떨어진 모서리 표식 네 곳 + 발행 때 고정한 칸 좌표다.** 표식 모양·크기·인쇄 여백은 아직 측정하지 않았다. QR은 발행물·쪽·학생지/채점표·방향을 식별하고, 모서리 표식은 지면과 사진의 위치 대응을 돕게 역할을 나눈다.

| 방법 | 판단 |
| --- | --- |
| QR 하나의 모서리만 사용 | 이론적으로 알려진 평면의 대응점으로 변환을 구할 수 있다. 하지만 작은 머리 QR 근처의 위치 오차를 먼 답 칸까지 확대 적용하게 되고, QR이 읽혔다고 종이 전체가 나왔거나 휘지 않았다는 뜻도 아니다. 단독 자동 표시의 출시 근거로는 부족하다. |
| QR + 넓게 떨어진 인쇄 표식 | **새 발행물의 주 경로로 추천.** 이미 인쇄 지면을 바꾸는 시점이므로, 알려진 위치를 직접 제공하는 편이 임의 필기·문항 번호를 찾아 맞추는 것보다 검증하기 쉽다는 판단이다. 실물 성능은 미측정이다. |
| 종이 외곽 자동 검출 / 사용자가 네 모서리 지정 | 보조 복구 후보. 바탕과 종이 경계, 잘린 사진, 사용자 선택 오차에 취약하므로 주 경로의 검증을 생략하는 수단으로 쓰지 않는다. |
| 모델 bbox / 문항 번호 OCR | 1차의 권위 있는 좌표로 쓰지 않는다. 읽기 보고서의 검출기 간 일치는 사람 참 경계 정확도가 아니며, 새 지면의 실제 폰 정합 시험도 아니다. |

평면 간 변환의 전제는 [OpenCV 공식 homography 설명](https://docs.opencv.org/4.13.0/d9/dab/tutorial_homography.html)에서 확인했다. QR 주변 오차의 외삽 위험과 표식 배치 선택은 이 원리에서 한 **설계 추론**이다. 접힌 종이·휘어진 책장·국소 왜곡을 평면 변환만으로 해결했다고 주장하지 않는다. 표식에 맞춰 변환을 구한 뒤 같은 표식에 잘 맞는다는 것만으로 독립 검증을 대신해서도 안 된다.

필요한 선행 자산은 **실제로 발행한 최종 지면의 배치 기록**이다. 글꼴 로딩·쪽 나눔·QR·표식을 반영한 렌더에서 쪽 크기, 표식 위치, `slotId`별 답 영역, 배치 버전, 지면 산출물의 지문을 고정한다. 답·기준의 서버 스냅숏과 같은 발행 ID에 묶는다. 다시 열 때 현재 은행이나 최신 CSS로 옛 지면을 재생성해 좌표를 덧씌우지 않는다. 브라우저가 보낸 임의 좌표를 검증 없이 발행 기준으로 저장해서도 안 된다.

관찰: 현재 `MarkedPhoto`는 실제 사진이 아닌 P1 지면 DOM을 렌더하고, 각 쪽의 앞 두 서술 답 칸을 계측한다. 선택한 다른 P안의 폰 사진이나 모든 형식의 칸에 정합한 구현이 아니다. 뒷단 `planSheet`에도 촬영 좌표는 없다. 따라서 이 부분은 단순한 화면 배선이 아니라 별도의 검증 과제다.

**후속 측정 제안:** 변환을 구하는 데 쓰지 않은 답 칸의 모서리·중심을 사람이 사진에서 표시해, 투영한 위치와의 차이를 사진 픽셀과 지면 환산 mm로 함께 기록한다. 머리 QR 가까운 칸과 먼 아래쪽 칸을 나누고, 중앙값뿐 아니라 최대 오차·칸을 잘못 연결한 건수·표시를 포기한 사진 수도 남긴다. 이 보고서에는 이 오차의 실측값이나 허용치를 제시하지 않는다. 합성 원근 변환 시험과 실제 종이·폰 시험도 별개로 기록해야 한다.

**실패했을 때는 다음 순서로 후퇴한다.**

1. QR/발행물/쪽을 확인할 수 없으면 먼저 재촬영한다. 글자 복구 코드는 인증 후 발행물 찾기와 쪽 선택에 쓰고, 저장된 지면 미리보기로 확인한다. 코드 자체가 제출 권한은 아니다. **학생이 코드를 입력하고 쪽을 골랐다는 사실만으로 실제 사진의 식별이 끝났다고 처리하지 않는다.** 사진 자체의 식별을 회복하지 못하면 첫 출시에서는 교사 수동 확인으로 넘기고 자동 채점 진입을 막는다.
2. 발행물은 맞지만 좌표 맞춤이 불확실하면 재촬영을 안내한다. 그래도 안 되면 **추측 번호·테두리를 숨기고**, 원본 전체와 쪽·문항·칸 목록으로 직접 확인하거나 교사에게 넘긴다. 수동 연결은 수동으로 했다고 남긴다.
3. 어느 칸의 답인지 신뢰할 수 없거나 글을 읽을 수 없으면 자동 판정을 확정하지 않는다. 확인 필요를 유지하고 확인 가능한 나머지만 공개한다. 잘못된 칸에 그럴듯한 번호를 붙이는 것보다 기능을 줄인다.
4. 저장된 발행 스냅숏이 없는 옛 지면은 현 은행으로 복원해 자동 채점하지 않는다. 교사 수동 확인 또는 새 지면 재발행으로 안내한다.

사진 확대는 **화면에서 보는 기능**으로 둔다. 이것을 AI 문항별 크롭 재호출로 연결하지 않는다. 읽기는 현재 추천된 한 쪽 전체·원색 경로를 유지하고, 빨강 제거로 연필을 복원하려 하지 않는다. 이름 등 가릴 영역은 확정된 지면 배치로 검증해야 하며, 측정 자료의 상단 일정 비율 가림을 새 QR 지면에 그대로 복사하지 않는다. 읽기 입력을 원근 보정하거나 압축 조건을 바꾸면 그것도 새 측정 조건이다.

## 4. 뒷단 물음 1~8에 대한 추천 답

### 1 — A 판정

**교사 확인으로 둔다.** §2의 범위를 따른다. 이후 추가하려면 교사가 개념별 근거 영역과 판정을 확정한 실제 자유 서술 표본이 필요하다. 단어가 있다는 이유로 개념을 안다고 판정하거나 그림·예에 임의 점수를 주지 않는다.

### 2 — 코드 없는 지면의 식별자

**선택 내용을 재인코딩한 긴 코드 대신, 서버에 저장된 발행물을 가리키는 별도 불투명 ID를 발급한다.** 정확한 `pick`과 legacy 코드가 인쇄 정원을 넘는 경우도 같은 방식으로 지원한다. 스냅숏과 최종 배치 저장에 성공한 뒤에만 발행을 확정한다. QR과 사람이 입력할 복구 코드는 같은 발행물을 가리키며, 복구 코드는 충돌·오타 검사를 갖춘 별도 표현으로 둔다. 길이는 아직 측정하지 않았으므로 여기서 임의로 확정하지 않는다.

같은 발행물의 재인쇄는 같은 저장 지면을 사용한다. 내용·선택·배치가 바뀌면 새 발행물이다. QR에는 발행 ID·쪽·학생지/채점표 구분만 담고 정답·학생 이름·인증 비밀을 담지 않는다. 기존 글자 코드는 과거 지면 찾기의 보조로 남기되, 정확한 저장본을 특정하지 못하면 자동 복원을 허용하지 않는다.

### 3 — 사진 보존 7일/30일

**채점 근거로 사용한 사진은 30일**, 미제출·실패·채점에 사용하지 않은 교체 사진은 **7일 이내 정리**를 추천한다. 두 기한 모두 각 사진의 최초 업로드 시각부터 센다. 제출 이름이 «정상»인지보다 실제 판정 근거로 사용됐는지가 구분 기준이다. 둘 다 이번 정책 제안이며 관측된 최적 보존 기간이나 법적 의무가 아니다. 공개 뒤 교사 정정에 증거가 필요하므로 판정에 쓴 사진은 7일보다 30일을 택했다. 주간 확인이 늦어지거나 결석 때문에 검토가 밀릴 수 있다는 이유는 **추측**이며 실제 검토 시점 자료는 없다.

열람·재시도만으로 이전 사진의 만료를 연장하지 않는다. 이미 판정 근거로 쓰인 이전 사진은 «실패 사진»으로 재분류해 먼저 지우지 않는다. 만료된 미처리 사진은 재촬영을 요청하며, 남아 있는 객체를 뒤늦게 채점해 기한을 되살리지 않는다. 원본에서 만든 축소본·확대본도 원본 만료를 따른다. 비공개 저장, 권한 확인 후 짧은 유효기간의 열람 주소, 만료 시 신규 열람 차단, 실제 객체 삭제와 실패 재처리가 필요하다. 주소를 발급할 때 남은 보존 기간을 넘지 않게 한다. 삭제 성공 전 메타데이터만 삭제 완료로 표시하지 않는다. 구현 근거는 [DB 초안의 보존·삭제 경로](../../../../prisma/drafts/concept-blank-scan/README.md)다.

서명 주소의 만료와 이미 전달한 사진의 회수는 다르다. Supabase 공식 문서는 서명 토큰 기한과 응답 캐시 기한을 구별하며, 객체 삭제는 SQL 메타데이터 삭제가 아닌 Storage API로 하라고 설명한다. 따라서 «기한이 되면 모든 사본이 즉시 사라진다»고 약속하지 않고, 열람 응답의 캐시 정책과 실제 객체 삭제를 함께 검증한다. ([공식 캐시 안내](https://supabase.com/docs/guides/storage/cdn/smart-cdn), [공식 삭제 안내](https://supabase.com/docs/guides/storage/management/delete-objects))

학생은 본인 사진 삭제를 요청할 수 있고, 담당 교사는 현재 권한 범위에서 조기 삭제를 실행할 수 있게 권한다. 삭제 사유·시각은 남기되 사진 삭제를 평가 결과 삭제와 묶지 않는다. 읽은 글·직접 입력·판정 이력은 사진과 분리해 기존 학생 학습기록의 보존·탈퇴·삭제 정책을 따르게 한다. **기존 정책의 실제 기간은 이번 자료로 확인되지 않았다.** 출시 전 그 정책을 연결해 명시해야 하며 이를 무기한 보관의 허가로 해석하지 않는다. 사진이 만료되면 사진으로 재검증할 수 없다는 사실을 교사에게 표시한다.

### 4 — 월 상한의 의미

**호출 전 보수적인 최대 비용을 선예약하는 상한을 추천한다.** 검토 대상 뒷단 보고서에 적힌 «도달한 뒤 다음 호출 중지»는 진행 중 호출이 잔액을 넘을 수 있다. 이것을 엄격한 한도라고 안내하면 안 된다. 읽기·채점의 입력 한계와 최대 출력에 근거한 상계를 확보하고, 사용액 + 미정산 예약액 + 새 예약액이 상한 안일 때만 호출을 받는 영속·원자적 처리가 필요하다. 상계를 신뢰할 수 없는 요청은 보내지 않는다. 평균 $0.0402/쪽을 예약 최대액으로 쓰지 않는다.

완료되면 보고된 실제 토큰으로 정산하고 차액을 푼다. 사용량 불명은 예약을 유지한다. 이 한도는 **지정된 고정 단가로 계산하는 사진 채점 예산**이며 제공자 청구서의 절대 상한 보증은 아니다. 같은 API 키를 쓰는 다른 기능의 비용까지 이 원장에 자동으로 잡히는 것도 아니다.

현재 기본 **$100**, 읽기·채점 공통, 지점·학생별 복제 없는 전역 합계, **호출을 시작한 UTC 월**은 유지할 것을 추천한다. 운영 화면에 UTC 기준과 포함 범위를 명시한다. 한국 달력 월·지점 배분은 이번 첫 출시에서 추가하지 않는다. 호출 사이에 잔액이 부족해지면 진행 상태를 저장하고 보류할 수 있어야 하며, 완료한 읽기를 다시 유료 실행하지 않는다.

### 5 — 운영 복구와 동시성

**초기에는 현재의 전역 한 호출 제한을 유지하되, 사용자 재시도 대신 영속 작업 상태와 대기 순서를 둔다.** 탭 종료·중복 클릭·서버 재시작에도 같은 제출 판·쪽 사진·작업 단계의 실행과 정산이 중복되지 않아야 한다. 동시 호출 확대는 선예약과 복구 시험 뒤에 결정한다. 현재의 바쁨 거절만 그대로 제품에 내보내면, 학생들이 재시도하면서 혼란을 겪을 수 있다는 추측이다.

사용량 미확인 복구는 운영 담당자가 맡는다. 호출 식별자·시작 시각·모델·토큰 영수증·가능한 제공자 사용 내역을 대조해 실제 비용을 확정하고 해제한다. 사용량을 끝내 확인하지 못하면 보수적 예약액을 유지하거나 그 상계로 정산했다는 근거를 남긴다. 타임아웃만으로 무료 처리하거나 같은 호출을 자동 재실행하지 않는다. 이미 받은 유료 응답은 보관해 결과 저장 실패나 파싱 복구에 재사용하고, 새 AI 호출로 바꾸지 않는다. 사진·답 원문을 복구 로그에 불필요하게 복사하지 않는다. 네트워크 실패는 학생 답의 «못 읽음»과 구별한다.

### 6 — 발행·학생 연결과 소유

**발행물과 제출 대상을 명시적으로 연결하고, QR은 찾기 수단으로만 쓴다.** 교사는 자기 권한 안의 발행물을 현재 맡은 학생에게 배정한다. 학생 제출은 인증된 `studentId`와 그 배정을 서버에서 확인한다. 요청 본문의 학생 ID·손글씨 이름·코드를 안다는 사실만으로 제출할 수 없다. 교사의 대리 촬영도 같은 검사를 거친다.

이 배정은 **새 정책 제안**이며 현재 DB 초안에 이미 구현된 사실이 아니다. 무관한 학생의 제출을 줄이는 이점과 교사의 배정 작업이 늘어나는 부담을 함께 가진다. 종이 배부와 함께 학생을 지정하는 흐름을 Hi-fi에서 확인할 것을 권한다.

여기서 배정은 제출 허용 대상을 정한다는 뜻이다. 별도의 과제·마감·독촉 기능까지 1차 범위에 넣자는 제안은 아니다. 지점 소속만으로 허용하는 더 단순한 안도 가능하지만, 개인 발행물과 같은 지점 공유를 구별할 명시적 정책이 먼저 있어야 하므로 이번 독립안에서는 대상 연결을 추천한다.

교사의 개인 작업물을 같은 지점 전체에 자동 공개하지 않는다. 지점 공유는 별도 명시된 공유 범위를 기존 `ownerScope`와 함께 검사한다. 지면을 볼 권한과 특정 학생 제출을 볼 권한도 각각 확인한다. NULL 지점을 전체 권한으로 취급하지 않는다.

전반·교사 이동 뒤에도 제출의 원래 발행·지점·작성자 이력은 고정한다. **과거 소유했다는 이유만으로 이동한 교사에게 계속 열어 주거나, 현재 담당이라는 이유만으로 이전 지점 자료를 자동으로 넘기지 않는다.** 현재 권한에 따른 명시적 인계가 있어야 새 교사가 과거 자료를 본다. 학생은 본인 계정의 학습기록 정책에 따라 본인 기록을 보되, 그 사실이 새 교사의 과거 지점 자료 권한을 만들지는 않는다. 기존 DB 초안만으로 이 배정·인계 규칙이 완성됐다고 보지 않는다.

### 7 — 사진 위 번호

**§3의 발행 배치 + 모서리 표식 경로를 택하고, 검증 실패 시 자동 표시를 끈다.** QR 복호화 성공과 답 칸 정합 성공을 별개 상태로 취급한다. 사용자에게 보이는 번호는 서버의 안정된 `slotId`에 묶고, 좌표 추정 순서로 답을 다른 칸에 재배정하지 않는다. 수동 복구에서도 전체 지면·쪽·문항을 확인할 수 있어야 한다.

### 8 — 재측정과 모델 선택

**읽기 Opus high·한 쪽 전체 원색, 채점도 현재 기본으로 시작한다.** 이것은 현재 비교 자료에서의 출발점이지 A~E 운영 정확도가 검증됐다는 뜻이 아니다. Sonnet 읽기나 Haiku 채점으로 내리는 결정은 별도의 새 표본 결과를 보고 한다.

새 평가 표본은 경로 선택에 쓴 기존 스캔과 분리한다. 실제 발행물의 폰 사진, 지원할 각 형식, 옅은 연필·지움·겹침·빈 답·기울기·그림자·잘린 모서리·답 칸 밖 필기를 포함하고, 사람이 사진에 보이는 글과 칸 대응을 확정한다. 의미 판정 참값은 인쇄 당시 질문·기준을 보고 별도로 정한다. A와 옛 D는 별도 연구군으로 둔다. 정답을 보며 읽은 참값을 만들거나 모델끼리의 합의를 사람 확정으로 부르지 않는다.

판독 오독·확인 필요·빈 답 오인, 잘못된 칸 연결, 의미 판정 차이, 학생 수정 부담을 따로 센다. 전체 완료 시간은 촬영/업로드/대기/읽기/확인/채점을 나누어 재고, 실제 배관의 사용 토큰·실패·재시도 비용을 함께 기록한다. 압축으로 품질이 낮아지는 분기도 검증한다. 출시 기준은 측정 전에 정하며, **다른 학생·발행물·답 칸으로 잘못 연결되는 수용 시험 실패는 허용하지 않는 것**을 추천한다. 이는 제안한 통과 조건이며 관측된 오류율이 아니다. 근거 없는 정확도 목표나 대기 시간 약속을 여기서 만들지 않는다.

## 5. 구현 차례와 가장 큰 위험 셋

### 구현 차례

1. **협의안을 하나로 합치고 범위를 기록한다.** 수정 시점·A 제외·판정 단위·발행 권한·보존·예산 의미를 먼저 닫는다. [05 §0](../../05-design-system.md#0-디자인-작업-방식-확정)의 Wire → Hi-fi 절차에 따라 선택 구조 위의 Hi-fi 4~5안을 비교한다. 이번 원장님의 위임을 협의·세부 결정의 근거로 삼으며 매번 같은 선택을 다시 묻는 절차를 만들지 않는다. 이 보고서 자체는 최종 합의나 Hi-fi 완료가 아니다.
2. **발행과 좌표의 작은 실물 검증을 먼저 한다.** 저장 스냅숏·발행 ID·P1·표식·최종 배치 기록을 한 지면으로 연결한다. 실제 프린트와 폰에서 식별·정합·잘림·후퇴를 확인한 뒤 모든 지원 형식과 긴 지면으로 넓힌다. 이 단계가 실패하면 번호를 추측하는 화면부터 만들지 않는다.
3. **권한·저장·복구 경계를 만든다.** 발행 배정, 학생/교사 조회·쓰기, 사진 보존·삭제, 영속 호출 원장·선예약·작업 재개를 준비한다. 공개 전 입력 판 고정, 중복·오래된 요청 방어도 여기서 한다. DB 초안이 있다는 사실과 적용·운영 검증을 구별한다.
4. **C1 → V3 혼합안 → R2/R4를 실제 계약에 연결한다.** 촬영 누락·정합 실패·빈 답·미확인·처리 실패·재시작·교사 정정을 포함한다. 시안의 가상 역할·DOM 사진·순환 판정·브라우저 메모리 상태를 실제 동작으로 착각하지 않는다.
5. **새 폰 표본으로 읽기와 판정을 따로 검증하고 제한적으로 연다.** 통과한 형식만 자동 판정을 활성화한다. 후퇴 경로·교사 정정·사진 만료·상한 중지를 실제 흐름에서 확인하고, 이후에만 동시성이나 저가 모델로 최적화한다. «검증 중»인 A·옛 D를 조용히 포함하지 않는다.

## 추측과 아직 실측으로 닫아야 할 물음

- **교사는 학생을 먼저 확정하는 편이 안전한가?** 그렇게 추천하지만 실제 연속 촬영 관찰은 없다. 카메라 진입을 방해하지 않는지 Hi-fi에서 확인한다.
- **모서리 표식은 어떤 크기·모양·배치면 충분한가?** 추가를 추천하지만 위치 오차·잘림·프린터 여백의 허용값은 아직 없다. 최종 QR 주소와 함께 실물에서 정한다. 하나의 QR만으로 충분하다는 검증이 새로 나오면 더 단순한 구성을 재검토할 수 있다.
- **30일 안에 교사 정정이 실제로 끝나는가?** 30일은 증거 대조를 위한 정책 선택이다. 실제 검토 시점과 사진 삭제 요구를 관찰해 보존 기간을 다시 판단한다. 텍스트·판정 이력은 연결할 기존 기록 정책을 확인해야 한다.
- **예약할 최대 비용과 제한된 동시성으로 수업 시간의 요청을 감당하는가?** 평균 읽기 비용·CLI 시간으로는 답할 수 없다. 실제 입력 상계와 운영 배관의 대기·비용을 측정해야 한다.

이번 협의 요청에서 편집한 산출물은 이 독립 협의 보고서 한 파일이다. 제품 코드·설정·DB·지면은 변경하지 않았고, 실 AI 호출·새 벤치마크·배포·커밋은 하지 않았다. 작업을 시작할 때 이미 있던 다른 변경·미추적 파일은 이 보고서의 산출물로 세지 않았으며 수정하거나 삭제하지 않았다.
