## 3. 저장 — 학생 SRS JSON 에 넣지 않는다

- **분량 설정**: 별도 정책 표, 학생당 한 행(학생 ID · 분량 덮어쓰기(nullable = 서비스 기본) · 설정 revision · 바꾼 사람 · 시각 · 적용일).
  학생 기록 JSON(`fading`)에 섞으면 ① 엄격한 계약(`storedFadingSchema`)이라 옛 배포판이 학생 기록 전체를 못 읽고(새 되돌림 하한),
  ② 학생이 풀 때마다 revision 이 바뀌어 교사 설정 저장이 부딪히고, ③ 초기화 · 복원이 교사 설정까지 건드린다.
- **상한 30 · 멈춤 3 의 집행**: 새 JSON 칸 없이 된다 — `relearn.day.checks`(그날 판정한 확인 수)로 30회를, 영수증 `graded`(최근 32개 ·
  명제 · 판정 · 시각)를 그날 · 명제로 묶어 «틀림» 3회를 센다. 성립 조건: 모든 확인 경로에서 30회를 지켜 그날 영수증이 32개 안에
  남을 것 · 화면이 아니라 저장 전이에서 막을 것 · 동시 요청 · 재전송 · 자정 · 대조 대기를 넣어도 30을 넘지 않을 것.
  영수증 보관 수를 줄이거나 30의 예외를 만들면 이 근거를 다시 본다.
- **«분량 점검 필요»(최근 7일 중 3일 이상 상한 도달)**: 하루치 `day` 와 영수증 32개로는 복원이 안 된다. 쓰려면 학생 · 날짜별 운영 집계를
  JSON 밖에 따로 둔다(D안은 이것이 꼭 있어야 한다).
- 배포 차례: DB(정책 표) → 설정을 읽는 코드 → 쓰기 열기. 되돌림 하한 `6f3d51e3f` 는 그대로.
- 서버가 정책을 정해 통합 계획의 `quota` 와 홈의 `cap` 에 함께 준다. 지금의 `?quota=` 는 호출자가 주는 값이라, 학생 경로에서 교사 설정을
  덮지 못하게 한다.
- 쓰기 권한: 계정 · SRS 메뉴 권한에 더해 소유 범위 · 지점 · 현재 반 등록을 저장 거래 안에서 다시 본다(진도 계획 쓰기와 같은 꼴).

## 6. codex 가 바로잡은 Claude 의 사실

- 결정 2 이후 첫 평가의 틀리지 않은 명제(`exposed`)는 5분 확인 한 번이다(1분 → 5분 · 통과 두 번은 틀린 뒤의 길).

- «처리량 변화 ±1»은 틀렸다 — 중3 성실은 +1.8.

## 8. Hi-fi 4안 (codex 3차 협의 — `/dev/fading-quota-hifi`)

바탕은 제품 그대로다(교사 현황 H2 · 학생 탐험 홈 · 추가 확인 칸). 안끼리 다른 것은 덧붙는 부분의 처리뿐이다.

| 안            | 교사 상세                                                                        | 학생 추가 확인 칸                    |
| ------------- | -------------------------------------------------------------------------------- | ------------------------------------ |
| Q1            | 지금 지표 칸에 «오늘 추가 확인» 소제목 + 줄 넷 · 분량은 칩 넷                    | 상한 문구 한 줄                      |
| **Q2 (추천)** | «오늘 추가 확인» · «하루 분량» 흰 묶음 둘 · 필요한 상태에만 호박색 딱지 · select | 구분선 아래 상한 문구 + 멈춘 문장 수 |
| Q3            | 이름 아래 «하루 분량 … · 바꾸기» → 제자리 펼침 · 추가 확인은 수치 한 줄          | 상한 문구 + 오늘의 학습 아래 안내    |
| Q4            | 최근 7일 띠(날짜별 수 · 상한 도달 · 기록 없음) + 그 아래 분량 칩                 | 상한 문구 + 멈춘 문장 목록           |

네 안 공통(codex 와 맞춤):

- 저장 상태 — 바꾸기 전 · 고른 뒤 저장 전(«변경안 10/18부터 … · 저장 전») · 저장 중 · 저장됨(«저장됨 · 10/18부터 …», 오늘 적용 값은 그대로 보인다) ·
  실패(입력 유지 · «저장하지 못했습니다. 다시 시도해 주세요.») · 충돌(«분량 설정이 변경되었습니다. 최신 설정을 확인한 뒤 다시 저장해 주세요.» —
  최신 값과 내 변경안을 함께 · 덮어쓰지 않음) · 강사(«분량 변경은 원장 · 지점 관리자가 할 수 있습니다.»).
- «기본»은 «서비스 기본(현재 15칸)»으로 써 «학생 지정 15칸»과 가른다.
- 학생 문구 — 상한: «오늘 추가 확인은 여기까지예요. 남은 문장은 내일부터 이어서 확인해요.» · 문장 멈춤: «이 문장은 오늘 여기까지예요. 내일부터 다시 확인해요.»
  학생에게 상한 수 «30/30»은 보이지 않는다(지금의 «오늘 N회»는 그대로). Wire 에서 Q3 의 30칸 막대 · Q4 의 학생 «30/30회»는 이 까닭으로 뺐다.
- 성공은 `role="status"`, 실패 · 충돌은 `role="alert"`. 폰 폭에서는 고르기 → 적용 안내 → 저장 순으로 쌓는다(칩은 2×2).

codex 가 짚은 구현 전 사실: 교사 요약의 `relearn.checks`(`src/lib/fading/teacher.ts:122`)는 **남은 문장들의 확인 수 합계**라 «오늘 판정한 확인»으로
쓰면 안 된다. 오늘 수는 `relearn.day.checks`, 7일 신호와 Q4 의 띠는 날짜별 집계(§3)가 있어야 한다.
