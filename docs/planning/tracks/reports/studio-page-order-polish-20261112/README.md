## 실제 화면 검증 범위

- 기존 `/dev/workspace-alignment`의 실제 `UnifiedWorkspace`, `StudioView`, `StudioPageOrder`, `PaperStrip`, `ConceptBlankView`를 사용했다. 닮은 모형 화면을 만들지 않았다. 창 하나의 Orca 내장 브라우저에서 순차 확인했다.
- 합성 8쪽 PDF + 3쪽 PDF를 업로드하고 PDF.js의 실제 미리보기 렌더를 사용했다. 이후 합성 JPEG도 추가하여 `원본 이미지`와 파일 3 구분을 확인했다. 계정 자료를 사용하지 않았다.
- 개발 서버의 `DATABASE_URL`은 연결 불가능한 localhost 포트, `AUTH_SECRET`은 일회성 검사용 값으로 실행했다. 기존 dev 화면이 `/api/**`에 메모리 응답을 제공한다. 실계정 저장·유료 AI·공유 DB 쓰기·스키마 변경·`.env` 수정/복사·의존성 설치/생성·운영 빌드 없음. 합성 업로드 뒤 보이는 저장 불가 알림은 dev fixture의 의도된 응답이다.
- 폭/높이: 1920×1080, 2560×1440, 1280×800, 1050×800, 768×1024, 760×900, 390×844, 320×740, 짧은 1920×600. 전부 문서 가로 넘침 0. 좁은 화면은 상세가 목록 아래에 있으므로 스크롤해서 마지막 이동/빼기/키보드 안내에 접근했다([390 상세](actual-390-preview.png)). 짧은 데스크톱은 560px 최소 작업 높이를 유지하여 문서 스크롤을 허용한다.
- 2560 CSS viewport의 DPR 1 캡처는 Orca의 큰 래스터 캡처에서 오른쪽/아래 픽셀이 반복됐다. 같은 **2560×1440 CSS viewport와 실측**을 유지하고 DPR 0.75로 재캡처한 원본을 위에 실었다. 이미지 편집·합성은 하지 않았다. 나머지는 DPR 1이다.
- Alt+→는 이전에 선택한 카드 대신 **키보드 초점이 있는 카드**를 옮겼고 초점을 유지했다([실제 키보드 결과](native-keyboard.json)). 코드 시험은 Alt+←, 경계, 뺀 쪽, 대기·실패, IME, 취소·외부 끌기·제자리 놓기도 포함한다.
- 기존 H2의 1920/1280/390 세 장면에서 한글 낱말 9,111개를 Range로 확인했고 중간 줄바꿈 0, 가로 넘침 0이었다. 전 학년 문장 전수 검사나 실물 인쇄 검수라는 뜻은 아니다.
