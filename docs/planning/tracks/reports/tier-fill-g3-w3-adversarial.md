### ⑴ `1-1-4 심화중` 은 답이 **전수 100%** 로 「지면 두 수의 차」다 — D-115 반증 ⑥ 위반

```
전수 (제품 가드를 그대로 걸고):
  1-1-4 : 통과 20,625짝 · down 강제 20,625 · **up 강제 0** · 둘 다 0   → 100.0%
  1-1-3 : 통과 58,625짝 · down 강제 20,625 · **up 강제 0** · 둘 다 38,000 → 67.6%
실물 : 씨앗 0~4999 · 1-1-4 더하기 쪽 0 · 빼기 쪽 5000. 시험이 쓰는 씨앗 24개도 24/24 빼기.
       씨앗 0~3 = 801−102=699 · 821−125=696 · 614−195=419 · 835−158=677
```

**뿌리는 `kPage` 가드다.** 전수로 재면 항등식이 선다 —
`borrowCount(known, known−diff) === borrowCount(known, diff)` (**122,848짝 어긋남 0**,
창을 넓혀 493,650짝에서도 0). `known = down + diff` 이므로 둘 다 같은 받아올림 패턴이다.
그래서 「지면에 적히는 뺄셈도 약속 안」이라는 그 가드는 실은 **「down 은 반드시 답 후보다」와
같은 말**이고, 약속이 `[2,2]` 한 칸인 1-1-4 는 `kUp ≠ kDown` 가드가 up 을 **늘** 지운다.

**더 나쁜 것** — 학생이 무심코 한 그 뺄셈의 받아내림이 발문이 내건 횟수와 **늘 같다**.
조건이 후보를 거르는 게 아니라 **naive 답을 확인해 준다.**

보고서 §9-7 의 손 판단(「어느 쪽인지는 성질이 정하므로 순방향 계산 하나로는 답이 안 나온다」)이
**측정으로 거짓**이다. 반증 ⑥ 이 묻는 것은 「답이 하나로 정해지나」가 아니라 **「답이 나오나」**다.
보고서가 스스로 「내 독해이지 기계가 잰 것이 아니다」라고 적어 둔 자리다.

**왜 아무 자도 안 울었나 — `forwardReachable` 이 여기서 «아니오»를 못 낸다.**
허용 꼴이 `a×b`·`a×b×c`·`a×b±c`·`a×b±c×d` 넷뿐이라 **곱이 첫 걸음이 아니면 길이 없다.**
1-1 은 지면 수가 둘이라 구조적으로 늘 `false` → `g3.ts:2228` 의 ⑥ 필터가 **한 씨앗도 안 거른다**.
판정기의 「⑥ 0건」은 «깨끗»이 아니라 **«못 셈»**이다(그 판정기는 자기 눈먼 자리를 스스로 찍는다 —
「🔴 ④ 를 못 재는 소단원 34개 … 초3 1-1-3(연산 0/8) · 초3 1-1-4(연산 0/8)」).

**대체 축은 실제로 갈린다**(재 봤다) — 「지면 두 수의 +− 한 걸음」:
```
초3 1-1-4  연산 8/8 닿음 · 기본 8/8 · 응용 0/8 · 심화중 8/8 닿음
```
연산 대조군이 8/8 이므로 **못 재는 자리가 아니다.** 세웠더라면 1-1-4 심화중을 8/8 물었다.

  안 적는 길을 만들어 kPage 가드를 떼라(그러면 up 강제 자리가 되살아난다).
