# 공용 도형 편집기 최종 포팅 · 2026-10-22

todays-math의 기존 시험지 적용·SVG 저장 계약을 유지하면서 math-figure-editor 공용 편집기를 포팅했다. 원본 기준은 `129207fba40a6324cfc3c3fc365aee67c2e3bbb8`이다. 원본 저장소는 읽기만 했다. 이후 웹앱 미들웨어·관리자·배포 커밋은 이 포팅 범위가 아니다.

## 반영 범위

- 세 번째 ‘수식편집기’ 탭과 123개 구조형 수식 틀. MathLive 0.111.1은 탭을 열 때 지연 로드한다. Next의 public 경로에 폰트 20개와 LICENSE를 넣었다.
- 전체·가로·세로 틀 확장. 자식 좌표·그림 크기는 유지하며 viewBox와 명시적 크기만 넓힌다. 잘못된 축·여백·viewBox·상대 크기를 거부한다.
- 일반 SVG 그룹의 변환·실제 잉크 경계 측정을 보완했다. todays-math의 현행 41종·과거 39종 등록 자산 frame, 위변조·특이행렬 검사와 자식 좌표 보존은 유지했다. 원본의 합성 asset 시험은 등록 자산 검증을 우회하지 않도록 일반 그룹 시험으로 맞췄다.
- 외부 내려받기는 PNG만 제공한다. 파일명 규칙과 `figure:png-exported` 이벤트를 반영했다. 내부 복사는 동일 페이지 메모리의 불투명 키만 내보내며, 붙여넣기·번호 갱신·실패 시 잘라내기 보호를 유지한다.
- PNG 저장은 편집기를 닫거나 시험지에 적용하지 않는다. 기존 ‘도형 적용’은 편집용 SVG·dataUrl·originalImage 계약을 유지하고 호스트 Promise 완료 후 닫는다. 실패하면 오류를 표시하고 재시도할 수 있다.

관리자 콘솔, 서버 저장, IP 차단, 공용 최근 작업, 원본 앱의 자동 저장·닫기 확인은 가져오지 않았다. 기존 화살표 커밋 `406615bf8`과 Native 그래프 어댑터는 그대로 보존했다.

브라우저는 실제 todays-math 편집기를 독립 fixture에서 열었다. 탭을 열기 전 MathLive 미등록, 실제 0.111.1 로드, 분수 두 칸 입력, TeX 전환, 캔버스 배치, 흰 배경 PNG 생성, 이벤트 1회, 편집기 유지, 비동기 호스트 적용, 다시 열어 수식·편집용 SVG 보존을 확인했다. 저장 Promise를 대기시킨 뒤 MathLive에 입력을 시도해 값이 변하지 않는 것도 확인했다. PNG는 다운로드 anchor를 수집해 실제 PNG 바이트를 검사했다. OS 파일 저장 대화상자나 운영 DB를 사용한 검증은 아니다. 데스크톱·320px 화면과 출력 PNG도 직접 확인했다.

초기 실패와 자원 보류 기록은 삭제하지 않았다. 이전 화면 기대값과 시험 mock의 중복 status 선택은 수정 후 재검사했다. 포팅에서 메뉴 설정을 DOM 연결보다 먼저 실행했던 오류는 원본과 같은 연결 후 순서로 고쳤고 실제 브라우저로 재검사했다. 이는 원본 결함이 아니다. 256MiB 린트 실행의 heap 부족 뒤 512MiB 단일 프로세스로 통과했다.

최종 정리에서 `exportImage.ts` 끝의 빈 줄 하나만 제거했다. 검증 당시 원본 바이트를 `pre-format-exportImage.ts`로 보존하고, 마지막 줄바꿈을 제외한 전체 바이트 일치와 이전·현재 SHA를 `eof-format-binding-r1.json`에 연결했다. 다른 운영 코드 내용은 검증본과 동일하다. 이 공백 정리 뒤의 전체 재실행은 메모리 관문에서 시작되지 않았으며 새 실행으로 세지 않는다.

공유 node_modules 정션에는 설치·생성 명령을 실행하지 않았다. package/lock은 독립 폴더에서 lock-only로 갱신했다. 검증은 integrity를 확인한 독립 MathLive 0.111.1을 사용했다. 공유 정션의 설치본 0.110.0은 그대로다. 전체 Next 빌드·운영 배포·실물 인쇄까지 완료했다는 뜻은 아니다. 원본 앱의 1813개 시험과 운영 브라우저 결과는 이 저장소의 검사 수에 합산하지 않았다.

커밋 훅의 `prettier --write`가 해시로 묶인 원본 사본·검증 입력까지 다시 쓰므로 이 증거 커밋에서는 자동 변경 훅을 실행하지 않는다. 위 프로젝트 ESLint·affordance CLI·타입·회귀·브라우저 검사를 직접 실행했고, staged whitespace 검사도 통과시킨다. LICENSE·원시 오류 로그의 공백 예외는 해당 증거 파일에만 지정해 원래 바이트를 보존한다.

## 공용 원본과의 차이 및 역반영

- 저장 대기 중 커스텀 MathLive 입력은 기존 `fieldset disabled={busy}`만으로 막히지 않는다. 같은 fieldset에 `inert={busy}`를 추가했다. 원본 담당자도 같은 한 줄을 반영 중이라고 확인했다. 중복 패치는 필요 없다.
- 탭 클릭에서 경고를 지우던 코드는 포팅 중 추가한 차이였으며 제거했다. 이를 원본의 새 결함으로 주장하지 않는다. todays-math에 이미 있던 값에 연결된 HWP 경고 보존도 유지했다.
- `FigureMathEditor.tsx`에는 같은 값으로 라벨 identity가 바뀌어도 새 필드를 초기화하는 처리, 마지막 입력을 탭·캔버스 클릭 전에 확정하는 처리, 미처리 이벤트가 unmount 뒤 callback을 호출하지 않도록 하는 처리를 보완했다. 근거는 `FigureMathEditor.test.tsx`의 세 회귀 사례와 위 실제 브라우저 결과다. 원본 앱 전체에서의 독립 재현·회귀 검증을 대신하지 않는다.
- 원본 담당자에게 전달할 입력 처리 후보는 `upstream-input-fixes-unidiff-zero-r2.patch`이다. Vite BASE_URL·기존 원본 UI를 유지한 `FigureMathEditor.tsx` 한 파일만 대상으로 한다. `git apply --check --unidiff-zero` 확인만 수행하며 원본 저장소에 적용하지 않는다. 초기 3파일 후보는 역사적 검토물이며 역반영 대상으로 사용하지 않는다.

## 엔진 잔여 범위

이번 완료는 공용 편집기 포팅이다. 전체 기출·생성 엔진 완료가 아니다. M5 최종 회귀 갱신 중인 `middleM3Stat2.test.ts`는 미검증 WIP로 별도 보존하고 이 운영 코드 커밋에 넣지 않는다. M4 소유관계 16건 및 M14 EF 배치 10건 보류도 이 검증으로 해소되지 않는다. 기존 작성·검수·권리·학년 집계와 82개 잠금, 영구 제외를 바꾸지 않았다. 새 문항 작성·승인·적재·운영 DB 쓰기·배포는 모두 0이다.
