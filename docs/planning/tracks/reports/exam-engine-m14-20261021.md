# M14 교점 O 누락 수정과 별도 치수 보류

대상은 앞으로 생성하는 `2-2|평행선 사이의 선분의 길이의 비|10`이다. 발문은 두 대각선의 교점 O와 O를 지나는 EF를 쓰지만, 기존 도형은 대각선만 있고 O의 점·라벨이 없었다. 두 대각선은 이미 있으므로 더 추가하지 않는다. `diag` 갈래에서 반올림 전 좌표로 AC를 AD:BC로 나눈 점 O와 라벨 O만 추가했다. 공유 함수의 비대각선 `09`는 그대로다. 기존 출제·저장 문항, DB, 원본 자료는 수정하지 않았다.

변경 전 실제 handler의 두 갈래 × 원래 숫자쌍 10개와 `09` 공개 API 32개를 채집했다. 회귀 시험은 변경 전 O 누락으로 21실패·1통과, 변경 후 22개 통과였다. 실제 handler 20개와 공개 API seed 100개에서 O가 AC·BD·EF의 내부에 있음을 검사했다. 기존 좌표의 소수 둘째 자리 반올림을 고려한 선까지 거리 한도는 0.015 SVG 단위다. O 점·라벨을 제외한 모든 기존 필드와 두 번의 난수 호출 순서는 같으며, `09`의 전체 결과 32개는 직렬화 바이트가 같다. 새 계산 결과나 답 라벨은 추가하지 않았다. 관련 6파일 406개, TypeScript 3루트 오류 0, ESLint 3파일 오류·경고 0이 통과했다. 전체 프로젝트 검사라는 뜻은 아니다.

실제 공개 렌더 함수로 MathJax가 조판하는 명세 20개를 엄격 모드로 실행했다. 첫 갈래 10개는 통과했고, 둘째 갈래 10개는 주어진 EF의 치수선 `d_EF`를 놓지 못했다. 각 명세에서 O만 제거해 만든 변경 전 비교군도 정확히 같은 10개에서 같은 오류였다. 일반 표시 경로는 기존 계약에 따라 `droppedDimensions: ["d_EF"]`를 돌려준다. 그 그림 10개를 완전한 치수 표시나 출제 가능 상태로 승인하지 않는다. 이번 수정은 O 참조 누락만 해결하며 **둘째 갈래의 EF 치수 배치 보류를 유지한다**. 이 기존 충돌을 우회하려고 검사나 원본 오류를 삭제하지 않았다.

첫 갈래와 둘째 갈래에서 각각 두 PNG를 직접 확인했다. O는 두 대각선과 EF의 교점 위에 라벨로 보이고, 둘째 갈래의 EF 치수 누락도 확인했다. 픽셀은 수학적 정답의 근거가 아니다. 원래 독립 검수의 유리수 교점 계산은 10개 숫자쌍의 소스 이식 계산이며, 실제 TypeScript 호출로 세지 않는다. 현재 출력의 독립 후속 검수는 별도 진행 중이다.

어댑터 버전은 `20261021-named-diagonal-intersection-r1`이다. 기존 recipe의 출력을 조용히 바꾸거나 DB를 갱신하지 않는다. 학생 풀이·교육과정·Unit/live family·권리·유사성·실물 인쇄·저장 명세 재실행 승인은 이 참조 검사와 별도다. 새 문항 저작·독립 학생 풀이·최종 승인·운영 적재 수는 모두 추가하지 않는다.
