# P1b 연산 그림 자료 분리

기준은 로컬 `main`과 작업 브랜치가 가리키던 `c065d613d`다. `e4c80d746`에서 기준 출력과 번들 검사를 먼저 남겼고, `f12f90200`에서 준비 경계를 연결했다. 공유 DB와 유료 API는 사용하지 않았다.

## 소비자와 데이터 경계

| 소비자 | 준비 방식 |
| --- | --- |
| 교사 작업대의 생성·검토·부분 재생성·저장본 열기 | `ArithmeticGeneratedWorkflow`가 현재 시험지에서 참조할 그림 계열을 준비하고 기존 동기 투영을 실행한다. 지연·실패 중에는 출력 화면과 저장 동작이 없으며, 재시도하면 필요한 계열만 다시 요청한다. |
| 유형 예시와 관리 미리보기 | 유형 예시는 현재 툴팁의 문항에 필요한 계열을 받는다. 다른 유형으로 전환하면 이전 응답이 현재 화면을 갱신하지 못한다. `AdminArithmeticPreview`는 저장본을 검증한 뒤 해당 시험지의 계열이 준비되면 공용 지면을 렌더한다. |
| `WorksheetEditor` · `WorksheetPrint` · `ProblemMeta` | 작업대가 만든 `StudioProblem[]`을 받는다. 표시 SVG가 준비된 뒤 편집기가 열리고, 실제 인쇄 버튼은 기존 페이지 측정까지 기다린다. 교사용 브라우저 인쇄·PDF·HWPX는 이 지면에서 시작한다. |
| `/dev/arithmetic/grade-print` · `GradeArithmeticPaper` | 서버 페이지는 파일 추적에 등록된 JSON을 필요한 시점에 동기로 읽고 `GradeArithmeticPaper`에 표시 문제를 전달한다. 파일이 빠지면 인쇄 요청이 실패한다. |
| 자료 제공 | 교사와 최고관리자는 `/api/arithmetic/v2/packs`를 쓴다. `/dev/arithmetic` 예시는 이전과 같은 검수 권한으로 `/dev/arithmetic/packs`를 쓴다. 두 경로가 파일 추적에 등록돼 있으며 확인된 pack 이름과 계열 하나를 반환한다. |

압축 JSON 여섯 개는 그대로 배포 데이터에 싣는다. 각도 pack은 기존 단일 압축 단위로, 나머지는 기존 계열·인라인 청크 구조로 읽는다. 조판용 3.2 KiB 사전은 정적 데이터로 유지했다. 각 계열의 지연 디코딩과 LRU 상한, 저장 canonical SVG 대조, ID와 저장 스냅샷은 기존 동작을 유지한다. 저작 파일의 계열이 바뀌면 `node scripts/qa/update-arithmetic-pack-index.mjs`로 인덱스를 갱신한다. `--check`로 일치 여부를 확인할 수 있다.

Mac 로컬에서 `.next`를 임시 디렉터리로 옮겨 냉간 상태로 만들고 `/usr/bin/time -l node scripts/deploy/build-next.mjs`를 실행했다. 전후 모두 P0.1의 소스맵·파일 캐시 비활성화 및 빌드 전 분리 타입 검사를 적용했다.

Chrome 시간은 서로 다른 새 브라우저에서 고정 시드로 3회 반복한 중앙값이다. 작업대 표본은 피타고라스 유형을 담았고, 새 경로의 두 계열 요청 전송량은 합계 5,796 B였다. Grade-print는 `m2-right-triangle-height` 5문항을 인쇄했다. 이미지 5개의 SVG 및 치수, 본문, 인쇄 매체의 이미지 위치·크기 해시가 세 번 모두 일치했다. Chrome이 만든 PDF 크기도 254,936 B로 일치했다. 빌드 시간과 RSS는 단일 Mac 실측이다. 동시 작업과 서버 프로세스 캐시 상태를 통제한 성능 시험은 별도로 남아 있다.

분리 전후 모두 선분 계열 네 개를 첫 접근할 때 4회 디코딩했고, 캐시에 남은 계열을 다시 읽을 때 추가 디코딩은 0회였다. 다섯째 계열을 열 때 1회, 밀려난 계열을 다시 열 때 1회였다. 전체 카탈로그의 브라우저 준비 시험에서 중복 준비는 계열당 한 요청으로 합쳤고, 준비 완료 후 같은 자료의 추가 요청은 0회였다.

## RED와 회귀 검증

- `node scripts/qa/check-arithmetic-pack-bundles.mjs`는 기준 빌드의 SSR 청크 2개와 브라우저 청크 1개를 검출했고 전환 후 통과했다. 브라우저 청크에 선분 계열 하나를 삽입하거나 grade-print 추적에서 원본 하나를 빼면 각각 실패했다. 정상 산출물은 두 경로 처리기와 grade-print 추적에서 각 pack 파일을 확인했다.
- 기준 커밋에서 737개 카탈로그 유형의 seeded 표시 SVG·치수·본문 줄바꿈·정답·문항 ID·스냅샷 투영을 해시로 기록했다. 파일 기반 Node와 브라우저 자료 준비 경로가 모두 `0f476b4a116324c070e44b1363233aca6a4c73c92df69d00c1e9ab933d9fc1e9`을 재현했다.
- 준비 여부를 항상 참으로 바꾸자 관리자·worksheet·유형 예시 시험 3개가 실패했다. 응답의 계열 대조를 빼자 관리자 오류 시험이 실패했다. 파일 누락 오류를 기존 배치 실패 처리에서 삼키게 하자 grade-print의 실패 응답 시험이 실패했다. 변이를 제거한 뒤 모두 통과했다.
- 실제 Chrome에서 작업대의 두 요청을 지연한 뒤 503으로 응답시켜 출력이 잠기고 오류가 표시되는 것을 확인했다. 재시도 후 실제 검토 화면이 열렸고, 도형 문항 부분 재생성은 추가 자료 요청 없이 끝났으며 worksheet 인쇄 동작은 한 번 실행됐다. 저장·열기와 관리 미리보기는 인메모리 통합 시험으로 검증했다.
- Vitest의 연산·worksheet·보관함·권한·문제 렌더링 관련 91개 파일, 4,137개 시험이 통과했다. `npm run type-check`, `npm run lint:affordance`, 변경 TS/TSX/MJS 파일의 ESLint, pack 인덱스 검사를 통과했다.

## 남은 위험과 원장님 확인

- 저장 브랜치 전체 ESLint는 기존 위반으로 실패한다. 기준 `c065d613d`의 추적 파일 사본에서 오류 275건과 경고 94건을 재현했다. 전역 라우트 오류 기록 검사도 기존 개념 백지·온톨로지 경로에서 2개 실패한다. 새 연산 경로의 범위를 넘어 이 항목을 수정하지 않았다.
- 필터 없는 `/dev/arithmetic/grade-print`는 기준과 P1b에서 모두 500을 반환한다. 기본 요청의 737개 유형이 회차당 200개 제약을 넘는다. 한 유형을 고른 인쇄는 양쪽에서 200이었다. 전체 학년을 한 번에 출력하는 검수 용도가 있으면 별도 작업에서 회차로 나눌지 확인이 필요하다.
- 이미 준비한 계열은 같은 탭에서 재사용한다. 새 탭에서 처음 여는 계열은 연결이 필요하다. 가장 큰 개별 인라인 계열 응답은 약 3.17 MB이며, 많은 계열을 섞은 시험지는 계열별 요청을 여러 건 보낸다. 운영 연결과 저사양 단말에서의 체감은 아직 측정하지 않았다. 원장님이 오프라인에서 아직 열지 않은 단원의 인쇄도 사용하시는지 확인하고 싶다.
- 기존 인쇄 템플릿과 CSS로 Chrome 인쇄 매체와 PDF를 검증했다. 물리 프린터 확인은 남아 있다.
