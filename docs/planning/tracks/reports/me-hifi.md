## 4. 이번 회차에 고친 것 (그림을 보고 찾았다)

1. **«새로고침» 단추가 단추로 안 보였다** — 구역 머리가 `.dashboard` 밖이라 [CD] `.button` 고른 이가 안 닿아, 테두리 없는 굵은 글자로 그려졌고 폰에서는 «새로 / 고침» 두 줄로 꺾였다.
   → 고른 이를 `:is(.dashboard, .sectionHeading) .button` 으로 넓혔다(제품은 머리가 `.dashboard` 안이다). 첫 화면 그림 열 장 · `empty` 가 바뀌었다.
2. **칸 모양(H2 · H4)의 운영 확인 줄이 네 줄** — 목록이 좁아지면(PC 에서 오른쪽 칸이 선 때 · 폰) «시작 전» 딱지가 줄 폭을 다 먹고, 값 · 자리가 따로 꺾이고, 계정 확인 링크가 맨 아래로 갔다
   (앞 그림 `H2-1280-open` · `H4-1280-open` 의 한유나 · 안채원 · 홍지안). → 학습 개입 줄과 같은 묶음(`x-rsn`)으로 감싸 딱지 · 값 · 자리가 한 줄로 흐르고, 링크는 이름 줄 오른쪽에 선다.
   넓을 때 끝 칸을 108px 고정에서 `auto` 로 — «반 관리에서 계정 확인 →»가 108px 칸을 넘어 목록 상자에 잘릴 자리였다(딱지 · 값 칸은 안쪽 격자가 왼쪽부터 맞춰 그대로 줄을 선다).
3. **운영 확인 이름이 아무 일도 안 하는 단추**였다 — 손가락 커서와 hover 면이 있는데 누르면 열 것이 없다(D-30). → 글자로 바꾸고 자리 · 줄 높이(1.4)를 이름 단추와 같게(두 줄 다 67.8px).
4. **오른쪽 칸 안(H2 · H4 · H5)의 줄 단추가 폰에서 거짓말** — 폰에서는 줄 안에서 펼치는데 «기록 보기 >»였고 펼친 뒤에도 같은 글이었다. → 본문이 960px 보다 좁으면 «펼치기 ∨ / 접기 ∧»(H1 · H3 와 같은 말). PC 는 그대로 «기록 보기 >».
5. **안내 쪽(제품 화면 아님) 가로 넘침 1302px** — 1280 액자의 iframe 이 격자 칸을 1280 으로 밀었다. → `grid-template-columns: minmax(0, 1fr)`. 안내 쪽 «좋은 점 · 걸리는 점» 글 셋도 잰 값에 맞췄다(H3 «일곱 명이 다 선다» → 실제 여섯 등).

**다시 찍은 그림 16장**: 첫 화면 열 장 · `H2/H4-1280-open` · `H2/H4/H5-390-open` · `empty-1280`.
**그대로 둔 6장**: `entry-1280` · `H1-1280-open` · `H1-390-open` · `H3-1280-open` · `H3-390-open` · `H5-1280-open` — 새로 뜬 것과 견주면 다른 픽셀이 32~122개뿐(글자 가장자리 앤티에일리어싱. 앞 작업자의 렌더러가 달랐던 것으로 보인다)이라 내용이 같다.

## 5. 수치 — Playwright 로 잰 것

재는 법: 그림과 같은 창(1280 × 900 · 390 × 844, deviceScaleFactor 1), Playwright 1.62.1 + 이미 깔린 Chromium 헤드리스 셸 1223(`executablePath` — 1.62.1 이 찾는 1234 는 없어서 내려받지 않았다), 브라우저 하나, 글꼴 로드 뒤.
«보이는 학생» = 학습 개입 줄의 이름 글자(`.studentIdentity > strong`) 상자가 **윗줄 아래 ~ 화면 바닥(폰은 고정된 아래 메뉴 위, y 777)** 안에 **통째로** 든 것. 반쯤 걸린 이름은 세지 않았다(다섯 안 모두 반쯤 걸린 이름 0).
«블록 높이» = 닫힌 학생 줄(`.x-line`)의 높이(px, 줄 사이 선 1px 제외).

## 6. 그림을 보고 걸린 것 — 고치지 않고 판단 재료로 남김

- **H5 의 폰 네 줄**(류하은) — 브리프 «네 줄은 안 된다»에 표본이 걸렸다. 고치려면 카드 이름을 곁 줄로 옮기거나 문장을 줄이는 것이라 안의 결(곁 정보를 펼치지 않고 보인다)을 바꾼다 — 그래서 고치지 않고 적는다.
- **390 에서 14장을 펼치면 다섯 안 모두 다음 학생이 화면 밖**이다. 단원별 묶음(H3 · H4 — 755 · 768px)이 표(H1 · H2 · H5 — 1155~1172px)의 3분의 2. 폰에서 «다음 이름이 남는가»를 지키려면 펼친 칸 자체를 줄이는 결정(예: 단원별 묶음 + 세션 접기)이 따로 필요하다.
- **칸 모양(H2 · H4)은 PC 에서 오른쪽 칸이 서 있는 동안 칸이 아니다** — 목록이 좁아져 딱지 · 값 · 자리가 쌓인 모양으로 풀린다. «값이 세로로 줄을 서서 견주기 쉽다»는 오른쪽 칸이 닫혀 있을 때만이다.
- **빈 상태에도 홍지안의 기록 사유 딱지가 남는다**(«학습 개입 0명» 아래 운영 확인 줄에 «복습 밀림 5장 · 12일»). 합의 8다 규칙 그대로지만 «0명»과 같이 읽히면 헷갈릴 수 있다.
- **«모은 카드 15 / 230»** — 빗금 꼴이 남은 유일한 자리(숫자 줄). 230 이 날짜로 읽힐 일은 없어 두었지만, 문장 쪽과 맞추려면 «230장 중 15장».

## 6.1 의견 (참고로만 — 고르는 것은 3자 눈검수)

수치만으로는 **H3** 이 가장 고르다(1280 여섯 · 390 하나 · 두 줄 67.8 / 87px · 1280 펼침 뒤 다음 학생 남음 · 폰 펼침이 가장 짧은 쪽). 칸 모양을 원하면 같은 뼈대의 **H4**.
