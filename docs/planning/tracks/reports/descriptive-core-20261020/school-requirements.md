# 중학 1학기 서술형 요구 독립 조사 — 2026-10-20

**결론:** 원장 중 파일명으로 학년·1학기를 확정한 서술형은 **3,040행·737편**이다. 중1 1,092행, 중2 1,001행, 중3 947행. 시험지 연결 메타데이터로 추가 87행을 식별하면 3,127행·758편이다. 배점은 확인 가능한 3,036행 중 2,893행(95.3%)이 4~12점이다. 아래 첫 후보 10개는 중1 3개·중2 3개·중3 4개로 제안하며, 부모가 지정한 연립 직사각형 시연을 C05에 포함한다.

**구조 의견:** 학교 시험의 추상 요구와 가족을 관리하는 `examStudy`를 요구의 기준으로 삼고, 서술형 저자·계약이 이를 연결하는 방향이 타당하다. 다만 기존 50개 ID는 매우 구체적이다. “연립식이 있다”는 이유만으로 직사각형 모델을 `written.two-work-rates`로 매핑하면 다른 과제가 된다. 정확히 맞지 않는 것은 새 요구 후보로 표시했으며 등록부·계약은 변경하지 않았다. 이 보고서는 구현 구조 확정이나 `full` 승격 증거를 대신하지 않는다.

읽은 기준: 부모 `docs/planning/tracks/brief-descriptive-core-codex.md`, 정본 `docs/planning/descriptive-engine-middle-20261020.md`의 마지막 합의안, `math-exam-engine-upgrade-20261018.md`, `requirements.ts`, 계약과 중등 생성기. 상위 브리프의 2027년 1학기 결정이 이전 2학기 도형 후보보다 우선한다. 1학기 대수에 붙는 도형 모델 C05·C06·C09는 포함하되 중2 2학기 도형 증명은 포함하지 않았다.

## 1. 자료·재현·분모

- 입력: `scripts/import/ledgers/legacy-corpus-delete.json.gz`, 1회차. 삭제 원장의 파일만 읽었고 DB에 접근하지 않았다.
- 원장 SHA-256: `5de3c92f1245b2ed827e7b743f32c2b884c5c73a2674e251a6dd887d9891dde5`.
- 독립 작업트리와 부모의 원장·`requirements.ts`·계약·`middle/generate.ts` 내용이 동일함을 해시로 확인했다.
- 전 학기 모집단: `source=past_exam`, `subject=수학`, `school`이 `중`으로 끝남, `questionType=서술형`인 4,033행. `problemType`으로 대체하지 않는다.
- 주 분석: 파일명 패턴 `\[([123])\]\[(\d{2,4})-([12])(?:-|\])`로 학년·연도·학기를 읽고 학기 1만 취한다. 2023~2025년 자료이므로 2027 교육과정의 대표 표본으로 간주하지 않는다.
- 파일명 미판독 94행은 `examQuestion.problemId → examQuestion.examId → exam.id`로 모두 판독 가능했다. 그중 1학기 87행은 확장 집계에만 넣는다. `problem.examId`는 `exam.id`나 `externalExamId`에 직접 붙지 않으므로 직접 조인하지 않는다. 파일명과 연결 메타데이터의 학년·연도·학기 충돌은 0행이다.
- 4,033행 중 `examQuestion` 연결 4,008행, 복수 연결 4행, 문항형식 불일치 19행. 모집단은 원래 `problem.questionType`으로 고정했다.
- 배점: `problem.score`를 우선하되 비어 있으면 연결된 `examQuestion.score`의 일치값으로 보충한다. 양쪽이 충돌하거나 연결 배점이 복수이면 미확정으로 남긴다. 주 분석은 보충 513행, 충돌 4행(중3, 1편). 임의 평균·덮어쓰기 없음.
- 문항수는 저장 행 수다. 소문항으로 행을 쪼개지 않는다. 편수는 `sourceFile` 고유값이며 학교·학년·연도·학기·중간/기말로 묶은 편수도 주 분석에서는 같았다.
- 공백을 제거한 본문 지문으로 정확 중복을 집계하면 4행이 중복 초과분이다(고유 본문 3,036). 수치가 달라진 유사 문항이나 그림의 중복까지 판별한 것은 아니다.

- 방정식·부등식·함수의 과도하게 복잡한 활용을 피한다. 기존 고난도 요구가 등록되어 있다는 사실은 2027 학교 범위 적합성의 인증이 아니다.

## 8. 확인한 구현 자산과 남은 일

- 부모 환경의 `registeredTypes()`를 실제 호출해 **1,517개**, `STUDY_REQUIREMENTS`를 호출해 **50개**를 확인했다. 서술형 요구 또는 1학기 지원 수가 1,517개라는 뜻은 아니다.
- 후보 10개 키를 등록부에서 찾고 각 seed `1, 17, 2027`로 handler를 실행했다. 최종 후보 기준 **30회 생성 성공**. 수치·문장 출력은 하지 않았고 `figureSpec.kind`와 facts 필드 이름만 확인했다. 이는 G3 독립 검산이나 모든 갈래 검증이 아니다.
- 확인 파일: C01 `m1Num.ts:1120`, C02 `m1Calc.ts:594`, C03 `m1LinearApply.ts:696`, C04 `m2IneqApply.ts:392`, C05 `m2System.ts:1558`, C06 `m2Line.ts:1061`, C07 `m3Root.ts:668`, C08 `m3Poly.ts:1586`, C09 `m3Quad.ts:2166`, C10 `m3Func.ts:1623` (`src/lib/middle/` 기준).
- C05의 facts는 width/height/perimeter/difference/answer이고 기존 정답은 세로다. 넓이·소거 증거는 부모 저자의 새 요구이며, 계산 엔진의 단답 결과가 이미 서술형이라는 뜻은 아니다. G3는 조립된 발문·그림으로 이 추가 중간량까지 확인해야 한다.
- C06만 기존 그림 명세 `linearGraph`를 반환한다. 나머지 9개는 null/없음이다. 그래프·도형의 실제 렌더·지면·라벨 시각 검수는 이 조사에서 수행하지 않았다. `figure`가 있는 원장 행 639개 역시 자산 존재 신호이지 그림이 정상이라는 판정이 아니다.
- 원장 집계의 분모·형식 합계·소문항 표지 합계·배점 합계 assertion을 통과했다. 같은 입력으로 재실행해 동일 집계가 재현됨을 확인했다. 저장소 변경이 없는 조사라 전체 회귀는 실행하지 않았다.

정본 합의 중 아직 완료를 주장하지 않는 일: 학교·연도·중복을 고려한 약 200행의 **사람 판독 층화 검증**, 학교 답안지 12~20건 대조, 세부 요구별 원장 전수 주석, 각 후보의 최종 발문·문지기 검증, 교사 실제 답안 채점 일치도·시간, 학교별 2027 범위 확인. 따라서 10개 정의의 기출 커버리지나 측정 학습 효과 수치를 제시하지 않는다.
