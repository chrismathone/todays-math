# 검수 근거 형식과 답 형식 메타데이터 관문

실제 16번 독립 검토가 일곱 학년 면을 모두 통과로 기록했지만, 객체의 근거를 `reason`에만 넣어 기존 집계기가 학년 0으로 처리했다. 원래 보고서·집계 결과를 보존하고 별도 보고서에서 각 면의 `basis`·`evidence`를 작성했다. 생성되는 `VERIFY-BRIEF.md`도 객체 형식을 명확히 안내하도록 수정했다. 학년 근거 검사나 원시 풀이·보고서 바이트를 느슨하게 고치지 않았다. 기존 문자열 상태를 읽는 호환성은 유지하되 그 경우에도 각 면의 실제 판단 근거가 필요함을 안내한다.

18번 서술형에는 저자 초안에서 복사한 `answerFormat=single-choice`가 남아 있었다. 새 메타데이터 버전에서 본문·답·해설·배점·rubric과 학생 digest를 보존하며 `scalar-with-working`으로 보정했고, 현재 후보 digest에 연결하는 새 독립 보고서를 요구했다. 새 문제나 새 blind 풀이로 세지 않는다.

이 재발을 막기 위해 후보 검사는 비객관식에 남은 알려진 객관식 답 형식 두 값(`single-choice`, `single circled choice`)을 별도 메타데이터 불일치로 표시한다. 역사적 초안의 읽기와 실제 수학·학년 증거는 유지하고, 내용·분류 통과 집계는 이 불일치를 자동 보류한다. 보고서가 verified이고 기존 12개 검사가 true여도 이를 통과 수로 늘리지 못한다. 임의의 자유 서술 답 형식을 모두 이해하는 의미 검증기는 아니며 미기재 값·새 형식의 적절성은 별도 검토 대상이다.

기존 TypeSafe 스킬과 [현재 문서](https://docs.typesafe.ai/llms.txt), [근거 대조 패턴](https://docs.typesafe.ai/cookbooks/citation_check)을 확인했다. 이번 변경은 확률이나 AI 판정으로 학년을 승인하는 통합이 아니라, 실제 검토 결과를 현재 근거에 묶는 결정적 계약·집계 코드와 안내다. 새 API·유료 호출·의존성 설치가 없다.

관련 Node 검사 9파일의 최신 결과는 **122통과 / 실패·건너뜀 0**이다. 앞선 근거 형식 검사 120통과 실행과 이후 메타데이터 회귀검사 두 개를 추가한 실행을 각각 보존하며 242개로 합산하지 않는다. 합성 제어에서는 `reason`만 있는 학년 객체가 학년 수를 늘리지 못함, 명시적인 `basis` 또는 `evidence`를 넣으면 실제 수학 증거를 유지하며 읽힘, 객관식 답 형식이 남은 서술형은 수학·학년 1이어도 내용·분류 0임을 확인했다. 고친 답 형식의 새 현재 후보는 같은 통제 조건에서 정상 분류되며, 권리·출처·native 적재 승인은 양쪽 모두 0이다.

이는 오프라인 검수 도구 변경이며 운영 DB 쓰기·배포·feature의 main 병합이나 기존 82행의 잠금 해제가 아니다. 그림의 픽셀·해시가 계산 또는 학년 판단을 대신하지 않는다.
