## 1. 물음 ② — 모집단이 둘인가

### 1.1 답: **엔진 경로는 하나다.** 그러나 «시각»이 둘이고, 판정기가 못 보는 세 번째 경로가 있다

초등은 `generateElementaryProblem`(갈래)와 `generateElementaryForm`(문형) **둘**이었고
적재기가 부르는 것은 문형인데 판정기는 갈래를 재고 있었다(g5 §1). 중등은 다르다 —
**적재기와 판정기가 같은 함수를 부른다.**

| 경로 | 부르는 함수 | 누가 쓰나 |
|------|------------|----------|
| 유형 | `generateMiddleProblem(key, seed, variant)` | 적재기 `load-engine-problems.ts:256` **그리고** 중등 판정기 전부 |
| 결합형 | `generateMiddleComboProblem(comboId, …)` (`src/lib/middle/combo.ts:547`) | `/middle-gen` CLI(`scripts/middle/gen-cli.ts:226`)만. **적재기도 판정기도 안 본다** |

적재기는 `buildMiddleRows`(`:239`)에서 `typesForSection(...)`(`:240`)로 유형을 고르고
`generateMiddleProblem`(`:256`)을 부른다. 초등처럼 «문형»이라는 두 번째 축이 **없다.**
`expandFamily`(`src/lib/engine/expandEngine.ts:60`)가 그 산출을 형식 **2종**(단답·객관)으로
펼치지만 `difficulty` 는 그대로 복사된다(`load-engine-problems.ts:265`) —
**형식은 난이도 축이 아니다.**

### 1.2 🔴 걸린 것 ㉠ — 적재본이 **엔진보다 4유형 뒤**다 (측정)

적재 원장 다섯(`docs/planning/tracks/reports/engine-load-*.json`, **커밋된 파일**)에서
`engine-mid:` 행의 유형 키를 뽑아 지금 등록된 중2 유형과 대조했다:

| | 수 |
|---|---|
| 지금 등록된 중2 유형 | **572** |
| 적재 원장에 한 번이라도 나온 중2 유형 | **568** |
| **원장에 한 번도 안 나온 유형** | **4** |

```
2-2|여러 가지 사각형|29  등변사다리꼴의 넓이와 둘레        → 연산
2-2|여러 가지 사각형|30  등변사다리꼴의 두 대각선          → 기본
```

넷은 커밋 `baf77d87`「feat(중2): 등변사다리꼴 소단원을 8 → 12유형으로 — **연산 갈래가
통째로 비어 있었다**」가 더한 것이고, 마지막 중등 적재(2026-08-27~28)보다 **뒤**다.
즉 그 커밋이 고친 「연산 갈래가 비어 있다」는 **엔진에서만 고쳐졌고 지면에는 안 갔다.**
CLAUDE.md 2026-08-27·08-30 의 「엔진을 고친 것과 적재본을 고친 것은 다른 일이다」가
**세 번째**로 물린 자리다.

⚠️ 이 수치의 참은 **DB 가 아니라 커밋된 적재 원장**이다. 이 워크트리에 `.env` 가 없어
(`ls -a | grep '^\.env'` → `.env.example` 뿐) **DB 를 한 줄도 못 쟀다.** 원장에 없는데
DB 에 있을 수는 없지만(원장이 INSERT 보다 먼저 쓰인다), 원장에 있는데 DB 에서
지워졌을 수는 있다 — **그 방향은 못 봤다**(§5).

### 1.3 🔴 걸린 것 ㉡ — 결합형은 **어느 판정기도 안 본다**

`middleComboDefinitions()` 6건 중 중2 앵커 **3건**(위임 2 · 새 문형 1)이고 셋 다 **심화하**다
(씨앗 7 · 변형 3 · 9표본 전량). 위임 둘은 `generateMiddleProblem` 을 지나가므로 유형 경로와
같은 문항이지만, **새 문형 하나**는 `families` 안에서만 산다 —
`registeredTypes()` 에 없으므로 `probe-middle-*` 전부와 **이 계량기**가 구조적으로 못 본다.
지금은 1건이라 작지만, **결합형이 늘면 그만큼 판정 밖 지면이 늘어난다.**

### 1.4 난이도를 정하는 것이 무엇인가 (물음 ③, 코드 줄)

```
TypeEntry 에는 difficulty 가 없다                      src/lib/middle/types.ts:36-46

```

**핸들러가 정한다.** 표도 아니고 적재기도 아니다.

🔴 그리고 **브리프 ③ 의 전제가 절반만 맞다.** 「`resolveMiddleTier` 가 기본을 연산으로
내리기만 한다」는 참인데, **연산 갈래가 그 규칙에서만 오는 것이 아니다** — 측정:

```
중2 연산 표본 302 ─┬─ 규칙이 «기본»을 내린 것        122
                  └─ 핸들러가 «연산»을 직접 적은 것   180  (15유형)
```

직접 적는 15유형은 대개 `midSupB.ts` 의 `…A` 키다(`2-1|연립일차방정식|01A` 꼴).
그러므로 「등록값에 연산이 없다」는 말은 **지금 거짓**이고, `tier.ts` 머리말의
「중등 엔진은 세 칸(easy·mid·hard)이 전부라 연산 칸이 통째로 빈다」도 **낡았다**(§6).

그리고 난이도는 **유형의 성질이 아니라 문항의 성질**이다 — `resolveMiddleTier` 가
발문 모양을 보므로 같은 유형 키에서도 갈래가 갈린다. 측정으로 **3유형이 그렇다**:

```
2-1|단항식의 계산|01 · |02 · |04   → 연산 과 기본 이 섞여 나온다
```

유형 단위로 난이도를 세는 표는 이 3유형에서 조용히 어긋난다.

## 2. 물음 ① — 우리 꼭대기가 외부 눈금의 어디에 닿나

### 2.1 먼저 측정 — 6단에 댈 신호 Ⓐ~Ⓔ

`--sixgrade` (모집단 6,864 · 소단원 56):

|------|-----|

| Ⓑ 응용이 «지시 한 줄 + 식»뿐 | 52건 (1.8%) · 소단원 4/56 |
| Ⓒ **연산에 되짚기 마디가 둘 이상** (사다리 밑동이 이미 되짚는다) | 72건 (**23.8%**) · 소단원 6/56 |

| Ⓔ 정답이 값 여럿 | 전체 152건 (2.2%) · 연산 0% · 기본 2.0% · 응용 2.5% · 심화하 2.4% |

Ⓐ 의 열쇠는 **새로 짓지 않았다** — D-106 이 873유형 census 로 고른 `loneInstruction` +
`OPERATION_INSTRUCTION_WORDS` 를 그대로 이었다(`scripts/qa/tier4Rules.ts`).

**Ⓓ 에 걸린 2유형을 눈으로 봤다.**

* `2-1|일차부등식|03` **[기본]** 「$x$의 값이 $-2,-1,0,1,2$일 때 부등식의 해를 모두」
  → **거짓 양성.** 다섯 값을 대입해 보는 것이지 구조 탐색이 아니다.
* `2-2|피타고라스 정리|08` **[심화하]** 「세 변이 $5$, $12$, $x$인 삼각형이 둔각삼각형이
  되도록 하는 자연수 $x$를 모두」 → **참.** 삼각형 부등식과 둔각 조건 **두 범위를 겹쳐**
  좁힌 뒤 나열한다. 저쪽 눈금으로 **심화(하)~심화(중) 경계**다.

🔴 **Ⓓ 는 «답이 여럿»을 요구하므로 구조 탐색인데 답이 하나인 것을 못 본다.** 실제로
`2-2 경우의 수` 심화 셋(바둑판 최단 거리 · 동전 지불 방법의 수 · 네 부분 6색 칠하기)이
전부 구조 탐색인데 답이 수 하나라 **Ⓓ 가 구조적으로 침묵한다.** 그 0 은 «없다»가
아니다 — 아래 §2.2 의 경우의 수 줄은 그래서 **읽고 적은 것**이다.

### 2.3 배정 요약 — 초등의 답을 물려받지 않았다

| 우리 갈래 | 저쪽 6단에서 앉는 자리 | 꼭대기 |
|-----------|--------------------|--------|
| 연산 | **기본**, 그런데 2중단원에서 **실력(하)~실력(중)** 로 튄다 | 실력(중) |
| 기본 | **개념 ~ 실력(중)** — 폭이 가장 넓다 | 실력(중) |
| 응용 | **기본 ~ 심화(하)** — 이것도 넓다 | 심화(하) |
| 심화하 | **실력(중) ~ 심화(중) 경계** | **심화(하), 두 자리에서 심화(중) 경계** |

🔴 **초등의 답(우리 심화 = 저쪽 실력(중))을 그대로 옮기면 틀린다.**
중2 심화하의 꼭대기는 **초5보다 한 칸 위**다 — 초5 에서는 저쪽 심화(중) 표지가
**9,408건에 진짜 0** 이었는데, 중2 에서는 **경계에 닿는 문형이 실제로 있다**:

* `2-2|피타고라스 정리|08` 「둔각삼각형이 되도록 하는 자연수 $x$를 모두」 (Ⓓ 가 잡았다)
* `2-2|경우의 수` 「A→P→B 바둑판 최단 거리」 · 「동전으로 $n$원을 지불하는 방법의 수」
  · 「이웃한 부분에 다른 색, 6색으로 네 부분 칠하기」 (Ⓓ 가 못 본다 — 답이 하나다)

**그러나 그 넷은 전부 «경우의 수·피타고라스» 두 중단원에 있다.** 나머지 18중단원의
심화하는 **심화(하) 아래**이고, 그중 **5중단원은 심화가 응용과 같은 자리**다(위 표).

⚠️ **문형 «직접 대응»은 못 했다.** 브리프가 요구한 「저쪽이 실력(중)에 두는 문형이
우리에게는 심화더라」식 대조는 **저쪽 화면을 봐야** 성립하는데, 로그인 전이라
접속하지 않았다(§5). 위 배정은 **잣대만** 물려받아 우리 지면에 댄 것이다.

   **등록값에 확대 갈래가 없다**」는 «연산» 쪽에서는 이미 낡았다(§1.4).

## 7. 내가 확신하지 못하는 것 셋

1. 🔴 **§3 의 「되짚기 축이 안 선다」가 셋 중 어느 것인지 못 갈랐다** —
   ㉠ **축이 없다**(중2 심화는 되짚기로 안 만들어진다) ㉡ **내 검출기가 못 본다**
   (「기호 = 수」는 **굳은 결과만** 보는 열쇠라, D-115 가 심화중·심화상을 가르는 데
   쓰는 **«굳지 않는 마디»** 는 지면에 자국이 없어 구조적으로 못 본다)
   ㉢ **라벨이 안 가른다**(응용·심화하가 RPM 사람 주석이라 그 둘이 원래 가깝다).
   ㉡ 을 줄이려고 낱개 열쇠 13개로 쪼갰고(§3.3) 눈금이 실제로 검출기 결함을 두 번
   잡았지만(§0), 셋을 **가르는 실험을 못 만들었다.** 내가 잰 것은 「되짚기가 몇 번
   있나」이지 「되짚기가 얼마나 어려운가」가 아니다.

2. **§2.2 의 6단 배정.** 저쪽 화면을 못 봤으므로 잣대만 옮겨 댄 것이고, 특히
   「중2 심화하의 꼭대기가 초5보다 한 칸 위」라는 결론은 **문형 넷**(피타고라스 1 ·
   경우의 수 3)에 기대고 있다. 저쪽 중2 심화(중)이 그보다 훨씬 위일 수 있고, 그러면
   **초등과 같은 결론**(우리 꼭대기 = 저쪽 실력(중))이 될 수도 있다.

3. **§4.2 의 「연산이 35소단원에 없다」가 결함인지 성질인지.** 「일차함수 그래프의
   연산 갈래」·「삼각형 외심의 연산 갈래」가 **성립하는 개념인지** 나는 모른다.
   초등에서는 연산이 「그 소단원의 계산을 그대로 한 번」이라 늘 성립했는데, 중등
   기하에는 그런 자리가 없을 수 있다. 있다면 결함이고 없다면 **하위반 프리셋 쪽이
   틀린 것**인데, 그 판단은 이 조사 밖이다.
