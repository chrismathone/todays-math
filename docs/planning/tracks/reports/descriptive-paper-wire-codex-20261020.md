## 1. 비교할 수 있는 것

같은 자작 7문항을 모든 안에 같은 번호·문장·수치·그림으로 사용했다. 객관식 2개, 단답 2개, 통서술형 문5, ⑴⑵⑶ 소문항 문6, 도형 설명 문7이다. 서술형만 **6·8·6점**, 합계 20점을 표시한다.

상단의 A~E 버튼, 일일·확인·기출형 버튼, 학생용·교사용 버튼으로 전환한다. E안에는 **소문항별 분할 / 큰 칸 하나** 전환이 있다. 현재 선택한 학생용 또는 교사용만 인쇄한다.

| 안  | 한 줄 설명                                            | 배점 위치 / 답란 | 약점                                                                  |
| --- | ----------------------------------------------------- | ---------------- | --------------------------------------------------------------------- |
| A   | 문제 바로 아래에서 풀이와 답을 쓴다.                  | 번호 옆 / 줄     | 기출형은 서술형이 두 쪽에 흩어지고 좁은 단의 풀이 공간 제약이 남는다. |
| B   | 같은 묶음의 마지막 쪽에 서술형 답란을 모은다.         | 문항 끝 / 모눈   | 문제와 답란을 번갈아 찾아야 한다.                                     |
| C   | 문제지를 유지하고 별도 답안지 한 장을 배부한다.       | 답란 머리 / 빈칸 | 일일·확인은 한 쪽이 늘고 답안지를 따로 관리해야 한다.                 |
| D   | 일반 문항은 두 단, 뒤쪽 서술형은 전폭으로 배치한다.   | 답란 머리 / 줄   | 일일·확인의 일반 문항 풀이 공간이 줄고 기출형은 한 쪽이 늘어난다.     |
| E   | 문6을 ⑴⑵⑶ 칸으로 나누고 같은 높이의 큰 칸과 비교한다. | 번호 옆 / 모눈   | 긴 풀이가 다른 소문항의 빈 공간을 이용할 수 없다.                     |

답란은 이 고정 예시에서 **기준 3개 × 기준당 2줄 × 줄 높이 8mm = 48mm**다. E의 세 소문항 칸은 각각 16mm다. 배점에 비례해 공간을 나누지 않았으며, 엔진의 확정 높이 규칙이나 손풀이 공간의 충분성 검증을 뜻하지 않는다.

교사용은 각 안·지면 종류마다 한 쪽이다. 모범풀이, 기준별 배점, 만점·부분·0점 선택용 □, 문항 소계, 서술형 합계를 포함한다. 앞 단계의 수치 오류를 일관되게 이어 푼 경우와 동등한 풀이의 인정 원칙도 표시했다. 채점표는 종이에 기록하는 시안이며 자동 채점 기능은 없다.

## 2. 실제 PDF 쪽 수

표의 `문제 + 답안 = 합계`는 학생에게 배부하는 **쪽** 수다. 양면 인쇄의 종이 장수는 아니다. 교사용은 모든 조합에 별도로 **1쪽**이다.

| 안  |               일일 |               확인 |             기출형 |
| --- | -----------------: | -----------------: | -----------------: |
| A   |  4 + 0 = **4** (0) |  4 + 0 = **4** (0) |  2 + 0 = **2** (0) |
| B   |  3 + 1 = **4** (0) |  3 + 1 = **4** (0) |  1 + 1 = **2** (0) |
| C   | 4 + 1 = **5** (+1) | 4 + 1 = **5** (+1) |  1 + 1 = **2** (0) |
| D   | 3 + 0 = **3** (−1) | 3 + 0 = **3** (−1) | 3 + 0 = **3** (+1) |
| E   |  4 + 0 = **4** (0) |  4 + 0 = **4** (0) |  1 + 1 = **2** (0) |

괄호는 비교 기준 대비 증감이다. 일일·확인은 현행 장당 두 문항 구조로 이 예시를 배치한 4쪽, 기출형은 **문제지 1쪽 + 미구현 별도 답안지의 Wire 1쪽 = 2쪽**을 기준으로 삼았다. 기출형의 현행 제품이 답안지를 이미 출력한다는 뜻이 아니다. B는 마지막 답란을 같은 묶음으로, C와 기출형 E는 별도 배부로 구분한다.

쪽 나눔은 7문항을 비교하기 위한 명시적 배치다. 실제 제품의 자동 측정·페이지 분할 결과나 모든 길이의 문항에 대한 쪽 수를 주장하지 않는다.

## 3. 현행 제품과의 관계

앞선 [소스 검토](descriptive-paper-wire-codex-20261020/source-review.md)와 현재 연결부를 대조했다.

- **일일·확인은 같은 `JaseupTemplate` 경로**다. 머리말·첫 장 개념 상자·문항과 풀이 공간의 구조를 흑백으로 옮겼다. 다른 제품 양식인 `PyeonggaTemplate`을 확인테스트로 간주하지 않았다.
- **기출형은 명시적인 두 단과 문항 띠**를 기준으로 했다. B·C·E는 문제지에 답란을 두지 않는다. A·D의 서술형 답란 통합은 D-119와 다른 비교 제안임을 화면에 표시했다.
- 일일·확인의 배점 없음 원칙에 대한 **서술형만의 예외**를 반영했다. 기출형도 이번 브리프에 맞춰 서술형에만 배점을 표시했다. 현행 제품의 일반 문항 배점 정책을 바꾼 것은 아니다.
- 흑백 Wire용 CSS와 A4 치수는 해당 `/dev` 경로 안에만 있다. 공용 인쇄 템플릿·토큰·측정 규칙·워크스페이스 셸을 수정하지 않았다.
- 페이지는 로컬 고정 데이터와 브라우저 상태만 사용한다. API·DB·인증 정보가 필요하지 않다. 개발용 Next 서버는 페이지를 제공하는 데 사용하며 별도 업무 서버는 없다. production의 `notFound()` 가드는 소스에서 확인했고 production 빌드·배포는 수행하지 않았다.

## 4. 중단 지점 이후 처리

재개 시 시안 코드, QA 스크립트, 캡처와 PDF, 두 검토 문서가 미추적 상태로 남아 있었고 이 최종 보고서는 없었다. 기존 파일을 보존하고 아래를 마무리했다.

1. 기출형에도 일반 문항의 `내 정답` 칸이 출력되는 문제를 발견해 제거했다. 기출형 일반 문항의 풀이 공간도 렌더하지 않도록 제한했다. QA에 일반 답란은 일일·확인에서만 존재한다는 검사를 추가했다.
2. [앞선 수학 검토](descriptive-paper-wire-codex-20261020/math-review.md)의 지적과 최종 코드를 대조했다. 문5의 각 항 설명, 문7의 과정 요구와 부분점수 경계, AB 전체를 가리키는 8cm 치수선, 선행 오류 예시는 이미 보완되어 있었다.
3. 문5에서 잘못 구한 가격을 대입해 **총액 불일치를 정확히 확인해도 검산 1점**임을 교사용에 보충했다. 뒤 단계에서 새 계산 오류를 낸 경우까지 인정하는 문구는 아니다.
4. 교사용 하단 채점 안내·합계도 푸터 충돌 검사에 포함하고, 측정 결과에 실행 시각을 남겼다.
5. 현재 코드로 전체 화면·PDF 검증과 캡처를 다시 만들고 이 보고서를 작성했다. 기존 검토 문서는 검토 당시의 이력으로 보존한다.

예시 계산은 문1~4가 ③·②·5·1, 문5가 2,900원, 문6이 3·11·6, 문7이 AD=DB=4cm·같은 높이 6cm·전체 넓이 24cm²로 일치한다. 고정 예시 검토를 생성 엔진 전체나 교육과정 정합성 승인으로 확대하지 않는다.

전체 검증에는 이미 열려 있던 이 작업트리의 `127.0.0.1:3034` 개발 서버를 재사용했다. 최종 접속 확인에서 이전 실행의 로그 파이프가 끊긴 `EPIPE`를 발견해 같은 작업트리·포트로 서버를 다시 시작했다. 재시작 로그는 `tmp/descriptive-paper-wire-dev.log`에 남긴다. 서버를 새로 열어야 하면 심볼릭 링크로 연결된 의존성을 그대로 사용해 다음 명령을 실행한다.

재시작 후 **HTTP 200**과 [1040px 30조합 재검증](descriptive-paper-wire-codex-20261020/quick-measurements.json)을 확인했다. 이 재검증도 API·외부 요청과 브라우저 오류가 0건이다.

```sh
node node_modules/next/dist/bin/next dev --webpack --hostname 127.0.0.1 --port 3034
```

```sh
DESCRIPTIVE_WIRE_URL=http://127.0.0.1:3034/dev/descriptive-paper-wire node scripts/qa/measure-descriptive-paper-wire.mjs
```

전체 실행은 증거 폴더의 캡처·측정 JSON과 `tmp/pdfs/descriptive-paper-wire/`의 검증용 PDF 30개를 갱신한다. `--quick`은 1040px만 확인하며 PDF를 만들지 않는다. PDF는 검증용 중간 산출물이고 납품물은 Wire 페이지와 이 보고서·캡처다.

이번 납품은 **Wire 5안 비교까지**다. 안 선택 뒤의 Hi-fi·제품 적용은 이 브리프에 포함되지 않는다. 작업트리는 미커밋 결과를 보존한다.
