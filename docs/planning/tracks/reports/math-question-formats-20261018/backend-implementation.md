# 출제·바구니·사용 이력 구현

2026-10-18 · Codex · 승인 계획 SHA `50c525785cae16825d23d7bd55de81f7a779fa54cd98e8933d470a126acccc61`

- 출제 풀에서 검증된 questionId를 먼저 추첨하고 실제 표현을 고른다. 형식 행이 많은 문항이
  확률을 더 받지 않는다. 최근 실제 ID는 모든 현재 형제로 확장하고 같은 유형의 다른 숫자는 남긴다.
- 일일/확인 출제의 optional `formats`는 기존 3형식의 정확한 할당이다. 먼저 전체 풀에서
  난이도와 형식을 함께 맞춘다. 난이도 대체가 필요한 경우에도 형식은 바꾸지 않는다.
  탐색 한도는 409, 구성 불가는 422로 구분하며 부족한 수를 임의 형식으로 채우지 않는다.
- 교체는 현재 표현의 형식을 보존하고 현재 문항의 모든 표현을 제외한다. 생성/교체 쓰기
  트랜잭션에서 실제 문항 행을 잠그고 자격·정체·본문·정답·난이도를 다시 확인한다.
- 계정 바구니의 쓰기는 사용자별 PostgreSQL advisory transaction lock을 공유한다.
  같은 문항의 다른 형식을 추가하려면 명시적 PATCH로 바꾼다. 기존 중복 바구니는 GET에서
  한 충돌 카드로 보이고 삭제하지 않는다. PATCH는 유지할 실제 표현과 원래 순서를 보존한다.
- 새 바구니 출제는 선택한 실제 ID·순서·개정을 검증한다. 충돌·잠금·다른 기기 변경은
  시험 생성/바구니 비우기를 모두 막는다. 기존 수동 recent 생략 기본은 유지한다.
- 30일 내 출제의 question 보기에서 형제의 시험 ID 합집합을 센다. 한 시험의 두 표현은
  한 번 사용한 것이다. 순위 모집단도 문항 단위이며 잠긴 표현의 자격을 빌리지 않는다.
- source proof가 있는 3개 결합형과 계수 위치 8개만 canonical family로 정리했다.
  원래 키/코드/기록과 해 없음·무수히 많은 해의 구분을 보존한다.
- 일일 학생 항목의 optional `problemCount`는 해당 반의 실제 기본값이다. 묶음의 최댓값을
  학생별 형식 할당에 복사하지 않는다.

검증: 관련 API/순수 규칙 **14파일 139검사 통과**, 수정 파일 ESLint 오류·경고 0,
`git diff --check` 통과. API 검사는 이전 요청 호환, 실제 객관 정답, 형식 유지 교체,
형식 부족, 오래된 바구니 충돌, 같은 자리 형식 변경, 개정 충돌 시 바구니 보존을 포함한다.
타입 검사의 남은 두 오류는 공유 schema의 기존 교과서 fixture/RecoverySnapshot 호환이며
core 담당이 수정 중이다. 해당 수정 뒤 전체 타입 검사를 다시 수행한다.

인메모리 대역은 두 lock SQL만 명시적으로 받아들이며 다른 raw SQL은 거부한다.
이 API 검사만으로 PostgreSQL의 실제 동시 잠금·인덱스·권한을 증명하지 않는다.
실 DB lock/카탈로그 확인은 최종 통합 단계에서 수행한다. 이 단계의 공유 DB 쓰기는 0건이다.
행을 직접 바꾸거나 기존 TEST·학생 응답·교과서 snapshot·승인된 1차 원장을 재작성하지 않았다.
