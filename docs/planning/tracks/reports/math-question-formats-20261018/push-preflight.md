# 사용자 push 지시 후 통합 검증

2026-10-18 · 앞선 로컬 main 완료 뒤 사용자가 “밀어”를 지시했다.
원격 main `32aeb8a066702b88e849c50d06d6ed7831f92547`을 fetch하고,
로컬에 없던 15개 커밋을 `fa6b30cf5`에서 병합했다. 원격의 성적표·에이와 변경과
기존 수학 문항 통합·보강을 모두 보존했다.

충돌은 계획 문서, 초등 문형 등록부, 인쇄 검수 목록과 그 검사의 네 파일이었다.
진술 문형·보강 문형을 함께 등록하고, 인쇄 항목을 양쪽 모두 유지했다.
실제 검수 목록은 124개다. 누락된 세 수학 검수 항목과 새 성적표 항목을 포함해
기존 수량 검사를 실제 등록 수에 맞췄다. 실물 검수 상태는 대기를 유지했다.

추가 검사에서 개발용 출처 API의 optional Request가 Next 생성 타입에 맞지 않는 것을 확인했다.
Codex의 별도 작업 `e6ce14bb1`은 실제 Request를 필수로 받고 두 직접 호출 검사에 Request를
제공한다. 오류 기록 wrapper, 개발 환경 gate, 이전 출처 응답과 새 문항 단위 응답은 유지한다.
해당 작업은 4파일 53검사, 새 Next 타입 생성, 전체 타입 검사, lint를 통과했고 `39db460de`에 병합했다.

기존 초4 보강 회귀 검사는 이후 승인된 진술 문형 14개와 도형 오류 수정을 반영하지 못했다.
원래 `g4-legacy-baseline.json`은 수정하지 않았다. 그 원장의 기준 커밋에서 g4만 복원해
3개 seed의 7,428개 결과와 원래 전체 SHA-256이 재현되는 것을 확인했다.
Claude R3 승인 manifest와 같은 소스에서 변경된 것은 정확히 5문형·15결과였고
나머지 7,413개 결과는 같았다. [추가 원장](g4-approved-repair-baseline.json)은 그 15개 원래 결과와
현재 결과의 해시를 고정한다. 회귀 검사는 그 15개만 원래 결과로 복원해 **기존 전체 해시**를
그대로 검증하고, 현재 수정 결과와 승인된 g4 소스 해시도 각각 검증한다.
나머지 소스 파일의 원래 해시 검사는 유지한다. 새 진술 14개·보강 9개와 원래 2,476개의
등록 수를 따로 확인한다. 이 수정은 `512218a1a`다.

최종 통합 코드는 관련 **51파일 / 1,007검사**와 전체 `tsc --noEmit`를 통과했다.
테스트 runner가 예정 파일과 실제 결과를 대조했으며 누락·실패는 없었다.
수정 검사 파일 ESLint와 `git diff --check`도 통과했다. 이 후속 과정에서는 DB 내용을
다시 쓰거나 원래 승인 manifest·과거 적재 원장을 재생성하지 않았다.

push 직전 원격 main을 다시 fetch·비교하고, 신규 변경이 있으면 통합·재검증한다.
main의 원래 pre-push hook을 통해 배포 그림·저장 LaTeX·미적재 유형·그림 보기 연결·타입을 검사한다.
첫 시도는 그림 검사를 통과한 뒤 LaTeX 검사기의 새 `question_group_key` 열 분류 누락으로 중단됐다.
이 열을 지면 텍스트가 아닌 문항 연결 식별자로 명시했다. 본문·정답·해설 전수 검사는 그대로 유지한다.
이 문서는 push 전 코드 검증 기록이며 원격 push 성공 및 운영 배포 완료를 대신하는 기록은 아니다.
