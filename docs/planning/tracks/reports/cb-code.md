## 0. 한 줄

학생지 · 채점표 **모든 장 맨 아래**에 작은 고딕 한 줄 `1RWK.YVEB.6B5C.GECG.J1 · 2/5 · 학생지` 가 찍힌다. 코드는 **그것만으로 고르기를
되살리고**(DB 없음) 은행 판을 가르며, 학생을 가리키는 값(이름 · 제목 · 날짜)은 싣지 않는다. 화면 기본 고르기에서 소단원 하나 16~19글자 ·
대단원 통째 ≤ 27 · 학년을 넘는 열 개 35~44글자. 한 줄 정원 60글자를 넘는 고르기(흩어진 소단원이 대략 22개를 넘을 때)는 «코드 없음»
(리드 결정). 올리기 · AI · 저장 · DB · QR 은 하지 않았다. 남은 것은 **실물 검수 «폰으로 찍어 읽히는가»**(`/dev/print-check` «대기»).

## 1. 코드의 꼴 (판 1)

```
[판 1] [고르기 비트 …] [은행 지문 4] [검사 1]      → 네 글자마다 점: 1RWK.YVEB.6B5C.GECG.J1
```

| 칸 | 꼴 | 까닭 |
|---|---|---|
| 글자표 | Crockford base32 `0123456789ABCDEFGHJKMNPQRSTVWXYZ` — 대문자 + 숫자, `I` `L` `O` `U` 없음 · 글자 하나 = 5비트 | 손으로 옮기거나 사진에서 읽을 때 `0/O` · `1/I/L` 을 안 헷갈리게. 읽을 때는 소문자 · `O`(→0) · `I` `L`(→1) · 점 · 빈칸 · 붙임표를 너그럽게 받는다 |
| 판 번호 | 맨 앞 글자 `1` | 꼴을 바꾸면 올린다 — 옛 지면은 옛 판으로 읽는다 |
| 소단원 | 단원 나무의 **차례 번호**(교육과정 시드의 순서 · 초1~중3 490개 · 0 부터)를 **이어진 묶음**(run)으로. 묶음 수 − 1(EG0) · 첫 시작 9비트 · 길이 − 1(EG1) · 다음 묶음은 앞 묶음과의 틈 − 1(EG2) · 길이 − 1(EG1) | 대단원 하나 통째 = 묶음 하나(그 대단원이 소단원 열셋이어도 짧다). 9비트 = 512 — 나무가 512 를 넘으면 시험이 운다(판을 올릴 때) |
| 형식 | 1비트 — 0 이면 정해진 차례(A B C D E · 겹침 없음)의 5비트 표, 1 이면 목록(개수 − 1 3비트 + 형식마다 3비트) | 화면은 늘 정해진 차례라 6비트. 손으로 만든 `?s=`(차례가 다르거나 겹침)도 그대로 되살린다 — 형식 차례가 지면 차례다 |
| 수 | 형식마다 본 수 하 · 중 · 상(EG2). 둘째 형식부터 «앞 형식의 본 수와 같음» 1비트. B · C 만 extras(○× · 적용) | A · B · C · D 의 «개념 수»는 기본이 같은 재고라 흔히 같다(셋째 형식부터 1비트). A · D · E 의 extras 는 합치기가 안 쓰므로 싣지 않는다(되살리면 0) |
| 은행 지문 | 20비트(4글자) — 그 고르기로 **지면에 찍히는 것 전부**(합치기 결과에서 머리만 뺀 것 — 문항 id · 정답 · 뜻 문장 · 물음 · 그림 · A 의 소단원 칸 이름)와 소단원 열쇠를, 열쇠 차례를 고정한 JSON 으로 FNV-1a 32 + murmur3 마무리 섞기 | 브리프의 «id 와 정답»을 품는다. 문장도 넣은 까닭 — **문장 길이가 쪽 나눔을 바꾼다**(물음만 길어져도 문항이 다음 장으로 넘어가 «3/5 쪽»이 다른 장이 된다). 지면에 안 찍히는 문항을 고쳐도 지문 · 코드는 그대로다(시험) |
| 검사 | GF(32)(x⁵+x²+1) 가중합 Σ αⁱ·sᵢ 한 글자 | 어느 자리든 **한 글자 바뀜**과 **이웃 두 글자 뒤바뀜**을 반드시 잡는다(무게가 0 이 아니고 이웃끼리 다르다). 거기에 «되살린 고르기를 다시 묶으면 같은 글자»를 더해, 틀린 코드가 **다른 고르기로 읽히지 않고 null** 이 된다 |

- **싣지 않는 것** — 제목 · 날짜(원장님이 학생 이름을 적을 수 있는 칸이다 · 문항과 쪽 나눔을 안 바꾼다). 그래서 «같은 고르기 = 같은 코드»에서
  소단원을 고른 차례 · 겹침 · 제목 · 날짜는 코드를 바꾸지 않는다. 되살린 고르기에는 제목 · 날짜가 없다.
- **읽기** `decodeSheetCode(code, bank?)` → `{ selection, bankDigest, bankChanged } | null`. 지문이 지금 은행으로 낸 것과 다르면 고르기는 그대로
  돌려주고 `bankChanged: true`(옛 지면). 판 번호 · 검사 글자 · 비트 꼴 · 계약 · «다시 묶으면 같은 글자» 가운데 하나라도 어긋나면 null.
- **계약** `src/contracts/conceptBlank.contract.ts` — `SHEET_CODE_ALPHABET` · `SHEET_CODE_VERSION` · `SHEET_CODE_DIGEST_LENGTH` · `sheetCodeSchema`(찍힌 꼴) ·
  `SheetCodeReading` · `SHEET_PART_LABELS`. 함수 `src/lib/concept-blank/sheetCode.ts`(`encodeSheetCode` · `decodeSheetCode` · `sheetBankDigest` · `canonicalSheetSelection`).
- 🔴 차례 번호는 교육과정 시드(`prisma/seed-data/units.ts`)의 순서다. 시드에 소단원이 끼어들면 옛 코드는 다른 소단원을 가리키는데, 지문에 소단원
  열쇠가 들어 있어 **«은행이 바뀜»으로 드러난다**(조용히 다른 지면을 채점하지는 않는다 — 옛 고르기를 되살리지는 못한다 · §6).

## 3. 지면 — 자리 · 예산 · 정원

- **자리** — 학생지는 발(맞은 개수 · 오늘의 메모) **바로 밑**, 채점표는 표(마지막 장은 채점 안내 상자) 밑, 곧 **모든 장의 맨 끝 덩이**.
  9px 고딕(`--paper-font-sans`) · 오른쪽 맞춤 · 한 줄(줄바꿈 없음) · 코드만 굵기 600 · 진하게(`--ink70`), 나머지는 `--ink50`.
  장의 안쪽(아래 여백 20px 위)에 둔다 — 종이 끝 5mm 안쪽은 프린터가 못 찍는다. `SheetCodeLine`(`paper/PaperParts.tsx`) · `.codeLine`(`paper.module.css`).
- **쪽 번호** — 몫(학생지 · 채점표)마다 **형식을 넘어 1 부터** 센다(리드 확인). 형식 안 번호로는 형식이 여럿일 때 같은 코드에 «1/2 · 학생지»가
  두 장 생겨 장을 못 가린다. 머리의 «p. N»(형식 안 번호)은 그대로. view(학생지만 · 채점표만 · 둘 다)와 상관없이 같은 장에 같은 번호(시험).
- **예산** — 줄 높이 16px(위 여백 4 + 한 줄 12)만큼 `GEOMETRY` 의 몸 높이를 모두 낮췄다: 학생지 895 → **879** · 1000 → **984**,
  채점표 935 → **919** · 1000 → **984**(남기던 여유는 그대로). 쪽 나눔은 코드가 있든 없든 · 길든 짧든 같다.
- **정원** — 가장 넓은 글자로만 지은 코드가 글 폭 694px 한 줄에 서는 수(`e2e/concept-blank-paper/code.spec.ts` · 쪽 번호는 «999/999»로 넉넉히):

## 5. 리드에게 물은 것 · 답 (2026-10-01)

1. **한 줄에 안 드는 코드** → (가) 찍지 않고 «코드 없음 · 쪽/전체쪽 · 몫»(쪽 나눔 불변). 정원은 실측으로 보고서에 · «정원 안이면 찍힌다 · 넘으면 코드 없음»
   두 갈래를 시험으로 잠근다. 화면 경고는 이번 범위 밖(§6 다음 걸음).
2. **쪽/전체쪽의 범위** → 몫마다 형식을 넘어 1 부터 — 좋다. 머리의 p. N 은 그대로.
3. (알림) 은행 지문을 «지면에 찍히는 것 전부»로 낸 것 — 좋다. 은행을 고치면 옛 코드가 «은행이 바뀜»으로 읽히는 시험을 **픽스처 은행으로** 잠갔다
   (리드가 main 에서 은행 글을 고치는 중이라 실제 은행 글 그대로의 지문 값을 박지 않았다 — 실제 은행 시험은 값을 박지 않고 왕복만 본다).

- **쪽 나눔 규칙이 바뀌면** 같은 코드 · 같은 지문이라도 «3/5 쪽»이 다른 장일 수 있다 — 지문은 은행 · 합치기만 본다(`paginate.ts` 의 예산 · 천장은 안 본다).
  사진 채점을 만들 때 «지면 판»(쪽 나눔 규칙의 판)을 코드에 넣을지(꼴 판 2) · 쪽 나눔을 바꿀 때마다 판 번호를 올릴지 정해야 한다.
- **교육과정 시드의 차례가 바뀌면** 옛 코드는 «은행이 바뀜»으로만 드러나고 옛 고르기를 되살리지 못한다 — 옛 차례표를 남길지(판마다 소단원 열쇠 목록을 고정해 두기)는 채점 기능 때.
- **정원 60 은 이 PC 글꼴 기준** — 맥(Apple SD Gothic Neo)은 재지 않았다. W 만으로 지은 코드가 가장 넓어 실제 코드는 여유가 크다.
- **지문 20비트** — 은행을 고쳤는데 지문이 우연히 같을 확률은 약 100만분의 1.
- **누구 답인지**는 코드가 말하지 않는다(합의 그대로) — 이름 칸 손글씨를 읽을지 · 학생을 따로 고를지는 채점 기능 때.
- **실물 검수** — `/dev/print-check` «개념 백지 지면 코드 — 폰으로 찍어 읽히는가»(대기): 프린터가 줄을 자르지 않는가 · 폰 사진에서 코드를
  틀림없이 옮겨 적을 수 있는가(`8/B` · `5/S` · `2/Z` · `0/D`) · 옮긴 코드가 `decodeSheetCode` 로 돌아오는가 · n/N 이 이어지는가 · 흑백에서 읽히는가.
