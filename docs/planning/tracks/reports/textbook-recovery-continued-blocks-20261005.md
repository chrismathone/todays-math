## 2. 이어지는 개념 조각

모델은 한 차시의 개념을 여러 블록으로 나누고 둘째 블록부터 `continuation` 을 켠다(`….part-1` · `….part-2`). 지금까지 그 블록은 **제목 없이** 찍혔다 — 검수에서 나온 초3 12쪽(초4 · 초5 도 같은 꼴)의 이름 없는 개념 카드다.

- `block.continuation` 이면 제목 `h3` 대신 `<div class="tb-concept-continuation" data-continuation data-anchor="concept-continuation">제목<small>계속</small></div>` 를 찍는다.
- 제목은 **그 블록의 원래 제목 그대로**다: 개념 노드가 있으면 그 개념의 이름, 저장 본문이면 저장된 제목, 원본 조각이면 블록 제목. 번호 칩은 찍지 않는다.
- 이어지지 않는 블록은 한 글자도 달라지지 않았다.
- 7.5pt · 줄 높이 1.5 · 아래 여백 1.5mm, «계속»은 6.5pt 옅은 색. 셈으로 약 5.5mm 가 블록 높이에 더해진다(재지 않은 값).

## 3. 이어지는 은행 암기 블록

은행에서 쓴 암기 블록(`rows` 노드)은 개념 이름이 없고, 이어지는 블록은 지시 줄도 없다. 모델이 주는 `memoryContinuationTitle`(소단원 제목)을 이미 잡아 둔 줄에 찍는다.

- 조건: `rows` 노드 · `semantic.source` 없음 · `block.continuation` 또는 `semantic.continuation`.
- 자리: `header.tb-memory-title.tb-memory-title-bare` 안에 `<span class="tb-memory-continuation" data-continuation><span class="tb-memory-continuation-title">제목</span><small>계속</small></span>`. 개념학습 · 빈칸 · 통문장 **세 단계 모두**. 제목이 없으면 «계속»만.
- 8pt · 줄 높이 1.5 — 7mm 줄을 키우지 않는다. 제목은 한 줄이고 넘치면 줄임표로 자른다.
- **바뀌지 않는 것**: 원본에서 옮긴 암기 지면 · 자기 개념 제목이 있는 은행 블록 · 이어지지 않는 블록. 앞의 둘은 `memoryContinuationTitle` 이 있든 없든 HTML 이 글자까지 같다.

실제 Chromium: 이어지는 줄의 높이는 빈 줄(7mm)과 0.05mm 안에서 같고 긴 제목도 줄을 키우지 않는다. «계속»은 줄 안에 온전히 있고 1~4회 표시와 겹치지 않는다. 세 단계에서 줄과 행의 위치가 같다.

## 4. 맞붙은 수식 (조율 담당의 전수 조사에서 나온 결함)

은행 행 `{$50$}$\%$` 처럼 **수식인 핵심어 바로 뒤에 수식이 붙은** 행이 핵심어가 보이는 모든 지면에서 실패했다(`m3-07-03-c3` · `c10`, 중3 상자그림).

- 원인: 행의 조각을 찍기 위해 이으면 `$50$` + `$\%$` = `$50$$\%$` 가 되고, 가운데 `$$` 가 별행 수식의 시작으로 읽혀 KaTeX 가 거절했다.
- 고침: 조각을 잇는 자리 하나(`typesetRecallPieces`)에서, 앞 조각이 `$` 로 끝나고 뒤 조각이 `$` 로 시작하면 사이에 사설 영역 표지(U+E003)를 끼워 조판하고, 조판된 HTML 에서 그 표지를 뺀다. 두 수식은 지면에서 그대로 붙어 있고 **지면에 더해지는 글자는 없다**.
- 저장된 행 · 모델이 만든 `displayRows` · 원본 지면의 기하는 바뀌지 않는다. 개념 카드도 같은 방식으로 잇는다.
- 회귀 검사 `textbookRecoveryAdjacentMath.test.ts`(8건): 먼저 보고된 오류(`KaTeX parse error … 50$$\%`)를 실제 은행 행으로 재현한 뒤 고쳤다. 은행 꼴의 두 행을 세 단계 × 학생용 · 정답 판 × 투영 유무로 찍어 수식의 차례와 «붙어 있음»을 단정하고, 학생 빈칸 지면은 수를 가리고 `%` 만 남기는지, 통문장 지면은 비는지 본다. 원본 v15 행(display style) · 개념 카드 · **자동 교재 은행에서 조각 사이에 수식이 맞붙는 모든 행**도 본다.
- 자동 교재 은행(`TEXTBOOK_CORE_BANK`)에서 그런 행은 위의 둘이다. 개념 백지의 보강 은행(`m3-plus.ts`)에도 같은 꼴이 여섯 자리 있다 — 교재는 그 은행을 쓰지 않고, 개념 백지의 렌더 경로는 이 작업 범위가 아니라 **보지 않았다**.

## 9. 한계 — 정확히

- **돌리지 않은 것**: 교재 검사 전체 · 저장소 전체 `tsc` · API 통합 검사 · 작성기 검사(`textbookRecoveryWriter.test.ts`) · 조율 담당의 Chromium 검사 · 얼린 추출 증명. 지시대로 좁은 검사만 했다.
- 좁은 `tsc` 는 `tsconfig.json` 을 물려받고 대상만 좁힌 임시 설정으로 돌렸다(설정 파일은 지웠다). 저장소 전체의 타입 일관성은 보지 않았다.
- **지시 줄의 대조는 블록 안의 상대 위치다.** 쪽 위에서 지시 줄이 61.230mm 에 놓이는지, 블록 사이가 4.7mm 인지, 끝 줄이 어디 놓이는지는 조율 담당의 조판을 거친 지면에서 재야 한다 — 재지 않았다.
- 원본 측정은 이 컴퓨터의 Edge 154(제품의 PDF 경로가 고르는 브라우저와 같다)로 한 번 했다.
- 이어지는 개념 조각의 높이 증가(약 5.5mm)는 셈이다. 실제 쪽 조판에서 12쪽이 어떻게 달라지는지는 보지 않았다.
- 모델은 개념 조각마다 번호를 하나씩 올린다. 이어지는 조각에는 번호 칩을 찍지 않으므로 지면의 번호는 건너뛰어 보일 수 있다(코드 읽기로만 확인).
- 은행 블록의 «계속» 제목은 **소단원 제목**이다 — 모델이 그 값을 준다.
- 맞붙은 수식의 이음은 **조각 사이**만 본다. 한 조각 안에 `$…$$…$` 가 그대로 적힌 원문이 있다면 원문대로 조판된다. 지금 은행 파일 전부에 `$$` 가 적힌 줄은 0줄이다.
- 도우미의 조판은 블록 높이를 고정값(제목 16mm · 그 밖 75mm)으로 준다. 어떤 블록이 놓이는지만 보고 **지면 기하는 증명하지 않는다**.
- 도우미는 펼침이 들어가는지 스스로 판정하려고 조판의 높이 한도 254mm 와 `introTextFits` 조건을 따로 적었고(폭 허용값은 조판의 `A4.toleranceMm` 를 쓴다), 적힌 까닭은 경고 문구의 «홀수 시작 쪽»으로 가른다. 조판에서 그 조건이나 문구를 바꾸면 도우미도 고쳐야 한다.
- **기계 상태**: 작업 중 C: 드라이브의 남은 공간이 0 이 되어 검사 실행기가 뜨지 않았다(`ENOSPC` · V8 메모리 할당 실패). 이 세션의 옛 임시 산출물 835MB 를 지웠다. 그 뒤로는 검사를 한 파일씩, 작업자 하나로 돌렸다.
- 실물 인쇄는 하지 않았다.
