# 오류 기록·수정 식·최종값의 답 비교

노변 19번의 저자 답과 Git 봉인 독립 답은 같은 기록 ㄴ과 같은 수정 식·최종값을 답했다. 하지만 이전 일반 서술형 비교기는 세 역할을 지원하지 않아 실제 수집 결과는 수학·학년 각각 0이었다. 그 결과와 보고서를 보존했다. 검수자의 수학 의견을 자동 통과 수로 옮기거나 봉인 답의 문장을 저자 답에 맞춰 고치지 않았다.

`recordCorrectionAnswer.mjs`와 후보 연결을 추가했다(U48). 메타데이터에 버전·답 종류·허용 기록 기호·수정 대상 식·최종 대상 식을 명시해야 이 비교를 사용한다. 답은 ‘기록 기호 / 수정 식의 값 / 최종값’ 세 부분을 순서대로 읽는다. 수정 대상과 최종 대상의 좌변은 명시된 역할과 같아야 하며, 우변은 기존 정확 상수 비교기로 대조한다. 근호항 순서·표준 분수 표기·괄호 표기의 차이는 다루지만 일반 문자식의 동치나 방정식의 참을 증명하지 않는다.

기록·부호·상수·단위·수정 대상·최종 대상·답 순서가 바뀌거나 부분이 추가되면 통과시키지 않는다. 자유 문장과 변수 값, 누락·변조된 schema도 보류한다. 알려진 새 답 형식에서 schema가 없으면 두 답 문자열이 같아도 이 비교를 우회하지 않는다. 학생용 문제의 타당성과 실제 단계는 독립 풀이·해설·학년 검수에 남긴다.

19번은 새 r3 메타데이터에서 이 답 역할만 추가했다. ID·학생 본문·답·해설·배점·rubric·자산·원시 풀이 바이트는 모두 보존하며 새 후보 digest에 대한 새 검수 보고서가 필요하다. 기존 두 답을 덮어쓰거나 새 문항·추가 blind 풀이로 세지 않는다. [수정 기록](../../../../.qa-artifacts/exam-resume-20261008/nobyeon-sem1-authoring-group11-r3/answer-schema-revision-r3.json)에 최초 수집 보류와 한계를 함께 연결했다.

관련 Node **11파일 135검사 통과**, 실패·건너뜀 0이다. 첫 검사에서 지원하지 못한 유효한 한 자리 분수 표기 `\frac12`도 보존했고, 명시적인 표기 정규화 후 같은 검사를 통과했다. 최초 PowerShell 로그는 UTF-16 BOM 원본을 그대로 두고 별도 UTF-8 사본과 변환 해시를 남겼다. [검증 기록](../../../../.qa-artifacts/exam-resume-20261008/engine-upgrade-20261019/record-correction-validation-r1.json)은 현재 125개 선택본과 새 후보의 기호 관문, 과거 보류와 새 typed 비교의 차이를 확인한다. 전체 앱·학년·권리의 자동 승인은 아니다.
