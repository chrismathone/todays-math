# 시험지 만들기 이중 스크롤 고침 (2026-10-21)

원장님 말씀 — 1단계 «이중스크롤 부분 해결해줘 … 외부 스크롤이 필요없어보임», 3단계 «세로스크롤은 필요없고, 가로스크롤도 항상 잘 보이게».
지시서 `display-survey/consensus/brief-builder-scroll.md`(저장소 밖). 이미 확정된 화면의 스크롤 결함이라 시안 없이 고쳤다 — 배치 · 크기 비율은 그대로다.
모양이 바뀐 곳은 하나 — 문항 정체 확인 실패 문단을 단 아래에서 다른 오류 문단과 같은 단 위로 옮겼다(Codex 제안 · 합의).

## 원인 (실제 작업실 화면에서 잰 것)

1. **1 · 2단계** — 단의 높이는 `100dvh − 단의 위 − 12px` 인데 단 아래에는 작업실의 쪽 여백 16px 이 있다. 페이지가 4px 넘치고,
   페이지를 내리면 단의 위가 올라가 단이 그만큼 커져(`--builder-viewport-top` 을 스크롤마다 다시 잰다) 또 넘친다 — 바깥 스크롤이 끝없이 이어졌다.
   아래 여백(`--builder-viewport-bottom`)은 3단계 단에만 재고 있었다.
2. **2단계의 84px** — 미리보기의 «저장 오류» 같은 껍데기 알림이 빌더 **위**에 늦게 끼면 빌더는 내려가기만 하고 크기는 그대로라
   ResizeObserver 가 안 울었다. 단의 위가 낡은 값(297 → 실제 377)으로 남아 단이 80px 길었다. 알림을 **접을** 때는 거꾸로 단이 20px 짧게 남았다.
3. **3단계** — 지면 띠(`PaperStrip`)가 쪽 크기를 **창** 높이(`innerHeight − 띠의 위 − 16`)로 정했는데 미리보기 단은 창 바닥보다
   32px 위에서 끝난다. 띠가 단 밖으로 15px 넘쳐 단에 세로 스크롤이 생기고 가로 막대는 단 아래로 숨었다(1440×900).
   1680×1000 · 1280×800 에서는 거꾸로 띠가 단 바닥보다 56px 짧았다 — 띠를 잴 때의 위치가 지금보다 56px 아래였다(띠 위의 무엇이
   나중에 줄어도 띠 자신의 크기는 그대로라 다시 재지 않는다). 어느 쪽이 나올지가 화면이 그려지는 차례에 달려 있었다.

## 고친 것

- `useBuilderScrollFrame.ts` — 모든 단 틀(범위 · 검토 · 출력)에 아래 여백을 잰다. 빌더의 **조상 전부**의 크기도 지켜봐서
  위에 알림이 끼거나 접히거나 사라지면 다시 잰다(`body` 만 보면 접힐 때를 놓친다 — 셸의 `min-height: 100dvh` 가 `body` 를 그대로 둔다).
- `ExamBuilder.module.css` 끝 — 넓은 화면(901px+)이고 **600px 보다 높은** 화면에서는 범위 · 검토 단이 아래 여백까지 비운다.
  600px 이하 낮은 화면은 예전 규칙(−12px, 페이지를 내려 단을 키움) 그대로다.
- `ExamBuilder.tsx` — 문항 정체 확인 실패 문단(`identityError`)을 단 위로(단 아래에 있으면 그 높이만큼 페이지가 넘친다).
- `PaperStrip` 에 `fill` — 높이가 정해진 세로 flex 칸 안에서 띠가 남은 높이를 채우고, 쪽 크기를 **띠 자신의 높이**에 맞춘다(가로 막대 16px 몫 포함).
  띠의 바깥이 flex 가 아니면 예전처럼 창에 맞춘다. 지금 켜는 곳은 `WorksheetPrint` 하나 — 띠를 부르는 다른 자리 여덟 곳(개발용 시안 넷 포함)은 그대로다.
  🔴 바깥 flex 칸의 높이가 정해져 있지 않으면 띠 높이가 쪽 크기를 따라 줄어드는 되먹임이 된다 — 높이가 정해진 칸에서만 켠다.
- `WorksheetEditor.module.css` — 시험지 만들기 3단계(`.builderFrame`, 901px+, **601px 이상**)에서만 미리보기 단을 세로 flex 로 해 띠에 남은 높이를 준다.
  낮은 화면 · 자료 제작의 내보내기 화면(같은 편집기, 틀 없음)은 그대로다. 인쇄 지면(`printDocument`)은 건드리지 않았다.
- `/dev/workspace-alignment` 의 가짜 API — `view=curriculum` · `view=scope-counts` 를 운영과 같은 모양으로 답한다
  (전에는 일반 목록을 돌려줘 1단계가 계약 오류를 띄웠다 — 하네스로 1 → 2 → 3단계를 못 밟았다).

## 잰 값 (Playwright Chromium · 실제 작업실 · 고전 스크롤 막대)

`페이지` 는 첫 화면의 바깥 넘침 / 끝까지 내려 본 거리. `단` 은 아래 끝(px) · scrollHeight/clientHeight.

| 크기 | 단계 | 고치기 전 | 고친 뒤 |
|---|---|---|---|
| 1440×900 | 1 범위 | 페이지 4 / 48+ · 오른쪽 단 888 | 페이지 0 / 0 · 884 · 1250/687 |
| | 2 검토(알림 · 접음) | 페이지 84 / 128+ · 두 단 968(창 밖) | 0 / 0 · 두 단 884(알림 507 · 접음 527) |
| | 3 출력 | 미리보기 단 703/688(세로 스크롤) · 띠 883 > 단 868(막대 숨음) | 688/688 · 띠 868 = 단 868 · 막대 15px 보임 |
| 1680×1000 | 1 · 2 · 3 | 4 / 48+ · 84 / 128+ · 띠 912(56px 빔) | 전부 0 / 0 · 띠 968 = 단 968 |
| 1280×800 | 1 · 2 · 3 | 4 / 48+ · 84 / 128+ · 띠 712(56px 빔) | 전부 0 / 0 · 띠 768 = 단 768 |
| 1366×600 (낮음) | 1 · 2 | 4 / 48+ · 84 / 128+ | 4 / 늘어남 — 예전 규칙(2단계 84 는 낡은 값이 고쳐져 4) |
| | 3 | 페이지 0 · 띠 512 | 같다(예전대로 창에 맞춤) |
| 800×900 (좁음) | 1 · 2 · 3 | 단이 쌓이고 페이지가 스크롤 | 같다 |

3단계는 «1단 · 1단당 2»로 쪽을 늘려 띠가 옆으로 넘칠 때도 쟀다 — 세 크기 모두 막대가 단 · 창 안에 있고 쪽이 잘리지 않는다.

## 재는 법

```bash
next dev                                   # 아무 포트
BASE=http://127.0.0.1:3000 node scripts/qa/measure-builder-scroll.mjs
```

`/dev/workspace-alignment#bank` 를 1 → 2(알림 → 접음) → 3(알림 · 쪽 늘림 · 접음)단계로 밟으며 크기 다섯에서 잰다.
망으로 나가는 `/api` 요청이 하나라도 있으면 실패한다(가짜 API 는 페이지 안에서 답한다 — DB · 계정 없음). 화면이 안정되지 않아도 실패한다.
스크린샷 · `results.json` 은 `.qa-artifacts/builder-scroll/`. 단위 시험은 `src/__tests__/components/useBuilderScrollFrame.test.tsx` · `PaperStrip.test.tsx`.
고친 것을 하나씩 되돌리면 각각 실패한다 — 아래 여백 → 1단계 바깥 넘침 · 조상 지켜보기를 `body` 로 → 2단계 접음에서 단이 20px 짧음 · `fill` → 3단계 세로 스크롤.

⚠️ 작업트리(링크한 `node_modules`)에서는 Turbopack 이 링크를 거부하고 webpack 은 `ArithmeticWorkbench.module.css:540` 의
`:global(...) > :not(...)` 에서 멈춰 이 화면을 못 띄운다. 이번에는 내부 디스크에 소스 사본 + `cp -c` 로 복제한 `node_modules` 를 두고 Turbopack 으로 띄웠다.

## 남은 것

- 낮은 화면(600px 이하)은 지시대로 예전 동작이다 — 3단계의 띠가 단 밖으로 넘치는 결함도 거기서는 그대로다. 넓히려면 `fill` 칸에 바닥 높이를 두고 601px 조건을 걷는다(칸이 너무 낮으면 쪽이 잘리므로 바닥이 필요하다 — Codex 지적).
- macOS 의 «스크롤할 때만» 막대(겹쳐 그리는 막대)는 넘길 때만 보인다 — 이번 고침은 막대가 단 **안**에 오게 한 것이다. 늘 보이는 막대로 바꾸는 것은 모양 결정이라 하지 않았다.
- `src/app/dev/exam-builder-output` 묶음의 실패 3건(제목 두 개 · 단계 단추 수)은 고치기 전 코드에서도 같다 — 이번 일과 무관.
- `src/__tests__/unit/m3Reinforcement20261018.test.tsx` 가 돌 때마다 추적되는 `math-bank-reinforcement-20261018/m3-candidates.json` · `m3-verification.json` 을 다시 쓴다(렌더 갈래 뒤 지문 값이 바뀌었다) — 이번 커밋에는 넣지 않았다.
