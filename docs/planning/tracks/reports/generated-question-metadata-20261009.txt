Generated question metadata strengthening — 2026-10-09

Behavior
- Engine import plans can explicitly map an exact generated externalId to an
  original originProblemId. The generated row keeps its engine family, seeded
  identity, unit, difficulty, question type and solution. Original school/exam
  membership is not copied onto a newly authored question.
- New engine rows with an explicit original enter pending review with
  directUseAllowed=false. Existing approved rows remain approved on a matching
  rerun. Missing, private, mismatched or conflicting originals fail preflight.
- API list, detail, bank preview/selection, review and AI adoption responses can
  include a read-only sourceReference with the recorded original's code, source,
  school, exam year/semester/round/number and textbook publisher/author/material.
  An absent or inaccessible recorded origin remains unknown; matching a family
  or unit never creates attribution. No schema migration was needed.
- Legacy Problem.examId does not always equal normalized Exam.externalExamId.
  The resolver uses the explicit ExamQuestion.problemId association first and
  refuses to select an arbitrary exam when several ambiguous links exist.
- Source lookup is batched per page/selection. Unlinked questions add no source
  query; the card/detail components add no network requests. Legacy origin
  chains are bounded to eight reads and cycles are rejected.
- Teacher problem cards and bank detail display the supplied original source.
  Example: 기출 변형 · 정화중 2025년 2학기 중간 2번 기반.
  Legacy workbook originals remain labeled 문제집, distinct from 교과서.
  The additional source paragraph is hidden in printed output.
- AI adoption now records AI solution provenance and engine-rendered figure
  provenance when those artifacts exist. Original-reference resolution occurs
  before insertion so a failed metadata read cannot encourage duplicate retries.
