## 독립 검토에서 찾아 고친 경계

1. Windows `Alias`/`alias`가 보고서는 2개인데 PNG 1개로 덮이는 문제: 대소문자 정규화 충돌을
   저장 전에 거부한다. `only=[없는 key]`도 빈 결과로 성공시키지 않는다.
2. `ticks=0/4`, `ticks=2, arcs=1`을 장식으로 삭제해 다른 각 표시가 되는 문제: 지원되는 1/2 별칭만
   변환하고 충돌·잘못된 값은 반려한다. R1의 arcs ‘0~2’ 설명은 일반 `_mark_count` 범위였다.
   실제 각 생성은 0을 추가로 거부하므로 **사용 가능한 각 arcs는 1/2**다. R2에서 정정했다.
3. 기존 `verify_figure`가 NaN 각도·반지름, 음수 길이와 양수 길이의 혼합을 통과시키던 문제:
   수치·좌표·허용오차의 유한성, 필요한 양수·비퇴화를 검사한다. 실패한 재검산이 같은 key의
   이전 성공을 남겨 빌더를 통과시키지 않게 했다.

## 유지한 제한과 다음 작업

- `figure_scene.py`, `figure_solid.py`, `label_markup.py`, `render_spec.py`는 시작 바이트 그대로다.
  앞선 `clear_angle_labels`를 덮어쓰지 않았다. 제품 스펙 수리는 자동 연결하지 않았고 좌표 이동은 기본 금지다.
- 검산 등록은 여전히 scope/key 호출 이력이다. SVG·검산식·후보 본문의 완전한 수학적 대응이나
  `semantic_inventory_issue`의 의미 이해를 보증하지 않는다. 현재 해시와 독립 풀이·내용 검토를 연결해야 한다.
- 실제 Unit/live family·교육과정·학생 풀이의 학년 적합성과 권리/유사성 심사는 별도다.
  이 코드 체크포인트가 문항 승인·기존 문제 수정·적재 허가를 뜻하지 않는다.
- 원본 크롭 완성 처리, COM writer, 모델/API 교체, 전역 68mm 인쇄 폭, 가짜 점으로 여백 늘리기는 채택하지 않았다.
  기존 문항·지면 재구축 세션의 작업 범위는 그대로 유지한다.
- 다음은 이미 검토된 M2 피타고라스의 파생 길이 라벨 노출 수정과 3D 검산 입력 경계 확인이다.
  전체 기출 추출·쌍둥이 검수·엔진 개선 완료로 보고하지 않는다. 기존 v50 집계와 운영 적재 0 유지.

## 푸시 직전 새 main 보존과 추가 검사

보호 스크립트가 원격 main `656a2fff8`의 새 커밋을 발견해 첫 푸시를 실행하지 않았다.
새 소스 선택기·본문 제한 주석/테스트·SRS 미리보기 변경을 `f12e30355`로 보존 통합했다.
이번에 가져온 엔진 소스는 r50과 같으며, 최신 main에서 5파일 37개 관련 검사가 최종 통과했다
(`post-main-validation.json`, progress r51). 앞의 32개와 중복되므로 합산한 독립 검수 수로 표시하지 않는다.

첫 추가 검사에서는 프로젝트 공통 test setup이 빠져 API 픽스처 3개가 연결 불가능한
`127.0.0.1:1` Prisma 대상에서 실패했고, SQL 검사는 server-only mock 누락으로 적재되지 않았다.
이 결과도 보존했다. 실제 DB로 연결하지 않고 저장소의 공통 setup·인메모리 Prisma 대역을 적용해
해당 두 파일 6개를 통과시켰다. SQL 동작은 별도의 일시적 PGlite 픽스처에서만 확인했다.
공유/운영 DB 문항·학생 기록 수정은 0이며 전체 프로젝트 build/typecheck나 HWP 실물 인쇄를 검증했다는 뜻이 아니다.
