### 1.2 🔴 저장하기 전에 결과를 본다 — 미리보기 경로 (리드 결정 E)

- **`POST /api/classes/{id}/progress-plan/preview`** (새로) — 본문은 PUT 과 같은 규칙 한 줄, `?day=` 는 GET 과 같다.
  **아무것도 안 쓴다.** 예정은 저장된 계획의 GET 과 **같은 함수**(`loadPlanSchedule` → `buildPlanSchedule` → `resolveDailyPlan`)로 편다
  — 시험이 «같은 규칙을 저장하고 GET 으로 읽은 예정과 `toEqual`»로 잠근다. 순서: 401 → 경로 id 400 → 반 404/403(`requireOwnedClass(id, session)` —
  관리자는 넘는다, D-130) → `?day=`·본문 422 → 없는 차시 422. 계약 `progressPlanPreviewResponseSchema`.
- 화면: 칸이 저장된 규칙과 달라지고(요일 하나 이상 · 시작 차시 · 날짜 모양이 차면) **250ms 뒤** 미리보기를 부른다(연달아 누르면 앞 요청은 끊는다).
  오른쪽 카드가 미리보기로 바뀌고 맨 위에 «저장 전 미리보기» 한 줄. 규칙을 되돌리면 저장된 예정으로 돌아간다.
- 「오늘」은 `kstDateOf` 한 곳에서 한 번 정해 읽기·미리보기에 `?day=` 로 같이 넘긴다.

### 1.3 반 만들기 — 계획 칸은 접어 둔다 (D-131 ⑷)

`반 추가` 폼 아래 **«수업 계획 넣기»** 한 줄(`aria-expanded`). 누르면 1.1 과 **같은 칸**(`ProgressPlanFields.tsx`)이 열린다.
열린 채 만들면 `POST /api/classes` 에 `progressPlan` 을 같이, **접힌 채면 칸 없이**(지금처럼 반만). 되면 칸을 접고 비운다.
만든 반이 골라지면 1.1 카드가 GET 으로 계획·예정을 읽는다 — **반 만들기 응답에 칸을 더하지 않았다**(`classApi.ts` 파싱 그대로 · 리드 결정 D).
거절되면 «반을 추가하지 못했습니다. <서버 문구 · 칸 문구>» — 400/422 로 가르지 않는다(`ServerError` · `serverErrorText`).

### 1.5 🔴 «자동 출제» 표지 — 만들지 않았다 (브리프 §1-5 → ⑤-A)

찾아본 것: `Test` 모델(`userId · classId · studentId · testType · status · testDate · predictionRunId …`)에 자동/손 구분이 없다.
`generateDraftTest` 는 두 길(«모두 출제» 단추 · 아침 cron)에 **같은 행**을 쓴다. `AutoDraftRun` 은 `targets · created · skipped · skips[{studentId, reason}]` —
**만든 시험 id 를 안 남긴다.** 시각으로 추정(`ranAt` 앞 5분의 초안)은 8시 무렵 원장님이 «모두 출제»를 누르면 섞여 버렸다.
그리고 표지를 붙일 **`Test` 목록 화면이 제품에 없다** — `/api/tests` 목록은 메인 파이프라인 셈에만 쓰이고, «내 시험지»는 작업실 문서(`privateDraftStore`)다.

## ⑤ 리드가 정할 것

**A. 🔴 «자동 출제» 표지를 어떻게 알까 — 공유 DB 스키마라 원장님 확인이 필요하다(브리프 §1-5).** 지금은 길이 없다(§1.5). 길 셋:

| 길 | 무엇 | 좋은 점 | 걸리는 점 |
|---|---|---|---|
| ⑴ `Test.autoDraftRunId`(uuid NULL · FK → `auto_draft_run`, SetNull) | `runAutoDraft` 가 회차 행을 **먼저** 만들고 그 id 로 초안을 세운다 | 시험 행 하나만 보면 된다 · 목록·메인·검수 화면 어디서나 표지 · 회차 기록과 이어진다 | `record()` 가 끝에 한 번 쓰는 지금 순서를 바꿔야 한다(회차 행을 먼저 · 합계는 끝에 고쳐 쓰기) · `test` 표 ALTER |
| ⑵ `AutoDraftRun.createdTestIds`(uuid[] 또는 JSONB) | 회차가 만든 시험 id 를 적는다 | `test` 표를 안 건드린다 | 화면이 표지를 알려면 회차 기록을 따로 읽어 맞대야 한다 · 시험을 지우면 id 가 남는다 |
| ⑶ 시각 창 추정 | `ranAt` 앞 5분의 초안 | 스키마 0 | 🔴 8시 무렵 «모두 출제»와 섞인다 — 버렸다 |

⑴을 권한다. 어느 쪽이든 **배포 순서**는 22 §4 «표 없이 배포되면 500» 과 같다(마이그레이션 먼저). 그리고 **표지를 붙일 목록 화면이 없다** —
메인 «오늘의 확인테스트»의 검수 링크(학생 이름)에 붙일지, `Test` 목록 화면을 새로 만들지(D-07 시안부터)도 같이 정해 주십시오.

**B. daily-review 응답에 칸 셋을 더했다**(`hasPlan` · `delayed` · `noLessonClasses` — §1.4). 계약이 strict 라 이 응답을 파싱하는 곳은 전부 새 칸이 필요하다
(MSW 기본값 · 섹션 시험 픽스처는 고쳤다). 아침 초안(`runAutoDraft`)은 `planDailyReview` 의 `delayed` · `attendedClassIds` 를 받지만 안 쓴다.

**C. 밀림을 누구로 세나** — ① **오늘 대상만**(오늘 수업이 아닌 밀린 학생은 칩에 없다) ② **계획 없는 학생은 없다**(잴 계획이 없다)
③ 🔴 **시험기간·미분류(D-64)는 뺐다** — 진도를 안 나가는 까닭이 이미 «시험기간 N명»으로 선다. 넣으면 시험 철마다 «12일 밀림 N명»이 부푼다. 뒤집으려면 `planDailyReview.ts` 한 줄(푸시 자리를 D-64 `continue` 앞으로).

**D. «오늘 초안 N장»은 자동·손을 가르지 않는다** — A 가 정해질 때까지 오늘 확인테스트 **초안 전부**(확정·인쇄는 뺀다)를 센다. A 의 ⑴이 들어오면 «자동으로 선 초안»만 셀지 정해 주십시오.

**E. `noLessonClasses` 의 모집단** — 소유 범위의 반 **전부**(학생 0 반 · 계획 없는 반 · eywa 갈래 반 포함)에서 오늘 대상이 있는 반을 뺀 것. 관리자 계정이면
역할 계정의 걸어보기 반까지 나온다(D-130 N «누구의 반»과 같은 뿌리). «계획이 **있는** 반 중 오늘 수업 없는 반»으로 좁힐지.

**F. 🔴 `DailyReviewSection.test.tsx` 가 파일째 안 읽히고 있었다** — `app/(main)/page` 를 그렸는데 그 페이지가 작업실·계정 전환(df1eb904) 뒤 `server-only` 를 불러
**시험 0건**(plan-api·admin-sees-all 보고서의 «트랙 밖 빨간 4파일» 중 하나로 보인다). 섹션을 **직접** 그리게 옮겨 12건이 돈다. 같은 까닭으로 `Main.test.tsx` 도 모듈 단계에서
깨져 있다 — 이 트랙 밖이라 그대로 뒀다.

**G. 학생 계획 «끄기»(멈춤) 화면 · 계획 지우기(DELETE) 화면은 없다** — 브리프 §2 대로 학생별 계획은 안 만들었고, 반 계획은 «자동 출제» 끄기로 멈춘다. 지우는 단추가 필요할지.

**H. 작업실 CSS 한 곳을 고쳤다** — `TeachingView.module.css` 의 `[aria-label="단원 선택"]` 규칙 여덟을 `:is([aria-label="단원 선택"], [aria-label="시작 차시 선택"])` 로.
접근성 이름에 스타일이 걸린 기존 방식을 따랐다(두 고르기가 한 화면에 있어 같은 이름을 쓸 수 없다).

**I. 반 선택기의 «누구의 반»(D-130 N)** — 이 트랙은 표시를 짓지 않았다(브리프). 관리자 계정의 반 목록 · 메인 «… — 오늘 수업 계획이 없습니다.» 줄에 역할 계정의 같은 이름 반이 섞인다 → ⑥-10.

**J. 전체 관문 `npm run test` 는 돌리지 않았다** — 관련 파일만(④). 이 기계가 다른 세션과 CPU·메모리를 나눠 쓴다. 병합 검수 때 한 번.

6. **계기판 칸 수가 반마다 다르다** — 주 1회 반은 2칸(칸이 넓다), 매일 수업 반은 14칸(휴대폰 360 에서는 3칸씩 다섯 줄, 긴 차시 이름 칸은 8줄 — `classes-stress-360`). 시안은 5칸 한 줄. 이대로 둘지 · 칸을 «이번 주»(7일)만으로 줄일지(그러면 금·토요일에 앞으로 나갈 칸이 적다).
7. **시안에 없던 상태 문구** — «수업 계획을 불러오는 중…» · «수업 계획이 없습니다.» · «이번 주 수업일이 없습니다.» · «저장하는 중…» · «저장했습니다.» · (반 만들기 거절) «반을 추가하지 못했습니다. <서버 문구>».
8. **반 만들기의 «수업 계획 넣기»** — 코발트 글자 한 줄, 열면 가는 선 아래 계획 카드와 같은 칸(`create-open-*`). 열었을 때 한 줄의 글자를 «수업 계획 접기»처럼 바꿀지(지금은 그대로).
9. **카드 제목 크기 · 요일 토글 44px** — 옆 카드들과 맞춰 작업실 크기(제목 18px · 단추 44px)로 그렸다. 시안(15px · 40px)이 더 가볍다.
10. **«누구의 반»**(D-130 N) — 원장님(관리자) 계정의 반 목록과 메인 «… 오늘 수업 계획이 없습니다.» 줄에 test_t · test_o · 걸어보기 계정의 반이 섞인다. 같은 이름 반을 어떻게 가를지(시안부터).
11. 🔴 **학생별 계획 덮어쓰기 화면**(개별 진도 학생) — 브리프대로 **안 만들었다(열린 질문)**. API(`/api/students/{id}/progress-plan`)는 있다. 어디에(학생 이름을 눌러 서는 칸 — 오늘의 개념 발급 칸 옆?) · «끄기 = 멈춤»(반 계획으로 돌아가지 않는다, 리드 결정 C)을 어떤 문구로 보일지 시안이 필요하다.

## ⑦ 확인 못 한 것

1. **실제 Postgres · 실제 세션** — 로컬 DB 가 없다(Docker 없음). 미리보기 경로 · daily-review 새 칸은 인메모리 가짜(`prismaTestDouble`) 위에서만 돌았다.
