# 편집기 08 이관과 검수 계약 보존

SourceD `4ccb0cb`의 최종 08을 별도 사본에 풀어 현재 Root와 비교했다. 27개 파일의 적용·보존·보류 판단은 `editor08-integration-20261021-r1/transfer-decisions-r1.json`에 있다. SourceD 저장소는 읽기만 했다. 앱을 그대로 덮어쓰지 않았으므로 편집기 전체 바이트 동일성을 주장하지 않는다. 엔진 8종의 동일 출력은 이전 에셋 41종 보고서의 별도 계약이다.

반영한 기능:

- **그림 메뉴**: 평면 29·입체 12를 선택해 넣는다. Next의 `public` 정적 자산 규칙에 맞춰 검증된 SVG 41개를 파일 내용 지문이 붙은 경로에 만들고 필요한 원문만 불러온다. Vite의 `import.meta.glob`는 쓰지 않는다. 불러온 LF 정규화 바이트의 SHA-256·등록 형상·당시 프레임·양수 크기·유한 기준점·요소 ID 충돌을 확인한다. 실패한 불러오기는 재시도할 수 있고, 닫힌 편집기에 늦게 도착한 삽입은 버린다.
- **중첩 묶음**: 기존 묶음을 다시 묶고 한 겹씩 푼다. 이전 이름을 예약해 다시 매기기와 부분 해제 시 다른 묶음으로 합쳐지지 않게 한다. 원문 편집과 이력은 한 작업으로 묶고 수학 좌표·라벨·기존 번호를 바꾸지 않는다. 새 SVG를 가져오거나 다시 열 때 임시 `data-object-id`를 정규화하는 기존 계약과 편집 중 ID 보존은 구분한다.
- **조절점 커서·원근 직각 편집**: 화면 방향에 맞는 크기 조절 커서를 유지한다. `addAngle`의 명시적 불리언 `perspective:true`는 `right:true`와 함께만 받으며 평면·퇴화 각의 검증은 유지한다. 투영 표시는 실제 직각이나 해당 학년 적합성 증명이 아니다.
- **수동 그리기의 새 좌표**: 08처럼 새로 넣는 선·도형의 숫자를 SVG 단위 소수 셋째 자리로 정리해 포인터의 부동소수점 끝자리를 남기지 않는다. 기존 원문 좌표를 일괄 변환하는 작업은 아니다. 0.001 단위보다 미세한 새 수동 형상을 보장하지 않으며 수학 조건을 자동 교정하거나 답을 검증하는 기능으로 쓰지 않는다.
- **명세와 검수 지적 전달**: 실제 렌더 진입점이 받는 `assets`를 프롬프트용 계약 사본에 명시했다. 원본 대조 의견은 워크플로가 지정한 출처 유형으로 `review-issues-data`에 이스케이프해 싣는다. 오류 문자열의 접두사로 권한을 추정하지 않는다. 의견을 같은 원본과 대조해 수정하도록 하며 원본 근거가 없는 선분·관계를 만들어 통과시키지 않는다.

보존·보류:

Root의 엄격한 모눈 메타데이터 검증, 이전 39·현재 41의 형상과 프레임 인식, MathJax 안전 태그, 모달 초점 경계 및 되돌리기 후 초점 이동을 보존했다. 표시 이름만 보고 그림 속 수학 도형을 가리는 `stripAssetBodies`, 경로 숫자를 좌표 쌍으로 해석하는 상자 추정은 반영하지 않았다.

자동 좌표 축소·반올림, 그림 기준점으로 수학 선분을 보태는 수선, `perpective`를 `perspective` 권한으로 바꾸는 자동 수선은 보류했다. 각각 점의 합쳐짐·원본에 없는 선·평면 검증 우회를 만들 수 있어 현재의 원본 근거를 보존하는 재질문 경로를 유지한다. 대조 의견 삭제나 마지막 검수 생략도 반영하지 않았다. `parseReview`의 `passed && issues.length === 0`, 원본·실제 렌더 대조, 취소·시간 초과 실패 및 원본 보존 계약을 유지한다.

프로젝트 TypeSafe 스킬과 라이브 [불확실성 처리](https://docs.typesafe.ai/confidence), [근거 대조 예제](https://docs.typesafe.ai/cookbooks/citation_check)를 확인했다. 여기서는 계산·형상·워크플로 출처를 코드로 검증하며 신규 모델·API·확률 승인 경로를 만들지 않았다.

검증 이력:

- 첫 통합 실행은 529 통과·44 실패였다. 새 시험의 임시 ID 재수입 및 PointRef 형식 가정과 새 한 겹 해제에 맞지 않는 기존 기대값을 고쳤다. 검증기를 느슨하게 바꾸지 않았다. 그 뒤 관련 21개 파일 **577개 통과**, 타입 17개 진입점 오류 0, 린트 17개 파일 오류·경고 0이었다. 후속 독립 경계 검사의 수정 전 버전 기록으로 보존한다.
- 실제 Edge 한 페이지를 재사용해 1280·768·390·320px **4/4 통과**. 평면/입체 탭 키보드 이동, 메뉴 화면 안 배치, 새 입체 그림 삽입, 기존 옛 집 그림과 수학 선 보존, 삽입 한 걸음 undo/redo, 묶음 깊이 1→2→1→0, 커서, 다른 도형·번호·본문 보존을 확인했다. 1280·320px 메뉴와 320px 편집기를 직접 봤다. 실제 Root 컴포넌트의 별도 Vite 검수 구동이며 Next 운영 빌드·전체 작업실·인쇄·실계정 검증은 아니다.
- 후속 독립 검수의 실제 DOM 114건 중 113 통과·1 실패를 보존했다. 긴 이름을 반복해 묶은 실제 64번째 작업은 이전 63겹 JSON이 8,128→8,259자로 8,192자 읽기 제한을 넘어 이력이 빈 목록으로 읽혔다. 정적 예제의 8,123→8,254와 구분했다. 깊이 한도만으로 이력 보존을 보장하지 못했다.
- 제안된 JSON 전체를 저장 전에 검사하고, 존재하지 않는 이력과 손상된 이력을 구분했다. 잘못된 기존 이력의 묶기·해제도 거부한다. 화면에는 거부 사유를 표시하고 현재 SVG·기존 번호·되돌리기 이력을 보존한다. 이 수정 뒤 관련 21개 파일 **580개 통과**, 타입 17개 진입점 오류 0·린트 17개 파일 오류와 경고 0이었다. 이전 577개의 통과 수나 UI 4건으로 독립 실패를 덮지 않는다. 현재 코드 독립 재실행과 화면 후속 증거는 별도로 묶는다.
- 독립 R2는 기존 114건을 모두 통과했고, 추가 음성 검사의 명시적 빈 속성에서 2건 실패해 134/136이었다. 속성 부재와 빈 속성을 분리한 R3는 **같은 136개 입력·기대값·실행기 그대로 136/136 통과**했다. 기존 두 실패와 제안 길이 초과는 거부 전에 남아 있던 SVG가 그대로임을 확인했다. 세 번의 실행을 새 독립 문항 수로 합산하지 않았다.
- 최종 현재 코드의 관련 검사 **21개 파일 581개 통과**, 타입 **17개 진입점 오류 0**, 린트 **17개 파일 오류·경고 0**. 최종 Edge R3도 네 폭 **4/4 통과**, 원본 코드 해시 불변·외부 요청 및 운영 API 호출 0이었다. 앞선 실패 입력과 검사 기록은 별도 버전으로 보존했다. 현재 검증을 이전 실행 수와 더해 부풀리지 않았다.

문항 제작·개별 수학·학년·권리·적재 승인은 이 기술 검사와 별개다. 발행 문항, 학생·은행 기록, DB, 보호된 82개·영구 제외·원본을 바꾸지 않았다. 기존 작성·독립검수 집계와 최종 승인·운영 적재 0은 그대로다. 전체 엔진 개선은 아직 진행 중이다.
