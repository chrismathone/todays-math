# 양식 C2 · 입력 패널 P1 제품 적용 — 2026-10-19

[구현 브리프](../brief-print-color-impl-codex.md)의 C2·P1을 실제 여섯 양식에 적용했다. 기본 남색 포함 9색, 양식별 정보 구성, 시험 종류, 워크북 유형·전략 상자, 미사용 입력 비활성화를 공통 출력 경로에 연결했다. 기존 저장 형식과 값은 변경하지 않았다. DB 접근·스테이징·커밋·푸시는 하지 않았으며 `node_modules` 심볼릭 링크를 그대로 보존했다.

기준 HEAD는 `86fb78a678942904f9cfc5e31f79d2e3cb10f5bb`, 브랜치는 `phase/12-print-color`다. 시작할 때 있던 미커밋 시안·감사·대비 수정은 보존했다. 변경은 이 작업트리에 미커밋 상태로 남아 있다.

## 1. 실제 적용

색·배치는 확정 시안 C2에서 가져왔다. 여섯 템플릿은 공통 `PrintHeader.tsx`와 `PrintHeader.module.css`로 각자의 머리를 그린다. 머리 면·번호 상자는 고른 색을 그대로 채우고 `inkOnColor`로 검정/흰색 글자를 선택한다. 정보 라벨은 `readablePaperColor`를 사용하고 색 면 안에서는 해당 면의 글자색을 따른다. 본문·풀이칸 선의 중립색과 기존 문항 렌더러·풀이 공간·여백 프리셋은 유지했다.

| 양식 | 싣는 정보 | 자리 |
|---|---|---|
| 평가원 | 제목·학교/기관명·학년·과목·학기·시험일·시험 시간·총점 | 영역 머리 오른쪽 시험 종류, 제목, 시험 정보 |
| 정통 | 제목·학교/기관명·학년·과목·학기·시험일·시험 시간·출제자·총점 | 색 면 제목 옆 시험 종류, 정보표, 학생·점수 수기칸 |
| 모던 | 제목·학교/기관명·학년·과목·학기·시험일·총점 | 학교 머리 오른쪽 시험 종류, 제목, 짧은 정보줄 |
| 워크북 | 제목·학원명·강사명·학년·과목·시험일·유형명·핵심 전략 | 학원 머리, 단원 띠 오른쪽 시험 종류, **새 유형·전략 상자** |
| 자습 | 제목·과목·시험일·오늘의 목표·개념 정리 | 자습 머리 오른쪽 시험 종류, 목표, 개념 상자 |
| 유형 | 제목·학년·과목·유형명·핵심 전략 | 제목 옆 시험 종류, 유형 띠, 전략줄 |

모든 양식의 첫 문제 쪽에 시험 종류를 표시하고 «없음»이면 생략한다. 연산의 회차 표시는 기존처럼 머리 안에서 유지하며, 상세 정보·전용 칸은 회차 첫 쪽에 표시한다. 별도 `AnswerPage`의 정답·해설지 구성을 문제지 머리로 교체하지 않았다.

`templateFields.ts`가 실제 출력과 패널의 공통 필드 목록이다. P1은 모든 입력을 보여 주되 해당 양식이 싣지 않는 입력을 흐리게 표시하고 실제 `disabled`로 막는다. «이 양식에는 찍히지 않음»과 시안의 짧은 까닭을 상시 표시하고 `aria-describedby`로 연결했다. 양식 전환은 메타 값을 지우거나 다시 쓰지 않는다. 목표·개념 정리·핵심 전략은 여러 줄 입력이며 넓이를 확보했다. 날짜를 싣지 않는 유형 양식에서는 날짜 표시 조작도 값 보존 상태로 비활성화한다.

`SheetTagPicker` 안내는 «모든 양식에 표시합니다. «없음»을 고르면 지면에서 생략합니다.»로 바꿨다. 태그의 값·저장 위치·허용 종류는 그대로다.

## 2. 저장값과 출력 경로

| 진입 | 기존 값 → 공통 출력 |
|---|---|
| 연산대장 | `presentation.tag`·`printOptions`·`printMeta` → `ArithmeticWorkflow` → `WorksheetEditor` |
| 시험지 만들기 | draft의 `tag`·출력 설정 → `UnifiedWorkspace.editorProps` → `MathExamBuilder` → `WorksheetEditor` |
| 문제 추출 | 문항을 담은 공통 draft → `WorksheetEditor`; 이미 있는 draft 태그도 전달 |
| 내 시험지 | 저장된 draft/연산 문서를 복원한 뒤 위 경로로 출력 |

태그는 `WorksheetEditor`의 별도 `sheetTag` prop으로 받고, 렌더에 쓰는 메타 복사본에만 붙인다. 부모의 저장 메타를 수정하지 않는다. 시험 종류 변경도 출력 준비 상태와 비동기 출력 전 검증에 반영된다. 태그가 없는 옛 저장본에 기본 태그를 만들어 넣지 않는다.

워크북 유형·전략은 이미 있던 `patternName`·`patternStrategy`를 사용한다. `DEFAULT_PRINT_OPTIONS`, `DEFAULT_PRINT_META`, draft/presentation/printPreset의 저장 스키마·버전·저장 위치를 변경하지 않았다. 내 양식의 저장 범위도 출력 옵션 전체와 기존 머리 정보 일곱 칸 그대로다. 태그·유형·전략·목표·개념을 새로 내 양식에 넣지 않았다.

미리보기·확대·인쇄용 `[data-mathgen-document]`는 같은 템플릿 노드를 사용한다. 서버 PDF와 HWPX는 이 인쇄 DOM을 수집하므로 새로운 메타 API나 출력별 필드 재매핑을 만들지 않았다. 네 진입 경로에 대한 별도 Orca Codex [읽기 감사](print-color-impl-codex-20261019/independent-audit.md)도 이 전달을 대조했다. 실계정/실DB로 네 메뉴를 열어 저장·출력한 검증은 수행하지 않았다.

## 3. 쪽 나눔 대조

기존 `useMeasuredPages`·`packMeasured` 알고리즘은 변경하지 않았다. 새 머리와 번호의 실제 높이를 기존 측정기로 재고, 문항이 들어갈 공간을 다시 계산한다. **모든 쪽 나눔이 이전과 같다는 결과는 아니다.** C5에 보존한 이전 컴포넌트와 같은 문항·메타·설정을 실측한 94개 조합 중 다음 네 조합에서 문제지 쪽 수가 달라졌다.

| 조건 — 모두 40문항 fixture | 이전 | C2 |
|---|---:|---:|
| 모던 · 1단 · 여백 배치 | 5쪽 | 4쪽 |
| 모던 · 1단 · 넓은 여백 · 긴 머리 정보 | 5쪽 | 4쪽 |
| 워크북 · 1단 · 넓은 여백 · 긴 유형·전략 정보 | 10쪽 | 11쪽 |
| 자습 · 2단 · 여백 배치 | 3쪽 | 4쪽 |

확정된 머리 구성·번호 상자의 높이에 따른 재배치다. 이 조합을 포함해 A4 가로/세로 넘침 0, 본문 밖 문항 0, 문항 누락·중복·순서 변경 0을 확인했다. 연산 회차가 같은 쪽에 섞이지 않았고, 2회차 40문항과 빠른 정답지를 포함한 PDF는 실측 결과와 같은 10쪽이었다. 기존 페이지 수에 맞추려고 시안의 칸·정보를 삭제하거나 문항을 잘라 내지 않았다.

## 4. HWPX 지원과 한계

실제 DOM 수집기 → 기존 payload 스키마 → 로컬 Python writer → HWPX ZIP까지 여섯 양식을 생성했다. 단색 머리·번호 면은 `rect`로 수집되고 XML의 `faceColor`에 선택색이 남는다. 흑백 글자와 읽기 보정 정보색도 보존된다. 여섯 파일의 시험 종류, 워크북의 새 유형·전략 텍스트를 수집 결과와 XML 양쪽에서 확인했다. C2의 새 칸을 별도 이미지나 새 저장 필드로 우회하지 않았다.

다음은 기존 내보내기 방식의 한계다.

- 전체 종이를 덮는 배경은 여백 계산을 위해 의도적으로 제외한다. 자습의 따뜻한 **전체 종이색**은 HWPX 보존 대상이 아니다.
- 머리 표·새 상자는 위치를 가진 글자·직사각형 면·선으로 옮긴다. HTML의 의미 있는 입력칸이나 다중 셀 표 구조 그대로 복원하는 것은 아니다.
- 반투명은 흰색 기준으로 합성한다. CSS 필터·그림자·둥근 모서리·임의 쌓임순서 등의 완전한 재현은 지원하지 않는다. 이번 C2의 불투명 머리·번호 면은 이 제한을 피한다.
- 한글은 설치 글꼴과 수식 크기로 다시 조판한다. 실제 한글 프로그램에서 열기·재인쇄는 미실시이며, 픽셀 단위 일치나 긴 내용의 재조판 동등성을 인증하지 않는다.

화면 미리보기와 출력 머리 DOM 일치, 확대 조작이 지면을 가리지 않는지, 320px 확대 화면, P1 입력 왕복, 태그 없음, 날짜 숨김도 확인했다. 페이지 오류·허용하지 않은 요청은 0이다. 실제 지면 6장과 P1·확대 화면, 생성 PDF 렌더를 직접 살폈다.

PDF 검증은 **실제 `pdfClient`의 복제 payload를 로컬 모의 수신한 뒤 `buildPdf`를 직접 호출**했다. API 인증과 DB를 거치지 않는다. fixture의 로컬 글꼴을 쓰도록 이 검증에서만 `fontPolicy: self-hosted`를 설정했다. 운영 기본의 외부 글꼴 적재를 검증한 뜻은 아니다. PDF 7개(양식별 1개 + 회차/정답지 10쪽)를 생성하고 쪽 수·시험 종류·워크북 새 칸의 추출 텍스트를 확인했다.

기존 `node scripts/qa/print-info-color-hifi.mjs`도 통과했다: 컬러 90조합·회색조 30장·18개 화면 조합, 오류/넘침 0. 3219 Next 개발 경로 `/dev/print-color-hifi`의 HTTP 200·hydration·C2/C5 조작·21개 지면·«이전» 표시를 확인했고 페이지 오류/업무 API 요청은 없었다.

## 6. 비교 시안·실물 검수·증거
