# 합의 요청 — 학생 SRS 지시서의 결정 다섯 (2026-10-03 밤)

너는 독립 검토자다. 아래 다섯 안건에 **안건마다 하나의 안을 고르고** 근거를 적어라. 다른 검토자의 답은 보지 못한다.
«사실»에는 어디서 쟀는지를 붙였다. 붙지 않은 줄은 «추정»이라 적었다. 사실이 틀렸다고 보면 그렇게 적어라.

## 배경

수학학원용 서비스의 학생 화면 `/learn` 에 «수학 탐험»이 있다 — 진도판 한 칸 = 하루 한 임무, 별 · 상자 · 기지, 간격 복습(1 · 3 · 7 · 14 · 30일).
하루 임무는 셋 중 하나다: **개념 날**(개념 카드 5장 × 활동 3종 = 15활동 — 문장 조립 · 예 모으기 · 경계 살피기) · **은행 날**(초등 10문항 / 중등 12문항의 4지선다) · **기억 복습 날**.
학생은 학원 실습실에서 폰 · 태블릿으로 푼다.

원장님이 외부에서 받은 **«학생 SRS 전체 구현 지시서»**(다른 AI 가 코드를 감사하고 해외 9개 수학 프로그램을 비교해 쓴 것)를 코딩 에이전트에 넘기려 한다. 지시서의 뼈대:

- 목표: 학생이 «수학적 선택 · 조작 · 발견 · 회복»으로 자발적으로 20 ~ 25분 학습.
- **실습 모드** — 기존 학습과 따로 고르는 진입 «오늘의 탐험 · 약 20 ~ 25분». 여섯 구간: 목표 선택(2분) → 필요한 회상(4분) → 핵심 퍼즐(7분) → 선택 확장(4분) → 혼자 확인(4분) → 정리(2분).
- 첫 에피소드 «조각 다리 연구소» — 분수의 통분 · 덧셈. 여섯 단계: 예상 → 재분할 → 합치기 → 규칙을 말과 식으로 → 두 갈래 확장 → 새 문제를 혼자.
- **회복 사다리**: 틀리면 «조작 가능한 힌트 → 짧은 설명 → 값이 다른 새 문제». «재시도에도 모르겠어요 · 힌트를 숨기지 말 것».
- **공정한 기록**: 최초 독립 응답 · 힌트 사용 · 설명 뒤 재현 · 새 문제 전이 · 나중 회상을 **분리해 저장**(«도움받아 마침»은 «혼자 앎»으로 승격하지 않는다).
- 먼저 할 것(P0): 간격 갱신 · 보상의 중복 방지, 최초 응답과 도움 후 성공의 분리, 학생 간 격리.

리드가 지시서를 지금 코드와 기존 결정 기록에 대어 본 결과가 아래다.

## 사실 — 지금 코드

1. 지시서의 코드 사실 주장 10개 가운데 7개가 맞고 3개는 일부만 맞다. 틀린 것은 없다. *(조사 에이전트가 파일 · 줄을 대조 · 리드가 표본 확인)*
2. 지시서가 «먼저 만들라»고 한 것 가운데 **이미 있는 것**: 간격 갱신의 중복 방지(학생당 한 줄 저장 + revision 비교 후 쓰기 · 요청 영수증 256건) ·
   보상 한 번뿐(카드 레벨 · 상자 · 날짜당 한 칸) · 학생 간 격리(학생 id 는 세션에서만) · 서버 쪽 이어하기. 시험도 있다. *(`serverStore.ts:102` · `engine.ts:72-87` · `definition-cards.ts:865,675` · `routes.ts:205`)*
3. **없는 것**: 탐험의 답안별 기록(무엇을 골랐는지 저장하지 않는다 — 카드별 · 세션별 합계만) · 학생 기능을 켜고 끄는 체계(환경변수 하나와 시험용 계정뿐). *(`mathExplorers.contract.ts:80-132` · `enabled.ts`)*
4. **분수 공방이 이미 있다** — 카드 `g5-common-denominator` 에서만 뜨는 조작 활동, 여섯 단계: 예상(3지선다 · 채점 없이 기록) → 조각 나누기 → 조각 크기 맞추기 → 규칙 찾기 → 새 분수로 확인 두 문제 → 끝.
   오늘의 탐험 **안에서**, 그 개념을 배우는 도중에 뜬다. 처음엔 전부, 설계도가 있으면 확인 둘만, 발견 3일 뒤에는 기억 확인. 설계도 별 +1 은 한 번. *(`workshop.ts:178-251` · `engine.ts:297-326`)*
5. 🔴 **결함(리드가 엔진을 돌려 확인)**: 개념 활동 화면에는 세 활동 모두에 «아직 모르겠어요» 단추가 있고 누르면 빈 답을 보낸다.
   서버는 **문장 조립 · 경계 살피기에서 400 «답을 다시 확인해주세요.»**를 낸다(답의 개수가 2 · 1 이 아니라서). 예 모으기만 빈 답을 받아 오답으로 처리한다.
   곧 세 활동 중 둘에서 학생이 «모른다»고 할 수 없다. 서버 시험에 빈 답을 보내는 것이 없다. 카드 230장 가운데 «예가 전부 아니다»인 카드는 0 — 예 모으기의 빈 답은 늘 오답이다.
   *(`ExplorerPractice.tsx:362-368` · `definition-cards.ts:800-817` · 탐침 스크립트)*
6. 개념 활동의 재도전: 첫 풀이 뒤 틀린 활동만 모아 **세 바퀴**까지 다시 푼다(한 활동 최대 4번). 그래도 남으면 «미해결»로 끝나고, **그때** 학생이 요청하면 해설을 본다.
   활동 중에는 뜻(정의)도 풀이도 안 보인다. 첫 바퀴를 깨끗이 맞힌 카드만 레벨이 오르고 간격이 늘어난다(재도전 성공은 간격을 안 늘린다). *(`definition-cards.ts:826-899` · `engine.ts:148-153`)*
7. 중등 은행 날(4지선다 12문항): 첫 풀이에는 «아직 모르겠어요»가 있다. **재도전에서는 그 단추가 없다.** 틀린 재도전은 저장을 안 바꾸고 문항을 줄 끝으로 돌린다 — **상한이 없다.**
   서버는 풀이(`solution`)와 힌트를 내려주지만 **화면이 그리지 않는다.** 풀이가 보이는 유일한 길은 «지난 칸 다시 풀기»인데, 그 임무의 모든 오답을 해결한 뒤에만 열린다.
   곧 재도전에 막힌 학생은 **보기를 하나씩 지워 가며** 벗어난다. 간격(기억)은 첫 풀이에서 정해지고 재도전은 건드리지 않는다. *(`StudentMathSrs.tsx:659-668,193-196` · `serverState.ts:331-348` · `replay.ts:259-266`)*
8. 운영 자료가 거의 없다 — 2026-10-01 기준 학생 상태 1행 · 개념 카드 기록 0건. *(저장소 27번 문서 §5)*
9. 교사가 탐험 기록을 보는 화면은 main 에 없다(요약 계산과 API 는 있다). 화면 작업은 원장님 요청으로 멈춰 있다. *(가지 `me-screen` 의 커밋 제목)*

## 사실 — 이미 내려진 결정 (원장님 · 앞선 3자 합의)

10. **통합 탐험 결정문(2026-09-26 · 원장님 요구로 정함)**:
    «`/learn` 이 유일한 게임 홈 — 첫 화면에 주 실행 버튼 하나» · «기억 · 회복 · 통분 공방 **시작 메뉴는 만들지 않는다**» ·
    «조작 활동은 해당 개념의 학습 도중 **같은 틀 안에서** 등장한다. 새로운 프로그램이나 장소로 이동시키지 않는다» ·
    «하루에 온전한 학습 묶음 하나 — 개념 15활동에 은행 분량을 더하지 않는다» ·
    «정오답은 짧은 오버레이로 알려 주며 **답이나 해설을 자동으로 공개하지 않는다**» ·
    «자동 재도전 세 바퀴 뒤에도 남은 문제는 완료로 꾸미지 않는다. **학생이 요청하면 해설**을 열고 남은 문제만 다시 도전» ·
    «최초 정답 통계와 재해결은 구분한다».
11. **27번 문서(2026-10-01 · 비슷한 외부 보고서를 대어 본 뒤)**: «활동 중 힌트 단계 · 도움받은 성공 — 하지 않는다» · «필수 · 복습 · 선택을 섞은 하루 화면 — 하지 않는다» ·
    «탐험의 답안별 기록 표 — **지금은 안 한다(3:0)** · 교사 화면을 2주 쓴 뒤 답안 정보가 없어 개입을 못 정한 비율이 20% 를 넘으면 다시 연다».
12. 폰은 4지선다 · 번호 키(D-141 · D-145). 별의 원천은 전부 한 번뿐이고 하루 상한 · 추가 쓸 곳이 없다(D-144).
13. 새 화면은 «시안 4 ~ 5안 → 선택 → 정밀 시안 → 선택» 뒤에만 구현한다(D-07). 공유 DB 에 표 · 칸을 더하는 일은 적용 직전에 원장님께 다시 여쭌다.
14. 저장 꼴을 바꾸면 «읽기 먼저 · 쓰기 나중»으로 두 번 배포한다(관례).

## 안건

### S1 — «아직 모르겠어요» 결함(사실 5)을 어떻게 고치나
- ㉮ 빈 답을 «모름 = 그 활동의 오답»으로 받는다(재도전 줄에 넣는다 · 첫 시도 정답으로 세지 않는다). 세 활동 모두 같은 뜻.
- ㉯ 문장 조립 · 경계 살피기에서는 단추를 감춘다(예 모으기에만 둔다).
- ㉰ 그대로 둔다(SRS 재설계 때 같이).

### S2 — 활동 **도중**의 힌트 · 풀이를 여는가 (지시서의 회복 사다리 ↔ 사실 10 · 11)
- ㉮ 지금대로 — 활동 중에는 답도 해설도 없다. 재도전이 끝난 뒤 학생이 요청하면 해설.
- ㉯ **공방(조작 활동) 안에서만** 연다 — 답을 드러내지 않는 조작 도움(«두 막대의 조각 크기가 같은지 보자»)과 틀린 결과를 눈으로 견주는 피드백. 개념 15활동 · 은행 문항은 ㉮ 그대로.
- ㉰ 전부 연다 — 개념 활동 · 은행 문항에도 힌트 → 설명 → 새 문제. 도움받은 성공은 따로 기록(지시서대로).

### S3 — «실습 모드»를 따로 여는가 (↔ 사실 4 · 10)
- ㉮ 지시서대로 — 별도 진입 «오늘의 탐험 · 약 20 ~ 25분» · 여섯 구간(회상 + 퍼즐 + 확장 + 전이).
- ㉯ **기존 공방을 키운다** — 별도 진입 없이, 오늘의 탐험 안에서 그 개념을 배울 때 뜨는 공방에 «합치기 · 오답(분모를 더함)의 눈으로 견주기 · 두 갈래 확장 · 새 문제 혼자»를 더한다. 20 ~ 25분은 재 볼 가설로만 둔다.
- ㉰ 보류 — 학생이 실제로 쓰기 시작해 자료가 쌓인 뒤(사실 8) 정한다. 지금은 S1 · S5 같은 결함만 고친다.

### S4 — 답안별 · 지원 수준 기록을 지금 여는가 (↔ 사실 3 · 11 · 13)
- ㉮ 지금 연다 — 덧붙이기 전용 표(최초 응답 · 지원 수준 · 오류 유형 · 전이 결과). 공유 DB 에 표 추가.
- ㉯ 새 표 없이 **공방 세션 기록 안에만** 최소한을 둔다(단계별 첫 응답이 맞았나 · 도움을 열었나 · 새 문제를 혼자 맞혔나). 개념 15활동 · 은행은 지금 그대로.
- ㉰ 안 한다 — 27번 문서의 조건(교사 화면 2주 뒤 20%)을 그대로 지킨다.

### S5 — 중등 은행 날의 재도전(사실 7)을 어떻게 하나
- ㉮ 지금대로.
- ㉯ 재도전에서도 «아직 모르겠어요»를 보이고, 재도전을 **두 바퀴** 돈 뒤에도 남은 문항은 **학생이 요청하면 풀이**를 연다(서버가 이미 내려주는 `solution` 을 그린다).
  풀이를 본 문항은 «도움 후»로 남기고 칸은 미해결 0 이어야 얻는다는 규칙은 그대로. 간격은 이미 첫 풀이에서 정해졌으니 안 바뀐다.
- ㉰ 재도전 첫 오답부터 풀이를 연다.
- ㉱ 재도전에서 «모르겠어요»만 되살리고 풀이는 그대로 둔다(누르면 줄 끝으로).

## 답의 형식

안건마다: **고른 안** · 근거 3줄 안팎 · 그 안의 가장 큰 위험 하나.
끝에 한 단락: **코딩 에이전트에 넘길 첫 일감의 범위**를 한 문장으로(무엇을 하고 무엇을 하지 않는가). 요청서에서 틀렸거나 빠졌다고 보는 사실이 있으면 적어라.
