# 관리 콘솔·지점 관리 통합 검증

2026-10-03. [최종 계획](../../admin-branch-upgrade-20261003.md), [Codex·Claude·Grok 합의](admin-branch-consensus-20261003.md).

## 구현 결과

- 관리 콘솔 첫 화면은 지점 목록이다. 지점 안에서 계정 검색·승인 상태·정지/삭제 목록과 계정 검토를 수행한다. 미소속 계정은 별도 목록에 모은다.
- 지점 상세의 ‘사용 메뉴’에서 수학·영어 체크리스트를 저장한다. 원장·관리자·강사와 지점 소속 최고관리자의 업무 메뉴에도 같은 지점 제한을 적용한다. 최고관리자 운영 콘솔과 기존 원장 관리 경로는 유지한다.
- 실제 메뉴는 지점 허용, 개인 허용, 기존 듣기 시범 조건의 교집합이다. 지점에서 끈 항목은 개인 화면에 해제 상태와 사유를 표시하지만 개인 선택 자체는 보존한다. 이름만 수정할 때 개인 메뉴를 다시 저장하지 않는다.
- 계정 상세 URL에 지점 맥락을 포함한다. 기존 계정 URL은 실제 소속으로 연결하고, 잘못 조합한 지점/계정 URL은 404다. 계정 이동 성공 후 새 소속 상세로 이동한다.
- 지점 메뉴 저장은 revision 충돌을 409로 알려 준다. 메뉴·계정·비밀번호 변경과 감사 기록이 함께 성공하거나 함께 롤백한다. 비밀번호 재발급은 수정 시각과 현재 소속을 함께 검사한다.
- 기존 eywa 소속 잠금, 마지막 원장 보호, 학생 학습 경로와 자료 소유권은 유지했다.

## 통합 검증

초기 통합 커밋 `3171fd64f`에서 34개 파일·527개 테스트가 통과했고, 원격 main의 교재 제작·계정 연결 상태와 `2adb8b193` 학생 인증 수정까지 병합한 뒤에는 **38개 파일·607개 테스트가 모두 통과**했다. 실제 로컬 PostgreSQL 검사 12개도 새 교재 메뉴 CHECK를 포함한 통합 코드로 다시 통과했다. TypeScript·변경 파일 ESLint·affordance 검사와 운영용 빌드가 통과했다.

실제 로그인과 로컬 PostgreSQL을 연결한 Chromium 검사에서 다음을 확인했다.

- 지점/미소속 계정 목록과 모든 상태 집계의 범위, 잘못된 필터 거부.
- 접속 중인 원장과 지점 소속 최고관리자에게 지점 메뉴 변경 반영, 다른 지점 영향 없음.
- 영어 앞의 세 메뉴를 꺼도 지점에서 허용한 듣기·자료은행은 독립적으로 이용 가능.
- 직접 API·인쇄 경로 차단, 개인 선택 보존과 지점 메뉴 재허용 후 복구.
- 동시 저장 하나만 성공, 오래된 계정 이동 전 화면의 비밀번호 변경 거부.
- 기존 상세 URL 이동, 지점/계정 불일치 404, 마지막 원장 삭제 방지.
- 모든 업무 메뉴를 꺼도 허용된 관리 경로는 유지되고 학생의 기존 학습·듣기 조회는 계속 가능.
- 좁은 화면의 메뉴 설정과 키보드 방향키 탭 이동, 브라우저 런타임 오류 없음.

운영용 빌드를 로컬에서 실행해 계정 목록이 로드된 데스크톱·모바일 화면, 원장 개인 메뉴 저장/복구, UI 계정 이동과 새 소속으로의 연결, 비밀번호 재발급, 실제 동시 수정 409 표시와 최신 설정 복구까지 확인했다.

`2adb8b193`까지 반영한 마지막 운영용 빌드에서도 전체 10개 브라우저 흐름을 다시 통과했다. 빌드 재검사 중 개발 서버가 남긴 Prisma DLL 잠금과 `.next/dev`의 별도 타입 생성물을 정리했다. 제품 타입 검사나 빌드 관문을 비활성화하지 않았다.

최신 main 병합에서는 계정 연결 상태 표시와 지점 메뉴 응답을 함께 유지했다. 새 교재 메뉴의 순서를 테스트에 반영하고, 영어 경계 검사에는 검토된 교재 서버 조회와 연동 migration 도구의 정확한 파일만 추가했다. 학생 클라이언트의 DB 접근과 교사 영어 계약 유출은 계속 차단되는지 변이 검사로 확인했다. 인증 변경 뒤에도 학생 경로와 교직원 지점 정책 검사를 함께 실행했다.

검증 로그와 가상 계정 화면은 로컬 `.qa-artifacts/branch-admin/`에 보관한다. 비밀번호·접속 문자열이 포함된 fixture와 연결 파일은 Git에 추가하지 않는다. Docker와 유료 AI API 호출은 사용하지 않았다.

## 데이터 적용과 호환 범위

대상 migration은 `20261003170000_branch_admin_menu_policy`와, 최신 main의 교재 메뉴를 지점 CHECK에 추가하는 `20261003230000_branch_menu_textbook` 두 개다. Branch 차단 목록의 기본값은 빈 배열(전체 허용), revision은 1이다. 기존 계정별 정책을 초기화하지 않는다. Branch/User의 공개 클라이언트 권한을 회수하고 RLS를 활성화하되 기존 서버 역할의 접근은 유지한다. 관련 없는 migration 이력은 검사만 하고 변경하지 않는다. 운영 User CHECK는 이미 `textbook`과 `english-bank`를 모두 허용함을 별도로 확인했다.

두 migration은 운영 프로젝트 `jyaguxwuaxgdnovtulna`에 적용·검증 완료했다. 기존 지점 2개·계정 13개의 수와 개인 정책/소속/관리자 표식 해시가 전후 동일했다. 지점은 모두 전체 허용으로 시작하며 사용자가 직접 체크값을 결정한다. `anon`·`authenticated`의 User/Branch 읽기가 실제 거부되고, 기존 서버 역할의 접근은 유지됨을 확인했다.

첫 운영 DDL 시도 두 차례는 기존 자동 동기화의 60초 트랜잭션과 겹쳐 5초 lock timeout으로 롤백됐다. 해당 작업의 담당 세션과 진단 시점을 조율한 뒤 기존 트랜잭션이 끝나는 시점에 적용했다. 자동 동기화를 끄거나 다른 DB 세션을 종료하지 않았다. 마지막 적용에서도 검사 실패 시 전체 롤백하는 동일 가드를 유지했다.

개인 메뉴 저장의 기존 영어 호환 규칙은 유지했다. 개인 설정에서 영어 기존 세 메뉴를 모두 끄면 듣기·자료은행도 차단하는 과거 의미 때문에, 새 개인 설정으로 듣기/은행만 단독 선택하려는 조합은 안내와 함께 거부한다. **지점 체크리스트는 이 제약 없이 듣기/은행만 따로 허용할 수 있다.** 이 제한을 없애려면 별도 개인 정책 버전 전환이 필요하다.

세 Orca 작업의 소스는 main에 병합했다. 작업 종료·깨끗한 상태·병합 여부를 확인한 뒤 해당 작업트리만 제거했고 Git 브랜치는 보존했다. 다른 진행 중 작업트리는 유지했다. 사용자 요청에 따라 매 push 직전 fetch·원격 비교·병합·관련 재검증 규칙을 AGENTS.md에 기록했다.
