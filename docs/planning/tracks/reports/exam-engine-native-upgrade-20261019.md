# 기출 분석의 엔진 반영 — 2026-10-19

기출 feature에서 기존 main의 도형·생성·출처 계약을 유지하며, 정확값 보기 검사·저장된 imagegen 자산 지원·기출 변형의 사용 잠금 계승을 실제 코드에 연결했다. 운영 적재·배포는 하지 않았다. 전체 기출 추출이나 기존 30개 엔진 개선 항목의 완료 선언이 아니다.

## 구현된 경로

- `deriveFormats`의 정확값 중복 방지에 이어 `expandFamily`가 생성기 자체의 객관식을 받을 때도 같은 검사를 수행한다. 정답이 유일하더라도 오답 둘이 `√8`과 `2√2`처럼 같으면 거부한다. 은행의 실제 보기 파서를 사용한다. 읽을 수 없는 문자식·다항식·일반 도형 관계를 증명한 것으로 세지 않는다.
- 기존 `renderFigureSpec` 진입점은 `authored-image-panel/v1`을 구분하고 서버가 제공한 저장 자산만 렌더한다. 요청 JSON에는 자산 ID 및 PNG·수학 조건·제작 기록·프롬프트 해시만 들어간다. 외부 URL·클라이언트 SVG·이미지 바이트 삽입 필드는 허용하지 않는다. 일반 벡터 엔진의 이미지 금지는 변경하지 않았다.
- 새 어댑터는 PNG 해시, 청크/CRC·표시 크기·헤더 형식, 제한된 압축 해제 결과와 행 필터까지 검사한다. 최초 지원은 2MiB 이하, 4,194,304픽셀 이하, 비인터레이스 8비트 회색/RGB/알파 PNG이며 다른 형식은 보류한다. 실제 삽화 픽셀은 변경하지 않는다.
- 삽화는 상황 표현만 맡는다. 별도 기존 엔진 도형, 학생 본문, 수치·관계·양수/정의역 조건, 변형 전략·공유 개념·핵심 풀이, 실제 Unit/family/분류 스냅샷을 하나의 수학 조건 해시에 연결한다. 본문·도형·수치·프롬프트·제작 기록이 변경되면 이전 요청/검수 기록은 새 버전을 통과시키지 못한다. 픽셀을 계산 근거로 사용하지 않는다.
- 적용 일정이 확인된 중3·2025–2027만 이 초기 어댑터에 허용한다. 2025/2026은 2015, 2027은 2022이며 다른 학년/연도는 별도 확장·검토가 필요하다. 일정은 [교육부 고시 안내](https://www.moe.go.kr/boardCnts/viewRenew.do?boardID=141&boardSeq=93458&lev=0)와 대응한다. 일정 일치는 개별 문항의 범위 승인과 별개다.
- 학생의 7개 표면과 학년 내 정당한 방법, 수학·분류·권리·유사성·native 표시를 각각 검토한다. 현재 버전의 학년 제외 판정은 미리보기에서도 차단하고, 빠진 근거는 보류한다. 검토용 미리보기와 검수 완료 자산 표시를 구분한다. 어느 렌더 성공도 문제 승인/DB 적재 허가가 아니다. 앱에서 스킬/API를 호출하거나 과금 경로로 전환하지 않는다.
- `transform/adopt`는 원본/문항류 대표의 잠금과 실제 출처 사슬을 확인한다. 기출 원문, 기출을 조상으로 둔 예전 변형, 이미 잠긴 원본, 확인되지 않은 출처 사슬에서 새로 저장하는 후보는 `directUseAllowed=false`다. 원문 답 재현이 맞았다는 이유로 새 쌍둥이를 열지 않는다. 이 경로는 독립 풀이·학년·권리 검수를 마친 전용 쌍둥이 적재기를 대체하지 않는다.
- 검수 출력은 정션 여부와 관계없이 `node_modules`와 `.git` 아래에 만들 수 없다. 기존 작업자의 의존성 미연결 상태에서 드러난 보호 시험도 이 실제 보호 규칙으로 해결했다. 기존 증거를 덮어쓰지 않는다.

## 실제 자산·검수 확인

`verify-authored-image-support.ts`로 이미 내장 imagegen으로 제작한 범일 q10/q19의 새 어댑터 미리보기를 만들었다. 두 PNG 원본 픽셀이 바이트까지 보존됐고, 두 관계도는 기존 Python/MathJax 도형 엔진으로 strict 모드에서 다시 그렸다. 새 제작이 아니므로 기존 imagegen 2개 집계는 늘리지 않는다. 새 어댑터/표시 버전에는 이전 후보 승인을 복사하지 않았고, 둘 다 검수 완료 표시 요청이 차단됐다.

설치된 Edge의 실제 이미지 디코드와 70mm 표시 폭(264.5625px), 네 개 패널, 미해결 수학 라벨 0개를 확인하고 스크린샷을 검토했다. 이 것은 검토 지면 QA이며 모든 은행/API/인쇄 경로의 승인이나 물리 출력 시험이 아니다. q10의 58° 외부 라벨은 각호에서 나오는 곡선 지시선으로 연결되는 기존 엔진의 의도된 표현임을 별도 작업자가 확인했다.

독립 코드 검토가 CRC만 맞는 깨진 PNG의 통과를 발견했다. 해당 입력, 잘못된 비트 깊이/팔레트/행 필터, 압축 해제 초과를 차단하는 회귀시험을 추가했고, 작업자가 원래 반례의 거부를 다시 확인했다. 최초 실패·검토 보고서와 이후 버전을 보존했다.
