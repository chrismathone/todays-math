# 자료은행 합의안 — Claude·Grok 재검토 반영 완료

2026-10-03. Codex·Claude·Grok 1차 검토와 양측 재검토를 반영했다. Grok은 구현 계약 1–10에 동의했고, Claude도 열 가지 결정에 동의하면서 C1–C4 보완을 요청했다. 아래에 네 보완과 실측 결과를 기록했다. 구현은 이 합의문을 따른다.

## 고정된 사용자 결정

자료은행은 A 목록+상세, 지문/듣기 탭, 기존 웹앱의 컴포넌트·색상·글꼴을 쓴다. 은행은 합의 후 구현한다. 문항에 맞는 자체 그림 소재를 준비한다. 자체 장소 그림 한 장(5개 패널)을 기존 sample-01의 2번 문항에 맞춰 생성했으며, 이는 교사 검토용 파일이지 학생 발행이나 개별 보기 자산 등록 완료가 아니다.

## 이번 구현 계약

1. **독립 지문:** `EnglishPassage`에 `userId` 관계와 CAS `revision`, 본문 `textRevision`, 제목·학년·출처·원문·중복해시·권리·가져온 참조·보관 해제 시각을 둔다. `EnglishPassageRevision`은 불변 본문·정확 해시를 갖는다. 제목·출처 수정은 CAS만, 본문 수정은 본문 개정도 증가한다. 모든 은행 쓰기는 소유 범위를 재확인한다. 수학·일반 작업실 표는 쓰지 않는다.
2. **보존:** 시험 FK로 은행 원문을 삭제하지 않는다. 은행 삭제는 보관 해제이며 과거 개정·사용한 세트는 보존한다. `EnglishPassageUse`는 사용한 세트와 본문 개정을 연결하고 제작 당시 원문·출처의 사본을 저장한다. 세트 삭제는 사용 연결만 지운다.
3. **기존 V1 연결:** 세트 `meta.passageRef`에 `{passageId,textRevision,snapshotHash}`를 추가한다. 이 필드는 새 V2 문서가 아니다. 세트 POST가 트랜잭션 안에서 참조 소유·개정·원문 입력을 검증하고 사용 사본을 기록한다. 변형 세트는 생성된 지문이 아닌 실제 입력 원문과 대조한다. `clientKey` 재시도에 다른 원문 참조를 끼우면 409다. 교사가 입력문을 바꾸면 은행 참조를 해제하고 사유를 표시한다.
4. **길이:** 은행 저장은 30,000자. 기존 세트 24,000자, 외부 생성 18,000자를 유지한다. 원문 복원은 24,000자까지, ChatGPT/API 제작은 18,000자까지로 경로별 준비 검사를 한다. 초과 본문은 자르지 않고 차이를 안내한다. 긴 원문을 `meta.sourcePassage`에 억지로 넣지 않고 사용 사본에 보존한다.
5. **등록·가져오기:** 직접 입력/TXT, 기존 자료·기존 생성 지문의 명시적 선택을 지원한다. 서버가 원본을 읽고 원본 경로 권한도 검사한다. 기존 세트는 `sourcePassage`와 제작 지문을 구분하며 원문 정보가 없으면 자동 추정하지 않는다. TXT의 잘린 content를 원문으로 옮기지 않고 bytes와 대조한다. PDF/DOCX에서 텍스트가 없으면 이유를 안내한다. 사용자+가져오기 키로 동시 요청도 멱등 처리하고 다른 본문에 같은 키면 409다. 같은 원본·본문의 재가져오기도 기존 항목으로 안내한다.
6. **중복:** NFC·공백 정규화 해시는 같은 소유자 안의 후보를 찾는 데만 사용한다. 전역 유니크·자동 병합 없음. 원문은 정규화 전 글을 보존한다.
7. **권리:** 새 자료와 가져온 자료는 미확인으로 시작한다. 소유 범위 내 교사의 별도 확인 명령에서 근거·허용 용도·확인자·시각을 기록한다. 은행에서 문제 제작에는 generation_input, 외부 모델로 보낼 때에는 external_model도 확인한다. 기존 시험 화면의 은행과 무관한 세트를 전면 차단하는 변경은 하지 않는다. 무료 공개가 이용 허락이라는 기본값은 금지한다.
8. **검색:** 제목·본문·학년·출처를 서버 필터링하고 안정적인 정렬과 페이지 나누기를 제공한다. 목록에는 bytes/전체 원문을 싣지 않는다. 상세에서 본문·사용 이력을 읽는다. 시험이 없어도 은행은 열린다.
9. **듣기:** 기존 `/sets` 배열 응답을 유지하고 은행용 서버 검색 경로를 추가한다. 자체 세트 상세·재생·검수·수업은 기존 작업대를 연다. 은행에서 기존 초안을 조용히 덮지 않는다. EBS 카탈로그는 별도 공식 참조 목록이며 공식 페이지를 연다. 원본 파일을 우리 서버로 받거나 teacher_authored로 저장하지 않는다.
10. **메뉴:** 새 `english-bank`는 기존 `english` 허용값에 자동 추가하지 않는다. 기존 영어 전체 차단에는 포함한다. 은행 권한과 듣기 시범 권한은 별개다. 듣기 탭/조회는 기존 듣기 허용과 시범 조건을 모두 지키고, 은행 등록이 공유 범위를 넓히지 않는다.

## 그림의 적용 순서

은행 기능의 완료와 그림 문항 발행을 같은 것으로 보고하지 않는다. 이번에는 문항에 맞춘 자체 소재와 제작 기록을 보존하고 교사 검토용 시범을 제공한다. 현재 `{id,text}` 계약에는 이미지 데이터를 몰래 넣거나 무시하지 않는다.

그림 지원은 선택지별 삽화와 문항 공통 상황 그림·표를 구분한 계약으로 진행한다. 지도·시계·표는 결정적인 데이터+렌더러, 사물·장소·행동은 이미지 생성 도구가 담당한다. 소리로 나오는 선택지 대사는 별도 교사 필드로 두며 잠긴 학생 보기 text에 넣지 않는다. 자산은 ID+해시로 고정하고 교체하면 새 자산 및 검수 무효화다. 출처·프롬프트는 학생에게 보내지 않으며 대체 설명은 시각 정보만 동등하게 설명한다.

학생 발행을 열기 전에 저장 계약·인증된 이미지 전달·학생 projection·검수 해시·발행 사본·학생 화면·인쇄를 함께 검증한다. 이번 은행 변경에서 초안 이미지 필드만 추가하고 발행 가능한 것처럼 표시하지 않는다. 실제 그림 문항 편집·학생 발행은 이 별도 변경이 완료되기 전까지 미지원으로 명시한다.

## 완료 근거

격리 PostgreSQL의 동시 수정·멱등 가져오기·수명·소유 범위·불변 개정, 경로/권리/길이 테스트, 기존 영어·듣기 회귀, 타입·린트·빌드, 브라우저 등록→검색→문제 제작→저장→원문 사용 이력 왕복과 듣기/공식 링크, 모바일·키보드. 운영 스키마 변경안은 새 은행 표 추가와 `user_disabled_menus_valid` 허용값 확장이다. 기존 자료 일괄 이관은 하지 않는다. 실제 실행한 검증과 미실시 항목을 보고서에 구분한다.

## Claude C1–C4 반영

1. 관련성 비교는 기존 `normalizeEnglishText`의 공백 접기에 NFC를 더한다. `snapshotHash`는 불변 개정의 정확 본문 해시다. 사용 사본은 서버가 개정 행에서 읽으며 요청 본문을 원문으로 믿지 않는다. 사용 행은 setId 유일이고 세트 저장과 같은 트랜잭션에서 생성한다. 같은 저장 재시도에서는 추가하지 않는다. 관련 세트와 사용 사본은 그 세트의 부모 시험 소유 범위도 검사한다.
2. 24,001–30,000자 지문은 이번 버전에서 **보관·열람 전용**이다. 제작 연결이 안 된다는 설명을 상세에 표시한다. 발췌 기능은 이번에 구현하지 않으며 필요하면 사용자가 발췌문을 별도 지문으로 등록한다. 제작 왕복 검증은 해당 경로 상한 이내의 지문을 대상으로 한다.
3. 운영 변경은 새 표와 메뉴 CHECK 확장 둘이다. 기존 CHECK가 영어 하위 메뉴 차단 저장을 막는 실제 결함을 함께 고친다. 새 자료은행은 기존 deny-list 정책대로 전체 영어 차단이 아닌 승인 계정에 기본 표시되며, 독립 메뉴로 끌 수 있다. 기존 전체 영어 차단은 계속 적용한다. 기존 데이터는 재작성하지 않는다.
4. 형식이 틀린 참조는 400, 없거나 소유 범위 밖이면 구별되지 않는 `CONFLICT`+`details.reason=PASSAGE_UNAVAILABLE`, 범위 안의 본문 불일치는 `PASSAGE_TEXT_MISMATCH`로 409를 반환한다. 실패 시 세트·사용 행은 만들지 않는다. 화면은 초안을 보존하고 연결 해제 후 새 키로 저장할 수 있게 한다.

은행 보관·열람은 권리 미확인에서도 가능하다. 제작 이용 근거 확인은 은행 경로에만 적용하며 전체 붙여넣기 경로까지 통제한다고 표현하지 않는다. 확인자는 세션에서 정하고 출처·권리 변경 시 확인을 비운다. 듣기 검색은 UUID 단건과 겹치지 않는 `/api/english/listening/bank`를 사용하며 EBS 참조는 서버에서 공식 페이지 필드만 골라 반환한다.

## 쟁점의 조정 근거

- 상한 24,000/30,000: 보관과 제작을 분리해 30,000자를 보존한다. 잘린 TXT 사본 검사와 제작 경로별 24,000/18,000자 검사를 모두 구현한다.
- 연결 meta만/별도 사용 표: 원문 변형에서는 세트의 passage가 원문 사본이 아니므로 불변 원문과 제작 당시 출처를 사용 표에 함께 남긴다. V1 meta는 작은 참조만 추가한다.
- 불일치 참조를 버리고 저장/409: UI에서 사용자가 바꾼 입력은 참조 해제를 표시하며, 서버에 틀린 참조가 도착하면 409로 알려준다. 저장 성공처럼 보이면서 원문 이력을 잃지 않는다.
- 파생 메뉴/새 메뉴: 은행 권한을 독립적으로 관리할 수 있게 새 키를 쓰되 옛 영어 전체 차단과 듣기 시범 차단을 보존한다. DB CHECK도 함께 갱신한다.
- 권리 표시만/실행 검사: 은행의 새 재사용 경로에 한해서 별도 교사 확인과 용도 검사를 연결한다. 기존 모든 세트를 소급 차단하지 않는다.
- 그림: 공통 합의 후보는 S0 자체 표본부터다. 런타임 이미지 필드만 급히 더하는 구현은 이번 은행 릴리스에 넣지 않는다.

### 메뉴 결함 실측

Codex가 `npx vitest run src/__tests__/unit/workspaceMenuConstraint.test.ts` 실행: 기존 테스트 2개 실패. 메뉴 배열/DB CHECK 및 legacy `english` enum 차이가 원인이다. 운영 DB를 **읽기 전용 트랜잭션**으로 조회한 결과, `user_disabled_menus_valid`는 실제로 legacy `english`까지만 허용하고 `english-school`, `english-maker`, `english-library`, `english-listening`을 포함하지 않았다. 운영 변경은 이 조회에서 하지 않았다.

수정 시 DB CHECK는 현재 메뉴와 legacy `english`를 모두 허용해 옛 차단 값을 보존한다. 테스트는 `workspaceMenuSchema`의 호환 입력과 실제 표시 메뉴를 구분하되, 새 실제 메뉴가 CHECK에서 빠지면 계속 실패하도록 바꾼다. DB 제약 갱신을 앱 배포보다 먼저 적용한다.

**재조회:** 초기 조회 뒤 같은 프로젝트(`jyaguxwuaxgdnovtulna`)를 다시 읽었을 때 영어 하위 메뉴와 `textbook`이 CHECK에 추가된 정의를 관측했다. 이 작업에서는 운영 쓰기를 실행하지 않았다. 영어 하위 메뉴 차단을 가진 계정은 재조회 시 0건이다. 따라서 초기 결함 기록은 당시 관측이며 현재도 그대로라고 단정하지 않는다. 이번 마이그레이션은 관측된 `textbook` 호환값도 보존하고 `english-bank`를 더한다. 적용 직전 정의와 영향 행 수를 다시 확인한다.
