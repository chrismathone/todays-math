## 1. 저장

만들기 화면과 세트 POST 만 바꾼다. 유형 목록, 프롬프트, 지면, `quality.ts` 는 건드리지 않는다.

**문항 수.** `EnglishMakerView` 의 선택지는 `[3, 5, 8]` 이다. 계약은 1~8 을 받고, 고른 유형 수보다 문항 수가 작으면 거절한다. 선택지에 6 을 넣는다. 유형이 들어오는 두 길, 첫 상태와 «이 시험의 출제 설정 불러오기», 에서 허용 유형을 정한 뒤 문항 수가 유형 수보다 작으면 선택지 가운데 유형 수 이상인 가장 작은 값으로 올린다. 여섯 유형이면 6 이다. 시험은 두 길을 다 본다.

**다시 저장.** 생성을 다시 하는 길은 API 뿐이다. 붙여넣기는 저장이 성공해야 글을 지우고, 원문 복원 칸은 남는다. 다만 다시 누르면 초안이 새로 생겨 키가 바뀐다.

세 길은 세트 POST 전에, 검증을 통과한 초안·그때의 meta·`clientKey` 를 한 묶음으로 화면에 둔다. «다시 저장»은 그 본문만 다시 보낸다. 그 사이 폼의 소재나 유형을 바꿔도 재전송 본문과 키는 그대로다. API 생성 실패에는 «다시 저장»을 보이지 않는다. 저장 503 은 AI 연결 상태를 «대기»로 바꾸지 않는다. 저장이 성공하면 그 묶음을 지우고 검토 화면으로 간다. 원래 단추를 다시 눌러 같은 초안이 나오면 같은 키를 쓴다.

**같은 키는 행 하나.** `englishSetMetaSchema` 는 `strictObject` 다. `clientKey`(uuid, 선택)를 넣지 않으면 거절된다. 만들기 화면이 초안마다 하나를 만든다.

세트 POST 는 지금 매번 `create` 다. `meta` 에는 유일 색인이 없다. 조회 뒤에 생성만 두면 동시에 도착한 두 요청이 둘 다 통과한다. 소유권 확인과 입력 검증은 유지하고, 그 시험 행을 트랜잭션 안에서 잠근 뒤 같은 트랜잭션에서 키를 조회하고 만든다. 마이그레이션은 없다. 같은 키의 두 번째 요청은 저장할 `title`·`source`·`passage`·`questions` 가 같으면 200 으로 그 행을 돌려준다. 하나라도 다르면 409 이고 덮어쓰지 않는다. 비교는 계약 검증을 거친 값이다. 문항은 순서와 모든 칸을 보고, JSON 키의 나열 순서는 보지 않는다. 기존 행을 돌려줄 때 `status`·`revision`·`meta` 를 초기화하지 않는다. 키가 없으면 지금처럼 201 이다. 다른 시험의 같은 키는 별개의 행이다.

이 잠금이 막는 것은 같은 키의 동시 요청과, 응답이 끊긴 뒤의 재시도다. 화면의 저장 중 단추 잠금은 그대로 둔다. 메모리 대역이 트랜잭션을 구현하지 않으면 그 시험으로 데이터베이스 동시성을 입증했다고 적지 않는다. 순차 재시도(생성 1회, 세트 POST 2회, 행 하나)는 반드시 본다.

**자료 이름.** 자료 이름은 255 자이고 `materialName` 만 200 자다. 상한을 255 로 올린다. 255 자는 저장되고 256 자는 거절된다.

시험 파일: `EnglishMakerView.test.tsx`, `englishSets.test.ts`, `englishSetMeta.test.ts`. 기존 저장·meta 시험은 그대로 초록이어야 한다. 세트 PUT 뒤에 `clientKey` 가 응답에 남는지 포함한다. PUT 은 meta 를 갱신하지 않는다.

## 2a. 어휘 — 읽기·검사·밑줄

생성 목록에 어휘를 넣는 순간 `ENGLISH_TYPE_GUIDE` 가 `Record<EnglishGeneratedType, string>` 이라 안내 줄이 없으면 `tsc` 가 깨진다. 벤치 `promptV1.ts`·`promptV2.ts`·`promptV3.ts` 도 같은 `Record` 다. 그래서 이 조각에서는 어휘를 `ENGLISH_QUESTION_TYPES` 에만 넣고, «원문 복원»과 같이 `ENGLISH_GENERATED_TYPES` 에서 뺀다. 생성 요청, 출제 설정, 만든 조건의 유형 배열, 프롬프트에는 나오지 않는다. 저장된 세트로 읽는 시험은 가능하다. 옛 여섯 유형 세트를 열고 인쇄하는 회귀를 이 조각의 첫 시험으로 둔다.

**정답 검사.** `quality.ts` 의 변형 진입 목록에 어휘를 넣으면 어법과 같은 토큰 정렬을 탄다. 그 검사가 보장하는 것은 «원문과 다른 곳이 하나이고, 그 자리가 정답 번호와 닿는다»까지다. 밑줄이 실제로 다섯인지, 보기가 그 밑줄과 같은지, 바뀐 것이 어휘인지 어형인지는 보장하지 않는다. 저장은 막지 않는다.

어휘 고정물은 따로 둔다. 통과 표본은 밑줄 ①~⑤ 가 실제 `<u>` 구간과 대응하고, 각 보기가 그 밑줄과 같고, 정답이 아닌 네 구간이 원문 그 자리에 있고, 정답 구간만 다르다. 실패 표본은 번호 누락·중복, 보기와 밑줄 불일치, 두 곳 변경, 틀린 정답 번호다. 문장에는 «어휘»를 쓰고, 어법 메시지 문장은 고치지 않는다.

**누출.** `leak.ts` 의 `VARIANT_TYPES` 에 없으면 `answerSpan` 을 고쳐도 검사에 닿지 않는다. 목록과 밑줄 분기 둘 다에 어휘를 넣는다. 어휘의 답 위치는 틀리게 보여 준 낱말이 아니라, 원 지문에서 그 자리가 차지하던 원래 표현이다. 앞뒤 문맥을 붙인 20 자 이상 토큰 창으로 다른 변형 문항 발문과 비교한다.

`bundle.ts` 의 목록은 지우고 `leak.ts` 의 목록을 가져다 쓴다. 두 벌이면 한쪽만 고쳐도 시험이 초록일 수 있다.

시험은 개수를 세지 않는다. 어휘 → 빈칸 짝이 있고 `kind` 가 «어휘»이며, 근거 구절이 원래 표현을 담고 20 자 이상이다. 양방향 표본은 두 짝으로 확인한다. 원래 낱말만 같고 문맥이 다른 표본은 누출이 아니다. 목록이나 밑줄 분기를 빼면 이 시험이 실패한다.

**묶음.** 어휘는 변형이다. 독해 묶음의 원 지문 상자와 나뉜다. 유형 이름만으로 어법과 어휘가 다른 묶음이 되지는 않는다. 서로 원래 표현을 보여 주는 붙여넣기 표본은 `findVariantLeaks` 결과로 묶음이 나뉘고, 순환으로 남는 짝은 `open` 과 지금 안내 문장에 남는다. 분류만으로 누출이 해결되었다고 적지 않는다.

**밑줄.** 밑줄 유형은 한 상수(어법 · 어휘)로 두고 `underline.ts` 와 `EnglishPromptText` 가 같이 쓴다. 알림 세 줄의 «어법 문항»은 «밑줄 문항(어법 · 어휘)»처럼 둘을 다 덮는 말로 바꾼다. 어휘를 빼면 `<u>` 가 종이에 글자로 찍히고, 잠금 알림이 어휘를 어법이라고 부른다. 밑줄이 아닌 어법의 인쇄 허용과, 다른 유형에 남은 꺾쇠를 글자 그대로 찍는 규칙은 유지한다.

**보기 줄.** `options.ts` 는 유형을 보지 않는다. «①<u>» 꼴이면 이미 보기 줄을 생략한다. 유형 분기를 넣지 않는다. 시험만 하나 더한다. 어휘 문항이 그 표기와 번호뿐인 보기를 가지면 보기 줄이 없고 번호가 한 번만 찍힌다.

**검수.** `src/app/dev/print-check/items.ts` 에 어휘 밑줄 항목을 더한다. 기준은 어법과 같다. 꺾쇠 글자가 보이지 않을 것, 내림 글자에 선이 닿지 않을 것. 상태는 «대기»다. 어법 밑줄 항목도 아직 «대기»이므로 같은 출력에서 둘을 같이 본다.

이 조각이 끝날 때까지 생성 요청·출제 설정·프롬프트에는 어휘가 없다.

## 2b. 어휘 — 생성

2a 시험이 초록인 뒤에, 한 커밋에서 한다.

- `ENGLISH_GENERATED_TYPES` 에서 어휘 빼기를 걷는다.
- `ENGLISH_TYPE_GUIDE` 에 어휘 줄을 넣는다. 문제용 지문은 `prompt` 안, `passage` 는 원 지문, 밑줄은 `①<u>표현</u>`, 보기 다섯은 그 밑줄과 대응, 정답은 번호 문자열, 원래 표현이 다른 문항의 문제용 지문·발문·보기에 드러나지 않게. 공통 규칙 1·4·5·10 의 문장은 고치지 않는다. 그 줄들에 어휘가 없으므로 안내 줄이 그 조건을 같이 말한다. 어법 안내 줄은 고치지 않는다.
- API 시스템 프롬프트와 ChatGPT 제작 요청은 그 안내를 같이 읽는다. 수정 요청문은 허용 유형 이름만 읽으므로 생성 목록이 열리면 같이 들어간다. 원문 복원은 `makeCloze` 라 이 안내를 쓰지 않는다.
- `ENGLISH_EXAM_PROMPT_VERSION` 을 올린다. `englishGenerate.test.ts` 가 `"v3"` 를 기대하므로 그 기대값도 바꾼다. 벤치에 탈락한 `promptV4.ts` 가 있어 «v4»는 쓰지 않는다. 벤치 `promptV1~V3.ts`, `score.ts`, `tasks.ts`, `compare.ts` 는 여섯 유형 목록에 고정해 지난 벤치 재현과 `tsc` 를 지킨다.

**어법과 어휘를 같이 고르는 일.** 생성 목록이 열린 뒤에 만들기 화면에 건다. 유형이 들어오는 세 길에 한 함수를 쓴다. 첫 상태, «출제 설정 불러오기», 체크박스. 이미 하나가 선택된 상태에서 다른 쪽을 누르면 새 선택을 받지 않고, 기존 `onNotice` 로 «어법과 어휘는 한 세트에 넣지 않습니다»를 보인다. 둘을 한 배열로 불러오면 그 배열에서 먼저 나온 쪽을 남긴다. 저장 배열은 상수 순서라 클릭 시각이 아니다. 어법이 어휘보다 앞이면 어법이 남는다. 출제 설정 대화상자는 시험이 기억할 목록이라 둘 다 저장할 수 있다.

붙여넣기는 `validatedConditions` 의 유형으로 결과를 거절한다. 화면에서 하나를 빼 두면, 둘을 담은 붙여넣기가 그 검증에 걸린다. 그래서 예외는 하나다. 고른 쪽이 어법이면 어휘가, 어휘이면 어법이 결과에 같이 있어도 그 한 유형만 허용한다. 다른 미선택 유형, 문항 수, 요청 유형 누락, 원문 유지, 보기·정답·근거 검증은 유지한다. 수정 요청문도 같은 허용 범위를 쓴다. 시험은 세트 POST 가 아니라 붙여넣기 단추로, 둘을 담은 세트가 저장되는지 본다.

**문서.** `docs/planning/25-english-studio.md` 에 짧은 절을 남긴다. `docs/planning/07-coding-convention.md` 의 결정 번호는 `git fetch` 뒤 `origin/main` 의 마지막 번호 다음으로 한다.

## 3. 나중 — 글의 순서, 무관한 문장

이번 구현에서 코드를 쓰지 않는다. 시안을 고른 뒤의 받아들임 기준만 남긴다. 순서는 시안 → 계약 이름 → 검사·누출·묶음 → 인쇄와 `print-check` 다. 표기는 시안이 정한다. 지금 토큰기는 ①~⑤ 와 `____` 만 표지로 안다.

글의 순서가 지키면 통과인 조건. 보기 다섯은 (A)(B)(C) 의 서로 다른 순서다. 정답 순서로 이으면 원문 문장 차례와 같다. 주어진 글과 세 조각의 합은 원문과 같고, 빠진 문장과 더한 문장이 없다. 발문이 지문 전체를 담으므로 누출의 대상(답을 보여 주는 쪽)이다. 묶음으로도 순환이 남으면 `open` 에 적고 저장은 막지 않는다. 지면은 새 꼴이라 시안 4~5 안을 제품 지면 폭으로 잰 뒤에만 `EnglishPaper` 를 고친다.

무관한 문장이 지키면 통과인 조건. 발문의 문장 넷은 원문 차례 그대로다. 원문에 없는 문장이 정확히 하나이고 그 문장이 정답이다. 그 문장을 빼면 원문과 같다. 그 문항은 누출의 답을 내는 쪽인 동시에, 원문 네 문장을 담아 다른 변형 문항의 답을 보여 주는 쪽이다. `VARIANT_TYPES` 에 넣는다. ①~⑤ 를 문장 앞에 둘지 본문 안에 둘지는 시안이 정한다.

## 4. 하지 않는 일

- 제목·요지·주장·함축을 계약에 넣지 않는다. 넣더라도 `quality.ts` 가 저장을 막지 않는다.
- 서술형에 꼴 선택 칸을 만들지 않는다.
- 어법 안내 줄과 공통 규칙 문장을 조이지 않는다.
- 사람 감사는 이 계획의 완료 조건이 아니다.
- 한컴 COM, 문제은행 `Problem`, 수학 엔진, `worksheetView` 에 영어 세트를 붙이지 않는다.
- 2a 만 배포하고 2b 를 남기지 않는다. 생성 목록과 안내 줄이 갈라진 채 나가면 `tsc` 가 깨지거나 안내가 비어 있다.

## 5. 완료를 가르는 시험

| 조각 | 먼저 실패해야 하는 시험 | 통과로 볼 수 있는 것 |
|---|---|---|
| 저장 | 두 길의 문항 수 6, API 는 생성 1회·저장 2회, 재시도 전 폼을 바꿔도 본문과 키가 유지, 생성 실패에는 «다시 저장» 없음, 같은 키 200·다른 본문 409·키 없음 201, 이름 255 자 | 기존 `englishSets`·`EnglishMakerView`·`englishSetMeta` |
| 2a | 밑줄·보기 대응 실패 표본, 어휘→빈칸 누출 짝, 문맥만 다른 음성 표본, 묶음이 독해와 분리, `<u>` 가 글자가 아님 | 옛 여섯 유형 열기·인쇄. 생성 화면에 어휘 체크박스 없음 |
| 2b | 안내 줄과 판 번호, 붙여넣기 단추로 어법·어휘가 같이 든 세트 저장, 체크박스에서 둘째 선택이 거부 | `npm run type-check`. 어법 안내 줄은 한 글자도 다르지 않음 |

브라우저로 볼 자리. 저장 조각은 만들기 화면에서 저장 실패 뒤 «다시 저장»이 생성을 다시 하지 않는지, 그 사이 폼을 바꿔도 같은 세트가 가는지. 2b 는 편집 화면과 학생용 인쇄 미리보기에서 어휘 밑줄이 어법과 같은지, 보관함 딱지에 «어휘»가 보이는지. 데스크톱과 좁은 폭. 실물 프린터는 `print-check` 가 «대기»인 동안 완료라고 적지 않는다.
