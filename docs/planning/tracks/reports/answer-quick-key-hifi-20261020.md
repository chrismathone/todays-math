## 데이터와 출력 범위

- 기존 Wire B의 자체 제작 25문항 정답 DOM을 정적으로 읽어 HTML에 포함했다. **새 빌드나 수식 렌더링을 실행하지 않았다.** 원래 제품의 `fractionViewFor → MathText`를 통과한 수식 글과 KaTeX 내장 글꼴을 재사용한다.
- HTML 내부 `captured` 데이터에 원본 경로, 원본 커밋 `6c52d6869`, 원본 SHA-256을 보존했다. 답의 일부를 줄이거나 LaTeX 문자열 길이로 칸 수를 정하지 않는다.
- 50·100문항은 같은 25개 답을 반복한 스트레스 표본이다. 분수·식·두 값·단위·긴 문장과 5개 소문항 답을 포함한다. 새 문제은행 데이터나 학생 기록을 사용하지 않았다.
- 해설 포함판은 표가 전부 끝난 뒤 해당 문항 수만큼 정답·해설을 표시하도록 작성했다. 해설 문장은 이 표본을 위한 자체 제작 문장이고, 해설 안 정답 수식은 표와 같은 기존 MathText DOM이다. 이번 문서는 새로 SolutionText를 실행한 결과라고 주장하지 않는다.
- 정답만 판은 해설 노드를 생성하지 않는다. 표가 길면 같은 표가 다음 쪽으로 이어지며 머리·쪽수를 반복한다. 문항 번호는 순서대로 한 번씩 등장하도록 코드에 검사를 넣었다.
- 표 행은 쪽을 가르지 않는다. 해설 제목은 첫 해설과 묶고, 나머지 해설은 문항 단위로 다음 쪽에 넘기는 코드를 작성했다. 제품의 `measure`와 아직 연결하지 않았다.
- 5열, A4 실제 크기, 좌우 15mm·상하 12mm, 정답 12px·1.8을 유지한다. 기본은 55% 미리보기이며 100% 보기와 각 판의 쪽 이동·인쇄 버튼을 둔다.

## 재개 뒤 검증

리드가 재개를 알리면 다음을 **한 단계씩** 수행한다. 지금은 실행하지 않았다.

1. `node scripts/qa/print-templates/review-quick-key-hifi.mjs --resume-after-lead-release`
2. 한 브라우저·한 컨텍스트씩 H1~H5 × 25·50·100을 열어 30개 판의 번호 완전성·순서·정답만 판의 해설 부재·셀·쪽 넘침을 확인한다. 사용 가능 메모리 1.5GiB 미만이면 다음 사례를 시작하지 않도록 했다.
3. 첫 쪽과 100문항 마지막 쪽 캡처를 눈으로 검토한다. 번호 칸과 분수의 위아래 잘림, 병합 후 빈 칸, 해설 시작, 이어지는 머리, 인쇄 쪽 나눔을 본다.
4. 필요한 경우 해당 안만 수정·재검증한 뒤 HTML의 작성 단계 표시와 이 보고를 갱신한다. 실측 JSON은 성공 후에만 만든다.

개별 안만 여는 주소 매개변수: `?variant=h2&count=100`. 검증 시 다섯 안을 동시에 배치하지 않도록 범위를 좁혔다. 일반 비교 화면은 다섯 안을 나란히 제공한다.
