### 1.1 DB 가 지키는 것 (앱이 잊어도 깨지지 않는 것)

- 발행 · 종료 판본과 그 자식(구획 · 배치 · 개념 · 자산 색인 · 산출물)은 못 고친다.
- 자식을 쓴 문장마다 **같은 문장에서** 판본 집계 revision 이 오른다(문장 단위 AFTER 트리거 · 전이 표). 앱은 올리지 않는다.
- 초안 → 발행은 «열린 발행 요청 + 전부 끝난 조판 걸음 + 산출물 셋 + 놓인 배치의 연결 · 쪽 + 예약 상태 QR 0 + 굳은 개념»이 있어야 된다.
- 같은 주인 · 같은 판본만 가리킨다(복합 FK 11). 책마다 초안 하나 · 판본마다 열린 발행 요청 하나 · 확정본마다 게시 영상 하나 · 배치/개념마다 QR 하나(부분 유일 색인 5).
- 확정본 · 바이트 · QR 대상 · 보관본은 만든 뒤로 안 바뀐다. 바이트는 넣을 때 DB 가 sha256 을 다시 계산한다.
- RLS 20표 전부 켬 · 정책 0 · `PUBLIC/anon/authenticated` 권한 0. 트리거 함수는 `search_path = ''`.
- 시각 기본값은 전부 `(now() AT TIME ZONE 'UTC')`(§3 의 6).

### 1.2 서버 경로

- **범위**: 쓰기는 주인만. 동료는 지점에 공유된 **발행본만** 읽는다(공유 · 보는 사람의 지금 지점 · 주인의 지금 지점 — 세 겹).
  `isAdmin` 을 읽는 줄이 없다. 없는 것과 남의 것은 같은 404.
- **멱등**: `runOnce`(사용자, requestId) — 같은 본문이면 그때의 결과, 다른 본문이면 409.
  학생 · 반 · 공유에 기대는 요청(확인 · 배정 만들기 · 회수)은 **지금의 범위를 재전송 기록보다 먼저** 본다(§3 의 7).
- **담기**: 문항마다 출제 자격을 묻는다. 시험지 문항에 확정본이 달려 있으면(`test_problem.snapshot_id`) 그 확정본을 싣는다 —
  같은 주인이면 같은 줄, 다른 주인이면 복제. 살아 있는 은행 문항의 내용 · 그림을 다시 읽지 않는다.
- **발행**: 사전 검사(읽기 · 발행 기준) → 예약(개념 굳히기 · QR 예약 · 걸음 계획) → 걸음(`requestId` 만 받는다 · 임대 CAS · 세 번까지) →
  확정(`requestId` 만 받는다 · 쪽 계획 전수 · QR 다시 읽기(학생용 · 해설 · 펼침면) · 검증기 · 상태는 마지막에).
  브라우저가 보낸 PDF · 쪽 · 해시 · «통과» 표지를 받는 칸이 없다(라우트 시험이 400 으로 잠근다).
- **산출물**: 학생용 · 해설 PDF, 펼침면 PDF, 단일 HTML, 검수 보고, 교환 JSON, 대응표 CSV, 교환 패키지 ZIP(64MB 안일 때).
  만들지 않은 것은 줄도 없다. 패키지는 `GET …/export?format=zip` 이 그때그때도 만든다(초안 포함).
- **구획 미리보기**: `GET …/sections/{sectionId}/preview` — 그 구획과 그 구획이 가리키는 것만 실은 교환 형식. 발행 · 내보내기와 **같은 조립의 부분집합**이다.
  아무것도 쓰지 않는다(QR 을 만들지 않고, 초안의 개념은 응답 안에서만 굳힌 모양이다. 발행본의 개념은 발행 때 굳힌 그대로).
- **새 문항 등록**: 연결 안 된 배치를 은행의 **검수 대기** 문항으로 올린다. 연결하지도 승인하지도 않는다. 만든 은행 문항을 그 트랜잭션 안에서
  다시 캡처해 내용 해시가 같을 때만 남긴다. 그림은 인라인 SVG 하나일 때만(은행의 `figure_svg` 에 글자 그대로) — 스캔 그림은 거절한다.
- **그 밖**: 영상 연결(초안 → 검수 대기 → 게시 · 검수한 해시 = 확정본 해시), 배정, 백지 활동(교사 관찰 · 확인), 재출제(문항마다 확정본을 단다),
  패키지 보관 · 복사, 연결 확정(다시 캡처한 내용 해시가 같을 때만), 백지 소단원 → 교재 개념 조회(`hasFrozen` 포함),
  목차의 개념 강의 참조 검증 · 고를 수 있는 강의 목록, 활동 증거의 표시 정보(읽을 수 있는 책의 이름만).

«엄격한 응답 스키마는 서버 함수 시험이 지나지 않는 층이다» · «멱등 재전송은 권한 검사를 건너뛰는 길이다». 그 문서는 내 범위 밖이라 쓰지 않았다.

**내 작업 폴더에서 낸 사고 하나**(저장소에는 영향 없음): 변이 하네스를 별도 임시 워크트리에서 돌리려고 `node_modules` 를 정션으로 걸었고,
끝난 뒤 `git worktree remove --force` 로 치우면서 git 이 정션을 따라 들어가 **이 워크트리의 `node_modules` 를 비웠다.**
`npm ci --ignore-scripts` 와 `prisma generate` 로 되살렸고(잠금 파일 변화 없음 · 훅 살아 있음) 그 뒤 시험 738 · 실제 조판기 발행을 다시 돌려 통과를 확인했다.
정션을 건 워크트리는 정션부터 떼고 지워야 한다.

## 4. 못 본 것 · 못 잰 것

- **공유 DB(Supabase)** — 닿지 않았다. 역할 · 기본 권한 · 연결 풀러 · 기존 행이 있는 상태에서의 적용은 재지 못했다. 적용기의 «기존 표 행 수»는 빈 DB 의 0 → 0 만 봤다.
- **서버리스에서의 조판** — 실제 조판은 로컬 Chrome 으로만 돌렸다(문항 셋 · 22 ~ 36초). 걸음 하나가 300초 · 메모리 한도 안에 드는지, 큰 책(Codex 의 203쪽 견본은 조판기 단독 158초)이 걸음 계획대로 끝나는지는 **재지 않았다.**
- **64MB 를 넘는 파일** — 합친 PDF · 단일 HTML · 패키지가 한도를 넘는 경로는 시험이 없다(넘으면 걸음이 사유를 남기고 멈춘다. 분권은 없다).
- **실제 은행 데이터** — 전부 시험용 문항이다. 실제 문항의 그림 · 수식 · 긴 해설로는 담기도 조판도 해 보지 않았다.
- **인쇄 실물** — 지면은 Codex · 리드의 범위다. `/dev/print-check` 항목은 내가 더하지 않았다. 실물 검수 전에는 발행 산출물을 «완료»로 적지 않는다.
- **경합** — 여덟 갈래만 쟀다. 걸음 임대의 만료 경합 · 올리기 조각의 동시 쓰기는 PGlite 의 차례 시험뿐이다. 경합 검사는 마지막 코드가 아니라 `aa1aadf34` 무렵의 코드에서 돌렸다(그 뒤 잠금의 차례를 바꾼 것은 재전송 범위의 앞 검사뿐이다 — 다시 돌리지 않았다).
- **origin/main 최신과 합친 상태의 내 시험** — 이 가지에서는 돌리지 않았다(병합은 리드가 통합 가지에서 했다).
- **구획 미리보기를 실제 편집 화면에서** — 응답이 계약과 실제 검증기를 지나는 것까지만 봤다. Grok 의 화면이 그것으로 그리는 것은 보지 않았다.
- 서버 변이는 **건 자리**에 대해서만 말한다. 걸지 않은 가드는 재지지 않았다.

## 5. 리드가 알아야 하는 것(이미 보낸 것의 정리)

① 마이그레이션 `20261003120000_textbook_studio` 는 오늘 **두 번 바뀌었다**(걸음 종류에 `spread` · `offline`, 시각 기본값 UTC).
   옛 내용을 적용한 격리 DB 는 다시 만든다. 공유 DB 에는 적용한 적이 없다.
② 메뉴 CHECK(`…120200`)는 옛 통합 키 `english` 와 origin/main 의 `english-listening` 까지 담는다 — 통째로 갈아 끼우는 제약이라 빠지면 그 메뉴를 끄는 저장이 23514 다.
③ `publishDeps()` 의 기본 조판기는 실제 조판기다. `TEXTBOOK_PUBLIC_ORIGIN`(https · 경로 없음 · 개발 주소 아님)이 없으면 사전 검사가 막는다.
④ `/api/textbook/**` 의 파일 추적(글꼴 · KaTeX 묶음 · Chromium)은 리드의 `next.config`.
⑤ 로컬 격리 Postgres(127.0.0.1:54331)는 세션 시간대가 Asia/Seoul 이다. 교재가 아닌 표의 기본값은 여전히 세션 시간대다 — 브라우저 검증용 DB 는 `ALTER DATABASE … SET timezone TO 'UTC'`.
   **이 서버는 내가 띄웠고 끄지 않았다**(리드의 브라우저 검증이 쓴다). 내 DB 는 `textbook_apply` · `textbook_test` · `textbook_tz`.
⑥ 재출제 응답은 `titlePersisted: false` 를 낸다(시험지 표에 제목 칸이 없다).
⑦ 구획 미리보기의 교환 형식은 부분집합이다 — 검증할 때 manifest 확인을 끈다(`manifestVerified: false`).

## 6. 열린 것

**세 모델 합의로 닫힌 것**(구현 Codex `927cb7ca0` · 내 시험 `2035cabff`)

- **D1 · 그림과 보기의 짝.** 스캔 그림의 짝을 모르면(`choiceIndex` null — 은행의 빈 배열 기본값) 원래 차례대로 한 덩어리로 놓고 **경고**로 낸다.
  null 을 0 으로 바꾸거나 짝을 지어내지 않는다. 구조가 틀린 짝 · 자산은 그대로 오류다. 엔진이 그린 인라인 SVG 는 정의상 발문의 그림이라 0 으로 적는다(내 캡처).
- **D2 · 해설판의 자리.** 해설판은 정답 · 해설의 실제 높이로 **따로 쪽을 나눈다**. 학생용의 쪽 계획이 QR · 쪽 참조의 정본이다.
  서버 쪽은 고친 것이 없다(확정은 쪽 계획을 학생용 걸음에서만 모으고, 해설판은 찍힌 QR 이 예약한 주소로 읽히는지만 본다).

**결정 · 일이 남은 것**

- **D3 · 본문 시작 면.** 첫 구획이 왼쪽 면 시작이면 `config.print.firstPhysicalPageIndex` 가 짝수여야 한다(`SECTION_PARITY`). 편집기의 기본값이 맞아야 한다.
- **스캔 그림이 있는 문항의 등록.** 은행에는 그림 파일을 화면에서 올리는 길이 없다(배포 파일 · 공유 저장소의 명부. 기존 손등록에도 그림 칸이 없다).
  바이트를 잃지 않고 올리려면 «저장된 바이트로 그림을 내는 새 그림 주소»가 필요하고, 그것은 은행의 그림 읽기 · 인쇄 경로를 건드린다 — 기존 기반으로는 안 된다.
- **`workspaceMenuConstraint.test.ts`** 는 이 가지에서 빼고 돌렸다 — CHECK 와 enum 에 옛 `english` 가 있고 메뉴 배열에는 없어 2 실패였다(리드의 시험. 통합 가지에서 고쳤다고 알렸다).

**하지 않은 것 · 알고 있는 틈**

- 한 번에 담는 문항은 300개까지다(계약은 2,000 을 받는다 — 넘으면 400 과 사유).
- 교환 패키지가 64MB 를 넘으면 산출물 줄이 없다(내보내기가 그때그때 만든다).
- 담기 바구니 출제(`/api/basket/test`)와 재출제는 같은 규칙을 **따로** 구현했다 — 한 함수로 모으지 않았다.
- 굳은 개념의 `assetHashes` 가 가리키는 바이트는 내가 얼리지 않는다(루트 · Codex 의 굳히기가 낸 값을 그대로 적는다).
- 조판기가 원고의 사유 없이 실패하면(브라우저를 못 띄움) 같은 걸음을 세 번까지 다시 한다. 사유가 있으면 다시 하지 않는다.
- 재전송 범위는 «학생 · 반 · 공유에 기대는 요청»만 고쳤다. 판본 · 책 · 확정본 · 올리기에 기대는 요청은 주인이 바뀌지 않아 그때의 결과가 곧 자기 것이다.
- 구획 미리보기는 판본의 개념 줄 전부와 배치 줄 전부(가벼운 칸)를 읽은 뒤 고른다 — 다른 구획의 원고 · 확정본 내용은 읽지 않지만, 개념이 수백 개인 책에서의 응답 시간은 재지 않았다.
- 학생 쪽 SQL(리드)의 시각 비교가 세션 시간대에 기대는지는 보지 않았다.

## 7. 배포 순서 (DB 먼저 · 코드 나중)

1. 리드가 병합한 뒤 공유 DB 에서 **드라이런**: `npx tsx scripts/qa/apply-textbook-studio-migration.ts`
2. 적용: `ALLOW_SHARED_IMPORT=1 npx tsx scripts/qa/apply-textbook-studio-migration.ts --apply` — ① 표 ② `test_problem.snapshot_id` ③ 메뉴 CHECK.
   ①②가 코드보다 **먼저**다(`TestProblem.snapshotId` 를 읽는 코드가 칸 없는 DB 에 나가면 시험지를 읽는 요청이 전부 죽는다).
3. `TEXTBOOK_PUBLIC_ORIGIN` 을 넣는다.
4. 코드를 낸다.
5. 되돌리기: `--revert`(드라이런) · `--revert --apply`. 발행본이 하나라도 있으면 되돌리지 않는다(인쇄된 QR 이 그 행에 달려 있다).

`prisma migrate dev/deploy` · `db push` 로 공유 DB 에 적용하지 않는다(다른 트랙의 미적용 마이그레이션까지 같이 적용한다).
