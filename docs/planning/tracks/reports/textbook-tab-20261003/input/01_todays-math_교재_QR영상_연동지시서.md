# todays-math ↔ 인재원 교재·QR 해설영상 연동 구현 지시서

작성일: 2026-10-03 / 버전: 1.0 / 함께 읽기: `03_공통데이터계약_및_통합검수.md`

## 1. 구현 목표

원장이 todays-math에서 선정하거나 출제한 문제를 교재 스튜디오로 가져온다. 교재와 앱에는 발문·수치·조건·보기·도형·정답이 같은 문항이 실린다. 학생이 책의 문제 옆 QR을 찍으면 책 이름, 판본, 문제 번호, 해당 문제와 해설영상을 확인할 수 있다.

기존 출제·문제은행·단원·학생 인증·영상 재생 기능을 재사용한다. 코드 확인과 구현을 수행하고, 계획만 제안한 상태로 완료 처리하지 않는다. 운영 데이터 변경과 배포 범위는 실제 작업에 대한 사용자 지시를 따른다.

## 3. 반드시 지킬 동일성 규칙

1. **같은 유형과 같은 문제를 구분한다.** `familyKey`가 같아도 숫자·보기·그림이 다르면 다른 문제다. 변형 생성은 결과를 문항으로 저장하고 고유 ID를 받은 뒤 교재로 전달한다.
2. `Problem.id`는 원본 연결, `problemCode`는 교사가 확인하는 코드, 교재의 `023`은 해당 책 안의 표시 번호다. 셋을 혼용하지 않는다.
3. `problemCode`는 저장된 그대로 내보낸다. 학년·단원명·배치 순서에서 재생성하지 않는다.
4. 문제은행 원문과 교재 원문을 각각 AI로 다시 생성하여 맞추려 하지 않는다. 동일 데이터를 서로 다른 레이아웃으로 렌더한다.
5. 발행한 책은 **발행 당시 내용·도형·정답·해설의 확정본**을 보존한다. 원문 수정은 새 개정본을 만들고, 기존 인쇄본의 QR 의미를 바꾸지 않는다.
6. 스튜디오에서 의미가 바뀌는 수정은 새 문항 또는 새 문항 개정본으로 서버에 등록한다. 수정된 문제에 예전 문제 코드를 붙인 채 동기화 완료로 표시하지 않는다.
7. 동일 문항이 여러 책 또는 한 책의 여러 위치에 나오더라도 각각의 교재 배치 ID는 구분한다.

## 4. 기준 구조

todays-math 서버가 문항·판본·영상·QR 연결의 기준을 가진다. 스튜디오는 서버가 제공한 문항 확정본을 가져와 원고를 구성하고 조판한다. 교재의 대화·설명·학습 활동은 스튜디오 원고이며, 문제은행 문항을 임의로 변경하는 통로로 사용하지 않는다.

필요한 개념은 아래와 같다. 정확한 테이블명은 기존 관례에 맞출 수 있으나 관계와 보존 규칙은 유지한다.

| 개념 | 역할 |
| --- | --- |
| `Textbook` | 학년·학기·권차 등 교재의 정체성 |
| `TextbookEdition` | 초안과 발행된 판본 구분, 발행 시 변경 불가 |
| `ProblemSnapshot` | 문항의 특정 시점 내용과 도형·정답·해설 보존 |
| `TextbookItem` | 판본 속 문항의 배치, 표시 번호, 개념·유형·단계, 최종 페이지 |
| `ProblemVideoBinding` | 특정 문항 확정본에 맞는 검수된 해설영상 연결 |
| `QrTarget` | 인쇄 후에도 유지되는 고정 주소와 판본·배치 연결 |
| 교재 배정 관계 | 학생·반에 교재 또는 일부 범위의 접근 권한 부여 |

한번 발행된 판본은 편집 가능한 초안과 분리한다. 발행한 판본을 열어 수정하면 새 개정 초안을 생성한다. 같은 판본에 다른 내용의 파일이 조용히 덮어써지면 안 된다.

## 5. 교사 사용 흐름

### A. 출제 결과로 교재 구성

1. 출제된 시험지 또는 문제 묶음에서 `교재에 담기`를 선택한다.
2. 서버가 대상 문항과 순서를 읽는다. 요청에 전달된 문항 ID·단원·권한·출제 가능 상태를 검증한다.
3. 교재·판본·단원·학습 단계·중복 처리 방식을 선택한다. 같은 문항의 재배치는 허용하되 사용자에게 중복 위치를 보여준다.
4. 스튜디오에서 실제 페이지를 확인한다. 초안 수정·정렬·문항 교체는 이 단계에서 한다.
5. 발행 전 검수에서 미연결 문항, 수식 오류, 영상 누락, 레이아웃 오류를 구분한다.
6. 발행 시점에 스냅샷, 도형 자산, 최종 배치·페이지, QR 연결, 내보내기 해시를 함께 확정한다.

시험지를 교재로 가져왔다고 해서 원래 시험지의 내용·배점·순서가 바뀌어서는 안 된다. 교재 편집은 별도 판본에서 진행한다.

### B. 교재에서 같은 문항 재출제

교재명·판본·쪽·문항 번호 또는 문항 코드로 찾을 수 있게 한다. `교재와 같은 문제로 출제`를 선택하면 발행본의 문항 내용을 사용한다. 현재 문제은행 내용과 달라진 경우 자동으로 최신 문제로 치환하지 않는다. 최신 문항으로 출제하려면 차이를 표시하고 명시적 선택을 받는다.

### C. 영상 등록

- 문항 옆에서 문제·정답·해설과 영상 미리보기를 함께 확인한다.
- 영상 유형은 `개념 예습`과 `문제 해설`로 구분한다.
- 기존 개념영상을 단원만 같다는 이유로 해당 문제의 해설영상이라고 표시하지 않는다.
- 한 영상에서 여러 문제를 설명하면 문항별 시작·종료 시점을 연결한다. 플레이어가 구간 제한을 지원하지 않으면 시작 시점 이동과 구간 안내로 처리한다.
- 등록, 검수 대기, 게시, 게시 중지 상태를 구분한다. 실제 영상이 없으면 완료로 표시하지 않는다.
- 영상 제작 자동화는 이 연동의 필수 범위가 아니다. 제작 파이프라인이 있으면 연결할 수 있지만 문항 대응과 교사 검수는 유지한다.

## 6. QR과 학생 열람

### 고정 주소

예시 경로는 `/q/{opaqueSlug}`이다. 실제 경로는 라우팅 충돌을 확인하여 결정한다. 서버가 발급·저장한 절대 HTTPS 주소를 QR에 넣는다. 스튜디오가 현재 프리뷰 주소, `localhost`, `file://`, 임시 배포 URL로 만들지 않는다.

- slug는 서버에서 발급하고 재사용·재할당하지 않는다.
- URL에 학생 이름, 학생 ID, 로그인 토큰, 만료되는 서명 값을 넣지 않는다.
- QR 주소 자체는 접근 권한을 부여하는 비밀 키가 아니다. 열람 시 서버에서 권한을 확인한다.
- QR은 해당 판본의 `itemId`에 연결한다. 페이지 번호나 문제 번호를 URL의 유일한 식별자로 삼지 않는다.
- 영상 교체는 같은 문항 확정본에 적합한 영상을 검수한 뒤 연결만 변경한다. QR은 유지한다.
- 인쇄 후 QR 대상을 다른 문제에 재사용하지 않는다. 연결 중지 시에도 안내 페이지는 유지한다.

### 학생 화면

모바일에서 QR을 열면 교재명·판본·문제 번호·문제 본문과 영상이 연결되어 보여야 한다. 정상 로그인 세션이 있으면 바로 재생 화면으로 진입한다. 로그인이 필요하면 로그인 후 원래 QR 화면으로 돌아온다. 복귀 주소는 서비스 내부 허용 경로로 제한한다.

영상이 없거나 준비 중이면 `해설영상 준비 중`을 표시하고, 허용된 경우 해당 문항의 글 해설을 제공한다. 다른 문제 영상이나 무관한 개념영상으로 대신 성공 처리하지 않는다. 모바일 재생은 브라우저의 사용자 동작 요구를 따른다. 무조건 자동 재생을 성공 조건으로 삼지 않는다.

### 접근 권한

현재 진도 기반 개념영상 규칙은 보존한다. 교재 QR에는 별도의 배정 판정을 추가한다.

- 교재 또는 범위를 배정받은 학생은 그 범위의 게시된 영상에 접근 가능하다.
- 예습 범위를 배정받으면 아직 수업 진도가 기록되지 않아도 해당 범위에 접근 가능하다.
- 배정받지 않은 책, 다른 학생의 책, 다른 지점 자료에 대한 접근은 기존 서비스 권한 정책에 맞게 거부한다.
- 반 이동, 개별 배정, 배정 회수, 만료 여부를 서버의 명시적 정책으로 처리한다. 기존 권한 정책을 우회하지 않는다.
- 모든 영상을 전체 공개하는 방식으로 예습 문제를 해결하지 않는다.
- 학생에게 반환하는 응답과 PDF는 교사용 초안·비공개 정보·다른 학생 데이터를 포함하지 않는다.

## 7. 데이터 전달과 API

03번의 `schemaVersion: injaewon.textbook.exchange.v1` 계약을 기준으로 서버 DTO와 스튜디오 검증기를 맞춘다. 아래 경로는 **신규 제안**이며 현재 구현된 API라고 가정하지 않는다.

| 기능 | 경로 예시 | 핵심 동작 |
| --- | --- | --- |
| 교재 목록·생성 | `GET/POST /api/textbooks` | 교재 메타데이터 |
| 초안 편집 | `PATCH /api/textbooks/{id}/editions/{editionId}` | revision 비교, 충돌 시 409 |
| 문항 담기 | `POST /api/textbooks/{id}/editions/{editionId}/items` | 문항 ID·순서·단계·출처 저장 |
| 원고 내보내기 | `GET .../export` | 확정본·도형·매핑·검증 결과 |
| 교재 발행 | `POST .../publish` | 검수 상태 확인, 트랜잭션·재시도 안전성 |
| 문항 영상 연결 | `POST /api/problem-snapshots/{snapshotId}/videos` | snapshot별 등록·검수·게시 |
| QR 조회 | `GET /q/{slug}` | 권한 확인 후 판본·문제·영상 표시 |

읽기 전용 API도 인증·권한을 확인한다. 파일 내보내기에 서비스용 비밀 키를 넣지 않는다. 오프라인 HTML이 DB에 직접 연결하거나 관리자 토큰을 보관하게 하지 않는다.

초기 완결 경로는 서버의 `교재 패키지 내보내기 → 스튜디오 가져오기 → PDF 출력`만으로도 구현 가능하다. 이후 같은 계약으로 앱 내 편집 UI를 붙인다. 다만 QR 발급·해석과 발행 정보 저장은 서버가 담당하며, 파일만 만들어서 전체 연동 완료라고 보고하지 않는다.

## 8. 발행 무결성과 도형 보존

- 스냅샷에 발문·보기·정답·해설·LaTeX·도형의 실제 버전을 함께 보존한다. 단순히 `updatedAt`이나 원문 URL만 복사하지 않는다.
- 기존 `figureSvg`, `figureUrls`, `figureDims`, `figureSourceMm`, `choiceFigureIndex`를 읽고 순서·보기 대응·크기 정보를 유지한다. 현재 직렬화 함수에서 빠진 필드가 있으면 인쇄용 응답에 명시적으로 추가한다.
- 외부 이미지나 기존 가변 경로는 발행 시 승인된 저장 경로로 고정한다. 만료되는 다운로드 URL 자체를 영구 자산으로 저장하지 않는다.
- 도형·이미지 내용 해시와 문제 내용 해시를 검증한다. HTML/SVG는 기존 보안 정책에 따라 정화하고 외부 스크립트·임의 이벤트 실행을 막는다.
- 변환기는 Markdown+LaTeX를 구조화 토큰 또는 안전한 렌더러로 처리한다. 전역 정규식 치환으로 달러 표시·수식·보기 순서를 훼손하지 않는다.
- 현재 교재의 `[[...]]` 수식은 기존 입력용 어댑터에서 변환한다. 서버 원문에 해당 구분자를 무조건 덧씌우지 않는다.
- 기존 `reviewStatus`, `directUseAllowed`, 출제 풀·접근 범위 판단을 재사용한다. 대상이 제외되면 이유를 보여주고 임의 해제하지 않는다.

## 9. 기존 2-1-1 문항 이관

현재 교재의 `B0001` 같은 ID는 스튜디오 내부 번호다. todays-math의 `Problem.id` 또는 `problemCode`가 아니다.

1. 기존 1,039문항을 우선 원문 그대로 보존한다.
2. 상태를 `연동 전`, `후보 있음`, `연결 확정`, `수정 필요`로 구분한다.
3. 문항 코드가 직접 제공된 경우 해당 레코드를 조회해 내용까지 검증한다.
4. 코드가 없으면 본문·수치·도형·보기·정답 비교로 후보를 찾는다. 유형명이나 유사도만으로 자동 확정하지 않는다.
5. 완전 일치 후보가 하나인지, 여러 개인지 기록한다. 여러 후보와 의미 차이는 교사가 확정한다.
6. 독자 제작 문항은 새 문항으로 등록할 수 있다. 등록된 실제 ID를 응답받기 전에는 연결 완료로 표시하지 않는다.
7. 대화·개념 설명·단원 도입 이미지는 문항 ID를 억지로 붙이지 않고 스튜디오 원고로 남긴다.

문항을 새로 등록하는 가져오기 작업은 요청 ID를 저장하여 재시도해도 중복 생성되지 않게 한다. 등록 시 검수 상태는 기존 정책을 따른다.

## 10. 구현 순서와 완료 증거

1. 기존 코드·DB migration·인증·출제 가능 판정·문항 렌더링을 조사하고 변경 파일 목록을 정한다.
2. 03번 DTO와 스냅샷·판본·배치 관계를 구현한다. 운영 DB를 초기화하거나 기존 ID를 재발급하지 않는다.
3. 기존 실제 문항을 초안에 담아 스튜디오로 내보내는 경로를 연결한다.
4. 영상 연결·고정 QR·학생 권한·로그인 복귀를 구현한다.
5. 02번의 조판 결과에서 생성된 QR로 통합 검증한다.
6. 기능별 변경사항, 마이그레이션 방법, 실행한 검증, 하지 못한 검증을 구분하여 보고한다.

필수 확인 시나리오:

- 동일 유형의 숫자가 다른 두 문제에 서로 다른 해설이 연결된다.
- 문제은행 내용 수정 후에도 이미 발행한 책의 문제와 해설은 유지된다.
- 같은 문제를 다른 페이지로 옮긴 초안의 번호·해설 참조가 함께 갱신된다.
- 영상 교체 후 인쇄된 기존 QR로 새 검수 영상이 열린다.
- 예습 배정 학생은 진도 기록 전에도 열람하고, 미배정 학생은 차단된다.
- 로그인 전 스캔 후 로그인하면 원래 문제로 돌아온다.
- SVG 도형, 선택지 그림, 분수·부등식이 교재와 학생 화면에서 같은 의미로 표시된다.
- 같은 가져오기 요청을 두 번 보내도 문항·판본·QR이 중복 생성되지 않는다.
- 영상 준비 중·게시 중지·존재하지 않는 QR·권한 없음이 구분된다.

자동 테스트, 출력 PDF, QR 디코딩 결과, 검증용 계정의 실제 열람 기록을 증거로 남긴다. 테스트용 모의 영상·모의 로그인으로만 확인한 것은 실제 영상·실제 인증 검증과 분리해 보고한다.
