# 공통 데이터 계약과 통합 검수

작성일: 2026-10-03 / 제안 계약 버전: `injaewon.textbook.exchange.v1`

이 문서의 새 이름과 구조는 구현 제안이다. 현재 저장소에 이미 존재하는 API·테이블이라는 뜻이 아니다. 01번과 02번을 구현하는 코드가 하나의 계약을 공유해야 하며, 기존 프로젝트의 타입·검증 라이브러리에 맞춰 구현한다.

## 1. 데이터의 기준

| 데이터 | 기준이 되는 곳 | 변경 규칙 |
| --- | --- | --- |
| 원본 문항·문항 코드 | todays-math 문제은행 | 기존 ID·코드 보존, 코드 재계산 금지 |
| 인쇄된 문항 내용 | 발행 판본의 스냅샷 | 불변, 수정은 새 판본·스냅샷 |
| 교재 순서·표시 번호·페이지 | 교재 판본의 배치와 최종 조판 결과 | 초안에서 변경 가능, 발행 시 고정 |
| 개념 설명·대화·학습 활동 | 스튜디오의 교재 원고 | 원고 revision 관리, 발행본 보존 |
| 영상 | 서버의 영상 자료와 게시 상태 | 검수 후 변경, 변경 기록 유지 |
| 영상 대응 | 특정 문제 스냅샷 ↔ 특정 영상 | 단원명·문제 번호의 유사성으로 연결 금지 |
| QR | 서버의 영구 대상 레코드 | slug 재사용 금지, 대상 판본·문항 불변 |
| 학생 열람 | 서버의 기존 인증과 교재 배정 정책 | 클라이언트·URL만으로 허용 금지 |

스튜디오가 사용하는 모든 linked 문항은 원문 식별자와 스냅샷을 함께 가진다. 원문 ID만으로는 인쇄본 보존을 충족하지 않는다.

## 2. 식별자와 개정의 의미

- `bookId`: 교재의 정체성. 같은 교재의 1판과 2판이 공유한다.
- `editionId`: 특정 판본. 발행한 뒤 내용이 바뀌면 새 ID를 만든다.
- `revision`: 발행 전 초안 편집 충돌을 감지하는 증가값. 판본 번호와 다르다.
- `problemId`: todays-math의 실제 문항 ID.
- `problemCode`: 저장되어 있는 교사용 문항 코드. 가져온 값을 그대로 보존한다.
- `snapshotId`: 특정 시점의 내용·정답·해설·도형을 가리키는 불변 ID.
- `contentHash`: 스냅샷의 내용 변형·누락 검출용 해시. ID를 대체하지 않는다.
- `itemId`: 특정 판본에 문항이 배치된 위치의 고유 ID. 같은 문제의 반복 배치도 다른 ID를 가진다.
- `displayNumber`: 학생이 책에서 보는 `023` 같은 번호. 연결의 기본키가 아니다.
- `physicalPageIndex`: 제본될 문서의 실제 순서. 홀짝 계산용.
- `printedPageLabel`: 지면에 인쇄하는 쪽번호 문자열. 앞부분 번호 생략·별도 표기에 대응한다.
- `qrTargetId`, `qrSlug`: 인쇄 QR의 영구 연결 대상. 학생 식별자와 무관하다.

고정 QR은 `editionId + itemId`에 연결하고, item이 가리키는 snapshot을 해석한다. 영상은 snapshot에 연결한다. 이렇게 하면 교재 번호가 다른 두 책에서 같은 문항의 검수 영상을 사용할 수 있고, 숫자가 달라진 변형 문제는 구분할 수 있다.

## 3. 전송 패키지

패키지는 UTF-8 JSON과 실제 이미지·도형·글꼴 등 필요한 자산으로 구성한다. ZIP은 선택 가능한 배포 포맷이며 API 응답도 같은 논리 계약을 따른다.

| 경로 예시 | 내용 |
| --- | --- |
| `manifest.json` | 계약 버전, 교재·판본, 생성 시각, 파일 목록과 해시 |
| `textbook.json` | 교재 설정·단원·원고 블록·배치·문항 스냅샷 |
| `assets/` | 허용된 경로에 고정한 자산 |
| `mapping.csv` | 교재 번호·문항 코드·snapshot·페이지·QR 대응 |
| `validation.json` | 구조·내용·레이아웃·영상·QR 검수 결과 |

스튜디오는 지원하지 않는 계약 버전을 명확한 오류로 거부한다. 더 최신 파일의 알 수 없는 필드를 임의 삭제하여 덮어쓰지 않는다. 입력 파일명·ZIP 경로를 신뢰하지 말고 경로 이탈, 과대 압축, 허용되지 않은 실행 콘텐츠를 검증한다.

## 4. 타입 계약의 기준안

아래는 두 구현이 공유할 TypeScript 모델의 기준안이다. 선택한 검증 라이브러리로 런타임 입력 검증을 함께 구현한다. 브랜드 타입·DB 모델·API 응답 타입을 프로젝트 관례에 맞춰 구체화하되 필드의 의미를 바꾸지 않는다.

```ts
type Id = string;
type IsoDateTime = string;
type Sha256 = string;
type SchoolLevel = 'elementary' | 'middle' | 'high';
type LinkStatus = 'unlinked' | 'candidate' | 'linked' | 'needs-review';
type LearningStage =
  | 'preparation' | 'worked-example' | 'concept-check' | 'basic'
  | 'type-practice' | 'application' | 'error-check' | 'written'
  | 'cumulative-review' | 'unit-assessment';

type ProblemSourceRef =
  | { system: 'todays-math'; problemId: Id; problemCode: string }
  | { system: 'legacy-studio'; legacyId: string }
  | { system: 'studio-authored'; localId: Id };

interface AssetRef {
  assetId: Id;
  packagePath: string;
  mimeType: string;
  sha256: Sha256;
  widthPx: number | null;
  heightPx: number | null;
}

interface FigureRef {
  assetId: Id;
  sha256: Sha256;
  choiceIndex: number | null;
  sourceWidthMm: number | null;
  altText: string | null;
}

interface ProblemPayload {
  format: 'markdown-latex';
  content: string;
  answer: string;
  solution: string | null;
  questionType: string | null;
  figures: FigureRef[];
}

interface ProblemSnapshot {
  snapshotId: Id;
  source: ProblemSourceRef;
  sourceUpdatedAt: IsoDateTime | null;
  capturedAt: IsoDateTime;
  unitId: Id | null;
  familyKey: string | null;
  difficulty: string | null;
  problemType: string | null;
  payload: ProblemPayload;
  contentHash: Sha256;
}

interface TextbookItem {
  itemId: Id;
  editionId: Id;
  snapshotId: Id;
  linkStatus: LinkStatus;
  sourceTestId: Id | null;
  sourceTestProblemId: Id | null;
  unitKey: string;
  sectionKey: string;
  learningStage: LearningStage;
  displayNumber: string;
  orderIndex: number;
  layout: {
    columnSpan: 1 | 2;
    minWorkLines: number;
    preferredWorkLines: number;
    maxWorkLines: number;
    keepTogether: boolean;
  };
  qrTargetId: Id | null;
}

interface TextbookConfig {
  bookId: Id;
  schoolLevel: SchoolLevel;
  grade: number;
  semester: 1 | 2;
  volume: number;
  volumeCount: number;
  displayCode: string;
  title: string;
  curriculumVersion: string;
  mode: 'integrated' | 'concept' | 'practice';
  pageBudget: {
    target: number;
    tolerance: number;
    strict: boolean;
  };
  print: {
    paper: 'A4';
    innerMarginMm: number;
    outerMarginMm: number;
    sectionStart: 'even-left';
    coverMode: 'included' | 'separate';
    firstPhysicalPageIndex: number;
  };
  videoPolicy: 'required' | 'optional';
}

type ManuscriptBlock =
  | { blockId: Id; kind: 'text'; markdown: string }
  | { blockId: Id; kind: 'problem'; itemId: Id }
  | { blockId: Id; kind: 'image'; assetId: Id; caption: string | null }
  | {
      blockId: Id;
      kind: 'dialogue';
      turns: Array<{
        speakerId: Id;
        side: 'left' | 'right';
        expression: 'neutral' | 'question' | 'thinking' | 'aha';
        portraitAssetId: Id;
        mirrorPortrait: boolean;
        markdown: string;
      }>;
    }
  | {
      blockId: Id;
      kind: 'concept-recall';
      phase: 'study' | 'keywords' | 'sentences';
      markdown: string;
      showRepetitionChecks: boolean;
    };

interface Section {
  sectionKey: string;
  title: string;
  templateKey: string;
  startPolicy: 'even-left' | 'continue';
  blocks: ManuscriptBlock[];
}

interface UnitManuscript {
  unitKey: string;
  title: string;
  sourceUnitIds: Id[];
  prerequisites: string[];
  goals: string[];
  conceptLectureRefs: Array<{ lectureId: Id; conceptKey: string }>;
  sections: Section[];
}

interface QrTarget {
  qrTargetId: Id;
  editionId: Id;
  itemId: Id;
  slug: string;
  url: string;
}

interface ProblemVideoBinding {
  bindingId: Id;
  snapshotId: Id;
  videoId: Id;
  status: 'draft' | 'review' | 'published' | 'withdrawn';
  startSeconds: number;
  endSeconds: number | null;
  reviewedAgainstHash: Sha256 | null;
}

interface PagePlacement {
  itemId: Id;
  physicalPageIndex: number;
  printedPageLabel: string;
  column: 1 | 2;
}

interface TextbookExchange {
  schemaVersion: 'injaewon.textbook.exchange.v1';
  exportedAt: IsoDateTime;
  config: TextbookConfig;
  edition: {
    editionId: Id;
    label: string;
    status: 'draft' | 'published' | 'retired';
    revision: number;
    publishedAt: IsoDateTime | null;
    manifestHash: Sha256 | null;
  };
  units: UnitManuscript[];
  snapshots: ProblemSnapshot[];
  items: TextbookItem[];
  assets: AssetRef[];
  qrTargets: QrTarget[];
  videoBindings: ProblemVideoBinding[];
  pageMap: PagePlacement[];
  rendererVersion: string;
  templateVersion: string;
}
```

다음은 필수 검증 조건이다.

- 위 모델은 **교사용 교환 형식**이다. 학생 공개 응답에 통째로 사용하지 않는다. 학생 화면은 권한 확인 후 필요한 판본·문제·게시 영상 정보만 받는다.
- 모든 참조 ID는 패키지 안 또는 허용된 서버 자료에서 해석되어야 한다. 없는 참조를 조용히 건너뛰지 않는다.
- linked 문항은 source가 `todays-math`이고 서버가 확인한 실제 ID·코드를 가져야 한다. 후보 매칭 ID는 확정 source로 기록하지 말고 별도의 후보 목록에 보관한다.
- legacy 문항은 기존 ID를 유지할 수 있다. 오프라인 편집용 snapshot ID와 서버 발행 snapshot ID가 다르면 명시적인 이관 매핑표를 만든다.
- `questionType`, `problemType`, `difficulty`는 다른 축이다. 기존 허용값과 null 처리 규칙을 보존한다.
- `sourceUpdatedAt`은 추적용이며 불변성 증거가 아니다. 내용 해시와 실제 자산을 함께 검증한다.
- `choiceIndex`는 `0`이면 본문 그림, 양수이면 해당 보기, `null`이면 대응을 모르는 상태다. 모르는 그림을 임의로 ①에 붙이지 않는다.
- 기존 `figureSvg`는 SVG 자산으로 저장하고 `figures`에 참조한다. `figureUrls`, `figureDims`, `figureSourceMm`, `choiceFigureIndex`는 원본 배열 순서대로 변환하며 미상 값은 그대로 표시한다.
- 모든 원고의 수학식은 Markdown+LaTeX 의미를 보존한다. 기존 `[[...]]`와 `{{...}}` 빈칸 표기는 전용 어댑터로 이관하고, 원본 백업과 변환 결과를 남긴다.
- `showRepetitionChecks`는 `keywords`, `sentences`에서 반드시 false다.
- 기본 Section만으로 부족한 개념·유형 전용 편집 필드는 명시적인 타입과 검증기로 추가한다. `any` 또는 검증하지 않는 HTML 덩어리로 우회하지 않는다.
- 템플릿은 `templateKey`로 렌더링을 선택한다. 특정 학년·단원 ID와 템플릿이 결합되지 않게 한다.
- 여백·선 수·시간·학년 등의 숫자는 허용 범위를 검사한다. 최소 풀이선 ≤ 선호 풀이선 ≤ 최대 풀이선, 종료 시점 > 시작 시점을 검증한다.
- `startPolicy: even-left`는 주요 구획에, `continue`는 그 안의 연속 학습 블록에 적용한다.
- `pageMap`은 실제 최종 조판에서 생성한다. 초안에서 문항을 이동했으면 다시 계산한다. 레거시 `q.page`를 신뢰해 이전 페이지로 답안 참조를 만들지 않는다.
- `videoBindings`에는 영상 서비스의 비밀 URL·자격증명을 넣지 않는다. 학생 재생 정보는 권한을 확인하는 서버가 별도 제공한다.
- 위 `QrTarget`은 문제별 QR 계약이다. 개념 예습 QR은 `conceptLectureRefs`와 기존 강의 연결을 보존하고, 개념용 연결 타입을 별도로 정의한다. 두 종류를 하나의 problemId에 억지로 맞추지 않는다. 개념 QR도 배정·진도에 따른 서버 권한 확인을 거친다.
- 영상 필수 정책을 일부 범위에만 적용하려면 문항별 정책 override를 명시적인 추가 필드로 구현한다. 단순히 누락된 영상은 선택 사항이라고 추정하지 않는다.
- 초안·보관된 JSON을 열어 지면을 미리 보는 것과, 온라인 영상을 오프라인으로 재생하는 것은 다른 기능이다. 오프라인 HTML에 영상 파일이 포함된 것으로 표시하지 않는다.

## 5. 해시와 스냅샷

해시는 SHA-256을 기본으로 하고 사용한 정규화 규칙과 구현 버전을 고정한다. 해시가 같다는 이유만으로 서로 다른 problemId를 자동 병합하지 않는다.

`contentHash`의 대상은 `ProblemPayload` 전체다. 발문·보기·정답·해설 문자열을 원문 그대로 포함하고, 도형은 순서·용도·물리 폭과 자산 바이트 해시를 포함한다. ID·타임스탬프·페이지·QR·다운로드 URL은 포함하지 않는다.

구현 규칙:

1. 검증된 JSON 값만 받는다. undefined, NaN, Infinity를 허용하지 않는다.
2. 객체 키는 재귀적으로 정렬하고 배열 순서는 보존한다.
3. 문자열의 내부 공백·LaTeX·부호·보기 순서를 정규화한다는 이유로 바꾸지 않는다.
4. UTF-8 JSON 바이트로 직렬화한 뒤 SHA-256을 계산한다.
5. 서버와 스튜디오는 같은 공통 모듈 또는 동일한 검증 벡터로 결과를 확인한다.
6. 내보내는 순간 자산 바이트의 해시와 payload에 들어간 자산 해시를 대조한다.

위 계약에서 `assetId`도 payload에 포함되므로 발행 스냅샷을 패키징할 때 ID를 재발급하지 않는다. 파일 경로를 바꾸더라도 assetId와 바이트를 유지한다.

`manifestHash`는 판본의 최종 설정·단원 원고·문항 스냅샷 목록과 해시·배치·페이지·QR 대상·자산 해시·템플릿/렌더러 버전으로 계산한다. `manifestHash` 자신의 값과 단순 내보내기 시각, 변경 가능한 영상 게시 상태·URL은 대상에서 제외한다. 영상 변경 이력은 별도로 기록한다.

정답이나 글 해설 수정도 새 snapshot으로 남긴다. 수정 전후 발문이 같다고 영상을 자동 승인하지 않는다. 새 snapshot에서도 영상이 적합한지 확인하여 `reviewedAgainstHash`를 기록한다.

## 6. 상태와 발행 순서

문항 연결 상태, 원고 교열 상태, 영상 상태, 판본 발행 상태를 하나의 `완료`로 합치지 않는다.

권장 발행 절차:

1. 초안 revision을 읽고 편집을 잠시 고정하거나 동일 revision으로 발행 시도를 시작한다.
2. 문항 연결·교열·영상 정책·자산·참조를 검사한다.
3. QR 대상 ID와 주소를 예약한다. 아직 미발행 판본의 QR은 교사 미리보기 외 학생에게 노출하지 않는다.
4. 실제 URL로 QR을 조판하고 최종 페이지 배치·PDF를 생성한다.
5. 레이아웃·수식·해시·QR 디코딩을 검증하고 그 결과를 서버에 보낸다. 서버는 클라이언트의 성공 플래그만 믿지 않고 내용·참조·revision·발행 요건을 검증한다.
6. 요청의 revision이 바뀌지 않았는지 확인한다. 달라졌으면 충돌로 중단하고 재조판한다.
7. 발행 트랜잭션에서 불변 원고·스냅샷·페이지·QR 대상을 확정하고 발행 상태로 전환한다.
8. PDF 아티팩트의 바이트 해시와 원고 manifestHash를 함께 기록한다. 동일 요청의 재시도는 같은 결과를 반환한다.

DB와 파일 저장은 하나의 DB 트랜잭션이 아니므로 임시 업로드·확정 단계를 구분한다. 실패한 예약과 업로드는 학생에게 보이지 않게 처리하고, 재시도 안전성을 확보한다. 자동으로 운영 자료를 삭제하는 정리 작업을 추가하지 않는다.

발행을 막는 조건:

- 필수 원고·수식·도형이 없거나 변환 실패
- linked로 표시했으나 실제 문항·snapshot을 확인할 수 없음
- 정답·보기·도형 대응의 알려진 오류
- 페이지 넘침·문항 잘림·QR 겹침·해독 실패
- 주요 구획의 시작 면 불일치
- `videoPolicy: required`인 대상의 검수·게시 영상 누락
- 만료 주소·개발 주소·다른 문제로 연결되는 QR
- 잘못된 참조·해시 불일치·편집 revision 충돌

미연결 legacy 원고는 오프라인 초안·검토 PDF로 출력할 수 있다. 다만 `연동 교재 발행 완료`로 처리하지 않는다. 초안 표시는 스튜디오 상태와 검수 보고서에 분명히 남기며 잘못된 QR은 인쇄하지 않는다.

`videoPolicy: optional`은 영상 미준비 상태를 허용하는 정책이다. 문제 일치·권한·QR 정확성까지 완화하는 정책이 아니다. 영상은 없지만 영구 문제 페이지를 제공하는 경우 QR은 그 페이지로 연결하고 준비 중임을 표시한다.

## 7. 최종 매핑표

`mapping.csv`의 최소 열:

```text
bookId,editionId,editionLabel,itemId,displayNumber,physicalPageIndex,printedPageLabel,unitKey,sectionKey,learningStage,problemId,problemCode,snapshotId,contentHash,linkStatus,qrTargetId,qrUrl,videoStatus
```

학생 정보는 이 파일에 넣지 않는다. CSV의 수식으로 오인되는 값은 내보내기에서 안전하게 처리하고 JSON 원본은 그대로 보존한다. 영상 상태는 매핑표 생성 시점의 상태이며, 인쇄 후 바뀔 수 있다.

## 9. 통합 인수 기준

아래 테스트는 양쪽 담당자가 같은 ID·같은 파일·같은 판본으로 수행한다. 단위 테스트만 통과하고 통합 완료로 표시하지 않는다.

| ID | 검증 | 통과 조건 |
| --- | --- | --- |
| I-01 | 출제 결과 가져오기 | 문항 수·순서·ID·본문·수치·정답·도형이 일치 |
| I-02 | 숫자 변형 두 문항 | 각각 올바른 문제와 영상, familyKey만으로 합쳐지지 않음 |
| I-03 | 원문 수정 | 기존 책의 문제·그림·글 해설·QR 의미 유지 |
| I-04 | 판본 수정 | 새 판본 생성, 기존판 PDF와 QR 영향 없음 |
| I-05 | 배치 변경 | 교재 번호·페이지·정답해설 참조가 일치 |
| I-06 | 영상 교체 | 실제 인쇄 QR 주소를 바꾸지 않고 검수 영상 교체 |
| I-07 | 로그인 복귀 | QR → 로그인 → 원래 문제 화면 |
| I-08 | 예습 접근 | 배정 범위는 진도 기록 전 열람, 범위 밖은 차단 |
| I-09 | 준비 중·게시 중지 | 상태를 정확히 표시하고 무관한 영상으로 대체하지 않음 |
| I-10 | 도형과 보기 | SVG·원본 그림·선택지 대응·크기 정보 보존 |
| I-11 | KaTeX | 분수·지수·부등식·긴 수식 오류·잘림 없음 |
| I-12 | 저장 후 재열기 | 설정·대화·표정·문항 ID·QR·원고가 손실 없이 복원 |
| I-13 | 재시도·동시 편집 | 중복 생성 없음, revision 충돌을 명시적으로 처리 |
| I-14 | 오프라인 | 지면 렌더에 필요한 로컬 자산 정상, 비밀키 포함 없음 |
| I-15 | 다른 학년 | 실제 다른 원고를 동일 템플릿으로 조판, 고정 중2 문구 없음 |
| I-16 | 단원 펼침면 | 왼쪽 짝수·오른쪽 홀수, 주요 구획 시작 면 일관 |
| I-17 | 정렬·공간 | 준비학습 포함 행·풀이선·하단 정렬, 짧은 문제에 적정 공간 |
| I-18 | QR 인쇄 | 출력 PDF의 모든 QR을 디코딩하여 manifest URL과 대조 |
| I-19 | 실제 모바일 | 대표 실물 출력물 스캔으로 올바른 문제·영상 열람 |
| I-20 | 기존 교재 회귀 | 기존 내용 누락·변경 없음, 변경된 페이지는 이동표 제공 |

I-18은 디지털 PDF 검사, I-19는 실제 기기·인쇄 검사다. 하나의 결과로 다른 항목을 통과 처리하지 않는다. QR이 해독되어도 서버 권한·영상이 틀리면 전체 실패다.

## 10. 검증 범위와 보고 양식

자동 검수는 전체 출력 페이지에 대해 레이아웃 경계·수식 오류·이미지 로드·참조·QR·문항 개수·중복·해시를 검사한다. 시각 검수는 대표 템플릿과 자동 검수 경고 페이지를 확인한다. 대응 행·하단 기준선의 허용 오차는 최초 구현값으로 0.5mm 이내를 목표로 삼고, 실제 글꼴·PDF 렌더에서 조정한 값과 이유를 기록한다.

내용 검증은 계산 가능한 정답 검산과 교사의 내용 교열을 나눠 집계한다. 1,039문항 전체에 대한 검산·교열을 했다고 추정하지 않는다. 새로 생성·변환된 문제, 도형 대응이 바뀐 문제, 숫자가 있는 대화와 예제는 우선 교열 대상이다.

완료 보고는 다음 형식으로 남긴다.

```text
기준 커밋 / 변경 커밋:
기준 스튜디오 버전 / 템플릿 버전:
구현한 실제 기능:
발행하거나 검증한 교재·판본:
원문 연결 확정 / 미연결 / 검토 필요 문항 수:
영상 게시 / 준비 중 / 실제 재생 확인 수:
학생용·해설 쪽수와 문항 수:
전체 자동 검사 결과:
시각 검수한 페이지와 발견·수정 사항:
실제 모바일·로그인·예습 권한 검사 결과:
실물 인쇄 QR 검사 여부:
마이그레이션 적용 여부와 복구 방법:
실행하지 못한 검사와 이유:
남은 원고·영상·데이터 작업:
산출물 경로와 실행 방법:
```

실제 인증·영상·인쇄 환경에 접근할 수 없으면 코드와 모의 검증까지 수행하고, 해당 항목만 미실행으로 보고한다. 성공한 것으로 꾸미거나 그 제한을 이유로 가능한 구현까지 중단하지 않는다.
