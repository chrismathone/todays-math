## 4. 막지 않는 메모 (구현 때 내가 맡을 자리)

- **같은 판본임을 DB 가 증명하게.** «UUID 존재 검사만으로 통과하지 않는다»는 복합 FK 로 건다: 배치 `(edition_id, section_id)` → 구획 `(edition_id, id)`, QR `(edition_id, item_id)` → 배치 `(edition_id, id)`, 개념 `(edition_id, section_id)` 도 같다. 확정본 · 자산의 주인이 판본의 주인과 같은지는 표를 넘는 조건이라 앱과 시험이 맡는다.
- 배치 고치기(`PATCH …/items/{id}`)는 `orderIndex` 를 받지 않는다. 자리의 원천은 구획의 블록 순서 하나다.
- `conceptKey` 는 주소에 실린다. 글자를 `[a-z0-9-]` 60자 안으로 묶는다.
- 근거 보기는 학생 한 명 길만 있다. 반 화면에서 후보를 보려면 같은 투영의 반 길이 필요하다(탐험의 교사 보기도 반 · 학생 둘이다).
- 탐험을 교재에서 시작할 때 «통합 탐험»의 하루 임무와 어떻게 맞물리는지는 읽지 않았다. 상태 기계 시험 하나로 잠근다: 그날 탐험을 시작하지 않은 학생이 교재에서 복습을 시작해도 기존 화면이 그 도전을 정상으로 보인다.
- 의존성 넷과 pglite 의 판 번호는 명세에 적힌 대로 고정하면 된다. 설치는 아직 없다.

## 5. Hi-fi 표결 — H1

본 것: `hifi-h1~h4-desktop-full.png` · `hifi-h1~h4-mobile-full.png` 여덟 장과 `hifi-review.html` 의 글.

**H1(작업실)** 이다.

- 원고 칸과 미리보기 칸이 반반이다. v03 에서 원고 쪽에 들어갈 것이 늘었다 — 개념 원고 여덟 칸, 백지 항목 고르기, 연결의 검토 상태. H4 의 300px 원고 칸에는 안 들어간다.
- H4 가 나은 점은 미리보기 크기다(쪽 하나 330px 대 230px). H1 에도 «키우기»가 있다. 키우면 원고 칸을 접고 미리보기가 폭 전체를 쓰게 하면 같은 것을 얻는다.
- H4 의 학생용 · 교사용 축소판은 늘 떠 있으면 고칠 때마다 조판이 세 번 돈다. 축소판으로는 정답 누출도 못 본다 — 그것은 서버 시험이 본다.
- H3 의 검수 표는 내용이 맞다(구획마다 상태와 «열기» 단추). 자리가 틀렸다. 원고 위에 얹혀 양식을 화면 밖으로 민다. 따로 선 검수 화면이나 접히는 판으로 둔다.
- H2 는 위 도구 줄의 «초안 · 학생용 · 교사용»이 미리보기의 같은 단추와 겹친다. 작은 기본 모양 단추가 앱의 다른 화면과 다르다.
- 휴대폰은 넷 다 «원고 / 미리보기» 두 탭이다. Wire 때 붙인 조건이 들어갔다. H1 과 H4 는 원고 탭이 같은 화면이다.

H1 에 붙이는 조건:

1. **구획 목차를 접히는 나무로.** 지금은 양식 카드 맨 위의 글 세 줄이다. 실제 책은 구획이 70개쯤이다. 구획마다 저장 상태와 검수 표시를 단다.
2. **저장 상태는 구획에.** 오른쪽 위 «저장됨» 하나로는 모자란다. 구획 제목 옆에 다섯 상태(이 기기에만 있음 / 저장 안 됨 / 저장 중 / 저장됨 / 다른 기기에서 바뀜)를 둔다.
3. **왼쪽 아래의 이름 없는 입력 칸과 «검수» 단추.** 무엇을 적는 칸인지 안 보인다. H3 화면에서는 양식 위에 겹쳐 있다. 이름을 붙이거나 빼고, 내용 위에 겹치지 않게 한다.
4. **미리보기 위의 단추 두 줄을 한 줄로.** 지금 110px 쯤을 쓴다. 그만큼 펼침이 내려간다.
5. **개념 백지 자리에 상태를.** 항목마다 갈래(개념 · ○× · 적용 · 그림)와 검토 상태(후보 · 확정 · 바뀜 · 없어짐), 순서를 옮기는 손잡이.
6. **미리보기는 «미리보기»라고 적는다.** 발행 화면은 서버가 조판한 쪽을 보인다.
7. **휴대폰 아래 메뉴**의 이름이 잘린다(«문제 추», «수업·학», «기억 학습»). 메뉴가 아홉이 되어서다. 실제 앱의 아래 메뉴가 이 폭에서 어떻게 도는지에 맞춘다.

### 7.2 `e94aedb8…` — 승인

대상: SHA-256 `e94aedb8a5bff13d64ddded08539a187aadc9111e39603eabb9554d6eff41ca1`(138줄 · 24,697바이트).

**승인.** 남은 막는 사유가 없다.

- 확인한 방법: 루트 워크트리에 커밋된 판(`19ea787e9`)의 해시가 `647397f8…` 이다 — 전문을 읽은 그 판이다. 거기서 지금 파일까지의 `git diff` 가 **더한 한 줄 · 바뀐 한 줄**뿐이다.
- 더한 줄(B2): `pick` 이 든 고르기는 `?s=` 에 싣지 않는다. 인쇄는 저장본 id 나 교재 개념 참조로 서버가 읽는다. `?s=` 를 읽는 쪽은 `pick` 이 든 입력을 거절한다. `pick` 이 없는 기존 주소는 그대로다.
- 바뀐 줄(B1): 영수증 스키마를 바꾸지 않는다. 같은 `requestId` 가 다시 오면 상태를 바꾸지 않고 지금 상태로 `resumed` · `deferred` 를 `replayed: true` 와 함께 돌려준다. 둘 다 아니면 `unavailable` 과 사유 `already-processed`. `started` 는 도전을 실제로 만든 첫 요청에만 낸다.

구현 때 내가 맡을 자리의 메모(§4)는 그대로다. 표는 20개다(v02 의 17 + 개념 · 활동 + 보관본).
