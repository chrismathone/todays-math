# 실물 에셋 편집·명세 안내 연결

엔진 통합 06(`2dc8d3857` 원격 체크포인트) 뒤, 전달 05의 src 7파일을 현재 편집기에 맞춰 연결했다. 집·건물 같은 실물 그림은 요소 하나로 선택·회전·대칭·삭제하고, AI 명세 안내는 같은 picture-assets 목록을 읽는다. 숫자 뒤 띄어 쓴 m/g와 mL의 정자 표기를 두 MathJax 조판기에 연결했다. 교사 편집 도구·엔진 작업이며 기존 문항이나 DB를 다시 쓰지 않는다.

전달 패치 그대로의 `assetBox`는 경로 숫자를 두 개씩 좌표처럼 읽고 사각형의 대각 두 점만 변환한다. 이는 H/V·호·상대 좌표와 회전된 도형에서 잘못된 상자를 만들 수 있다. 현재 코드는 실제 등록 에셋의 형상과 자식 변환이 일치할 때만 하나의 조각으로 취급하고, 등록 viewBox의 네 모서리를 그림 좌표로 옮겨 **틀 상자**를 쓴다. 픽셀로 잰 잉크 상자나 수학적 길이가 아니다. 회전·대칭도 기존 공통 엔진에서 조각 전체의 변환으로 처리한다.

`build_asset_editor_registry.py`가 실제 manifest/SVG 39종에서 기하 구조·틀·소스 텍스트 해시를 생성한다. 소스 해시는 `sha256-utf8-lf`로 명시해 다른 컴퓨터의 CRLF/LF 차이에도 재현한다. 각 소스와 해시를 실제 비교하고 생성기 재실행 결과가 현재 JSON과 바이트 동일함을 확인했다. 색·선 굵기 변경은 허용하지만 형상·중첩 변환이 바뀌거나 수학 선을 끼워 넣으면 marker만 제거하고 실제 도형을 일반 요소로 남긴다. 알 수 없는 slug·leaf의 marker도 같은 경계를 따른다. 이 일치는 등록된 **형상 식별**이며 출처·권리 승인 서명이 아니다.

유효하지 않은 transform을 identity로 대체해 틀을 인증하지 않는다. 지원 변환의 문법·개수·유한 수·행렬 비퇴화를 검사하고 불명은 일반 도형으로 유지한다. 기존 모눈 수치·배치 검사와 내부 SVG 라벨의 실행/외부 참조 차단도 보존했다. `stripAssetBodies`의 이름만 보고 본문을 삭제하는 구현은 들이지 않았고, 대조·편집 증거의 SVG 본문을 유지한다.

명세 안내의 “right:true는 항상 화면에서 수직”과 “원근 표시 지원” 충돌도 해소했다. 평면 직각은 기존 수직 검산을 유지하고 원문에 명시된 투영된 입체 직각만 perspective로 표시한다. 해당 표시는 공간 직각의 증명이나 학년 허용 근거가 아니며, 엔진 오류를 피하려고 평면 그림에 플래그를 붙이지 않게 했다. 지원하지 않는 사진·삽화나 보이지 않는 수학 조건을 임의로 만들지 않는다. 모델·강도·라우팅·최종 figureReview 계약은 바꾸지 않았다.

화면 검사 초기 r1에서는 상세 회전 단추가 undo로 사라지며 초점이 body로 빠져 다음 Ctrl+Y가 무시됐다. r3에서는 선택한 요소 단추를 Delete로 지운 뒤에도 같은 이유로 Ctrl+Z가 무시됐다. 단축키 undo/redo/delete 뒤 캔버스에 초점을 돌리고 회전·삭제 두 회귀를 추가했다. 중간 r2의 선택이 풀린 상태에서 삭제하려던 QA 스크립트 오류도 보존하고 재선택하도록 수정했다. 최종 화면 r4는 오류 0이다. 원래 실패·수정 후 결과를 지우거나 스킵을 통과로 세지 않았다.

메모리 사전 기준 미달 실행은 Node 시작 전에 건너뛰었다. 절약용 384MiB 한도로 시작한 타입 검사는 heap 한도 초과로 종료되어 실패 로그를 보존했고 통과로 세지 않았다. 메모리 회복 후 512MiB의 단일 Node로 현재 12파일을 검사해 통과했다 (`types-next-ambient-r4.json`). 독립 Node 검사는 별도로 192MiB/실제 V8 한도 216MiB에서 끝났고 부모 UI·175개 검사를 자기 검수로 복사하지 않았다. 독립 검수의 두 MathJax/Python 교차 대조는 미실행으로 남기며, 부모의 두 조판기 단위 검사는 그와 구분한다.

QA는 `.qa-artifacts/exam-resume-20261008/engine-upgrade-20261019/assets-editor-integration-20261021-r1/`, 화면 결과는 `browser/browser-results-r4.json`이다. 1280·390 화면 PNG를 직접 확인했다. 전체 작업실·인쇄·실제 출제 문항의 전수 검증은 아니다. 기존 v50 집계·보호 잠금·원본·타 세션 파일은 그대로 유지하고 최종/적재 가능·운영 쓰기·배포는 0이다. 모눈 실측 보조와 남은 엔진 카드 등 전체 개선은 계속 미완료로 추적한다.

독립 실행은 `figure-assets-editor-current-audit-20261021-r1/own-executed-report.json`(`c3c2b8359`), 그 준비는 `f282a0e50`, 이전 정적 반례는 `f0fb427c6`으로 보존했다. 준비·정적 감사·실제 실행과 과거 코드 스냅샷의 결과를 현재 전체 UI 검증으로 확장하지 않는다.

최신 main `7266c9b28`의 SRS 11커밋을 `f81b1d3ac`에 보존 통합했다. 이후 현재 11파일 175개 회귀를 다시 실행하여 실패 0을 확인했고, 사용자 지정 원본 `check_engine.py`도 다시 실행해 6종 출력 모두 바이트 일치를 확인했다. 외부 확인 스크립트와 기대 파일의 해시도 그대로다. 독립 88개와 이전 화면·타입·린트 결과는 각 소스 해시에 묶인 별도 실행이며 새 회귀 수에 더하지 않는다. 최신 증거는 `assets-editor-after-main-r1-execution.json`과 `engine-all-sync-20261021-r1/check-after-main-r1.json`, 통합 원장은 `engine-upgrades-progress-r57.json`이다.

재개 직후 이 작업트리의 Git 인덱스·참조·일부 검수 보조 파일에서 NUL만 남은 기록이 관측됐다. 원인은 확정하지 않았다. 손상 바이트를 외부 별도 폴더에 먼저 백업하고, 살아 있는 `cf392bde6` 커밋 객체에서 이 작업트리의 인덱스·참조와 검수 보조 파일 7개를 복원했다. 내용이 같은 줄바꿈 차이 2파일도 커밋 바이트로 되돌렸다. 실제 코드 144파일의 검수 해시는 모두 일치한다. 병합이 임시 참조에서 중단되며 남긴 새 main 파일 23개는 원격 내용과 비교·별도 보존한 뒤 정상 병합했다. 브랜치 reset/clean/force-push나 기존 문항·DB 쓰기는 없다. 재현 기록은 `engine-upgrade-20261019/git-recovery-20261021-r1/recovery-summary.json`, 원본 메타데이터 백업은 그 기록에 명시된 로컬 외부 폴더에 보존한다.
