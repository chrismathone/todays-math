## 실제 화면

[확정 H3-B와 구현 나란히](h3-b-side-by-side.png) · [구현 원본 크기](actual-desktop.png) · [모바일 카드](actual-mobile.png) · [모바일 크게 보기](actual-mobile-preview.png) · [끌기 삽입선](actual-drag.png) · [자동 제외 안내](actual-auto-excluded.png).

Orca 내장 Chromium 하나로 목업과 실제 `StudioView`를 열었다. 시연 PDF의 앞 6쪽/뒤 2쪽을 로컬에서 나눠 두 파일로 가져왔다. 데스크톱은 카드 다섯 열과 340px 오른쪽 칸이다. 320·390·768px 문서 가로 넘침 없음, 390px 조작 단추 44×44px 이상, 오른쪽 칸은 아래로 쌓여 스크롤로 접근한다. 데스크톱 단추는 H3-B의 34px/28px/26px 밀도다.

브라우저에서 파일 사이 `앞으로`, Alt+←, 빼기와 되돌리기, 손잡이의 native dragstart/dragover/drop과 파란 세로선, 새 차례의 영역 지정 목록을 확인했다. 끌기 뒤 본문 원본 2→1→3→4→서술형 원본 2→본문 5→6→서술형 1의 차례를 확인했다. 합성 두 파일을 추가하자 이전 차례를 유지하며 뒤에 붙었고 자동 제외 세 쪽을 건너뛴 11쪽이 영역 지정 select에 나타났다. 로컬 IndexedDB에 저장한 섞인 차례는 새로고침 후에도 유지됐다. 인식 호출·담기 차례·상자/해설 보존은 아래 RTL로 검사했다. 시연 녹화본을 읽거나 쓰지 않았다.

공유 DB 연결을 없앤 임시 `/dev/studio-page-order-qa`에서 실제 컴포넌트를 사용했다. 임시 `AUTH_SECRET`, 연결 불가능한 localhost DB 주소, 외부 API 차단 fetch를 사용했으며 환경 파일은 복사하지 않았다. 기존 dev 자산 route가 이 Webpack 환경에서 500을 내므로 설치된 **같은 pdfjs-dist** worker·wasm·font를 로컬 정적 경로로 제공했다. 제품의 PDF 로드 경로는 바꾸지 않았다. 검수용 route·symlink·worker는 제거했고 두 로컬 서버를 종료했다. 재현용 임시 harness와 측정용 PDF는 무시되는 `scratch/page-order/`에만 남겼다. 운영 빌드는 실행하지 않았다.

실제 Next 화면에서 확인한 React 목록 key 경고는 공용 편집 카드의 `key`를 props spread 앞으로 옮겨 해결했다(새로고침 후 경고 없음). 같은 키로 카드 이미지·caption도 고정했다. 기존 MathJax named-export 개발 경고는 이번 범위 밖이다.

## 실제 PDF 측정

제품의 `renderStudioPagePreview`와 `measurePageInk`를 로컬 브라우저에서 사용했다. PDF.js viewport는 최대 728×1031, 흰 바탕 합성 후 RGB 어느 채널이든 252 미만이면 잉크다. 글이 없고 비율이 **0.000001 미만**인 경우에만 빈 쪽이다. 이 해상도에서는 잉크 한 픽셀도 약 0.00000133이므로 보존한다. 문턱을 넓혀 희미한 문항을 자동 제외하지 않았다. 원시 결과는 [measurements.json](measurements.json).

관측한 14쪽 중 문항의 거짓 제외는 0쪽이다. 이것은 작은 표본의 관측이며 전체 교재 성능을 뜻하지 않는다. 실제 스캔 표지 1쪽은 의도적으로 남긴다. 텍스트 없는 스캔에서 그림으로 표지/정답표를 구별하지 않는다. 거의 흰 252~255 픽셀만으로 된 내용, 훼손되거나 불완전한 PDF 텍스트층까지 보존한다고 보증하지 않는다. 사람이 복원할 수 있도록 모든 제외 쪽은 자리와 원본 신분을 유지한다.

PDF.js가 `2`와 `학년`을 다른 text item으로 내보내는 실제 합성 PDF에서 표지 인식 누락을 발견했다. 인접 x좌표·width로 붙어 있는 글자를 복원하는 시험을 RED로 확인한 뒤 수정했다. 분리된 열/줄은 공백과 줄머리를 유지한다.

## 범위

별도 갤러리를 만들지 않고 `PaperStrip.editable`로 공용 격자/선택/삽입선/옆 칸을 확장했다. 카드 자체는 클릭·hover 배경·손가락 커서가 없다. 그림은 신분+회전별 캐시를 공유하며 나열·선택마다 다시 렌더하지 않는다. `sourceId+page`는 불변이고, 저장한 상자 배열을 유지한 채 활성 차례의 파생 목록만 정렬한다. 제외 쪽의 상자·문항·해설은 삭제하지 않는다. 자동 분석은 새로 가져온 파일에만 한 번 적용하며 저장본 복원·되살리기·단계 재진입 시 덮어쓰지 않는다.

Orca Codex 두 작업자로 모델과 UI를 분담했다. 별도 자식 worktree 생성이 기존 Orca 저장 경로 권한 오류로 거절돼 같은 작업트리에서 파일 소유를 나눴고, 작업자 모두 커밋하지 않은 채 결과를 돌려줬다. 통합·검수·커밋은 코디네이터가 수행한다. 사용자 지시에 따라 main 병합·push·공유 DB 쓰기는 하지 않는다.

호환 범위는 **옛 저장본을 새 코드가 읽는 것**이다. 이전 코드의 세션 검증은 새 `order` 단계를 거부하므로, 배포 후 이 단계로 저장한 자료를 구버전 화면에서 다시 여는 것은 지원하지 않는다. 이 작업에서는 실제 공유 저장소에 새 기록을 쓰지 않았다.
