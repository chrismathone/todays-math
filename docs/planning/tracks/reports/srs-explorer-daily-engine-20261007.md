## 2. 화면이 쓰는 길

```ts
source.dailyPlan?.({ quota: 20 }) // → FadingDailyPlan (없으면 지금의 네 길만으로 그대로 돈다)
```

- `activities` 는 **할 차례**다: 풀던 것 → 복습 → 선수 개념 → 새 진도의 개념 → 탐험의 한 덩이, 오늘 못 내는 것 · 끝난 것은 뒤. `next` 가 지금 할 것의 열쇠다.
- `kind: "recall"`(개념 떠올리기 · 선수 개념 확인도 이것 — `bucket` 으로 가른다): `start` 가 `continue` 면 열린 풀이, `open` · `pick-open` 이면 `act({ action: "open", conceptId })` 하나로 시작한다(고르기까지 된다). 그 뒤는 지금의 풀이 흐름 그대로다.
- `kind: "practice"`(탐험의 한 덩이): 지금 있는 탐험의 시작 · 이어 하기로 한다. `state: "blocked"` 면 오늘은 내지 않는 것이다(`reason.code` 가 `over-budget` 이면 남은 칸에 안 들어가서, `blocked` 면 시작할 수 없어서).
- 🔴 계획은 **읽기뿐**이다. 한 것(`done`)은 저장된 기록이 말하는 만큼만이다 — 오늘 평가로 닫은 개념 · 탐험이 적은 푼 문제 수.

## 3. 넣는 규칙

분량(`quota.total`)은 **넘지 않는 합계**다. 정해 둔 비율이 없다 — 넣는 차례가 우선순위다.

1. **풀던 것**(열린 풀이 · 풀던 탐험) — 빚진 것이라 분량을 넘어도 낸다(`quota.over`).
2. **복습일이 된 개념** — 망각 위험(지금의 `fsrsRetrievability` 로 낸 떠올릴 확률의 나머지)이 큰 것부터. 밀린 날 수가 아니다. 복습이 분량을 다 쓰면 그 뒤는 0 이다.
   선수 개념 가운데 **근거가 있는 것**(«다시»로 끝났거나 복습일이 된 것)도 이 차례에 같이 든다. 학생이 «오늘 전부»를 고른 날은 전부 낸다(학생이 고른 분량이다).
3. **탐험의 한 덩이** — 남은 칸에 **통째로** 들어갈 때만.
4. **확인한 기록이 없는 선수 개념** — 적혀 있는 연결마다 **하루에 하나**. 필요한지 아직 모르는 것이라 탐험의 덩이를 밀어내지 않는다(내 판단 — 조율자가 전한 차례는 «복습 → 필요한 선수 확인 → 새 진도»였고,
   «필요한»을 «근거가 있는»으로 읽었다. 기록이 없을 뿐인 것을 덩이 앞에 두면 분량이 10 인 학생은 선수 묶음이 남아 있는 날마다 탐험이 안 나간다).
   그 개념 자신의 풀이라 그 개념의 복습일만 정해진다. 읽어 보기만 하는 것은 칸을 쓰지 않는다(안내에만 실린다).
5. **새 개념** — 학생이 골라 둔 것 → 오늘 진도 소단원의 아직 고르지 않은 것(하 → 중 → 상).

놓는 차례(`activities`)는 넣는 차례와 따로다 — 풀던 것 → 복습 → 선수 개념 → 새 개념 → 탐험의 덩이(확인과 개념을 문제보다 먼저 한다).

- **칸의 단위는 «물음 하나»다** — 문제 하나 · 카드 활동 하나 · 개념 묶음의 **명제 하나**. 묶음 하나(명제 3 ~ 5)는 3 ~ 5칸이고, 네 단계의 되풀이를 곱하지 않는다.
  실제 수는 `units` 에 따로 있다: 묶음(`recall`) · 명제(`prompt`) · 문제(`question`) · 카드 활동(`task`).
- 묶음도 탐험의 덩이도 **쪼개지 않는다.** 남은 칸에 안 들어가면 건너뛴다 — 복습은 `held` 에(복습일은 그대로다), 탐험의 덩이는 `blocked` 로 싣는다.
- 못 채운 칸은 채워 넣지 않고 `shortfall` 로 낸다(까닭과 함께).
- 분량을 안 주면 20 이 **대신 값**으로 들어가고 `quota.source` 가 `default` 다 — 정해진 하루 분량이 아니다. 저장하는 값이 아니라 부를 때마다 준다(1 ~ 60).

## 4. 선수 개념의 안내 — 적혀 있는 연결만

쓰는 연결은 넷이고 전부 사람이 적어 둔 것이다.

1. 코스 소단원 ↔ 은행 소단원 열쇠 — 같은 교육과정 시드의 같은 줄(글자를 견주어 찾지 않는다).
2. 소단원 → 개념 카드 · 탐험 단원 → 소단원(`curriculumBridge.ts`).
3. 개념 카드 → 선수 카드(카드 자료의 `prerequisites`).
4. 교육과정 연결도의 단원 간선 — 확인된 시범 매핑(`E56-N03 → E56-N04`)이 닿는 단원만 · 직접 선수만.

근거는 **원천마다 따로** 싣는다(`unassessed` · `weak` · `stale` · `recent` · `unknown`). `recent` 는 숙달이 아니다.

## 5. 한계 — 있는 그대로

1. **문제를 하나씩 고르지 않는다.** 탐험의 하루 분량(초등 문제은행 10 · 중1 12 · 개념 날 카드 활동 15)을 **덩이째** 낸다. 덩이 안의 복습 · 새 소단원의 섞임은 탐험의 규칙(`expeditionCourseRecommendation`)이 정한다 —
   «문제은행 문제 스무 개를 위험 순으로 한 줄로 짠 것»이 아니다. 그렇게 하려면 탐험의 추천과 쓰기 가드를 고쳐야 한다(이번 범위 밖).
2. **밀린 복습이 분량을 채우면 탐험은 그날 나가지 않는다.** 조율자가 전한 규칙(복습 → 선수 → 남은 칸에 새 진도 · 덩이는 들어갈 때만)을 그대로 따랐다.
   복습이 날마다 밀리는 학생은 진도판이 멈춘다 — **원장님이 보실 것.**
3. **분량의 저장 칸이 없다.** 교사가 정한 «하루 몇 개»를 읽는 길이 아니라 부르는 쪽이 주는 값이다(DB · 꼴을 안 건드리려고). 초등 코스의 `dailyQuestionCount` 는 탐험 안에서 이미 쓰이지 않는다(탐험의 초등 날은 늘 10).
4. **칸이 딱 맞지 않는 날이 흔하다.** 묶음이 3 ~ 5칸이라 한두 칸이 남는다 — 채워 넣지 않고 `shortfall` 로 낸다.
5. **일정은 날 단위 · 묶음 단위다.** «다시»는 내일이 복습일이고, 복습일은 묶음 하나에 하나다(명제마다 따로 없다). 같은 날 1분 · 5분 뒤에 다시 묻는 것은 이 계획에 없다 — 따로 선 작업이 맡는다.
   이 계획은 **기본 분량**만 말하고 그 덤을 더해 세지 않는다.
6. **선수 연결은 적혀 있는 만큼만 닿는다**(§4 의 표). 코스 근거는 시범 소단원 넷뿐이다.
7. **옛 개념 카드 · 중1 은행의 복습 만기**는 탐험이 «복습하는 날»로 정했을 때만 계획에 보인다(탐험의 덩이가 복습 갈래로 실린다). 이 계획이 따로 위험 순으로 세우지 않는다 — 옛 일정은 망각 위험을 내지 않는다.
8. 같은 날 탐험의 칸을 얻은 뒤 다른 미션이 열리면(풀다 만 옛 세션), 계획에는 열린 미션만 보이고 끝낸 칸은 안 보인다.
9. 화면 · 브라우저 · 운영 DB 로는 보지 않았다. 시험은 전부 메모리의 대역으로 돈다.
