지시서 `docs/planning/tracks/brief-builder-simple-hifi-codex.md`에 따라 네 안의 1·2단계, 총 여덟 화면을 만들었다. **커밋·스테이징·push를 하지 않았다.** 제품 부품·공유 가드·기존 Wire 파일을 수정하지 않았으며 DB·`.env`·`prisma generate`·외부 API를 사용하지 않았다.

## 확인 경로

- `/dev/exam-builder-simple-hifi`
- `#H1`~`#H4`: 안별 설명·약점과 두 단계.
- `#H1-1`~`#H4-2`: 개별 화면.

네 안 모두 **1단계 넓은 단원 목록 + 오른쪽 조건 칸**, **출처 전체/교과서만 한 줄**, **2단계 왼쪽 통계·순서표 + 오른쪽 문항**을 유지한다. 안별로 모양·밀도·강조와 막힘 안내 위치만 달리했다.

## 안별 차이

## 상태와 조작

각 2단계 화면의 ‘진행 상태’에서 다음 여섯 장면을 선택한다.

| 장면          | 표시                                                                                  |
| ------------- | ------------------------------------------------------------------------------------- |
| 진행 가능     | 실제 담은 수를 유지하고 다음 단계 링크 활성                                           |
| 확인 중       | ‘출력할 문항을 확인하는 중입니다. 확인이 끝나면 다음 단계로 이동합니다.’              |
| 0문항         | ‘담은 문항이 없습니다. 범위 설정에서 문항을 구성해 주세요.’                           |
| 출력 권한     | ‘양식 구성·출력 권한이 없습니다. 원장님에게 출력 권한을 요청해 주세요.’               |
| 총수 불일치   | 지정 총수·현재 수와 부족/초과 수를 표시하고 추가·조건 수정 진입 제공                  |
| 형식별 불일치 | 실제 형식별 지정값과 현재 수를 표시하고 조건 수정 진입 제공. 지정한 0도 생략하지 않음 |

다섯 막힘 장면은 다음 단추와 같은 영역에 이유를 두고 `aria-describedby`로 연결한다. 문항 추가·교체·조건 적용·빼기 후에는 실제 시안 배열과 조건을 다시 대조한다. 목록 대기·실패 자체를 출력 차단 원인으로 취급하지 않는다.

각 1·2단계 화면의 ‘목록 상태’에서 표시/불러오는 중/실패를 바꾼다. 범위·교과서·문항·추가/교체 후보는 **해당 목록 영역 가운데**에서 안내한다. 실패는 ‘목록을 불러오지 못했습니다. / 선택은 유지됩니다. / 다시 불러오기’이며 `role=alert`와 재시도 단추를 제공한다. 가짜 진행률·예상 시간은 없다.

범위 체크·검색·쪽 이동, 출처 선택, 난이도·형식 입력, 창 열기/취소/적용, 조건 이름 변경/삭제/보관, 문항 대조/교체/추가/빼기/되돌리기, 드래그·키보드 순서 변경은 시안 안에서 동작한다. 수 입력의 음수·소수·범위 밖 값은 적용을 막는다. 교체 후에는 같은 자리의 조작을 유지하며, 막힘 해소로 복구 단추가 사라지는 경우 상단 구성 조건 단추로 초점을 옮긴다.

**두 단계는 독립 픽스처 장면이다.** ‘문항 구성’은 같은 안의 2단계로 이동하고, 출력 진입은 이 시안의 기존 3단계 안내로 이동한다. 제품의 생성·클라우드 저장·출력은 실행하지 않는다. 책·출처 선택도 실제 보유량을 조회하는 동작이 아니다. 실제 3단계는 기존 WorksheetEditor·여섯 양식을 그대로 잇는 대상으로 명시했다.

## 데이터·토큰·반응형

- 전체 735범위는 지시서의 관측 규모이며 현재 DB 조회 결과가 아니다.
- 초3 1학기의 긴 실제 차시명 31개를 원본 순서로 담고 20개씩 표시한다. 가능 수·책·문항은 자체 픽스처다.
- 34·40·50·36개의 실제 문항 배열에서 통계·난이도·형식·범위 수를 센다. 순서표와 문항 목록은 같은 쪽의 여섯 문항을 보여 준다.
- 제작 화면에 보유 수 줄을 넣지 않았다. 선택 범위 수와 해당 범위의 예시 가능 수는 남겼다.
- 현재 `globals.css`의 `--learn-*`, 글자 크기, 반경, dialog 폭과 ExamBuilder의 `--builder-border/control` 별칭을 사용한다. Pretendard와 동일 폴백을 사용하고 색 hex를 새로 복제하지 않았다.
- 그라데이션·기성 킷·장식 아이콘·이모지를 사용하지 않았다. 난이도 분포는 중립색으로 표시한다.
- 최대 본문은 1040px이다. 바깥 1080px에 양쪽 20px 여백을 포함한다. 1440px viewport에서도 이 본문을 유지하며 좁은 폭에서는 유동으로 줄어든다.
- 900px 가용 컨테이너부터 한 열로 쌓는다. 300px 조건 칸과 넓은 범위 목록의 최소 사용 폭을 확보하기 위한 시안 분기이며 제품 breakpoint는 변경하지 않았다. 600/420px에서 조작과 순서표를 재배치한다.
- 긴 이름은 줄바꿈하고 grid/flex의 유동 열에 `min-width:0`과 `minmax(0,1fr)`를 사용했다. 가로 넘침을 숨기기 위한 `overflow-x:hidden/clip`은 없다. 조작 높이는 44px 이상이며 긴 폼은 통째로 고정하지 않는다.

반응형 CSS와 DOM은 검토했지만, 아래 브라우저 기동 제한 때문에 **실측 가로 넘침 0을 확인했다고 주장하지 않는다.**

시험은 여덟 화면과 내부 링크·A의 열 구조·픽스처 합·객관식 먼저·모든 막힘 전환·실패/재시도와 입력 보존·정답 접힘·구성 조건의 취소/적용·0/빈 칸·음수/소수·조건 관리·ID 충돌 방지·명시적 교체와 같은 자리/초점·되돌리기·키보드 이동을 다룬다. jsdom의 dialog shim은 열기/닫기와 초점 복귀만 확인하며 **브라우저 focus trap·Escape·top layer 검증은 아니다.**

독립 읽기 전용 검토에서 보고된 본문 폭, 초기 형식 순서, 저장 조건 ID 충돌, 교체 후 초점 문제를 반영했다. 제품 기본값·권한·저장 계약의 변경은 없다.

### 폭 측정 스크립트

`scripts/qa/measure-builder-simple-hifi.mjs`는 Next 서버를 시작하지 않고, Hi-fi 폴더와 기존 순수 조건 계산기만 Vite로 번들한다. 루트 설정과 환경 파일을 읽지 않으며 로컬 토큰·Pretendard를 정적 HTML에 포함한다. 외부 요청을 막고 산출물은 `/tmp`에만 쓴다.

계획된 측정은 1440×1000, 1050×900, 768×1024, 390×844, 320×640, 1440×600의 여섯 크기와 각 38장면(기본·긴 제목·여덟 목록의 대기/실패·네 안의 다섯 막힘), 총 228조합이다. 문서·본문·각 화면의 `scrollWidth-clientWidth`, 가림으로 숨긴 넘침, 화면 밖으로 나온 요소, 화면 간 상태 누출을 검사한다. `--screenshots`로 캡처를 남길 수 있다.

이 환경에서는 `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome` 실행이 `Failed to launch the browser process: Code: null`로 실패했다. **측정 횟수는 0이며 통과가 아니다.** 스크립트와 오프라인 HTML 생성은 확인했고 실제 화면·폰 폭·짧은 높이·창의 브라우저 검수는 미확인으로 남긴다. 권한 확장이나 브라우저 GUI 우회는 시도하지 않았다.

최종 로컬 산출물:

- `/tmp/builder-simple-hifi-gNkLp1/standalone.html` — 토큰·글꼴·시안·조작을 포함한 독립 미리보기.
- `/tmp/builder-simple-hifi-gNkLp1/measurements.json` — 번들 크기·브라우저 기동 오류·측정 생략 기록.
- `/tmp/builder-simple-hifi-tests.log`, `/tmp/builder-simple-hifi-type-check.log` — 최종 시험·타입 검사 로그.

이 경로들은 임시 산출물이며 위 명령으로 다시 만들 수 있다.

Orca의 `worktree current --json`도 샌드박스 `runtime_access_denied (EPERM)`으로 차단되었다. 새 작업트리·커밋·병합 없이 지정 작업트리에서 구현하고, 독립 에이전트로 읽기 전용 검토와 QA 스크립트 작업을 병행했다. 기존 미추적 Wire 파일과 지시서는 보존했다.
