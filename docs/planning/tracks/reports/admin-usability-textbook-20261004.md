## 하지 않은 것 · 한계

- **브라우저 확인을 하지 않았다.** jsdom 시험만 돌렸다. 실제 이동·저장·내려받기와 데스크톱/모바일 배치는 리드의 통합 확인 대상이다.
- **전체 타입 검사를 통과시키지 못했다.** 이 워크트리에서 `tsc --noEmit` 전체가 4GB 힙에서 메모리 부족으로 죽었다(10분). 교재 소스·시험만 포함한 설정으로 검사했다. 전체 시험도 돌리지 않았다.
- **가려진 화면에서의 앱 안 링크.** 교재 화면이 작업실의 다른 화면에 가려져 있을 때는 링크를 막지 않는다(확인 칸이 보이지 않아 갇히기 때문). 그 상태에서 작업실 밖으로 나가는 링크를 누르면 저장하지 않은 원고가 경고 없이 사라진다. 작업실에는 화면별 `…-before-leave` 취소 이벤트가 있다(`UnifiedWorkspace.tsx`). 교재도 그 방식으로 묶으려면 작업실 쪽 수정이 필요하다 — 리드 결정.
- **다른 사람이 고친 구획 + 내 미저장 원고.** 개념 연결 다시 시도는 서버의 최신 구획에 블록을 붙이되 내 원고는 건드리지 않는다. 이후 원고 저장은 기존 409 충돌 화면으로 간다.
- **영상 목록.** 연결이 하나라도 있으면 연결만 보여 주는 기존 `listVideos` 동작은 그대로다. 고르기용 `listVideoChoices` 를 API 인터페이스에 더했다(같은 `/api/textbook/videos` 응답 사용, 서버 변경 없음).
- **문항 내용을 볼 수 없는 연결.** 그 판본의 자료에 확정본이 없으면 검수 요청·게시를 보낼 수 없다. 새 연결을 만들어야 한다.
- 옛 strict reader 는 `teacherAnswer` 가 든 패키지를 거절한다(P1 계약의 기존 규칙).
- `node_modules` 는 리드 워크트리로 가는 정션이다. 이 워크트리를 지울 때는 정션만 먼저 `rmdir` 한다.

### 작업실 이탈 연동 (T03 나머지)

- `src/lib/textbook/navigation.ts` — `requestTextbookNavigation(proceed)`. 취소 가능한 `textbook-before-leave` 이벤트를 `detail.proceed` 와 함께 낸다. `true` 면 막는 쪽이 없어 부른 쪽이 바로 이동하고, `false` 면 교재 화면이 이동을 붙잡은 것이다.
- 교재 화면은 고친 것이 있거나 처리 중이고 **화면이 보이는 동안** 이 이벤트를 붙잡는다.
  - 고친 것이 있으면 기존 공통 확인 칸을 띄운다. 저장이 성공하거나 버린 뒤에만 `proceed` 를 한 번 부른다. «계속 편집»이면 부르지 않고 화면과 입력이 그대로다. 저장이 실패하면 부르지 않고 확인 칸이 남는다.
  - 저장·불러오기·조판이 도는 동안에는 붙잡기만 하고 «처리 중입니다»를 알린다. 그 `proceed` 는 부르지 않는다 — 끝난 뒤 다시 눌러야 한다.
  - 작업실 화면 전환 뒤에도 교재는 연 채로 남는다(목록으로 돌아가지 않는다).
- 새로고침·탭 닫기의 기본 경고에 처리 중 상태를 넣었다.
- **승인한 이동이 다시 물어 올 때.** 작업실의 `#` · 뒤로가기 연결은 넘겨준 `proceed` 안에서 주소를 되돌리고 같은 동기화를 다시 돌리며, 그 동기화가 헬퍼를 한 번 더 부른다. 그 순간 화면은 아직 다시 그려지기 전이라 옛 «고친 것이 있다 / 저장 중» 상태를 본다. 승인 표시를 `proceed` 를 부르기 직전에 세우고, 살아 있는 동안에는 붙잡지 않는다. 상태가 바뀌어 다시 그려지면(또는 다음 틱에) 거둔다 — 다음 이동까지 남지 않는다.
- 리드가 연결할 때: 다음 화면이 교재가 아닐 때 부르면 된다. 교재 화면이 가려져 있으면 붙잡지 않고 `true` 를 돌려준다 — 다른 화면 사이의 이동이 보이지 않는 확인 칸에 갇히지 않는다. 지금 제품 코드에서 이 헬퍼를 부르는 곳은 아직 없다.
- 1차 보고의 한계 «가려진 화면에서의 앱 안 링크»는 그대로 남아 있다. 교재가 가려진 채로 작업실 밖으로 나가는 링크를 누르면 미저장 원고가 경고 없이 사라진다. 그 상태에서도 새로고침·탭 닫기는 경고한다.

| 되돌리기 | 고친 뒤 실제 `location.reload()` 에 브라우저의 `beforeunload` 대화상자가 뜨고, 머무르면 원고가 남는다. 원래 값으로 되돌리면 경고가 풀리고 목록 이동이 확인 없이 된다 |
| 저장·버리기·계속 | 완성 보기의 다른 구획, 작업실의 다른 화면, 작업실 밖 링크에서 같은 확인 칸. 계속 편집 → 화면·입력 그대로. 버리고 이동 → 화면이 바뀌고 돌아오면 저장된 값. 저장 후 이동 → 저장 1회 뒤 화면 전환 |
| 주소의 `#` · 뒤로가기 | 고친 채 `#other` 로 바꾸면 붙잡고 주소가 교재로 되돌아온다. 버리고 이동 → 넘겨준 길이 주소를 되돌리고 다시 물어도 붙잡히지 않아 화면과 주소가 바뀐다. 뒤로 와서 다시 고친 뒤 앞으로 가기 → 붙잡힘 → 저장 후 이동 → 저장 1회 뒤 이동 |
| 저장 중 보호 | 저장 응답을 붙잡아 둔 동안 단추가 막히고, 억지로 눌러도 요청은 1회. 작업실 화면 전환은 붙잡히고 «처리 중입니다» 표시 |
| 발행 뒤 읽기 실패 | 확정 성공 → 판본 읽기 503 → 알림과 함께 이미 잠김(원고 입력 불가·확정 비활성) → «판본 다시 불러오기» → 확정 요청은 1회, PDF 링크 표시 |
| 개념 연결 다시 시도 | 개념 저장 성공 + 구획 저장 409 → «개념 저장 완료 · 구획 연결 실패», 원고 유지 → 다시 시도는 구획 저장만(개념 저장 1회) → 새로 고쳐 다시 열면 개념이 붙어 있다 |
| 가로 넘침 320px · 390px | 완성 보기 · 세부 편집(메모 입력) · 확인 칸 · 배정 · 영상 · 목록과 가져오기 칸에서 `scrollWidth − clientWidth ≤ 1`. 화면 캡처는 `test-results/textbook-admin/` |

각 시험은 모르는 API 요청 0건과 콘솔·페이지 오류 0건을 함께 단정한다(일부러 낸 409·503 의 네트워크 오류 줄은 뺀다).

브라우저 시험이 결함을 잡는지: 작업실 이탈을 막지 않게, 그리고 클라이언트가 메모를 보내지 않게 되돌려 다시 빌드하니 당시 8개 중 3개가 실패했다. 승인 표시를 보지 않게 되돌리면 `#` · 뒤로가기 시험이 실패한다(버린 뒤에도 화면이 교재에 남는다). 되돌린 뒤 소스가 백업과 같음을 확인했다.

### 단위 시험 (브라우저와 따로)

- 작업실 이탈 7개와 승인한 이동의 재요청 4개를 `TextbookStudioUsability.test.tsx` 에 더했다(이제 40개). 구현 전에 각각 5개 · 2개가 실패하는 것을 먼저 봤다.
- 학생 비노출·판본 해시·서버의 409 는 브라우저로 재지 않았다. 1차의 PGlite·단위 시험이 근거다.
- 병합 뒤 대상 실행: 17파일 **416개 통과**(exit 0). 하니스 폴더 `tsc -p e2e/textbook-admin/tsconfig.json` 통과. 바뀐 파일 ESLint 오류 0, 어포던스 검사 통과.
- 전체 타입 검사와 전체 시험은 다시 돌리지 않았다.

### 한계

- 하니스의 작업실은 모형이다(`main.tsx` — `hidden` 으로 가리고 헬퍼로 묻는 것만 흉내 낸다). 제품 `UnifiedWorkspace` 의 옆 메뉴·단축키·`#`·뒤로가기 연결은 리드의 통합 가지에서 확인해야 한다.
- 합성 서버는 계약에 맞는 응답을 지어낼 뿐이다. 실제 서버의 권한·CAS·발행은 확인하지 않는다.
- Chromium 만 돌렸다. 데스크톱 1280px 와 320·390px 만 봤다. 실제 PDF 생성·파일 올리기·영상 연결·배정 추가는 브라우저로 돌리지 않았다.
- `beforeunload` 대화상자는 «머무르기» 쪽만 확인했다.
- 「고급 입력」 펼침에 자동 만들기 칸과 같은 모양의 스타일을 `textbook.module.css` 에 더했다(손가락 커서·굵은 글).
