# B · DB textbook blind solving and semantic review

Implemented `reviewDbRetryPair` in `src/lib/import/schoolTextbook/dbRetryReview.ts`, with shared evidence additions in `dbRetry.types.ts` and an injected-dependency unit suite. Base: `e2de60f0d`. This worker did not write to the shared database, copy the root credentials, invoke a paid model, or run a whole batch. The existing `node_modules` junction was preserved.

The first reasoning request receives only the original and two candidate question texts, question types, fixed local problem identifiers and actual figure images with their choice associations. It receives no stored answers, candidate answers, author solutions, generator checks, source identifiers or curriculum hints. The three returned answers must independently agree with their stored counterparts. Missing conditions/images, unknown answers, ambiguous results, empty reasoning, duplicate/omitted problem results and malformed pairs fail the review. The code checks actual image bytes against their hashes and accepted raster signatures; it does not substitute image URLs or missing figures with text.

A separate reasoning request then checks both candidate worked solutions against the fixed blind results and their own questions/images. Its recorded `solutionReviews` require `agreesWithBlindSolution`, `allStepsValid` and `complete`, with empty `missingEvidence` and `issues`. Correct final answers cannot waive this check. The root pilot's concrete failure, `$2\times3-6=0$ (거짓)` followed by an invalid choice elimination, is represented by an MC regression fixture and explicitly addressed in the reviewer instructions. This fixture verifies the gate rejects a failed step review even when all independent final answers match; it is not an evaluation of the real reasoning model's detection rate.

Only after both reasoning phases pass does TypeSafe receive six separate Noul questions: same learning goal, comparable curriculum/method level and problem completeness for each candidate. Its text state uses the independent solver's explanation, including any figure interpretation; Jev receives no images or author solution. Strict Noul results contain `type: "noul"` and a finite `noul` in `[0,1]`; missing/extra answers, another primitive, NaN or out-of-range values fail. Default minimum probabilities are 0.95 for goal, 0.90 for level and 0.95 for completeness, recorded in the evidence and configurable through typed options. These are conservative policy settings, not calibrated performance claims. Noul has no separate confidence field, and none of these judgments proves mathematical correctness.

Answer equality removes whole math-span wrappers and a small set of presentation commands, and compares exact rational scalar values, labeled scalar assignments and labeled tuples. It preserves variable identities, all requested values/roots, ordering in unlabeled tuples and units. It does not simplify arbitrary algebra, extract a matching number from prose, perform approximate floating-point comparison, or assume a scalar belongs to a variable. Undefined numeric forms are rejected. MC comparison requires explicitly sequential choices, accepts circled labels or supported numeric index labels and can match unique explicit choice content; missing choices, multiple labels, out-of-range labels and ambiguous matching content fail. Unsupported equivalent formats may remain pending for another review rather than be normalized broadly.

The evidence kind is `machine-blind-reasoning-review`, distinct from deterministic calculation evidence. It records separate solver/solution-reviewer/semantic models and per-call requested/returned model, latency, status and token counts when available. Network, cancellation and malformed-response failures fail closed; arbitrary SDK exception strings, provider error bodies, keys, database URLs and image base64 are not copied into review communications. Defaults use `deepseek-v4-pro` for text and `deepseek-flash` when any real picture is present, with a fresh independent request for the worked-solution check. The default transport uses the installed OpenAI SDK and TypeSafe direct HTTP. Paid defaults are blocked under Vitest even if an inherited environment contains keys. Dependency callbacks and response envelopes are typed; callers can inject all three inference phases. Timeouts and caller cancellation also bound injected callbacks that ignore an abort signal.

The immutable binding contract agreed with root/A/C is:

- `sourceDigest`: `textbookVariantSourceDigest(origin.problem)`, including every supplied raw source field.
- `candidatePayloadDigest`: `reviewDigest` of the slot-sorted full candidate DTOs, including provenance, validation, answer and every proposed solution step.
- Figure bundle digests: `reviewDigest` of ordered `{ sha256, choiceIndex, origin, sourceSha256: sourceSha256 ?? null }` objects. The reviewer recomputes `sha256` from the decoded image bytes and checks the supplied digest. Optional `sourceSha256` binds fetched original bytes independently of a rendered PNG; the reviewer checks its format but cannot reconstruct those original SVG bytes from PNG data.
- `sourceFigureDigest` and `candidateFigureDigests`: the verified source and slot-1/slot-2 bundle digests.
- `bindingDigest`: the complete origin including grade/chapter/section, slot-sorted full pair and complete source/candidate figure bundles with recomputed actual image hashes. `dbRetryReviewBinding` exposes every binding field for a fresh comparison at qualification. `candidateFigures` always follows slot-1/slot-2 order.

Inputs are snapshotted before asynchronous calls, callback problem state and returned evidence are deeply frozen, and caller changes during review force `inputs-changed-during-review`. Changing an original, provenance, author step, generator validation, unit label, image bytes, image association, image order or optional source-byte hash invalidates reuse. Root's qualification still needs to reload/re-render the current assets and compare the complete bindings and production-render evidence; a review does not independently demonstrate that arbitrary injected PNG bytes were rendered from a claimed SVG.
