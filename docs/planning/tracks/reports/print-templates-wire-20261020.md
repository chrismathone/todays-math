## 재 본 표의 요점

같은 자체 제작 25문항을 제품 기본 옵션에서 template만 바꾸어 실제 `WorksheetPrint`로 조판했다. 객관식 10·단답 15개이며 그림 5·긴 발문 5개가 섞였다. A4, 1단, 정상 여백, gap 18px, 시스템 글꼴, 남색을 고정했다.

| 평가원 | 정통 | 모던 | 워크북 | 자습 | 유형 |
|---:|---:|---:|---:|---:|---:|
| 5쪽 | 5쪽 | 6쪽 | 8쪽 | 8쪽 | 5쪽 |

- 여섯 모두 번호 모양·선택지 배치 규칙·글꼴 팩·옵션 색이 같다. 일반 시험의 2쪽 이후 머리도 공통으로 없다. 첫 머리 구조와 높이, 문항 틀·풀이 공간·푸터는 실제로 다르다.
- 평가원·정통·모던·유형은 같은 문항끼리 text-y 값이 **25/25개 모두 같다**. 워크북과 자습도 서로 25/25개가 같으며, 풀이 공간이 본문 폭을 좁혀 앞 네 종과는 일부 발문의 줄이 달라진다. text-y는 수식의 위아래 조각을 포함한 텍스트 fragment 높이 값으로 산문 줄 수와 다르다.
- 평가원/정통의 전체 지면 픽셀 차이는 첫 쪽 **5.5485%**, 마지막 쪽 **1.6789%**다. 두 지면의 비흰 픽셀 합집합을 분모로 하면 **56.6914% / 78.9871%**이므로 이 수치를 ‘98.3% 동일’ 같은 지각적 유사성으로 해석하지 않는다.
- 여섯 모두 실제 한글 텍스트 잎에서 로컬 **Batang** 사용을 CDP로 확인했다. 서버 PDF나 다른 기기의 글꼴 증거는 아니다.

따라서 ‘모두 같은 지면’은 아니다. 다만 같은 번호·글꼴·보기와 비슷한 본문 흐름이 반복되는 근거가 있다. 제안에서는 머리 장식뿐 아니라 **문항 구조와 학생이 쓰는 공간**을 함께 가른다.

## Wire 안마다 한 줄

| 안 | 한 줄 | 무엇으로 가르는가 |
|---|---|---|
| A · 여섯 원형을 분명하게 | 이름 여섯을 유지하고 각 양식의 구조를 크게 다르게 한다. | 영역 2단 / 학교 정보표 / 안내 머리 / 오른쪽 풀이 / 개념·모눈 / 유형 반복 |
| B · 시험·과제·자습 세 갈래 | 쓰임을 먼저 고르고 그 안에서 두 세부형을 고른다. | 답 기록 / 서술 줄 / 제출 확인 / 풀이 확인 / 학습 순서 / 두 번 풀기 |
| C · 네 가지로 줄이기 | 겹치는 평가원+정통, 워크북+유형을 합쳐 네 지면만 둔다. | 시험 / 안내 / 풀이 / 개념. 여섯 기존 이름의 대응표는 유지 |
| D · 머리 하나, 종이 배분 여섯 | 머리·색·글꼴을 같게 두고 본문의 밀도와 쓰기 영역을 가른다. | 읽기 2단 / 답 줄 / 전달 여백 / 넓은 풀이 / 개념 높이 / 하단 재풀이 |

각 안의 기존 여섯 이름별 한 줄 정체성은 HTML의 대응표와 `scripts/qa/print-templates/directions.mjs`에 모두 남겼다. C는 대응 여섯을 실제 네 지면으로 합쳐 보여 준다. C 선택 시 저장 프리셋 호환 설계가 추가로 필요하며, 현재 키를 삭제하거나 변경하지 않았다.

**리드 추천: A.** 여섯 템플릿의 차이를 체감하기 어렵다는 문제에 직접 답하며, 메뉴나 저장 프리셋의 이름을 바꾸는 결정 없이 본문 구조까지 구별할 수 있다. 메뉴 단순화가 우선이면 C가 비교 후보이고, 현재 공통 머리를 최대한 지키려면 D가 맞는다.

## 지면 출발점과 검증

- 현재 12면은 실제 출력 DOM·CSS·그림·글꼴 변수를 보존한 첫/마지막 쪽이다. 초기의 빈 PNG와 빈 글꼴 조회는 버리고 수정 캡처를 채택했으며, 12장 모두 어두운 픽셀 존재 검사를 통과했다.
- 제안 22면은 실제 정통 출력의 문항 DOM을 공통 사용하고, 같은 document 래퍼·CSS 상속을 보존했다. 수식·보기·그림 렌더러를 새로 만들지 않았다. 차이는 문항 배치·머리·번호의 시각 표현·쓰기 공간이다.
- 793.70 × 1122.52px, 좌우 15mm·상하 12mm를 제품에서 가져왔다. 본문은 현재 13.5px에서 출발하며 유형 컴팩트는 제품에 있는 12.5px를 사용한다. 제안만 흑백으로 표시해 구조를 비교한다.
- 현재 12면 + 제안 22면 = **34면**에서 A4 크기·문항 존재·실제 표시 상태·가로/세로 넘침을 확인했다. 넘침·브라우저 오류·외부 HTTP 요청 모두 0. 모눈·재풀이 공간이 넘쳤던 경우를 실제 측정으로 줄여 다시 검증했다.
- 네 방향의 캡처를 눈으로 확인했다. HTML은 기본 45% 비교와 실제 크기 보기를 제공하고, 좁은 화면에서는 종이의 비율을 바꾸지 않고 가로로 넘긴다.
- 제안은 첫 2~6문항의 **첫 쪽 Wire**다. 새 구조에서 25문항 전부의 쪽수를 검증한 결과가 아니며, 빈 공간은 풀이 용도다. 제품 페이지네이션과 실물 프린터는 선택 후 Hi-fi·구현 단계에서 검수한다.

재현: `node scripts/qa/print-templates/build-template-wire.mjs` → 가용 메모리 3GiB 이상에서 `node scripts/qa/print-templates/verify-wires.mjs`. 전체 타입 검사·설치·Prisma·DB·제품 `src/**` 수정·푸시 없이 수행했다. 각 측정의 Vite·Chromium은 종료했다.

앞선 빠른 채점표 Wire B 선택에 따른 Hi-fi 5안은 `ce23d039f`에 완료했으며, [별도 보고](answer-quick-key-hifi-20261020.md)에 30사례·캡처·H2 추천을 남겼다. 정답만 판의 실제 제품 적용 여부는 선택 전이다. 이 브랜치와 하위 측정 작업은 main에 아직 합치지 않았으므로 작업트리는 보존한다.
