# 관리자 사용성 후속 계획 합의

2026-10-04. 실제 Orca CLI의 Claude·Grok 세션이 독립 검토하고 수정안 v02를 재검토했다. 다른 모델을 해당 모델로 표시하거나 Codex의 대리 의견을 사용하지 않았다.

| 검토자 | 1차 검토 | 최종 검토 | 근거 |
|---|---|---|---|
| Claude Fable 5.1 (`claude-fable-5-1`) | 계약 차단 6건, 수정 요구 | APPROVE, 문장 정정 3건은 재검토 불필요 | [Claude 보고서](admin-usability-claude-review-20261004.md), `006b14d4e` |
| Grok 4.7 (xhigh) | 계약 이의 9건, 수정 요구 | APPROVE, 9건 해소 | [Grok 보고서](admin-usability-grok-review-20261004.md), `625336372` |
| Codex | 두 검토와 실제 소스를 대조 | 수정 계약 및 마지막 정정 채택 | [실행 계획](../../admin-usability-remediation-20261004.md), `6136b4afc`·`3e70221dc` |

최종 재검토 대상은 계획 `6136b4afc`다. Claude가 요청한 마지막 정정은 `3e70221dc`에서 반영했다: 모든 편집 화면의 이탈을 내부 전환/앱 링크/브라우저 종료로 구분하고 교재에도 beforeunload를 적용한다. 발급 대상 빈 배열은 0명이며 잘못된 본문은 400이다. 연동 활성화에는 원본 enabled 검사를 새 서버 조건으로 추가하고 거부 시험을 둔다.

의견 차이는 다음과 같이 결정했다.

- B02는 입력 원복 후 저장·취소·이동을 막는 작업 함정이므로 P1을 유지한다. 데이터 손실이 확인됐다는 뜻은 아니다. Claude는 최종 재검토에서 이의 없음을 명시했다.
- T01은 기존 구획 JSONB의 선택 키 `teacherAnswer`로 저장한다. 새 DB 칸이나 학생 text 블록을 사용하지 않는다. 값 없는 과거 파일 digest와 발행 불변성은 유지하며, 학생 응답·PDF는 기존 allowlist로 정답을 제외한다. 교사에게 PDF 비인쇄 범위를 표시한다.
- D07은 새 preview 토큰 대신 선택적 `studentIds`를 서버에서 현재 허용 명단과 교집합한다. 미리보기 후 추가된 학생은 발급하지 않는다. 진짜 본문 없는 기존 POST는 유지한다.
- B01은 접근·세션 차단 효과를 유지한다. 활성화 요청 접수와 새 snapshot/lease 적용 후 복구를 별도 단계로 표시한다. 수동 정지는 자동 해제하지 않는다.
- A07 사유는 기존 감사 기록을 관리용 조회에서 연결한다. 외부 events의 errorCode 계약은 바꾸지 않는다. 보관 담당자 지정은 소속·승인·활성·CAS·감사를 검사한다.
- C01은 기본 대상과 보충/학년 확인 필요를 구분하고 두 반에 등록된 같은 학생의 공유 계획과 반 메타데이터를 분리한다.
- D03은 선택 즉시 저장에서 미리보기 후 명시적 적용으로 바꾼다. 저장 범위는 기존 서비스 전체 학생이며 지점이나 개인 범위로 바꾸지 않는다.
- 사용자가 계획 보강과 진행을 위임했다. 기존 컴포넌트와 문구 기준 안에서 배치를 결정하며 학생 인쇄 지면이나 시각 정체성을 새로 만들지 않는다.

세 모델의 계획 합의는 구현 완료 증거가 아니다. 항목별 구현·검증·운영 반영 여부는 별도 [통합 보고서](admin-usability-integration-20261004.md)에 기록한다.
