계획: [cb-scan-markup-plan-20261126](../../cb-scan-markup-plan-20261126.md) §4 M2. 잉크 글줄 찾기(M2-A)는 codex 트랙 — 따로 보고한다.

## 한 것
- `readScanPageWithName({ lines: true })` — 판 `cb-scan-whole-20261127-v4-lines`, 스키마 `SCAN_READ_LINES_OUTPUT_SCHEMA`.
  - v3 지시문 뒤에 한 문단만 더한다: 칸마다 `lines`(학생이 실제 줄을 바꾼 대로, 위→아래).
  - 글줄은 **`read` 판독이고, 공백 하나로 이으면 판독 글과 같을 때만** 믿는다. 아니면 `null`. 판독 · 판정은 건드리지 않는다.
  - 끄면 v3 요청과 한 글자도 다르지 않다(시험). `jobs.ts` 에 배선하지 않았다 — 운영 동작은 그대로.
- 시험 `conceptBlankScanReadLines.test.ts` 3개. `conceptBlankScan*` 25파일 159개 통과.

## 측정 — 가상 폰 사진 32장, 1회씩
도구 `scripts/qa/concept-photo-bench/synth-photo/read-lines-bench.mjs`. 제품 경로 그대로(QR → 맞춤 → 편 A4 JPEG, 맞춤이 안 되면 원래 사진 → 읽기). 모델만 구독 CLI(Opus 5.5 high). 사진은 [가상 사진 보고](cb-scan-markup-synth-photo.md)의 32장(빈칸 아닌 칸 105 · 빈칸 35).

| | v3(지금 운영) | v4(글줄) |
|---|---:|---:|
| 빈칸 → blank | 35/35 | 35/35 |
| 글이 있는 칸의 상태 read / uncertain / unreadable | 86 / 18 / 1 | 82 / 22 / 1 |
| read 가운데 글이 참과 같음(NFC · 공백 하나) | 85/86 | 80/82 |
| read 가운데 글줄 수가 참과 같음 | — | **82/82** |
| 여러 줄 칸(12) 글 · 글줄 모두 정확 | — | **12/12** |

- 틀린 read 는 둘 다 띄어쓰기(«옮길수» · «대응 각»)뿐이다.
- uncertain 은 대부분 **두 줄 그어 지운 낱말(«넓이»)을 함께 옮기고 불확실로 표시한 것**과 ○ · × 표시였다. 틀리게 읽느니 불확실로 — 지시문이 바라는 쪽이다. 불확실 판독에는 첨삭을 달지 않으므로(§6.2) 글줄도 내지 않는다.
- v3 와 v4 의 read 86 · 82 차이는 1회씩이라 말하지 않는다(교훈 2026-10-06). 글줄을 함께 물어 판독이 눈에 띄게 나빠지지는 않았다.

## 이 수치가 말하지 않는 것
- 손글씨 **글꼴**이다. 실제 학생 글씨의 오독은 여기서 안 보인다 — 실제 사진에서 다시 잰다.
- 1회 · 한 단원 · 구독 CLI(구조화 출력 없음).
