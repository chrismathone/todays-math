## 발견한 문제와 수정

1. 보류 사실이 부적격 후보의 선택을 필수로 요구해 인용할 수 없었다. 보류 설명과 실제 후보 제안을 분리했다.
2. context 답변에서 관측 사실을 금지해, 힌트·재시도 질문에 일반 정책만 답하는 압력이 있었다. 코드 소유 관측을 정확한 출처와 함께 인용할 수 있게 했다.
3. 후보 제안 불가를 설명 불가와 동일하게 처리하던 프롬프트를 고쳤다. 범위 밖 요청의 거절은 보존한다.
4. 새 관측의 시간 필터를 문자열이 아닌 시각 값으로 비교해, 유효한 offset 표기 경계를 맞췄다. 기존 시범 판정 함수는 변경하지 않았다.
5. 질문 입력칸의 width ResizeObserver 안에서 높이를 즉시 바꾸면 같은 전달 주기에 다시 크기가 바뀌었다. width 변경에 따른 fit만 취소 가능한 다음 frame으로 옮겼고, 값 변경의 즉시 fit·확대/축소·focus를 보존했다.
6. 검수 자료가 후보 계산에는 on을 강제하고 snapshot 문구에는 off를 사용했다. 실제 운영 wrapper와 명시한 같은 시나리오 flag로 자료를 다시 만들었다. 이전 모순 자료와 캡처를 삭제하지 않았다.
7. 마지막 날짜 관련성 사례에서 오늘의 확인 원천 외에 이전 목표 원천까지 인용했다. 원천별 날짜를 모델 입력에서 생략했던 한계를 확인했으며, KST 기준일과 원천별 날짜·완료 여부를 코드가 계산해 제공했다. 미래·미완료·원천 누락을 오늘 완료로 표시하지 않으며, 정확한 시계·실세션 ID는 추가 전송하지 않는다. 기존 실패와 새로운 날짜 질문을 정확한 원천까지 대조해 교정했다.
