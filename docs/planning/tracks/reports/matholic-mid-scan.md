**작성 2026-08-31 · 리드(main 워크트리) · 원장님 지시 「중등도 매스홀릭으로 탐색시작해」**

> **한 줄**: 중1-1~중3-2 **132소단원 전량**(빠짐 0)을 저쪽 API 로 훑었다. **30,607문항.**

> **정답률이 일곱 칸을 따라 단조로 내려간다**(87→81→76→72→65→56→**42**).

## 1. 다시 재는 법 — **화면을 클릭하지 않고 잰다**

원장님 학원 계정(`injaewon0`)이 붙어 있는 브라우저 안에서 저쪽 API 를 다시 부른다.
**읽기(조회) API 만** 부른다 — 출제·저장·결제·학생 관련 API 는 한 번도 안 불렀다.

| 무엇 | 어디 |
|------|------|
| 과정 목록 + **난이도 코드 태그** | `GET payment.matholic.com/chapter/root/academy` |
| 단원 나무(소단원까지) | `GET payment.matholic.com/chapter/{과정}/tree` |
| 소단원의 «유형» 목록 | `POST jellyg.matholic.com/api/opentextbook/repUnits` — `chapterIds=…` |
| **문항 레코드** | `POST …/api/opentextbook/units/v3` — `{encryptIds, maxCount}` ← **maxCount 가 파라미터** |
| **고난도 풀** | `POST …/api/extract/unit/advanced/v2` — `chapterIds=…` |

인증은 `localStorage.access_token` 을 `Authorization: Bearer` 로. **10~15분이면 만료**하므로
쓸기는 401 을 만나면 페이지를 새로고침하고 그 소단원부터 다시 한다(회수 3번 났다).

문항 레코드가 들고 있는 것 중 우리에게 값어치 있는 것:

```
tagLevel      -1 / 11 / 21 / 22 / 31 / 32 / 41     ← 일곱 칸과 1:1
accuracy      **실제 정답률(%)**                    ← 🔴 «본문 밖»에서 온 난이도 근거
level         -1 / 1 / 2 / 3 / 4
subGroupName  유형 이름          answerType  ONE / CHOICE12 / CHOICE12345
aspectRatio   지면 세로/가로 비   filePathMd5 문항 이미지
```

### 🔴 화면의 「출제 문제 N」은 **재고가 아니다**

같은 소단원에서 화면은 `20/28/20/28/28/16`, API 는 `40/66/39/72/58/38` 이었다.
화면 쪽은 **중복출제 방지** 등 학원 이력이 걸린 **학원별** 숫자다. **재고는 API 로 센다.**

### 분모 검산

트리가 센 소단원 **132** = 저장된 파일 **132**. `comm` 으로 대조해 **빠진 것 0**.

## 2. 🔴 물음 ① 의 답 — 저쪽은 중등에도 연다. 그런데 **여섯이 아니라 일곱**이다

### 2.1 화면이 여는 여섯

`학습지 출제 → 문제은행 → 단원별` 에서 유형그룹을 고르면 「출제 문제 난이도」가 연다:

```
개념 · 기본 · 실력(하) · 실력(중) · 심화(하) · 심화(중)
```

**초등과 이름이 같다.** 여섯 보고서가 못 답한 자리 — **연다.**

### 2.2 그런데 과정 태그에는 코드가 **일곱**이다

`chapter/root/academy` 의 각 과정에 「단원 유형분석 난이도」 태그가 붙어 있다.

```
중등 1-1 ~ 3-2 (여섯 과정 전부)   -1, 11, 21, 22, 31, 32, **41**
초등(교과심화 사고력수학)            11, 21, 22, 31, 32, **33**      ← 체계가 다르다
```

`41` 은 단원별 화면에 **없다.** 132소단원 전량을 훑어도 `41` 은 **0건**이었다.
찾아보니 **메뉴가 다르다** — `목적별 → 고난도 (단원별 고난도 문항 출제)`,
`/workbook/new/advanced`, 별도 엔드포인트 `/api/extract/unit/advanced/v2`.

**추론이 아니라 API 가 그렇게 말한다** — 그 응답의 레코드가 전부
`level: 4 · tagLevel: 41` 이고 `rootTagName: "고난도수업"` 태그가 붙어 있다.
그리고 그 문항의 `filePathMd5` 는 **단원별 풀의 31/32 목록에 하나도 없다**(4/4 불일치).
**겹치지 않는 별도 풀이다.**

### 2.3 일곱 칸 — 재고와 **정답률**

| 기본 | 11 | 4,961 | 16.2% | 81% |

🔴 **정답률이 일곱 칸을 따라 한 번도 안 뒤집히고 내려간다.**
이름이 아니라 **측정**이 칸의 차례를 떠받친다 — 우리가 지금까지 한 번도 못 가졌던 종류의 근거다.

⚠️ **소단원 하나만 보면 안 갈린다.** 중1 `2.2.2 일차방정식의 풀이` 한 곳에서는

**표본이 얇으면 이 축은 침묵한다** — 이 저장소가 여러 번 데인 그 자리다.

## 3. tagLevel ↔ 칸 이름 — **읽고 적지 않고 대조했다**

이 대응이 틀리면 위 표가 통째로 허깨비다. 그래서 **본문 밖 증거**로 맞췄다.

```
㉠ 화면에서 「심화(중)」만 켜고 출제하면 16문항이 나오는데 그 16 이 **전부**
   유형 «일차방정식의 풀이 응용» 이었다.
㉡ API 에서 그 유형에만 갇힌 tagLevel 은 **32 하나뿐**이다(다른 여섯 칸은 여러 유형에 걸쳐 있다).
㉢ 고난도 메뉴가 낸 4문항의 md5 가 API 응답에서 전부 tagLevel 41 이었다.
```

`level` 은 굵은 층(−1·1·2·3·4)이고 `tagLevel` 은 그것을 하/중으로 쪼갠 두 자리다
(`21`=실력하, `22`=실력중, `31`=심화하, `32`=심화중).

## 4. 🔴 실물 — 저쪽 위 두 칸이 **무엇을 시키나** (눈으로 봤다)

문항은 옮겨 적지 않는다. **꼴**만 적는다.

### 4.1 `심화(중)`(32) — **마디 하나가 안 굳고, 소단원 개념이 굳힌다**

중1 `일차방정식의 풀이` 여섯을 봤더니 **한 가지 꼴**이었다:

```
문자가 둘~셋인데 값이 안 굳는다
  → **비(比) 또는 조건식**이 그 문자들을 **한 매개변수로 접는다**
  → 접히면 물어본 식의 값이 **하나로 굳는다**
  → 그 값을 다시 «x 에 대한 일차방정식의 해»로 놓고 **상수를 역산**한다 (여섯 중 셋)
```

중3 `이차함수 y=ax²+bx+c의 그래프` 다섯은 굳히는 성질이 다르지만 **구조가 같았다** —
「그래프가 어떤 도형과 만나도록 하는 계수의 **범위**」에서 후보(경계)를 **둘** 만들고,
어느 쪽이 위끝·아래끝인지는 **그래프 개형**(= 그 소단원 개념)이 굳힌다.

🔴 **이것이 D-115 심화중 정의와 글자 그대로 같다** —
「굳지 않는 마디가 **하나** 있고, **그 소단원의 성질**이 그것을 굳힌다」.

### 4.2 `고난도`(41) — **성질로 못 굳혀 다 만들어 견줘야 한다**

중1 `일차방정식` 의 고난도 넷은 위와 **다른 부류**였다:

```
· 조건이 **두 번** 걸려 매개변수로 접은 뒤에도 자연수 조건이 다시 걸러야 한다
· 방정식이 **셋**이고 셋의 해가 같다 — 하나를 풀고 나머지 둘에 넣어 **각각** 역산
· 절댓값 — **구간을 나눠 경우를 전부 만들고** 각 해가 그 구간에 드는지 검사한 뒤 다시 거른다
· 조건 (가)(나) 각각에 대해 **모든 자연수를 훑어 합**을 낸다
```

🔴 **이것이 D-115 심화상 정의다** — 「성질로 **못 굳혀** 실제로 **만들어 견주어야** 하나가
남고, 그 후보를 발문이 주지 않는다」, 그리고 ⑾ 「후보를 **다 계산해 견주어야** 하면 상」.

### 4.3 그래서 대응이 이렇다

```
저쪽 심화(하) 31  →  우리 **심화하**
저쪽 심화(중) 32  →  우리 **심화중**    성질 하나가 후보를 «끝까지 계산하지 않고» 거른다
저쪽 고난도   41  →  우리 **심화상**    후보를 다 만들어 견줘야 한다
```

**D-113 의 여섯 칸이 저쪽 일곱 칸 안에 그대로 앉는다.** 그리고 이 대응은
초등 잣대를 옮긴 것이 아니라 **중등 실물로 확인한 것**이다.

⚠️ 표본은 **중1 일차방정식 6+4 · 중3 이차함수 5** 다. 넓히기 전에는 **가설**이다(§7-1).

## 5. 🔴 그러면 `tier-bench-m{1,2,3}` 셋을 다시 읽어야 한다

세 보고서와 grok 적대 검토가 닿은 결론은
**「D-115 의 되짚기 축이 중등에서 안 선다」**(배수 1.05~1.85배)였다.

그 결론은 **여전히 참이다. 그러나 그것이 재는 것이 무엇인지가 달라진다.**

```
셋이 잰 것 = **우리 중등 풀**에서 그 축이 갈래를 가르는가
이 문서가 잰 것 = 저쪽 **중등 위 칸의 실물**이 그 축의 정의에 맞는가
```

**우리 풀에는 §4 의 꼴이 없다.** `resolveMiddleTier` 는 등록값을 내리기만 하고
등록값에 확대 갈래가 아예 없다(D-113 ⑼). 그러니 「축이 갈래를 안 가른다」는
**「위 칸이 비어 있다」의 다른 표현**일 수 있다 — 두 문장은 같은 말이 아니다.

🔴 그리고 리드(나)가 `adv-mid-tier` 브리프에서 **틀린 것 하나**도 여기 걸린다:
「초등에서 갈린 열거 자를 중등에 대 보라」고 썼는데, 그 자는 **초등에서도**
응용 1.7% = 심화하 1.7% 로 그 칸을 안 가른다. 가르는 칸은 **심화중↔심화상**이고
**중등에는 그 갈래가 0** 이다. 즉 그 자로는 처음부터 못 잰다.
(`probe-elem-tier-enumeration.ts` 머리말에 못 박아 두었다.)

**다음 수는 「축을 찾는 것」이 아니라 「§4 의 꼴을 중등에 세우고 그 축으로 재는 것」이다.**

## 7. 🔴 이 조사가 못 본 것

1. **실물 표본이 얇다.** 심화(중) 11문항(중1 6 · 중3 5) · 고난도 4문항, 두 대단원.
   §4 의 「한 가지 꼴」은 **가설**이다. 학년·대단원을 넓혀 세어야 한다.
   그리고 §4.1 은 **내가 읽고 적은 것**이다 — 「굳히는 성질이 소단원 개념인가」를
   기계로 세는 자는 아직 없다.
2. **정답률이 어느 모집단의 값인지 모른다.** 저쪽 전체 학생인지, 학원 표본인지,
   기간이 언제인지 API 가 안 말해 준다. **칸 사이의 차례**를 보는 데는 쓸 수 있지만
   **절대값**을 우리 예상 점수(11-score-predictor)에 그대로 쓰면 안 된다.
3. **고난도 풀의 «중단원 몫»을 안 셌다.** 학기별 총량(89~226)만 셌다. 어느 중단원이
   두껍고 어느 곳이 비었는지는 안 봤다 — 우리가 심화상을 어디부터 세울지 정할 때 필요하다.
4. **저쪽 초등의 `33` 을 안 봤다.** 초등은 꼭대기 코드가 33 이고 중등은 41 이라
   **체계가 다르다.** 초등 6단 눈금이 지금도 옳은지는 이 문서가 답하지 않는다 —
   `tier-bench-g{3,4,5,6}` 넷이 전부 그 눈금 위에 서 있으므로 **따로 확인해야 한다.**
