# 선수 확인 구현과 최종 검증

기준: 실제 세 모델이 승인한 [plan-v03](./plan-v03.md), [구조·시각 합의](./consensus.md). 구현과 검증을 별도로 기록하며 운영 교육 효과를 주장하지 않는다.

## 구현 범위

- 붙여넣기 문법을 복구한 루트 `math-graph.cjs`는 Node 기본 모듈만 사용한다. 11개 불필요 과목과 그 연결을 제외하고 JSON/Markdown을 생성한다. 단원 100, 학습 요소 356, 단원 선수 186, 도움 2, 포함 356이다. 소단원 직접 선수 간선은 0이며 성취기준 전수 대조 상태는 미완료다.
- 화면과 별도의 불변 교육과정 데이터·조회 모듈을 둔다. 학교급/학년군/과목/영역 검색과 단원별 요소·직접 선수·후속·도움·과목 관계·역추적 복습 후보를 조회한다. 교사의 후보 제외 조작은 화면 안에서만 유지하며 학생 숙달로 저장하지 않는다.
- 자동 배정은 `g5-fractions`의 목표 `5-2-2-1`, `5-2-2-2`와 확인 `5-1-5-4`, `5-1-5-3`뿐이다. 그래프에 있는 모든 소단원이나 중등·고등으로 확대하지 않는다.
- 현재 계획 이후, 최근 14일 안의 가장 최근 완료 목표 두 세션에서 독립 오답이 각각 2개 이상일 때만 확인을 발동한다. 직접 채점된 첫 풀이만 사용하며 힌트/자기채점/포기/재도전/미완료/반복 본문은 제외한다. 4개 독립 정답은 해당 소단원 일부의 최근 통과 근거다. 한 번의 오답이나 소단원 일부로 단원 전체 숙달을 확정하지 않는다.
- 진행 중 풀이/재도전 우선, 5문항 분량 한도, KST 하루 확인 1회, 깊이 1, 확인 후보 최대 2개, 같은 확인 14일 유예를 지킨다. 확인 후 현재 목표 learn으로 복귀한다. 확인 범위의 보류는 통과 판정과 구별하고 교사에게 사유를 표시한다.
- 공급기는 현재/보존 세션/최근 답안의 실제 본문을 제외하고 같은 소단원·갈래 구성의 5문항 세션을 최대 20seed 검사한다. 확인 공급 실패 시 안전한 새 목표 문제를 대체 공급하고, 목표도 공급할 수 없으면 이유와 비활성 시작 단추를 표시한다. 공급 부족을 학습 완료로 표시하지 않는다.
- 학생 기록은 기존 학생별 strict SRS 상태에만 저장한다. 그래프나 다른 학생의 근거와 합치지 않는다. 저장 키·테이블·마이그레이션을 추가하지 않았다. 버전값과 표시 근거는 파생 DTO다. 담당 학생 권한, origin, CAS, 재전송/409 처리와 열린 탐험의 고정 단원·분량을 유지한다.

## 활성화

서버 환경 `MATH_PREREQ_CHECK=on`일 때만 자동 선수 확인과 학생 근거 표시가 활성화된다. 기본은 꺼짐이며 이 작업에서 운영 환경값은 바꾸지 않았다. 100단원 교사 연결도 조회는 사용할 수 있다. 임계값은 잠정 정책으로, 운영 자료로 보정된 진단 정확도나 숙달 확률이 아니다.

## 검증 중 보완

실제 브라우저에서 생성기의 `fraction-parts` 입력이 저장된 선택지를 숨기는 경우를 발견했다. 공급 세션의 기존 `interactive` 필드를 명시적 `null`로 고정해 검증된 네 선택지를 표시한다. 본문·정답·선택지·문항 seed·갈래·채점·20seed/반복 제외는 그대로다. 기존 일반 세션의 조작형 입력도 유지한다. `publicCourseSession`이 다른 입력을 다시 파생하지 않는 회귀 검사와 실제 복귀 화면의 네 단추를 확인한다. Claude의 실제 검토 `msg_3188d84720f1`이 이 처리에 동의했다. 조작형 입력을 가진 세션을 모두 거절하는 접근은 P2 공급을 없애므로 채택하지 않았다.

교사 계획 저장 뒤 선택 시점의 낡은 revision으로 근거가 남는 문제는 독립 검토에서 재현해 수정했다. 학생 변경의 첫 렌더와 늦은 응답도 요청한 학생 ID·revision으로 제한한다. Claude가 `c0ec1e3d3`의 회귀 검사·변이 검사로 확인해 실제 승인했다(`msg_1d352d8547af`).

## 실제 검증 기록

- 그래프/독립 CLI: 50검사 통과. CJS만 빈 폴더에 복사한 실행, `--target M3-R02`, `--mastered M1-N02`, 공백 경로 `--out`, 잘못된 ID의 쓰기 전 거절, 직접 topic 간선 없음, 순환/중복/누락 ID, JSON/Markdown/해시 일치를 포함한다. 생성 콘텐츠 해시 `80f599e064e428f56f63ef06d89ede24d71319521b2c93ff97a3126212f17554`.
- 공급 관문: 원시 2,400문항과 실제 800세션(4,000문항)의 입력·채점·그림·보기 검사를 수행했다. 공급기가 세션 안의 중복 본문을 제외한다. [Claude 원문 기록](./impl-claude-evidence-policy.md)에 갈래별 서로 다른 본문 수를 기록했다. 의미상 유사성이나 문항류 다양성 검증은 아니다.
- 실제 API: Codex의 19개 새 route 검사와 14개 기존 검사가 통과했다. 두 탭 CAS, 동일 요청 ID, old strict parser, 담당 학생 격리, origin/auth, flag off, 하루 5/10/15/20와 미션 10, 공급 오류를 포함한다. [원문](./implementation-codex-integration.md).
- 공급 입력 표시 보완 뒤 관련 공급·정책·통합·회귀·200seed 관문 5파일 58검사가 통과했다. 이후 추가한 public DTO/최종 병합 검증은 별도로 기록한다.
- 격리 실제 브라우저: 실제 handler와 React 플레이어를 메모리 DB/인증 fixture로 연결했다. A는 확인 다섯 답을 저장한 뒤 목표 learn으로 복귀, B는 한 완료 실패뿐이므로 기존 목표 review와 독립 기록을 유지했다. PC/390/320에서 빈 화면·framework overlay·페이지 예외·가로 넘침을 확인했다. 초기 Vite 의존성 로딩 때 첫 탐색이 시간 초과해 재접속했으며, 실제 문제·현황이 로딩된 뒤 smoke 통과로 기록했다. 운영 학생 사용 결과나 전체 Next 배포 시험으로 보고하지 않는다.
