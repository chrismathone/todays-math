## 0. 결론

- 루트의 제약 여섯 가지를 **전부 받는다.** 그대로 받는 것이 넷, 값을 고쳐 받는 것이 둘(①의 복귀 모드 · ③의 미지원 상태)이다.

## 2. 계약 — 복귀와 한정 선택

### 낱말

- `T` = `nextLearning(state)` — `courseAutomation.ts:258-266`. 허용 목록의 목표(`5-2-2-1` · `5-2-2-2`)일 때만 아래가 돈다.
- `S` = `course.learner.session`. **끝남** = `completedAt` 이 있고, 재도전이 없거나 재도전도 끝남 — `courseAutomation.ts:284-286` 의 `active` 의 부정.
- 확인 소단원 = T 의 허용 목록 줄의 `checkSectionIds`(`5-1-5-4`, `5-1-5-3` 순).
- 켜짐 = 환경변수가 `on` 이고 `plan.enabled`.

### 문항 판정 (끝낸 세션의 첫 풀이만)

| 갈래 | 정의 | 근거 |
|---|---|---|
| 스스로 맞음 | `!selfAssessed` · `correct` · `!usedHint` | `courseAutomation.ts:644-655` |
| 서버 채점 오답 | `!selfAssessed` · `!correct` · `!usedHint` · `submittedAnswer !== ""` | 포기는 `""` 로 저장된다 — `:646`. 숫자 문항은 빈 답을 받지 않는다 — `answers.ts:211`, `:633-637` |
| 모름 | 자기채점 · 힌트 · 포기 · 같은 본문이 이 세션 앞이나 보존된 이전 문항에 있음 | — |

세션 판정: 서로 다른 본문의 스스로 맞음 ≥ 4 → `pass` · 서로 다른 본문의 서버 채점 오답 ≥ 2 → `fail` · 그 밖은 `unknown`. 끝내지 않은 세션과 `session.retry` 는 보지 않는다.

덧붙임: 숫자 문항은 답을 내기 전에 힌트를 열 수 없다(`courseAutomation.ts:453-460` — 자기채점 문항만 열린다). 그래서 서버 채점 문항의 첫 풀이는 지금도 `usedHint` 가 거짓이다. 힌트 조건은 겹쳐 둔 안전장치다.

### 사슬의 순서 (ⓐ `courseSummary` — `courseAutomation.ts:299-319`)

```
이어 풀기 → (꺼짐 · 오늘 목표 달성이면 없음) → 복귀 → 확인 → 만기 복습 → 다음 학습
```

ⓑ `expeditionCourseRecommendation` 의 대체 가지(`expedition.ts:574-581`): `복귀 → 확인 → 지금대로(현재 세션의 소단원을 review)`.

### 복귀

- **R1 조건.** 켜짐 · `S` 가 끝남 · `S.sectionId` 가 확인 소단원. 그것뿐이다. 발동 여부도, `S` 가 확인이었는지 보통 복습이었는지도 묻지 않는다.
- **R2 모드.** ⓐ 와 ⓑ 모두 `{T, learn}`. `learnedToday`(`courseAutomation.ts:288-297`)를 보지 않는다. ⓑ 를 `learn` 으로 두는 까닭: `review` 는 맞혀도 `completedSectionIds` 에 못 들어간다(`:761-763`). 보통의 «실패한 새 학습은 내일까지 쉰다»는 그대로다 — 복귀가 아닌 `learn` 가지는 고치지 않는다.
- **R3 한 번.** 복귀 세션이 시작되면 `S` 가 T 가 된다(`:398-412`). 조건이 꺼진다. P 가 같은 날 다시 `S` 가 되는 길은 없다 — 확인은 하루 하나(C2), P 의 만기는 푼 뒤 최소 하루 뒤(`:727-730`), ⓑ 의 «같은 소단원 한 번 더»는 복귀가 먼저 가져간다.
- **R4 옛 목표 없음.** T 는 매번 지금 상태에서 다시 구한다. 교사가 시작 소단원을 바꾸면(`:252-254`) · 꺼지면 · T 가 목표 목록 밖이면 복귀는 `null` 이고 지금의 계획대로 간다. `review` 는 `selectedSectionId` 를 안 바꾸므로(`:748`, `math-srs/elementary/progress.ts:453-456`) 확인 중에 T 가 움직이지도 않는다.
- **R5 예산.** ⓐ 에서는 «오늘 목표 달성» 뒤에 있다(`:305`). ⓑ 에서는 `mission.answered >= mission.goal` 뒤에 있다(`expedition.ts:571`). 문항을 더하지 않는다.
- **R6 이력 절단.** `S` 는 `history` 가 아니라 `learner.session` 이다. 새 세션이 시작될 때까지 남는다. 30세션 절단(`:406-411`)이 대기 중인 복귀를 끊지 못한다.

보통의 만기 복습으로 P 를 푼 뒤에도 복귀가 한 번 선다. 보수적이고 해가 없다(다른 만기 복습보다 목표 학습이 한 번 앞설 뿐). 그래서 복귀 문장은 «확인을 마쳤다»고 말하지 않는다(§4).

### 확인

- **C1 발동.** T 의 끝낸 `learn` 세션(보존된 것) 가운데 가장 최근 둘이 모두 `fail` 이고 둘 다 14일 안. 하나만 `fail` 이거나 최근 것이 `unknown` 이면 없다.
- **C2 하루 한도.** 확인 소단원 중 `memories[P].lastReviewedAt` 의 KST 날짜가 오늘인 것이 있으면 없다. 진행 중인 확인 세션은 «이어 풀기»가 사슬 맨 앞에서 가져간다(ⓐ `:299-304`, ⓑ `expedition.ts:570`) — 풀이 0개인 세션은 `memories` 에 없지만 그래서 한도를 새지 않는다.
- **C3 유예.** `memories[P]` 가 없거나 `lastReviewedAt` 이 14일보다 오래됐을 때만 후보. 유예는 발급 제한이고 숙달이 아니다.
- **C4 선택.** `checkSectionIds` 를 적힌 순서로. C3 를 넘고 G1 로 만들 수 있는 첫 P. 깊이 1. 모드는 `{P, review}`.

## 3. 계약 — 문항 생성

- **G1 확인 세션은 엄격하게 만든다.** 씨앗은 상태에서만 나온다: `stableSeed("prereq-check:" + P + ":" + <발동의 가장 최근 실패 세션 id>)`. 자리(연산 1 · 기본 2 · 응용 2)마다 씨앗을 0 ~ 19번 바꿔, `mode === "number"` 이고 본문이 보존된 이력 · 이 세션의 앞 자리와 겹치지 않는 첫 문항을 고른다. 한 자리라도 못 채우면 `null`. 은행 후보는 쓰지 않는다.
- **G2 까닭 — 씨앗이 무작위면 안 된다.** 가드는 «시작된 세션의 소단원 · 모드 = 추천»을 요구한다(`expedition.ts:661-676`). 시작하다 바닥난 것을 알면 다른 소단원으로 돌릴 수 없고(409), 아무것도 안 하면 학생이 선다. 그래서 «만들 수 있는가»를 **추천 함수 안에서** 같은 씨앗으로 먼저 답해야 한다. 세션 id 는 학생마다 다른 UUID 라 학생끼리 같은 문항이 나오지 않는다.
- **G3 미지원.** C1 ~ C3 를 넘는 P 가 있는데 G1 이 전부 `null` 이면 확인을 내지 않는다. 사슬은 만기 복습 → 다음 학습으로 **지금대로** 간다. 그때 `{T, learn}` 의 이유 문장만 미지원 문장으로 바꾼다(§4). 빈 시작도, 다른 소단원 대체도, 반복 문항도 없다.
- **G4 목표 세션.** 목표 소단원의 세션에만 «보존된 이력의 본문 피하기 · 씨앗 20번»을 건다. 바닥나면 **지금 규칙의 문항**이 나온다 — 목표 학습은 멈출 수 없다. 그 문항은 «모름»이고(§2 표), 이유 문장은 새 문제라고 말하지 않는다. 허용 목록 밖 소단원의 생성 결과는 지금과 글자까지 같다.

바꿀 곳: `math-srs/elementary/generator.ts:21-81`(엄격 모드와 피할 본문) · `courseAutomation.ts:386-392`.

| 때 | 문장 | 붙는 추천 |
|---|---|---|
| 확인 | 분수의 곱셈에 쓰이는 분수의 뺄셈을 먼저 확인해요. | `{P, review}` |
| 복귀 | 분수의 뺄셈 다음에 분수의 곱셈을 이어서 학습해요. | `{T, learn}` |

`courseSummarySchema.recommendation` 은 이미 `{ sectionId, mode, reason }` 이다(`mathSrsCourse.contract.ts:50-56`). 새 칸이 없다.

## 5. 정정 — 미션 흐름의 학생은 이유 문장을 보지 못한다

1차 조정안 §3.1 에서 «이유를 학생 · 교사에게 보임 — 됨»이라 적었다. 학생 쪽은 틀렸다.

- 실제 길(`/learn`)은 `ExplorerBankActivity` 가 `StudentCourseSrs` 를 `expedition` 과 함께 올린다 — `ExplorerBankActivity.tsx:14-17, 55-56`.
- 그 모드는 추천이 있으면 **바로 시작한다** — 불러올 때 `StudentCourseSrs.tsx:91-110`, 세션이 끝난 뒤 `:253-264`. 이유 문장이 있는 카드(`:337-364`)는 그려지지 않는다.
- 학생이 보는 것은 풀이 화면의 머리다: «초5 · 1학기 · 분수의 덧셈과 뺄셈», 소단원 이름, «기억을 꺼내는 복습» — `StudentCoursePractice.tsx:90-100, 128`. 세션 사이 화면은 «길을 따라 다음 5문제로 이어가요.» — `:858`.
- 이유 문장이 닿는 곳은 교사 화면(`CourseDashboard.tsx:845`)과 미션 밖의 학습 홈 카드, 그리고 응답 DTO 다.

계획 §1 의 완료 흐름 3(«이유와 함께 제시»)을 학생 화면에서 지키려면 풀이 화면에 한 줄이 새로 들어가야 한다. 그것은 화면 변경이다.

## 6. 새 저장이 필요 없다는 근거

| 판단 | 읽는 것 | 잘리는가 |
|---|---|---|
| T | `learner.selectedSectionId` · `completedSectionIds` | 아니다 |
| 발동(C1) | `history` + `learner.session` | 잘린다 → 발동이 꺼져 지금 흐름. 기다리는 것이 없다 |
| 하루 한도 · 유예(C2 · C3) | `memories` | 아니다(`:817` — 소단원마다 한 칸) |
| 복귀(R1) | `learner.session` | 아니다 |
| 확인 씨앗(G1) | 발동 세션의 id | 발동과 같이 잘린다 → 확인 자체가 없다 |
| 피할 본문(G1 · G4) | `history` · `recentAttempts` | 잘린다 → 그 범위 밖은 주장하지 않는다 |

저장 없이 못 하는 것은 둘이고 둘 다 요구가 아니다: «P 세션이 확인이었나 보통 복습이었나»의 구별(R1 이 묻지 않는다), 그리고 30세션 밖 본문의 반복 방지(주장하지 않는다).

## 7. 하루 문항 수별 추적 (미션 목표는 10 고정 — `expedition.ts:137`)

| `dailyQuestionCount` | 세션을 정하는 자리 | 확인과 복귀 |
|---|---|---|
| 5 | 첫째 ⓐ · 둘째 ⓑ | 발동한 날 둘째(ⓑ)가 확인 → 다음 날 첫째(ⓐ)가 복귀 `learn`. 유예가 풀린 날이면 첫째(ⓐ) 확인 → 둘째(ⓑ) 복귀 `learn` |
| 10 | 둘 다 ⓐ | 실패한 `learn` 다음 세션이 확인 → 그다음 세션이 복귀. 날을 넘기면 다음 날 첫째 |
| 15 · 20 | 미션 안은 10 과 같다. 미션 뒤의 세션도 ⓐ | 같은 날 셋째 세션이 복귀일 수 있다 — 이때만 `learnedToday` 를 넘는다(R2) |

두 자리의 규칙이 같으므로 결과가 문항 수에 따라 갈리지 않는다.

멈추지 않는다는 점검:

- 확인 둘이 모두 유예 중이고 T 가 또 실패 → 확인 없음 · 복귀 없음(`S` 가 T) → 만기 복습 → 다음 날 `learn T`. 지금 흐름이다. 14일 뒤 유예가 풀리면 확인이 다시 하나.
- 확인을 못 만듦(G3) → 지금 흐름 + 문장.
- 하루 한도에 걸림 → 지금 흐름.

알려 둘 기존 동작(이 기능이 만들지 않고 고치지 않는다): 문항 수 5 에서는 ⓐ 가 하루 한 세션만 정하고 만기 복습이 `learn` 보다 앞이다. T 자신의 복습이 매일 만기면 `learn T` 의 둘째 시도가 며칠 밀린다. 발동이 그만큼 늦어진다.

| B4 | 경로의 `now` 와 저장기의 `new Date()`(`serverStore.ts:91`)가 자정 · 14일 경계에서 갈리면 409 | 쓰기 전에 던지므로 저장은 그대로다. 다시 읽고 시작하면 된다는 시험 |
| B5 | 브라우저 검증의 경계 | 로컬 DB 가 없고 공유 DB 가 운영이다. 저장 포트(`serverStore.ts:22-38`)를 대역으로 둔 실제 핸들러 + 기존 플레이어로 본다면 «DB 는 대역»이라고 적는다. 실제 DB 를 거친 것처럼 쓰지 않는다 |

B1 은 계획 문구로, B2 · B3 은 구현의 첫 시험으로 풀린다.

## 9. 교사용 그래프 패널 (조정자 추가 요청)

`CourseDashboard` 안의 펼침 패널 · 100개 단원 조회 · 고른 학생의 부분 근거 — 받는다. 시안 4 + Hi-fi 4 를 먼저 만들고 세 모델이 고른 뒤 화면 코드를 쓴다는 순서도 받는다. 지킬 것 넷:

1. 학생 근거는 §2 의 순수 함수에서만 나온다. 개수와 문장으로 싣고 점수 · 확률은 없다. `E56-N03` · `E56-N04` 는 `partial` 이고 `demonstrated` 가 될 수 없다.
2. 공급 상태(`available / unavailable`)를 단원마다 보인다. `M3-R02` · 고등 · 초1 ~ 2 는 `unavailable`.
3. 새 끝점은 `teacherGate`(`courseTeacherRoutes.ts:32-49`) · 학생 소유 검사 · `withErrorLog` 를 지난다.
4. 고른 시안을 사용자에게 가는 최종 보고에 싣는다 — 뒤집기 쉬운 때에 보이도록.

## 10. 시험 (계약마다 하나)

1. R2: 문항 수 5 에서 확인 다음 세션이 `{T, learn}` 이고, 다섯을 스스로 맞히면 T 가 `completedSectionIds` 에 들어간다.
2. R2: 같은 날 `learn T` 실패 → 확인 → 복귀 `learn T` 가 한 번 나온다(문항 수 20 · 미션 없음). 그 뒤 같은 날 `learn T` 는 없다.
3. R3: 복귀 뒤 같은 날 P 가 다시 나오지 않는다.
4. R4: 확인 뒤 교사가 시작 소단원을 허용 목록 밖으로 옮기면 복귀가 없고 추천이 지금 사슬과 같다. 꺼도 같다.
5. R6: P 세션 뒤 `history` 를 30개로 채워도 복귀가 선다.
6. C1: 오답 1개짜리 실패 · 포기 5개 · 힌트 · 자기채점으로는 발동하지 않는다.
7. C2: 풀이 0개인 확인 세션이 열려 있으면 추천은 «이어 풀기»다. 끝낸 날에는 둘째 확인이 없다.
8. G1 ~ G3: 씨앗 20개가 모두 겹치는 대역에서 추천이 확인이 아니고 `{T, learn}` + 미지원 문장이다. 시작이 세션을 만든다(빈 시작 없음). 가드를 통과한다.
9. B4: 경로 `now` 는 23:59, 저장기 `now` 는 00:00 → 409 · 저장 불변 → 다시 시작하면 성공.
10. B3: 발동하지 않은 학생 100명의 명단에서 생성기 호출이 0 이다.
11. 꺼져 있으면 ⓐ · ⓑ · 생성기의 출력이 지금과 같다. 켜져 있어도 허용 목록 밖 소단원의 세션은 지금과 같다.
