## P0: Observation identity and correction semantics are unresolved

Resolution: v1 live write ingestion is limited to authenticated server-graded course attempts and new prerequisite-session attempts. Middle mission attempts are read adapters where explicitly mapped; no use of conceptWeights. Exam observations are derived from canonical current DB rows at read time, not an additive callback ledger. Canonical exam key is studentId:testId:problemId; latest result for studentId:testId wins by takenAt descending, createdAt descending, id descending. Treat repeat submissions for the same test as revisions, not independent new tests. Latest absent result contributes no observations and replaces previous contributions. Changed answers replace prior facts; recompute the bounded assessment rather than subtracting approximate scores. Answer-mode unanswered rows contribute no direct correctness evidence. Marks-mode rows are teacher judgments, identified by gradingMode, not fabricated student attempts.
Take at most the latest 30 test IDs per student within 30 days and recompute from source. Do not cache exam conclusions without a canonical-source fingerprint; merging fresh exam facts with retained practice facts is deterministic. This avoids a cross-table transaction requirement. True retakes require a different test ID in v1.
Tests: submitting an unchanged grade sheet twice adds zero evidence; wrong-to-correct and present-to-absent revisions replace prior facts; equal timestamp tie-break is deterministic; cross-student same test IDs never collide; omitted response is not an observed incorrect attempt.

## P1: Whole-unit mastery must not arise from partial form coverage
Evidence: math-graph.cjs:44-46 and 61-62 define broad units; topics are positional editorial IDs. E56-N01 includes divisors, multiples, common divisors/multiples, GCD and LCM; one GCD section is a fraction of that scope. memory.ts uses weighted concept evidence; courseAutomation.ts:688 has existing heuristic mastery independent of the new diagnosis.
Resolution: each fact has exact directly assessed scope, provenance, grade status, assistance and attempt role. A problem mapped only to a unit records a unit observation but cannot establish all its topics. For v1 policy-1, unaided first-pass server-graded outcomes are diagnostic; self-assessment, hinted or revealed-answer work, immediate retries, unknown assistance and teacher marks remain displayed facts and may prompt needs_check, never establish demonstrated. Explicit give-up after presentation is difficulty evidence but not independent incorrect-answer evidence; skipped/not presented/absent contributes none. Essay partial score is displayed as partial, never thresholded by the legacy 60% into mastery.
Use a 30-day window and at most the most recent five independent facts per authored assessment bucket. No facts=unassessed; one failure=needs_check; at least two first-pass failures on different content fingerprints within the window=needs_practice. Assisted/teacher-only evidence gives needs_check without asserting weakness. A bucket is demonstrated only with at least three unaided successes, at least two distinct authored families across at least two sessions, and no failure among its latest three eligible outcomes. Same-family number variants may trigger a limited check but cannot satisfy family coverage.
Unit demonstrated requires a reviewed complete bucket inventory covering every declared topic and each required bucket demonstrated. Incomplete mapping/supply keeps coverage=partial and unit demonstrated impossible. Unit needs_practice may report a specific direct weak bucket without marking other buckets weak. Stale facts become unassessed unless newer facts support another state; never preserve mastery by ancestry. All numbers are initial deterministic policy, not calibrated probabilities.
Tests: GCD-only success never demonstrates E56-N01; same family 20 seeds does not satisfy coverage; slow correct independent answer remains success; hinted/retry/self-check successes excluded; stale facts; one wrong no automatic remediation; downstream correct/wrong leaves ancestor and sibling assessments unchanged.

## P1: Bounded scheduling and return need a real state machine
Resolution: phases target -> prerequisite_check -> remediation -> target_recheck -> completed or stopped. Target requires two distinct first-pass failures before offering an opt-in loop. Lock original target unit, section and supported form set at loop creation. Traverse prerequisite edges only at depth=1, at most two direct candidate units, sorted by missing direct evidence then graph ID. Select an authored check scope for each candidate; this is a question coverage choice, not a topic prerequisite edge. Skip a candidate only when that relevant bucket has fresh demonstrated evidence, never because its broad unit has an unrelated high score.
Budget: maximum two check questions, two remediation questions, then exactly one reserved fresh target return question; maximum five loop questions, four non-target questions per KST day, one loop per target per 24 hours. Charge once at issuance. No recursive descent or nested loop. Correct unaided check skips remediation; wrong or assisted check selects at most two supported remedial items and shows existing solution after grading. Whether remediation succeeds or fails, return to target with an honest reason; failure then stops and recommends teacher help, never starts another loop. If all candidates unavailable, show reason and directly offer ordinary target practice. Reserve target supply before diverting; lack of target return supply blocks diversion. Cancel/pause preserves original target and consumes no unissued budget; changing target terminates prior loop with a reason.
Exact content fingerprint cannot repeat within the loop or latest 20 issued problems. Cap the same family at two appearances per loop; an exhausted supplier after 20 deterministic candidate seeds returns unavailable, never relaxes constraints. Sufficient success for passing the narrow check does not imply whole-unit mastery.
Tests: pass/failed checks, persistent failure, both candidates unavailable, target reserve unavailable, 23:59/00:00 KST boundary and rolling cooldown, refresh/two tabs, cancellation, daily budget exhaustion, hint-after-grade, family exhaustion, support edge ignored, returning to identical original target.
