## 2. 내 1차 검토에서 틀린 것

### C1. 확인 소단원 `5-1-4-2`(약분)는 자기채점으로 떨어진다 — **차단 사항**

`getCourseProblemInput` 은 발문이 `needsComparison` 에 걸리면 `self-check` 를 준다 — `math-srs/elementary/answers.ts:168-185`. 그 정규식에 `약분(?:하|해)` 와 `(기약분수|…)\s*(로|꼴로)\s*(나타내|나타냈|…)` 가 있다. `self-check` 의 정답 여부는 학생이 보낸 `selfCorrect` 다 — `courseAutomation.ts:648-651`.

`5-1-4-2` 의 생성기(`src/lib/elementary/g5.ts`):

| 갈래(세션 자리) | 발문 | 판정 |
|---|---|---|
| 연산 ×1 — `sim142Calc` :5721 | «…을 t로 **약분하**시오.» | 자기채점 (항상) |
| 기본 ×2 — `sim142Read` :5737 | «…**약분할** 수 있는 수 중에서 가장 큰 수» | 서버 채점 |
| 기본 ×2 — `sim142Read` :5749 | «…을 **약분하**여 만들 수 있는 분수는 모두 몇 개» | 자기채점 |
| 응용 ×2 — `sim142Apply` :5765 | «…을 **기약분수로 나타냈**을 때, 분모와 분자의 합» | 자기채점 |
| 응용 ×2 — `sim142Apply` :5772 | «…**약분하**면 …이 되는 분수» | 자기채점 |

다섯 문항 중 서버가 채점하는 것은 많아야 2개다. 이 세션으로는 «스스로 맞음 4개»가 성립할 수 없다. 학생이 «맞았어요»를 누른 것이 근거가 된다 — 계획의 «학생이 보낸 correct 는 신뢰하지 않는다»와 어긋난다.

돌려 본 것이 아니라 발문 문자열과 정규식을 대조한 결과다. 정규식의 `하`·`해`·`할` 은 서로 다른 글자라 «약분할»은 걸리지 않고 «약분하시오 · 약분하여 · 약분하면»은 걸린다.

### C2. «소단원 완료» 판정을 근거 판정으로 다시 쓰면 안 된다

1차 P1-2 에서 `courseAutomation.ts:761-772` 를 그대로 쓰자고 했다. 그 판정은 자동 채점 문항이 0개여도 참이 된다(`0 >= ceil(0 × 0.8)`). 자기채점 문항만 있는 세션은 학생이 전부 «맞음»을 누르면 통과한다. 진도를 넘기는 규칙으로는 의도된 것이고(그 줄 위 주석), 직접 근거로는 쓸 수 없다. 근거 판정은 따로 둔다(§4.3).

### C3. 하루 문항 수가 5 이면 둘째 세션은 사슬을 지나지 않는다

`courseSummary` 는 `plan.dailyQuestionCount`(5 · 10 · 15 · 20)를 채우면 추천이 `null` 이다 — `courseAutomation.ts:305-306`. 초등 미션의 목표는 10 고정이다 — `expedition.ts:137`. 그래서 5 로 둔 학생의 둘째 세션은 `expeditionCourseRecommendation` 의 **대체 가지**가 정한다: «지금 세션과 같은 소단원을 복습 모드로» — `expedition.ts:574-581`.

결과: `courseSummary` 한 곳에만 끼우면, 5 로 둔 학생은 확인 세션 뒤에 **같은 확인 소단원을 한 번 더** 받는다. «하루 확인 1개»와 «확인 뒤 바로 목표»가 깨진다. 끼우는 자리는 둘이어야 한다(§4.4).

### C4. D6 의 뜻을 좁힌다

«최근 14일 안에 푼 기록이 있으면 건너뜀»은 **발급 제한**이다. 숙달의 근거가 아니다. 근거(가장 최근 확인의 결과 · 최근의 스스로 맞음)는 다른 함수가 따로 낸다(§4.3). 조정자의 지적이 맞다.

## 4. 공통 최소안 — 값

### 4.1 정적 데이터

- 그래프: 100개 단원 · 간선 · 학습 요소. 조회 전용. 제외 11과목 유지. 소단원 간선 0.
- 판 넷: `schemaVersion: "1.1.0"`(문자열) · `graphVersion` · `PREREQ_MAPPING_VERSION = 1` · `PREREQ_POLICY_VERSION = 1`. 학생 기록에는 저장하지 않는다.
- 공급 상태: 허용 목록에 줄이 있는 목표 단원만 `available`. `M3-R02` · `H-*` · `E12-*` 를 포함한 나머지는 `unavailable` 이고 시험이 고정한다.

### 4.2 허용 목록 (v1 — 한 줄)

```
{ from: "E56-N03", to: "E56-N04",
  targetSectionIds: ["5-2-2-1", "5-2-2-2"],
  checkSectionIds:  ["5-1-5-4", "5-1-5-3"] }
```

근거(전부 `src/lib/elementary/g5.ts`):

- 목표 `5-2-2-1` · `5-2-2-2` 의 응용 갈래는 곱한 뒤 **분수를 뺀다** — `fm221Apply` :8348-8364(`subFrac`), `fm222Apply` :8421-8436(`k − 분수`). 세션 다섯 문항 중 둘이 응용이다. 여기서 틀리는 학생이 곱셈을 못 하는지 뺄셈을 못 하는지를 확인이 가른다.
- 확인 `5-1-5-4` 대분수의 뺄셈 — `sub154Calc` :7120, `sub154Read` :7139, `sub154Apply` :7162(자연수 − 대분수: `fm222Apply` 와 같은 꼴). `5-1-5-3` 진분수의 뺄셈 — `sub153Calc` :6947, `sub153Read` :6960, `sub153Apply` :6974.
- 다섯 생성기의 발문은 «계산하시오 · 몇 L 입니까 · 전체의 얼마입니까»다. `needsComparison` 에 걸리는 말이 없다. 답은 분수 하나이고 `number()` 가 대분수 TeX 까지 읽는다(`answers.ts:133-149`). 그림이 없다(`make` 의 다섯째 인자 없음).
- 넷 다 탐험 단원 `g5-fractions`(`curriculumBridge.ts:23`)이고 연산 · 기본 · 응용이 등록돼 있다(`g5.ts:16770-16785, 16827-16839`).
- `5-2-2-3`(세 분수의 곱)과 `5-2-2-4`(대분수 → 가분수)는 뺄셈을 쓰지 않는다. v1 목표에서 뺀다.

원장님이 고르실 것 하나: 확인의 차례(대분수의 뺄셈 먼저인가 진분수의 뺄셈 먼저인가). 위 값은 내 제안이다.

### 4.3 근거 판정 — 발급 · 결과 · 최근 성공을 가른다

끝낸 세션 하나의 첫 풀이 다섯에서:

- `auto` = 자기채점이 아닌 문항 · `ind` = `auto` 중 정답이고 힌트 없음 · `wrong` = `auto` 중 오답(«모르겠어요» 포함)
- `passed` = `ind ≥ 4` · `failed` = `wrong ≥ 2` · 나머지는 `inconclusive`
- 재도전 답안(`session.retry`)과 끝내지 않은 세션은 보지 않는다.
- 보존된 이력에 같은 `content` 가 이미 있는 문항은 `ind` 에서 뺀다.

| 이름 | 정의 | 쓰는 곳 |
|---|---|---|
| 발급 제한 `cooldown(P)` | `memories[P].lastReviewedAt` 이 14일 안 | 확인을 낼지 말지 — **이것만** |
| 가장 최근 결과 `latestOutcome(P)` | 보존된 이력에서 P 의 마지막 끝낸 세션의 `passed / failed / inconclusive`. 없으면 `unknown` | 이유 문장 · 교사 표시 |
| 최근 스스로 맞음 `freshUnaided(P)` | `latestOutcome = passed` 이고 14일 안 | 소단원 상태 `passed_recent`. 단원 숙달로 올리지 않는다 |

발급이 `memories` 만 보므로 이력이 잘려도 확인이 되풀이되거나 멈추지 않는다. 결과가 잘리면 `unknown` 으로 **말할 뿐**이다.

### 4.4 한 함수, 끼우는 자리 둘

```
prerequisiteStep(course, now, enabled) →
  { kind: "check",  sectionId: P, targetSectionId: T } |
  { kind: "return", sectionId: T } | null
```

`T` = 다음 학습 소단원(`nextLearning` — `courseAutomation.ts:258-266`). 아래가 모두 참일 때만 값을 낸다: 켜짐 · `plan.enabled` · T 가 허용 목록의 목표.

- `check`: ① T 의 `learn` 세션 가운데 **가장 최근 둘**이 모두 `failed` 이고 둘 다 14일 안 ② 오늘(KST) 푼 확인 소단원이 없다 ③ `checkSectionIds` 를 적힌 순서로 보아 `cooldown` 이 아닌 첫 P.
- `return`: 현재 세션이 끝났고(재도전 포함) 그 소단원이 T 의 확인 소단원이다.

| 자리 | 지금 | 바꿈 |
|---|---|---|
| ⓐ `courseSummary` — `courseAutomation.ts:299-319` | 이어 풀기 → (꺼짐 · 목표 달성) → 만기 복습 → 다음 학습 | 만기 복습 **앞**에: `check` → `{P, review}` · `return` 이고 오늘 T 를 `learn` 하지 않았으면 → `{T, learn}` |
| ⓑ `expeditionCourseRecommendation` 의 대체 가지 — `expedition.ts:574-581` | 지금 세션의 소단원을 `review` 로 | `check` → `{P, review}` · `return` → `{T, review}` · 없으면 지금대로 |

가드(`expedition.ts:661`)와 두 경로(`courseRoutes.ts:82-97`, `expeditionStart.ts:10-19`)는 이 두 함수를 부르므로 고치지 않아도 일치한다. 가드 코드 · 스키마 · 계약 · 학생 컴포넌트는 바뀌지 않는다. ⓑ 의 모드는 지금처럼 늘 `review` 다 — 대체 가지가 진도를 올리지 않는 성질을 지킨다.

### 4.5 한정

깊이 1 · 하루 확인 세션 1개 · 목표 단원당 확인 소단원 2개 · 같은 소단원 재확인은 14일 뒤 · `support` 간선과 `reviewCandidates` 는 쓰지 않는다. 확인 둘이 모두 유예 중이고 T 가 여전히 실패하면 자동 확인은 없고, 교사 화면의 이유 문장이 «선생님 확인»을 말한다.

멈추지 않는다는 근거: 어느 가지도 «없는 기록을 기다리지» 않는다. 발동 기록이 잘리면 `check` 가 꺼져 지금 흐름이 되고, 확인 세션이 잘려도 `memories` 가 유예를 지키고, `return` 은 현재 세션만 본다.

### 4.6 문항 — 반복과 출처

- 확인 세션에는 은행 후보를 넘기지 않는다(엔진 문항만 — 출처는 저장된 `sectionId · tier · seed`). 바꿀 곳: `courseRoutes.ts:82-97`, `math-explorers/routes.ts:103-108`.
- 켜져 있으면 세션을 만들 때 보존된 이력(세션 30개 + 최근 답안 100개)의 본문을 피한다. 자리마다 씨앗을 20번까지 바꾼다. 바꿀 곳: `courseAutomation.ts:386-392`, `math-srs/elementary/generator.ts:35-65`. 저장되는 `seed` 는 실제로 쓴 씨앗이다.
- 20번 안에 못 찾으면 그 자리는 지금 규칙의 문항을 낸다. 다른 소단원 · 다른 갈래로 메우지 않는다. 그 문항은 §4.3 에 따라 근거에서 빠진다. 세션을 거절하지 않는 까닭: 시작이 아무 일도 안 하면 학생이 선다.
- 문항류가 다르다는 주장은 하지 않는다. 주장하는 것은 «보존된 이력 안에서 본문이 다르다»뿐이다.
- 켜지지 않았으면 생성 결과는 지금과 글자까지 같다.

### 4.7 이유 문장 (허용 목록에 손으로 적는다 — 조사 계산 없음)

- 확인: «분수의 곱셈에 쓰이는 분수의 뺄셈을 먼저 확인해요.»
- 복귀: «확인을 마쳤어요. 분수의 곱셈을 다시 학습해요.»

기존 문장(«복습 날짜가 가장 오래 지난 소단원이에요»)과 같은 말투다. v0.2 에 이 문장을 그대로 싣는다 — 합의된 계획이 곧 문구의 근거다. 복귀 문장에 «새 문제»를 넣지 않은 까닭: §4.6 의 셋째 줄 때문에 항상 참이 아니다.

### 4.8 끄기

`MATH_PREREQ_CHECK=on` 일 때만. 읽는 곳은 `src/lib/math-prerequisite/enabled.ts` 한 줄이고, 순수 함수는 `enabled` 를 인자로 받는다. `courseAutomation` · `expedition` 은 지금 환경변수를 읽지 않는다. `src/components` · `src/app` 이 둘을 직접 불러오는 곳도 없다(직접 import 만 확인했고, 다른 모듈을 거친 경로는 보지 않았다).

### 4.9 27번 문서 §5 안건 5

이번 합의와 원장님의 2026-10-03 지시로 **대체한다**고 v0.2 에 한 줄 적으면 된다. 따로 허락을 받는 단계를 더하지 않는다(1차 P0-2 의 «원장님 확인 한 줄»을 거둔다). 결정 번호는 origin 의 마지막 번호를 확인하고 받는다.

## 7. 시험에 더할 것 (1차 §8 에 덧붙임)

1. `5-1-4-2` 세션은 `passed` 가 될 수 없다(자기채점 3개 이상) — 허용 목록에 못 들어오는 까닭을 시험이 말한다.
2. 자기채점 다섯 개를 전부 «맞음»으로 눌러도 `passed` 가 아니다. 완료 판정은 지금대로 참이다(두 판정이 갈린 것을 고정).
3. 하루 문항 수 5 · 10 · 15 · 20 각각에서 확인 세션은 하루 하나이고, 확인 다음 세션의 소단원이 목표다.
4. 확인 세션이 이력에서 잘린 상태(세션 31개째)에서 확인이 다시 나오지 않는다. 발동 세션이 잘린 상태에서 추천이 지금 흐름과 같다.
5. 이력의 본문과 같은 문항이 나오지 않는다. 씨앗 20개가 모두 겹치게 만든 대역에서 세션은 만들어지고 그 문항은 `ind` 에 세지 않는다.
6. 확인 세션에 은행 후보가 들어가지 않는다.
7. 추천이 `{P, review}` 일 때 `startRecommendedCourse` 의 결과가 `updateExpedition` 을 통과한다(초등 미션 열림 · 미션 없음). 개념 · 중등 미션이 열려 있으면 지금처럼 거절된다.
8. KST 23:59 에 확인을 끝내고 00:00 에 시작하면 그날의 확인 한도가 새로 열리되 14일 유예는 그대로다.
9. 꺼져 있으면 `courseSummary` · `expeditionCourseRecommendation` · `generateCourseSession` 의 출력이 지금과 같다(같은 입력의 스냅샷 대조).
10. `parseSrsState` 가 선수 확인을 거친 상태를 새 키 없이 읽는다.

## 8. 승인을 받을 v0.2 문구

다음이 그대로(또는 같은 뜻의 값으로) 들어 있으면 approve 한다.

1. «v1 은 DB 표와 `StudentSrsState` payload 의 꼴을 바꾸지 않는다. 판정과 추천은 저장된 초등 코스 기록에서 읽을 때 뽑는다.»
2. «끼우는 자리는 `prerequisiteStep` 한 함수이고, `courseSummary` 의 추천 사슬과 `expeditionCourseRecommendation` 의 대체 가지 두 곳에서 부른다. 가드 · 스키마 · 계약 · 학생 컴포넌트는 고치지 않는다.»
3. 허용 목록 한 줄 — 목표 `5-2-2-1 · 5-2-2-2`, 확인은 **서버가 채점하는** 소단원(내 제안 `5-1-5-4 · 5-1-5-3`). `5-1-4-2` 는 쓰지 않는다고 까닭과 함께.
4. «근거 판정은 완료 판정과 다르다: 자기채점 · 힌트 · 재도전 · 이미 본 본문은 스스로 맞음에 세지 않는다. 통과 = 스스로 맞음 4 이상, 실패 = 서버 채점 오답 2 이상.»
5. «발급 제한(14일 · `memories`)은 숙달의 근거가 아니다. 가장 최근 결과와 최근 스스로 맞음은 따로 낸다. 일부 소단원의 통과로 단원 숙달을 말하지 않는다.»

7. «확인 뒤에는 만기 복습보다 먼저 목표의 `learn` 을 낸다.»
