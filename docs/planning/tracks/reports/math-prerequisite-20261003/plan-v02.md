## 1. 목적과 이번 완료 범위

학생이 푼 문제에서 **직접 확인할 수 있는 어려움**을 찾고, 관련된 선수 범위를 확인한 뒤 목표 문제로 돌아오게 한다. 목표에서 틀렸다고 그 선수 전체나 모든 조상을 부족한 단원으로 확정하지 않는다.

이번에 완료할 것:
1. 사용자 코드의 붙여넣기 오류를 고친 독립 `math-graph.cjs`와 실제 Node 실행으로 생성한 `math_graph_2022.json`, `math_graph_2022.md`.
2. 요청한 11과목을 제외한 **100개 편집 단원**의 조회. 단원 선택 시 학습 요소·직접 선수·후속 단원·도움 관계·과목 관계와 연결 이유를 표시한다.
3. 학교급·학년군·과목·영역·검색어로 조회하고 선수 관계를 역추적해 **교사가 확인할 복습 후보**를 표시한다.
4. 기존 학생 학습 화면에서 실제 작동하는 **분수 곱셈 → 분수 뺄셈 확인 → 분수 곱셈 재확인** 시범 경로.
5. 학생 A의 기록이 B에 영향을 주지 않으며, 서버 채점·힌트·자기채점·재도전·반복 문항을 구별한 근거 표시.
6. 단원의 조회 가능 여부와 자동 문제 제시 가능 여부를 구별하고, 미지원은 명시한다.

100단원 전체의 맞춤 출제를 완료했다고 주장하지 않는다. 이번 자동 경로는 아래 2개 목표 소단원과 2개 확인 소단원뿐이다. 이차방정식 `M3-R02`는 그래프/복습 후보 조회가 되며 자동 문제 제시는 미지원이다. 다른 단원의 문제로 바꾸어 표시하지 않는다.

## 2. 데이터 범위와 변경하지 않는 의미

유지: 초등·중학교 수학; 공통수학1·2, 기본수학1·2, 대수, 미적분Ⅰ·Ⅱ, 확률과 통계, 기하.
제외: 경제 수학, 인공지능 수학, 직무 수학, 수학과 문화, 실용 통계, 수학과제 탐구, 전문 수학, 이산 수학, 고급 대수, 고급 미적분, 고급 기하. 기존 직업계고 전문교과별 전공 수학·학교별 인정 과목의 제외도 유지한다.

- `units`는 편집 단원, `topics`는 학습 요소, `contains`는 포함 관계다.
- `prerequisite`는 교육적 추론, `support`는 도움 관계다. 공식 필수 이수 조건이 아니다.
- `courseRelations`는 과목 순서·대체·권장 관계이며 개념 선수 간선으로 자동 변환하지 않는다.
- **소단원끼리의 직접 선수 간선은 없다.** 단원 간선을 모든 소단원 사이로 확대하지 않는다.
- 학습 요소의 배열 순서, `orderIndex`, 제목 유사도로 선수 간선을 만들지 않는다.
- 성취기준 전수 검증은 미완료다. `achievementStandardIds: []`, `needsCurriculumAudit: true`, `isOfficialEnrollmentRequirement: false` 유지.
- 중학교 ID의 숫자는 화면 배치 제안이며 공식 학년군과 구별한다. 고등 영역은 편집 분류로 표시한다.
- 정적 교육과정·화면 코드·학생 풀이 저장을 분리한다.
- `E56-N03`/`E56-N04` 모두 전체 학습 요소를 다 측정하지 않으므로 **부분 확인** 상태다. 일부 통과로 단원 전체 숙달을 말하지 않는다.

## 3. 선택한 구조와 기존 결정

**v1은 DB 표와 StudentSrsState payload의 저장 형식을 바꾸지 않는다.** 학생의 기존 초등 `course` 기록을 읽을 때 근거와 추천을 계산한다. 새 마이그레이션, 관찰 ledger, 복사한 학생 숙달 상태, 새 독립 학습 세션/보상 체계가 없다.

새 결정 식별자 **MPR-20261003-01**: 현재 사용자 지시와 이번 3자 합의가 `docs/planning/tracks/reports/consult-27/consensus.md`의 자동 선수 배정 보류를 **아래 시범 범위에 한해 대체한다**. 기존 하루 학습 묶음, 5문항 코스 세션, 미션 완료·재도전 우선, 총점/숙달 확률을 표시하지 않는 원칙은 유지한다. 현재 지시로 승인된 일상 구현 선택을 다시 허락받는 단계는 추가하지 않는다.

| 선택 | 이유 |
|---|---|
| 기존 코스 기록에서 계산 | strictObject 저장 호환·기존 CAS/재전송·학생 소유권을 유지 |
| 같은 탐험 단원 안의 시범 | 열린 미션의 고정된 단원과 기존 guard를 통과 |
| 기존 5문항 learn/review | 새 짧은 세션 메뉴나 추가 하루 학습량 없이 실제 학생 화면에 연결 |
| 손으로 쓴 간선별 확인 범위 | 큰 단원 간선을 소단원 선수 간선으로 오해하지 않음 |
| 외부 AI 호출 0 | 채점·그래프 탐색·근거 집계·추천은 결정적인 코드로 구현 |

Codex의 선택 필드 및 Grok의 별도 테이블은 문항류 출처 보존·긴 기간 근거·교차 탐험 경로 등을 위한 후속 선택이다. 이번 범위에는 필요하지 않아 넣지 않는다. 과거 시험 `TestResult/ProblemAnswer/AnalysisReport`, 중등 간접 `conceptWeights`, 개념 카드, 다른 학생 기록은 v1 근거에 편입하지 않는다.

## 4. 정적 그래프와 계약

정본은 루트 `math-graph.cjs`의 편집 데이터다. 루트 JSON과 Markdown은 커밋하는 파생물이다. UI는 JSON을 조회하는 별도 TypeScript 계층을 사용한다. HTTP 요청에서 생성기를 실행하지 않는다. CJS를 require 할 때 파일을 쓰지 않으며 CLI 실행의 기존 기본 출력과 `--out/--target/--mastered`는 유지한다.

새 로직 위치: `src/lib/math-prerequisite/`.
그래프/교사용 읽기 DTO 계약: `src/contracts/mathPrerequisite.contract.ts`.
기존 엄격한 학생 저장 스키마는 수정하지 않는다. 교사 상세의 읽기 전용 근거 DTO와 학생 응답의 선택적 `prerequisiteContext`(표시 이유·현재 확인 범위)는 추가할 수 있다. 저장하는 phase/판정이 아니다. 원본 답/정답은 학생 시작 응답에 노출하지 않는다. 기존 DTO fixture에 새 선택 필드가 없어도 파싱되며, 배포 시 reader 먼저 호환시키고 writer를 켜는 순서를 문서화한다.

판을 구별한다:
- `schemaVersion`: 그래프 형식 문자열 **"1.1.0"**.
- `graphContentHash`/`graphVersion`: 단원·학습 요소·간선·과목 관계의 내용. 동일 스키마에서도 내용이 바뀌면 새 값.
- `mappingVersion`: 손으로 쓴 단원/소단원 매핑 및 자동 확인 허용 목록.
- `policyVersion`: 발동·근거·신선도·예산 규칙.

파생 근거 DTO에 현재 판 정보를 싣는다. 판정을 저장하지 않으므로 오래된 파생 상태를 혼합하거나 캐시에서 복구하지 않는다. 소단원 ID `.tNN`는 표시용 구조 ID이며 저장된 문제의 안정된 의미 태그로 사용하지 않는다.

그래프 적재 검사는 중복 단원/학습 요소 ID, 없는 간선 끝점, 자기 선수, 선수 순환, 포함 관계의 부모, 주제 간 선수 간선 0, 제외 과목 유입 0을 실제로 검사한다. 그래프의 집계와 생성 결과도 대조한다.

CLI 전체 역추적 후보에서 숙달 표시 단원의 조상 탐색을 끊는 기존 동작은 **교사용 확인 후보 조회**로만 사용한다. 제품 자동 추천은 그 목록을 호출하지 않는다. 따라서 숙달을 조상에 상속하거나 모든 조상을 문제로 바꾸지 않는다.

## 5. 명시적 매핑과 첫 경로

| 역할 | 그래프 단원 | 기존 코스 소단원 | 범위 |
|---|---|---|---|
| 목표 T | E56-N04 분수 곱셈·나눗셈 | 5-2-2-1, 5-2-2-2 | 분수×자연수, 자연수×분수의 코스 5문항 |
| 확인 P1 | E56-N03 분수 덧셈·뺄셈 | 5-1-5-4 | 대분수의 뺄셈 |
| 확인 P2 | E56-N03 분수 덧셈·뺄셈 | 5-1-5-3 | 진분수의 뺄셈 |

확인 순서는 P1 → P2로 고정한다. 목표 응용 문항의 뺄셈 사용(`g5.ts` fm221Apply/subFrac 및 fm222Apply의 자연수-분수)과 확인 범위의 출제 등록을 소스에서 확인했다. 넷 모두 `g5-fractions` 탐험 안이다. `curriculumBridge`는 미션 단원 일치 확인에만 쓰며 그래프 매핑으로 재사용하지 않는다.

`5-1-4-2` 약분은 현재 발문 정규식 때문에 상당수가 자기채점이므로 허용 목록에서 제외한다. `5-2-2-3/4`는 같은 뺄셈 맥락을 보장하지 않아 시범 목표에 넣지 않는다.

매핑 상태 `verified/ambiguous/unmapped`와 공급 상태 `available/unavailable`를 분리한다. `verified`는 이 편집 단원과 코드의 대응을 확인했다는 의미이며 공식 성취기준 감사 완료가 아니다. UUID 대신 정확한 코스 section ID를 사용한다. 미래 DB 연결에서는 동일 (학년, chapter, section)에 정확히 한 UUID일 때만 매핑한다.

자동 확인 허용 목록은 **단원 간선 E56-N03 → E56-N04와 지정된 확인 범위**를 참조한다. 새 소단원 선수 그래프를 만드는 것이 아니다. 이 허용 목록 밖의 M3·고등·초1~2는 자동 제시 unavailable이며 조회는 가능하다.

첫 구현 관문: 4개 소단원 × 연산/기본/응용 × **seed 0..199** 및 실제 5문항 생성 결과에 대해 자동 채점 가능, 그림 없음, 보기의 유일한 정답, 정답 채점 성공/오답 거절을 검사한다. 자기채점이나 채점 오류가 한 건이라도 있으면 해당 경로를 켜지 않고, 같은 문서의 공급 게이트 수정 절차로 3자 재검토한다. 실패한 범위를 조용히 다른 소단원으로 대체하지 않는다.

## 6. 직접 근거와 상태

원천은 현재 세션과 보존된 최대 30개 코스 세션. 세션/문항 ID로 원천 사건을 구별하고, **본문 content**로 반복 노출을 구별한다. seed나 새 UUID만으로 독립성을 주장하지 않는다. 최근 답안 100개는 추가 본문 제외에 쓰되 근거의 세션 결과를 복제하지 않는다.

끝낸 세션의 첫 풀이에서만 계산:
- 독립 정답: 서버 자동 채점·정답·힌트 없음·자기채점 아님·앞서 보존된 세션에서 본 동일 본문 아님.
- 독립 오답: 서버 자동 채점·오답·힌트 없음·자기채점 아님·빈 답으로 포기 아님·동일 본문 반복 아님.
- 힌트·자기채점·포기·재도전·미완료·판정 불명은 독립 성공/실패에 세지 않는다.
- 동점시 session startedAt/id 순으로 안정적으로 정렬한다. 중복 사건은 한 번만 센다.
- `passed`: 독립 정답 4개 이상.
- `failed`: 독립 오답 2개 이상.
- 그 밖은 `inconclusive`. 기록이 없거나 잘렸으면 `unknown`/미측정이다.
- 기존 진도 완료 규칙은 유지하고 이 새 근거 판정과 혼동하지 않는다. 자기채점만으로 진도가 넘어가도 직접 성공 근거는 아니다.

관찰/추정을 구별한다:
| 값 | 정의 | 용도 |
|---|---|---|
| 최근 확인 제한 | P의 memories.lastReviewedAt가 14일 이내 | 확인 발급 제한만. 숙달 아님 |
| 최근 결과 | 보존된 기록 중 해당 소단원의 가장 최근 완료 세션 결과 | 교사용 근거 |
| 최근 독립 성공 | 가장 최근 결과 passed, 14일 이내 | 해당 소단원만 passed_recent |
| 부분 확인 | 시범 매핑 외 학습 요소 미측정 | 단원 전체 demonstrated 금지 |

소단원 상태: `unassessed/passed_recent/not_passed_recent/stale/inconclusive`와 직접 관찰 개수·확인 시각. 단원은 확인된 소단원과 미확인 범위를 표시한다. 단일 숙달 점수, 숙달 확률, 부분 범위의 단원 전체 통과를 표시하지 않는다. 정책 수치(2세션, 4정답, 2오답, 14일)는 운영 자료로 보정된 값이 아닌 **잠정 정책**이라고 문서화한다.

## 7. 추천·보충·목표 복귀의 정확한 한도

공통 순수 함수 `prerequisiteStep(course, now, enabled)`는 현재 서버의 `nextLearning` 목표와 허용 목록을 기준으로 `check/return/null`을 계산한다. 학생이 목표/선수/정답/상태를 지정하는 새 요청은 만들지 않는다.

우선순위:
1. 진행 중인 세션/재도전은 그대로 resume.
2. 계획이 꺼졌거나 그 요청에 적용되는 하루 분량을 다 채웠으면 새 세션 없음.
3. 현재 완료 세션이 현재 목표 T의 허용 확인 P라면 **목표 복귀를 먼저** 추천.
4. 다음으로 선수 확인 조건을 검사.
5. 그 뒤 기존 만기 복습 및 일반 새 학습.

확인 발동: 현재 미완료 목표 T의 **가장 최근 완료 learn 세션 둘**이 모두 failed, 둘 다 14일 이내. 단일 오답, 실패 한 세션, 두 세션 사이 성공/불명 결과는 발동하지 않는다. 같은 날 기존 코스가 여러 번 T를 내더라도 서로 다른 직접 본문 근거가 있어야 한다.

상한: 깊이 1, KST 하루 확인 1세션(5문항), 후보 P1/P2 최대 2개, 동일 P 확인 유예 14일. support 및 선수의 선수는 자동 확인에 쓰지 않는다. 해당 확인 소단원의 오늘 관찰이 있으면 새 확인 없음. 현재 미완료 확인은 resume가 우선이다. P 둘 모두 유예 중인 반복 어려움은 추가 자동 확인 대신 목표 일반 연습과 교사 확인 안내로 이어진다.

복귀: 완료된 확인 P는 현재 세션에 남아 있으므로 이력 30개가 잘려도 다음 추천이 현재 T로 돌아온다. 동일 P를 자동 확인이라고 확정하는 별도 phase는 저장하지 않는다. 현재 목표와 연결되는 일반 복습 P 뒤에도 보수적으로 목표 복귀를 추천할 수 있다. 교사가 목표를 바꾸거나 기능을 끄면 현재 계획으로 계산하며 오래된 목표를 복구하지 않는다.

확인 뒤 목표 learn을 만기 복습보다 먼저 낸다. **확인 직후 단 한 번의 복귀는 learnedToday 억제보다 우선**이며 기존 하루 분량을 넘기지 않는다. 새 목표 세션을 시작하면 현재 세션이 T가 되어 복귀 예외가 사라진다. 확인에서 통과하지 못해도 목표로 돌아온다. 더 아래로 내려가지 않는다. 확인 실패의 보충은 기존 1일 간격 만기 복습을 사용하며 새로운 무한 보충 루프를 만들지 않는다.

끼우는 자리:
- `courseSummary`의 resume/활성 계획/하루 한도 다음, due/learnedToday 전에 공통 함수를 적용.
- `expeditionCourseRecommendation`의 고정된 초등 미션 안에서도 같은 공통 함수를 적용. 코스 dailyQuestionCount=5와 미션 goal=10 차이 때문에 fallback을 빠뜨리지 않는다. 열린 미션의 answered<goal 범위에서 같은 탐험 단원만 허용하고 guard가 재계산하는 동일 추천을 사용한다. **확인 뒤 fallback 복귀도 T의 learn**으로 낸다. 기존 fallback의 review 고정은 이 시범 복귀에 한해서 변경하며, 목표를 잘 풀면 기존 진도 완료 규칙으로 진행한다. 미션 한도와 같은 탐험 단원 검사는 유지한다.
- `expeditionInitialCourseRecommendation`/`courseRoutes`/미션 시작 경로가 같은 권위를 통해 시작한다.
- 이미 열린 중등·개념 미션, 목표 변경 제한, 미션 완료/보상 guard를 우회하지 않는다.

코스 하루 5/10/15/20 및 초등 미션 10의 모든 경우를 검사한다. 한도를 채우면 복귀는 다음 학습 가능 시점까지 미루며 그 사유를 표시한다. KST 경계에서 route와 저장 시각의 추천이 갈리면 기존 409→재조회로 회복하고 데이터 손상/중복 시작을 막는다.

## 8. 출제·공급 부족

첫 자동 확인 및 목표 복귀는 **엔진 출제만** 사용한다. 기존 은행 후보는 problemId/family 출처가 저장되지 않아 새 진단에서 그 출처를 주장하지 않는다. 일반 비시범 경로는 그대로다.

실제 저장된 본문(현재/보존된 세션·recentAttempts)과 새 세션 안의 본문을 제외한다. 지정 section/난이도 구성을 바꾸지 않고 세션 seed를 최대 20개까지 결정적으로 시도한다. 확인 seed는 발동한 마지막 목표 세션 ID+P, 복귀 seed는 현재 완료 P 세션 ID+T에서 안정적으로 산출한다. 추천의 사전 공급 검사와 실제 시작은 같은 상태·seed·제약을 사용해 guard가 검사하는 section/mode와 공급 결과가 갈리지 않는다. 저장된 실제 seed로 그림/본문 재현도 유지한다. 문항류 다양성이 검증됐다는 표현은 쓰지 않는다. 발동하지 않은 명단 학생의 요약은 생성기를 호출하지 않는다.

20개 안에 5문항을 안전하게 공급하지 못하면 그 자동 경로는 **unavailable**와 구체적 이유를 표시한다. 반복된 문항을 독립 근거라고 계산하지 않는다. 다른 단원으로 바꾸거나 새 정책의 제약을 조용히 풀지 않는다. 공급 실패는 추천 계산에서 확인하고 새 진단 세션을 시작하지 않는다. 기존 하루 한도 안의 목표 일반 학습/미션의 정상 이어 풀기로 돌아가며 “안전한 확인 문제를 준비하지 못해 목표 학습을 이어갑니다”라는 이유를 표시한다. 정상 경로의 문항을 새 진단 문항이라고 표시하지 않는다. 학생에게 빈 시작이나 끝없는 시작 재시도를 요구하지 않는다. 이 nonstalling 동작과 guard 일치는 구현 관문에서 별도로 검증한다.

서버가 시작·정답 채점을 정한다. 기존 student auth, same-origin, no-store, revision CAS, 중복 요청 처리와 원본 답 비노출을 재사용한다. 새 학생 입력 API나 studentId 입력은 없다. 교사 상세 근거는 기존 담당 반/소유 범위를 따른다.

## 9. 화면과 디자인 합의

학생 화면은 기존 StudentCourseSrs/StudentReviewHome 플레이어를 사용한다. 새 메뉴·새 독립 세션 화면은 만들지 않는다. 실제 /learn 미션은 자동 시작하므로 홈 추천 카드만 바꾸면 이유가 보이지 않는다. **StudentCoursePractice 머리에 서버가 계산한 현재 확인/복귀 이유 한 줄을 표시**하고, 교사 패널과 같은 Wire/Hi-fi 시각 검토를 거친다. refresh/resume에서도 저장 기록으로 해당 맥락을 계산하며 근거 없이 이전 phase를 복원하지 않는다. 표시 문구:
- 확인: “분수의 곱셈에 쓰이는 분수의 뺄셈을 먼저 확인해요.”
- 복귀: “확인을 마쳤어요. 분수의 곱셈을 다시 학습해요.”
- 한도/미지원/공급 부족은 실제 다음 행동을 짧게 안내한다. 모든 상황에 새 문제를 보장한다는 문장은 쓰지 않는다.

교사용 `CurriculumGraphPanel`을 기존 CourseDashboard에 펼치는 조회 영역으로 연결한다. 새 전역 페이지/사이드바를 만들지 않는다. 학생 선택이 없어도 100개 교육과정 조회 가능. 선택한 학생의 근거가 있으면 그 학생만 부분 확인 상태를 함께 표시한다.

필수 조작: 검색, 학교급/학년군/과목/영역 필터, 단원 선택 및 관계 단원으로 이동, 필터 초기화, 역추적 복습 확인 후보(진단 아님). 학습 요소 목록과 직접/후속/도움 관계·이유·과목을 구별하고 목록에 관계가 없음과 학습상 관계가 없음은 동일시하지 않는다. 데이터 상태(편집·전수 검증 미완료)와 자동 문제 제시 지원 범위를 표시한다. 키보드/휴대폰도 접근 가능해야 한다.

디자인 순서: 프로젝트 확정 디자인을 보존하며 **Wire 4안 → 실제 Codex/Grok/Claude 구조 선택 → Hi-fi 4안 → 셋이 화면을 직접 보고 최종 선택 → 제품 UI 코드**. 현재 사용자의 3자 합의 지시를 이 작업의 선택 권한으로 적용한다. 시안·각 세션의 판단·선택 근거를 저장한다. 합의된 기능 계획만으로 검토하지 않은 UI를 구현하지 않는다.

## 10. 병렬 작업과 파일 소유

일반 기능 계획 승인 후 공통 타입/계약을 먼저 동결한다. 독립 가능한 부분은 Orca worktree에서 병렬 구현하며 main의 다른 작업/미추적 문서를 보존한다.

| 담당 | 소유 | 다른 담당 파일 |
|---|---|---|
| 그래프 담당 | 루트 CJS/JSON/MD, graph/schema/조회/그래프 테스트 | 기존 SRS/미션/화면 편집 금지 |
| 근거·정책 담당 | mapping/evidence/policy/버전·단위 테스트 | 기존 저장/route/화면 편집 금지 |
| 조정자 | 기존 course/expedition/generator 호출 연결, 읽기 DTO, UI 연결, 통합·브라우저 검증 | 독립 담당 모듈은 계약으로 연결 |
| 디자인 담당(위 세션 재사용) | planning 시안/캡처/시각 검토 보고서 | 검토 완료 전 제품 TSX 편집 금지 |

독립 구현 소스는 main에 먼저 합친 확정 계획과 계약을 기준으로 한다. shared파일의 수정은 조정자 한 명이 한다. 담당자는 단계 결과와 테스트를 제출하고, 조정자가 diff를 검토·관련 회귀 검증 후 main에 병합한다. 완료·병합·깨끗함·비활성 조건을 모두 만족한 Orca worktree만 제거하며 브랜치는 보존한다.

## 11. 검증과 실패 시 처리

| 관문 | 필수 증거 |
|---|---|
| 계획 합의 | 동일 최종 plan SHA256에 실제 3명 명시적 approve. worker_done 성공만으로 승인 처리하지 않음 |
| 그래프 | 단원 100, 제외11과목/간선0, topics 간 선수0, 실제 ID/순환/포함 검사; 생성 JSON 일치 |
| 독립 실행 | Node 기본 실행 및 --target M3-R02, --mastered M1-N02, --out 경로; 외부 패키지/원본 문서 없이 성공 |
| 문제 공급 | 4개 소단원 × 3갈래 × 200seed 및 5문항 입력/정답/오답 검사. 실패면 시범 켜지 않음 |
| 근거 | 학생 분리·완료/미완료·힌트·자기채점·포기·재시도·중복본문/사건·이력 절단·신선도·부분 커버리지 |
| 추천 | 한 번 실패 무발동; 최근2실패 발동; 중간성공/불명 중단; 직접 간선만; 14일/KST경계; 하루1확인; 확정 목표 복귀 우선; 미래기록/잘못된ID 거절; 미발동 명단 100명의 생성기 호출0 |
| 통합 | 코스 하루5/10/15/20; 초등 미션10; active/retry resume; 고정단원 guard; 중등/개념 미션 차단; 두탭 CAS/재전송/409 재조회; 꺼진 기능의 기존 출력 동일 |
| 공급 오류 | 20seed 모두 반복/불가능한 대역에서 이유 표시·목표경로 유지·무한클릭 없음·허위독립근거0 |
| 저장 호환 | 이전 strict payload parser로 시범을 거친 상태 읽기; 새 저장 키0·DB변경0 |
| 화면 | 실물 교사 검색/필터/선택/직접·후속·도움/역추적·미지원; 학생 A/B 격리 fixture로 기존 플레이어 확인→목표 복귀를 브라우저에서 검증 |
| 최종 | 관련 vitest·typecheck·lint 및 필요한 build. 실제 운영 데이터와 교육적 효과 검증은 완료했다고 주장하지 않음 |

브라우저 테스트는 운영 학생/공유 DB를 수정하지 않는 격리 fixture를 사용한다. 실제 handler 경로와 저장 mock 회귀, 같은 플레이어의 브라우저 흐름을 함께 증명한다. 테스트 fixture 화면을 실제 운영 학생 사용 결과로 보고하지 않는다.

부족한 범위나 문항 실패는 reason/partial/unavailable로 남긴다. 성취기준 상태를 완료로 바꾸지 않는다. 중요 계약·첫 경로·정책을 바꿔야 하는 경우 같은 최종 문서에 수정 내용을 반영하고 SHA를 바꾼 뒤 3자 재승인을 받는다. 기존 기능의 별도 결함을 발견하면 근거를 기록하고 이번 기능 때문에 밟는 경로만 먼저 안전하게 해결한다.

## 12. 합의 기록과 최종 전달

실제 Run/task/dispatch, 검토 파일, 승인한 plan SHA256, 각 verdict와 해결된 쟁점을 `consensus.md`에 기록한다. 승인하지 않은 모델, 무응답, 도구 실패를 합의로 표시하지 않는다.

최종 전달: 생성 파일과 실행 집계, 첫 자동 경로의 동작/활성 방법, 검증 결과, 명시적 지원 범위와 남은 데이터 감사 상태, 합의 기록 링크. 운영 배포나 공유 DB 재작성이 있어야 이번 구현이 완료된다는 조건은 두지 않는다.
