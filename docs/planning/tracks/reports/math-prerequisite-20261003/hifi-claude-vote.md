## 판정 — **H1 · approve**

아래 §3 의 조건 다섯은 구현에서 지킬 것이다. 문구 · 표시 규칙이라 구조와 해시를 다시 돌릴 일은 아니라고 본다. 루트나 다른 검토자가 같은 해시에 이것을 고쳐 넣기로 하면 그것도 좋다.

## 1. H1 을 고른 까닭

- **목록을 훑기에 가장 낫다.** 행마다 «코드 + 이름»(굵게)과 «학년군 · 과목 · 영역»(작게)이 늘 같은 두 줄이다. 같은 이름 셋(경우의 수)이 과목으로 바로 갈린다. 320 에서도 한 열이고 높이가 넷 중 가장 덜 늘어난다.
- **H2** 는 펼친 단원 제목(23px)이 또렷하지만, 접힌 행에서 학년 · 과목 줄이 사라진다. 100단원을 훑는 목록에서 같은 이름을 가르려면 펼쳐야 한다.
- **H3** 의 알약은 «문제를 낼 수 있음 · 자동으로 내지 않음»을 행에서 바로 보이게 해 준다 — 이 화면에서 교사가 가장 알고 싶은 것이다. 하지만 모든 행에 «접힘» 알약이 붙어 소음이 되고, 520 칸에서 가운데 메타 열 때문에 제목이 «분수 곱셈·나 / 눗셈»처럼 낱말 가운데서 끊긴다. 390 에서는 알약이 셋째 줄로 내려가 행이 더 길어진다.
- **H4** 는 상태 글자가 제목 줄 끝에 붙어 줄마다 끊기는 자리가 다르다.
- H3 의 장점(공급 상태를 행에서 보기)은 H1 에 한 줄로 옮길 수 있다(§3 조건 1).

## 4. 이 투표가 뜻하지 않는 것

다른 두 모델의 승인을 가정하지 않는다. 제품 화면 코드는 세 모델의 하이파이 승인이 맞은 뒤의 일이고, 그 뒤에도 실물 · 브라우저 검증이 남는다.
