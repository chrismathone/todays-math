제품 수정은 `src/components/math-srs/elementary-practice.module.css`의 **900px 이하 `flex-basis` 두 곳을 `0`에서 `auto`로 바꾼 것**이다.
새 높이·문구·테마·저장 계약·채점·일정·데이터 변경은 없다. 로컬 재현과 검증을 마쳤으며 운영 반영은 하지 않았다.

## 원인과 수정

실제 경로는 `StudentAppShell → StudentReviewPage(embedded/embeddedMain) → StudentCourseSrs의 practiceStage → StudentCoursePractice`다.
관리되는 학생 셸은 문서 내용 높이를 쓰고, 독립 학습 경로의 `100dvh`·flex 부모를 사용하지 않는다.
그러나 900px 이하 `.fixedPractice .fixedQuestion`과 그 안 `.problemScroll`은 `flex: 1 1 0`이었다.
부모의 확정된 남는 높이가 없는 상태에서 카드와 본문의 내용 크기가 사라졌다.

- 390×844·768×1024: 카드 28px(위아래 padding뿐), grid 행 `0px 0px`, `problemPane` 0px, 본문 8px(padding뿐), 답 영역 0px.
- 844×390: 짧은 높이용 flex 전환 규칙이 있어 내부 면은 생겼지만 **카드 자체가 20px**로 접혀 접근할 수 없었다.
- 독립 QA의 고정 높이 부모에서는 재현되지 않았다. 기존 `mobile-practice-qa`의 부모를 그대로 쓰는 것만으로는 H-02를 잡지 못한다.

두 곳을 `flex: 1 1 auto`로 바꾸어 관리되는 셸에서는 내용으로 높이를 계산하고, 확정 높이가 있는 독립 프레임에서는 기존 shrink·내부 스크롤을 유지한다.
`min-height: 0`, grid 구조, 기존 짧은 가로 화면의 스크롤 규칙, 책 테마·follow-up 구조는 그대로다.

카드 한 곳만 고친 중간 판은 보기만 복구되고 본문이 8px로 남았다. 캡처를 열어 발견했으며 `diagnostic-one-basis/`에 보존했다.
최종 검사는 단순한 양수 높이 외에 **본문 글줄 전체가 스크롤 영역 안에 들어오는지와 `elementFromPoint` 가림 여부**를 확인한다.
