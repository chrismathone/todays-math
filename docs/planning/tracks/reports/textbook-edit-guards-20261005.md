## 3. 고친 것 — 규칙 넷

화면마다 조건을 덧붙이지 않고 규칙으로 닫았다(`src/components/textbook/TextbookStudioView.tsx` · `parts.tsx`).

1. **처리 중에는 원고 입력과 구조 변경을 잠근다. «이 구획 저장» 만 연다.**
   `frozen = leaving || (busy && !savingManuscript) || publishUnknown`. 가져오기 · 개념 저장 · 연결 다시 시도 ·
   저장 후 이동 · 발행 단계 · 구획 불러오기가 도는 동안 편집 칸 · 구획/단원 추가 · 목차 이동 · 강의 연결 · 설정이 잠긴다.
   늦은 응답이 덮거나 발행 잠금에 갇힐 «그사이의 수정» 이 생기지 않는다.
   발행 결과를 확인하지 못한 동안(`publishUnknown`)에도 잠근다 — 다시 읽는 중에도, 다시 읽기에 실패해도 풀지 않고
   판본을 실제로 읽은 뒤에만 푼다.
2. **구획 저장은 요청 때의 원고만 저장한 것으로 다룬다.** 응답이 왔을 때 원고가 요청 때와 다른 객체면
   그대로 두고 revision 만 올린다. 저장본은 요청 스냅샷, 알림과 목록 상태는 미저장으로 남는다.
3. **원고나 구조를 바꾸는 작업은 한 번에 하나만 돈다(`begin()`).** 가져오기 · 개념 저장 · 다시 고정 · 연결 · 등록 ·
   백지 검색 · 목차 저장 · 강의 연결 · 구획 삭제. 전에는 이 가운데 여럿이 처리 중 표시를 세우지 않아, 도는 동안
   다른 구획을 열거나 다른 작업을 겹칠 수 있었다(삭제 대기 → 다른 구획 수정 → 삭제 완료가 그 원고를 비움).
   진입은 ref 로 그 자리에서 가르고, 처리 중 표시는 작업 수로 센다 — 참/거짓 하나였을 때는 먼저 끝난 작업이 표시를 껐다.
4. **늦은 응답은 요청한 판본 · 구획이 아직 열려 있을 때만 화면에 올린다(`sectionOpen` · `editionOpen`).**
   화면 안의 이동은 처리 중 표시가 막지만 주소 동기화(`initialEditionId`)는 다른 판본을 열 수 있다.
   판본 revision 을 올리는 함수형 갱신도 판본 번호를 본다 — 다른 판본의 구획을 읽는 사이에 끝난 저장이
   그 판본의 revision 을 바꾸지 않는다.
   간편 생성은 «시작한 때의 생성 양식» 이 화면에 남아 있을 때만 만든 교재를 열고, 아니면 목록에 올리고 알린다.

그 밖에:

- B06: 목록이 «어느 선택» 의 것인지로 준비 여부를 판정한다. 상위 선택을 바꾸면 앞 목록 · 선택을 바로 거두고,
  새 목록이 올 때까지 «문항 가져오기» 를 잠근다. 읽기 실패는 빈 목록과 가른다.
- B07: 입력이 같으면 요청 번호 · 교재 번호를 성공할 때까지 유지한다(`client.createBook` 이 `bookId` 를 받는다).
  서버는 실제 교재 번호를 따로 짓는다 — 유지하는 번호는 본문 해시를 같게 만드는 값이다.
  성공 응답은 보낸 값과 같은 칸만 비운다.
- 가져오기 뒤에도 편집 중이던 개념 원고가 남는다. 다시 읽기에 실패해도 이미 담겨 있던 문항 목록이 남는다.
- U03: 생성 양식으로만 쓸 때는 다른 자리에 목록이 있으면 «만든 교재가 없습니다.» 를 내지 않는다.

시험: `src/__tests__/components/TextbookStudioGuards.test.tsx`(새 파일) · `src/__tests__/unit/textbookEditorState.test.ts`.
요청을 손에 쥐고 그사이에 고치거나 옮기거나 다시 누른 뒤 풀어 주는 방식이다 — 응답이 바로 오는 시험으로는 이 경계가 보이지 않는다.

## 4. 원장님 결정 (2026-10-05) — 형태와 문구

형태와 문구를 정하는 일이라(절대 규칙 1 · D-07) codex 와 «구현 뒤 보고» 가 아니라 «결정 뒤 구현» 으로 합의했고,
선택지를 올려 원장님이 넷 모두 첫째 안을 골랐다.

- **처리 중 입력 잠금과 수리에 딸린 상태 문구** — 이대로 확정.
  「구획을 저장했습니다. 저장 중에 고친 내용은 아직 저장되지 않았습니다.」 ·
  「○○ 교재를 만들었습니다. 목록에서 열 수 있습니다.」 · 「교재를 만들지 못했습니다. {사유}」 ·
  선택 칸의 「시험지를 불러오는 중입니다」 · 「시험지를 읽지 못했습니다」.
- **U01** 단추 이름은 두고 단추 곁에 한 줄 —
  「PDF가 완성되면 이 판본이 발행되어 원고가 잠깁니다. 수정하려면 새 초안을 만드세요.」 발행된 판본에는 내지 않는다.
- **U02** 쪽 번호 표기는 두고 곁에 한 줄 —
  「구획 미리보기의 임시 쪽 번호입니다. 전체 교재의 쪽 번호는 PDF에서 확인하세요.」 쪽 번호가 보이는 면에만 낸다(첫 구획 포함).
- **B05** 지면이 본문이 아니라 구조에서 나오는 글 블록은 «본문» 을 읽기 전용으로 하고 곁에 한 줄 —
  「이 본문은 저장된 구조에서 생성됩니다. 이 입력 칸에서는 수정할 수 없습니다.」

B05 의 통과 기준은 보고서의 «수정이 출력에 반영» 이 아니라 **«지원하지 않는 본문 수정은 입력 단계에서 막고, 기존 구조와 지면은 그대로 둔다»** 다.

- 판정은 렌더 층의 한 함수다(`textPrintsFromStructure` — `src/lib/textbook/render/blocks/semantic.ts`).
  `writing` · `references` · `exampleGroup` · `fragments` · `board`, 그리고 자동 단원 도입 틀(`auto-unit-intro`)의 `unitIntro`.
  종류마다 본문만 바꿔 두 번 그려 «지면이 같다 ⇔ 구조에서 나온다» 를 시험한다(`textbookStructureText.test.ts`).
- 은행 활동(`rows`)처럼 본문을 일부라도 읽는 종류, `concept` · `referencePage`, 회상(`concept-recall`) 블록은 **이번에 판정하지 않았다** — 지금처럼 고칠 수 있다.
- 구조를 고치는 전용 편집 칸, 이미 저장된 본문과 구조의 불일치 복구는 하지 않았다.
  `writing` 을 본문에서 다시 만드는 동기화도 하지 않는다(빈 줄을 문항 경계로 확정할 수 없다).
