## L-09b read-only audit

`explorerView` in `src/lib/math-explorers/engine.ts` reads `definitionCard(task.cardId)` and emits `card.exampleTitle`, `card.examples[sourceIndex].text` and `card.trap`. `definitionOptions` in `definition-cards.ts` hashes session ID, card ID, activity kind and round/continuation solely to permute indices. Answer mapping in `engine.ts` maps public choice positions back to those same indices, and `applyDefinitionAction` compares to static `examples[].yes`. `CourseCard` has authored text/boolean examples; `DefinitionSession` has no example variant version. The current code therefore does not implement next-day numeric variation for these examples.

A safe separate change needs reviewed per-card numerical templates with a shared resolver for display, grade and solution, and explicit preservation of already-open sessions. If persisted variant/version data is needed it must follow reader-first deployment; do not silently substitute every number in a sentence. Definition assembly/boundary truth, units/equalities, saved choice indices and follow-up solutions cannot be independently randomized. This finding and minimum boundary were sent to the coordinator; experience-owned files were not edited.
