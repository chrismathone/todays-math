# 비교 이미지의 모눈 실측 보조

현재 재작도 대조 경로에 반복선 실측 보조를 연결했다. 같은 요청에서 이미 디코딩한 두 이미지를 흰 바탕의 제한된 캔버스에서 읽고, 정사각 격자로 추정되는 경우에만 비교 이미지 둘레에 칸 번호를 표시한다. 숫자는 **분석용 순번**이며 원문의 좌표·단위·정답이 아니다. 원본 데이터 URL과 재작도 SVG·FigureSpec은 그대로이고, 학생용 그림이나 저장 명세에 이 숫자를 넣지 않는다. 기존 출제 문항·문제은행·DB는 변경하지 않는다.

`gridMeasure.ts`는 최대 변 1,400·총 200만 픽셀 이내의 정수 회색 자료만 읽고, 양방향 선의 지지와 간격을 확인한다. 캔버스 분석은 최대 변 900에서 수행하고, 투명 픽셀을 먼저 흰색에 합성한 뒤 299/587/114 밝기를 계산한다. 테이블과 모눈은 픽셀이 완전히 같을 수 있으므로 실측 결과에도 `heuristic-only`·`requiresReview`를 붙인다. 없거나 잘린 선·불균등 간격·불명은 null이며 승인으로 바꾸지 않는다. 캔버스 접근 불가나 분석 크기 초과도 실측 불명으로 남긴다. 디코딩 자체의 모든 자원 한도를 증명한 것은 아니다.

비교용 순번의 원점은 각 판의 검출 영역 왼쪽 아래다. 이미지의 자연 크기, 분석 크기의 가로·세로 반올림, `object-fit:contain` 여백을 따로 계산한다. 두 판의 칸 수가 다르면 그대로 따로 표시하고, 한쪽을 재지 못하면 그 판에 실측 불명을 적는다. 실제 SVG의 viewBox 숫자를 화면 픽셀과 바로 같다고 가정하지 않는다. 글자는 이미지 밖 여백의 `textContent`로만 더한다. 반 칸 끝점을 정수 격자점으로 옮기거나 선·점·곡선을 바꾸는 자동 snap은 넣지 않았다.

기존 브라우저와 요청별 페이지를 재사용한다. JavaScript 비활성화, 외부 네트워크 차단, 취소 시 해당 페이지만 닫기, 유휴 브라우저 종료를 유지한다. 최종 `source-and-rendered-images` 대조와 재시도·시간 초과의 `passed=false`도 그대로다. 대조 안내에는 추정 순번을 원문 좌표로 복사하지 말고, 표와의 구별·칸 수·끝점을 실제 인쇄 내용으로 다시 확인하도록 명시했다. 비교 그림만 생성하는 이 보조 경로가 새 문항의 학년·권리·수학 검산을 승인하지 않는다.

현재 실제 회귀는 10파일 151개 통과다. 순수 회색 자료·좌표 매핑, 브라우저 재사용·취소, 기존 엔진·카탈로그·거절/검수 경계와 실제 브라우저 4사례를 포함한다. 실제 브라우저는 투명 배경의 8×8, 8×8 대 9×8, 한쪽 실측 불명, 양쪽 모눈 없음으로 검사했다. 하나의 실제 브라우저를 쓰고 외부 요청·모델·DB 호출은 0이었다. 원본/재작도 입력 바이트 유지, 번호의 프레임 내부 배치, 한글 안내와 번호 상자의 비겹침을 검사했다. 수학적 정답을 그림 픽셀로 구하지 않았다. 실제 시험지나 모델 작도 정확도·속도의 실측은 아니다.

실제 첫 화면 r1은 한글 대체 글꼴에서 안내문과 위쪽 번호 상자가 겹쳐 3사례가 실패했다. 여백을 48, 이미지 영역을 804로 조정하고 줄 높이를 명시했다. 같은 검사의 r2는 네 사례 모두 통과했고 칸 수 불일치 화면을 직접 확인했다. 초기 숫자 비교의 부동소수점 단정 오류와 없는 Node 래스터 패키지·JS 테스트 별칭 오류도 각각 보존했다. 래스터 준비는 이미 설치된 엔진의 `svg_to_png_bytes`를 사용하며 새 패키지를 설치하지 않았다. 메모리 기준에 못 미쳐 시작하지 않은 실행을 통과로 세지 않는다.

QA는 `.qa-artifacts/exam-resume-20261008/engine-upgrade-20261019/grid-advisory-integration-20261021-r1/`, 최종 현재 실행은 `grid-advisory-r7-execution.json`, 화면은 `actual-browser-results-r3.json`이다. 테스트의 타입 주석 보완 후 최신 main `7266c9b28`에서 10파일 151개를 다시 통과했고 실행 전후 코드·검사 설정·실제 화면 하네스·네이티브 입력 해시를 묶었다. 앞선 r6/r2도 보존했다. TypeSafe 프로젝트 스킬과 [최신 confidence 문서](https://docs.typesafe.ai/confidence), [근거 확인 예제](https://docs.typesafe.ai/cookbooks/citation_check)를 읽고, 수치 계산은 코드에 두며 불명을 승인으로 바꾸지 않는 설계를 유지했다. 새로운 TypeSafe·모델 API나 라우팅은 추가하지 않았다. 학년·권리·최종 검수/적재 가능 0과 기존 v50 문항 원장을 유지한다.

변경 5파일의 프로젝트 옵션/선언 기반 TypeScript 오류 0·전역 진단 0, ESLint 오류 0을 확인했다. 첫 타입 검사에서 테스트 자료 factory의 추론 오류 3개를 찾아 명시적 타입을 추가했다. 검사 자료나 생산 동작을 완화하지 않았다. 별도 작업자는 현재 Root 모듈을 직접 불러 독립 회색 입력·유리수 좌표·위조/불명 입력 42개를 통과했고 관련 8파일의 실행 전후 해시가 같다. 부모의 151개나 화면 4사례를 자기 검수 수로 복사하지 않았으며, 실제 캔버스·브라우저·취소·시간 초과 동작은 그 별도 직접 함수 검수의 범위가 아니다. 독립 원장은 `grid-advisory-current-audit-20261021-r1/own-execution-r1/own-report.json`이다. 전체 프로젝트 타입 검사·전체 엔진 개선·전수 문항 검증 완료는 아니다.

후속 확인 중 전달 저장소가 새 `5990a0d`(이미지 생성판 에셋 41종)로 바뀐 것을 발견했다. README·패치 06은 같지만 기대 `assets.json`은 새 에셋 내용이다. 6종 확인 스크립트가 같았던 시점의 원본 경로 확인은 **5종 같음/에셋 1종 다름**이며 이 실패를 보존했다(`check-grid-r1`). 이어진 캡처 시점에는 확인 스크립트도 변경 중이었고, 미커밋 패치 07·08 및 3D 기대 파일이 추가되고 있었다. 이 시점들을 현재 하나의 불변 묶음처럼 취급하지 않는다. 기존에 캡처한 패치 06의 기대 출력 6종은 다시 실행해 모두 바이트 일치했고 그 기대 파일을 바꾸지 않았다(`captured-six-r1`). 새 에셋·anchor·manifest·합성/카탈로그의 커밋된 51파일 차이와 후속 전달 묶음은 다음 별도 동기화 범위다. 기존 SVG의 형상 식별·틀 호환성을 보존하는 방법과 새 41종을 검수한 뒤 반영하며, 신규 자산이 imagegen에서 왔다는 이유만으로 권리·학년·수학 조건을 승인하지 않는다. 원본 대조의 마지막 바퀴 생략·불확실 지적 삭제·모델 변경은 적용하지 않았다.
