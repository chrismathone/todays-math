# 개념 백지 사진 채점 — 출고 작업 기록

2026-11-25 · `phase/cb-scan-core` · 시작 `0619edd6a` · [지시서](../briefs/cb-scan-ship.md).

**구현·로컬 E2E·인쇄 합성 검증·문서를 마쳤다. 전체 검사에서 «기존 4건만 실패» 조건은 못 닫았다.** 아래 최종 검사에 원래 실행 결과와 시작 커밋 대조를 남긴다. 공유 DB 적용·push·운영 빌드·실제 AI 호출은 하지 않았다. 지시서의 합의가 독립 협의 보고서와 다른 곳(별도 배정 표 없음, 사진 보존 분류 등)은 합의를 따랐다. 현 가지에서 이어 하라는 지시로 새 가지·워크트리는 만들지 않았다. 독립 협의 보고서는 고치거나 커밋하지 않는다.

**리드 검수 뒤 사용량 원장의 최종 동작은 맨 아래 «검수 반영»을 따른다.** 앞 본문의 단일 호출·$4.32 예약·불명 사용량 수동 해제 설명은 그 절로 대체한다.

## Hi-fi 선택 — H1 «기록의 여백»

보존 경로 `/dev/concept-blank-scan-hifi`. 실제 초5 은행의 single/multi/all 고르기와 제품 `ConceptBlankPaper`, 글꼴, `PaperStrip`, `PickerDialog`를 사용한다. P1 머리 오른쪽 QR은 20mm, 네 표식은 지면 바깥 여백에 둔다. 표식의 3mm 한 변·종이 끝에서 5mm는 실물 검증 전 설계값이며 인식률로 정한 값이 아니다.

| 안 | 차이 | 선택/버린 까닭 |
| --- | --- | --- |
| **H1 기록의 여백** | 흰 면·남색 제목·가는 구분선·코발트 실행, 같은 폭의 답과 근거 | **선택.** 기존 개념 백지와 작업실의 차분한 인상을 유지하고, 폰에서 입력/빈 답/확인 필요 행동이 같은 자리에서 읽힌다. 상태는 색만으로 구별하지 않는다. |
| H2 또렷한 차례 | 코발트 머리, 번호와 왼쪽 강조선 | 버림. 머리와 구분선이 답안보다 강하고, 폰에서 입력의 보조 행동이 더 많이 줄바꿈한다. |
| H3 칸마다 확인 | 옅은 중립 면의 독립 답 칸 | 버림. 결과가 길어질 때 같은 면·경계·여백이 반복되어 지면 순서로 훑는 데 불리하다. |
| H4 주석이 있는 기록 | 남색 머리·주석선·조밀한 정보 | 버림. 교사 대조에는 맞지만 학생 폰의 첫 확인에 머리와 근거 정보의 밀도가 높다. 역할별 구조는 H1 안에서도 R2/R4로 나뉜다. |

이 선택은 [05 §0](../../05-design-system.md#0-디자인-작업-방식-확정)의 Wire → Hi-fi 절차와 이번 원장님 위임에 따른 Codex의 선택 기록이다. 다른 네 구조를 새로 섞지 않고 지시서의 P1/C1/V3/R2/R4 합의를 유지한다. 장식 그라데이션·기성 킷 기본 모양·카드 그리드·가짜 종합 점수를 쓰지 않는다. 조작은 native button/input/select이며 D-30을 검사한다.

시안의 사진은 실제 사진 대신 미작성 지면, 결과는 상태 예시다. 시안에는 실제 카메라·AI·DB가 없다. 표시 좌표의 사진 정합과 판독 성능은 별도 제품 검증 대상이다. 브라우저 화면의 «맞춤 성공 시안» 스위치는 제품에서 사용자 판단으로 신뢰도를 올리는 기능이 아니다.

## 정한 것과 까닭 / 운영 인계

아래는 구현과 실제 검증의 기록이다. 코드·로컬 검증과 운영 적용·실물 확인을 구분한다.


### DB·선예약·발행 기반

- `20261125120000_concept_blank_scan/migration.sql`과 Prisma 모델 8개를 추가했다. 기존 표의 열·CHECK는 바꾸지 않았다. 새 표는 모두 RLS와 브라우저 권한 회수, 발행본/읽기/수정/판정 덮어쓰기 방지, 공개·채점 중 수정 차단을 갖춘다. **공유 DB에는 적용하지 않았다.**
- Prisma `validate`와 `generate`는 접속 불가능한 로컬 더미 URL로 실행했다. 두 명령은 성공했으며 DB 연결·적용 명령은 실행하지 않았다.
- 마이그레이션 전체 사슬을 새 PGlite 메모리 DB에 적용하는 전용 하네스를 만들었다. 이 엔진의 단일 연결은 순서·제약·트랜잭션 결과를 검증하며, 여러 실제 PostgreSQL 연결의 잠금 경합을 검증했다는 뜻이 아니다.
- DB 사용량 저장소는 원자적으로 예약 → 호출 → 실제 토큰 비용 정산을 수행한다. 단절/사용량 불명은 예약을 남긴 채 막고, 완료 원문과 정산을 같은 트랜잭션에 남겨 작업 재개 시 다시 호출하지 않는다. 저장소나 워커가 사라졌다는 추정만으로 진행 중 호출을 풀지 않는다.
- **보수적인 예약 결정:** 지원하는 5.5 모델의 전체 입력 문맥 상한 1,000,000토큰 + 전송하는 최대 출력 16,000토큰을 예약한다. [공식 모델 표](https://platform.claude.com/docs/en/models/overview)의 입력 한도와 코드의 출력 제한을 사용했으며 측정 평균을 최대치로 쓰지 않았다. 고정 환산표에서 Opus는 $4.32/호출 예약이다. 실제 비용 정산 후 차액은 즉시 풀지만, 월말 잔액이 이 예약액보다 작으면 실제로는 더 싼 요청도 멈춘다. 제공자 청구서 전체의 절대 상한을 보장하는 기능은 아니다. 새 모델/문맥 한도를 쓰려면 이 표도 검토해야 한다.
- 저장소 표/열 미적용은 503용 `ScanUnavailableError`로 변환한다. 일반 네트워크 오류는 마이그레이션 누락으로 위장하지 않는다. 발행/제출 HTTP 시험에서도 503과 이유를 확인했다.
- 합의대로 옛 D도 A와 함께 교사 확인으로 남기도록 스냅숏과 판정 경계를 고쳤다. 옛 D에 수동 확인 표지가 없는 스냅숏이어도 의미/예 칸을 자동 판정하지 않는다.
- 기반 단계 관련 코어·선예약·DDL·좌표 계약: **4파일 41시험 통과**. 별도 발행/권한 시험 **4시험 통과**: 동일 요청의 ID 재사용, 다른 고르기 재사용 거절, 다른 교사의 학생/다른 지점/학생의 채점표/메뉴 꺼짐/소속 이동 거절. 이후 HTTP·화면·전체 시험 결과는 최종 검사 절을 따른다.

### 발행 좌표를 믿는 길

제품 `ConceptBlankPaper`의 쪽 나눔을 그대로 쓰는 `IssuedPaper`에 QR·표식만 더한다. 제품 답 영역에는 기하를 바꾸지 않는 문항/영역 표지만 달았다. 서버가 실제 컴포넌트를 정적 HTML로 그리고, 기존 CSS 모듈 원문을 **그 빌드의 클래스 이름**에 대응시켜 사용한다. 지면 CSS를 손으로 별도 복제하지 않는다. 인쇄 글꼴과 KaTeX 글꼴은 바이트를 CSS에 함께 담는다.

격리 Chromium은 외부 요청과 제출 HTML의 JavaScript를 차단하고, 실제 글꼴·그림을 모두 읽은 다음 모든 스냅숏 `slotId`의 영역과 QR/표식 위치를 mm로 잰다. 누락·중복·다른 칸·본문 넘침이면 발행을 실패시킨다. 최종 HTML·CSS·글꼴·좌표·지문을 발행 행에 동결한다. 재인쇄는 현재 은행/CSS를 읽지 않는다. 브라우저가 준 좌표를 저장하는 입력은 없다.

초기 검사에서 지면의 고딕 토큰이 변수 대신 `Pretendard` 이름을 쓰는데 자체 글꼴을 다른 이름으로 선언한 문제를 찾아, 실제 제품 이름으로 선언하고 400/700/800 굵기의 한글 글꼴 적재를 확인하게 했다. 아직 숫자를 찍지 않은 글꼴을 `document.fonts.ready`만으로 적재됐다고 보지 않는다.

실제 은행 single/multi/all의 서버 렌더와 PDF 생성 결과(`scripts/qa/cb-scan-ship/render.mjs`): 학생지/채점표 **1/1, 3/2, 6/5쪽**, 합계 **18쪽**. 각 조합은 기존 지면 쪽 수와 같고, 모든 쪽의 측정 본문 넘침은 **0px**다. 결과·PDF·고정 산출물은 `/tmp/cb-scan-ship-20261125/issued-*`에 있다. 이 값은 새 서버 렌더의 관측이며 실물 인쇄나 폰 촬영 결과가 아니다.

`raster.mjs`는 PDF를 `pdftoppm -r 300`으로 만든 **18쪽 모두**에서 QR을 정확한 발행 UUID/쪽/part로 복호화했다.
QR은 최종 주소의 버전 6이다. `registration.mjs`는 학생지 10쪽 각각에 독립적으로 고정한 오른쪽/왼쪽 원근·회전 변환을 적용했다.
**30사진·735점**(답 칸 네 모서리와 중심)을 알려진 변환의 참좌표와 대조한 최대 오차는 **1.102871px / 0.266114mm**다.
표식을 피팅한 잔차를 정답으로 쓰지 않았다. 제품은 표식으로 얻은 변환을 QR 네 모서리와도 대조하며, 누락·중복·독립 대조 실패는 좌표 없는 `uncertain`으로 내린다.
QR 독립 대조의 **1.25mm 문턱은 보수적인 설계값**이고 폰 시험으로 고른 최적값이 아니다. 합성 평면에서의 수치를 휜 종이·옅은 연필·손떨림 정확도로 일반화하지 않는다.
Poppler는 가변 글꼴의 Type3 glyph bounding box 경고를 냈다. PDF 페이지 수·래스터·QR과 실제 캡처로 확인했으며, 실물 검수는 대기로 남겼다.

### 라우트·화면·동시성

`/concept-blank/scan`과 `/api/concept-blank/scan/**`의 실제 경로를 연결했다. 로그인과 첫 비밀번호 변경은 발행 ID/쪽/submission을 보존한다.
공용 학생 관문과 기존 `conceptBlank` 메뉴를 사용한다. 익명은 로그인 안내, 채점표 QR은 학생지 안내, 저장 전 옛 코드는 재발행 안내다.
발행 교사의 현재 `ownerScope`에 속한 학생만 제출하며 교사 대리 촬영은 발행물·학생 양쪽을 확인한다. 별도 배정 표는 만들지 않았다.
제출/업로드/수정/작업 시작은 revision과 부모 행 잠금을 사용한다. 업로드 전에 7일짜리 메타데이터를 먼저 두어 중간 실패한 객체도 정리할 수 있다.
사진 업로드는 덮어쓰지 않고 읽어 온 바이트 지문까지 확인한다. 늦게 끝난 재촬영이 최신 사진을 덮지 않는다.

브라우저는 JPEG/PNG/WebP를 다시 인코딩해 방향·메타데이터를 정리하고 기존 AI 이미지 사다리를 쓴다. 선택 파일의 32MiB 제한은 브라우저 메모리 부담을 묶는 설계값이며 실측 최적값이 아니다.
서버도 MIME·실제 이미지·픽셀·전송 크기·사진 자체 QR을 검증한다. 못 읽는 QR/다른 발행물/채점표는 저장·AI 전에 거절한다.
번호는 필기 바깥에 두고 좁으면 확대를 쓴다. 불확실한 사진 정합에는 번호·테두리가 없다. 확대에서 전체 판독문에 숨겨진 해당 입력 칸도 열어 준다.
학생의 빈 답·확인 필요·텍스트 정정은 별도 값이며 공개 전에만 저장된다. 저장 실패한 초안은 되돌리고 최신 답안을 읽을 수 있다.
채점 중 입력 판은 고정되고 미완성 판정은 학생에게 나오지 않는다. 자동 판정·직접 입력·최초 판독은 교사 수정으로 지워지지 않는다.

Next `after` 작업은 HTTP 연결 취소와 분리된다. 작업 예산 240초, route 최대 300초, 앱 작업 재개는 360초 뒤부터다.
이 시간들은 운영 안전 여유를 둔 설계값이다. 유료 `running/unresolved` 호출은 그 시간만으로 해제하지 않는다.
이미 저장된 읽기/판정과 정산된 응답 원문을 재사용한다. 꺼짐·바쁨·예약액 부족은 이유를 보여 주고 입력을 보존한다.
공개 뒤 학생 수정, 다른 탭의 옛 요청, 처리 중 사진 교체·삭제, 교사의 이유 없는 수정은 각각 서버/DB 시험에서 거절한다.

### 사진 보존과 운영 인계

비공개 버킷 기본값은 `concept-blank-scan-private`다. 앱의 `SUPABASE_URL`과 서버 `SUPABASE_SECRET_KEY` 또는 `SUPABASE_SERVICE_ROLE_KEY`를 쓴다.
브라우저에는 키를 보내지 않는다. 읽기/업로드/서명 때 버킷이 비공개인지 확인하며 객체 키는 발행/제출/사진 UUID로 제한한다.
최초 업로드부터 미사용 사진 7일, 채점 입력으로 사용한 사진 30일이다. 재열람·재시도로 기한을 늘리지 않는다.
권한 재확인 후 최대 60초 서명 주소를 발급하며, 서명 요청 도중 삭제·권한 변경도 다시 확인한다.
교사 조기 삭제는 먼저 새 열람을 차단하고 Storage API 성공 뒤에만 삭제 완료를 기록한다. 실패는 재시도 이력에 남긴다.
`GET /api/concept-blank/scan/purge/cron`은 기존 `CRON_SECRET` bearer만 받는다. `vercel.json`의 매일 **18:45 UTC** 예약으로 최대 50개/120초씩 정리한다.
배치가 밀리면 객체 삭제는 늦어질 수 있으나 기한 지난 새 열람은 차단된다. 이미 전송된 사본의 회수나 텍스트 이력 삭제까지 약속하지 않는다.

### 제품 E2E 증거

`scripts/qa/cb-scan-ship/e2e.mjs`의 실제 발행 서비스·HTTP 처리·화면을 사용했다. PGlite는 마이그레이션 전체를 새 메모리 DB에 적용하고,
신원·모델·Storage는 명시적으로 주입했다. 실제 유료 키/DB URL을 이 프로세스에서 제거하고 외부 요청을 거절한다.
발행 PDF의 실제 QR로 진입해 학생지 **세 쪽**을 파일로 올리고 브라우저 인코더·서버 QR/정합을 통과했다.
답 칸 확대 → 숨겨진 입력 칸 초점 → 빈 답/텍스트 정정 → 채점 → 학생 결과 → 교사 이유 있는 수정 → 학생 고르기 창을 검증했다.

- `flow-evidence.json`: HTTP **29요청**, 가짜 모델 **읽기 3 + 채점 3회**, 브라우저 오류/외부 요청 **0**.
- 최종 DB: `teacher-corrected`, 최초 판정 21개(모델 대역 16/규칙 5), 교사 판정 1개 추가, 직접 입력 2개(빈 답/텍스트 각각 하나), 사진 3개 모두 matched·사용 근거 30일.
- **7캡처**, 390/1440에서 가로 넘침 **0px**. `flow-answer-zoom-390`, `flow-check-390`, `flow-student-result-390`, `flow-teacher-result-1440` 등을 직접 확인했다.
- 최초 E2E에서 포괄 버튼 스타일이 지면 띠의 투명 확대 단추를 흰색으로 덮고 숨긴 파일 입력이 가로 넘침을 만든 것을 수정했다. 사진 이미지 적재만으로 표시 검증을 대신하지 않았다.

사진은 미작성 발행지의 래스터이며 답/판정은 가짜 모델이다. 이 검증은 기능 연결의 증거로, 실제 학생 필기 정확도·운영 인증 배포·다중 DB 연결 경합의 증거가 아니다.
Next의 실제 암호화 학생 세션과 소유 범위·proxy는 별도 시험에서 확인한다. 재현 명령은 [QA README](../../../../scripts/qa/cb-scan-ship/README.md)에 있다.

### 배포와 되돌림 — 이번 작업에서는 적용하지 않음

1. 리드가 추가 SQL/권한/트리거를 검수하고 **DB 먼저** 적용한다. 이 작업에서는 새 로컬 PGlite 외의 DB에 연결하지 않았다.
2. 앱 전용 **비공개 버킷**, 서버 Storage 자격 증명, `ANTHROPIC_API_KEY`, `CRON_SECRET`, QR의 정식 `AUTH_URL`을 준비한다. 준비 전 유료 처리 스위치는 off로 둔다.
3. `prisma generate`한 **코드를 나중에** 배포한다. 기존 Chromium 배포 자산과 새 CSS/글꼴 tracing 포함을 운영 배포에서 확인한다. 표가 없으면 사진 채점 API는 503, 기존 인쇄는 QR 없이 계속된다.
4. 원장님이 `print-check`의 `concept-blank-scan-20261125`를 실물 인쇄·폰 촬영으로 검수하고, 사람 참값으로 새 폰 사진의 읽기/의미 채점을 측정한다. 현재 status는 **대기**다.

문제가 생기면 `CONCEPT_BLANK_SCAN_ENABLED=off`로 새 유료 호출부터 막고 저장 결과 조회·사진 정리는 유지한다.
코드를 되돌리더라도 추가 표/비용 원장/사진 메타데이터는 보존한다. 신규 기록이 있는데 DROP하는 역마이그레이션은 만들지 않았다.
사용량 불명은 운영 담당자가 원장과 제공자 영수증을 대조한 뒤 별도 승인된 복구로 정산한다. 자동 TTL 해제·유료 자동 재실행·증거 삭제로 복구하지 않는다.
공유 DB 적용·실제 AI·push·운영 배포·실물 검수는 이번 출고 코드 검증에 포함하지 않았다.

### ① 동시 호출과 영속 대기열

월 원장의 `active_call_id`와 월별 running 한 개만 허용하던 인덱스를 없앴다. 입장·정산의 짧은 트랜잭션만 서비스 공용 advisory lock으로 직렬화한다. **AI 호출 동안 DB 잠금을 잡지 않는다.** 입장은 `spent + reserved + 새 예약 ≤ 월 상한`으로 결정하고, queued/running 예약을 모두 합산한다. 대기 중 같은 시도를 다시 읽어도 예약을 두 번 더하지 않는다. 월이 바뀌어도 서비스 전체 running 수를 함께 센다.

`CONCEPT_BLANK_SCAN_MAX_CONCURRENT`는 양의 정수, 기본 **4**다. 자리가 없으면 usage_call을 `queued`로 커밋하고 identity 순서의 FIFO 차례를 보존한다. 새 호출의 슬롯을 얻으면 `running`으로 바꾼다. 상한을 낮춘 뒤 이미 대기하던 요청도 실행 전에 현재 금액 상한을 다시 확인한다.

앱 작업은 대기 상태·원래 권한 주체·같은 작업 ID를 DB에 남기고, 학생 화면에는 **«차례를 기다리는 중»**을 표시한다. 이미 읽은 쪽은 건너뛴다. 진행 중 작업의 완료 후, 권한을 확인한 상태 조회 후, 그리고 `/api/concept-blank/scan/queue/cron`이 대기를 이어 받는다. cron은 기존 `CRON_SECRET`으로만 접근하며 `vercel.json`에 **매분** 일정을 추가했다. 열린 탭이 없어도 이어갈 길이다. HTTP/cron 한 번의 실행·연속 처리 전체는 **240초** 예산을 공유하고 route는 **300초**다. 이는 설계 제한이며 한 반의 실제 대기 시간을 측정한 수치가 아니다.

새 cron의 학생 접근은 닫혀 있다. `studentRouteAccess` 전수 검사의 메서드 수는 **11→12**, cron 제외 목록도 함께 갱신했다. 허용 학생 메서드 일곱은 늘리지 않았다.

### ② 실제 요청으로 계산하는 예약 상계

`reservation.ts`는 전송할 **동일 base64 이미지 바이트**를 읽어 가로·세로를 얻는다. 못 읽는 형식/치수, 여러 프레임, 과도한 입력 등으로 상계를 구하지 못하면 예약·전송 전에 실패한다. 텍스트에는 실제 읽기 함수가 만든 지시문과 답 칸 목록을 포함한다.

- 그림: `ceil(width / 28) × ceil(height / 28)`. [Anthropic Vision의 공식 계산식](https://platform.claude.com/docs/en/build-with-claude/vision#resolution-and-token-cost)과 [패딩·축소 규칙](https://platform.claude.com/docs/en/build-with-claude/vision-coordinates#how-claude-resizes-and-pads-images)을 확인하고 코드 주석에 출처를 남겼다. 제공자가 축소해 주는 절약분은 상계에서 빼지 않는다.
- 글: **UTF-8 바이트 수**. 토큰당 한 바이트 이상이라는 상계를 쓰며 글자 수/4나 과거 평균을 쓰지 않는다.
- 메시지 구조 여유: **1,024토큰**을 더한다. 이는 공식 그림 공식이나 실측값이 아니라 이 서비스의 보수적 설계 여유다. 전송 형식은 도구·시스템 프롬프트·대화 이력·스키마 없이 이미지 한 장과 사용자 글 한 블록이며, 어댑터 시험이 그 모양을 확인한다. 입력 블록을 늘리면 이 계산도 함께 바꿔야 한다.
- 출력: 실제 `max_tokens`와 같은 **16,000**. 입력/출력을 기존 고정 단가로 환산하며, 각 호출에 치수·바이트·토큰 상계(`bound`)도 저장한다.

측정은 `/tmp/cb-scan-review-20261125/request-bound.json`에 있다. `FIXTURE_BANK`의 A 형식 첫 쪽과 **1786×2526 합성 PNG**를 실제 `readScanPage`에 넣고, 모델 대역이 받은 요청을 `scanReservation`으로 계산했다. 유료 호출이나 실제 필기 사진은 사용하지 않았다.

### ③ 사용량 불명 확정 정산과 명시적 재시도

사용량이 없거나 잘못되었으면 `cost = reserved`, `status = settled`, `settlement_reason = usage-unknown`으로 확정한다. 예약 합에서는 빼고 사용액에 전액 더한다. 원래 예약액·요청/결과 식별자·토큰 근거·정산 이유·시각을 보존하며 해당 호출만 종료한다. 다른 호출과 그 달 전체를 막지 않는다. 실제 영수증이 상계를 초과한 경우에도 실제 금액을 원장에 기록한 뒤 오류를 낸다.

같은 시도 ID는 다시 호출할 수 없다. 성공 응답을 재사용할 **결과 키**와 명시적 작업 시작의 **시도 키**를 분리했다. 대기 재개는 같은 시도이고, 학생이 **«다시 시도»**를 누를 때만 새 작업/시도 ID를 만든다. 이전에 성공한 쪽·정산된 응답은 계속 재사용한다. 불명 결과는 자동 재호출하거나 성공 응답으로 재생하지 않는다.

프로세스가 사라져 finally 정산도 못 한 running 호출은 **실행 시작부터 360초**가 지난 뒤 queue 유지 작업에서 `worker-expired`로 예약 전액을 확정한다. 늦은 정산이나 반복 정리는 돈을 다시 더하거나 줄이지 못한다. 아직 실행하지 않은 취소/고아 queued 호출만 `queue-cancelled`·0원으로 종료한다. 시간만 지나 유료 예약을 무료로 푸는 방식은 쓰지 않는다. 정산 이유와 금액 관계는 DB CHECK도 확인한다.

## 운영 장애 2026-11-25

리드가 배포한 `347844c9c`에서 발행 POST는 PostgreSQL 42883(`uuid = text`), 대기열 cron은 `void` 역직렬화 오류로 실패했다. 발행 행이 생기지 않아 QR도 나오지 않았다.

- **원인:** 운영 `database.server.ts`는 Prisma 6.19.3 `$queryRawUnsafe`를 쓴다. 문자열은 TEXT, 정수는 INT8, 소수/Decimal은 NUMERIC, 객체는 JSONB로 Parse 단계에 형을 지정한다. UUID·시각처럼 보이는 문자열도 TEXT다. 기존 SQL은 문맥 추론에 의존했고, advisory lock의 void 값을 결과 열로 노출했다.
- **왜 시험이 못 잡았나:** PGlite에 형 없이 값을 전달하면 PostgreSQL이 대상 열에서 UUID·시각 등을 추론했다. 또한 PGlite는 void 결과를 받아 주지만 Prisma는 역직렬화하지 못한다. 같은 SQL·같은 마이그레이션을 쓴다는 사실만으로 드라이버 계약까지 같다고 간주한 것이 검증 공백이었다.
- **먼저 RED:** 생산 SQL을 바꾸기 전에 `paramTypes`와 void OID(2278) 거절을 넣었다. `conceptBlankScanIssue`·`conceptBlankScanQuotaReview` 두 파일에서 **8 실패·1 통과**, 실제 발행의 `uuid = text`와 원장 잠금의 void 오류가 각각 재현됐다(`/tmp/cb-scan-prod-fix-20261125/red.log`). fixture 준비 SQL만 먼저 형을 명시해 실제 서비스 호출에서 실패하도록 했다.
- **수정:** 발행·제출·사진·읽기·정정·채점·사용량·대기열·정리의 모든 SQL placeholder에 목적 형을 명시했다. UUID 식별자와 TEXT인 답 칸/판정 대상 식별자를 구분한다. 잠금은 `SELECT 1 AS locked FROM pg_advisory_xact_lock(...)`로 호출해 결과 열에 void가 없다. E2E도 같은 `openScanTestDb` 어댑터를 사용한다.
