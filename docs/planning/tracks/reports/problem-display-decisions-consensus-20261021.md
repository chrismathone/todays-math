## 3. 차례 — 이중 수정 금지

1. **렌더러**: ① 이음(U+2060) · ④ `[그림:n]` 파서 · 그림별 캡션 · ③ 제자리 배치. 시험 · 운영 빌드 · main · **운영 배포 Ready 확인**.
2. **초등 엔진 ①⑥⑨ 한 번에** → 기준(승인 층) 재생성 한 번 → 공유 DB 갱신 한 번(⑩⑪ 잠금 · 보충 포함). ⑥⑨ 는 지금 문지기가 정상적으로 거부하는 변경이다 — 문지기를 느슨하게 하지 말고 **행별 전후를 확인한 `--same-problem` 목록**을 만든다(⑥ 은 피연산자 · 연산 · 정답과 새 그림의 대응까지).
3. **교과서 DB 글 ③④** 한 묶음 — 1 의 렌더러가 운영에 나간 **뒤에** 새 표기를 쓴다.
4. **② keep-all + 높이 캐시 재측정 · 넘침 전수 전후 비교** — 맨 끝 한 번(고친 뒤 다시 재는 것은 허용).
5. **⑧** — 엔진 세션 인계 문서(`tracks/brief-engine-handoff-display-20261021.md`).

## 4. 멈출 조건 (Codex 2회차 H)

- **쓰는 순간의 대조**: 엔진 갱신(`refresh-engine-content.ts:758` 은 `where: { id }` 뿐)과 교과서 수리 도구 모두 **쓰는 순간 대상 칸이 «앞» 값과 같을 때만** 쓰고(compare-and-set), 기대 갱신 수와 다르면 그 거래를 멈춘다. 원장에는 바뀐 칸 전부와 새 id 를 남기고 되돌림도 같은 검사를 한다.
- **드라이런 = 확정 목록**: 건수만이 아니라 id 집합 · 바뀌는 칸 · 전후 내용이 확정 목록과 같아야 적용. 합의 밖의 새 unmatched · 동일성 거부를 자동 잠금으로 넓히지 않는다.
- **지면 검증 실패**: 그림 누락 · 중복, 캡션 오연결, 수 · 답 · 조건의 뜻 변경, 합의 밖 공급 감소, 되읽기 불일치, 새 잘림 · 넘침 — 하나라도 나오면 다음 단계로 안 간다.
- **SRS 학습 기록**은 이번 처분에 넣지 않는다(위 참조 0 의 한계).
- 실물 인쇄는 원장님 몫 — 브라우저 · 인쇄 매체 검증까지는 우리가 한다. 지면이 바뀌는 단계마다 `/dev/print-check` 항목.
