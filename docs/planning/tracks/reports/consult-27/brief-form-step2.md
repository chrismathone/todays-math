# 3자 협의 — 안건 2 «값은 맞고 꼴이 틀린 답» 2단계를 열 것인가 (2026-10-01, 3회전)

## 지난 합의
1회전 안건 2: **(가) 자동으로 가른다 — 기약분수 · 대분수 둘만**(2:1, 리드 초안 «먼저 센다»가 졌다).
1단계(트랙 `me-form`)는 끝나 main 에 있다: 판정 순수 함수 `answerForms.ts`(`requiredForm` · `gradeValueAndForm`) + 시험 + 읽기 전용 집계 스크립트.
**학생 화면 · 제출 경로 · 저장 꼴 · DB 는 안 바뀌었다.** 2단계 = 제출 경로에 잇기(«값 맞음 · 꼴 고쳐 쓰기» 상태 · 시도 소모 · 재시도 · 복습 간격 · 계약 변경) + 학생 문구 시안.

## 1단계가 찾은 사실 (코드 근거)
- 은행 문항은 `courseBank.ts` 에서 입력 방식이 `number` 가 아니면 **전부 뺀다**. 학생이 «스스로 채점(self-check)»을 만나는 길은 은행이 모자랄 때 채우는 **자체 생성기** 쪽에만 남아 있다(예: `g3.ts` 대분수 변환, `g5.ts` 기약분수 변환).
- 스스로 채점은 지금도 숙달을 올리지 않고 복습 간격을 1일로 둔다(`courseAutomation.ts`) — «틀린 꼴을 맞다고 눌러 기록이 오염된다»는 1회전의 걱정은 **숙달 · 간격에는 이미 막혀 있다**. 남는 피해는 «꼴이 틀렸다는 되먹임이 없다»는 것.

## 새로 잰 숫자 (오늘 main 에서 집계 — 운영 DB 은행, 학생 기록 아님)
표본: 초등 230소단원 × 고정 seed 32개 × 5문항 = **최종 세션 문항 36,800개**(학생 노출 빈도가 아니라 현행 출제기가 내는 세션의 표본).

| 최종 세션 문항 | 수 | 비율 |
|---|---|---|
| 4지선다로 보임 | 32,112 | 87.3% |
| 분수 칠하기 등 조작 | 1,032 | 2.8% |
| **스스로 채점** | **3,655** | **9.9%** |
| 직접 입력 | 1 | 0.003% |
| 그중 기약분수 · 대분수 판정이 붙을 수 있는 문항 | **5**(대분수 5, 기약분수 0) | 0.014% |

- 스스로 채점이 나오는 소단원은 **65 / 230**. 몇 소단원은 **세션 전부가 스스로 채점**이다(3-1-6-2 · 3-2-3-1 · 4-1-4-1: 160/160). 이것들의 사유는 기약분수 · 대분수가 아니다(비교 · 그리기 · 기타).
- 은행 전체(출제 자격 단답형 28,410행) 중 스스로 채점이라 빠진 것 4,859행(17.1%). 그중 **기약분수 88 · 대분수 53 = 141행**(스스로 채점의 2.9%, 은행의 0.5%) — 다섯 소단원에만 몰려 있다(3-2-4-5 대분수 53 · 5-1-4-2 기약분수 52 · 6-1-1-1 · 6-1-4-3 · 6-1-4-5 각 12).
- 즉 2단계를 다 해도 **지금 세션에서 바뀌는 문항은 36,800 중 5개**, 은행에서 되살릴 수 있는 문항은 141행이다. 나머지 스스로 채점 약 97% 는 이 안건의 두 꼴이 아니다.

## 물음
2단계(제출 경로 + 계약 + 학생 문구 시안 — 두 번 배포 · 학생 화면 변경)를 **지금** 열 것인가?

- (A) **닫는다(보류)** — 1단계(순수 함수 · 시험 · 집계)는 남기고, 숫자를 기록한다. 스스로 채점 문제는 «어느 사유가 몇 %인가»로 다시 세워 별도 안건으로.
- (B) **좁혀 연다** — 다섯 소단원의 141행만 은행에 되살리고(직접 입력 · 두 꼴 판정), 학생 문구 시안.
- (C) **그대로 연다** — 1회전 합의대로 2단계 전부.
- (D) 다른 안.

답의 틀: 첫 줄에 고른 안 한 글자. 이어서 까닭 3~6줄(위 숫자 중 무엇이 결정을 가르는지) · 1회전 합의를 뒤집는다면 그 까닭 · 빠진 사실이 있으면 무엇을 더 재야 하는지 한두 줄.
