# 서술형 지면 B 구현 보고

2026-10-20 · `phase/13-descriptive-paper` · 기준 HEAD `93449b575470c1727d2319d9fa1b1b109f50cb82`

확정 시안 **B «옅은 모눈»을 제품 렌더 경로에 구현했다.** 일일·확인은 문제 바로 아래 답란, 기출형은 문제지 뒤 별도 답안지, 교사용은 기준별 채점표를 사용한다. 개념 백지와 일반 문항의 기존 풀이 공간은 유지했다. 출제·자동 출제에서 서술형을 선택하는 배선은 이번 범위에 포함하지 않는다.

## 1. 구현한 지면

| 경로 | 학생용 | 교사용 |
| --- | --- | --- |
| 기존 일일·확인 `TestPrint` | native r2 문항 아래 B 답란. 서술형은 한 쪽을 배정하고 일반 문항의 기존 두 문항 배치를 유지 | 일반 정답·해설과 서술형 채점표 분리 |
| 기존 기출형 `PastPaperPrint` / `PastPaperTemplate` | 기존 2단 문제지 + 서술형 문항별 별도 답안지. 문제지에는 답란을 삽입하지 않음 | 일반 정답·해설 뒤 문항별 서술형 채점표 |
| 통합 인쇄 `WorksheetPrint` | 자습·정통·현대·워크북·유형은 문제 아래 답란. 평가형은 별도 답안지 | `showAnswers`일 때 기존 문제지 뒤 일반 해설·서술형 채점표. 빠른 정답만 보기에서도 채점표 유지 |

- 배점은 서술형 번호 바로 옆에 표시한다. native 문항은 `rubric.totalPoints`를 정본으로 삼는다. 기존 기출형의 일반 문항 배점도 D-163에 맞춰 숨겼고, 기출 측정 probe를 같은 마크업·스타일로 맞췄다.
- 학생 답란은 **4mm 모눈, 선색 `#e8e8eb`, 줄 예산 8mm**다. 전체형은 `기준 수 × 2줄 × 8mm`, 소문항형은 `기준 수 × 3줄 × 8mm`. 소문항형의 첫 칸 한 줄을 마지막 칸으로 옮긴다. 기준 3개는 전체형 48mm, 이번 소문항형은 **72mm = 16 + 24 + 32mm**다. 배점 비율로 칸을 나누지 않는다.
- 교사용에는 모범답안, 볼 증거, 기준별 배점·만점·부분점수·0점, **□ 11개**, 문항 소계·합계와 선행 오류 원칙을 넣었다. 실제 시연의 기준은 3개, 배점은 3·3·2점이다.
- 서술형을 일반 정답지에서 제외한 뒤에도 일반 문항 번호가 당겨지지 않도록 원래 번호를 전달한다. 학생용에는 모범답안·채점 기준이 출력되지 않는다.
- 통합 인쇄는 필기 답란을 축소하지 않는다. 한 쪽에 들어가지 않아 축소가 필요한 서술형이나 실제로 넘치는 별도 답안지·채점표는 출력 준비 완료를 내보내지 않고 안내한다. 눈에 보이지 않는 KaTeX 접근성 텍스트·SVG 정의는 넘침에서 제외하고, 표시 수식은 계속 검사한다.

## 2. 공용 답란과 자료 경계

`WritingArea`는 `grid | lines | blank`, 고정 높이·최소 높이·남은 공간 채움, 모눈 간격·줄 간격, 분할 칸과 머리표를 속성으로 받는다. 문항·채점·개념 백지의 쪽 나눔 규칙은 이 부품에 넣지 않았다. 개념 백지가 나중에 쓰더라도 현재의 늘어나는 칸과 30px 줄을 표현할 수 있다. 공용 부품 도입 자체가 개념 백지의 4mm 모눈 전환을 뜻하지 않는다.

출력 입력에 선택적 `nativeDescriptive`를 더했다. 내용은 주 저자 조립 결과 r2의 `rubric`, `requirements`, `modelAnswer`이며 저장 계약을 늘리지 않는다. 직렬화된 해설을 문자열로 분석해서 채점표를 만들지 않는다.

개발 페이지는 실제 `rectangleAuthor`를 `createNativeAuthoredTask(rectangleAuthor, 20261020, 0)`로 조립한 [고정 견본](../../../../src/app/dev/descriptive-paper/rectangleFixture.json)을 읽는다. 실제 SVG·수식을 포함하며 단순 손작성 문제로 대체하지 않았다. [견본 생성 스크립트](../../../../scripts/qa/build-descriptive-paper-fixture.ts)는 프로세스 안에서 외부 엔진 주소를 비우고 로컬 생성 경로를 사용한다. 문항 등록이나 DB 적재는 하지 않는다.

## 3. 검증

최종 브라우저 측정 결과와 파일별 SHA-256은 [measurements.json](descriptive-paper-impl-codex-20261020/measurements.json)에 기록한다. 측정 시작과 종료의 코드 해시가 다르면 검증 스크립트가 실패한다. 개발 화면만 캡처하는 검사가 아니라, 제품 렌더러가 만든 Chromium A4 PDF를 Poppler로 다시 읽고 픽셀·텍스트 경계를 검사한다.

- TDD: 공용 부품·출력 연결의 미구현 실패를 먼저 확인했다. 인쇄 검수 항목, 답란을 포함한 높이 예산, 잘못된 HTML 중첩, 수식 접근성 텍스트 오탐도 각각 실패 시험 후 수정했다.
- 관련 회귀 **46개 파일 · 585개 테스트 통과**. 일반 인쇄·개념 백지·영어·서술형 저자·스마트 여백·쪽 나눔·색상·배점 검사를 포함한다.
- 별도 기출 probe 일치 검사 7개도 통과했다. 마지막 핵심 재검사는 서술형 두 파일과 probe를 합쳐 **3개 파일 · 37개 테스트 통과**다. 중복을 제외하면 총 47개 파일·592개 테스트다.
- 저장소 전체 `npm run type-check` 통과. 개발 견본의 구형/통합 자료형 차이를 명시적 필드 변환으로 수정한 뒤 재검사했다.
- 변경 TS/TSX/MJS의 ESLint, 변경 TSX/CSS의 D-30 affordance, `git diff --check` 통과.

## 4. 개념 백지와 일반 풀이 공간 비교

근거 파일과 형식별 영향은 [전체 비교표](descriptive-paper-concept-comparison-20261020.md)에 정리했다. 현재 구현 관찰과 앞으로의 변경 예상을 구분했다.

| 항목 | 현재 개념 백지 | 서술형 B |
| --- | --- | --- |
| 답란 모양 | 30px 줄, A 그림 칸 16px 모눈, 문장 속 밑줄 등 형식별로 다름 | 4mm 모눈·선택적 소문항 분할 |
| 높이 | 참고 답·수식 길이와 남은 쪽 높이에 따라 배분 | 채점 기준 수 × 줄 수 × 8mm |
| 머리말 | 형식·목표·단원·학습일·이름/반·지면 코드 | 기존 시험지 머리, 별도 답안지/채점표 이름·반 |
| 채점 | ○/△/×, 확인할 내용·맞은 개수 | 기준별 점수·부분점수·합계·선행 오류 |

원장님 선택지는 다음 세 가지다. **권고는 1안**이며 이번에는 적용하지 않았다.

| 선택 | 효과 | 높이·쪽 수·실물 검수 |
| --- | --- | --- |
| **1. 답란만 공유** | 줄·모눈·빈 내부만 공통 부품으로 관리. 개념의 기존 높이·쪽 나눔·채점 유지 | 외곽 치수를 보존하면 배치 유지가 목표. 4mm로 바꿀 칸은 별도 선택. 적용 형식의 실물 회귀 검수 필요 |
| 2. 머리말까지 공유 | 제목·날짜·이름/반·간소 머리 틀도 공유 | 본문 가용 높이가 달라질 수 있어 다섯 형식의 쪽 나눔·코드·푸터를 재계산·재검수 |
| 3. 개념 백지는 그대로 | 서술형만 공용 부품 사용 | 이번 공유로 생기는 쪽 수 변화 없음. 기존 검수 대기는 유지 |

기존 일반 풀이 공간도 하나의 양식이 아니다. 구형 일일은 오른쪽 16px 모눈, 통합 자습은 아래 85px 높이 모눈, 워크북은 오른쪽 빈 칸, 별도 풀이는 빈칸/24px 줄/칠판이다. B의 4mm는 16px(약 4.233mm)보다 조금 촘촘하고 기존 통합 자습보다 선이 옅다. 이번에 일반 풀이 공간을 일괄 변경하지 않았다. 공유 후 쪽 수 증감이나 손글씨 적합성을 측정한 것처럼 보고하지 않는다.

## 5. 실물 검수와 작업 상태

`/dev/print-check`에 **«서술형 답란 B — 일일 · 확인 · 기출 답안지 · 교사용»**을 **대기**로 추가했다. PDF 검증이 실물 통과를 대신하지 않는다. A4 100%·배경 그래픽 켬에서 프린터/복사기 모눈 잔존, 손글씨 공간, 4mm 간격과 72mm 높이, 채점 □와 푸터를 확인해야 한다. 배경 그래픽 끔이나 실제 복사 결과는 이번에 검증하지 않았다.

긴 모든 문항·모든 기준 수가 한 쪽에 들어간다고 보장하지 않는다. 이번 교사용 한 쪽 증거는 미등록 직사각형 1문항의 3기준이다. 현재 조합은 서술형 문항별 답안지/채점표를 배정하며 통합 출력의 긴 지면은 축소 대신 차단한다.

DB·등록·적재·스테이징·커밋·푸시를 실행하지 않았다. `node_modules` 심볼릭 링크와 의존성 파일, 개념 백지 코드를 변경하지 않았다. Orca Codex 작업 두 건의 산출물을 현재 작업트리에 통합하고 작업자를 종료했다. 커밋 금지 조건상 main 병합을 하지 않았으므로, 미커밋 파일이 남아 있는 작업트리는 삭제하지 않았다.
