## 할 일
1. **교체 경로(후보 쪽 문항 ID만 읽기)와 화면 쪽 정리(단원 목록 먼저 · 받은 수 재사용)는 남긴다.**
2. **수 세기 경로(범위 수량 · 문항 추가 · 출처 고르기)는 1차 전보다 느려지면 안 된다.** 둘 중 하나:
   - (가) 두 번째 집계를 없앤다 — 애매한 문항은 첫 집계에서 «애매» 칸으로 따로 세고, 본문 판정 결과의 **차이만** 더한다. 한 번의 집계 + 애매 문항 읽기로 끝나야 한다.
   - (나) (가)로도 1차 전보다 빠르지 않으면 수 세기는 1차 전 코드로 되돌린다.
   결과 수는 1차 전 코드와 **완전히 같아야** 한다(기존 parity 시험 유지).
3. 공유 DB에 대어 **읽기만** 하는 측정 스크립트를 `scripts/qa/measure-builder-speed-live.ts` 로 남긴다. 1차 전/후를 같은 프로세스에서 번갈아 3회 재고 표를 낸다. 실행: `npx tsx --env-file=/Users/pss/Desktop/creative/today_/.env scripts/qa/measure-builder-speed-live.ts`. 쓰기 쿼리 금지, 비밀값 출력 금지. 직접 돌려서 표를 보고서에 싣는다(네트워크가 막히면 막혔다고 적는다).
4. 화면 짜임 · 문구 · 스타일은 바꾸지 않는다(D-07). DB 스키마 · 공유 DB 쓰기 · `prisma generate` 금지. 커밋 금지.
