# 문제은행과 연산대장 계획 합의 기록

2026-10-14 · 대상 [실행 계획 개정안 4](goal-bank-arithmetic-brand-20261014.md)

**Codex·Claude·Grok가 실제 검토와 수정안 재검토를 거쳐 계획에 합의했다.** Claude와 Grok의 최종 판정은 모두 `approve`다. Gemini는 실행기가 설치되어 있지 않아 참여하지 못했다. 이번 결과는 계획 합의이며 코드 구현·운영 DB 적용·배포·학습효과 검증은 아니다.

## 참여와 근거

| 참여자 | 수행 | 최종 결과 |
| --- | --- | --- |
| Codex | 기존 계획과 코드 대조, 사용자 요구 반영, 양쪽 제안 조정, 개정안 작성 | 개정안 4 채택 |
| Claude | 수량·출처 메타데이터·두 변형·문서 저장/권한·출시 조건 독립 검토, 수정안 재검토 | approve, 차단 없음 |
| Grok | 전용 연산 범위·생성/검산·유한 용량·중복·저장/정답 전용 출력 독립 검토, 수정안 재검토 | approve, 차단 없음 |
| Gemini | Orca에서 실행 시도 | 실행기 없음으로 실패. 의견·합의 없음 |

실제 Orca Run은 `run_00c3cdc517b2`다. 동일 제공자의 세션을 후속 Task로 재사용했다. 다른 모델에게 역할 이름만 붙여 검토했다고 보고하지 않았다.

- Claude 최종: Task `task_5c4e8d3750a7`, Dispatch `ctx_00b07572d104`, 메시지 `msg_3cbcdf09b976`.
- Grok 최종: Task `task_564cbc3af2cc`, Dispatch `ctx_ca9147192cd6`, 메시지 `msg_ee39ce472c80`.
- Gemini 실행 실패: Task `task_100ca3e6edff`, Dispatch `ctx_93a6875fa1aa`. 터미널에서 `gemini` 명령을 인식하지 못했고 준비 단계가 실패했다.

## 이견과 최종 결정

| 쟁점 | 검토에서 나온 차이 | 합의된 결정 |
| --- | --- | --- |
| 연산 원천 | 기존 엔진 선별 또는 전용 엔진 | 전용 `src/lib/arithmetic/`. 기존 난이도 연산은 도형/문장제까지 포함하므로 원천으로 사용하지 않음. 검증한 순수 수학·표현 부품만 재사용 |
| 첫 출시 범위 | Claude는 초·중 한 갈래씩, Grok는 정확히 정의한 초등 7스킬군 제안 | 7스킬군부터 출시. 조건별 목표 기능과 유한 용량을 검증. 분수·소수·음의 정수·혼합 계산은 확장 단계. Claude도 수용 |
| 연산 저장과 채점 | 유한 묶음을 Problem에 적재해 Test 채점에 연결하거나 별도 문서로 먼저 출시 | 별도 `arithmeticSheet` 문서에 명세와 발문·정답 스냅샷 저장. Problem/Test 자동 삽입 없음. 학생 답 채점·분석은 후속 계약으로 분리 |
| 풀이와 출력 | 초기 프롬프트에 해설 요구와 선택적 solution 표현이 남음 | 공개 연산 payload와 출력에 solution 없음. 문제지와 답만 있는 정답지. 내부 검산은 독립적으로 수행 |
| 문항 수와 중복 | 시드 수를 고유 문항 수로 오해할 수 있음 | skillId와 순서 있는 피연산자로 동일성 판단. 표기 방식은 skillId에 고정. 스킬별 domainSize 초과 시 회차 전체 거절. 회차 간 학습 반복은 허용 |
| 문제은행 숫자 | 전역 보유 수, 자격 있는 수, 필터 결과, 담긴 수가 혼용됨 | 기존 전역 count/open 의미 보존. 현재 조건 가용량은 명시적 조회 계약으로 구분. 목록·범위·랜덤 풀을 같은 조건으로 검증 |
| 교과서 찾기 | 경쟁사 책/쪽/번호 탐색을 그대로 계획 | 현재 본문 쪽 데이터가 없으므로 책→자료 단원/종류/회차→자료 안 번호. 학평 제외, 기출은 실제 데이터 셈 이후 준비된 탐색만 공개 |
| 두 변형 준비 | 준비 화면에만 fingerprint 검사를 넣으면 복습과 불일치 | 런타임은 planRetry의 source/origin/unitId/externalId/자격 술어와 동일. 원문 갱신과 변형 잠금/내용 대응 검증은 적재·갱신 도구에서 보강 |
| 원문과 변형 동시 담기 | 차단 또는 경고 허용 | 이미 연습한 변형이 복습에 다시 나올 수 있음을 경고하고 허용. 2/2는 가용 슬롯 수이며 미사용 문항 수가 아님 |
| 문서 종류와 출시 | JSON payload만 추가하면 DB CHECK에 걸림 | 문서 kind CHECK 확장→호환 읽기 배포→새 kind 쓰기 활성화. 권한·공유·문서 문항 수를 함께 검증. 새 최상위 메뉴 없이 제작기 안에 진입 |
| 브랜드와 디자인 | 표시명 변경과 디자인 선택 절차 혼동 | 오늘 수학/오늘 영어는 사용자 확정. 독립 기능명·식별자 유지. 새 화면/지면은 기존 Wire/Hi-fi와 공용 컴포넌트 절차 적용 |

## 합의의 범위

사용자의 세 가지 연산 요구를 우선 반영했다. **연산 능력 자체를 위한 문항**, **필요한 전용 엔진 신설**, **풀이 없이 답만 출력**이다. 정확성과 목표 기능 조건은 검증하지만, 학생의 학습효과나 특정 오개념 진단이 입증됐다고 표현하지 않는다.

초기 계획에서 빠진 문서 kind 마이그레이션과 원문 갱신 시 변형 처리 책임도 보강했다. 최종 판정 이후 Claude가 남긴 비차단 편집 메모에 따라 수용 시나리오 4의 “fingerprint 변경”을 “적재 도구의 원문·변형 잠금/재검증”으로 풀어 썼다. 설계 결정은 바꾸지 않았다.

실행 단계에는 실제 데이터 준비도, 구체적인 화면/지면 시안, 단위·통합·권한 시험, 인쇄 검수, 배포 확인이 남는다. 이들은 합의한 완료 기준이며 지금 완료한 것으로 기록하지 않는다. Gemini의 독립 검토도 포함되지 않았다.
