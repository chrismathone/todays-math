매쓰플랫의 목록 수치와 PDF의 묶음 문항 수는 그대로 일치하지 않았다(목록 24, 열람 PDF 번호 1~48). 서비스 내부 집계 이유는 확인하지 않았으며 우리 생성 가능 수 계약의 근거로 사용하지 않는다. 연산대장 유형 카드의 `출제율 순위`는 관찰했으나 그 집계 기간·모집단·중복 처리 방식은 공개 화면에서 확인하지 못했다. 우리 순위는 자체 사용 기록과 명시적인 집계 계약으로 만든다.

로컬 PDF/PNG는 `tmp/pdfs/arithmetic-benchmark/`에 검토용으로만 보관한다. 외부 원문·그림·장식·브랜드를 우리 카탈로그나 지면으로 복사하지 않는다. 실제 프린터 출력과 세 서비스의 전체 양식 조합 검증은 수행하지 않았다.

구조 시안 수정: 유형별 예시와 특징/순위 라벨 → 조건·수량 → 공통 출력으로 이어지는 A안을 기본 제안한다. 시안 순위는 `표시 예시`로 명시하며 운영 데이터로 보이지 않게 한다. 출력은 큰 글씨 12개/기본 24개/조밀 40개 후보를 비교하고, 최종 지원 밀도는 실제 A4 측정 후 결정한다. 정답은 별도 페이지이며 해설은 없다.

사용자는 같은 날 **Wire A(유형 카드+구성판)**, 이어 **Hi-fi 1(기존 작업실)**을 선택했다. 구조안은 `docs/design/mockups/arithmetic-wire-20261014.html`, 시각안은 `docs/design/mockups/arithmetic-hifi-20261014.html`이다. 확정한 화면으로 실제 엔진·저장·지면을 연결한다. 이후 사용자는 코덱스 내부 작업으로 기본 유형을 다수 준비하고, 웹에서 숫자를 바꾸어 즉시·반복 생성하는 흐름까지 검증하도록 추가 지시했다. 외부 유료 생성 API 없이 검증된 조건 카탈로그와 결정론적 엔진을 사용한다.

추가 관찰: 매쓰홀릭 연결 연산대장은 웹에서 유형과 수량을 정한 뒤 바로 문제지를 생성했다. 관찰한 좁은 숫자 범위의 10문항에는 같은 식 반복이 있었다. 매쓰플랫의 연산 목록에서는 기존 문제/빠른 정답 PDF 열기·인쇄·다운로드를 확인했으며, 확인한 행 메뉴에서는 숫자 재생성 동작을 찾지 못했다. 서비스 전체에 없는 기능이라는 판정은 아니다.

우리 구현은 규칙과 새 시드로 웹에서 즉시 생성하고, 유한 도메인 안에서 한 회차의 같은 식을 제외한다. 97개 중 기본 수량이 도메인 전부인 유형은 새 시드에서 순서만 바뀔 수 있고, 단일 식 유형은 그대로다. 학년 범위는 [별도 감사](arithmetic-grade-coverage-20261014.md), 실제 A4·화면·저장 연결 검증은 [구현 보고](../reports/bank-arithmetic-ui-20261014.md)에 기록한다.
