# 관리자 사용성 점검 후속 실행 계획

상태: 수정안 v02의 실제 Claude Fable 5.1·Grok 4.7 재검토 승인을 받고 구현 중이다. [합의 기록](tracks/reports/admin-usability-consensus-20261004.md)과 각 영역의 구현·검증 보고서를 남긴다. 이전 [지점 관리 고도화](admin-branch-upgrade-20261003.md)의 완료 기록은 유지한다.

## 근거와 완료 기준

- 입력: `오늘의수학_관리자_사용성_점검_20261004.docx`, `오늘의수학_관리자_점검_재현증빙_20261004.zip`. ZIP의 체크섬 15개와 시나리오 37개를 확인했다.
- 증빙 기준 커밋은 `487236f7c`, 코드 대조 기준은 `1285a24f0`. 운영 배포 버전은 확인되지 않았다. 소스상 실패 경로와 운영에서 직접 관찰된 증상을 구분한다.
- 홈 193명, SRS 323건, 진도 보류 390건은 당시 관찰값이다. 고유 학생 수·현재 미처리 건수·데이터 손실로 단정하지 않는다.
- 이미 구현된 종료 반 제외, 연결 학생 필터, 명시적 반별 계정 발급, 관리자 유형 변경, 공통 뒤로가기 버튼과 넓은 배치를 보존한다.
- 각 항목은 구현 파일, 의미 있는 검증 결과, 제한 사항으로 추적한다. 계획 보강만으로 완료 처리하지 않는다. 운영 DB·실제 계정의 변경 없이 합성 데이터와 로컬 검증을 먼저 마친다.

## 공통 계약

1. 쓰기 성공과 후속 읽기 실패를 별도 상태로 표시한다. 이미 성공한 비밀번호 변경·게시·발행을 조회 재시도로 다시 실행하지 않는다. 비밀번호는 로그·URL·증빙에 남기지 않는다.
2. 입력 변경 여부는 원본과 현재 값으로 계산한다. 화면 안 전환은 저장·버리기·계속 편집, 앱 안 링크는 검증된 onNavigate/onClickCapture 보호, 새로고침·탭 닫기는 beforeunload 기본 경고로 구분한다. 이 구분은 T02/T03·B02·B06과 교재 화면에도 적용하며, 저장 중 대상 전환과 중복 제출을 막는다.
3. 비동기 조회는 대상 ID와 요청 세대를 확인한다. 늦은 이전 반 응답, 기본값 응답, 이전 판본 내보내기 응답이 현재 선택이나 수동 입력을 덮지 않는다.
4. 복귀 URL은 허용된 내부 경로와 필요한 쿼리만 받는다. 검색·필터·페이지·선택·탭을 URL에 담고 스크롤은 안전한 동일 화면 복원으로 보존한다. 외부 URL·다른 지점 경로·민감값을 받지 않는다.
5. 학생의 학습 상태와 반 등록 행은 분리한다. 등록 행은 `(classId, studentId)`로 식별하며 공유 학습 상태 갱신이 반 이름·소유권을 바꾸지 않는다.
6. 서버의 권한·소속·동시 수정 검사·감사·발행 불변성·학생 정답 비공개 계약을 유지한다. UI 개선 때문에 메뉴 권한이나 연동 세션 검증을 우회하지 않는다.
7. 지점 연결은 원본 시스템에서 관리한다. 계정 발급은 지점 관리자 이상이 명시적으로 실행할 때만 한다. 학생 이름 ID, 등록 전화번호 끝 4자리 기본값, 기존 계정 보존과 중복 이름·번호 누락 제외 사유를 유지한다.

## 정책 결정안

- B01: 현행 중지의 보안 효과를 유지한다. 버튼을 ‘연동 계정 접근·동기화 중지’로 정확히 설명하고 영향 대상·세션 중지·복구 방법을 실행 전에 확인시킨다. ‘쓰기만 중지’로 권한을 느슨하게 바꾸지 않는다.
- B02: 원복 후 저장·취소·이동이 모두 막히는 작업 함정이므로 P1을 유지한다. 데이터 손실이 확인됐다는 뜻은 아니다.
- A06: 기존 반별 복습 엔진은 사실에 맞는 ‘개념 카드 복습(대수 6개 개념)’으로 구분하고 학년과 대상 범위를 명시한다. 과정 SRS 진입점도 안내하며 기존 이력을 삭제·재계산하지 않는다.
- C01: 초3~초6은 기본 과정 대상, 그 밖은 ‘보충학습 대상’으로 명시적으로 선택할 수 있다. 기본 ‘설정 필요’ 집계에서 대상 외 학생을 제외하고 별도 수와 필터를 제공한다. 이미 설정한 보충 계획은 유지한다.
- D03: 현재 ‘학원의 모든 학생’ 안내는 존재한다. 적용 버튼으로 명시적 저장과 적용 범위를 함께 보여주며 공통 저장 범위를 임의로 개인 설정으로 바꾸지 않는다.
- 개선 제안도 이번 실행 범위에 포함한다. D06은 기존 고급 입력을 보존하면서 선택·URL 입력·자동 계산을 추가한다. 새 권한 체계, 학생 정책 확대, SRS 엔진 교체는 포함하지 않는다.

## 실행 순서와 검증

1. Claude·Grok가 이 계획과 현행 소스를 독립 검토하고 실제 모델·검토 결과 파일을 남긴다. Codex가 의견 차이·채택 근거를 기록하고 수정안에 대해 두 검토자의 명시적 재검토 결론을 받는다. 인증/런타임 문제는 성공으로 가장하지 않고 실제 오류와 진행 가능한 경로를 기록한다.
2. 계약을 먼저 확정한 뒤 Orca 자식 워크트리로 교재, 연동·계정, SRS·복귀, 작업실을 분리한다. 공유 파일 수정은 소유자를 지정하여 순서대로 통합한다. 독립 작업을 먼저 모두 시작한다.
3. 회귀 테스트는 변경의 실패 경로에 집중한다: POST 성공/GET 실패, 두 반의 같은 학생, 입력 원복, stale async 응답, dirty navigation, 권한 최소값, 101개 반, CAS 충돌·재시도. 정답은 교사용/학생용 응답 분리 테스트를 필수로 한다.
4. 현재 테스트가 없는 404 링크를 정답으로 기대하는 사례도 수정한다. 테스트 통과만으로 실제 이동·저장 흐름이 검증됐다고 주장하지 않는다.
5. 타입·관련 테스트·빌드 후 데스크톱/모바일 브라우저로 전체 흐름을 확인한다. 로컬 main에 최신 다른 작업을 보존하며 통합한다. push 직전에 remote fetch·비교·통합·필요 재검증을 수행한다. 완료·병합·깨끗함·실행 종료가 확인된 Orca 워크트리만 정리한다.
6. 운영 반영이 필요한 migration은 변경과 로컬 검증이 끝난 뒤 대상·전제·체크섬·DB→코드 순서를 명시한다. 현재 운영 배포 여부와 코드 완료를 구분해서 보고한다.

## 독립 검토를 반영한 확정 계약 v02

아래 구체적 계약이 위 표의 짧은 문장보다 우선한다. P1은 A01/A05/A07/B01/B02/B03/T01/T02/T05이며 나머지 오류는 P2, D01~D07은 개선이다. W07의 공통 전체 페이지 조회는 복귀·검색 구현보다 먼저 통합한다.

### 교사용 정답과 교재 저장

- T01은 `textbookSectionSchema`의 선택 칸 `teacherAnswer`로 확장한다. 문항 정답과 다른 구획 자유 글이다. 빈 글은 키 생략, `null`/빈 문자열/파싱 기본값은 금지한다. 기존 JSONB `textbook_section.content`에 저장할 수 있어 새 칸/migration은 만들지 않는다. 학생용 text 블록에 넣지 않는다.
- 교사 구획 read/write, 409 `serverSection`, quickCreate, 문항 담기, 새 초안 복사, 교사용 내보내기/가져오기(copy)/보관본을 왕복 검증한다. 구획 바이트 상한과 기존 CAS·발행 잠금은 그대로다. P1 계약 문서의 허용 확장 목록도 개정한다.
- manifest의 기존 units 투영으로 값 있는 정답만 해시에 포함한다. 칸 없는 이전 파일의 digest 불변, 값 있음/한 글자 변경의 digest 변경을 독립 벡터로 검증한다. 이미 발행한 판본에는 키나 기본값을 추가하지 않는다.
- 학생용 렌더 모델·PDF·HTML·배정/학습/QR 응답은 기존 allowlist를 유지하여 표지 정답이 들어가지 않음을 검증한다. 이번 정답 칸은 교사 원고·미리보기·교사 교환 파일에 저장하며 ‘구획 정답 메모 · PDF에 인쇄되지 않음’을 표시한다. 서버 해설 PDF 조판 변경은 이번 범위에 넣지 않는다.
- T05는 개념 CAS 성공→구획 블록 연결 CAS 순서다. 부분 실패는 ‘개념 저장 완료 · 구획 연결 실패’로 알리고 원고와 conceptKey를 보존한다. 재시도는 연결만 하며 재생성하지 않는다. 블록 없는 기존 개념도 선택하여 연결할 수 있다.
- T04의 발행 성공은 재조회 전에 편집 잠금을 반영한다. GET 실패에는 재조회만 제공하며 finalize를 반복하지 않는다. T06 가져오기 오류는 판본 검수 issues와 별도 상태다. D06의 자동 해시는 교사가 확인한 내용의 해시이며 제출 때 최신 값을 몰래 읽어 채우지 않는다. 확인 뒤 내용 변경은 409로 검증한다.

### 연동 중지·복구와 발급 대상

- B01의 ‘활성화’는 mode만 바꾸고 재조정 사건을 생성하는 기존 동작이다. 복구가 끝났다고 표시하지 않는다. 이번에는 원본 control을 다시 확인(healthy, enabled, 같은 epoch, 미retired)→활성 모드 전환/재조정 접수→새 snapshot 적용/lease 갱신→연동 원인으로 정지된 계정만 재조정에 따라 복구→재로그인 순서와 단계별 결과를 제공한다. enabled는 새 서버 전제 조건으로 강화하고 false이면 활성화를 거부하는 시험을 둔다. 원본 장애, 수동 정지·삭제·폐기, epoch 불일치에서는 복구 완료를 표시하거나 풀지 않는다. retire/rebaseline의 기존 fail-closed 경계는 보존한다. 중지 대상 수는 서버가 세고 감사에는 처리 수와 식별자만 남긴다.
- A07은 외부 events 상태 응답의 errorCode 계약을 임의로 바꾸지 않는다. 관리용 읽기에서 기존 관계 충돌 감사 details(bindingId/snapshotId)에 eventId/사유/검토 ID를 연결해 보여준다. 새 migration 없이 기존 감사 저장을 사용한다. 관계 충돌과 계정 확인 대기 n건의 두 원천을 모두 설명한다. 새로 접수한 사건에는 관리용 결과 감사가 있고 과거 불명 사건은 ‘사유 미기록’으로 구분한다.
- 보관 담당자 변경은 최고관리자 전용, 대상 지점의 승인·미정지·미삭제 교사 계정만 허용한다. lockBinding 안에서 기대한 현재 담당자와 비교하고 전/후 ID를 감사에 기록한다. null→지정 및 검증된 교체를 허용하되 이미 소유자가 있는 반은 이동하지 않는다. 담당자를 못 찾은 반에 접근권을 부여한다는 영향과 원인 해결 전 재처리의 반복 실패를 실행 전에 알린다.
- B04는 비밀번호 route와 동일한 판정 함수로 capability/사유를 낸다. Eywa 인증 계정은 원본 복구 경로만, 로컬 계정에 연동 매핑이 있으면 기존 30자 복구 근거 입력·검증을 제공한다. 최고관리자/삭제 계정 차단은 유지한다.
- D07은 GET preview의 생성 가능/기존/제외 ID와 사유를 확인한 후 POST한다. 새 preview 토큰은 만들지 않는다. POST에 선택적 `studentIds`를 더해 UI는 확인한 ID만 보낸다. 서버는 현재 반의 허용 대상 중 그 부분집합만 발급하며 확인 뒤 추가된 학생을 생성하지 않는다. 빈 배열은 아무도 발급하지 않으며, 본문이 있는데 형식이 틀리면 400을 반환한다. 파싱 실패를 본문 없음으로 취급하지 않는다. 기존 본문 없는 직접 POST 호환과 기존 계정 보존을 유지한다. 비밀번호·전화번호는 preview/로그/증빙에 넣지 않는다. 일반 승인·권한 일괄 처리 전체를 이 항목 완료로 주장하지 않는다.
- B07 검증/네트워크 실패에는 비민감 근거·선택을 보존한다. version 충돌은 글을 보존하고 최신 후보를 다시 읽으며 확인 체크를 해제한다. 본인 연결용 비밀번호 입력은 실패 후에도 저장/복원하지 않는다.

### SRS 등록과 안전한 복귀

- A05 선택·강조·React key는 (classId,studentId), 공유 plan/summary/revision은 학생 단위다. 저장 후 같은 학생 모든 행의 공유 상태만 변경하고 classId/className/학년을 보존한다. 상세/저장의 optional classId는 requireOwnedStudentInClass로 검증한다. fixture는 같은 연동 학생의 서로 다른 반 등록 두 건이다. 고유 학생·설정 필요·대상 수와 등록 건수를 별도로 표시한다.
- C01은 반 학년을 DTO에 포함하고 반의 학교급을 학생 개인 값으로 덮지 않는다. 같은 학생의 등록 중 하나라도 정확한 초3~초6이면 고유 학생 집계의 기본 대상이다. 그 외는 보충/학년 확인 필요 수와 필터를 항상 보이고 숨기지 않는다. 연동에서 추정한 중1을 확인된 학년이라고 주장하지 않고 원본/반 등록 기준을 표시한다. 대상 외 학생의 기존 계획 또는 명시적 보충 설정 진입 후 계획 저장을 보충 대상으로 파생하여 새 저장 플래그 없이 기존 계획을 유지한다.
- B06은 같은 학생의 다른 반 행으로 전환하는 경우도 원고를 보존/확인한다. CoursePlanForm dirty 통지는 선택 prop으로 추가하여 학생용 화면을 변경하지 않는다. 화면 안 전환은 저장/버리기/계속 편집, 앱 안 링크는 검증된 onNavigate/onClickCapture 보호, 새로고침·탭 닫기는 beforeunload 기본 경고로 구분한다. 저장 중 대상 전환을 막는다.
- A01 실제 도착지는 교사 /classes/manage, 원장·지점 관리자 /branch?tab=classes, 최고관리자의 허용된 반 관리 화면이다. 도착지에서 반·학생 선택과 권한을 다시 검사한다. /classes/manage redirect도 선택을 보존한다.
- A02는 허용 키 q/status/page/tab/selection을 URL에 두고 동일 지점 고정 경로로 복귀 링크를 구성한다. A01/A03 셸 복귀는 from=admin-srs/workspace-srs/teaching 등 열거 맥락과 선택 ID로 표현하며 자유 외부 경로를 받지 않는다. 기존 내부 return helper가 필요하면 화면별 allowlist·동일 지점·허용 query/hash 검증을 모두 적용한다. 검색어는 이름/이메일을 포함할 수 있지만 비밀번호·복구 근거·토큰을 query에 넣지 않는다. 앱 감사는 쿼리를 기록하지 않는다. scroll은 정규화된 동일 화면 키에만 저장·복원한다.
- useSearchParams의 정적 경로에는 Suspense 또는 서버 searchParams(Promise) props를 사용한다. history.replaceState를 통한 입력 상태 갱신은 기존 hash를 유지한다. A04 헤더는 최고관리자에게만 지점/SRS 메뉴를 보이고 지점 관리자는 자기 /branch로 복귀하며 기존 화면 진입 권한을 넓히지 않는다.

### 작업실 조회와 결과 상태

- A08은 반/단원 첫 응답으로 수업 목록을 점진 표시하고 반별 진도/제안 실패를 해당 반에 격리한다. 진도 요청은 제한된 동시 실행이며 실패한 반은 읽기만 재시도한다. 첫 반 목록 표시가 반 수만큼의 진도 응답을 기다리지 않는지 지연 fixture로 확인한다. 반복 측정 전 목표 시간을 주장하지 않는다.
- B05 teaching 단독 계정의 tests/metrics 요청은 0회다. 권한 capability에 따라 DailyReviewSection/시험 링크/통계를 제공하고 없거나 실패한 값은 0건·0%로 가장하지 않는다. 권한 있는 부가 조회 실패에도 핵심 수업 화면은 유지한다.
- W07은 기존 fetchClasses 공통 함수를 전체 페이지 조회로 바꿔 출제 설정/수업 진행/반 관리/BasketPanel/OnboardingForm 다섯 소비처가 사용한다. 학생 목록도 현재 반 전체 페이지를 읽는다. 요청 반이 없으면 안내하며 다른 반으로 대체하지 않는다. 시험 목록의 100건 제한 전체 개편은 이 항목의 완료 범위가 아니다.
- A09는 kstDateOf 한 곳을 써서 상단/시행일/바구니 기본일/인쇄 머리 날짜를 맞춘다. UTC 서버와 한국 브라우저, 여러 브라우저 시간대의 KST 자정 전후를 검증하며 SSR/hydration 불일치를 확인한다.
- W02 학생 비우기는 selectClass에서 동기로 한다. W03 수동 범위 보호는 같은 반/학생 키에서만 적용하며 반·학생이 바뀌면 범위를 비우는 기존 안전 규칙을 유지한다. 명단 응답이 수동 범위를 지우는 연쇄도 테스트한다. W01은 서버 계산 단일 행만 갱신하여 현재 검수 목록을 재정렬/제거하지 않는다.
- B03/T04/W08 결과는 성공·명시적 실패·응답 유실로 불명을 구분한다. 성공/GET 실패에는 읽기만 재시도한다. 비밀번호 POST 응답 유실에는 최신 변경 상태를 확인하는 안내와 명시적인 새 재발급을 구분하며 자동 POST 재시도하지 않는다. 성공 후 GET이 끝나기 전 stale updatedAt으로 다른 계정 변경을 제출하지 않고 최신 조회 필요 사유를 보여준다.

### 디자인 위임과 검증 범위

사용자의 ‘Claude와 Grok과 함께 계획서 보강하고 진행’과 기존 관리자 고도화의 배치 검토 위임을 근거로, 기존 버튼·패널·필터·dialog·텍스트 토큰 안에서 세 모델이 화면 구성을 결정한다. 새로운 시각 정체성이나 학생 인쇄 지면을 만들지 않는다. A07/B01/C01/D01/D02/D03/D05/D06/D07/T06의 새 단계는 기존 확정 컴포넌트로 구현하고 데스크톱/모바일·키보드 시안을 검증한다. T01은 PDF 지면 변경을 하지 않는다. 문구는 D-08의 사무적 기준을 따른다.
