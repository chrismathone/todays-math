## 4. 🔴 «답 9,785» 는 믿을 수 없는 숫자였다 — 표본을 읽고 찾은 결함

첫 판은 답이 붙은 문항을 9,785 로 셌고, 무작위 표본 27개를 직접 풀어 전부 맞았다. 그런데 **본문을 읽으니** 틀린 문항이 나왔다.
넷 다 «글은 멀쩡해 보이는데 틀린 문항»을 만든다 — 번호와 답의 짝은 맞고 **본문이 다른 문항의 것**이라, 답만 맞춰 보는 표본으로는 안 보인다.

1. **소단원 제목을 문항 번호로 읽었다** — «02 등차수열» 이 2번 문항이 되고, 뒤따르는 01 · 02 가 그 본문으로 들어갔다. 답은 2번 것만 붙는다.
2. **발문 아래에 띄워 둔 자료 표가 앞 문항에 붙었다** — 표가 발문 문단의 맨 앞 run 에 매여 있고 자리만 «문단 아래»다. XML 차례로 읽으면
   표가 발문보다 먼저 나와 앞 문항의 끝에 붙고, 제 문항은 자료 없이 «다음은 … 나타낸 것이다. 중앙값은?» 만 남는다.
3. **두 단 표의 문항이 가로로 읽혔다** — 01 · 03 · 02 · 04. 03 이 01 의 본문이 된다.
4. **번호가 1로 돌아갔을 때 물음이 몇 줄 뒤면 «정답 칸»으로 읽었다** — 뒤 묶음의 **문항 글을 답으로** 붙였다(비상 «문제 NOTE» 의 답 19개가 전부 다른 문항의 본문).

고친 뒤: 문항 20,951 → 25,066 · 답 붙음 9,785 → 12,675. 그리고 고치다 하나를 새로 냈다 — 뜬 개체의 세로 자리가 **부호 없는 32비트로 적힌 음수**
(`4294967240` = −56)인데 그대로 «아주 아래»로 읽어, 번호 상자가 발문 뒤로 밀렸다(미래엔 «단원평가»). 이것은 **시범 검토자가 짚었다**.

수식에도 하나 있었다 — **한글 수식의 첨자는 띄어쓰기까지다**(`x^m+n` = x^{m+n} · `{}_n-1 {rm P}_r-1` · `a_ij`). 변환 정본은 첫 토큰만 올려
`x^{m}+n` 을 낸다. KaTeX 는 초록이고 식은 틀린다. 수식 372,942개 가운데 2,900여 자리 — 변환 앞에서 그 몫을 중괄호로 묶는다(`prepare.brace_scripts`).

→ 그래서 **싣기 전에 전부 풀어서 맞춰 본다**(§5). 답만 맞는지가 아니라, 본문만 보고 푼 답이 출판사 정답과 같은지를.

## 5. 검토 — 정답을 안 보여 주고 풀게 한다

검토자(구독 모델 · Sonnet)는 문항 묶음과 그 과목의 차시 목록만 받는다. 정답 · 풀이는 다른 폴더(`key/`)에 있고 열지 않는다.
문항마다: 실을 수 있나(그림 없이 풀리나 · 글이 깨지지 않았나) · **직접 푼 답** · 차시 · 유형(계산/개념/활용) · 난이도 여섯 · 형식 · (필요하면) 해설.
`collect.py` 가 그 답을 출판사 정답과 **표기를 접어** 대조한다 — 값이 다르면 다르다고 한다(같아 보이는데 다른 것을 같다고 하지 않는다).

| 판정 | 뜻 | 다음 |
|---|---|---|
| match | 검토자의 답 = 출판사 정답 | 싣는다 |
| differ | 둘 다 답이 있는데 다르다 | 둘째 검토(같은 값의 다른 표기인가 · 누가 틀렸나) → 그래도 다르면 보류 |
| not-ok | 그림 · 표 없이는 못 푼다 · 글이 깨졌다 · 붙은 문항 | 보류(그림 단계로 넘기거나 버린다) |
| no-answer | 검토자가 못 풀었다 | 보류 |

해설: 교과서 해설이 있으면 그것을 쓴다(`solutionSource = original`). 없거나 답만 적혀 있으면 검토자가 쓴 것(`ai`) — 검토자의 답이 출판사 정답과 같을 때만.
