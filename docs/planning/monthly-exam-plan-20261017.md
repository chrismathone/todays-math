## 2. 지금 우리 — 데이터에서 본 틈 (코드로 확인 · codex 검산)

- 작업실 시험지는 `workspace_document` 의 JSON 이고, ID 목록이 아니라 **본문 · 정답 · 해설 · 그림을 든 `problems[]` 전체**다(`src/components/unified/draftStore.ts:24`).
  시험지 만들기가 은행에서 고른 문항은 `Problem.id` 를 유지한다(`src/lib/unifiedBankSelection.ts:290`). 🔴 직접 가져와 **편집한 문항은 은행 행과 묶이지 않는다**(`studioHelpers.ts:225`).
- 반 시험은 `test` · `test_problem` · `test_result` 다. `test_type` 은 `daily` · `review` 둘뿐이고(`common.contract.ts:73`) 끝 단원이 필수다.
  바구니 경로는 문항 단원의 양끝으로 범위를 잡아 `review` 로 저장한다(`src/app/api/basket/test/route.ts:123`) — 🔴 그런데 `review` 는 **다음 확인테스트의 기본 범위**
  (`api/tests/default-range/route.ts:105`)와 **아침 자동 초안**(`runAutoDraft.ts:183`)이 읽는다. 월말평가를 `review` 로 넣으면 진도의 뜻이 어긋난다.
- **배점은 이미 쓰인다**: 채점은 `test_problem.score` → `Problem.score` → `100 / 문항 수` 차례로 배점을 정하고, 서술형은 입력 비율 × 배점이다
  (`src/lib/testResults/gradeAnswers.ts:84` · `gradeSheet.ts:240`). 예측 시험지가 이 칸을 쓴다(`persistPredictedPaper.ts:141`). 판독기 쪽에는 100점 검증 · 0 ~ 100 제한이 있다
  (`scoreNormalizer.ts:420` · `predictStudentScore.ts:85`).
- 재시험은 고정본이 아니라 **지금 은행의 원문**을 읽는다(`planTestRetry.ts:76`). 교과서 스냅샷(`snapshot_id`)은 교재 재출제 경로에서만 붙는다(`textbook/server/reissue.ts:167`).
- 그래서 «작업실에서 만든 월말평가»는 지금 **채점 · 재시험 · 기록으로 갈 길이 없다** — 가장 큰 틈이다(두 서비스 모두 «만든 학습지 = 채점 단위 = 오답의 원천»).

## 3. 목표 — 원장님의 월말평가 하루

```
작업실 «시험지 만들기»            반에 내기                       인쇄                      채점 · 재시험 · 기록
범위 · 개수 · 형식 · 배점  ──▶  반(들) · 날짜 · 고정  ──▶  문제지 · 정답지 · OMR  ──▶  채점표 → 재시험 → A4 한 장
(지금 있음 + M2 · M3)           (M1 · 새 길)                (M4 · OMR)                 (반 시험의 것을 그대로 · M5 리포트)
```

원칙: **새 채점 화면을 만들지 않는다** — 반 시험의 채점표 · 재시험을 그대로 쓰고, 작업실 시험지를 그 단위로 «낸다».

## 4. 단계 (M1 ~ M5)

각 단계의 순서: 계약 · DB 초안 → (DB 가 바뀌면) 원장님 승인 · 드라이런 · 적용 → 코드 → 화면은 D-07 → 인쇄는 실물 검수.

### M1 — 작업실 시험지를 «반에 내기» (가장 먼저 · 가장 큰 갭)

두 설계 가운데 고른다(codex 검산 · Claude 추천 **B**).

| 안                   | 무엇                                                                                                                              | 대가                                                                                                                                                                                                                                                    |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A — `test` 를 넓힌다 | 바구니 경로처럼 `test` + `test_problem` 을 만든다. 종류 enum 에 `monthly` 를 더한다                                               | enum 은 DB 추가 → 그 값을 아는 코드 배포 → 새 값 쓰기의 세 단계(계약 `common.contract.ts:73` · 메인 화면 `lib/main/pipeline.ts:66` 이 `daily` 밖을 범위형으로 본다). `review` 로 넣으면 확인테스트 범위 · 자동 초안이 틀어진다. 편집 문항은 담지 못한다 |
| **B — 따로 «발행»**  | 낸 시험지를 새 표에 **고정**한다(문항 글 · 정답 · 배점 · 대상 반 · 시험일). 채점은 지금 채점 함수 · 채점표를 어댑터로 그대로 쓴다 | 새 표 · 어댑터가 필요하다. 대신 `test` 의 진도 뜻을 건드리지 않고, 편집 문항 · 잠긴 교과서 문항도 «낸 그대로» 채점 · 재시험할 수 있다                                                                                                                   |

- 어느 안이든: **낸 시험지는 고정**(매쓰플랫의 «복제 후 수정»). 작업실 원본은 계속 고칠 수 있고, 다시 내면 새 시험이다. 반 여럿에 한 번에 낸다.
- 재시험은 B 에서 «낸 그대로의 글»을 원천으로 삼아야 한다 — 지금 재시험은 은행 원문을 읽는다(`planTestRetry.ts:76`). 잠긴 교과서 문항은 재출제가 거부된다(`reissue.ts:118`) — 유사문항 재시험의 원천을 정한다.
- 시험: 채점표가 뜨고 결시 · 미채점이 그대로 담긴다 · 다른 지점의 반에는 낼 수 없다 · 다음 확인테스트 범위 · 아침 초안이 바뀌지 않는다(짝 시험).

### M2 — 배점

- 문항별 배점 입력 · 총점 표기(지면 머리와 문항 옆) · «객관식 n점 · 서술형 m점으로 100 맞추기» 한 번 누르기. 저장은 작업실 시험지 JSON → 발행 때 고정.
- 채점은 이미 배점을 읽는다(`gradeAnswers.ts:84` — 문항 배점 → 은행 배점 → 100 / 문항 수). 새 셈을 짓지 않고 그 차례에 «발행본의 배점»을 넣는다.
- 판독기 쪽의 100점 검증 · 0 ~ 100 제한(`scoreNormalizer.ts:420` · `predictStudentScore.ts:85`)에 월말평가가 섞이지 않게 한다.
- 총점이 100 이 아니어도 막지 않는다 — 표시만 한다(원장님 확인 필요 · 매쓰플랫은 서술형 채점에서 100 을 강제).

### M3 — 구성 조건 보강

- **형식별 개수**(객관식 · 단답 · 서술형) — 지금 세기만 하는 값을 «구성 조건» 창의 조건으로.
- **난이도 단계 고르면 개수 자동 채움**(매쓰홀릭식) — 결과는 지금처럼 개수로 보이고 손으로 고칠 수 있다.
- **«객관식 위로» 정렬** — 순서 바꾸기에 정렬 하나.
- 문제은행 재료가 모자라면 지금처럼 «부족» 표시(조용히 줄이지 않는다).

### M4 — OMR 답안지 인쇄

- 인쇄 옵션에 «OMR 답안지» 한 장(학원명 · 이름 · 번호 · 객관식 칸 · 서술형 칸). 🔴 새 지면이라 D-07 시안 → 실물 프린터 검수.
- **스캔 채점(사진으로 읽기)은 보류** — 후보로만 둔다. 오늘의 영어 «사진에서 글 읽기»(D-158)의 길이 있지만 값 · 개인정보 · 정확도 측정이 먼저다.

### M5 — 결과 → A4 한 장 (23번 문서와 합류)

- 월말평가는 23번 리포트의 «시험 결과» 칸의 원천이 된다. 리포트 화면 · 지면은 23번의 Wire(원장 화면 + 학부모 A4)를 따른다 — 이 계획서가 따로 짓지 않는다.
- 한 회차로 단원 그래프 · 정답률 표를 그리지 않는다(23번 §4 — 표본이 작다). 틀린 문항 · 재시험 결과 · 원장님 문장.

### 따로 — 고등

- 고등 배선은 main 밖(`high-wiring` 가지 · 공유 DB 미적재)이고 원장님 결정이 남아 있다(10-handoff §0-ZU). 월말평가 계획과 따로 결정한다.

## 6. 원장님께 여쭐 것

1. **순서** — 추천: M1(반에 내기) → M2(배점) → M3(구성 조건) → M4(OMR) → M5(리포트, 23번과 함께). M1 없이 M2 · M3 만 하면 «더 좋은 시험지를 만들지만 기록은 안 남는» 상태다.
2. **M1 의 설계** — B(따로 발행 · 낸 그대로 고정 · 지금 채점표 재사용, 추천) / A(`test` 를 넓힘).
3. **시험 종류 이름** — `월말평가` 하나를 더할지, 「시험」으로 넓게 둘지(단원평가 · 내신 대비도 같은 길).
4. **낸 시험지 고정** — 채점이 시작되면 문항을 못 바꾸고 «복제 후 수정»(추천).
5. **총점 100** — 맞추기 단추만 두고 강제하지 않음(추천) / 강제.
6. **OMR** — 이번에 인쇄만(추천) / 스캔 채점까지 검토.
7. **고등** — 월말평가에 고등이 필요한 시기.

## 7. 위험 · 순서

- M1 은 새 표(B) 또는 `test` 의 꼴(A)을 바꾼다 — **DB 먼저 · 코드 나중**. A 의 enum 은 못 빼고 세 단계로 나눠 낸다.
- 작업실 시험지의 문항이 그 뒤 잠기거나(교과서 문항의 `direct_use_allowed`) 은행에서 바뀌어도 — B 는 «낸 그대로»를 들고 있어 채점이 흔들리지 않는다. 재시험의 유사문항 원천은 따로 정한다.
- 지면을 바꾸는 단계(M2 배점 표기 · M4 OMR)는 실물 검수까지가 완료다.

## 9. M1 구현 설계 (2026-10-17 · 원장님 «진행» — Wire B · Hi-fi H3 · codex 설계 검토)

정해진 것: 내는 자리 **«내 시험지» 표**(Hi-fi **H3** — 표 위 «채점이 남은 시험» 띠 · 줄마다 «반에 내기» 글자 단추 · «N개 반에 냄» 딱지) ·
시험 종류 월말평가(기본) · 단원평가 · 내신 대비 · 기타 · 시험일 기본 오늘 · 반 여럿 한 번에 · 학생 개인 내기 없음 · 채점 시작 전에만 지울 수 있음 · 낸 시험지는 고정.

### 9.1 모양 — 발행본 하나 + 반마다 반 시험(`test`) 한 행

- 낼 때 **발행본**(`exam_publication`)을 하나 만들어 문항의 글 · 정답 · 해설 · 그림 참조 · 배점 · 차례 · 출력 설정을 **낸 그대로** JSON 으로 묶는다.
- 반마다 지금의 반 시험(`test`) 한 행 + `test_problem` 을 만들고 `test.publication_id` 로 발행본에 잇는다 → 채점표 · 결과 · 분석 저장은 **지금 그대로**(`problem_answer` 가 은행 문항을 외래 키로 요구하므로 이 길이 가장 많이 재사용한다).
- 🔴 `publication_id` 가 있는 반 시험은 **«일반 시험» 조회에서 뺀다** — 확인테스트 기본 범위 · 아침 자동 초안 · 메인 · 지표 · 최근 출제 빼기 · 사용 표시 · 관리 학생 상태(codex 전수 — 아래 9.4). 소유 · 채점 헬퍼에서는 빼지 않는다(빼면 발행 시험을 채점할 수 없다).
- 범위 칸(`range_end_unit_id` 필수)은 **문항들의 단원 양끝**으로 채운다(바구니 경로와 같은 셈) — 칸을 nullable 로 바꾸지 않는다(읽는 곳의 형이 전부 흔들린다). 그 범위는 위의 «일반 시험» 조회에서 빠지므로 다음 확인테스트 범위를 바꾸지 않는다.
- `test_type` enum 은 늘리지 않는다 — 종류(월말평가 등)는 발행본의 글자 칸(CHECK)이다. 반 시험 행은 호환용 `review` 로 둔다.

### 9.2 M1 이 받지 않는 것 (명시)

- **은행에 없는 문항**(직접 가져와 편집한 문항 — id 가 crop id)은 낼 때 **문항 번호를 모두 알려 주고 거절**한다(조용히 채점에서 빼지 않는다). 같은 은행 문항이 두 번 든 시험지도 거절한다(채점이 문항 id 로 가른다).
- 은행 id 가 있는데 글을 고친 문항은 **고친 글 그대로 고정**한다 — 은행 원문으로 덮지 않는다. 그 문항의 지면 · 재시험 «그대로»는 고정본을 읽는다(지금 재시험은 은행을 다시 읽는다 — `planTestRetry.ts:76`).
- 학생 명단은 고정하지 않는다 — 지금 반 시험처럼 **채점할 때의 반 명단**이다(반을 옮긴 학생은 지금 시험과 같게 처리된다).
- 그림은 지금처럼 공개 그림 저장소의 참조로 고정한다(바이트를 따로 보관하지 않는다).
- 판독기 예상 점수는 지금 채점 저장이 늘 적는다 — 발행 시험 화면에서 보이지 않게 할 뿐 저장 칸은 그대로다.

### 9.3 DB 변경 (공유 DB — 원장님 승인 대상 · DB 먼저)

```sql
CREATE TABLE "exam_publication" (
  "id" UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  "user_id" UUID NOT NULL REFERENCES "user"("id") ON DELETE CASCADE,
  "branch_id" UUID REFERENCES "branch"("id") ON DELETE SET NULL,
  "document_id" VARCHAR(100) NOT NULL,          -- 원본 «내 시험지»(지워져도 발행본은 남는다)
  "source_revision" INTEGER NOT NULL,
  "title" VARCHAR(200) NOT NULL,
  "exam_type" VARCHAR(20) NOT NULL DEFAULT 'monthly' CHECK ("exam_type" IN ('monthly','unit','school','other')),
  "test_date" DATE NOT NULL,
  "payload" JSONB NOT NULL,                      -- 고정본: 문항 · 배점 · 차례 · 출력 설정 (스키마 판 포함)
  "content_hash" CHAR(64) NOT NULL,
  "request_id" UUID NOT NULL,                    -- 재전송 멱등
  "created_at" TIMESTAMP(3) NOT NULL DEFAULT CURRENT_TIMESTAMP,
  UNIQUE ("user_id", "request_id")
);
CREATE INDEX ON "exam_publication" ("user_id", "document_id", "created_at" DESC);
ALTER TABLE "test" ADD COLUMN "publication_id" UUID REFERENCES "exam_publication"("id") ON DELETE RESTRICT;
CREATE UNIQUE INDEX "test_publication_class_key" ON "test" ("publication_id", "class_id") WHERE "publication_id" IS NOT NULL;
-- 새 표는 RLS 켜고 브라우저 역할(anon · authenticated) 권한 회수 — 서버만 읽고 쓴다.
```

- 지금 코드는 새 칸 · 새 표를 모른다 — 넓히기만 해서 **먼저 적용해도 지금 배포가 깨지지 않는다.** 되돌림: 발행본이 하나라도 생기면 표를 지우지 않는다.

### 10.3 연구가 말하는 것

- **숫자 옆에 해석 문장** — 부모가 숫자를 풀게 하지 않는다. 오차 · 한계는 말로(Kannan 외 2021 — 부모 196명, 오차 정보를 넣으면 더 잘 이해하고 원했다) [연구].
- **백분위 · 학년 환산은 오독된다**(«65 백분위 = 65점») · 부모는 **색 하나로 잘함/못함을 빨리 가른다**(«우리 아이에게 빨강을 쓰지 마라») [연구].
- **피드백은 «다음 할 일»이 가장 효과가 크다**(Hattie 외 2021) · 주의가 과제에서 «나»로 옮기면 해롭다(Kluger & DeNisi — 1/3 넘는 사례에서 성과가 떨어짐) · **점수를 붙이면 코멘트 효과가 사라진다**(Butler 1988 — 하위권에서 특히) [연구].
- **등수를 알려 주면 만족은 오르고 성적은 떨어졌다**(Azmat 외 2016 무작위 실험) [연구].
- 한국: 학원이 동의 없이 성적을 광고하지 못하게 지도(서울교육청 2014) · 성적 유출 과태료(2023) — 성적은 개인정보다.
