### 10.1 무엇이 문제였나

- **절반 넘게는 문항이 아니라 형식 하나의 문제다.** 개념 한 장이 형식 넷에 같이 쓰이는데 형식마다 학생에게 찍히는 칸이 다르다 —
  A 는 소단원 이름만, B 는 **용어만**, C 는 **뜻 문장만**, D 는 **용어 + 예 물음만**. 은행 3차가 «난이도별 10개씩»을 채우느라 더한 개념의
  상당수가 «일반 제목 + 구체 계산 한 문장»(«단위가 있는 곱» → `$4\,\mathrm{m}$의 $0.3$배는 {$1.2\,\mathrm{m}$}이다.`)이라, C 로는 멀쩡하지만
  B 에서는 제목만 보고 숨은 수치를 써야 했고 채점 안내는 «굵은 핵심어가 다 들어가야 ○»였다.
  외부 검토의 개념 의견 1,957건 가운데 1,191건이 «원문 뜻 문장을 빈칸으로 찍어라»(= 이미 있는 C)였다.

### 10.2 합의한 방침 (요지 — 표는 합의문)

| 안건 | 방침 |
|---|---|
| 형식 문제 | 채점 안내를 고친다(«굵은 부분의 뜻이 모두 있어야 ○. 말 · 식 · 단위의 꼴이 달라도 된다») + **용어 칸에 조건을 싣는다**(«$4\,\mathrm{m}$의 $0.3$배 구하기») — 뜻 문장은 그대로라 C 지면이 안 바뀐다. 40자를 넘길 때만 뜻 문장을 일반 진술로 |
| A(완전 백지) | **사례 문항은 A 채점표에 싣지 않는다** — 굵은 답이 용어에 주어진 값으로 정해지는 카드에 표지를 단다(계약 `givenCase` · 보강 파일은 줄 끝 `CASE` · 원래 파일은 파일 끝 `markGivenCases`). 수 자체가 개념인 카드(단위 환산 · 자리값)는 달지 않는다. 줄이 줄어도 채우지 않는다. 화면의 A 최대 문항 수도 표지를 뺀 수다 |
| 굵은 글이 용어뿐인 개념 | 핵심어 표기를 늘리지 않는다. 이름 대기 문장(`…을 {세로셈}이라 한다`)은 두고 B · D 채점 안내가 가른다(«굵은 글이 용어와 같으면 그 이름은 답이 아니다 …» — 그런 줄이 있는 채점표에만). 답이 새는 문장은 빈칸을 옮긴다 |
| 범위 | 핵심어에 숫자가 든 개념 4,317개 전수 판정 — «용어만 보고 굵은 핵심어를 **하나로** 정할 수 있으면 둔다» |
| 예(D) | 80자 안이면 조건을 예 물음에 다시 쓴다. 넘치면 뜻이 보편 진술일 때만 예를 뺀다. 초3 처음 은행의 예 56개는 전부 새로 쓴다 |
| 조건을 붙이는 선 | 문항의 수 · 그림 안에서 반례가 생기거나 ○× 가 갈리면 붙인다. 학년 정의가 이미 막으면 안 붙인다(각기둥 = 직각기둥 · 공정한 주사위 · 0 이 아닌 수로 나눈다) |
| 난이도 | 초4 · 초6 처음 은행은 적용 전부 «상» · ○× 전부 «중»(소단원당 하나) — **이번에는 안 건드린다**(수행 자료 없이 다시 매기면 «10개씩»이 검토자 취향으로 깨진다) |
| 후보 · 선택 개선 | 전부 원문과 대조해 고침 / 둠(까닭)을 원장에 남긴다 — 필수가 먼저 |
| 그림 «금색» | 색 말고 단서가 없는 것만 — 획(굵게 · 점선)과 물음 말을 같이 바꾼다 |

### 11.2 방침 (요지 — 표결과 «리드가 틀린 곳»은 합의문)

- **가르는 물음**: «정답으로 인정받으려면 어떤 개념 근거를 드러내야 하는가» — 계산값 · ○× 표시 · 외운 절차만으로 정답이 다 채워지면 계산형이다.
- 개념의 사례 카드 → **성립 조건을 쓴 보편 진술**(용어는 개념의 이름 · 굵은 글은 뜻의 알맹이) + **예**(방법 · 오개념 · 경계 카드는 꼭 — 예도 계산형이면 안 된다). 사례 표지를 뗀다 —
  A(완전 백지) 채점표에 다시 실린다(§10.4 결정 ①이 여기서 풀린다). 참인 보편 문장을 못 쓰면 뺀다.
  🔴 **예의 답은 빈칸 하나에 드는 짧은 구다**(보이는 폭 15.4em — 한글 열다섯 자쯤). D 지면은 예 물음 뒤에 빈칸 하나(최대 240px)만 준다.
  리드가 시범의 예를 «…이기 때문이다» 문장으로 썼다가 지면 자(`ink.spec`)에서 드러났고, 그사이 트랙 넷이 25개를 넘게 썼다 — 은행 시험이 잠근다
  (`every map example answer fits the blank the sheet gives it` · 전부터 넘던 다섯은 줄기만 하는 목록). 예 칸을 줄 칸으로 넓히는 것은 지면 꼴을 바꾸는 일이라 하지 않았다.
  🔴 **핵심어 `{ }` 도 빈칸 하나에 든다**(같은 15.4em) — 트랙이 까닭 절을 통째로 감싸 C 지면 빈칸보다 긴 핵심어가 202개가 됐다(처음 은행 32 · 초6 107).
  지면 자(`ink.spec`)가 «어림이 1.5em 넓다»로 울어 드러났다. 은행 시험은 학년마다 줄기만 하는 상한으로 잠그고 트랙이 줄인다(끝은 0).
  **원장 줄 밖 카드의 예는 이번 범위가 아니다** — 은행의 예 2,970개(중1 1,213 · 중2 694 · 초5 573 …)는 대부분 뜻을 사례에 대어 보는 짧은 물음(«$13$의 약수를 모두 쓰면?»)이고 codex 는 이것도
  계산형이라 짚는다(중1 첫 소단원 34건 중 20건). 그대로 두고 트랙이 수만 적는다 — 넓힐지는 원장님 결정.
- 적용 → **결론 + 근거인 한 문장**. 값뿐인 답은 «수 자체가 개념»일 때만 남는다.
- ○× → **문장이 계산 한 번으로 갈리면 다시 쓴다**(흔한 오개념을 적은 문장이 가장 좋다). 수는 자리의 뜻 · 오개념의 장면일 때만.
- **되풀이 = 같은 판단 + 같은 근거를 수만 바꿔 요구.** 먼저 채워 보고, 같은 말밖에 안 남으면 뺀다(`RETIRED`). 하한은 없다(시험은 칸이 비지 않게 1) —
  3장 아래 · 절반 넘게 뺀 칸은 트랙이 보고한다. «소단원마다 10개씩» 시험은 **까닭을 적고 뺀 자리만큼** 봐준다. 앞 학년 개념으로 칸을 채우지 않는다.
- 난이도 딱지는 그대로 두고 그 딱지에 맞게 쓴다(물음의 종류가 난이도가 아니다). 문항 id · 소단원도 그대로. 계약은 안 바꾼다.
- 🔴 가장 큰 함정은 **조건 없는 일반화**다 — 리드의 첫 시범에서 보편 진술 넷이 반례에 깨졌다(«십의 자리 곱의 앞 숫자가 백의 자리 숫자» — $39\times9=351$). 문장을 쓴 뒤 반례 후보
  ($0$ · $1$ · 올림이 두 자리에서 같이 있는 경우 · 식은 다른데 값이 같은 경우)를 넣어 본다.

월 상한 기본은 $100이다. **출고 합의는 P1 · C1(교사는 첫 촬영 전 학생 선택) · V3 외형/공개 전 수정 · 학생 R2/교사 R4**다.
Hi-fi 네 안 중 **H1 «기록의 여백»**을 선택했고 `/dev/concept-blank-scan-hifi`에 비교안을 보존했다.
선택·버린 이유와 검증의 정본은 [cb-scan-ship 보고서](tracks/reports/cb-scan-ship.md)다.

### 13.2 측정 근거와 범위

[cb-scan-read](tracks/reports/cb-scan-read.md)의 후보 58칸 × 3회에서 Opus high 통째/원색2526은
맞게 읽음 169/174, 확신 오독 0, 못 읽음 5, 중앙 10.06초, 고정 단가 환산 $0.0402/쪽이었다.
전체 85칸 중 27칸은 사람 확인 대기이며, 참값 후보와 실행은 Claude 구독 CLI에서 얻었다.
운영 API/새 폰 사진의 성능 또는 다섯 형식 전체의 교사 대조 정확도를 검증한 수치가 아니다.
의미 채점은 현재 B형의 합성 답 36개 × 3회에서 Haiku도 108/108이었다. 읽기와 채점 모델은 별도 변수로
선택할 수 있지만 시작 기본은 둘 다 Opus다. 화면 제안은 [cb-scan-wire](tracks/reports/cb-scan-wire.md)에 보존했다.

### 13.3 발행과 실제 제출 흐름

기반 계약은 [cb-scan-core](tracks/reports/cb-scan-core.md), 출고 구현은 `src/lib/concept-blank/scan/`과
`src/components/concept-blank/scan/`에 있다. 추가 모델 8개와
`prisma/migrations/20261125120000_concept_blank_scan/migration.sql`을 작성했다. **공유 DB 미적용**이다.

인쇄 진입에서 서버가 고르기·당시 은행·판정 기준을 동결하고, 실제 제품 조판을 격리 Chromium으로 렌더해
글꼴 적재·본문 넘침·모든 답 칸의 대응을 확인한 뒤 HTML/CSS/글꼴/좌표/지문을 함께 저장한다.
브라우저가 보낸 좌표를 기준으로 삼지 않는다. P1 20mm QR과 본문 밖 네 표식은 학생지·채점표 모두에 붙는다.
발행 UUID는 정확한 `pick`·글자 코드 없는 지면도 지원한다. 재인쇄 `?p=<id>`는 저장된 산출물만 읽는다.
발행 실패 시 안내를 보이고 QR 없는 기존 지면으로 인쇄한다. 저장 전 옛 지면은 재발행을 안내한다.

학생 진입은 `/concept-blank/scan?p=<id>&page=<n>&part=student`이며 로그인·첫 비밀번호 변경 뒤에도 목적지를 유지한다.
학생은 발행 교사의 **현재 ownerScope**에 속해야 하고, 교사 대리 촬영은 발행물과 학생 양쪽의 권한을 확인한다.
새 배정 표 없이 기존 `conceptBlank` 메뉴를 따른다. 사진 자체 QR로 발행물·쪽·학생지 여부를 확인하며 채점표는 거절한다.
이미지는 브라우저에서 방향/메타데이터를 정리하고 기존 studio-ai 축소 사다리로 전송 한도 아래로 줄인다.

모든 쪽을 모은 뒤 읽는다. 확인 번호는 전체 학생지에 걸쳐 고정하며, 표식·QR의 독립 대조가 실패하면 번호/테두리를 숨긴다.
못 읽은 칸을 먼저 보여 주되 전체 판독문을 열 수 있고, 빈 답과 확인 필요는 다른 저장 행동이다.
직접 입력은 공개 전만 가능하며 최초 판독을 덮지 않는다. 채점 중 입력 판을 잠그고 늦은 수정은 거절한다.
모든 판정이 준비되면 즉시 공개한다. 교사 수정은 이유와 별도 이력으로 남는다. 종합 점수는 없고 단위별 ○·△·×·확인 필요 개수만 있다.
**A·옛 D는 교사 확인**이다. B ○×는 표시+까닭을 묶고, C 빈칸/적용·현재 D 질문·E 이름표/설명은 각 계약의 판정 단위를 따른다.

HTTP는 `/api/concept-blank/scan/` 아래 `issued`, `issued/{id}`, `submissions`, `submissions/{id}`,
`photos`, `answers`, `jobs`, `override`, 사진별 서명/삭제, `purge/cron`으로 나뉜다. 모든 export는 `withErrorLog`를 사용한다.
서버는 `after`로 수락한 읽기/채점을 이어 가며, 탭을 닫아도 결과를 저장한다. 중단 뒤에는 저장된 쪽/유료 응답부터 재개한다.

### 13.4 선예약·보존·운영 변수

DB 월 원장의 잠금 안에서 **사용액 + 미정산 예약 + 새 최대 비용 ≤ 상한**일 때만 호출한다.
지원 모델의 입력 상한 1,000,000토큰과 최대 출력 16,000토큰을 고정 단가에 적용한다(Opus 예약 $4.32/호출).
실제 토큰 정산 때 차액을 풀고, 응답 원문도 같은 트랜잭션에 보관해 파싱/저장 복구에 다시 돈을 쓰지 않는다.
사용량 불명은 예약을 유지하고 운영 확인을 요구한다. 앱 작업의 재개 기한은 유료 예약 해제 기한이 아니다.
UTC **호출 시작 월**, 읽기·채점 공통, 서비스 전체 한도다. 다른 기능의 사용료나 제공자 청구서 전체의 절대 상한을 보장하지 않는다.

사진은 비공개 버킷에 둔다. 채점 입력으로 사용한 사진은 업로드부터 30일, 미사용·실패·교체 사진은 7일이다.
서명 주소는 현재 권한 확인 후 최대 60초(남은 보존 기간 이내), 만료·삭제 요청 시 새 열람은 차단한다.
교사 조기 삭제는 먼저 열람을 막고 Storage 삭제 성공 뒤 `deleted_at`을 남긴다. 실패는 다음 cron에서 재시도한다.
cron은 매일 18:45 UTC, 한 번에 최대 50개/120초 처리 예산이다. 배치 한도로 실제 객체 정리가 늦어져도 만료 열람은 열지 않는다.
전달된 사본까지 즉시 회수한다는 보장은 하지 않는다. 텍스트·판정 이력은 사진 삭제와 분리된다.

| 변수 | 동작 |
| --- | --- |
| `ANTHROPIC_API_KEY` | 기존 서버 키. 실제 호출은 이번 작업에서 안 함 |
| `CONCEPT_BLANK_SCAN_ENABLED` | unset/on은 유료 처리 켜짐, 그 밖은 끔. 저장된 답·사진 조회와 삭제는 유지 |
| `CONCEPT_BLANK_SCAN_MODEL` / `_GRADE_MODEL` | 기본 Opus 5.5, 채점 값이 비면 읽기 모델과 같음 |
| `CONCEPT_BLANK_SCAN_EFFORT` | 기본 high |
| `CONCEPT_BLANK_SCAN_MONTHLY_USD_CAP` | 기본 100, 0은 새 유료 호출 차단 |
| `SUPABASE_URL` / `SUPABASE_SECRET_KEY` | 앱 Storage의 서버 전용 주소/키. URL은 `NEXT_PUBLIC_SUPABASE_URL`, 키는 `SUPABASE_SERVICE_ROLE_KEY`도 호환 |
| `CONCEPT_BLANK_SCAN_STORAGE_BUCKET` | 기본 `concept-blank-scan-private`; 비공개 여부를 서버에서 확인 |
| `CRON_SECRET` | 기존 cron bearer 인증. 학생·교사 세션은 정리 실행 권한이 아님 |
| `AUTH_URL` 또는 `NEXTAUTH_URL` | QR의 정식 서비스 origin. 둘 다 없으면 요청 origin 사용 |

### 13.5 배포·되돌림과 원장님 할 일

**DB 먼저 · 코드 나중**이다. 리드가 SQL을 검수해 운영에 적용하고 `prisma generate`한 코드와 함께 배포한다.
추가 표가 없으면 사진 채점 API는 준비 필요 이유와 503을 내며, 기존 인쇄는 QR 없이 계속된다.
비공개 버킷·서버 키·정식 origin·cron 시크릿을 준비하기 전에는 사진 채점 스위치를 off로 둔다.
서버 렌더가 사용하는 기존 Chromium 배포 자산과 새 CSS/글꼴 tracing 포함도 배포 환경에서 확인한다.

문제가 생기면 먼저 유료 처리 스위치를 끄고, 저장 결과 조회/사진 정리를 유지한다. 코드 되돌림은 추가 표를 보존한 채 한다.
새 기록이 있는 표를 DROP하거나 비용 원장/사진 증거를 지우는 역마이그레이션은 하지 않는다.
사용량 불명은 운영 담당자가 호출 원장·제공자 영수증을 대조한 후 별도 승인된 복구로 정산하며 TTL만으로 풀지 않는다.

원장님/리드에게 남긴 일: 운영 `ANTHROPIC_API_KEY`·비공개 버킷과 서버 자격 증명 준비, DB 적용/배포 검수,
`/dev/print-check`의 `concept-blank-scan-20261125` 실물 인쇄와 폰 촬영, 새 폰 표본의 사람 참값·읽기/의미 채점 재측정.
실물 항목은 **대기**다. 로컬 E2E는 가짜 모델·로컬 DB로 검증했으며 실제 손글씨 정확도나 운영 배포 성공을 뜻하지 않는다.
전체 검사 결과와 못 닫은 항목은 [출고 보고서](tracks/reports/cb-scan-ship.md)의 완료 표를 따른다.
