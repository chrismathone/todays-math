Catalog

- one-digit-add: 20 presets, exact domain sizes 1–25. Fixed additions 1–9 with/without carrying and the 0–4 / 5–9 operand ranges.
- one-digit-sub: 12 presets, exact domain sizes 1–21. Fixed subtractions 0–9, subtraction within 0–5, and subtraction from 9; differences are nonnegative.
- two-digit-vertical-add: 14 presets, exact domain sizes 2–3,735. Carry counts 0/1/2, fixed additions 11/19, and fixed tens 10/20/30/40/50 without carrying.
- two-digit-vertical-sub: 9 presets, exact domain sizes 9–2,475. Borrow counts 0/1, fixed subtraction 19, and fixed tens 10/20/30/40/50 without borrowing.
- times-table: 9 presets, exact domain size 9 each. Individual tables 1–9, each multiplied by 1–9.
- two-digit-times-one: 24 presets, exact domain sizes 2–72. Fixed multipliers 2–9, each with carry counts 0/1/2.
- two-digit-div-one: 9 presets, exact domain sizes 10–90. Fixed divisors 1–9, dividends 10–99, integer quotients and remainder 0.
- Only supported engine constraints are authored. IDs describe the operation, fixed value and carry/borrow condition; they do not depend on array order, titles or generated numbers.
- Core request normalization canonicalizes selections before deduplication. Duplicate IDs or normalized selections and empty domains fail catalog construction. Tests additionally reject equivalent full operand domains within the same skill even if constraints were written differently.
- defaultCount is exactly min(20, domainSize) for every preset. The engine's per-round and document limits still apply to mixed requests.

Exact coverage and omissions
- This is one-/two-digit nonnegative integer arithmetic in seven existing families. It does not establish elementary grade 3 through middle grade 3 coverage, official grade assignment or achievement-standard alignment.
- Fractions, decimals, negative integers/rationals, signed operations, algebraic expressions/equations, polynomials and radicals are not implemented here.
- Mixed-operation order, division with remainder, larger-digit families, word problems, geometry, official grade claims and student grading/SRS integration remain outside this task.
- 97 counts the available parameter presets, not additional curriculum families or problem-bank inventory.

UI integration contract
- Import listArithmeticPresets() and findArithmeticPreset(id) from @/lib/arithmeticPresets.
- list returns readonly {id,title,group,description,selection,defaultCount,domainSize,example}[]; find returns the matching entry or undefined.
- The default full-range two-digit addition with zero carries is add-two-carry-0.
- selection is the frozen core ArithmeticSkillSelection; send it in a core request allocation with count. No preset-only keys belong in the arithmeticSheet payload.
- The cached catalog and all nested objects are deeply frozen. Clone selection/constraints before user editing.
- Each example is an ArithmeticPrompt only, generated with seed preset-example-v1:<stable-id> and verified through buildArithmeticSheet. It carries no answer or solution field.
- Mixed presets can overlap within a skill: exact per-preset domain sizes do not imply their default counts can always be added. The existing engine rejects depleted/overlapping round allocations without padding them; a mixed-preset regression test confirms this.

Finite regeneration behavior
- At default counts, 38 presets sample only part of their domain; the seed tests verify a changed numeric membership set can be obtained.
- 56 presets use their entire domain of multiple items; regeneration can change order while retaining the same members.
- Three presets have one possible item: add-one-fixed-1-carry (9+1), add-one-fixed-9-no-carry (0+9), and sub-one-fixed-9 (9−9). Their defaultCount is 1, and no seed can create a different legal item.
- Fresh seeds may collide, and earlier seeds may reuse items. The variation checks use up to 32 deterministic seed probes and require variation only where possible; they do not promise a new item on every click or historical non-repetition.
