API contract for integration
- Types: src/contracts/workspaceArithmetic.contract.ts.
- GET /api/arithmetic/catalog -> WorkspaceArithmeticCatalogResponse:
  {data:{engineVersion,catalogVersion,skills,limits:{itemsPerRound,itemsTotal,rounds},writerEnabled}}.
  Skills are the core's catalog entries; limits are 100 per round, 100 total and 20 rounds.
- POST /api/arithmetic/generate takes WorkspaceArithmeticGenerateRequest (alias of core ArithmeticGenerateRequest) and returns {data: ArithmeticSheetPayload}.
  Preview does not require the document writer gate and never touches document/bank/student storage or usage counters.
  The request body is bounded to 64 KiB, depth 12, 20,000 tokens and 128-character strings; duplicate keys and invalid JSON numbers/encoding are rejected.
- Both routes require an approved authenticated account with bank rights. POST uses the existing same-origin mutation guard. Responses are private/no-store.
- Engine errors return HTTP 400 {error:{code,message,violations?,limit?}}. Capacity violations retain skillId/round/allocation/requested/available/reason. No partial sheet is returned.
- Existing /api/library/documents endpoints carry kind arithmeticSheet and the exact version-1 payload. PUT takes {kind,title,payload,expectedRevision,visibility?,sharedBranchId?}; new documents default to private.
- GET list/read, PUT save, POST shared copy, PATCH rename and DELETE revision-checked deletion support arithmeticSheet.
  Save and shared copy validate with reopenArithmeticSheet and compute the summary count with arithmeticSheetProblemCount.
  Read and rename validate the saved snapshot without regenerating it. Rename changes the envelope title only. Shared copy keeps prompt/answer snapshots, allocates a new document ID and becomes private.
  Stored payload versions, prompt/answer consistency, duplicate identity, ordering, schema and item quotas are verified by the frozen core.
  Arithmetic saves additionally reject ambiguous JSON and bodies over 256 KiB; a valid 100-item sheet with a 128-character seed is covered.

Permissions and concurrency
- bank-only accounts can list/read their arithmetic documents and eligible same-branch shares, and save/copy/rename/delete arithmetic documents.
- bank-only access does not permit legacy draft/extraction/conceptBlank reads, writes or private assets. List filters are constrained to arithmeticSheet.
- Existing storage-menu readers retain their previous document read scope. library retains owner rename/delete; arithmetic save/copy always require bank.
- Existing live branch-membership predicates, owner-only original mutation, explicit branch sharing, optimistic revisions and material audit logs are preserved.
- Existing administrative inspection audit logs and failure error logging remain; these are not usage/ranking counters.
- No labels or ranking fields were invented. The document title/sharing/revision envelope stays separate from the strict core snapshot. Root owns any further label metadata design.
