# 수학 엔진 학습 구조·난도 준비도 감사

2026-10-18 · 소스 `9b6dd60aeb5a0d7bc968aecd32d5163f35640997` · 감사만 수행

**현재 엔진은 기초 계산만 하는 단계가 아니다.** 개념 판단, 자연수/정수 조건의 완전 탐색, 실제 경우 나누기, 여러 단계 모델링을 연습할 수 있는 자작 문항이 이미 있다. 다만 **대륜중을 선택한 학생이 그 학교의 복합 조건·시각 읽기·서술 풀이까지 충분히 대비한다는 전체 판정은 아직 할 수 없다.** 연결된 과제 구조와 학년별 서술 rubric의 구체적 공백이 있고, 콘텐츠 능력과 실제 웹앱 전달은 따로 확인해야 한다.

원문을 DB에 넣지 않은 것은 저작권을 고려한 의도된 설계다. 원문/기출 연결0을 실패로 세지 않으며, 원문 복구·적재를 해결책으로 제안하지 않는다. 비교는 수학 요구의 추상 구조로 하고 새 연습은 기존 자작 생성기의 자체 문장·수치·그림으로 만든다.

## 판정과 관측 범위

`study-ready`는 표시한 추상 핵심을 현재 생성 문항으로 연습할 수 있다는 뜻이다. `component-only`는 계산/개념 재료는 있지만 요구한 공유 조건·시각/풀이 의존 또는 서술 형식 전체를 입증하지 못했다는 뜻이다. `upgrade-needed`는 검토한 경로에 실질적인 구조/설명 rubric 보강이 필요하다. `unverified`는 원자료나 대응/접근 근거가 부족한 상태다. 어느 것도 학교 전체의 적중률·학습효과 수치가 아니다.

48개 **선정 호출 진입점**에서 seed `731, 1907, 4613`, variant `0`으로 새 자작 문제 144개를 생성했고 반복 결과144개가 같았다. 별도 Python `Fraction`/제한 AST 계산, 원조건에서 유도한 유한 경계, 경우·순열 전수, 자료/좌표 검산으로 **144개를 검산하여 불일치0**이었다. `facts`를 정답 oracle로 쓰지 않았다. 판단형의 의미/반례와 native 설명은 코드 검산에 소스 논증 검토를 함께 썼으며, 모든 실수 입력에 대한 형식 증명이나 전체 엔진 정답률 검증은 아니다.

자체 생성 SVG7개를 현행 `renderFigureSpec(strict)`로 렌더하고 직접 확인했다. 대상은 비례/반비례 교점, 피타고라스 풍차, 내접 사각형, 외부 수선, 현과 활 높이, 두 막대차트, 표다. 시스템 Python3.9의 `dataclass(slots=True)` 환경 오류 후 이미 설치된3.12.15에서7/7성공했다. 학교 원본 그림이나 브라우저는 사용하지 않았다.

이전420,300회 캠페인은 재실행하지 않았다. 이전4,203은 정본 등록 단위,297,016은 당시 정의한 발문 변형 표본이다. 해당 생성 소스 디렉터리는 이전 pin과 이번 pin의 diff가 비어 재사용하지만 **독립적인 사고 유형 수·전체 수학 용량·품질 합격 수로 바꾸지 않는다.** 연산 엔진도 계산 성분의 별도 경로이며 이 표본의 구조 family 수에 더하지 않았다.

## 난도를 유지하는 것과 아직 보장하지 못하는 것

`중1 32T`는 최대공약수/최소공배수에서 서로소 쌍을 모두 찾고, `84X`는 네 선분을 각각 검사한다. `중2 34U`는 추월 전/후가 모두 살아야 하며, `127X`는 평행 두 경우와 공점 한 경우를 모두 포함한다. `109X`는 다섯 막대의 열 세쌍을 검사하고 살아남는 직각삼각형의 넓이를 합한다. `중3 41U`는 미지수에 따라 근호의 부호가 갈라져 나온 후보를 원구간에 되돌려 기각한다. `53V`는 자연수 매개변수의 경계를 먼저 닫고 유리근 조건을 완전 탐색한다. 이들은 **무슨 상태/경우를 적용할지 정하는 실제 요구**여서 숫자만 크게 만든 심화가 아니다.

그러나 생성기 가드나 소스의 `심화상` 표시는 학교 난도 교정이 아니다. 이번84X 세 표본은 교차2개만 관측했고,33U는 생성 발문이 닫힌 부등호만 쓴다. 가능한 분기/경계를 전부 확인했다고 쓰지 않는다. 같은 출력 값, 순서 셔플, 단답/객관 쌍, 순위/합/개수 차이도 새 사고 가족으로 세지 않는다.

증명에는 별도 경계가 있다. 중2 피타고라스05는 증명 설명을 읽고 수치 넓이를 구하며,06은 가운데 정사각형 넓이를 구한다. 고등 조합02는 제공된 증명의 빈칸 하나다. 이를 학생의 독립 증명 수행으로 보고하면 안 된다. native6개는 실제 모델답/배점·대안·오류를 갖지만 초4·중3에만 있다. [`expandFamily`](../../../src/lib/engine/expandEngine.ts#L1)는 끝말을 바꾼 서술형을 만들지 않는다.

## 최소 수용 검사와 보강 순서

- **A1 · concept judgement / truth-set:** 각 인쇄 진술을 별도 의미 판정기로 계산하고 참인 ID 집합 및 유일한 정답 보기를 비교한다. a=b의 항등성은 보편 명제로, 대입은 특정 후보로, 함수는 입력당 출력 유일성으로 각각 검산한다. 참 개수만 같고 참 ID가 다른 보기는 오답이어야 한다. 개수/번호/부분집합 표적은 같은 수학 family 안에서 다룬다.
- **A2 · visual reading:** 자체 FigureSpec을 실제 SVG로 렌더하고 모든 관련 축·점·눈금·길이를 독립 수치와 대조한다. 시각 읽기가 목표면 필요한 자료를 그림에 두고 텍스트 좌표 전량 제공으로 대체하지 않는다. 꺾은선의 극값·총이동거리·반복 교차·정지구간을 따로 계산하고 교차점/꼭짓점 중복을 제거한다.
- **A3 · complete constraints / all solutions:** 유한 검색 상한을 원조건에서 유도한 뒤 정수/자연수/실수 및 0 제외 조건으로 완전 집합을 대조한다. 매개변수 음수·0·양수, 열린/닫힌 경계, 무해·무한해·중근도 검산한다. 합·개수·최대·순위는 같은 집합의 표적 변형이며 새 family 수에 더하지 않는다.
- **A4 · multi-step algebra:** 발문만으로 식을 세우고 독립 전개/소거로 각 중간값과 최종식을 재계산한다. 앞 단계 결과가 다음 단계의 실제 입력인지 확인한다. 연결된 두 관계를 개별 문제 두 개로 제공하는 것은 통합 과제의 통과가 아니다. 동치식·합/차·계수 위치만 다른 변형은 재등록하지 않는다.
- **A5 · modeling:** 미지수 뜻·단위·정의역을 명시한 자체 모델에서 모든 해를 원상황에 대입한다. 거리와 이동거리, 지름/반지름, 백분율 기준량, 요금/증정 문턱, 최소 시간 올림을 각각 경계 전후로 검산한다. 두 별도 소문항은 하나의 새 결합 구조로 세지 않는다.
- **A6 · multi-concept dependencies:** 자체 수치·문장·그림으로 의존 순서를 명시하고 필요한 각 조건을 바꾸거나 제거하면 결과가 바뀌거나 미결정이 되는지 확인한다. 그래프-정사각형, 반비례 두 점-넓이비, 절편 재배치-다른 함수 등에서 모든 관계·비퇴화·부호를 동시에 만족해야 한다. 이웃 family의 존재만으로 통과하지 않는다.
- **A7 · proof / rubric:** 처음부터 이유·수정·반례·정당화가 필요한 다단계 과제를 저술하고 모범 답안 및 단계별 배점·허용 대안·오류 사례를 함께 둔다. 정답만 맞은 답안과 근거가 틀린 답안의 점수가 구별되어야 한다. 발문 끝만 서술형으로 바꾸거나 주어진 증명 한 빈칸을 완전 증명으로 판정하지 않는다.
- **A8 · difficulty / case selection:** 어떤 경우를 적용할지 학생이 결정해야 하는지 명시한다. 유효·기각 후보를 모두 유지하고 한 경우를 생략하거나 조건을 오독하면 답이 달라지는 음성 대조를 포함한다. 대표 seed가 놓친 분기와 경계는 별도 강제 입력으로 확인한다. 숫자 크기·해설 줄 수·사이트 난도 라벨로 난도 동등성을 대신하지 않는다.
- **A9 · product delivery (ROOT owned):** 원문 저장 없이 학교/학년/범위의 검토된 추상 요구를 family·조건·시각/서술 요구로 전달하는 합성 데이터 검사를 둔다. 같은 단원·난도인 서로 다른 구조 후보에서 맞는 구조가 선택되고 부족하면 미충족을 알려야 한다. 실제 학교 선택에서 접근 가능한 새 연습과 해설/그림/서술 채점 기준까지 ROOT가 확인한다.

우선순위는 **(1) 현재 준비된 가족을 실제 연습에 연결하고 (2) 그래프·기하/모델 의존과 공유 진리집합을 완성한 자작 과제를 검산하며 (3) 중1·중2 등 비어 있는 native 설명/rubric을 저술하고 (4) 구조/난도 요구를 학교 선택 경로에 전달하는 것**이다. 기존 집합 계산에서 합/순위를 바꾸기 위해 중복 family를 만들지 않는다. 처음부터 새로운 수학 연결이 필요한 경우와 기존 family의 표적/조건 확장을 구분해야 한다.

## 콘텐츠와 웹앱 전달의 경계

초등·중등·판정형·중등 결합형·native 서술은 [`load-engine-problems.ts`](../../../scripts/import/load-engine-problems.ts#L587)에 적재 코드가 있다. 이것이 지금 승인·출제 가능한 재고나 특정 학교 선택 시 접근을 입증하지는 않는다. 공통수학1의168키는 라이브러리/CLI 생성 가능성이고, 이 적재기의 고등 target은 없다. 공통2의 독립 생성 등록0도 다른 자작 콘텐츠의 부재 증명은 아니다. ROOT가 담당하는 실제 학교 선택·API·후보 조립 결과와 합쳐 판단해야 한다. 학교명을 표시하거나100점을 조립하는 것만으로 요구 구조가 전달됐다고 하지 않는다.

이번 작업은 DB·환경 파일·자격증명·외부 요청·유료/provider·브라우저/cookie를 사용하지 않았다. 제품 소스 변경이나 구현도 없다. 빈 환경 프로세스와 파일/모듈/연결 차단을 사용했다. tsx의 로컬 IPC 접속 시도2개는 guard가 차단했고 스택을 보존했다. 학교 원본 자료는 이 작업의 재현 입력이 아니다.
