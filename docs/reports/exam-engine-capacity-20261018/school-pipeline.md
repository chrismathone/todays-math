**학교 조건 수학 출제 경로 감사 — 2026-10-18**

기준 소스는 `d70137271e36e6f9c22209574e9ff224217f7296`이다. **“경명여중을 입력하면 그 학교의 실제 문제 구조를 반영한 새 문제가 나온다”는 요구는 현재 충족되지 않는다(`fail`).** 현재 수학 화면에는 두 생성 API를 실행하는 진입점이 없고, 현재 DB 내보내기에는 경명여중 자체 근거가 없으며, 백엔드는 학교별 분포로 기존 문제 행을 고르는 방식이다. 학교별 풀이 구조를 검증하거나 새 문장을 쓰는 단계는 이 경로에 없다.

이는 학교 조건이 전혀 작동하지 않는다는 뜻은 아니다. 합성 고정 자료에서 학교를 바꾸면 실제 `generatePredictedPaper`의 청사진과 선택 문항이 바뀌었다. 다만 학교의 과거 자료 없이 코호트만 있으면 학교 이름만 다른 동일 문항지를 만들 수도 있다. 구조적 일치와 현재 경명여중 자료의 부재를 아래에서 구분한다.

현재 자료 수치는 루트가 공급한 읽기 전용 내보내기를 오프라인 집계했다. 캡처 시각은 `2026-10-18T11:08:34.847Z`, 소스 커밋은 위와 같고, 루트 영수증은 `RepeatableRead`, 읽기 전용 트랜잭션 검증 성공, 운영 DML 0을 기록한다. 이 작업자는 DB에 연결하지 않았으며 두 입력 파일의 SHA-256이 영수증과 일치함을 확인했다. 전체 자료 해석은 통합본의 [school-data.md](school-data.md)가 담당하고, 실제 내보내기를 넣은 런타임 재현은 루트의 별도 `runtime-verification` 보고서가 담당한다.

코호트 대체를 완전히 숨기는 코드는 아니다. `evidenceCount`는 자체 학교 이력 수이고 근거가 없으면 0, `confidence`도 0이다(`predictBlueprint.ts:439-440`). 예측 run에는 `적은_과거회차` 위험 표시가 붙는다(`predictionRunService.ts:523-540`). 대시보드는 자체 근거 2편 미만을 “근거 부족”으로 막아 청사진 숫자를 숨긴다(`src/components/exam/viewModel.ts:151-166`; `BlueprintPanel.tsx:52-72`). 그러나 출제 API는 자체 근거 0만으로 거절하지 않고 수치 메타데이터를 반환할 뿐이며 명시적인 코호트 전용 경고 문장은 없다(`src/app/api/tests/predicted/route.ts:60-75`). 현 상태에서는 출제 화면도 없어, 사용자가 코호트 대체를 확인하고 승인하는 완료된 UI 흐름을 주장할 수 없다.

합성 재현 구성은 JSON에도 기록했다. A는 같은 이전 회차의 U단원 10문항 객관식·각 10점, B는 V단원 20문항 단답형·각 5점이며 모든 난이도 라벨은 하다. 후보는 U/V × 객관식/단답형 × 20행 = 80개이고 ID가 고정되어 있다. 기본 혼합 후 A 단원 기댓값은 U 2.5/V 7.5, B는 V 5/U 15였다. 이 분리된 주변 분포를 슬롯에 배치한 것이며 학교 원문의 풀이 구조를 학습한 결과가 아니다. 합성의 `familyKey`가 다른 후보도 동일 슬롯으로 취급했고, 동일 문항 표현 두 개에 동일한 `questionGroupKey`를 주어 중복을 검증했다.

현재 사용자 요구를 막는 구체 항목은 다음과 같다.

1. 현재 경명여중 자체 추출/신뢰/연결/출제 가능 자료가 없고, 수학 UI에 학교 조건 실행 경로가 없다. 데이터 복구와 실행 UI를 구분해 해결해야 한다.
2. 학교의 응답 형식 분포를 실제 문제 구조와 동일시할 수 없다. 문제군/의미/풀이 구조 요구와 검증 단계가 없는 상태에서 “그 학교 유형 새 문제 생성”을 약속할 수 없다.
3. 생성 API가 저장 run의 청사진을 사용하지 않으며 출처·과목 범위 규칙도 다르다. 어느 근거로 만들었는지를 하나의 실행 기록으로 재현할 수 있게 맞춰야 한다.
4. 현재 논리 문항 정체를 출제 후보·중복 제거·자체 학교 우대·저장 직전 재검사까지 이어야 한다. 행 10개가 문항 10개라는 전제는 오늘의 계약과 맞지 않는다.
5. 코호트 전용 대체와 각 축 완화를 출제 결과의 의미로 다뤄야 한다. 현재 숫자 메타데이터만으로 “경명여중 맞춤”으로 읽히게 해서는 안 된다.
6. 과거 시점 평가를 하려면 후보 원본 시점까지 검증해야 한다. 학습 근거만 시간 필터를 통과해도 최종 문제지가 같은 시간 조건을 지키는 것은 아니다.

이 작업의 변경은 공개 보고서 두 파일뿐이다. 제품 소스·스키마·운영 데이터는 변경하지 않았고 HTTP 쓰기, 유료 API, credential 조회, push/deploy를 수행하지 않았다. 실제 학생 배포·인쇄 완결성, 학교별 출제 예측 정확도, 학습 효과, 엔진의 전체 내용 공간은 이번 증거로 판정하지 않았다.
