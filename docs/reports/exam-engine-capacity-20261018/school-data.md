| 대상 | 형식·배점 | 원본 난도·소단원 | 우리 단원 | 생성 문항류 |
|---|---|---|---|---|
| 현재 경명여중 | 문항 자체 0 | 대상 없음 | 대상 없음 | 본교 원전 연결 0 |

| 같은 타교의 은행 101행 | 형식·배점은 메타데이터와 일치 | 은행 난도는 원본 상/중/하와 다른 축 | 9개 단원에 연결 | `familyKey` 63종이지만 본교 근거가 아니며 전부 출제 잠금 |

보관 문항 266개 중 251개는 삭제 원장의 본문 행으로 이어지며 그 251개에서 학교 출처 파일·문항 번호·형식이 일치한다. 나머지 15개는 `problemId` 자체가 없어 연결 본문이 없다. 연결된 251개 중 246개만 배점이 그대로 일치하고, 중2 2024-2 중간의 5개는 다르다. 추출·배점 보정 또는 원문 차이 중 무엇인지는 원본을 다시 확인해야 한다. 현재 원본 PDF/HWP와의 본문·그림·정답 대응은 검증하지 않았다. 보관 본문은 외부에 싣지 않고 편별 해시만 남겼다.

현재 [청사진 조립기](../../../src/lib/predictor/composePredictedPaper.ts#L203)는 `unitId`·난도·객/단답/서술 형식으로 은행 후보를 고른다. `topicRaw`를 단원으로 해석하지 않으며 `familyKey`·`questionGroupKey`를 소비하지 않는다. [서비스 후보 변환](../../../src/lib/predictor/generatePredictedPaper.ts#L200)도 이 두 키를 후보에 싣지 않는다. 따라서 현재 태그로 본교의 세부 풀이 유형이나 사고 단계를 배워 새 생성기를 선택하는 연결은 입증되지 않는다. 은행에 저장된 같은 문항의 객관식/단답형 표현은 `questionGroupKey`로 한 문항으로 세어야 하고, 보기 섞기는 새 내용이 아니다. 저장 행 수나 생성 샘플의 서로 다른 출력 수를 총 생성 용량으로 쓰지 않았다.

## 로더·정규화·가드의 실제 경계

- [별칭 함수](../../../src/lib/schools/normalizeSchoolName.ts#L61)를 실제 호출하면 `경명여중`, `경명여자중학교`, `대구광역시 경명여자중학교`는 모두 `경명여중`이다. 다만 [예측 요청 계약](../../../src/contracts/predictor.contract.ts#L57)과 [DB 조회](../../../src/lib/predictor/predictionRunService.ts#L257)는 이를 호출하지 않고 원문 문자열을 정확히 비교한다. 함수 존재가 API 전체 별칭 지원의 증거가 아니다.
- 자동 예측 근거는 계약 변환 → **cutoff보다 엄격히 이전** → [10문항 이상·95~105점](../../../src/lib/predictor/paperTrust.ts#L76) → [출처 분류](../../../src/lib/predictor/paperSource.ts#L52) 순이다. ‘대비’ 경로와 경로 없는 ‘미상’은 자동 `PredictionRun` 학습에서 빠진다. 경로에 ‘대비’가 없는 학원 제작물은 이 문자열 규칙으로 검출할 수 없다.
- [고정 입력 재실행](../../../src/lib/predictor/predictionRunService.ts#L317)은 수량·출처 가드를 재적용하지 않는 예외이며 시간 누출 검사는 유지한다. 이 예외를 자동 학습 자료의 자격으로 일반화하지 않는다.
- [문제지 생성 서비스](../../../src/lib/predictor/generatePredictedPaper.ts#L295)는 시간·수량 가드를 적용하지만 `paperSource`를 재적용하지 않는다. 자동 예측과 규칙이 다르다. 본교 현재 자료가 0이라 이번 스냅샷의 본교 대비 오염 사례가 있다는 뜻은 아니다.
- [오프라인 로더](../../../scripts/predictor/loadCorpus.ts#L203)는 추출 JSON과 기간 지도에 의존한다. 이 작업 위치와 검사한 root/기존 경로에는 기본 corpus와 `period-map.json`이 없었다. 대신 [삭제 원장](../../../scripts/import/ledgers/legacy-corpus-delete.json.gz)에 실제 과거 문항 데이터가 남아 있다. [삭제 스크립트](../../../scripts/import/delete-legacy-corpus.ts#L1)는 2026-08-27 과거 시험지·문항 연결을 함께 제거한 목적을 설명한다. 읽기만 했으며 복원하지 않았다.

## 재현 예와 미확인 부분

**현재 데이터로 본교 성공 예를 추천할 수 없다.** 제한된 연결 확인용 후보는 **경명여중·중3·2026-2 중간**이다. 자체 근거는 0편이고 타교 코호트는 5편이다. 전년의 같은 학기·회차를 쓰는 조건이지만 해당 자료의 단원·난도 원문 태그는 모두 비어 있다. 실제 선택 결과는 이 작업에서 만들지 않았다. 이를 경명여중 유형 재현 성공으로 표시하면 안 된다.

중1·중2에는 본교와 동급·동학년 코호트가 함께 0이다. 중3도 **2025-2 중간 자체를 대상으로 잡으면 같은 시점 5편이 모두 제외**돼 근거가 0이다. 그 이후 회차에서만 현재 다섯 편을 사용할 수 있다. 수학 학년·시험 범위 없이 학교 이름만 입력하는 조건으로 충분한 코퍼스가 아니다.

향후 별도로 원전·회복 검토를 한다면 보관 **중1·2025-1 기말**을 숨기고 앞선 통과 자료(2024-1 기말, 2025-1 중간)와 비교하는 메타데이터 홀드아웃이 상대적으로 명확하다. 목표 편은 22문항·100점이지만 연결 본문은 11개뿐이다. 이 제안은 과거 자료의 검토 후보이며 현재 출제 시연이나 복원 완료가 아니다.

이번 감사는 학교별 원본 전량의 소재·공식 출제 여부·최신 기출 수·미추출 편수·실제 학교와의 난도 동등성·학생 학습 효과를 입증하지 않는다. 본교 원전 확보와 문항별 단원/형식/풀이 유형 연결을 확인하기 전에는 일반 은행 재고나 RPM 유형 수를 경명여중의 생성 가능 용량으로 바꿔 말할 수 없다.

## 증거·검산
