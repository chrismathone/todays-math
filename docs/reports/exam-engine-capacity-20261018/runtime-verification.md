> **후속 해석 정정:** 기출 원문을 DB에 보관하지 않은 것은 사용자의 의도된 설계다. 원문 부재를 엔진 학습 불가의 근거로 사용하거나 복원·재적재를 권고하지 않는다. 이 문서는 당시 데이터/API 관측이며, 실제 기출 대비 학습 대응력은 [후속 기준](../math-engine-study-readiness-20261018/OWNER-CRITERIA.md)에 따라 별도로 검수한다.

**경명여중 실제 출제 서비스 재현 — 2026-10-18**

현재 연결된 데이터베이스에서 읽기 전용으로 확보한 자료를 실제 `generatePredictedPaper`에 넣어 **21개 조건**을 실행했다. **경명여중 고유 문제를 생성한다는 요구는 충족되지 않는다.** 중1·중2는 근거 없음으로 거절했고, 중3은 다른 학교 5편으로 20문항·100점의 기존 은행 문제지를 조립했다. 경명여중, 경명여자중학교, 임의의 미등록 학교는 동일 조건에서 **문항 ID·순서·배점이 모두 같았다.**

소스는 `d70137271e36e6f9c22209574e9ff224217f7296`, 자료 캡처는 `2026-10-18T11:08:34.847Z`, 재현은 `2026-10-18T11:18:17.231Z`이다. 현재 작업공간의 연결 DB를 검사한 결과이며 모든 배포 환경이 같은 DB를 사용한다고 별도로 확인한 것은 아니다. 별도 사이트의 자료를 이 DB의 자료로 간주하지 않았다.

검사는 실제 예측기·선택기·저장 함수의 가드를 실행했다. DB 모듈만 불변 내보내기와 합성 반 소유자 판정으로 교체했다. 저장 함수가 `db.$transaction`을 부르는 순간 콜백 실행 전에 의도적으로 중단했다. 따라서 **저장 직전까지의 조립 검증**이며 HTTP 201·저장된 시험지·학생 배포 성공으로 보고하지 않는다. 실제 DB 쓰기, 학생/반 기록 조회, 유료 API 호출은 0이다.

`grade`는 해당 학년의 모든 단원을 허용한 가용성 예시다. 실제 학교 시험 범위를 복원했다는 의미가 아니다. `chapters5-6`은 중3 삼각비와 원의 성질의 7개 단원을 명시한 별도 예시다. 사용자가 학년·대상 회차·범위를 지정하지 않아 학년별 네 회차와 좁은 범위를 함께 검사했다.

중3의 넓은 범위 예시는 후보 **7,898행**에서 객관식 14·단답형 1·서술형 5를 골랐다. 논리 문항도 20개라 이 실제 표본에서는 형식 쌍 중복이 관측되지 않았다. 별도 합성 재현에서는 동일 문항 객관식/단답형 형제가 한 장에 함께 들어갈 수 있었으므로 전체 경로가 중복에 안전하다는 뜻은 아니다. 선택된 문항은 모두 `manual`이며 새 본문 생성 호출은 없다.

자체 근거 수와 `confidence`는 모두 0이다. 단원 분포는 빈 배열이고 난이도 분포도 모든 칸이 0이다. 이때 조립기의 ‘정확 일치’ 20개는 **학교의 문제 구조와 일치했다는 뜻이 아니다.** 단원·난이도 조건을 알 수 없어 제약 없이 고른 칸도 포함한다. 넓은 범위에서는 인수분해, 근호 계산, 이차방정식, 이차함수, 원, 통계가 섞여 나온다.

좁은 범위에서는 후보 **2,489행**으로 20문항·100점을 채웠으나 서술형 5칸이 단답형으로 대체되었다. 결과는 객관식 14·단답형 6·서술형 0이며 `유형` 완화 5개가 기록됐다. 저장 가드는 빈칸과 100점을 검사하지만 이런 완화 자체를 거절하지는 않는다. ‘문항을 다 채움’과 ‘요청 형식/학교 특성 충족’을 따로 판정해야 한다.

경산여중 등 자체 기출 1편이 존재하는 다섯 학교로 바꾸면 문항 수와 응답 형식 비율은 각 학교의 과거 분포대로 달라졌다. 따라서 학교 조건 코드가 전혀 작동하지 않는 것은 아니다. 다만 현재 자료는 문항별 단원과 난이도 라벨이 모두 비어 있고, 문제군·풀이 구조를 학교별로 배우거나 생성기로 넘기는 연결은 없다. 현재 학교명을 바꾸어 얻을 수 있는 것은 주로 시험지 형식의 차이다.

검증은 환경 파일과 기본 테스트 설정을 읽지 않는 전용 Node 설정으로 수행했다. 실제 서비스 실행 21개 조건을 포함한 탐사 테스트 1개가 통과했고 원본 JSON·탐사 소스·설정 해시를 [runtime-verification.json](runtime-verification.json)에 기록했다. 대표 20문항의 실제 저장 본문·정답·해설·그림도 별도 읽기 전용 조회로 확인했다. 이 확인은 저장된 문항이 실재한다는 증거이며 모든 문항의 수학적 정답 검수나 학교 원본 대비 일치율 측정은 아니다.

개선 시 먼저 자체 기출 자료와 태그의 실제 가용성을 회복하고, 청사진의 풀이 구조와 논리 문항 ID를 생성/선택 단계까지 전달해야 한다. 다른 학교 대체, 형식 완화, 자체 근거 없음은 결과에 명시해야 하며, 새 유형 추가만으로 이 연결 문제가 해결되지는 않는다.
