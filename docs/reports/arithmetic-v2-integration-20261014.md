## 생성·저장

### 생성되지 않던 형태의 보강

원인은 문항 원본이나 AI 호출의 부족이 아니라 기존 생성 규칙의 피연산자 제한이었다. 예를 들어 두 자리 뺄셈은 두 수 모두 두 자리이고, 분수·소수 이항 연산은 양쪽 모두 정수가 아닌 경우만 받았으며, 중등 정수 나눗셈은 정수 몫만 생성했다. 해당 규칙은 기존 문서의 호환성을 위해 그대로 두고 새 ID로 보완했다.

- 초등 18유형: `13−7`, `305−27`, `8÷2`, `2.4×3`, `3÷0.6`, `3−0.4`, `3÷½`, `2−3/5`, `2⅓+⅙`, `3÷4`, `20−3×4`와 자연수·소수·분수의 나머지 주요 혼합 피연산자 조합.
- 중등 수치 7유형: `(-3)÷2`, `-2+1/3`, `-3+2×(-4)`, `(-1/2+3/4)÷(-2)` 등 정수·분수의 사칙과 연산 순서.
- 문자식·근호 6유형: `2(3x−4)`, `(6x−9)÷3`, `(1/2)x+(1/3)x`, `(-2x²)³`, `√8+√3−√2`, `√2(√3+2)`.

새 31유형의 개별 도메인 크기 합계는 2,414,896이다. 이는 유형 사이의 중복을 제거한 총 문항 수나 무한 생성 보장이 아니다. 각 유형의 숫자 범위와 정확한 생성 가능량을 카드에 표시하며, 한 학습지의 중복·수량 부족은 공통 엔진이 처리한다. 초1의 기존 기초 연산은 v1에 유지하며 새 학년 필터에는 실제 유형이 있는 초2부터 중3까지만 순서대로 표시한다.

최초 53유형의 ID·인덱스·식·정답은 바꾸지 않았다. 보강 전 캡처한 `arithmetic-v2-original-53.json`을 고정해 재열기와 동일 시드 재생성이 완전히 같은지 검사한다. v2 자체는 아직 운영 저장을 활성화하지 않은 로컬 통합 단계이며, 새 유형을 저장하기 전 모든 독자가 해당 ID를 읽는 버전이어야 한다.

- 유한한 정수 인덱스에서 숫자를 선택하고, 정확한 정수·유리수·다항식·근호 정규형으로 답을 계산한다. 유료 AI API나 문항 대량 적재 없이 웹에서 요청할 때 생성한다.
- 같은 시드와 버전은 같은 문항을 재현한다. 새 시드는 새 표본을 고르지만 모든 숫자가 반드시 달라지는 것은 아니다. 같은 회차 안에서는 표시되는 식의 중복을 제거하며, 가능한 수량이 부족하면 정확한 부족 오류를 반환한다.
- v2 생성·카탈로그 API와 엄격한 스냅샷 계약을 추가했다. 저장·재열기·복사·관리자 미리보기·문항 수·사용 라벨 독자는 v1/v2를 명시적으로 구분한다. 저장된 문서를 열 때 식과 답을 다시 뽑지 않는다.
- 계정별 원본 저장 문서의 사용 기록으로 새 유형 라벨도 집계한다. 순위는 같은 연산 묶음 안에서 비교하며, 표본이 부족하거나 조회에 실패한 경우 순위를 만들지 않는다. 미리보기와 생성만으로 출제 기록을 쌓지 않는다.

## 화면·지면

- 승인된 유형 카드+구성판을 유지하고 학년·연산 영역·검색을 추가했다. 실제 구현된 학년과 영역만 표시한다.
- `학년별 연산`과 `기초 연산 · 세부 조건`을 오가도 양쪽 초안을 보존한다. 저장 문서의 버전에 맞는 편집기로 연결한다. 미저장 변경과 진행 중 작업 상태를 합쳐 상위 화면에 전달한다.
- 구성 → 즉시 생성 → 문제지/정답지 미리보기 → 저장/출력 흐름을 연결했다. 저장된 서로 다른 회차 구성은 그대로 복원하며, 다시 만들 때는 1회차 구성을 사용한다는 안내를 표시한다.
- 문제지에는 식과 답란을, 정답지에는 답만 배치한다. 공통 MathText·PaperStrip·A4Page와 paper 토큰을 사용한다.
- 짧은 자연수·소수 연산은 쪽당 12/24문항을 선택한다. 분수·문자식·근호식이 포함되면 12문항으로 제한하고 화면에 이유를 알린다. 정답지는 3열, 최대 48개 답/쪽이다.
- 실제 PDF 검사에서 발견한 24문항 분수·문자식의 줄 겹침을 밀도 제한으로 해결했다. 12문항 근호식은 공통 셀의 큰 글씨를 상속하지 않도록 지면 수식 글씨를 15pt로 명시했다.
- 개발 확인 화면의 작은 화면 가로 넘침도 수정했다. 화면용 개발 경로는 기존 dev 접근 제한을 사용하고 DB에 저장하지 않는다.

## 검증 근거

최종 보강 통합에서 **20파일 805개 테스트 통과**, 전체 `npm run type-check` 통과. 통합 타입 검사에서 찾은 새 수치 연산 테스트의 두 타입 오류를 수정한 뒤 해당 67개 테스트와 전체 타입 검사를 재확인했다. 아래 최초 53유형의 검증 기록과 수를 합산하지 않는다.

- 초등 보강 67개 테스트: 18개 도메인의 수량을 별도로 열거하고, 작은 12개 도메인 32,056후보 전수와 큰 6개 도메인 24,380표본을 독립 오라클로 검사했다.
- 중등 수치 보강 67개 테스트: 7유형 84,356후보 전수. 표시된 식을 별도로 해석해 정답·인덱스·중복·변조·0 제수·경계·KaTeX를 검사했다.
- 문자식·근호 보강 41개 테스트: 6유형 40,908후보 전수. 계수 역연산, 별도 제곱인수 분해, 여러 근호 항과 최대 12차 단항식의 정규형·발문 대응을 검사했다.
- 실제 카탈로그를 사용하는 API 통합 검사는 84유형 모두를 생성하고 다시 읽었다. 인증은 테스트 세션을 사용하며 생성 중 DB 접근이 없고 저장 플래그가 꺼져도 생성되는지 확인했다.
- Orca 개발 미리보기에서 새 `자연수 ÷ 소수` 유형 담기 → 10문항 생성 → 같은 조건으로 다른 식 생성 → 정답지만 전환을 확인했다. 문제지 10답란·정답지 10답, 풀이 없음, KaTeX 오류 0.
- 실제 A4 PDF: 전체 84유형 9쪽(문제 7+정답 2), 새 세 근호 항 유형 100문항 12쪽(문제 9+정답 3). 수식·답란의 셀 경계 넘침 0, KaTeX 오류 0, 새 유형 지면과 정답 페이지를 PNG로 확인했다. 로컬 QA 파일은 `tmp/pdfs/arithmetic-supplement-all84.pdf`, `tmp/pdfs/arithmetic-supplement-radicals.pdf`이며 저장소에 넣지 않는다.

- [초등 엔진 보고](arithmetic-v2-elementary-20261014.md): **65개 테스트 통과**. 작은 19개 도메인 167,530개 전수 검사와 큰 8개 도메인의 경계·결정적 표본을 포함해 187,996개 후보 검증.
- [중등 엔진 보고](arithmetic-v2-middle-20261014.md): **72개 테스트 통과**. 26유형의 456,360개 후보 전수 검사, 별도 정답 오라클, 매개변수·발문·LaTeX 대응, 208개 KaTeX 표본 렌더링.
- [코어·API·저장 보고](arithmetic-v2-core-20261014.md): 통합·기존 회귀 **11파일 530개 테스트 통과**. 최종 중등 변경 후 중등/실제 유형 통합 **2파일 128개 재확인**. 이 수는 앞의 테스트와 겹치므로 합산하지 않는다.
- 화면·출력 **5파일 14개 테스트 통과**: `ArithmeticWorkbench`, `ArithmeticWorkbenchRouting`, `GradeArithmeticWorkbench`, `GradeArithmeticPaper`, `UsageLabels`. 실제 엔진으로 재생성, 저장 시 revision, v1/v2 경로, 양쪽 초안 보존, 변조 답 거절, 문제/정답 분리, 회차별 페이지와 밀도 제한을 검사했다.

- Orca 실제 브라우저에서 학년 선택·유형 담기·10문항 생성·문제/정답 전환을 확인했다. 390px 화면의 가로 넘침을 수정했고, 데스크톱 필터 3열·단일 h1·KaTeX 오류 0을 확인했다.
- 실제 A4 PDF: 53유형과 큰 분수·다항식·근호 경계를 포함한 7쪽(문제 5쪽+정답 2쪽), 자연수 24문항 밀도 표본 2쪽을 생성해 렌더링 검사했다. 수식·답란의 셀 경계 넘침 0, KaTeX 오류 0. 제목 200자 경계도 DOM에서 넘침 0을 확인했다. 로컬 QA 산출물은 `tmp/arithmetic-v2-12.pdf`, `tmp/arithmetic-v2-24-natural.pdf`이며 저장소에 추가하지 않는다.

## 운영 적용 범위

이 작업은 로컬 구현과 통합 검증이다. 푸시·배포, DB 스키마 적용, 운영 저장 플래그 활성화, 운영 계정의 실제 저장은 수행하지 않았다. 저장 경로는 메모리 저장소 테스트로 검증했고 기존 `ARITHMETIC_SHEET_WRITE=on` 조건을 보존했다. 실제 프린터 출력은 미실시다.

초등·중등·코어는 Orca의 독립 Codex 작업 세션에서 구현해 main에 병합했다. 완료된 세션은 실행을 종료하고 깨끗한 병합 상태를 확인한 뒤 작업트리를 정리했으며 Git 브랜치는 보존했다.
