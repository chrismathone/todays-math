# 수학 엔진의 실제 범위·원전 근거·문항 품질

감사 소스는 **`cd067a49a90283749ea9f525073a4a469eef54bd`**다. 최초 체크아웃 `e9ba95291`은 보존하고 별도 브랜치에서 지정 기준을 조사했다. DB에는 접속하지 않았다. root가 2026-10-18 13:58 KST에 읽기 전용으로 확보한 **118,020행 / 출제 가능 115,575행** 스냅샷을 스트리밍으로 읽었다. SHA-256은 `daf90c9a97e0630bb8be372e873187603f1fdbf5a201de18c009e266f7cfbac3`다.

**기초 반복에 쓸 수 있는 기반과 일부 응용·추론 문항은 충분히 존재한다. 다만 현재 엔진 전체를 검수된 기출 대체재로 판정할 근거는 없다.** 실제 출제 가능 문항에서도 계산 없이 범위만으로 답을 고르는 객관식을 확인했다. 증명이라는 색인 제목과 실제로 요구하는 사고가 다른 경우, 핵심 경우를 생략한 해설, 유형 사이의 같은 질문도 남는다. 초등의 확정 오류 4문항류·14행은 [별도 검수](elementary-quality.md)와 교차 확인했다.

모든 등록 키와 출처 지도, 65개 재고 후보의 개별 판정, 정확한 UUID·해시는 [engine-comparison.json](engine-comparison.json)에 있다. 제품·생성 소스·DB 수정, 재적재, 배포, push는 하지 않았다.

## 3. 최소 확정 품질 한계

### ENG-Q01 — 삼각비 객관식이 범위만으로 풀리는 경우

대상은 `3-2|삼각비|01`이다. 실제 `expandFamily`, familyKey=`mid:3-2|삼각비|01`로 seed 0~99마다 서로 다른 변형 3개를 요청했다. 객관식 **300관측**을 얻었으며, 발문의 두 변 길이를 다시 읽어 빗변을 계산하고 sin/cos/tan 값을 독립 계산했다. 답 위치·값·유일 정답 불일치 **0**이었다. seed 사이의 중복까지 제거한 300문항이라는 뜻은 아니다.

그중 sin/cos 물음 **195개 전부**에 예각의 범위 `0<sin A,cos A<1`을 벗어나는 오답이 하나 이상 있었다. **18개는 오답 4개 전부가 범위를 벗어나**, 변의 비를 계산하지 않아도 답이 정해졌다.

재현 예: seed 0에서 얻는 변형 중 `AB=10`, `BC=24`, `∠B=90°`, sin A를 묻는 판의 선지는 `25/13, 1, 12/13, 24/13, 120/13`이다. 답 `12/13`은 옳다. 다만 나머지 네 값은 모두 예각의 sin 값이 될 수 없다. 발문/선지 SHA-256은 JSON에 있다.

스냅샷에서도 해당 family의 출제 가능 **24행** 중 sin/cos 객관식은 **9행**, 9행 모두 범위 밖 오답이 있었으며 다음 **1행**은 네 오답 전부가 제외된다.

- 코드 `J30501-A01-002`, UUID `599405f6-3dab-4a35-8aba-b6e111c2507c`

이는 **정답 오류와 다른 객관식 변별력 결함**이다. 공용 `numericMistakes`의 수 변형에는 삼각비의 정의역/치역 조건이 전달되지 않는다. `declaredUpperBound`는 전체 일을 1로 놓는 등의 명시적 문구만 읽는다. 해당 비율의 범위와 풀이에서 실제로 나올 법한 오답을 함께 설계해야 한다. 18/195를 전체 은행의 오류율로 외삽하지 않는다.

### ENG-Q02 — 증명 색인과 실제 수행 과제의 차이

`2-2|피타고라스 정리|05`와 `|06`의 정본 제목은 각각 유클리드·피타고라스의 **증명**이다. 실제 생성기는 모두 정사각형의 **넓이 수치**를 묻는다.

- `05`, seed 0: 두 직각변 15, 8에서 빗변 위 정사각형의 넓이 289를 계산한다. 유클리드의 넓이 대응은 발문에 이미 설명되어 있고 이를 학생이 구성·정당화하도록 요구하지 않는다.
- `06`, seed 0: 바깥 정사각형 변 31, 직각변 7·24인 풍차 배치에서 중앙 넓이 625를 묻는다. 해설은 `피타고라스 정리에 의해 c²=7²+24²`라고 한다. 넓이 차 `(7+24)²−4×(7×24/2)`를 통해 정리를 설명하는 과정은 요구하지 않는다.

해당 두 family의 출제 가능 재고는 **14+14행**이다. 수치 답이 틀렸다는 뜻은 아니다. **등록 2개를 ‘두 증명 방법을 수행하는 문항까지 구현’으로 세면 거짓 양성**이라는 확인이다. 원래 RPM 문항이 어느 수준을 요구했는지는 이번에 원본 PDF를 읽지 못했으므로 판정하지 않는다.

### ENG-Q03 — 경우를 세는 해설에서 실제 경우를 생략

`2-2|경우의 수|02`는 “표로 정리하여 세면”이라고 하지만 표·성공한 동전 조합을 제시하지 않는다(`middle/m2Counting.ts:340`). seed 0의 100원 6개·50원 4개로 650원을 지불하는 문제는 독립 나열하면 `(100원 개수,50원 개수)=(5,3),(6,1)`로 **2가지**다. 답 2는 옳지만 그 근거가 해설에서 빠진다. 이 family의 출제 가능 재고는 **12행**이다.

전체 sweep의 해설 생략 휴리스틱은 중등 **4,551관측 중 543**, 3관측 모두 걸린 유형 **172개**를 냈다. 이는 문구·수식 수에 의한 **후보**다. 이 172개를 모두 부실 해설로 확정하지 않았으며, 별도 수작업으로 확인한 위 사례와 구분했다.

### ENG-Q04 — 새 유형으로 더하면 중복되는 하위 과제

`2-2|경우의 수|01`은 주사위 합·차와 카드 배수의 세 가지 가지를 가진다. 확장 `|70`은 그중 **주사위 차** 가지와 발문·답이 같다. 다만 해설은 70이 더 상세하다. 100seed×3variant를 읽어 해당 가지 **394관측**을 순서쌍 36개 나열로 독립 검산했고 불일치 0, 두 경로의 차 1~4 질문 **4개 모두 중복**을 확인했다.

저장본에서도 family 70의 UUID `08abe7f4-97c0-4f39-a672-9e8c8f94c248`와 family 01의 `1a6c2264-01a9-4518-8dc0-e52b852d7816`, `a9224b35-ce8e-416e-9420-92d9ee587152`는 선지를 제외한 질문이 정확히 같다. **수학적 유형 다양성의 중복**이며, 답 오류나 실제 시험지에서 중복 출제되었다는 판정은 아니다.

## 4. 복제 후보·변형 수의 거짓 양성 제거

함수의 `handler.toString()`이 같은 그룹은 17개였다. 고등 **168개 전체도 하나의 공통 wrapper**로 묶인다. wrapper가 캡처한 `gen` 함수는 서로 다르므로 이것을 복사 문항 168개라고 세지 않는다. 반대로 중등 결합형 6개 중 3개는 등록부에 원래 유형으로의 **위임**을 명시하며 실제로 같은 생성기를 부른다. 이를 독립 신규 과제 3개로 더하지 않는다.

숫자를 지운 질문 구조의 3관측이 같은 후보 그룹은 2개였다. 주사위 01/70은 위에서 확인했고, `3-2|상자그림과 산점도|50/51`은 **제1사분위수와 제3사분위수**를 각각 묻는다. 숫자 마스킹이 물음의 차이를 없애 만든 거짓 양성이므로 복제 판정에서 제외했다.

root의 재고 조사에서 질문/그림 기준 5개 미만인 **중등 59개+자작 서술형 6개 전부**를 읽고, 각 300variant를 생성했다. 총 **19,500관측**이며, 선지 순서만 다른 경우를 새 변형으로 세지 않았다.

합동 조건 유형 10도 선지 조건을 포함해 읽었지만 실제로는 세 config뿐이라 마지막 그룹에 남는다. 자작 서술형 6개는 저장본이 각각 **2개**지만, 300관측에서 서로 다른 질문이 **7,20,113,140,183,184개**였다. 이것은 샘플의 하한이며 생성 가능한 최대치가 아니다.

**5개는 이번 감사의 비교 시나리오이며 제품의 새 필수 기준이 아니다.** 같은 성질을 다시 확인하는 용도와 서로 다른 문제를 반복 연습하는 재고를 구분한다. 숫자·선지 순서·단답/객관 형식만 늘어난 수를 사고 방법의 수로 읽지 않는다.

소스와 저장본의 시점 차이도 있다. 지정 소스에는 없지만 스냅샷에 들어 있는 초3·초5·초6의 문형 31/32 **14 family·42행**을 root 결과와 대조했다. 별도 소스 `e331f90c6`와 적재 이력 `550096afc`가 있는 변경이다. 이를 잘못된 문제나 삭제된 재고로 단정하지 않지만 **감사 기준 소스만으로 재생성되는 재고라고 말할 수는 없다.** JSON에 14개 전부를 보존했다.

## 5. 실제 기출의 로컬 근거와 비교한 세 표본

원본 RPM PDF는 체크아웃과 root의 `.rpm-src`, 기존 소스 작업 폴더에서 찾지 못했다. 정본 JSON은 파일명·페이지·유형 제목의 색인이며 문제 본문은 없다. 외부 자료를 임의로 찾아 원전이라고 대체하지 않았다.

기출은 스냅샷의 이관 텍스트와 저장된 **원본 그림 crop 3개를 직접 열어** 확인했다. 전체 원본 PDF의 문항 위치·번호·완전한 조판을 재검증한 결과는 아니다. 다음 세 문항은 그림과 발문에서 조건을 읽어 다시 풀었고 저장 답과 일치했다. 모두 출제 불가 재고다.

| 기출 external ID / UUID                                                 | 독립 풀이 요지                                                                               | 생성기와의 비교                                                                                                                                                                                                   |
| ----------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `2025-gyeongsanyeo-3-2-mid-20` / `0d4928b0-3340-49b1-9240-0366bcc1bd67` | 반현 12, 활꼴 높이 8에서 `r=(12²+8²)/(2×8)=13`, 둘레 `26π`                                   | `3-2\|원과 직선\|03`도 같은 현/높이 반지름 복원식을 사용한다. 엔진 seed 0은 반현 4·높이 2에서 반지름 5를 묻는다. 기출은 깨진 접시의 상황을 읽고 둘레로 한 번 더 전환한다. **같은 핵심 응용이 존재한다**는 근거다. |
| `2025-dongdo-3-2-mid-4` / `03a1b248-a86e-4dc3-b86e-69f9b8b906df`        | 단위 정사각형에서 같은 두 변으로 E/F 위치의 대칭을 얻고 30° 조건을 적용하면 `AE:DE=(√3+1):2` | 정사각형·이등변·각 추론·삼각비·비의 정리가 함께 필요하다. 엔진 전체가 이러한 합성을 동등하게 공급하는지는 이번에 확인하지 못했다.                                                                                 |

이 세 표본은 엔진이 단순 숫자 계산만 한다는 주장도 지지하지 않는다. 현 복원·외부 수선·신규 서술형의 오류 진단과 정당화처럼 실제 응용이 있다. 다만 **동일 개념, 같은 단원, 색인 제목 일치를 원전의 모든 사고 요구와 난도에 대한 동등성으로 확대할 수 없다.** 교과서 전수 원문 비교는 별도 담당의 결과를 따라야 한다.

## 7. 사용 목적별 판정과 남은 일

| 목적                                 | 현재 근거로 내릴 판정                                                                                                                       | 필요한 보완/확인                                                                                                        |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| 기초 계산·성질 반복                  | **검수된 범위에서 조건부 충분**. 많은 생성 경로와 유한 계산 영역이 있고 답의 독립 검산도 일부 존재한다.                                     | 초등 확정 오류 4문항류·14행을 먼저 보완하고, 유한 질문 1~4개와 풍부한 연습 재고를 구분한다.                             |
| 응용·추론 학습                       | **일부 유형은 충분하나 전 범위 충분 판정은 불가**. 실제 현 복원·외부 수선·6개 자작 서술형이 있다.                                           | 증명 능력을 요구하지 않는 증명 라벨, 생략된 경우 나열, 다른 family의 같은 하위 과제, 영역만으로 풀리는 오답을 보완한다. |
| 실제 학교 시험의 대체·동등 난도 세트 | **현재 증거로는 부족**. RPM 색인 완성도는 사고·난도 동등성의 검증이 아니며, 원전 검토는 기출 3표본뿐이다. 고등은 미구현·미적재 경계도 크다. | 원문·그림·풀이의 단계를 보존한 기준 표본을 정하고 유형별 사고 동작·오답·독립 풀이·시험지 조합을 검수해야 한다.          |

우선순위는 **출제 가능 오류와 범위만으로 정해지는 객관식 → 해설/증명 과제 보완 → 중복을 제외한 유형·변형 수 → 원전 기반 시험 적합성 검증**이다. 자동 신호를 확정 오류 수로 세거나 전체 행을 독립 풀이했다고 보고하지 않는다. 공식 성취기준 완전 정합성이나 측정된 학습효과도 이번 감사의 결론이 아니다.

재현: `node_modules/.bin/tsx scripts/qa/bank/type-audit-engine.ts <출력 폴더>`가 현재 전체 등록부·3관측·형식·별도 연산지 경계 관측을 만든다. root의 65개 후보/선택된 564행 로컬 입력을 `--thin-families <JSON> --thin-rows <JSONL>`로 주면 선택지 조건을 보존한 300variant 재검토도 수행한다. 타깃 300문항·900렌더·저장본 교차 확인의 정확한 입력과 로그 해시는 JSON에 기록했다.
