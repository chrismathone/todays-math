## Delivered behavior

- Class access uses current membership, capabilities, Korea-local effective dates, active class state, immutable binding/branch identity, and the exact permission revision. Delegation is read-only even if malformed capabilities request writes. Normal end dates are inclusive; transfer end dates are exclusive. Manual pending handover does not silently transfer authority.
- Managed teachers cannot regain access through historical `userId` authorship. Current class authority covers operational tests/materials; private prediction documents remain author-private. Nonmanaged math behavior and English ownership remain supported, with English branch identity frozen on the resource rather than inferred from the creator's current branch.
- Students use stable identities and multiple enrollment records. Class/student operations use the requested enrollment, not the legacy primary-class pointer. Withdrawn, held, and test students are excluded where appropriate; retained historical records are not deleted. Progress and enrollment report metadata remain scoped to the actual class. Retired progress is excluded from effective reads.
- Binding OFF, retirement, stale permissions, and source errors fail closed. Idle learner sessions refresh expired control state and reread it; a source failure does not extend the prior lease. Student membership does not inherit suspension of a departed teacher.
- Class/student/progress/plan/test, daily planning, account issuance, math SRS, explorers, metrics, listening assignments/materials, and print paths use the shared access policy, including transaction-time checks on writes. English print headers use the exam's frozen branch.
- Legacy sync transport and database writers are fenced from managed bindings, including OFF/retired bindings. Auto-draft retains the explicit existing2 class allowlist even if broader roster import configuration is supplied. Automatic jobs skip unavailable or OFF bindings.

## Integration interfaces

`src/lib/eywa/managedRelations.ts` exports `applyEywaRelations(tx, manifest, rows)`. The receiver calls it inside its transaction only after validating the complete typed manifest, counts, hashes, and source context, and applying managed account identities. It enforces immutable identity, revisions/generations, complete enumeration, resource-local conflicts, and confirmed account mappings. OFF/shadow manifests do not apply operational relationships. Missing or ended memberships/enrollments/progress are revoked or retired without deleting history. Imported progress preserves stable report identities, class/makeup context, enrollment-local report metadata, and existing derived class-progress behavior. Ambiguous or conflicting resource context is held rather than merged by display name or rewritten globally. Returned counts include derived progress, unresolved/deferred resources, and conflicts.

`src/lib/classAccess.ts` provides the per-request access scope, operational roster queries, `assertClassWrite`, and `assertStudentEnrollment`. Write authorization refreshes source state before taking class row locks, then compares the local class revision to current authority inside the transaction; callers recheck the requested student enrollment after the class lock. `ClassAccessDenied` maps to HTTP 403. Multiple classes and students remain independent.

`activeStudentClassIds` refreshes expired binding state through the auth worker's `refreshManagedBinding`, which fetches before its own short database transaction. Callers must not hold binding/user/class row locks before that refresh; the existing listening caller performs plain reads under ReadCommitted, then rereads current state. Source failure remains unavailable, not an authorization grace period.
