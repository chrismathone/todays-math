# 기출 대비 엔진 1차 업그레이드

2026-10-18 · problem_make · 최종 로컬 통합 검수 통과

학교 원문을 DB에 복원하지 않고, 검토한 추상 수학 요구로 새 문제를 실제 생성하는 경로를 구현했다. 기존 `/exam`에서 `/exam/practice`로 들어가 학교·학년의 검토 범위 또는 일반 유형을 고르고, 문제·그림·풀이를 확인한 뒤 공통 시험지 양식으로 출력한다. [Claude 계획 검토](claude-plan-review.md)의 조건을 반영한 [실행안](../../planning/math-exam-engine-upgrade-20261018.md)을 기준으로 구현했다.

## 실제 제공 흐름

- `GET/POST /api/exam/practice`가 기존 계정·승인·역할·메뉴 권한과 동일 출처 검사를 통과한 교사에게 카탈로그와 실제 생성 결과를 제공한다. 기존 예측 이력과 저장 문항 선택 경로는 별도로 유지한다.
- 검토한 학교 프로필은 학교명 문자열이 아니라 요구 ID와 조건 의존 관계로 출제한다. 학교명만 주는 API 요청은 검토된 별칭을 찾을 수 있다. 유형을 직접 고른 요청에서는 학교 이름이 수학 문제·요구·내용 지문을 바꾸지 않는다.
- 요청한 학년·형식·난도·문항 수·유형 상한을 유지한다. 필요한 그림이나 검산·본래 서술 기준이 없으면 그 문항을 제외하고 `partial / unavailable`과 빠진 요구를 표시한다. 문항 수를 채워도 요구가 부족하면 `complete`가 아니다.
- 문항은 형식과 분리한 논리 정체와 내용 지문으로 중복을 검사한다. 객관식·단답형이나 보기 순서를 문항 수에 곱하지 않는다. 정답·풀이는 처음에 닫혀 있고, 과정 서술에는 모범 풀이·배점·허용 대안·흔한 오류를 보존한다.
- 재생성에서 현재 세트와 같은 논리 조합이 나오면 최대 3회 요청 안에서 다른 조합을 찾는다. 찾지 못하면 기존 문항과 안내를 유지한다. 무제한 새 문제나 과거 모든 회차와의 중복 방지를 약속하지 않는다.
- 출력은 기존 `WorksheetEditor`와 여섯 양식·인쇄/PDF/HWPX 클라이언트다. 기본 워크북에는 ‘기출 대비 자작 연습’과 풀이 공간을 넣었다. 출력 직전에 같은 레시피와 내용 지문을 서버에서 다시 확인한다. 저장하지 않은 생성 문항을 DB UUID로 가장하거나 미구현 저장 버튼을 제공하지 않는다.

## 새 수학 과제와 수량의 의미

중1·중2 **12개**, 공통수학2·중3·기하 **11개**, 합계 **23개 자작 가족**을 추가했다. 이 중 17개는 단답형, 6개는 본래 과정 서술형이다. 신규 객관식 형식은 선언하지 않았으며, 기존 adapter의 지원 형식과 요청 형식을 실제 출력에서 검사한다.

중등은 꺾은선의 복수 판단, 공유 변 정사각형, 반비례의 넓이비·동일 길이·부호 사다리꼴, 두 광선 분할, 연립식의 해 이동, 사다리꼴의 두 경우, 단위·최소 시간·연료·정지 이동·작업률 설명을 포함한다. 고등·기하는 진리집합 포함과 중간 집합, 제한 이차함수의 일대일대응, 근호곡선 넓이, 결손 정의역의 절댓값 유리함수, 유한 합성·역함수·반복 함수, 포물선과 직선의 연쇄 복원, 서로 다른 내심·외심과 내심·내접원 제외 넓이를 포함한다.

전수 검사한 유한 정규 매개변수 튜플은 **120 + 1,121 = 1,241개**다. 새로운 사고 구조나 무제한 문항 수가 아니다. seed·보기·응답 형식은 이 수를 늘리지 않는다. 기존 adapter의 **4,190개는 등록 항목 수**이며 새로운 가족 수·서로 다른 사고 유형 수·학교 대응률로 사용하지 않는다. 기존 등록부와 학생 기록은 바꾸지 않았다.

상세 저작·독립 검산과 경계는 [중등 기록](middle-implementation.md), [고등·기하 기록](advanced-implementation.md), [공통 엔진 기록](core-implementation.md)에 있다.

## 실제 API 생성에서 확인한 학교별 범위

같은 검토 자료와 학년을 선택하고 혼합 12문항, 유형당 최대 3문항으로 실제 API와 Python 그림 경로를 실행했다. 아래 ‘완결 요구’는 선택해 검토한 추상 요구 중 해당 실행에서 완결 연습을 제공한 수다. 원문 문항별 대응률·학교 시험 전체 범위·출제 빈도나 적중률이 아니다. 자료의 미확인 문항은 충족으로 계산하지 않는다.

| 검토 프로필      | 실제 제공 | 완결 요구 / 선택 요구 | 남은 보강·확인                                                                        |
| ---------------- | --------: | --------------------: | ------------------------------------------------------------------------------------- |
| 대륜중 중1       |        12 |                8 / 11 | 배증 시간차, 회전수 백분율, 서로소 잔여류 합                                          |
| 대륜중 중2       |        12 |                8 / 10 | 절편의 정수 넓이 조건, 이동한 그래프의 계수 재사용                                    |
| 경명여중 중1     |        12 |                 2 / 7 | 일차식 정리·등식·방정식 분류·모델·후보 검증의 기존 대응을 독립 검산으로 승격하는 작업 |

다섯 실행은 모두 부족한 요구가 남아 **부분 제공**으로 표시된다. 특정 지원 요구만 골라 요청 수까지 충족하면 그 선택 범위에 한해 완전 제공한다. 미검토 학교는 일반 유형 연습을 사용할 수 있으나 이름만으로 학교 특성을 만들어 내지 않는다. 학교 전체 기출·실측 난도·학생 학습 효과·공식 교육과정 전수 정합성은 확인한 범위가 아니다.

## 검수와 수정

독립 검토에서 일반 유형의 학교 라벨이 프로필을 끼워 넣는 결함과, 고등·기하 그림 글자가 실제 인쇄 폭에서 작아지는 결함을 찾았다. [일반 라벨 수정](general-school-label-fix.md)과 [실제 인쇄 가독성 보강](advanced-print-fix.md)을 통합한 뒤 두 건 모두 별도 재현 검사로 닫았다. [독립 검토의 최종 결론](independent-implementation-review.md)은 문서화한 부분 지원 범위에서 수용이며, 해결되지 않은 차단 지적은 없다. root는 실제 반복 생성에서 다른 seed가 같은 수학 과제로 이어지는 경우를 재현해 유한 재시도와 유지 안내를 추가했다.

학교 자료를 읽는 외부 로그인 세션이나 운영 DB 없이, 로컬에서 승인 교사 세션만 합성하고 실제 권한 정책·API·수학 생성기·Python·문항 UI·공통 출력 소스를 실행했다. 실제 서비스 로그인/배포 검증과 구분한다. 학교 원문·수치·도형은 새 생성 입력으로 사용하지 않았고, 새 생성에 유료 모델·DB 적재는 필요하지 않다.

실제 프린터에서 출력한 종이 검수는 완료로 표시하지 않으며, `/dev/print-check`의 새 두 항목은 ‘대기’다.

## 재현 근거 위치

현재 워크스페이스의 `.qa-artifacts/math-exam-engine-upgrade-20261018/`에 환경 파일을 읽지 않는 설정과 로그·원본이 아닌 자작 생성 결과·화면·지면 검수 자료를 보존한다.

- `task_78b12334131b-evidence/`: 공통 엔진·기존 여섯 양성 대응의 독립 검산·재현.
- `task_5559f9a5c813-evidence/`: 중등 120개 튜플·56개 실제 SVG와 배치 검사.
- `advanced-evidence/`: 고등·기하 1,121개 튜플·117개 실제 SVG의 최초 저작 검수.
- `general-label-fix-evidence/`: 학교 라벨의 수정 전후 행렬과 호환성 검사.
- `advanced-print-fix-evidence/`: 실제 출력 폭의 글자 크기·배치·불변 수학 비교.
- `independent-review-evidence/`: 별도 저술 검산, 조립·권한·비동기 경계와 독립 화면/출력 검수.

모든 검사는 기존 의존성과 Node 24, Python 3.12를 사용했다. DB 스키마·학교 원문 적재·provider·Prisma generate·빌드·원격 push·운영 배포는 이 검수에 포함하지 않는다. 실행 코드의 타입 검사·린트, 실제 수학·그림 검산, 합성 인증의 권한 경계와 브라우저 검수로 구현 범위를 확인한다.
