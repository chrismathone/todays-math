시험지 만들기 · 문제 추출 초기 로딩 수정 (2026-10-09)

사용 흐름
교사 작업실에서 시험지 만들기를 열어 범위를 정하고 문항을 구성한 뒤 공통 양식 구성·출력 화면으로 이동한다. 기존 작업 복원 중 화면 코드를 준비하되 복원이 끝나기 전에 편집하거나 저장하지 않는다.

확인한 원인
- 운영 origin/main 84e94834a는 BankView를 사용하고 2 문제 선택을 현재 단계로 표시한다. 확정 D안 MathExamBuilder/EnglishExamBuilder 연결은 로컬 main에만 있었다. 운영 브라우저에서도 현재 단계 '2 문제 선택', AI 상태판 표시를 확인했다.
- 로컬 D안은 복원한 문항이 있으면 검토 단계부터 시작했다. 문항은 유지하면서 새 진입은 범위 설정부터 열도록 변경했다.
- 인증 작업실 SSR은 처음부터 문제 12개의 본문·그림·출처를 조회했다. D안이 초기 화면에서 사용하는 것은 단원과 수량 정보다.
- 직접 #bank/#studio 진입 시 작업 복원 다음 화면 모듈을 불러오는 순서가 생겼다.
- 추출 세션은 원본 파일들을 차례로 받은 뒤 잘라낸 문제 이미지를 복원했다.

변경
- 시험지 만들기는 1 범위 설정으로 진입하며 복원된 문항·제목은 유지한다.
- AI 상태판은 production에서 렌더링하지 않는다. 실제 AI 실행 provider는 유지하며 운영에서는 auto로 요청하는 회귀 검사도 유지한다.
- loadUnifiedBankBootstrap은 수량·단원·학년·장 메타데이터만 반환한다. 문항 조회와 기존 필터/권한은 문항 구성 및 후보 조회 API에 남긴다.
- 제공된 Math 단원은 initialScopes로 첫 렌더에서 즉시 사용한다.
- 메뉴 hover/focus, 새 작업, 직접 진입에서 해당 편집기 코드와 작업 복원을 겹친다. 복원 완료 전 편집기 마운트 및 저장 차단은 유지한다.
- 추출 원본과 crop 이미지 복원을 병렬로 시작한다. 기존 전송 동시 상한 3과 실패 시 준비 완료 차단은 유지한다.
- 브라우저 통합 검사 중 발견한 MathLive 서버 번들 오류는 MathTextEditor의 브라우저 전용 dynamic 경계로 수정했다.

한계
제어된 요청 순서와 조회 수의 개선이며 운영 지연 시간 감소율을 뜻하지 않는다. 실제 시간은 계정의 저장 작업 크기, 원본 파일 용량, 네트워크와 서버 상태에 따라 달라진다.
