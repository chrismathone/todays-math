## 0. 한 줄 판정 (한국어 요약)

**후보안(허브 하나 · 전역 일일 원장 · 공용 활동 틀)은 방향이 맞다. 그러나 «완료된 날짜를
모드 구분 없이 합친다»는 원장 규칙은 틀렸다.** 합치면 보드 한 칸이 «어느 날이든 무엇이든
한 가지를 끝낸 날»이 되어, 원장님이 말씀하신 «오늘 정해진 학습량 전체 + 재도전을 끝내야
한 칸»이 깨진다. 칸은 **서버가 그날 처음 열 때 얼린 «오늘의 원정» 한 개**의 완료로만 생긴다.

원정은 **두 모양** 중 하나다. 새 단원 그룹에 들어서는 날은 **«관문의 날»** — 원본 그대로의
5카드·15활동 개념 묶음에 은행 문항 몇 개만 곁들인다. 나머지 날은 **«연습의 날»** — 은행 문항이
주이고 기억 카드 몇 장이 앞에 붙는다. 한 주를 합치면 은행 문항이 과반이다. 개념 15 와 은행 10 을
같은 날 쌓지 않는다.

학생 입구는 `/learn` **한 곳(판)**. 탭 넷은 없애고, 강의는 판 모서리의 자료함과 관문의 날
개념 카드 옆 «영상 보기»로만 닿는다.

## 1. 학생 머릿속 그림 (mental model)

학생이 알아야 하는 것은 셋뿐이다.

1. **판(보드)** = 내가 지금까지 걸어온 길. 칸 = 끝낸 «원정의 날». 칸에 그날의 **단원 이름**.
   단원 그룹 하나가 판의 한 **구역**이고, 구역 첫 칸이 관문이다.
2. **오늘의 원정** = 판의 큰 버튼 하나. 누르면 끝날 때까지 한 틀 안에서 문제만 나온다.
3. **자료함** = 모은 개념 카드(도감)와 강의 영상. 다시 읽기·다시 보기·다시 풀기는 되지만 걸음은 없다.

«개념 탐험 / 초등 복습 / 중등 복습 / 통분 공방 / 기억 퀘스트 / 회복 학습 / 강의 목록»은 **학생의
입구가 아니다.** 앞의 여섯은 원정 안 걸음의 «종류»로, 문제 화면 머리의 작은 꼬리표
(`개념` · `연습` · `다시 보기` · `기초 다지기` · `손으로 해 보기`)로만 보인다. 강의는 자료다.

후보안과 다른 점: 후보안은 «허브 하나 + 모드 여러 개 + 전역 원장»으로 읽힌다. 나는 **모드 자체를
학생에게서 없앤다.** 모드 선택이 남으면 원장 병합 문제(§2)와 탭 문제(§4)가 그대로 돌아온다.

## 2. 칸(일일)과 진도(교육과정)의 분리 — 핵심 결정

두 축을 **절대 한 숫자로 섞지 않는다.**

| 축 | 무엇 | 저장 | 보이는 곳 |
|---|---|---|---|
| **걸음(칸)** | 얼린 원정을 다 끝낸 KST 날짜 수 | 전역 원장 `journey.global[]` (한 날짜 한 행) | 판의 말 위치 |
| **진도** | 교육과정 위치(초등 단원 / 중등 개념 / 탐험 단원 그룹) | 기존 `course`·`missions`·`explorers` 상태 | 칸의 이름표, 구역, «다음 칸» 미리보기 |

칸에 적는 이름은 «그날 원정의 주 단원»이다. 그래서 판은 «걸어온 날»이면서 동시에 «지나온
단원»으로 읽힌다 — 하지만 **말이 한 칸 가는 조건은 진도가 아니라 원정 완료**다.

### 2.1 두 안의 명시적 비교 — «서버가 얼린 원정 1개» 대 «아무 출처든 끝낸 날의 합집합»

현재 `src/lib/math-srs/dailyJourney.ts` 는 `elementary`·`middle` 원장을 따로 두고 각자
`todayGoal`(초등 `dailyQuestionCount ?? 10`, 중등 12)을 센다. 여기에 탐험 쪽 단원 완료까지 더해
날짜 합집합을 내는 것이 «합집합 안»이다.

| 기준 | 합집합 안 | 얼린 원정 1개 안 (권고) |
|---|---|---|
| «그날 전체 학습량»을 지키나 | ✕ — 한 출처만 끝내도 칸 | ○ — 원정 목록이 비어야 칸 |
| 가장 쉬운 출처로 몰리는가 | 몰린다(초등 10문항 < 개념 15 < 중등 12) | 학생에게 고를 출처가 없다 |
| 학생이 모드를 골라야 하나 | 고른다 → 탭·버튼이 되살아남 | 안 고른다 → 버튼 하나 |
| 오늘 할 일이 도중에 바뀌나 | 바뀐다(진도·만기가 바뀌면 목표도 바뀜) | 안 바뀐다(스냅샷) |
| 하루 학습량을 누가 정하나 | 출처마다 제각각 | 조립기 한 곳이 시간 예산으로 |
| 구현 비용 | 작음 — 날짜 합치기만 | 중간 — 조립기·스냅샷·걸음 API. 새 표 없음 |
| 기존 기록 이관 | 그대로 | 과거 날짜만 `global` 로 한 번 복사(같은 날 둘이면 한 칸) |

**결론: 얼린 원정 1개.** 합집합 안은 구현이 싸지만 원장님이 정한 칸의 뜻을 지키지 못하고,
학생에게 출처를 고르게 해서 결국 모드 대시보드로 돌아간다. 기존 `elementary`/`middle` 원장은
**읽기 전용 이력**으로 남긴다.

### 2.2 원정을 얼리는 것 (freeze)

그날 첫 진입(또는 아침 자동 생성) 시 서버가 원정을 만들고 **payload 에 스냅샷**한다.
얼리는 것: `date(KST)`, `track`(초등/중등 — 학생 설정), 원정 모양(관문/연습), 걸음 목록(각 걸음의
종류·출처 ID·문항 ID), 주 단원 이름. 이후 진도가 바뀌어도, 새 복습 카드가 만기가 되어도
**오늘 원정은 안 바뀐다.** 이것이 `StudentSrsState` 한 문서 + `revision` CAS 로 이미 가능하다
(`prisma/schema.prisma` `StudentSrsState`, 탐험 상태도 같은 payload 의 `explorers` —
`src/lib/math-explorers/routes.ts:43`). **새 표가 필요 없다.**

### 2.3 경계 사례

| 상황 | 규칙 |
|---|---|
| **첫 설정** | 학년(초3~중3) 하나만 고른다 → 서버가 트랙·시작 단원 그룹을 정한다. 첫날 원정은 **관문의 날**(그 단원 그룹의 5카드 묶음). 설정 전에는 판 대신 학년 고르기 한 장. |
| **학년/트랙 변경** | 오늘 원정은 그대로(얼렸다). 변경은 **내일 원정부터**. 이미 걸은 칸은 안 변한다. 변경은 학생이 아니라 원장님 화면에 두는 편이 안전(현재 계획은 `course.plan` 에 있음). |
| **추가 학습** | 원정 완료 뒤 «더 하기»는 같은 틀을 쓰지만 `global` 원장에 안 적힌다. 기억 간격·진도·도감은 갱신, **걸음·별은 없음**(별은 원래 카드당 1회라 문제 없음). |
| **재도전 미완료** | 1차 통과만으로는 칸 없음. 판에 «다시 풀 문제 N개 남음». 재도전은 최대 3회 라운드(탐험 규칙) — 3회째에도 틀리면 **해설을 본 뒤 «다음에 다시»로 넘기고 완료 인정**, 그 문항은 다음 원정의 복습 걸음으로 넘긴다. 안 그러면 한 문항에 영원히 갇힌다. |
| **관문의 날 오답이 많음** | 개념 묶음 오답이 기준(예: 15중 5) 이상이면 다음 원정은 연습의 날이 아니라 **기초 다지기 묶음**(원본 규칙 그대로: 선수 4카드 + 목표 1카드 = 15활동)으로 얼린다. 이것도 «15활동 묶음 하나 + 은행 소량» 모양이라 하루 예산이 같다. |
| **늦은 완료(자정 넘김)** | 원정은 **얼린 날짜에 귀속**한다. 00:30 에 어제 원정을 끝내면 어제 날짜로 칸. 단 **다음날 원정이 생성되면 전날 미완 원정은 닫힌다**(칸 없음, 틀린 문항은 새 원정 복습으로 이월). 관문의 날이 닫혔으면 다음 원정이 같은 관문을 다시 연다(개념 묶음은 건너뛰지 않는다). 현재 `todayComplete` 가 `completedAt` 의 KST 날짜와 `day.date` 둘 다 보는데(`dailyJourney.ts` 약 270행), 전역판에서는 `day.date` 하나만 기준으로 한다. |
| **지난 칸 다시 하기** | 기존 readonly replay(`replayRoutes.ts`)를 그대로. 채점은 보여 주되 **원장·진도·별·상자·기억 간격 모두 불변**. 판에서 칸을 누르면 그날 문항 목록 → 다시 풀기. 관문 칸이면 개념 묶음 15활동 다시 하기. |
| **모드 전환 중 이탈** | 원정 걸음 커서를 payload 에 저장 → 다시 열면 같은 걸음부터. |

## 3. 하루 학습량과 원정의 두 모양

### 3.1 전제: «개념 15 + 은행 10» 을 매일 쌓지 않는다

개념 활동(정의 조립·모두 고르기·참거짓)은 은행 문항보다 짧지만 15개는 그 자체로 한 번의 학습이다.
여기에 은행 10 과 기억 카드까지 얹으면 초등 학생에게 매일 25~30걸음이 된다. 그래서 **개수가 아니라
시간 예산으로** 조립한다. 아래 시간은 **가정치**다 — 출시 전에 실제 학생 몇 명으로 걸음당 시간을
재서 맞춘다(탐험 원본의 기록에 활동당 시간이 없다).

| 걸음 | 가정 시간 |
|---|---|
| 개념 활동 1개(읽기 포함 평균) | 약 30초 → 15활동 ≈ 7~8분 |
| 초등 은행 문항 1개 | 약 60~90초 |
| 기억 카드 1장(참거짓·조립 한 번) | 약 20초 |
| 재도전 | 1차 오답 수에 비례 |

하루 목표 예산 ≈ **15분 안팎**(원장님 확정 필요 — 지금 초등 `dailyQuestionCount` 기본 10 과 같은 부피).

### 3.2 두 모양

| 모양 | 언제 | 구성(초등 예) | 가정 시간 |
|---|---|---|---|
| **관문의 날** | 새 단원 그룹에 들어서는 날(구역 첫 칸) · 기초 다지기가 필요한 날 | 기억 0~2장 → **개념 묶음 5카드·15활동(원본 그대로, 순서·상자 조건 포함)** → 같은 단원 은행 3~4문항 → 재도전 | 약 13~15분 |
| **연습의 날** | 그 밖의 날(구역 2~5칸째 등) | 기억 2~3장(만기 개념 카드 + 은행 오답) → 같은 단원 **은행 8~10문항**(분수 단원이면 그중 1개가 «손으로 해 보기») → 재도전 | 약 12~15분 |

한 구역(단원 그룹)을 관문 1일 + 연습 4일로 잡으면 5일간 은행 약 36~44문항, 개념 15활동,
기억 약 10장 — **은행이 과반**이다. 구역 길이(연습의 날 수)는 진도 계획(`course.plan`)이 정하고,
그 단원의 은행 문항이 모자라면 줄인다.

원본 규칙 보존:
- 5카드·15활동은 **한 원정 안에서 끊기지 않는다.** 처음 만나는 카드의 정의 읽기, 활동 순서,
  2·4번째 개념 뒤 상자, 카드당 1회 별이 원본 엔진(`src/lib/math-explorers/engine.ts`
  `applyExplorerAction`) 그대로 돈다. 원정 조립기는 묶음을 **통째로 한 걸음 덩어리**로 넣을 뿐이다.
- 기억 간격 1/3/7/14/30일은 원본 그대로. 기억 카드는 **연습의 날 앞머리**에 들어가며 따로 된 화면이 없다.
- 선수 회복의 «4 선수 + 목표 = 15활동» 묶음도 쪼개지 않는다 — 관문의 날 모양으로 들어간다(§2.3).

중등(중1~3)은 탐험 개념 묶음은 있으나 **일반 문항 엔진이 방정식 쪽(`src/lib/math-srs/generator.ts`)에만** 있다.
은행이 없는 중등 단원은 연습의 날을 만들 수 없으므로, 그 구역은 **관문의 날 + 기억 중심의 짧은 날**로
줄이고 판에 «이 단원은 연습 문제 준비 중»을 그대로 보인다. 690개 고정 활동을 돌려 막아 연습의 날을
채우지 않는다.

## 4. 첫 로그인 → 하루 → 판 복귀 시퀀스

```
[로그인] → `/learn` = 판 (첫 1회만 학년 고르기 1장)
[판]  말 · 지나온 칸(단원명) · 구역 표시 · 다음 3칸 미리보기
      큰 버튼 «오늘의 원정» (관문의 날이면 «관문: 약분과 통분»처럼 단원명)
      모서리: 자료함(카드·강의)
  └ 누름 → [원정 틀] (전체 화면, 하단 탭 없음, 닫기=판)
     관문의 날
       ① (있으면) 기억 0~2장
       ② 개념 묶음: 카드마다 처음이면 정의 읽기(+ 연결된 강의가 있으면 «영상 보기» 한 줄)
          → 조립 → 예 고르기 → 참거짓 … × 5카드, 2·4번째 뒤 상자
       ③ 같은 단원 은행 3~4문항
     연습의 날
       ① 기억 2~3장  ② 은행 8~10문항(분수 단원 1개는 막대 나누기·맞추기)
     — 1차 끝 —
       ④ 다시 풀기: 틀린 것만, 최대 3라운드. 해설은 재도전에서 «해설 보기»를 눌렀을 때만 모달.
     — 완료 → 도착 연출(책장 넘김 → 판)
[판]  말 한 칸 이동(여기서만) · 칸에 단원명 · 새 카드가 자료함에
```

배치 원칙:

- **개념(230 카드)** = 관문의 날의 개념 묶음 + 연습의 날의 기억 카드.
- **문제은행** = 연습의 날의 본체, 관문의 날의 꼬리. 주간 합계로 과반.
- **기억** = 원정 앞머리. 따로 된 «기억 퀘스트» 화면 없음.
- **선수 회복** = 관문의 날 모양의 기초 다지기 묶음(원본 15활동 그대로). 원장님 화면에서 수동 처방도 가능.
- **조작(통분 공방)** = 별도 방 금지(원장님 최신 지시). 분수 단원 연습 걸음 하나의 «입력 방식»으로만.
  현재 조작 활동은 **이것 하나**라는 것을 전제로 설계한다.
- **강의** = 입구가 아니라 자료. ⑴ 관문의 날 카드 읽기 화면의 «영상 보기» 한 줄(선택, 걸음 아님),
  ⑵ 자료함의 «강의» 목록(지금의 `LectureList` 그대로, 수업한 날로 묶음). 재생은 기존 `/learn/watch/[id]`.
  강의 시청은 칸·별에 영향 없음.
  ⚠️ 지금 강의는 **차시(`Unit`)** 에 붙고(`ConceptLecture`), 탐험 카드는 별도 개념 ID 를 쓴다
  (`src/lib/math-explorers/types.ts` `unitId?`). 카드 → 차시 연결표가 없으면 ⑴ 은 못 띄운다 —
  **처음엔 ⑵만, ⑴ 은 연결표를 만든 뒤(나중)**.
- **자료함** = 판 모서리 버튼 하나(시트). 탭 두 칸: `카드` · `강의`. 걸음 없음.
- **보상** = 별(카드 첫 통과 1회) · 상자(개념 묶음 2·4번째 뒤, 원본 그대로) · 기지 성장. 원정 완료 트랜잭션
  안에서 지급, 다시 하기·추가 학습에서는 0.

## 7. 모바일 320×600

- 원정 틀 = 3층 고정: 머리(꼬리표·진행 `7/14`·닫기, 44px) / **문제 영역(내부 스크롤, 남는 높이 전부)** /
  답 도크(2×2, 각 칸 ≥ 44px 높이, 총 ~112px) + 하단 여백. 하단 탭이 없으므로 600 − 44 − 112 − 안전영역 ≈ 400px 문제 영역.
- 정의 조립(말 조각 2개 순서)·예 모두 고르기는 2×2 도크에 안 맞는다 → 같은 도크 높이 안에서
  «조각 칩 줄 + 확인 버튼» 변형. **도크 높이는 모든 활동에서 같게**(흔들림 금지). 모두 고르기만 «확인» 1탭 추가.
- 처음 만나는 카드의 정의 읽기는 문제 영역을 다 쓰고 도크 자리에 «읽었어요» 한 버튼(같은 높이).
- 참/거짓 = 도크 2칸(넓은 두 칸). 조작(막대) = 문제 영역 안에서 조작, 도크엔 «확인».
- 긴 한국어/수식: 보기 칸 안 `overflow-wrap:anywhere`, KaTeX 는 칸 폭에 맞춰 축소(최소 글자 14px),
  넘치면 칸 안 가로 스크롤이 아니라 **문제 영역에서 크게 보기** 링크. 기존 식 목록 포맷터 재사용.
- 정오 오버레이 ~600ms, 책장 넘김 ~300ms, `prefers-reduced-motion` 이면 교차 페이드.
- 판: 320 폭에서 12칸 둘레(현재 `DailyJourneyBoard` `PAGE_SIZE=12`)면 칸당 ~70px — 단원명은 2줄 말줄임,
  칸 탭 시 시트에 전체 이름. 구역 경계(관문 칸)는 표지 하나로만.
- 시각 치장(기지 성장 그림, 말 효과)은 위 흐름이 시험으로 고정된 **뒤**에. (D-07: 형태 확정은 원장님.)

## 10. 핵심 권고 3개

1. **«날짜 합집합» 대신 «얼린 원정 1개 = 칸 1개».** 원정은 그날 처음 열 때 서버가 한 payload 에
   스냅샷하고, 재도전까지 끝나야만 전역 원장에 적힌다. 다시 하기·추가 학습·강의 시청은 쓰기 경로가 없다.
2. **원정은 두 모양 — 관문의 날(원본 5카드·15활동 통째 + 은행 소량)과 연습의 날(은행 본체 + 기억 앞머리).**
   개념 15 와 은행 10 을 같은 날 쌓지 않고, 원본 묶음도 쪼개지 않으며, 한 구역을 합치면 은행이 과반.
   은행 없는 중등 단원은 원정을 짧게, 화면에 정직하게.
3. **입구는 `/learn` 판 하나.** 하단 탭 넷 제거, 판에는 «오늘의 원정» 버튼 하나, 강의는 자료함과 (연결표가 생긴 뒤)
   카드 옆 «영상 보기». 구 경로는 리다이렉트, API 는 보존, 학생 첫 화면 변경은 원장님 확정으로 기록.
