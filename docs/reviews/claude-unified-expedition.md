## 0. 한 줄 판정 (한국어 요약)

**후보안(허브 하나 · 전역 일일 원장 · 공용 활동 틀)은 방향이 맞다. 그러나 «완료된 날짜를
모드 구분 없이 합친다»는 원장 규칙은 틀렸다.** 합치면 보드 한 칸이 «어느 날이든 무엇이든
한 가지를 끝낸 날»이 되어, 원장님이 말씀하신 «오늘 정해진 학습량 전체 + 재도전을 끝내야
한 칸»이 깨진다. 칸은 **서버가 아침에 얼린 «오늘의 원정» 한 개**의 완료로만 생긴다.
원정 안에 개념·문제은행·기억·선수 회복·조작 활동이 **정해진 순서의 걸음**으로 들어가고,
학생은 모드를 고르지 않는다. 탭 넷은 **«탐험» 하나 + «강의» 하나**로 줄인다.

## 1. 학생 머릿속 그림 (mental model)

학생이 알아야 하는 것은 셋뿐이다.

1. **판(보드)** = 내가 지금까지 걸어온 길. 칸 = 끝낸 «원정의 날». 칸에 그날의 **단원 이름**.
2. **오늘의 원정** = 판 가운데 버튼 하나. 누르면 끝날 때까지 한 틀 안에서 문제만 나온다.
3. **도감(모은 카드)** = 원정에서 만난 개념 카드. 다시 읽기·다시 풀기는 되지만 걸음은 없다.

«개념 탐험 / 초등 복습 / 중등 복습 / 통분 공방 / 기억 퀘스트 / 회복 학습»은 **학생 어휘에서
사라진다.** 그것들은 원정 안 걸음의 «종류»일 뿐이며, 문제 화면 머리에 작은 꼬리표
(`개념` · `연습` · `다시 보기` · `기초 다지기` · `손으로 해 보기`)로만 보인다.

후보안과 다른 점: 후보안은 «허브 하나 + 모드 여러 개 + 전역 원장»으로 읽힌다. 나는 **모드 자체를
학생에게서 없앤다.** 모드 선택이 남으면 원장 병합 문제(§2)와 탭 문제(§4)가 그대로 돌아온다.

## 2. 칸(일일)과 진도(교육과정)의 분리 — 핵심 결정

두 축을 **절대 한 숫자로 섞지 않는다.**

| 축 | 무엇 | 저장 | 보이는 곳 |
|---|---|---|---|
| **걸음(칸)** | 얼린 원정을 다 끝낸 KST 날짜 수 | 전역 원장 `journey.global[]` (한 날짜 한 행) | 판의 말 위치 |
| **진도** | 교육과정 위치(초등 단원 / 중등 개념 / 탐험 단원 그룹) | 기존 `course`·`missions`·`explorers` 상태 | 칸의 이름표, «다음 칸» 미리보기 |

칸에 적는 이름은 «그날 원정의 주 단원»이다. 그래서 판은 «걸어온 날»이면서 동시에 «지나온
단원»으로 읽힌다 — 하지만 **말이 한 칸 가는 조건은 진도가 아니라 원정 완료**다.

### 2.1 «아무 모드든 끝낸 날을 합친다»가 부족한 이유

현재 `src/lib/math-srs/dailyJourney.ts` 는 `elementary`·`middle` 원장을 따로 두고 각자
`todayGoal`(초등 `dailyQuestionCount ?? 10`, 중등 12)을 셈한다. 이 둘을 날짜 합집합으로 합치면:

- 초등 10문항만 끝내고 중등·개념은 손도 안 댄 날도 한 칸 → «전체 학습량» 위반.
- 탐험 단원 도전(15활동)을 따로 끝낸 날도 한 칸 → 보상 부풀리기 경로가 셋.
- 학년/모드를 바꿔 가장 쉬운 쪽만 끝내는 전략이 우세 전략이 된다.

**해법: 날짜 합집합이 아니라 «원정 1개 = 칸 1개».** 원정은 서버가 만든 걸음 목록이고,
그 목록이 비었을 때(재도전 포함)만 `global` 원장에 그 날짜가 `completedAt` 으로 적힌다.
기존 `elementary`/`middle` 원장은 **읽기 전용 이력**으로 남겨, 이관 시 과거 날짜만
`global` 로 한 번 복사한다(같은 날 둘 다 있으면 한 칸).

### 2.2 원정을 얼리는 것 (freeze)

오늘 첫 진입(또는 아침 자동 생성) 시 서버가 원정을 만들고 **payload 에 스냅샷**한다.
얼리는 것: `date(KST)`, `track`(초등/중등 — 학생 설정), 걸음 목록(각 걸음의 종류·출처 ID·
문항 ID), 목표 수, 주 단원 이름. 이후 진도가 바뀌어도, 새 복습 카드가 만기가 되어도
**오늘 원정은 안 바뀐다.** 이것이 `StudentSrsState` 한 문서 + `revision` CAS 로 이미 가능하다
(`prisma/schema.prisma` `StudentSrsState`, 탐험 상태도 같은 payload 의 `explorers` —
`src/lib/math-explorers/routes.ts:43`). **새 표가 필요 없다.**

### 2.3 경계 사례

| 상황 | 규칙 |
|---|---|
| **첫 설정** | 학년(초3~중3) 하나만 고른다 → 서버가 트랙·시작 단원을 정한다. 설정 날에도 원정 생성. 설정 전에는 판 대신 학년 고르기 한 장. |
| **학년/트랙 변경** | 오늘 원정은 그대로(얼렸다). 변경은 **내일 원정부터**. 이미 걸은 칸은 안 변한다. 변경은 학생이 아니라 원장님 화면에 두는 편이 안전(현재 계획은 `course.plan` 에 있음). |
| **추가 학습** | 원정 완료 뒤 «더 하기»는 같은 틀을 쓰지만 `global` 원장에 안 적힌다. 기억 간격·진도·도감은 갱신, **걸음·별은 없음**(별은 원래 카드당 1회라 문제 없음). |
| **재도전 미완료** | 1차 통과만으로는 칸 없음. 판에 «다시 풀 문제 N개 남음». 재도전은 최대 3회 라운드(탐험 규칙) — 3회째에도 틀리면 **해설을 본 뒤 «다음에 다시»로 넘기고 완료 인정**, 그 문항은 내일 원정의 복습 걸음으로 넘긴다. 안 그러면 한 문항에 영원히 갇힌다. |
| **늦은 완료(자정 넘김)** | 원정은 **얼린 날짜에 귀속**한다. 00:30 에 어제 원정을 끝내면 어제 날짜로 칸. 단 **다음날 원정이 생성되면 전날 미완 원정은 닫힌다**(칸 없음, 틀린 문항은 새 원정 복습으로 이월). 이틀치를 한 번에 몰아 걷지 못하게. 현재 `todayComplete` 가 `completedAt` 의 KST 날짜와 `day.date` 둘 다 보는데(`dailyJourney.ts` 약 270행), 전역판에서는 `day.date` 하나만 기준으로 한다. |
| **지난 칸 다시 하기** | 기존 readonly replay(`replayRoutes.ts`)를 그대로. 채점은 보여 주되 **원장·진도·별·기억 간격 모두 불변**. 판에서 칸을 누르면 그날 문항 목록 → 다시 풀기. |
| **모드 전환 중 이탈** | 원정 걸음 커서를 payload 에 저장 → 다시 열면 같은 걸음부터. |

## 3. 첫 로그인 → 하루 → 판 복귀 시퀀스

```
[로그인] → (첫 1회) 학년 고르기 1장 → [판]
[판]  말 · 지나온 칸(단원명) · 다음 3칸 미리보기 · 큰 버튼 «오늘의 원정 (0/14)»
  └ 누름 → [원정 틀] (판을 벗어난 한 화면, 뒤로=판)
       ① 기억 걸음 2~4개   만기된 개념 카드(1/3/7/14/30) · 은행 오답 복습
       ② 새 개념 걸음 1개  처음이면 정의 읽기 → 조립 → 예 고르기 → 참/거짓 (3활동)
       ③ 연습 걸음 6~10개  같은 단원의 기존 문제은행 문항(초등 courseBank / 중등 generator)
                           분수 단원이면 이 중 1개가 «손으로 해 보기»(막대 나누기·맞추기)
       ④ (조건부) 기초 다지기  오늘 개념 오답이 2개 이상일 때만, 선수 카드 1~2장 + 목표 카드
       — 1차 끝 —
       ⑤ 다시 풀기  틀린 것만, 최대 3라운드. 해설은 재도전에서 «해설 보기»를 눌렀을 때만 모달.
       — 완료 → 도착 연출(책장 넘김 → 판으로)
[판]  말 한 칸 이동(여기서만) · 칸에 단원명 · 상자가 걸리면 열기 · 새 카드가 도감에
```

배치 원칙:

- **개념(230 카드)** = 원정의 «새 개념» 걸음 + 기억 걸음. 단원 도전 15활동을 하루에 다 넣지 않는다
  — 5개념을 **닷새에 걸쳐** 하나씩(단원 그룹 = 판의 한 «구역»).
- **문제은행** = 걸음의 다수(연습). 원장님 요구 «기존 은행이 대부분»을 충족.
- **기억** = 원정 앞머리. 따로 «기억 퀘스트» 화면 없음.
- **선수 회복** = 원정 안의 조건부 걸음. 인수인계의 «4 선수 + 목표 = 15활동» 묶음은 하루치로 너무
  크다 — **원장님 화면의 수동 처방**으로만 두고, 자동은 1~2장으로 줄인다.
- **조작(통분 공방)** = 별도 방 금지(원장님 최신 지시). 해당 단원 연습 걸음 중 하나의 «입력 방식»으로만.
  현재 조작 활동은 **이것 하나**라는 것을 전제로 설계한다.
- **강의** = 원정 밖. «오늘의 개념»은 원장님이 올린 영상이 있을 때 **새 개념 걸음 앞에 «영상 보기»
  한 줄**로만 연결(선택). 강의 목록 자체는 두 번째 탭.
- **도감** = 판 화면 모서리 버튼 하나(모달/시트). 걸음 없음.
- **보상** = 별(카드 첫 통과 1회) · 상자(구역 안 2·4번째 개념 뒤) · 기지 성장. 전부 **원정 완료 트랜잭션
  안에서** 지급, 다시 하기·추가 학습에서는 0.

## 5. 후보안의 치명적 실패 5개와 우선순위

| # | 실패 | 결과 | 고침 | 지금/나중 |

| 1 | **원장을 날짜 합집합으로** | 한 가지만 끝내도 칸 → 걸음 가치 붕괴, 최약 모드로 몰림 | 얼린 원정 1개 = 칸 1개(§2) | **지금** — 이게 없으면 나머지가 무의미 |

| 5 | **보상·기억 이중 기록** | 개념 카드 별이 탐험 상태에, 걸음이 SRS 원장에 따로 → 한쪽만 저장되면 별만 받고 칸 없음/칸만 있고 별 없음 | 원정 완료를 **한 payload 한 revision** 에서 원자적으로(`StudentSrsState` CAS, 기존 영수증 `explorerReceipt` 재사용). 다시 하기는 쓰기 경로 자체가 없게 | **지금** |

덧붙여 위험(6위): 단원 도전의 «2/4 개념 뒤 상자»가 하루 1개념 배치에서는 **구역 5일 중 2·4일째**가 된다
— 의도대로 동작하나, 시험으로 못 박을 것.

## 6. 모바일 320×600

- 원정 틀 = 3층 고정: 머리(꼬리표·진행 `7/14`·닫기, 44px) / **문제 영역(내부 스크롤, 남는 높이 전부)** /
  답 도크(2×2, 각 칸 ≥ 44px 높이, 총 ~112px) + 하단 여백. 600 - 44 - 112 - 안전영역 ≈ 400px 문제 영역.
- 전역 하단 탭은 **원정 중 숨긴다**(원정은 전체 화면 모드, 닫기=판). 탭까지 두면 문제 영역이 ~340px 로 준다.
- 정의 조립(말 조각 2개 순서)·예 모두 고르기는 2×2 도크에 안 맞는다 → 같은 도크 높이 안에서
  «조각 칩 줄 + 확인 버튼» 변형. **도크 높이는 모든 활동에서 같게**(흔들림 금지). 모두 고르기만 «확인» 1탭 추가.
- 참/거짓 = 도크 2칸(넓은 두 칸). 조작(막대) = 문제 영역 안에서 조작, 도크엔 «확인».
- 긴 한국어/수식: 보기 칸 안 `overflow-wrap:anywhere`, KaTeX 는 칸 폭에 맞춰 축소(최소 글자 14px),
  넘치면 칸 안 가로 스크롤이 아니라 **문제 영역에서 크게 보기** 링크. 기존 식 목록 포맷터 재사용.
- 정오 오버레이 ~600ms, 책장 넘김 ~300ms, `prefers-reduced-motion` 이면 교차 페이드.
- 판: 320 폭에서 12칸 둘레(현재 `DailyJourneyBoard` `PAGE_SIZE=12`)면 칸당 ~70px — 단원명은 2줄 말줄임,
  칸 탭 시 시트에 전체 이름.
- 시각 치장(기지 성장 그림, 말 효과)은 위 흐름이 시험으로 고정된 **뒤**에. (D-07: 형태 확정은 원장님.)

## 7. 가장 작은 출시 단위 (smallest shippable)

새 표·새 엔진 없이:

1. `journey.global` 원장 + 원정 스냅샷 스키마(zod, `StudentSrsState.payload` 안).
2. 서버 원정 조립기 `buildExpedition(state, date)` — 기억(탐험 `explorerView` 만기 카드 + SRS 오답) →
   새 개념 1 → 은행 연습 N → 조건부 기초 다지기. 초등은 `courseBank`, 중등은 `generator` 가능한 개념만.
3. 원정 걸음 API 하나(`POST /api/learn/expedition/answer`) — 내부에서 각 엔진 채점 호출, 원장은 여기서만 씀.
4. 원정 틀 컴포넌트 하나(도크·오버레이·책장·오답 라운드·해설 모달) — 각 엔진은 문항 렌더 부품만.
5. 판 = `DailyJourneyBoard` 재사용, 데이터원만 `global`.
6. 탭 둘 + 구 경로 리다이렉트.

미룰 것: 통분 외 조작 활동, 중등 전 단원 일반 문항, 기지 성장 그림, 원장님 배정 모델, 선수 회복 15활동 묶음 자동화.

## 8. 수용 점검표 (acceptance)

- [ ] 한 날짜에 칸은 최대 1개. 초등 10문항만 끝낸 날은 원정이 안 끝났으면 칸 0 (시험).
- [ ] 원정 스냅샷은 생성 뒤 진도 변경·새 만기 카드에도 불변 (시험).
- [ ] 1차 통과 + 재도전 남음 → 칸 0. 재도전 3라운드 소진 → 완료 인정, 이월 문항이 다음 원정 복습에 있음.
- [ ] 자정 넘겨 끝내면 얼린 날짜의 칸. 다음날 원정 생성 뒤 전날 원정은 닫힘(칸 0).
- [ ] 지난 칸 다시 하기·추가 학습: 원장·별·상자·기억 간격·진도 **모두 불변** (payload diff 0 시험).
- [ ] 원정 완료 1회 = revision 1 증가, 칸·별·상자·도감이 같은 revision 에. 중복 요청은 영수증으로 무시.
- [ ] 학생 탭 = 2개. `/learn/math-srs*`, `/learn/math-explorers` 는 리다이렉트, API 경로 불변, 기존 계약 시험 초록.
- [ ] 판에 «오늘의 원정» 외 학습 진입 버튼 0 (도감은 읽기).
- [ ] 모든 걸음이 같은 도크 높이·같은 오버레이·같은 해설 규칙 (한 컴포넌트를 거침 — 구조로 보장).
- [ ] 320×600 에서 도크가 뷰포트 안 고정, 긴 문항은 문제 영역만 스크롤, 페이지 가로 스크롤 0 (e2e, CPU 감속 포함).
- [ ] 판 칸에 단원 이름. 중등 연습 엔진이 없는 단원은 «개념·기억만» 원정으로 짧아지고 그 사실이 화면에 보임.
- [ ] 통분 조작은 분수 단원 연습 걸음 안에서만 등장, 독립 진입 없음.
- [ ] 형태(판 칸 모양·말·연출·꼬리표 문구)는 05 디자인 시스템에서 원장님 확정 뒤 구현 (D-07).

## 9. 핵심 권고 3개

1. **«날짜 합집합» 대신 «얼린 원정 1개 = 칸 1개».** 원정은 아침에 서버가 한 payload 에 스냅샷하고, 재도전까지
   끝나야만 전역 원장에 적힌다. 다시 하기·추가 학습은 쓰기 경로가 없다.
2. **모드를 학생에게서 없앤다.** 탭 넷 → «탐험»·«강의» 둘, 판에는 버튼 하나. 개념·은행·기억·기초 다지기·조작은
   원정 안 걸음의 종류(꼬리표)일 뿐. 구 경로는 리다이렉트, API 는 보존.
3. **공통 규칙은 원정 틀 한 곳에, 엔진은 «문항+채점»만.** 그리고 690 고정 활동을 문제은행으로 속이지 않는다 —
   중등 연습 엔진이 없는 단원은 원정을 짧게, 화면에 정직하게.
