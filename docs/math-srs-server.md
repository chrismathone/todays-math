# 학생 계정으로 저장하는 오늘의 기억

`/lab/math-srs`는 기존 브라우저 체험판이다. `/learn/math-srs`는 이미 발급된 학생 계정으로 로그인하고 첫 비밀번호를 바꾼 뒤 사용하는 별도 학습 화면이다. 계정·반·학생을 새로 만들거나 이름으로 연결하지 않는다.

## 기존 코드 연결

- 학생 인증: `requireStudent`와 기존 학생 세션의 계정 중지·퇴원 판정, 정확한 경로 허용 목록을 사용한다. 학생 식별자는 항상 세션에서 읽으며 요청 본문으로 받지 않는다.
- 교사 조회: `authorizeAccount`, 메뉴 및 역할 판정, `requireOwnedClass`를 사용한다. 관리자 소유 범위도 기존 규칙을 따른다.
- 진도: 실제 반·개별 기록을 `getCurrentProgress`에 넘긴다. 개인 진도가 없으면 반 진도로 돌아가는 기존 규칙이 유지된다.
- 개념 영상: 기존 `loadStudentLectureScope`, `lectureOpenToStudent`, 정렬 함수를 사용한다. 연결할 단원 범위는 재사용 문제 유형 목록 `ENGINE_CATALOG`에서 가져온다.
- 문제·채점·기억: 기존 중1 유형을 연결한 `createMission`, `checkAnswer`, `recordAttempt`와 기억 갱신 함수를 서버에서도 사용한다. 하루 경계는 `kstDateOf`로 정한다.
- 공통 응답·오류 기록: Zod 응답 계약, 공용 오류 응답, `noStore`, `withErrorLog`를 사용한다.

진도는 학습 화면의 실제 수업 맥락과 영상 연결에 사용한다. 현재 미션은 일차방정식 여섯 개념을 진단하는 범위이며 **수업한 차시로만 문제를 제한하지 않는다**.

## 저장과 채점

`StudentSrsState`는 실제 `Student.id` 하나에 연결된 학습 상태다. 개념별 기억과 최근 90회 미션을 보관한다. 오래된 미션을 정리해도 누적 개념 기억은 유지한다. 학생을 삭제할 때 이 상태도 함께 삭제된다.

답안·힌트는 다음 문제 순서로만 받는다. 서버가 정답 여부, 사용한 힌트, 응답 시각과 경과 시간을 계산하고 기존 채점기가 자기평가 등급의 상한을 제한한다. 경과 시간에는 이전 답안의 풀이를 읽는 시간이 포함될 수 있으므로 정밀한 풀이 속도 측정값은 아니다.

미션 생성과 모든 변경은 `revision` 조건이 맞을 때만 저장한다. 두 창이 동시에 답을 제출해도 한 답안과 기억 갱신만 적용된다. 동일한 답안 요청의 재전송은 저장된 결과를 돌려주며, 이미 제출한 답을 바꾸는 요청은 409로 거절한다. 힌트 여부는 서버에 먼저 기록하므로 클라이언트가 `usedHint: false`로 바꿀 수 없다.

아직 제출하지 않은 문제의 정답·풀이·원본 정답 문자열·생성 시드는 응답에서 제외한다. 서버 미션과 문제에는 무작위 식별자를 부여한다. 저장된 JSON의 형식이나 순서가 깨지면 기록을 초기화하지 않고 오류를 표시한다.

`WorkspaceDocument`는 교사 소유의 시험지 초안과 추출 작업물이다. 학생 기록을 여기에 넣으면 소유권과 자료 목록의 의미가 달라지므로 사용하지 않는다. `TestResult`는 실제 시험지 채점 결과이며 성적 집계에 쓰인다. 기억 학습을 시험 점수로 만들어 넣지 않는다.

## API

| 경로 | 동작 |
| --- | --- |
| `GET /api/learn/math-srs` | 내 기록·진도·접근 가능한 관련 강의 |
| `POST /api/learn/math-srs` | 빈 객체로 오늘 미션 시작 또는 진행 중 미션 재개 |
| `POST /api/learn/math-srs/hint` | 현재 문제의 힌트 기록 후 표시 |
| `POST /api/learn/math-srs/attempts` | 현재 문제 제출과 서버 채점 |
| `GET /api/classes/[id]/math-srs` | 해당 반의 실제 학생·진도·학습 현황 |

모든 학생 API는 교사 세션을 학생으로 취급하지 않는다. 쓰기는 같은 사이트에서 온 요청이어야 한다. 응답에는 캐시 금지 헤더가 적용된다. 세부 요청·응답 계약은 `src/contracts/mathSrs.contract.ts`가 기준이다.

## 배포 전 필요한 저장소 적용

SQL 초안은 `prisma/migrations/20260923150000_student_srs_state/migration.sql`이다. 이 작업에서는 **데이터베이스 조회, SQL 적용, 다른 마이그레이션 실행을 하지 않았다**. 새 표가 아직 없거나 새 Prisma 클라이언트가 준비되지 않은 환경에서는 학생·교사 화면에 503 안내가 나오며, 저장된 것처럼 표시하거나 브라우저 저장으로 바꾸지 않는다.

저장소에는 다른 작업에서 남긴 미적용 마이그레이션이 있다. 전체 `migrate deploy`, `migrate dev`, `db push`로 함께 적용하지 말고, 기존 배포 검토 절차에 따라 이 SQL만 별도로 검토·적용해야 한다. 스키마의 오래된 미적용 주석만으로 기존 학생 계정·강의 표의 실제 적용 여부를 단정할 수 없다.
