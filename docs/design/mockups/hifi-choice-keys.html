보기 번호 키 · 엔터 키 모양 — 네 안

원장님 (운영 PC 에서 «예 모으기»를 보신 뒤) 1,2,3,4 숫자 버튼을 키보드처럼 만들어 주고 실제 키보드 1,2,3,4 를 눌러도 정답 입력 가능하게. 엔터로 제출 가능하게. 마찬가지로 엔터로 제출 가능한 곳에 엔터키 키보드 모양을 넣어 놔.

키 동작은 이미 들어갔습니다 — 숫자키 1~4(윗줄 · 숫자 패드)는 그 번호 단추를 누른 것과 같고, 엔터는 확인 단추를 누른 것과 같습니다(모든 학생 풀이 화면). 이 시안은 모양만 여쭙니다: 보기 번호를 어떤 «키»로 보일지, 확인 단추에 엔터를 어떻게 보일지, 폰에서는 숨길지. 틀은 제품 CSS · 실제 문항 그대로이고, 아래 «눌러 보는 화면»에서는 이 파일에서도 숫자키와 엔터가 먹습니다.

여쭐 것

  1. 번호 키 모양 — 몇 안으로 할까요. A 번호 키캡(추천) · B 보기 단추가 키 · C 선만 있는 작은 키 · D 안내 한 줄(보기는 지금 그대로) · 또는 지금 그대로.
  2. 엔터 모양. ㉮ 확인 단추 안 «⏎» 키(추천) · ㉯ 단추 오른쪽 끝 «Enter» 키(큐브 실험실에 이미 있는 모양) · ㉰ «↵» 기호만. 위 막대의 «엔터 모양»으로 어느 안에든 바꿔 볼 수 있습니다. 화살표가 이미 있는 초등 «정답 확인 →»에는 ㉠ 화살표 자리를 키가 대신(추천 — 한 단추에 화살표가 둘 서지 않게, 폰은 지금 화살표) · ㉡ 화살표 뒤에 키를 더함.
  3. 폰 · 키보드 없는 태블릿에서는. ㉮ 숨김 — 마우스가 있는 기기에서만 보임(추천) · ㉯ 늘 보임 · ㉰ 숨겨 두었다가 키보드를 한 번 쓰면 그때부터 보임. «터치 기기» 탭에 비교 캡처와 가르는 법 · 한계를 적었습니다.
  4. 엔터를 «넘김» 단추에도 걸까요. 지금은 확인 · 제출 단추에만 걸었습니다(선택한 예 확인하기 · 완성한 정의 확인하기 · 나눈/칠한 조각 확인하기 · 정답 확인 · 완성했어요). «정의를 가리고 도전하기 →» · 초등 «다음 문제 →» · 다시 풀기 «다음 복습 문제»에도 걸면 키보드만으로 끝까지 갈 수 있지만, 엔터를 연달아 치다 뜻 읽기를 건너뛸 수 있습니다. ㉮ 확인 · 제출만(지금) · ㉯ 넘김 단추까지.
  5. 알려 드릴 것 — 고른 보기에 포커스가 남은 채 엔터. PC 에서 보기를 마우스로 누르면 브라우저가 그 보기에 포커스를 둡니다. 그때 엔터를 치면 원래는 «그 보기를 한 번 더 누름(끄기)»인데, 확인 단추가 있는 화면에서는 엔터 = 확인으로 바꿨습니다(보기 끄고 켜기는 스페이스 · 숫자키). 이대로 괜찮을지.
