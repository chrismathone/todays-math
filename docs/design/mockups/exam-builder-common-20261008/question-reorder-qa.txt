Question reorder module QA — 2026-10-08

Scope: question-reorder.js and question-reorder.css, based on main 5171fcd5f.
No prototype HTML, application component, dependency or persistence changes.

Contract
- ExamReorder.create({ container, itemSelector, getIds, onReorder, announce? })
  returns { destroy() }. Initialize once on the stable root.
- Selected cards have data-reorder-id; their DOM order matches getIds().
  Handles are button.reorder-handle[data-reorder-handle], type=button, with
  caller-supplied Korean aria-labels. Existing arrow buttons remain independent.
- Mouse/touch pointer capture belongs to the stable container, so replacing
  cards during a gesture is supported. Cards remain in their original order
  until drop; a fixed insertion marker adds no layout space.
- Only an actual changed drop/keyboard commit invokes onReorder, once, with a
  fresh ordered array. The caller rerenders; synchronous renders retain focus.
- Space/Enter picks up or commits, arrows choose a position, Escape cancels.
  Pointer cancellation, loss of capture, blur and keyboard focus departure
  cancel. A changed ID list cancels rather than overwriting newer state.
- Nested passage groups and side-by-side groups use card rectangles, not
  sibling insertion. Edge scrolling is capped at 650px/s, with bounded frame
  time; the marker respects clipped scroll areas. destroy removes listeners,
  animation frames, marker, live region and temporary visual/ARIA state.
- Handles are at least 44x44px. Only handles disable native touch scrolling.
  CSS uses shared DESIGN.md tokens with standalone prototype fallbacks.
