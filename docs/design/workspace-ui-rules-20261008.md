# 작업실 UI 구조 규칙 — 오늘의수학 기준으로 오늘의영어 정렬

기준일: 2026-10-08 (KST). 관찰 기준 커밋: `94051e780`. 대상: 교사·관리자 작업실의 공통 셸과 영어 여섯 메뉴. 이 문서는 **구현 지침이며, 아래 통일 항목이 이미 구현되었다는 보고가 아니다.** 이번 문서 작업은 소스·API·DB·인쇄 계약을 변경하지 않는다.

사용자 방향은 “오늘의영어가 수학보다 정돈되지 않았다. 기존 오늘의수학을 기준으로 맞춘다”이다. 수학 방향을 다시 고르는 Wire/Hi-fi 회의를 열지 않는다. [05 디자인 시스템](../planning/05-design-system.md)의 §8.9 작업실, §8.23 영어, 2026-09-23 공통화 기록을 잇는다. 옛 §2 팔레트·§3.2 글자 크기나 §8.23의 초기 세 메뉴를 현재 구현이라고 읽지 않는다. 학생 탐험·SRS v2의 독립 시각 언어와 인쇄 지면은 이 작업실 규칙의 일괄 치환 대상이 아니다.

표시법: **[관찰]**은 기준 커밋의 소스 사실, **[통일]**은 이번 사용자 지시로 적용할 규칙, **[예외]**는 역할 때문에 유지할 차이, **[확인 필요]**는 구현·화면 검증이 남은 항목이다. CSS 숫자는 선언과 최종 cascade를 읽은 값이며 브라우저 실측값이 아니다. 제공된 캡처를 이 작업에서 직접 재측정하지 않았으므로 혼잡 원인은 소스 근거의 진단으로만 기록한다.

## 3. 글꼴·제목·행동의 위계

| 역할        | [관찰] 공통 값         | [통일] 용도                                                                       |
| ----------- | ---------------------- | --------------------------------------------------------------------------------- |
| 페이지 제목 | `--text-title: 24px`   | 활성 뷰의 h1 하나. 공통 헤더는 750, line-height 1.3, letter-spacing -0.035em.     |
| 영역 제목   | `--text-section: 18px` | 자료·결과·설정 등 h2. 반복 항목마다 18px를 쓰지 않는다.                           |
| 본문/조작   | `--text-body: 14px`    | 문장, 항목 이름, 버튼, 입력. 기본 line-height 1.5; 긴 지문·편집 1.6 이상은 허용.  |
| 메타/보조   | `--text-caption: 12px` | 날짜·출처·수량 단위·필드 설명. 오류 해결의 핵심 문장을 작은 메타로 숨기지 않는다. |

**[통일]** 화면은 적재된 `var(--font-pretendard)` 우선, 시스템 폴백을 공유한다. 영어 지문·문항 번호·보기·답·해설도 앱 글꼴이다. 명조와 별도 지면 폰트는 인쇄 컴포넌트에 둔다. 숫자는 필요한 수량·날짜 자리에서만 `tabular-nums`; 거대한 숫자나 장식 영문 eyebrow를 만들지 않는다. 본문 400~~500, 조작 600, 영역 제목 650~~700을 기본으로 하며 기존 공통 h1의 750은 유지한다.

**[관찰]** EnglishStudio의 17px 영역 제목·13px 설명, Maker의 16px 작은 제목, PrivateLibrary의 13px 조작/15px 이름, Basket의 11px 구성 정보는 남은 개별값이다. **[통일]** 수정하는 작업실 부분은 네 역할로 정리한다. 이 문서가 기존 코드 전체의 네 역할 준수를 인증하지 않는다.

### 셸과 페이지 제목의 소유권

1. **[관찰]** 셸 topbar는 `작업실 > 현재 메뉴`, 전역 빠른 검색, 계정과 영어 화면 최대화/복원을 가진다. 현재 메뉴를 h1로 그리는 곳이 아니다.
2. **[통일]** 일반 뷰는 `WorkspacePageHeader`로 제목·짧은 설명·오른쪽 행동을 한 번 그린다. 부모가 그리면 자식은 h2부터 시작한다. 이미 그린 페이지 제목 뒤에 동일한 제목을 담은 별도 workbar를 덧붙이지 않는다.
3. **[예외: 실제 수학 홈]** WorkroomHome은 `h1.srOnly` 후 바로 검색 작업을 시작한다. 홈에 큰 환영 영역을 추가하지 않는다. 영어 홈은 시험 맥락을 읽어야 하므로 컴팩트한 공통 제목을 유지할 수 있으나, 수학처럼 숨긴 제목이 이미 있다고 주장하지 않는다.
4. **[통일]** 한 작업 구역의 다음 행동 하나에 코발트를 준다. 다른 독립 작업 구역에는 그 구역의 주 행동이 있을 수 있다. 전체 페이지의 모든 버튼을 하나로 제한하는 규칙은 아니다. 같은 “새 시험 등록/만들기”를 셸·제목·빈 상태에서 동시에 같은 강도로 반복하지 않는다. 등록 전에는 빈 상태의 등록을 강조하고, 등록 후에는 현재 시험의 준비 행동을 강조한다.
5. **[통일]** 뒤로·새로고침·설정 수정·모두 보기·닫기는 보조/텍스트 버튼. 삭제는 대상 옆의 조용한 위험 행동과 기존 확인 흐름으로 유지한다. 동작을 줄이는 것이 아니라 행동 간 우선순위를 정리한다.

근거: [공통 헤더 CSS](../../src/components/unified/WorkspacePageHeader.module.css)의 `.header/.actions`(60px 최소 높이, 아래 16px, 행동 gap 8px), [WorkroomHome](../../src/components/unified/WorkroomHome.tsx), [EnglishPrepView](../../src/components/english/EnglishPrepView.tsx)의 중복 진입 버튼.

## 5. 레이아웃과 메뉴별 구현 체크리스트

### 공통 순서와 공간

**[통일]** 일반 작업 뷰의 읽는 순서는 **제목/행동 → 작업 맥락 → 검색/조건 → 결과 요약 → 결과 → 선택 결과/다음 행동**이다. 필요한 단계만 사용한다. 맥락은 “어느 시험의 자료인가”, 필터는 “그중 무엇을 찾나”, 결과는 “찾은 것”, 담기는 “사용자가 선택한 것”이다. 네 영역의 수량이나 제목을 서로 대체하지 않는다.

- 페이지 inset은 셸/뷰 중 **한 소유자**만 적용: Workroom `--workspace-page-padding: 16px 20px`; 모바일 `14px 16px`. `.viewContent` 아래의 EnglishStudio/Maker가 같은 페이지 여백을 다시 추가하지 않는다. 독립 라우트에는 별도 외곽 wrapper를 둔다.
- 기본 작업 구역 gap 16px, 같은 도구 모음 gap 8~~12px, 더 큰 독립 열 gap 20~~24px. 필터 판 padding 16px/radius 12px, 결과 카드 gap 12px는 Bank 기준이다. 모든 요소를 같은 카드 모양으로 감싸지 않는다.
- 상자 깊이는 페이지 바탕→작업 판→행/구분선으로 끝낸다. 지문·정답·오류처럼 별도 읽기 역할이 있는 면만 추가한다. 섹션 전체와 각 행을 모두 두꺼운 테두리·그림자로 둘러싸지 않는다.
- 학교/시험 선택은 한 맥락 영역에서 읽힌다. 학교가 늘수록 버튼 행이 무제한 증식하는 구조 대신, 현재 학교·시험과 변경 조작을 작게 유지하는 선택기를 사용한다. 변경은 기존 `onSelect`/시험 상태를 유지하며 문항 필터·저장 대상과 혼동하지 않게 라벨링한다.
- 검색·학년 등 핵심 조건은 항상 보이고, 추가 조건은 Bank처럼 펼친다. 현재 적용 조건은 해제 가능한 chip, 결과 수는 결과 바로 위, 초기화는 필터 옆이다. 모든 조건을 닫아 사용 중인 범위를 숨기지 않는다.
- 반복 자료·세트는 정렬된 행/표를 쓴다. **[예외]** 수학 Bank의 문항 본문은 [print/tokens.ts](../../src/components/print/tokens.ts)의 `PROBLEM_CARD_WIDTH`로 정해진 카드 격자다. 영어 긴 지문에는 수학 인쇄 열 폭을 복사하지 않는다. 지문+문항 상세가 필요한 목록/상세 2열은 허용한다.
- **[관찰]** 수학 홈은 넓은 주 작업 열+340px 보조 열(1250px 이하 300px, 1600px 이상 360px). 이것은 검색·진행 중 시험지의 관계이지 모든 영어 화면에 강제할 공통 비율이 아니다.

### 담기 패턴의 계약

**[관찰]** Math `BankBasket`은 그리드 열을 차지하지 않는다. 오른쪽 24px, 바닥 `max(20px, safe-area)+bottom-inset`, launcher 52px, 펼침 폭 320px, 5열 번호 목록이다. 미리보기에서 빼기, 가능한 경우 순서 변경/교체를 한다. `BankView`는 `100px + --workspace-bottom-inset`만큼 바닥을 확보한다.

**[통일]** 영어에서도 기본은 수량과 열기만 보이는 접힌 담기, 펼치면 선택 순서·제거·현재 지원하는 다음 행동이다. 리스트를 훑는 동안 빈 담기 패널이 영구 열을 차지하지 않는다. 정렬·제거 후 초점, Escape, 선택 개수 알림, 긴 목록의 마지막 항목 접근을 확인한다. **[예외]** 수학의 교체 API·난이도 구성·자동저장은 모양을 빌렸다고 영어 기능이 되지 않는다. 영어 데이터형과 `resolveBankQuestions`/현재 선택 상한/원본 변경 처리는 그대로 사용한다.

## 6. 깊이·스크롤·인쇄 분리

**[통일]** 기본 작업 면은 1px 선, 흰 면, 10~12px 카드 모서리다. 판 아래 그림자로 위계를 계속 늘리지 않는다. overlay·dialog·접힌 담기처럼 떠 있는 요소에만 뚜렷한 그림자를 둔다. **[관찰]** 수학 문항 카드에는 매우 약한 `0 2px 3px #172b4d05`, 담기 launcher에는 `0 5px 20px #172b4d29`, 펼침에는 `0 8px 32px #172b4d29`가 있다. 이를 모든 카드에 복사하지 않는다. Workroom topbar의 반투명/blur는 셸에 존재하는 예외이며 유리 카드 시스템의 근거가 아니다.

### 스크롤 소유권

- **[관찰]** Workroom은 `.workspace/.main min-height:100dvh`, 문서 스크롤, 고정 사이드바(자체 `overflow-y:auto`), sticky topbar를 쓴다. 콘텐츠 전체에 고정 높이를 걸지 않는다.
- **[관찰]** 수학 홈 최근 작업은 8개까지 표시하고 이름 있는 `role=region tabIndex=0` 목록을 스크롤한다. 데스크톱에서는 뒤쪽 CSS가 `min-height:calc(100dvh - 84px)`와 최근 목록용 grid를 적용한다. 모든 화면을 한 viewport 안에 억지로 가두는 규칙이 아니다.
- **[통일]** 긴 폼·결과·지문은 문서 흐름에서 읽는다. 짧은 목록/사진 비교/담기/대화상자처럼 독립 탐색이 필요한 곳만 제한 높이와 내부 스크롤을 둔다. 내부 스크롤에는 이름, 초점 진입, 스크롤 끝, touch overscroll을 확인한다. 외부와 내부 두 스크롤을 같은 본문에 중복 적용하지 않는다.
- **[통일]** 본문 textarea는 기존 `AutoGrowTextarea`를 유지한다. 사진 원본·긴 자료 목록은 제한 스크롤이 필요한 예외다. textarea 높이 고정으로 카드 높이를 억지로 맞추지 않는다.
- **[확인 필요]** 기준 CSS의 데스크톱 topbar는 **최종 선언 52px**이고 `--workspace-sticky-inset`은 **68px**, 최대화는 topbar/inset **44px**다. sticky 위치에 68px을 새 상수로 복제하지 말고 실제 셸 변수를 참조하고 가림을 검증한다. 값의 차이를 문서에서 “이미 통일됨”으로 숨기지 않는다.
- **[통일]** 모바일 하단 탐색+담기/저장 행동+safe area가 마지막 행·focus를 가리지 않아야 한다. sticky/fixed를 추가할 때 콘텐츠의 바닥 여백과 함께 검증한다. Maker의 `bottom:0` 저장판은 이 점검 대상이다.

### 인쇄

**[관찰]** [Workroom CSS의 `@media print`](../../src/components/unified/Workroom.module.css)는 셸 여백·배경을 풀고 사이드바/topbar/안내/dialog/skip link를 숨긴다. 공통 페이지 헤더도 인쇄에서 숨는다. [EnglishPrint.module.css](../../src/components/english/print/EnglishPrint.module.css)는 [공용 A4Page](../../src/components/print/A4Page.tsx)/TestPrint의 A4 규칙을 사용하며 `@page`를 중복 정의하지 않는다고 명시한다. [EnglishBankPrint.module.css](../../src/components/english/print/EnglishBankPrint.module.css)는 `data-english-bank-print`가 있을 때 해당 출력만 남기고 도구를 숨긴다. [듣기 인쇄 CSS](../../src/components/english/listening/print/ListeningPrint.module.css)는 별도 지면 규칙이다.

**[통일]** UI 정리는 화면 CSS module 안에서 한다. 전역 `h1/button/table`, 인쇄 폰트·A4 크기·문항 폭·줄바꿈·답 노출/묶음 분리·쪽 나눔을 함께 바꾸지 않는다. 시험지 만들기 preview는 원본 resolve와 기존 인쇄 경계를 유지한다. 인쇄 때 제목바·필터·담기·sticky 저장판·숨은 측정 틀·다른 mounted 뷰가 나오지 않는지 별도로 확인한다. 인쇄 지면의 serif를 화면 통일과 함께 제거하지 않는다.

**[예외]** 모든 컴포넌트에 같은 breakpoint를 강제하지 않는다. 기준 영어에는 Maker 800/640px, 사진 읽기 860px, 듣기 850px, 자료은행 900/680px와 필터 container 860/580px, QuestionBank 1150/700px가 있다. 내용 최소 폭이 이유인 breakpoint는 유지 가능하되, 변경 결과가 셸의 1050/760px와 함께 자연스럽게 동작해야 한다. 수학 PrivateLibrary의 max-width 1480px/padding 28px 32px(≤640px 20px 16px)는 실제 남은 차이이며 **새 영어 외곽 규칙으로 복제하지 않는다**.

**[통일]** 좁은 화면에서 컬럼을 쌓는 순서는 맥락→조건→결과→선택 상세/다음 행동이다. 긴 한글 학교명/시험명/자료명은 `min-width:0`, wrap 또는 이름을 회복할 수 있는 접근 가능한 줄임으로 처리한다. 가로 스크롤은 본문 전체의 해결책으로 쓰지 않는다. 재생 타임라인·큰 표·사진 확대처럼 본질적으로 넓은 영역만 별도 스크롤할 수 있다.

## 9. 에이전트 작업·검증 가이드

수정 전 [루트 DESIGN.md](../../DESIGN.md)→이 문서의 해당 메뉴→실제 import→CSS 마지막 override 순서로 읽는다. “관찰”을 그대로 복제할지 “통일”을 적용할지 구분한다. 구현 후 동작을 바꾼 계약·의도적 예외·검증 결과를 기록한다. 현재 Math 패턴을 적용하는 것은 이번 위임 범위이며 이미 승인된 방향을 다시 질문하지 않는다. 범위 밖 제품 기능/지면 변경은 이 규칙에서 결정하지 않는다.

각 변경 뷰의 리뷰 체크리스트:

- [ ] 일반 뷰 h1/페이지 헤더가 하나이며 부모·자식 제목 중복이 없다. 수학 홈의 숨긴 h1 예외는 유지했다.
- [ ] 페이지 inset 소유자가 하나다. 색·글자 네 역할·44px 조작의 차이가 남으면 이유와 위치를 기록했다.
- [ ] 현재 맥락, 적용 조건, 결과 수, 담은 수가 구별된다. 숫자의 원본과 범위가 실제 상태와 일치한다.
- [ ] 첫 진입/빈 데이터/필터 무결과/로딩/오류/성공/저장 충돌을 확인했다. 미구현 기능을 문구로 추가하지 않았다.
- [ ] 현재 메뉴 권한만 가진 계정, 만들기/보관함 권한 없는 상태, 숨은 듣기 메뉴 등에서 허용되지 않은 CTA가 생기지 않는다.
- [ ] 여섯 메뉴를 왕복해 시험 선택·작업 중 입력·열린 편집을 보존한다. hidden 유지와 비활성 상태의 접근성, 재생/요청 동작을 깨지 않았다.
- [ ] 탭·검색·필터 해제·페이지 전환·담기·제거·순서·열기·닫기·Escape를 키보드로 쓸 수 있고 초점이 보이며 복귀한다. 기존 native dialog와 이탈 보호를 유지했다.
- [ ] 넓은 화면(예: 1440), 접힌/펼친 사이드바, 1050 경계, 760 경계, 390/320 폭, 짧은 높이(예: 600), 영어 최대화에서 확인했다. 숫자는 **검증 입력 예시**이며 통과 측정 기록이 아니다.
- [ ] 긴 학교/시험/자료 이름, 많은 학교/자료, 긴 원문/해설에서 가로 넘침·반복 띠·이중 스크롤·하단 가림이 없다. 실제 읽기 순서를 확인했다.
- [ ] 학생용/교사용 및 해당 메뉴 인쇄 preview를 확인했다. 지면 규칙은 그대로이며 작업실·담기·필터·숨은 뷰가 종이에 섞이지 않는다.
- [ ] 변경 범위에 맞는 기존 컴포넌트/접근권한/인쇄 테스트를 실행하고 결과를 기록했다. 화면 확인 없이 “수학과 동일”, “접근성 통과”, “전체 완료”라고 보고하지 않았다.

이번 문서 감사의 검증 범위는 소스 연결·현재 선언·메뉴 목록·링크와 규칙의 일관성이다. 런타임 캡처·접근성 측정·백엔드 기능 시험은 수행하지 않았으며, 위 체크리스트는 구현 담당자의 후속 검증 항목이다.
