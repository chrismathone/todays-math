## 검증 방식

로컬 Next 개발 서버에서 실제 컴포넌트를 임시 검증 페이지로 렌더링했다. API는 저장된 테스트 픽스처로 브라우저에서 가로채어 응답하며, 실제 계정·운영 데이터에 쓰기 요청을 보내지 않았다. 임시 페이지는 확인 후 제거했다.

- 공통 화면 관련 5개 테스트 파일, 39개 테스트 통과.
- 타입 검사, 변경 파일 ESLint, 커밋 훅의 스타일·클릭 가능 표시 검사 통과.
- 1440px, 1024px, 900px 헤더 확인. 1024px·900px 가로 넘침 없음.
- 첫 Tab → 본문 건너뛰기 → Enter로 본문 초점 이동 확인.
- 메인 API 실패 → 다시 불러오기 → 대시보드 복구 확인.
- 대단원 탐색 시 저장된 진도와 탐색 위치가 별도로 표시되는 것 확인.

병합 후 `scripts/qa/run-tests.mjs`로 반 관리·시험 검토·단원 선택 6개 파일의 80개 테스트를 실행했고 모두 통과했다. 앞선 공통 화면 테스트와 단원 선택 5개가 중복되므로 총 10개 파일, 고유 테스트 114개를 확인했다. 통합된 코드의 `tsc --noEmit`도 통과했다.

- 학생 등록: 요청 대기 중 등록 버튼 비활성, 실패 후 이름 유지, 재시도 성공 후 목록 추가·입력 초기화.

- 시험 조회: 실패 화면의 다시 불러오기로 원래 시험 복구.
- 1024px 반 관리: 가로 넘침 없음. 1024px 시험 검토 화면도 기록.
