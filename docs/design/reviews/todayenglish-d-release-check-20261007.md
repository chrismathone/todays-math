# 오늘의 영어 D — 배포 전 점검

이 문서는 최초 배포 점검 기록이다. 이후 사용자의 “고치고 밀어” 지시에 따른 의존성 보안 수정·호환성 보완·재검사는 [후속 보안 수정 기록](todayenglish-d-security-release-20261007.md)을 따른다. 아래의 경고 10건과 push 미수행은 최초 점검 당시의 상태다.

점검일: 2026-10-07. 배포 실행 없이, 영어 D 변경과 최신 운영 커밋 `5d359e23f`를 통합한 후보를 점검했다. 전송 보완 `25ff36622`를 포함한 최종 코드 `a797e4993`의 로컬 프로덕션 빌드·관련 테스트가 통과했다. 현재 운영 배포가 준비 완료라는 사실과 이 후보의 배포 성공 여부는 구분한다.

## 발견 및 보완

### 문제은행의 큰 응답

저장·요청·응답 계약을 모두 만족하는 80문항이 5,077,930바이트 JSON을 만들 수 있었다. 기존 `NextResponse.json` 응답으로는 Vercel의 일반 응답 크기 제한을 넘을 수 있다. GET 최대 50문항도 긴 Unicode 원문과 문항을 포함하면 같은 문제가 가능하다.

영어 문제은행 전용 JSON 전송 헬퍼로 보완했다. 전체 소유·최신 버전 검사, 응답 스키마 검증, JSON 직렬화를 모두 끝낸 후 64KiB 이하의 UTF-8 바이트 조각을 소비 속도에 맞게 전달한다. 클라이언트는 기존처럼 `response.json()`을 사용한다. 고정 계약, 최대 80문항, 원문 문자열·순서·판번호, 단일 SQL 스냅샷과 오류의 전체 실패 원칙은 유지한다. `private, no-store`를 유지하며 `Content-Length`는 지정하지 않는다.

근거: [Vercel의 큰 응답 처리 안내](https://vercel.com/kb/guide/how-to-bypass-vercel-body-size-limit-serverless-functions). 실제 Vercel에 큰 응답을 보내는 검증은 아직 수행하지 않았다.

### 로컬 검증 환경

- 설치된 Next.js가 16.3.0으로 잠금 파일의 16.3.8과 달랐다. 해당 빌드를 중단하고 `npm ci`로 잠금 파일에 맞춰 재설치했다. 저장소의 의존성 선언·잠금 파일 변경은 없다.
- 운영 프로젝트는 Node.js 24.x다. 로컬 빌드는 Node.js 24.21.0, Next.js 16.3.8로 실행했다.
- 최초 로컬 빌드는 지정한 4GB 힙 한도에서 전체 TypeScript 검사 중 메모리 부족으로 끝났다. 번들 컴파일은 통과했으며, 저장소 `type-check` 명령과 같은 8GB 한도로 다시 확인해 전체 빌드가 통과했다. 타입 검사를 생략하거나 `ignoreBuildErrors`를 켜지 않았다.

## 운영 설정 확인

Vercel CLI로 `bigshols-projects/todays-math` 프로젝트를 명시해 확인했다. 연결된 MCP 계정의 다른 팀에는 이 프로젝트가 없어 CLI의 확인된 운영 범위를 사용했다.

- Node.js 24.x, Next.js 프레임워크, 표준 `npm run build` 설정.
- 운영 커밋 `5d359e23f`의 배포 `todays-math-gh3i9veh9-bigshols-projects.vercel.app`은 `READY`. 해당 빌드 로그에서 Next.js 16.3.8, 전체 TypeScript 검사 및 배포 완료 확인. 이 커밋에는 영어 D 변경이 포함되지 않는다.
- `DATABASE_URL`, `DIRECT_URL`, `AUTH_SECRET`, `OPENAI_API_KEY`, `DEEPSEEK_API_KEY`의 Production 등록을 확인했다. 값은 가져오거나 기록하지 않았다. 등록 사실은 자격 증명 유효성·모델 이용 가능성·쿼터 검증이 아니다.
- 영어 D는 기존 생성·저장 API를 재사용하고 별도 환경변수, 스키마 변경, DB 마이그레이션을 추가하지 않는다. 기존 생성 라우트의 300초 설정을 유지한다.

## 별도 잔여 사항

- `npm audit --omit=dev` 결과 기존 의존성 경고 10개(높음 5, 보통 1, 낮음 4)가 있다. 영어 D에서 의존성을 추가하거나 변경한 결과가 아니다. Prisma 설정 도구의 deepmerge-ts, MathJax 계열의 xmldom, PDF.js 등이 포함되며 이 점검으로 전체 의존성 보안을 통과했다고 주장하지 않는다. 강제 업·다운그레이드는 하지 않았다.
- [PDF.js 권고](https://github.com/advisories/GHSA-hq66-cqwq-w95j)는 scripting이 켜진 뷰어 사용을 조건으로 명시한다. 현재 확인한 영어 PDF 추출 및 스튜디오 코드는 `getDocument`로 텍스트·캔버스를 직접 처리하고, `PDFViewer`·`PDFScriptingManager`·`enableScripting` 연결은 소스 검색에서 발견하지 못했다. 이는 패키지 경고 해소나 전체 공격 경로 부재를 보증하는 결과가 아니다.
- 실제 운영 계정으로 새 API를 호출하는 확인, 라이브 DB 권한·지연 검사, AI 생성 성공·품질·취소, 후보의 Vercel 클라우드 빌드 및 스트리밍은 미검증이다.
- 배포·push·학생 배정·DB 쓰기는 수행하지 않았다.
