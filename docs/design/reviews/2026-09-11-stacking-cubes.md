# Blender 쌓기나무 실험 — 2026-09-11

개발 화면: `http://192.168.101.12:3000/dev/blender/stack-cubes`

Blender에서 만든 12개 블록을 회전하거나 층별로 벌려 살펴보는 설명용 예제다. 기존 직육면체 전개도 화면에서 이동할 수 있으며, 두 페이지 모두 production에서는 404를 반환한다.

## 구현

- 실제 GLB의 `Separate` 애니메이션을 0–100% 슬라이더와 층 벌리기/다시 쌓기 버튼으로 제어한다. 1초 길이이며 끝 프레임의 반복을 피하도록 마지막 표시는 0.999초로 제한한다.
- 위·앞·오른쪽 버튼은 층을 다시 쌓고 해당 방향으로 카메라를 전환한다. 파란 삼각형은 3D 모델의 앞쪽을 표시한다.
- 정답은 버튼을 누르면 공개한다. 층별 개수는 8, 3, 1개이며 합계는 12개다.
- 기존 도형 엔진으로 만든 SVG에서 위·앞·오른쪽의 정확한 칸 배치를 비교한다. 3D 화면에는 원근감이 있으므로 정투영 그림과 구분해 안내한다.
- 인쇄 CSS는 조작 화면을 숨기고 정적인 입체 SVG, 평면 SVG, 풀이를 표시한다. 조작 안내와 3D 전용 표식에 대한 설명은 인쇄에서 제외했다.
- `next.config.ts`의 `allowedDevOrigins`에 현재 LAN 주소 `192.168.101.12`를 추가했다. dev 서버는 포트 3000의 모든 인터페이스에서 수신한다.

## 검증 결과

- Blender 5.2.1 LTS로 GLB를 생성했다. 파일 크기 41,084바이트, 블록 12개, 애니메이션 1개다.
- 생성기와 `node scripts/blender/verify_stack_cubes.mjs`가 블록 크기, 지지 관계, 애니메이션 시작/중간/끝 좌표를 검사했다. 앞에서 뒤 순서의 높이 행렬 `[[1,1,0],[2,3,1],[1,2,1]]`과 각 SVG의 실제 좌표를 대조했다.
- 제어 컴포넌트 테스트 6개, 전체 TypeScript 검사, 변경 파일 ESLint와 whitespace 검사가 통과했다.
- Chromium에서 LAN 주소로 모델과 SVG가 로딩되며, 정상 시나리오에서 페이지 오류와 HTTP 실패가 없었다. LAN 루트 주소도 로그인 화면으로 정상 이동했다.
- 실제 모델에서 회전 드래그, 층 벌리기, 중간값, 키보드 Home/End, 위·앞·오른쪽·입체 방향, 정답 공개/닫기를 확인했다.
- 전개도 → 쌓기나무 → 전개도 → 쌓기나무 이동 후에도 모델 로딩과 층 분리 동작을 확인했다.
- GLB 요청에 의도적으로 503 응답을 주면 제어가 비활성화되고, 다시 시도를 누르면 로딩 후 활성화됐다.
- 모바일 390×844, 동작 줄이기 설정에서 모델과 층 분리가 정상 표시됐다. 문서 너비 390px로 가로 넘침이 없었다.
- 인쇄 미디어 에뮬레이션에서 3D 화면과 조작 안내는 숨겨지고 SVG 4개가 표시됐다. 실제 종이 출력이나 PDF 페이지 분할까지 검증한 것은 아니다.
