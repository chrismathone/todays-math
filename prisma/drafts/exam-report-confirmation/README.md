# 월말평가 성적표 확정 · PDF 보관 — 미적용 초안

2026-10-18 · M5. `draft.sql`은 검토 자료다. 공유 DB 접속·드라이런·적용을 하지 않았다. `schema.prisma`와 마이그레이션은 바꾸지 않았다.

- 발행본·학생마다 편집 자리 하나를 둔다. 원장님 문장과 출력 선택을 고칠 수 있다.
- 확정은 **현재 최신 채점 + 문장 + 출력 선택 + 지면 버전 + 렌더한 PDF**를 한 거래로 굳히는 일이다. 보관본은 수정하지 않는다. 확정 단추·저장 API는 아직 구현하지 않았다.
- 재채점 또는 문장·선택 수정은 확정을 푼다. 옛 보관본은 이력으로 남지만 에이와 목록에서 빠진다. 재확정한 새 내용·PDF는 새 지문을 갖는다. 문장 수정만으로 미검토 PDF가 자동 공개되지 않는다.
- `exam_report_draft.confirmed_artifact_id`가 가리키는 보관본만 읽는다. 그 보관본의 `source_digest`와 **현재** 뷰모델·선택·지면 버전 지문을 다시 대조한다. 읽기 중 재채점도 확인한다.
- 날짜는 시험일(`exam_publication.test_date`)이다. 확정 날짜가 아니다. 에이와는 아직 보내지 않은 수업보고서만 갱신하며 이미 보낸 ClassNote를 재발송하지 않는다. 전송·미첨부 안내는 에이와 책임이다.

SQL은 관계·용량·상태·수정 시 무효화의 제안이다. 확정 처리의 권한(`test:write`, 소유·지점), 최신 채점 잠금, 응답 완전성, JSON/Zod 계약, 정규 JSON 지문, PDF 렌더/바이트 지문은 적용 후 서버 코드에서 검사해야 한다. 보관본의 문장이 편집 자리의 문장과 일치하고, 내용·출력 버전이 지문과 일치해야 한다. SQL만으로 조판 결과의 의미를 증명하지 않는다.

DB 적용 순서: 원장님 승인 → 리드가 정본 스키마와 이 초안을 재검토 → 별도 드라이런 → DB 적용 → Prisma 스키마·클라이언트와 승인된 읽기/쓰기 어댑터 배포. 이 워크트리에서는 어느 단계도 실행하지 않는다. 데이터가 생긴 뒤 표를 지우는 되돌림은 하지 않는다.

현재 `src/lib/examReport/confirmedSource.ts`는 DB/PDF 생성기 import가 없는 닫힌 소스다. 표가 없거나 Prisma가 모르는 모델을 조회하지 않는다. 목록은 `availability: "not-installed", reports: []`, 항목 PDF는 404다. SQL만 적용해도 자동으로 열리지 않는다. 승인 후 어댑터를 연결하고 통합 시험을 추가해야 한다.

남은 검토: 보관본의 용량·보존기간·삭제 절차, 반 이동으로 같은 학생이 두 반 시험에 걸릴 때의 원기록 선택, 문장 길이와 넘침 안내는 실제 화면 확정 때 정한다. 현재 피드는 같은 발행본·에이와 학생의 중복 항목을 409로 거절한다.
